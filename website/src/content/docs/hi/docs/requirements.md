## ऑपरेटिंग सिस्टम

| सिस्टम  | संस्करण                                                        | आर्किटेक्चर          |
| ------- | -------------------------------------------------------------- | -------------------- |
| Windows | Windows 10 और 11                                               | x64, ARM64           |
| macOS   | macOS 10.15 Catalina या बाद का                                 | Apple silicon, Intel |
| Linux   | glibc 2.35 या बाद का: Ubuntu 22.04, Debian 12, Fedora 36 और नए | x64, ARM64           |

Homeport अपनी विंडो बनाने के लिए सिस्टम के वेब व्यू का इस्तेमाल करता है: Windows पर WebView2 (Windows 10 और 11 के साथ शामिल), macOS पर WebKit, और Linux पर WebKitGTK (`.deb` और `.rpm` पैकेज की डिपेंडेंसी के रूप में इंस्टॉल होता है, और AppImage में बंडल किया गया है)।

## प्रबंधित करने के लिए एक Docker Engine

Homeport में कोई कंटेनर रनटाइम शामिल नहीं है। यह उन Docker Engine को प्रबंधित करता है जो पहले से कहीं चल रहे हैं:

- **इस मशीन पर** — Docker Engine, Docker Desktop, Colima, OrbStack, Rancher Desktop या Podman। Homeport उन्हें आपके लिए ढूँढता है; [लोकल इंजन](/docs/hosts/local/) देखें।
- **किसी सर्वर पर** — [SSH](/docs/hosts/ssh/) पर, या [TLS या TCP](/docs/hosts/tls-tcp/) पर पहुँचा जा सकने वाला।

Docker Engine API बोलने वाला कोई भी इंजन काम करता है, जिसमें Podman का Docker-संगत सॉकेट भी शामिल है।

यह [containerd](/docs/hosts/containerd/) 1.7 और बाद के संस्करण को भी सीधे प्रबंधित करता है, इस मशीन पर उसके सॉकेट के ज़रिए या SSH पर: k3s का, Docker Engine का अपना, या किसी सर्वर पर containerd की सर्विस। वहाँ इमेज पुल करने के लिए containerd 2.0 या बाद का संस्करण चाहिए, और लॉग और टर्मिनल के लिए SSH पर पहुँचा गया होस्ट, या इस कंप्यूटर पर containerd (Linux) चाहिए।

यह [Incus](/docs/hosts/incus/) 6.0 और बाद के संस्करण को भी प्रबंधित करता है, इस मशीन पर उसके सॉकेट के ज़रिए या SSH पर, या ट्रस्ट टोकन के साथ HTTPS पर। वर्चुअल मशीन के लिए Incus सर्वर पर हार्डवेयर वर्चुअलाइज़ेशन (`/dev/kvm`) चाहिए, और उनमें टर्मिनल के लिए वह `incus-agent` चाहिए जो उसकी इमेज चलाती है।

Podman होस्ट पर, Homeport Podman के अपने API का भी इस्तेमाल करता है: [पॉड](/docs/guides/podman-pods/) के लिए Podman 4.0 या बाद का संस्करण चाहिए, और [Quadlet यूनिट](/docs/guides/quadlet/) Podman 5.7 से सूचीबद्ध होती हैं और 5.8 से इंस्टॉल, संपादित और हटाई जाती हैं। किसी Quadlet यूनिट को शुरू करने और रोकने के लिए होस्ट का SSH पर पहुँचा जाना, या इस कंप्यूटर पर Podman (Linux) चाहिए।

## वैकल्पिक: Kubernetes क्लस्टर

[क्लस्टर](/docs/clusters/) ब्राउज़ करने के लिए, Homeport को एक ऐसा kubeconfig चाहिए जो उन तक पहुँचता हो (वही जिसका `kubectl` इस्तेमाल करता है, या वह जिसे आप पेस्ट करते हैं) और उनके API सर्वर तक नेटवर्क पहुँच चाहिए। यह Kubernetes API ख़ुद बोलता है, इसलिए `kubectl` की ज़रूरत नहीं है।

- **Kubernetes संस्करण**: Kubernetes 1.24 या बाद का संस्करण चलाने वाले क्लस्टर। Homeport सिर्फ़ स्थिर API (`v1`, `apps/v1`, `batch/v1`, `networking.k8s.io/v1`) का इस्तेमाल करता है, और 1.33 API के अनुसार बनाया गया है।
- **Exec प्लगइन**: क्लाउड kubeconfig अपने क्रेडेंशियल के लिए इस कंप्यूटर पर चलाए जाने वाले एक प्रोग्राम का नाम देता है — EKS के लिए [AWS CLI](https://aws.amazon.com/cli/) (संस्करण 2), GKE के लिए Google Cloud CLI से `gke-gcloud-auth-plugin`, AKS के लिए `kubelogin`। वह इंस्टॉल करें जिसका नाम आपका kubeconfig देता है; [exec प्लगइन](/docs/clusters/exec-plugins/) देखें।

## वैकल्पिक: Nomad क्लस्टर

[Nomad क्लस्टर](/docs/clusters/nomad/) प्रबंधित करने के लिए, Homeport को किसी Nomad agent के HTTP API (डिफ़ॉल्ट रूप से पोर्ट 4646) तक नेटवर्क पहुँच चाहिए और, जब क्लस्टर में ACL सक्षम हों, एक टोकन चाहिए; उसे जिस [ACL policy](/docs/clusters/nomad/#acl-policies) की ज़रूरत है, वह देखें। यह Nomad का API ख़ुद बोलता है, इसलिए `nomad` CLI की ज़रूरत नहीं है, और क्लस्टर पर कुछ भी इंस्टॉल नहीं किया जाता।

- **Nomad संस्करण**: Nomad 1.6 या बाद का संस्करण। **संपादित करें और चलाएँ** किसी job के सबमिट किए गए स्पेसिफ़िकेशन से शुरू होता है, जिसे Nomad 1.6 से रखता है।

## वैकल्पिक: OS कीचेन

Homeport SSH कुंजियों, TLS प्रमाणपत्रों, क्लस्टर के kubeconfig क्रेडेंशियल, स्टैक के परिवेश, रजिस्ट्री लॉगिन और रिपॉज़िटरी की डिप्लॉय कुंजियों और टोकन को एक ऐसी कुंजी से एन्क्रिप्ट करता है जिसे वह आपके ऑपरेटिंग सिस्टम के कीचेन में रखता है:

- **macOS** — Keychain
- **Windows** — Credential Manager
- **Linux** — कोई Secret Service प्रोवाइडर, जैसे GNOME Keyring या KWallet

कीचेन के बिना, Homeport एक बैनर दिखाता है और फिर भी लोकल सॉकेट, सादे TCP और **ssh-agent** के ज़रिए SSH के साथ काम करता है। TLS होस्ट, सहेजी गई कुंजियों वाले SSH होस्ट, क्लस्टर, स्टैक के परिवेश, रजिस्ट्री लॉगिन और प्राइवेट रिपॉज़िटरी को कीचेन चाहिए; उसके बिना, इमेज गुमनाम रूप से पुल की जाती हैं और सिर्फ़ पब्लिक रिपॉज़िटरी जोड़ी जा सकती हैं। [सुरक्षा और आपका डेटा](/docs/reference/security/) देखें।

## वैकल्पिक: Docker Compose

[प्रबंधित, लिंक्ड और सिंक्ड स्टैक](/docs/guides/stacks/) डिप्लॉय करने के लिए, Homeport `docker compose` कमांड **इस** मशीन पर चलाता है — होस्ट पर नहीं। Compose प्लगइन के साथ Docker CLI इंस्टॉल करें (Docker Desktop में यह शामिल है), या स्टैंडअलोन `docker-compose` v2।

इसके बिना भी स्टैक दिखते हैं — लिंक्ड स्टैक सहित — और उन्हें शुरू किया, रोका और हटाया जा सकता है; सिर्फ़ डिप्लॉय करने के लिए Compose चाहिए। **सेटिंग्स → यह मशीन** दिखाता है कि Homeport को यह मिला या नहीं।

किसी [Swarm](/docs/guides/swarm/) पर स्टैक डिप्लॉय करने के लिए, Homeport इसके बजाय इस मशीन पर `docker stack deploy` चलाता है, इसलिए उसे ख़ुद `docker` कमांड चाहिए (Compose प्लगइन का इस्तेमाल नहीं होता)। Docker Desktop में यह है; Linux पर, अपने डिस्ट्रीब्यूशन का Docker CLI पैकेज (`docker-ce-cli`, `docker.io` या `docker`) इंस्टॉल करें। यहाँ किसी इंजन को चलने की ज़रूरत नहीं है।

## वैकल्पिक: git

[सिंक्ड स्टैक](/docs/guides/synced-stacks/) अपनी रिपॉज़िटरी को क्लोन और फ़ेच करने के लिए **इस** मशीन पर इंस्टॉल किए गए `git` को चलाते हैं: Git for Windows, Apple के कमांड लाइन टूल (`xcode-select --install`), या आपके डिस्ट्रीब्यूशन का `git` पैकेज। Windows पर, Homeport SSH रिपॉज़िटरी के लिए उसे सिस्टम के OpenSSH की ओर इंगित करता है। बाकी हर सुविधा git के बिना काम करती है; **सेटिंग्स → यह मशीन** दिखाता है कि Homeport को यह मिला या नहीं।

## वैकल्पिक: Helm

किसी क्लस्टर पर [Helm रिलीज़](/docs/clusters/helm/) प्रबंधित करने के लिए, Homeport **इस** मशीन पर `helm` कमांड, संस्करण 3 या बाद का, चलाता है। यह helm को एक निजी कनेक्शन के ज़रिए क्लस्टर की ओर इंगित करता है, इसलिए कोई भी क्लस्टर क्रेडेंशियल डिस्क पर नहीं लिखा जाता, और helm टर्मिनल की तरह ही अपनी चार्ट रिपॉज़िटरी का इस्तेमाल करता है। इसे `brew install helm` (macOS), `winget install Helm.Helm`, Chocolatey या Scoop (Windows), या `snap install helm --classic`, अपने डिस्ट्रीब्यूशन के पैकेज या [helm.sh](https://helm.sh/docs/intro/install/) की स्क्रिप्ट (Linux) से इंस्टॉल करें। क्लस्टर का हर दूसरा पेज इसके बिना काम करता है; **सेटिंग्स → यह मशीन** दिखाता है कि Homeport को यह मिला या नहीं।

## वैकल्पिक: सिस्टम ट्रे

Homeport सिस्टम ट्रे (macOS पर मेनू बार, Windows पर नोटिफ़िकेशन एरिया) में एक आइकन रखता है जो हर होस्ट को उसकी स्थिति के साथ सूचीबद्ध करता है। Windows और macOS में यह हमेशा होता है। Linux पर इसके लिए **appindicator** लाइब्रेरी चाहिए: AppImage में यह शामिल है, और `.deb` और `.rpm` पैकेज इसकी सिफ़ारिश करते हैं, इसलिए `apt`, `dnf` और `zypper` इसे इंस्टॉल करते हैं, जब तक कि आपने सुझाए गए पैकेज बंद न किए हों। नहीं तो `libayatana-appindicator3-1` (Debian, Ubuntu, openSUSE) या `libayatana-appindicator-gtk3` (Fedora) इंस्टॉल करें। कुछ डेस्कटॉप ट्रे आइकन छिपाते हैं — GNOME उन्हें सिर्फ़ AppIndicator Support जैसे किसी एक्सटेंशन के साथ दिखाता है। ट्रे के बिना, Homeport अपनी विंडो से काम करता है, और विंडो बंद करने पर वह बंद हो जाता है।
