किसी सर्वर पर Docker Engine तक पहुँचने के लिए SSH सुझाया गया तरीक़ा है। SSH पोर्ट के अलावा कुछ भी एक्सपोज़ करने की ज़रूरत नहीं होती, और इंजन का सॉकेट सर्वर पर निजी रहता है।

## यह कैसे काम करता है

Homeport का अपना SSH क्लाइंट है। यह सर्वर में लॉग इन करता है और इंजन के Unix सॉकेट तक एक चैनल फ़ॉरवर्ड करता है — वही जो `docker -H ssh://…` करता है, आपकी मशीन पर `ssh` प्रोग्राम या `docker` की ज़रूरत के बिना।

- कुंजियाँ सिर्फ़ मेमोरी में डिक्रिप्ट की जाती हैं और कभी डिस्क पर नहीं लिखी जातीं, इसलिए यह Windows, macOS और Linux पर एक जैसा काम करता है।
- Homeport `~/.ssh/known_hosts` नहीं पढ़ता: सर्वर कुंजियों पर Homeport में, हर होस्ट के लिए अलग से भरोसा किया जाता है। जो सर्वर सिर्फ़ किसी jump server के ज़रिए पहुँचा जा सकता है, उसे [बैस्टियन](#बैस्टियन-के-ज़रिए) के साथ जोड़ा जाता है, जो Homeport का `ProxyJump` है।
- सर्वर को Unix सॉकेट तक forwarding की अनुमति देनी चाहिए। OpenSSH डिफ़ॉल्ट रूप से ऐसा करता है (`AllowStreamLocalForwarding yes`)।

## SSH होस्ट जोड़ना

<Steps>

1. होस्ट स्विचर में **होस्ट जोड़ें…** चुनें और **SSH** चुना रहने दें।

2. कनेक्शन भरें:

   | फ़ील्ड              | क्या दर्ज करें                                                                                                                                                         |
   | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | **नाम**             | एक ऐसा नाम जिसे आप पहचान सकें, जैसे `production`।                                                                                                                      |
   | **सर्वर**           | सर्वर का होस्ट नाम या IP पता।                                                                                                                                          |
   | **पोर्ट**           | SSH पोर्ट; डिफ़ॉल्ट रूप से `22`।                                                                                                                                       |
   | **यूज़र**           | वह अकाउंट जिससे लॉग इन करना है। इसे Docker सॉकेट तक पहुँच चाहिए, आम तौर पर `docker` ग्रुप के ज़रिए।                                                                    |
   | **रिमोट सॉकेट पाथ** | सर्वर पर इंजन कहाँ सुनता है: डिफ़ॉल्ट रूप से `/var/run/docker.sock`, rootless Docker के लिए `/run/user/<uid>/docker.sock`, या Podman के लिए `/run/podman/podman.sock`। |

3. **प्रमाणीकरण** के नीचे चुनें कि कैसे साइन इन करना है (नीचे देखें)।

4. **होस्ट जोड़ें** चुनें। Homeport होस्ट का पेज खोलता है और कनेक्ट होता है।

</Steps>

## ~/.ssh/config से इम्पोर्ट करें

अगर आपके सर्वर पहले से `~/.ssh/config` में हैं, तो हर एक को टाइप करने के बजाय **होस्ट जोड़ें** पर **~/.ssh/config से इम्पोर्ट करें** चुनें। Homeport फ़ाइल में नामित हर सर्वर को सूचीबद्ध करता है — `Include` का पालन करते हुए, `Host *` डिफ़ॉल्ट लागू करते हुए — और आप जोड़ने के लिए सर्वर चुनते हैं।

| `~/.ssh/config` में | Homeport में                                                                                                |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| `Host prod`         | `prod` नाम का एक होस्ट। वाइल्डकार्ड वाली एंट्री (`Host *.example.com`) सिर्फ़ डिफ़ॉल्ट देती हैं।            |
| `HostName`          | **सर्वर**; जब यह न हो तो ख़ुद alias।                                                                        |
| `User`, `Port`      | **यूज़र** (डिफ़ॉल्ट रूप से आपका लोकल यूज़र नाम) और **पोर्ट** (`22`)।                                        |
| `IdentityFile`      | **मौजूदा कुंजी**: पहली फ़ाइल जो पढ़ी जा सके, `~` और `%h`, `%r`, `%u`, `%p` को विस्तारित करके।               |
| `IdentityFile` नहीं | **ssh-agent**।                                                                                              |
| `ProxyJump a,b`     | दो [बैस्टियन](#बैस्टियन-के-ज़रिए), क्रम से, हर एक उसी फ़ाइल में खोजा जाता है। किसी लूप की सूचना दी जाती है। |

**रिमोट सॉकेट पाथ** `/var/run/docker.sock` से शुरू होता है; rootless Docker या Podman के लिए इसे प्रीव्यू में बदलें। एन्क्रिप्टेड कुंजी वहीं अपना पासफ़्रेज़ माँगती है।

प्रीव्यू उन चीज़ों को चिह्नित करता है जिन्हें देखने की ज़रूरत है: ऐसी कुंजी जो पढ़ी नहीं जा सकती (होस्ट इसके बजाय ssh-agent का इस्तेमाल करता है), कोई `ProxyCommand` (समर्थित नहीं; उसके jump server को बैस्टियन के रूप में जोड़ें), और ऐसा alias जो पहले से किसी होस्ट का नाम है। वह चुना नहीं जाता: उसे इम्पोर्ट करने के लिए उसका नाम बदलें, ताकि दो बार इम्पोर्ट करने से कभी डुप्लिकेट न बनें। कुंजियाँ एक बार पढ़ी जाती हैं और एन्क्रिप्ट करके सहेजी जाती हैं; फ़ाइल ख़ुद कभी नहीं बदली जाती, और `Match` ब्लॉक और प्रमाणपत्र (`CertificateFile`) अनदेखे किए जाते हैं।

## प्रमाणीकरण

### इस होस्ट के लिए नई कुंजी (सुझाया गया)

Homeport सिर्फ़ इस होस्ट के लिए एक Ed25519 कुंजी बनाता है, उसे एन्क्रिप्ट करके सहेजता है, और आपको वह कमांड दिखाता है जो सर्वर पर उसे अधिकृत करता है। हर होस्ट के लिए एक कुंजी का मतलब है कि आप किसी और चीज़ को छुए बिना एक सर्वर से Homeport की पहुँच रद्द कर सकते हैं। कुंजी की टिप्पणी इस कंप्यूटर और होस्ट का नाम देती है, जैसे `homeport@laptop-production`, ताकि आप उसे `authorized_keys` में पहचान सकें।

### मौजूदा कुंजी

कोई निजी कुंजी पेस्ट करें, या **फ़ाइल से लोड करें…** चुनें, और अगर उसका **पासफ़्रेज़** है तो उसे दर्ज करें। Homeport Ed25519, ECDSA या RSA कुंजियों के साथ OpenSSH कुंजियाँ (`BEGIN OPENSSH PRIVATE KEY`), PKCS#8 और PEM कुंजियाँ, और PuTTY `.ppk` फ़ाइलें पढ़ता है। कुंजी और उसका पासफ़्रेज़ एन्क्रिप्ट करके सहेजे जाते हैं, इसलिए आपसे दोबारा नहीं पूछा जाता।

### ssh-agent

Homeport आपके चल रहे SSH agent से कुंजियाँ माँगता है, और कुछ भी नहीं सहेजता। macOS और Linux पर यह `$SSH_AUTH_SOCK` वाले agent का इस्तेमाल करता है।

Windows पर यह पहले OpenSSH Authentication Agent सर्विस से पूछता है, फिर PuTTY के **Pageant** से — या उसकी जगह काम करने वाले किसी टूल से, जैसे KeeAgent या PuTTY सपोर्ट वाला gpg-agent। इनमें से किसी के भी पास रखी कुंजी काम करती है: अगर OpenSSH agent नहीं चल रहा, या उसके पास ऐसी कोई कुंजी नहीं जिसे सर्वर स्वीकार करे, तो Homeport Pageant की कुंजियाँ भी आज़माता है।

<Aside>
  ssh-agent ही एकमात्र SSH विकल्प है जो [OS कीचेन](/docs/requirements/#वैकल्पिक-os-कीचेन) के बिना
  काम करता है। अगर Homeport किसी डेस्कटॉप मेनू से शुरू किया गया था, तो पक्का करें कि आपके सेशन का
  agent उसके लिए उपलब्ध है।
</Aside>

## पहला कनेक्शन

जब Homeport पहली बार कनेक्ट होता है, तो होस्ट का पेज आपको दो चरणों से ले जाता है।

### सर्वर की कुंजी पर भरोसा करें

स्थिति **सर्वर कुंजी पर भरोसा नहीं किया गया** दिखाती है, और पेज सर्वर की कुंजी के फ़िंगरप्रिंट, जैसे `SHA256:Kx8f…`, के साथ **क्या यह सही सर्वर है?** पूछता है।

इसकी तुलना सर्वर पर मौजूद फ़िंगरप्रिंट से करें:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

अगर वे मेल खाते हैं, तो **इस कुंजी पर भरोसा करें** चुनें। Homeport उसे याद रखता है और कनेक्ट होता है। यह वही trust-on-first-use जाँच है जो `ssh` करता है, बस कुंजी `~/.ssh/known_hosts` के बजाय Homeport में सहेजी जाती है।

### Homeport की कुंजी को अधिकृत करें

Homeport की बनाई कुंजी, या आपकी इम्पोर्ट की हुई कुंजी के लिए, **सर्वर पर Homeport को अधिकृत करें** कार्ड दो कमांड दिखाता है, हर एक के साथ **कॉपी करें** बटन। उन्हें सर्वर पर SSH यूज़र के रूप में चलाएँ:

<DocScreenshot
  name="host-ssh"
  alt="एक SSH होस्ट का पेज, उन कमांड के साथ जो सर्वर पर Homeport की कुंजी को अधिकृत करते हैं।"
/>

<Steps>

1. यूज़र की `authorized_keys` में **पब्लिक कुंजी जोड़ें**:

   ```sh
   mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'ssh-ed25519 AAAAC3Nza… homeport@laptop-production' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
   ```

2. अगर यूज़र पहले से Docker तक नहीं पहुँच सकता, तो **यूज़र को Docker तक पहुँचने दें**:

   ```sh
   sudo usermod -aG docker deploy
   ```

3. Homeport में वापस आकर, **फिर से कनेक्ट करें** चुनें।

</Steps>

जब तक कुंजी अधिकृत नहीं होती, होस्ट **पहुँच अस्वीकृत** दिखाता है: _सर्वर ने deploy@server के लिए कुंजी अस्वीकार कर दी। उसकी authorized_keys में पब्लिक कुंजी जोड़ें।_ यह दोबारा कोशिश करने के बजाय आपका इंतज़ार करता है।

## जब सर्वर की कुंजी बदल जाए

अगर सर्वर बाद में कोई अलग कुंजी पेश करता है, तो Homeport रुक जाता है और अपेक्षित और पेश किए गए फ़िंगरप्रिंट के साथ **सर्वर कुंजी बदल गई** दिखाता है।

<Aside type="caution">
  सर्वर को फिर से इंस्टॉल करने या उसकी होस्ट कुंजियाँ फिर से बनाने के बाद कुंजी का बदलना अपेक्षित
  है। इसका मतलब यह भी हो सकता है कि कोई कनेक्शन को बीच में पकड़ रहा है। नई कुंजी पर सिर्फ़ तभी भरोसा
  करें जब आप जानते हों कि वह क्यों बदली।
</Aside>

जब आप पक्का हों, तो **नई कुंजी पर भरोसा करें** चुनें और पुष्टि करें।

किसी होस्ट को किसी दूसरे सर्वर या पोर्ट की ओर इंगित करने के लिए संपादित करने से भरोसा की गई कुंजी भुला दी जाती है, और आपसे नई कुंजी पर भरोसा करने के लिए कहा जाएगा। होस्ट का नाम बदलने या यूज़र या सॉकेट पाथ बदलने से वह बनी रहती है।

## बैस्टियन के ज़रिए

कुछ सर्वर सिर्फ़ किसी jump server से SSH स्वीकार करते हैं। उस सर्वर को होस्ट के फ़ॉर्म में **बैस्टियन** के नीचे जोड़ें, और Homeport पहले उसमें लॉग इन करता है, फिर उसके ज़रिए होस्ट तक पहुँचता है — वही जो `ssh -J` या `ProxyJump` करते हैं, Homeport के अपने SSH क्लाइंट के साथ। बैस्टियन पर कुछ भी इंस्टॉल नहीं किया जाता, और कोई कुंजी डिस्क पर नहीं लिखी जाती।

<Steps>

1. SSH होस्ट के फ़ॉर्म में, **बैस्टियन जोड़ें** चुनें।

2. उसका **सर्वर**, **पोर्ट** और **यूज़र** दर्ज करें।

3. चुनें कि Homeport उसमें कैसे लॉग इन करे:

   | प्रमाणीकरण          | इसका इस्तेमाल कब करें                                                                                                                           |
   | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
   | **होस्ट वाली ही**   | बैस्टियन वह कुंजी स्वीकार करता है जिसका होस्ट इस्तेमाल करता है: Homeport की बनाई हुई, आपकी मौजूदा कुंजी, या आपके agent की।                      |
   | **इसकी अपनी कुंजी** | बैस्टियन को एक अलग कुंजी चाहिए। उसे पेस्ट करें या **फ़ाइल से लोड करें…** चुनें; वह होस्ट के दूसरे सीक्रेट के साथ एन्क्रिप्ट करके सहेजी जाती है। |
   | **ssh-agent**       | आपके agent के पास बैस्टियन की कुंजी है, जबकि होस्ट कोई दूसरी कुंजी इस्तेमाल करता है, जैसे Homeport की सिर्फ़ उसी के लिए बनाई गई कुंजी।          |

4. jump server की एक शृंखला (`ProxyJump a,b`) के लिए, हर सर्वर के लिए एक बैस्टियन जोड़ें, उसी क्रम में जिसमें Homeport उनसे गुज़रता है। तीर किसी बैस्टियन को ऊपर या नीचे ले जाते हैं।

</Steps>

पहले कनेक्शन पर Homeport आपसे बारी-बारी से हर सर्वर की कुंजी पर भरोसा करने के लिए कहता है, पहले बैस्टियन से शुरू करके: **क्या यह सही बैस्टियन है?** उसका नाम देता है और उसका फ़िंगरप्रिंट दिखाता है। हर बैस्टियन की कुंजी होस्ट के साथ रखी जाती है, और बदली हुई कुंजी कनेक्शन को **बैस्टियन … की कुंजी बदल गई** के साथ रोक देती है, जैसे ख़ुद होस्ट के लिए।

जब होस्ट Homeport की बनाई कुंजी इस्तेमाल करता है, तो **सर्वर पर Homeport को अधिकृत करें** कार्ड हर उस सर्वर को सूचीबद्ध करता है जिस पर उसे जोड़ना ज़रूरी है: **होस्ट वाली ही** पर सेट हर बैस्टियन, फिर होस्ट।

बैस्टियन को होस्ट तक TCP forwarding की अनुमति देनी चाहिए (`AllowTcpForwarding yes`, OpenSSH का डिफ़ॉल्ट)। अगर ऐसा नहीं है, या वह होस्ट तक नहीं पहुँच सकता, तो होस्ट _बैस्टियन …, … से कनेक्शन नहीं खोल सका_ दिखाता है।

सूची में किसी बैस्टियन को ऊपर-नीचे करने से उसकी भरोसा की गई कुंजी बनी रहती है; उसका सर्वर या पोर्ट बदलने से सिर्फ़ वही एक कुंजी भुला दी जाती है।

## कुंजी फिर से बनाना

Homeport की बनाई कुंजी के लिए, होस्ट के पेज पर **कुंजी फिर से बनाएँ** उसे बदल देता है। पुरानी कुंजी काम करना बंद कर देती है, इसलिए सर्वर पर नया **पब्लिक कुंजी जोड़ें** कमांड चलाएँ, और `~/.ssh/authorized_keys` से पुरानी लाइन हटा दें।

## SSH होस्ट हटाना

होस्ट हटाने से उसकी कुंजी Homeport से मिट जाती है, लेकिन सर्वर से नहीं। यूज़र की `~/.ssh/authorized_keys` से उसकी लाइन मिटा दें — `homeport@` से शुरू होने वाली टिप्पणी उसकी पहचान कराती है।
