---

जब किसी क्लस्टर पर [metrics-server](https://github.com/kubernetes-sigs/metrics-server) चलता है, तो Homeport दिखाता है कि हर Pod और हर Node कितना CPU और मेमोरी इस्तेमाल करता है: सूचियों में, और उनके पेजों पर लाइव चार्ट में। यह `kubectl top` की तरह metrics-server की दी हुई Metrics API (`metrics.k8s.io`) पढ़ता है।

## क्या चाहिए

metrics-server पहले से क्लस्टर पर चल रहा होना चाहिए: Homeport किसी क्लस्टर पर कुछ भी इंस्टॉल नहीं करता। वह मौजूद है या नहीं, यह इस पर निर्भर करता है कि क्लस्टर कैसे बनाया गया:

| क्लस्टर                  | metrics-server                                                                 |
| ------------------------ | ------------------------------------------------------------------------------ |
| GKE                      | इंस्टॉल है                                                                     |
| AKS                      | इंस्टॉल है                                                                     |
| k3s और k3d               | इंस्टॉल है (जब तक k3s को `--disable metrics-server` के साथ शुरू न किया गया हो) |
| Docker Desktop           | उसके Kubernetes के साथ इंस्टॉल है                                              |
| kind                     | इंस्टॉल नहीं है                                                                |
| EKS                      | इंस्टॉल नहीं है: metrics-server ऐड-ऑन जोड़ें, या उसे खुद इंस्टॉल करें          |
| minikube                 | इंस्टॉल नहीं है: `minikube addons enable metrics-server`                       |
| दूसरे क्लस्टर (kubeadm…) | आम तौर पर इंस्टॉल नहीं है                                                      |

उसे खुद इंस्टॉल करने के लिए [उसके निर्देश](https://github.com/kubernetes-sigs/metrics-server#installation) देखें; ऐसे लोकल क्लस्टर पर जिसके kubelets के सर्टिफ़िकेट सेल्फ़-साइन्ड हैं (kind), metrics-server को `--kubelet-insecure-tls` भी चाहिए।

metrics-server के बिना कुछ नहीं टूटता: CPU और मेमोरी के कॉलम नहीं दिखते, और किसी Pod या Node का **मेट्रिक्स** टैब बताता है कि metrics-server इंस्टॉल नहीं है, उसके लिंक के साथ। इंस्टॉल होने के ठीक बाद metrics-server को सैंपल जुटाने में करीब एक मिनट लगता है; तब तक टैब बताता है कि Metrics API अभी जवाब नहीं दे रहा।

आपके क्रेडेंशियल्स को मेट्रिक्स पढ़ने की अनुमति भी चाहिए: Namespace (या हर Namespace) में `pods.metrics.k8s.io` पर, और Nodes के लिए `nodes.metrics.k8s.io` पर `list` और `get`। अनुमति न होने पर **मेट्रिक्स** टैब बताता है कि कौन-सी अनुमति कम है, और बाकी सभी पेज काम करते रहते हैं।

## सूचियों में

**Pods** पर, **CPU** और **मेमोरी** कॉलम दिखाते हैं कि हर Pod कितना इस्तेमाल करता है (उसके कंटेनर जोड़कर), और यह उसकी लिमिट का कितना हिस्सा है, या लिमिट न होने पर उसकी रिक्वेस्ट का। किसी Pod की लिमिट तभी होती है जब उसके सभी कंटेनरों की लिमिट हो: बिना लिमिट वाला कंटेनर पूरा Node इस्तेमाल कर सकता है। CPU मिलीकोर में है, जैसे `kubectl top` लिखता है (`250m` एक कोर का चौथाई है), और मेमोरी वर्किंग सेट है, जिसके आधार पर kubelet Pods को हटाता है।

**Nodes** पर, **CPU इस्तेमाल** और **मेमोरी इस्तेमाल** दिखाते हैं कि हर Node कितना इस्तेमाल करता है, और Pods के लिए **आवंटन योग्य** का कितना हिस्सा।

किसी कॉलम के हेडर पर क्लिक करके उससे क्रम लगाएँ: सबसे ज़्यादा लोड वाले Pods या Nodes पहले।

## किसी Pod या Node के पेज पर

किसी Pod का **मेट्रिक्स** टैब हर कंटेनर का CPU और मेमोरी चार्ट में दिखाता है, और सेट होने पर उसकी रिक्वेस्ट और लिमिट पर एक-एक डैश वाली लाइन। किसी Node का टैब उसका CPU और मेमोरी आवंटन योग्य की लाइन के साथ दिखाता है।

metrics-server हर 15 सेकंड में kubelets पढ़ता है, और Homeport भी उसी रफ़्तार से नया सैंपल माँगता है, इसलिए लोड में बदलाव 30 सेकंड के अंदर चार्ट पर दिखता है। सैंपल तब तक रखे जाते हैं जब तक पेज खुला है, ज़्यादा से ज़्यादा 15 मिनट, चाहे आप किसी भी टैब पर हों, और सिर्फ़ मेमोरी में: पेज बंद करने से पढ़ना रुक जाता है और वे भुला दिए जाते हैं। Homeport मेट्रिक्स का कोई इतिहास नहीं रखता; उसके लिए Prometheus जैसे मॉनिटरिंग सिस्टम का इस्तेमाल करें।
