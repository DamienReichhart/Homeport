### क्या Homeport मुफ़्त है?

हाँ। Homeport निजी और व्यावसायिक काम के लिए इस्तेमाल करने के लिए मुफ़्त है, और [GNU Affero General Public License, version 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE) (AGPL) के तहत ओपन सोर्स है।

### मेरे लिए AGPL का क्या मतलब है?

अगर आप Homeport का इस्तेमाल करते हैं तो कुछ नहीं बदलता: इसे इंस्टॉल करें, घर पर या काम पर चलाएँ, जितने चाहें उतने कंप्यूटर पर। AGPL सिर्फ़ उनसे कुछ माँगता है जो Homeport को, बदला हुआ या नहीं, **वितरित** करते हैं, या बदला हुआ संस्करण दूसरों को नेटवर्क पर पेश करते हैं: उन्हें उसका पूरा सोर्स कोड उसी लाइसेंस के तहत प्रकाशित करना होगा। Homeport की हर कॉपी **सेटिंग्स → लाइसेंस** में अपने सटीक संस्करण के सोर्स से लिंक करती है।

0.11 तक के संस्करण MIT लाइसेंस के तहत जारी किए गए थे और उसी के तहत उपलब्ध रहते हैं।

### क्या Homeport Docker Desktop की जगह लेता है?

पूरी तरह नहीं। Homeport एक मैनेजर है: यह ख़ुद Docker Engine नहीं चलाता। Linux पर, Docker Engine इंस्टॉल करें और Homeport को उसके इंटरफ़ेस के रूप में इस्तेमाल करें। macOS और Windows पर आपको अभी भी इंजन चलाने वाली किसी चीज़ की ज़रूरत है — Docker Desktop, Colima, OrbStack, Rancher Desktop या Podman — और Homeport उनमें से किसी के भी ऊपर, आपके रिमोट सर्वर के साथ, काम कर सकता है।

### क्या यह containerd के साथ काम करता है?

हाँ, सीधे, Docker के बिना: किसी होस्ट का इंजन [containerd](/docs/hosts/containerd/) हो सकता है, जिस तक इस मशीन पर उसके सॉकेट के ज़रिए या SSH पर पहुँचा जाता है — k3s का, Docker Engine का अपना, या किसी सर्वर पर containerd की सर्विस। Homeport उसके नेमस्पेस, उसके कंटेनर और उनके टास्क (शुरू करना, रोकना, विराम देना, सिग्नल भेजना, हटाना), जहाँ nerdctl या Kubernetes ने लिखा वहाँ से उनके लॉग, उनमें टर्मिनल, उसकी इमेज (पुल करना, हटाना) और उसके स्नैपशॉट सूचीबद्ध करता है। यह वहाँ कंटेनर नहीं बनाता या स्टैक डिप्लॉय नहीं करता; यह nerdctl करता है।

### क्या यह Incus के साथ काम करता है?

हाँ: किसी होस्ट का इंजन [Incus](/docs/hosts/incus/) 6.0 या बाद का संस्करण हो सकता है, जिस तक इस मशीन पर उसके सॉकेट के ज़रिए या SSH पर, या `incus config trust add` से मिले ट्रस्ट टोकन के साथ HTTPS पर पहुँचा जाता है। Homeport किसी प्रोजेक्ट के [इंस्टेंस](/docs/guides/instances/), सिस्टम कंटेनर और वर्चुअल मशीन, सूचीबद्ध करता है, उन्हें शुरू करता है, रोकता है, फ़्रीज़ करता है, मिटाता है और बनाता है, उनका कंसोल और उनमें टर्मिनल खोलता है, स्नैपशॉट लेता और रीस्टोर करता है, और इमेज, प्रोफ़ाइल, स्टोरेज पूल और नेटवर्क प्रबंधित करता है। यह वहाँ स्टैक डिप्लॉय नहीं करता, और होस्ट पर कुछ भी इंस्टॉल नहीं करता।

### क्या यह LXD के साथ काम करता है?

सीधे तौर पर नहीं: Homeport Incus बोलता है, जो LXD का कम्युनिटी fork है, और किसी LXD सर्वर को अस्वीकार करता है, जिसका API अलग हो चुका है। उसे `lxd-to-incus` से माइग्रेट करें, फिर उसे Incus होस्ट के रूप में जोड़ें।

### क्या यह Podman के साथ काम करता है?

हाँ, Podman के Docker-संगत API सॉकेट के ज़रिए। Homeport Linux पर सामान्य Podman सॉकेट, हर चल रही [macOS पर Podman मशीन](/docs/hosts/local/#macos-पर-podman-मशीन), और Windows पर डिफ़ॉल्ट Podman मशीन pipe पहचानता है। बाकी कुछ भी [हाथ से जोड़ा](/docs/hosts/local/#हाथ-से-सॉकेट-जोड़ना) जा सकता है।

Homeport कनेक्ट होने पर Podman को पहचानता भी है, और फिर उसी सॉकेट पर Podman के अपने API के ज़रिए वह पेश करता है जो सिर्फ़ Podman में है: [पॉड](/docs/guides/podman-pods/), जिन्हें आप सूचीबद्ध कर सकते हैं, शुरू कर सकते हैं, रोक सकते हैं, बना सकते हैं और हटा सकते हैं, और रन डायलॉग से उनमें कंटेनर चला सकते हैं; और [Quadlet यूनिट](/docs/guides/quadlet/), जिन्हें आप सूचीबद्ध कर सकते हैं, पढ़ सकते हैं, इंस्टॉल कर सकते हैं, संपादित कर सकते हैं और हटा सकते हैं, और SSH पर शुरू या रोक सकते हैं।

### क्या यह Kubernetes, Nomad या Docker Swarm के साथ काम करता है?

Docker Swarm, हाँ। Homeport किसी Swarm को उसके मैनेजर होस्ट के ज़रिए ढूँढता है, जब उनमें से कोई एक होस्ट हो, और उसे पूरी तरह प्रबंधित करता है: उसके नोड, सर्विस, टास्क, secrets, configs और swarm स्टैक, उस पर डिप्लॉय किए गए प्रबंधित, लिंक्ड और सिंक्ड स्टैक सहित। यह किसी होस्ट पर Swarm शुरू भी कर सकता है, और किसी Swarm में शामिल हो सकता है या उसे छोड़ सकता है। सब कुछ किसी कनेक्ट किए गए मैनेजर के Engine API से होता है; नोड पर कुछ भी इंस्टॉल नहीं किया जाता। [Swarm](/docs/guides/swarm/) देखें।

Kubernetes, हाँ। अपने kubeconfig से कोई क्लस्टर जोड़ें — इस कंप्यूटर का या कोई जिसे आप पेस्ट करें — और Homeport आपके लिए लोकल क्लस्टर (Docker Desktop, OrbStack, Rancher Desktop, kind, k3d, minikube) ढूँढता है। EKS, GKE और AKS उस exec प्लगइन के ज़रिए काम करते हैं जिसका नाम उनका kubeconfig देता है। आप Namespace, वर्कलोड, Pod, Service, Ingress, ConfigMap, Secret, Node, Event और कोई भी दूसरा API रिसोर्स, कस्टम सहित, लाइव ब्राउज़ कर सकते हैं; लॉग फ़ॉलो कर सकते हैं, किसी Pod में टर्मिनल खोल सकते हैं, पोर्ट फ़ॉरवर्ड कर सकते हैं, स्केल, रीस्टार्ट और डिलीट कर सकते हैं, और प्रीव्यू के साथ YAML लागू या संपादित कर सकते हैं। क्लस्टर पर कुछ भी इंस्टॉल नहीं किया जाता: Homeport सिर्फ़ उसी Kubernetes API से बात करता है जिस तक आपका kubeconfig पहले से पहुँचता है, उसके क्रेडेंशियल के अधिकारों के साथ। इस कंप्यूटर पर `helm` CLI होने पर, Homeport [Helm रिलीज़](/docs/clusters/helm/) को सूचीबद्ध, इंस्टॉल, अपग्रेड, रोल बैक और अनइंस्टॉल भी करता है, और helm की चार्ट रिपॉज़िटरी प्रबंधित करता है। [क्लस्टर](/docs/clusters/) देखें।

Nomad, हाँ। किसी क्लस्टर को उसके agent के पते से जोड़ें, ACL टोकन और TLS सामग्री के साथ जब वह उनका इस्तेमाल करता हो। आप job और उनके allocation लाइव सूचीबद्ध कर सकते हैं; Nomad का plan देखने के बाद HCL या JSON से कोई job चला सकते हैं; किसी job को संपादित करके फिर से चला सकते हैं, उसे रोक या purge कर सकते हैं, और उसके task group स्केल कर सकते हैं; किसी task के लॉग फ़ॉलो कर सकते हैं और उसमें शेल खोल सकते हैं; client node ड्रेन कर सकते हैं और उनकी eligibility बदल सकते हैं; और एक namespace चुन सकते हैं। क्लस्टर पर कुछ भी इंस्टॉल नहीं किया जाता और किसी `nomad` CLI की ज़रूरत नहीं होती: Homeport टोकन के अधिकारों के साथ Nomad के HTTP API से बात करता है। [Nomad क्लस्टर](/docs/clusters/nomad/) देखें।

### क्या मुझे kubectl चाहिए?

नहीं। Homeport आपका kubeconfig पढ़ता है और ख़ुद Kubernetes API से बात करता है। यह सिर्फ़ वे [exec प्लगइन](/docs/clusters/exec-plugins/) चलाता है जिनका नाम kubeconfig देता है, जैसे EKS के लिए AWS CLI, GKE के लिए `gke-gcloud-auth-plugin` या AKS के लिए `kubelogin` — वही जो `kubectl` चलाता। फिर भी `kubectl` पास होने से यह जाँचने में मदद मिलती है कि आपके क्रेडेंशियल क्या कर सकते हैं (`kubectl auth can-i`)।

### क्या मुझे अपने सर्वर पर कुछ इंस्टॉल करना होगा?

नहीं — सिर्फ़ एक Docker Engine और एक SSH सर्वर, जो शायद आपके पास पहले से हैं। Homeport agent इंस्टॉल नहीं करता।

Swarm को भी इंजन के अलावा कुछ नहीं चाहिए। हालाँकि उसके नोड को एक-दूसरे तक पहुँचना चाहिए, जिसे Homeport आपके लिए सेट अप नहीं कर सकता: उनके बीच 2377/tcp (मैनेजर तक), 7946/tcp और 7946/udp, और 4789/udp खोलें। [नोड के बीच पोर्ट](/docs/guides/swarm/#नोड-के-बीच-पोर्ट) देखें।

### क्या रिमोट सर्वर प्रबंधित करने के लिए मेरे कंप्यूटर पर Docker इंस्टॉल होना चाहिए?

नहीं। Homeport ख़ुद Engine API और SSH बोलता है। सिर्फ़ अपवाद हैं प्रबंधित, लिंक्ड और सिंक्ड स्टैक डिप्लॉय करना, जो आपके कंप्यूटर पर `docker compose` कमांड का इस्तेमाल करता है, और उन्हें किसी Swarm पर डिप्लॉय करना, जो `docker` कमांड (`docker stack deploy`) का इस्तेमाल करता है। दोनों में से किसी को भी आपके कंप्यूटर पर इंजन की ज़रूरत नहीं है।

### क्या Homeport बंद होने पर मेरे स्टैक सिंक रखता है?

नहीं। [सिंक्ड स्टैक](/docs/guides/synced-stacks/) की नए कमिट के लिए जाँच, और अगर आप इसे चालू करें तो अपने-आप डिप्लॉय, सिर्फ़ तब होता है जब Homeport खुला हो। Homeport आपके सर्वर पर कुछ भी इंस्टॉल नहीं करता — न agent, न webhook receiver — इसलिए जब यह बंद होता है, तो आपकी रिपॉज़िटरी पर कोई नज़र नहीं रखता। जब आप इसे फिर से खोलते हैं, तो यह एक अंतराल तक इंतज़ार करता है, फिर सभी को जाँचता है। जिन डिप्लॉय को चौबीसों घंटे हर push का पालन करना है, उन्हें अपने CI से चलाएँ।

Homeport को उसकी विंडो के बिना चलता रखने के लिए, [सेटिंग्स → डेस्कटॉप](/docs/guides/settings/#डेस्कटॉप) में **बंद करने पर सिस्टम ट्रे में रखें**, और **ट्रे में छिपा हुआ शुरू करें** के साथ **लॉगिन पर शुरू करें** चालू करें।

### क्या Homeport मुझे बता सकता है कि कोई कंटेनर कब क्रैश होता है?

हाँ, जब तक यह चल रहा है — सिस्टम ट्रे में छिपे रहते हुए भी। जब कोई कंटेनर किसी त्रुटि के साथ रुकता है, मेमोरी ख़त्म हो जाती है या unhealthy हो जाता है, और जब कोई होस्ट पहुँच से बाहर हो जाता है या वापस आता है, तो यह एक OS सूचना दिखाता है। हर प्रकार को [सेटिंग्स → सूचनाएँ](/docs/guides/settings/#सूचनाएँ) में बंद किया जा सकता है। यह यह जानकारी उस इवेंट स्ट्रीम से लेता है जो इसके पास पहले से हर होस्ट के साथ है, इसलिए आपके सर्वर पर कुछ भी इंस्टॉल नहीं होता; जब Homeport नहीं चल रहा होता, तो किसी को नहीं बताया जाता।

### क्या Homeport को git चाहिए?

सिर्फ़ [सिंक्ड स्टैक](/docs/guides/synced-stacks/) के लिए, जो आपके कंप्यूटर पर इंस्टॉल `git` चलाते हैं, हर रिपॉज़िटरी की अपनी डिप्लॉय कुंजी या टोकन के साथ। **सेटिंग्स → यह मशीन** बताता है कि Homeport को यह मिला या नहीं। आपका अपना git कॉन्फ़िगरेशन, credential helper और SSH कुंजियाँ कभी इस्तेमाल नहीं होतीं।

### क्या कई लोग Homeport के होस्ट साझा कर सकते हैं?

हर व्यक्ति अपने होस्ट और कुंजियों के साथ अपना Homeport चलाता है। हर व्यक्ति और हर सर्वर के लिए Homeport की बनाई एक कुंजी के साथ, आप `authorized_keys` में हर एक की पहुँच देख और रद्द कर सकते हैं।

### क्या मैं Homeport को दूसरे कंप्यूटर पर ले जा सकता हूँ?

हाँ, दो तरीक़ों से:

- **सब कुछ**: **सेटिंग्स → डेटा → बैकअप लें…** हर होस्ट, क्लस्टर, स्टैक, रजिस्ट्री लॉगिन, रिपॉज़िटरी और सेटिंग को, उनके सीक्रेट के साथ, कम से कम 12 अक्षरों के पासफ़्रेज़ से सुरक्षित एक फ़ाइल में सहेजता है। नए कंप्यूटर पर, उसी जगह **रीस्टोर करें…** उसे खोलता है, सूचीबद्ध करता है कि उसमें क्या है, और वहाँ मौजूद चीज़ों को बदल देता है। सब कुछ आपसे फिर से कोई कुंजी या पासवर्ड माँगे बिना कनेक्ट और डिप्लॉय होता है। [बैकअप लेना और रीस्टोर करना](/docs/guides/settings/#बैकअप-लेना-और-रीस्टोर-करना) देखें।
- **कुछ होस्ट**: **होस्ट** पेज पर, अपने चुने हुए होस्ट को **एक्सपोर्ट करें**, और दूसरे कंप्यूटर पर उन्हें **इम्पोर्ट करें**, उसके पहले से मौजूद होस्ट के साथ। [दूसरे कंप्यूटर पर ले जाना](/docs/reference/security/#दूसरे-कंप्यूटर-पर-ले-जाना) देखें।

`homeport.db` कॉपी करना सीक्रेट के लिए काम नहीं करता: वे इस कंप्यूटर के कीचेन में रखी एक कुंजी से एन्क्रिप्ट किए जाते हैं, और कहीं और **क्रेडेंशियल खो गए** के रूप में दिखते हैं।

### क्या बैकअप में मेरे कंटेनर और वॉल्यूम शामिल होते हैं?

नहीं। बैकअप में वह होता है जो Homeport रखता है — आपके होस्ट तक कैसे पहुँचें, आपके स्टैक की परिभाषाएँ और परिवेश, लॉगिन और सेटिंग्स — न कि वह जो आपके होस्ट पर चलता है। आपके कंटेनर, इमेज और वॉल्यूम होस्ट पर रहते हैं। किसी वॉल्यूम का डेटा कॉपी करने के लिए, वॉल्यूम पेज से [उसका बैकअप एक फ़ाइल में लें](/docs/guides/volumes-networks/#बैकअप-लेना-और-रीस्टोर-करना)।

### क्या Homeport इमेज बना सकता है?

हाँ, दो जगहों पर। **इमेज** पेज इस कंप्यूटर के किसी फ़ोल्डर से इमेज बनाता है। और एक [लिंक्ड स्टैक](/docs/guides/stacks/#लिंक्ड-स्टैक) — ऐसा स्टैक जिसकी compose फ़ाइलें इस कंप्यूटर के किसी फ़ोल्डर में हैं — `build:` का इस्तेमाल कर सकता है: Homeport उस फ़ोल्डर में `docker compose` चलाता है, इसलिए बिल्ड context वहाँ से होस्ट के इंजन को भेजा जाता है, जो उसे बनाता है। कोड में बदलाव के बाद **फिर से बिल्ड करें और डिप्लॉय करें** फिर से बनाता है। प्रबंधित स्टैक बिल्ड नहीं कर सकता, क्योंकि Homeport के पास सिर्फ़ उसका YAML होता है और बनाने के लिए कोई फ़ोल्डर नहीं होता: इसके बजाय फ़ोल्डर लिंक करें, या इमेज को किसी रजिस्ट्री पर पुश करें।

### मेरा स्टैक मेरे दूसरे कंप्यूटर पर बाहरी क्यों दिखता है?

किसी फ़ोल्डर में `docker compose up` से शुरू किया गया स्टैक सिर्फ़ ऐसे कंप्यूटर पर [लिंक्ड](/docs/guides/stacks/#लिंक्ड-स्टैक-कैसे-खोजे-जाते-हैं) दिखता है जहाँ वह फ़ोल्डर और उसकी compose फ़ाइलें उसी पाथ पर मौजूद हों, और चल रही सर्विस को परिभाषित करती हों। दूसरे कंप्यूटर पर वह पाथ मौजूद नहीं होता, इसलिए Homeport के पास उसकी कोई compose फ़ाइल नहीं होती और वह उसे बाहरी दिखाता है। उसे वहाँ से भी प्रबंधित करने के लिए, प्रोजेक्ट को उस कंप्यूटर पर क्लोन करें और **नया स्टैक → इस कंप्यूटर का कोई फ़ोल्डर इस्तेमाल करें** से उसे लिंक करें, या उसे प्रबंधित स्टैक के रूप में अपनाएँ।

### क्या Homeport मेरे बारे में डेटा इकट्ठा करता है?

नहीं। कोई अकाउंट, टेलीमेट्री या एनालिटिक्स नहीं है। Homeport आपके कंप्यूटर से अपने-आप जो एकमात्र अनुरोध करता है, वह अपडेट जाँच है, जो इस वेबसाइट से एक छोटी फ़ाइल डाउनलोड करती है और आपके बारे में कुछ नहीं भेजती; आप इसे **सेटिंग्स → अपडेट** में बंद कर सकते हैं। अलग से, नई इमेज की जाँच हर होस्ट के इंजन के ज़रिए आपकी इमेज की रजिस्ट्री से पूछती है कि उनके टैग किस संस्करण की ओर इंगित करते हैं; लोकल होस्ट के लिए वह अनुरोध भी आपके कंप्यूटर से जाता है। [सुरक्षा और आपका डेटा](/docs/reference/security/#homeport-किससे-कनेक्ट-होता-है) देखें।

### क्या Homeport मेरी प्राइवेट रजिस्ट्री का इस्तेमाल कर सकता है?

हाँ। **सेटिंग्स → रजिस्ट्री** में हर रजिस्ट्री के लिए एक लॉगिन जोड़ें — Docker Hub, GHCR या आपकी अपनी। Homeport इसे किसी भी होस्ट पर पुल, पुश और बिल्ड करने के लिए इंजन को देता है, और डिप्लॉय करने से पहले इसके साथ किसी प्रबंधित, लिंक्ड या सिंक्ड स्टैक की इमेज पुल करता है। पासवर्ड और टोकन आपके OS कीचेन से एन्क्रिप्ट किए जाते हैं। Homeport इस कंप्यूटर पर `docker login` के लॉगिन नहीं पढ़ता।

### Homeport को कैसे पता चलता है कि कोई नई इमेज मौजूद है?

यह होस्ट के इंजन के ज़रिए इमेज की रजिस्ट्री से पूछता है कि टैग अभी किस digest की ओर इंगित करता है, और उसकी तुलना उस digest से करता है जिसे होस्ट ने पुल किया था। कुछ भी डाउनलोड नहीं होता, लेकिन Docker Hub हर सवाल को अपनी pull rate limit में गिनता है, किसी ऐसे `docker pull` की तरह जिसे कुछ नया नहीं मिलता। इसलिए Homeport हर जवाब को 6 घंटे तक रखता है, एक साथ अधिकतम चार रजिस्ट्री से पूछता है, और जल्दी सिर्फ़ तब पूछता है जब आप **नई इमेज जाँचें** चुनते हैं। **सेटिंग्स → रजिस्ट्री** में Docker Hub लॉगिन सीमा बढ़ा देता है। अगर किसी रजिस्ट्री तक पहुँचा नहीं जा सकता या वह rate-limit कर रही है, तो Homeport उसकी इमेज के लिए कोई निशान नहीं दिखाता और अपने लॉग में एक लाइन लिखता है।

### मैं अपडेट कैसे करूँ?

Windows, macOS और AppImage पर, नया संस्करण आने पर Homeport आपको बताता है: **इंस्टॉल करें और रीस्टार्ट करें** चुनें। Linux पर, `.deb` और `.rpm` पैकेज Homeport पैकेज रिपॉज़िटरी से आपके बाकी सिस्टम के साथ अपडेट होते हैं। [अपडेट करना](/docs/reference/updating/) देखें।

### क्या Homeport Homebrew, winget, Flathub या AUR पर है?

अभी नहीं। उनकी योजना है; [इंस्टॉलेशन पेज](/docs/installation/#बाद-में-आने-वाले) हर एक के issue से लिंक करता है।

### क्या Homeport मेरी भाषा में उपलब्ध है?

Homeport अंग्रेज़ी, फ़्रेंच, स्पैनिश, जर्मन, इतालवी, ब्राज़ीलियाई पुर्तगाली, रूसी, सरलीकृत चीनी, जापानी, कोरियाई, हिन्दी और अरबी बोलता है, और आपके ऑपरेटिंग सिस्टम की भाषा का पालन करता है, जब तक आप [सेटिंग्स → रूप-रंग](/docs/guides/settings/#रूप-रंग) में कोई भाषा न चुनें। वेबसाइट भी इन सभी भाषाओं में है; दस्तावेज़ का फ़्रेंच में पूरा अनुवाद है, और दूसरी भाषाएँ वहाँ अंग्रेज़ी पेज दिखाती हैं जहाँ अभी अनुवाद मौजूद नहीं है। कोई भाषा जोड़ने के लिए, [योगदान देना](/docs/project/contributing/#homeport-का-अनुवाद-करना) देखें।

### क्या Homeport सुलभ है?

इसका इस्तेमाल सिर्फ़ कीबोर्ड से किया जा सकता है, यह आपके सिस्टम की कम मोशन सेटिंग का पालन करता है, WCAG 2.2 AA कंट्रास्ट पूरा करता है, और हर पेज की स्वचालित सुलभता टूल से जाँच की जाती है। स्क्रीन रीडर का एक व्यावहारिक ऑडिट चल रहा है। क्या काम करता है, ज्ञात सीमाएँ और किसी बाधा की रिपोर्ट कैसे करें, इसके लिए [कीबोर्ड और सुलभता](/docs/reference/accessibility/) देखें।

### क्या कोई कमांड-लाइन इंटरफ़ेस है?

नहीं — Homeport एक डेस्कटॉप ऐप है। आपका मौजूदा `docker` CLI इसके साथ काम करता है, और जब आप टर्मिनल से चीज़ें बदलते हैं तो Homeport लाइव अपडेट होता है।

[GitHub issues](https://github.com/DamienReichhart/Homeport/issues) में बग की रिपोर्ट करें और सुविधाएँ सुझाएँ, या [योगदान देना](/docs/project/contributing/) देखें।
