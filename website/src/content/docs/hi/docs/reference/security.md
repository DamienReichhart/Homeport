Homeport ऐसे क्रेडेंशियल रखता है जो आपके सर्वर खोलते हैं। यह पेज ठीक-ठीक बताता है कि यह क्या रखता है, और कैसे।

## Homeport क्या सहेजता है

सब कुछ आपके यूज़र के ऐप्लिकेशन डेटा फ़ोल्डर में एक SQLite डेटाबेस, `homeport.db`, में रहता है:

| सिस्टम  | फ़ोल्डर                                           |
| ------- | ------------------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/`                |
| macOS   | `~/Library/Application Support/com.homeport.app/` |
| Windows | `%APPDATA%\com.homeport.app\`                     |

इसमें होता है:

| डेटा                                                            | कैसे सहेजा जाता है |
| --------------------------------------------------------------- | ------------------ |
| होस्ट के नाम, पते, SSH यूज़र और सॉकेट पाथ                       | सादा टेक्स्ट       |
| SSH पब्लिक कुंजियाँ और वे सर्वर कुंजियाँ जिन पर आपने भरोसा किया | सादा टेक्स्ट       |
| SSH निजी कुंजियाँ और उनके पासफ़्रेज़                            | **एन्क्रिप्टेड**   |
| TLS CA प्रमाणपत्र, क्लाइंट प्रमाणपत्र और कुंजियाँ               | **एन्क्रिप्टेड**   |
| Incus होस्ट की क्लाइंट कुंजियाँ और पिन किए गए प्रमाणपत्र        | **एन्क्रिप्टेड**   |
| प्रबंधित स्टैक की compose फ़ाइलें                               | सादा टेक्स्ट       |
| प्रबंधित स्टैक के परिवेश                                        | **एन्क्रिप्टेड**   |
| लिंक्ड स्टैक के फ़ोल्डर और compose फ़ाइल पाथ                    | सादा टेक्स्ट       |
| डिप्लॉय इतिहास: compose फ़ाइलें और profiles                     | सादा टेक्स्ट       |
| डिप्लॉय इतिहास: परिवेश                                          | **एन्क्रिप्टेड**   |
| रजिस्ट्री के पते और यूज़र नाम                                   | सादा टेक्स्ट       |
| रजिस्ट्री पासवर्ड और एक्सेस टोकन                                | **एन्क्रिप्टेड**   |
| रिपॉज़िटरी URL, डिप्लॉय कुंजियों के पब्लिक हिस्से               | सादा टेक्स्ट       |
| रिपॉज़िटरी की वे सर्वर कुंजियाँ जिन पर आपने भरोसा किया          | सादा टेक्स्ट       |
| रिपॉज़िटरी की डिप्लॉय कुंजियाँ और एक्सेस टोकन                   | **एन्क्रिप्टेड**   |
| क्लस्टर के नाम, API सर्वर URL और namespace                      | सादा टेक्स्ट       |
| हर क्लस्टर कैसे साइन इन करता है, उसका kubeconfig context        | सादा टेक्स्ट       |
| क्लस्टर CA, क्लाइंट प्रमाणपत्र और कुंजियाँ                      | **एन्क्रिप्टेड**   |
| क्लस्टर टोकन, पासवर्ड और OIDC टोकन                              | **एन्क्रिप्टेड**   |
| Exec प्लगइन के कमांड, आर्ग्युमेंट और परिवेश                     | **एन्क्रिप्टेड**   |
| आपकी थीम, आख़िरी चुनाव और हर क्लस्टर का namespace               | सादा टेक्स्ट       |
| इवेंट पेज के लिए, हर होस्ट के इंजन के इवेंट                     | सादा टेक्स्ट       |

Homeport आपके इंजन से और कुछ भी कॉपी नहीं करता: कंटेनर, इमेज, वॉल्यूम और लॉग लाइव पढ़े जाते हैं और कभी सहेजे नहीं जाते, सिवाय तब जब आप ख़ुद लॉग या फ़ाइलें डाउनलोड करें, या किसी वॉल्यूम का बैकअप लें। यह इंजन के जो इवेंट रखता है — किस कंटेनर, इमेज, वॉल्यूम या नेटवर्क के साथ क्या हुआ, उनके लेबल के साथ — वे डिफ़ॉल्ट रूप से 30 दिन तक रखे जाते हैं ([सेटिंग्स → डेटा](/docs/guides/settings/#डेटा)), हर होस्ट के लिए अधिकतम 10,000, और अपने होस्ट के साथ या **इतिहास साफ़ करें** से हटा दिए जाते हैं।

### लिंक्ड स्टैक के फ़ोल्डर

किसी [लिंक्ड स्टैक](/docs/guides/stacks/#लिंक्ड-स्टैक) के लिए, Homeport सिर्फ़ यह सहेजता है कि उसका फ़ोल्डर और compose फ़ाइलें कहाँ हैं, और फ़ाइलों का एक फ़िंगरप्रिंट ताकि पता चले कि वे कब बदलती हैं — कभी उनकी कॉपी नहीं। जब आप स्टैक खोलते हैं तो यह compose फ़ाइलें पढ़ता है, और उनमें सिर्फ़ तब लिखता है जब आप उसके **परिभाषा** टैब में **सहेजें** चुनते हैं, हर संपादित फ़ाइल को एक ही क़दम में बदलते हुए और उसकी अनुमतियाँ बनाए रखते हुए; आपके खोलने के बाद बदली हुई फ़ाइल को यह तब तक ओवरराइट नहीं करता जब तक आप न कहें। Homeport कभी फ़ोल्डर की `.env` नहीं पढ़ता या उसमें नहीं लिखता: Compose चलते समय उसे पढ़ता है। किसी लिंक्ड स्टैक को भुलाने से फ़ोल्डर को कभी छुआ नहीं जाता।

### रिपॉज़िटरी

[सिंक्ड स्टैक](/docs/guides/synced-stacks/) के लिए, Homeport हर रिपॉज़िटरी का URL रखता है, और या तो उस रिपॉज़िटरी के लिए बनाई गई एक डिप्लॉय कुंजी (उसका निजी हिस्सा एन्क्रिप्टेड) या आपका यूज़र नाम और एक एक्सेस टोकन (एन्क्रिप्टेड)। किसी रिपॉज़िटरी का कंटेंट सीक्रेट नहीं है: उसका क्लोन `homeport.db` के बगल में एक `repositories` फ़ोल्डर में रहता है।

### Swarm

Homeport किसी [Swarm](/docs/guides/swarm/) के बारे में कुछ नहीं सहेजता: यह हर बार कनेक्ट होने पर उसे उसके मैनेजर होस्ट के ज़रिए ढूँढता है। Swarm secret के मान Swarm को जाते हैं और Homeport उन्हें नहीं रखता: आपका टाइप किया या किसी फ़ाइल से लोड किया गया मान एक बार इंजन को भेजा जाता है, कभी `homeport.db`, किसी फ़ाइल या लॉग में नहीं लिखा जाता, और डायलॉग बंद होने पर मेमोरी से हटा दिया जाता है। इंजन कभी किसी secret का मान वापस नहीं भेजता, इसलिए Homeport भी उसे नहीं दिखा सकता। Join टोकन ज़रूरत पड़ने पर किसी मैनेजर से लाए जाते हैं, और कभी सहेजे या लॉग नहीं किए जाते।

### क्लस्टर

किसी [क्लस्टर](/docs/clusters/) के क्रेडेंशियल आपके kubeconfig से आते हैं और SSH कुंजियों की तरह सिर्फ़ एन्क्रिप्ट करके सहेजे जाते हैं; kubeconfig जिन फ़ाइलों का ज़िक्र करता है वे एक बार पढ़ी जाती हैं और inline की जाती हैं, पेस्ट किया गया kubeconfig कभी किसी फ़ाइल में नहीं लिखा जाता, और आपका kubeconfig कभी बदला नहीं जाता। कोई [exec प्लगइन](/docs/clusters/exec-plugins/) इस कंप्यूटर पर, आपके रूप में, चलता है, और जो टोकन या प्रमाणपत्र वह प्रिंट करता है वह सिर्फ़ मेमोरी में, उसके समाप्त होने तक, रखा जाता है। Homeport किसी क्लस्टर पर चलने वाली चीज़ों के बारे में और कुछ नहीं सहेजता: Pod, वर्कलोड और बाकी सब लाइव पढ़े जाते हैं। [पोर्ट फ़ॉरवर्ड](/docs/clusters/port-forward/) सिर्फ़ इस कंप्यूटर के loopback (`127.0.0.1` और `::1`) पर सुनते हैं, इसलिए आपके नेटवर्क पर कोई और उनका इस्तेमाल नहीं कर सकता, और Homeport बंद होने पर वे ख़त्म हो जाते हैं। [Apply YAML या Edit](/docs/clusters/yaml/) से किए गए बदलाव क्लस्टर पर field manager `homeport` के तहत दर्ज होते हैं।

[Helm](/docs/clusters/helm/) आपके kubeconfig के बिना और किसी भी क्लस्टर क्रेडेंशियल को डिस्क पर लिखे बिना किसी क्लस्टर पर आपका `helm` CLI चलाता है: हर कमांड के लिए, Homeport इस कंप्यूटर के loopback (`127.0.0.1`, एक रैंडम पोर्ट) पर एक निजी कनेक्शन खोलता है जो सिर्फ़ एक रैंडम टोकन वाले अनुरोध स्वीकार करता है, और helm को एक अस्थायी kubeconfig देता है, जिसे सिर्फ़ आप पढ़ सकते हैं, जिसमें वह टोकन और कुछ नहीं होता। Homeport रास्ते में हर अनुरोध में क्लस्टर के अपने क्रेडेंशियल जोड़ता है, और कमांड ख़त्म होने पर kubeconfig मिटा देता है और कनेक्शन बंद कर देता है। चार्ट के मान helm को उसके standard input पर जाते हैं, कभी किसी फ़ाइल में नहीं। helm की अपनी चार्ट रिपॉज़िटरी, रजिस्ट्री लॉगिन और कैश helm के ही रहते हैं, जैसे टर्मिनल में; Homeport सिर्फ़ पब्लिक रिपॉज़िटरी जोड़ता है और कोई रिपॉज़िटरी पासवर्ड नहीं सहेजता।

किसी [Nomad क्लस्टर](/docs/clusters/nomad/) का ACL टोकन, CA प्रमाणपत्र, क्लाइंट प्रमाणपत्र और कुंजी SSH कुंजियों की तरह सिर्फ़ एन्क्रिप्ट करके सहेजे जाते हैं; उसका पता, region और TLS server name सादे रूप में रखे जाते हैं। टोकन हर अनुरोध के `X-Nomad-Token` हेडर में जाता है, कभी किसी URL में नहीं, शेल के WebSocket सहित। Homeport किसी job के स्पेसिफ़िकेशन की कोई कॉपी नहीं रखता: Nomad उसे job के साथ सहेजता है।

**Kubernetes Secret के मान** सिर्फ़ तब लाए जाते हैं जब आप किसी एक key के लिए **दिखाएँ** चुनते हैं, एक बार में एक: सूचियाँ, किसी Secret का पेज और उसका YAML उसकी key और आकार दिखाते हैं, कभी उसके मान नहीं। दिखाया गया मान उस पेज की मेमोरी में रहता है — किसी कैश में नहीं, `homeport.db` में नहीं, लॉग में नहीं — और पेज छोड़ने पर फिर से छिप जाता है।

## सीक्रेट कैसे एन्क्रिप्ट किए जाते हैं

- हर सीक्रेट अलग से **XChaCha20-Poly1305** से सील किया जाता है, जो एक authenticated cipher है, इसलिए पढ़ने से रोकने के साथ-साथ छेड़छाड़ का भी पता चलता है।
- 256-बिट कुंजी रैंडम होती है, पहले लॉन्च पर बनती है, और आपके **OS कीचेन** — macOS Keychain, Windows Credential Manager, या Linux पर Secret Service — में `com.homeport.app` सर्विस के तहत रखी जाती है। यह कभी डेटा के बगल में नहीं सहेजी जाती।
- कोई मास्टर पासवर्ड नहीं है: कीचेन पहले से कुंजी को आपके यूज़र अकाउंट से जोड़ता है।

जिसके पास सिर्फ़ `homeport.db` की कॉपी है, वह होस्ट और क्लस्टर के नाम और पते पढ़ सकता है, लेकिन आपकी कुंजियाँ, प्रमाणपत्र, टोकन, स्टैक के परिवेश या रजिस्ट्री पासवर्ड नहीं।

### कीचेन के बिना

Homeport एक बैनर दिखाता है और सीक्रेट नहीं सहेजता। लोकल सॉकेट, TCP और ssh-agent होस्ट फिर भी काम करते हैं। [आवश्यकताएँ](/docs/requirements/#वैकल्पिक-os-कीचेन) देखें।

### अगर कीचेन की कुंजी खो जाए

कीचेन रीसेट करने, या `homeport.db` को किसी दूसरे कंप्यूटर या यूज़र पर ले जाने से ऐसे सीक्रेट बचते हैं जिन्हें डिक्रिप्ट नहीं किया जा सकता। Homeport कुछ भी नहीं मिटाता: प्रभावित होस्ट तब तक **क्रेडेंशियल खो गए** दिखाते हैं जब तक आप उनके क्रेडेंशियल फिर से दर्ज नहीं करते। [समस्या निवारण](/docs/reference/troubleshooting/#क्रेडेंशियल-खो-गए) देखें। अपना डेटा ले जाने के लिए, इसके बजाय उसका बैकअप लें या अपने होस्ट एक्सपोर्ट करें।

### दूसरे कंप्यूटर पर ले जाना

होस्ट पेज पर **एक्सपोर्ट करें** आपके चुने हुए होस्ट को, उनकी कुंजियों, प्रमाणपत्रों और भरोसा की गई सर्वर कुंजियों के साथ, एक फ़ाइल में लिखता है, जो आपके चुने हुए पासफ़्रेज़ से एन्क्रिप्ट होती है:

- पूरी फ़ाइल एन्क्रिप्ट की जाती है (XChaCha20-Poly1305, पासफ़्रेज़ से Argon2id द्वारा बनाई गई कुंजी के साथ), इसलिए पासफ़्रेज़ के बिना यह कुछ भी नहीं बताती — होस्ट के नाम या पते भी नहीं। फ़ाइल में कोई भी बदलाव उसे पढ़ने योग्य नहीं रहने देता।
- पासफ़्रेज़ में कम से कम 12 अक्षर चाहिए। Homeport उसे कभी सहेजता या लॉग नहीं करता; अगर आप उसे खो देते हैं, तो फ़ाइल नहीं खोली जा सकती।
- दूसरे कंप्यूटर पर **इम्पोर्ट करें** पासफ़्रेज़ माँगता है, फिर हर होस्ट के सीक्रेट को उस कंप्यूटर की अपनी कीचेन कुंजी के तहत एन्क्रिप्ट करके सहेजता है, किसी भी दूसरे सीक्रेट की तरह।
- जिस होस्ट के क्रेडेंशियल इस कंप्यूटर पर पहले से खो चुके हैं, वह उनके बिना एक्सपोर्ट होता है, और एक्सपोर्ट बताता है कि कौन-से।

फ़ाइल को उन कुंजियों की तरह ही संभालें जो उसमें हैं: इम्पोर्ट होने के बाद उसे मिटा दें। फ़ॉर्मेट [ADR 0013](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0013-passphrase-protected-export-bundles.md) में बताया गया है।

### बैकअप

**सेटिंग्स → डेटा → बैकअप लें…** ऊपर की हर चीज़ — होस्ट, क्लस्टर, स्टैक, रजिस्ट्री लॉगिन, रिपॉज़िटरी और सेटिंग्स, उनके सीक्रेट खोलकर — उसी एन्क्रिप्टेड फ़ॉर्मेट में एक फ़ाइल में लिखता है, एक ऐसे पासफ़्रेज़ के साथ जिसे आप दो बार टाइप करते हैं। इंजन के इवेंट और डिप्लॉय इतिहास शामिल नहीं होते। जो सीक्रेट इस कंप्यूटर पर नहीं खोला जा सकता, वह छोड़ दिया जाता है, और बैकअप बताता है कि कौन-सा।

**रीस्टोर करें…** पासफ़्रेज़ माँगता है और कुछ भी बदलने से पहले सूचीबद्ध करता है कि फ़ाइल में क्या है। फिर रीस्टोर करना:

1. मौजूदा डेटाबेस को `homeport.db` के बगल में `homeport.db.before-restore-<date and time>` में कॉपी करता है;
2. हर होस्ट, क्लस्टर, स्टैक, लॉगिन, रिपॉज़िटरी और सेटिंग को एक ही क़दम में बदलता है, ताकि कोई विफलता आपके डेटा को जैसा था वैसा ही छोड़े;
3. हर सीक्रेट को इस कंप्यूटर की कीचेन कुंजी से फिर से एन्क्रिप्ट करता है।

किसी नए Homeport से बनाया गया बैकअप अस्वीकार कर दिया जाता है; किसी पुराने Homeport से बनाया गया बैकअप रीस्टोर हो जाता है। बैकअप में वह हर सीक्रेट होता है जो Homeport के पास है: उसे, और उसके पासफ़्रेज़ को, ख़ुद कुंजियों जितना सुरक्षित रखें।

## कुंजियाँ कभी सादे रूप में डिस्क को नहीं छूतीं

Homeport का अपना SSH क्लाइंट है, इसलिए यह `ssh` के पढ़ने के लिए कभी कोई निजी कुंजी किसी फ़ाइल में नहीं लिखता, और कभी `~/.ssh` नहीं बदलता। डिक्रिप्ट की गई कुंजियाँ मेमोरी में रहती हैं।

जब `docker compose` किसी SSH या TLS होस्ट पर स्टैक डिप्लॉय करता है, तो Homeport इस कंप्यूटर पर एक अल्पकालिक निजी सॉकेट खोलता है — जिसे सिर्फ़ आपका यूज़र पढ़ सकता है, या Windows पर एक named pipe जो रिमोट क्लाइंट को अस्वीकार करता है — और उस एक कमांड के लिए उसे अपने कनेक्शन पर फ़ॉरवर्ड करता है।

रिपॉज़िटरी की कुंजियाँ और टोकन भी कभी डिस्क तक नहीं पहुँचते। हर `git` कमांड के लिए, Homeport एक निजी SSH agent चलाता है जिसमें सिर्फ़ उस रिपॉज़िटरी की डिप्लॉय कुंजी होती है — ऐसे सॉकेट पर जिसे सिर्फ़ आपका यूज़र खोल सकता है, या Windows पर एक named pipe जो रिमोट क्लाइंट को अस्वीकार करता है — या कमांड के परिवेश के ज़रिए HTTPS हेडर में टोकन देता है। आपका अपना git कॉन्फ़िगरेशन, credential helper और SSH कुंजियाँ अलग रखी जाती हैं, इसलिए आपके कीचेन या `~/.git-credentials` में कुछ भी कैश नहीं होता।

रजिस्ट्री लॉगिन भी कभी `docker compose` तक नहीं पहुँचते: Homeport `docker compose up` चलाने से पहले Engine API के ज़रिए ख़ुद स्टैक की इमेज पुल करता है, इसलिए कमांड के परिवेश और उसे दी गई फ़ाइलों में कोई पासवर्ड या टोकन नहीं होता।

## सर्वर पर भरोसा करना

जब Homeport पहली बार किसी SSH सर्वर से कनेक्ट होता है, तो यह आपसे सर्वर की कुंजी के फ़िंगरप्रिंट की पुष्टि करने के लिए कहता है, और अगर वह कुंजी बाद में बदलती है तो जब तक आप फिर से पुष्टि न करें, कनेक्ट होने से इनकार करता है। TLS होस्ट सर्वर के प्रमाणपत्र को आपके CA और सर्वर के नाम से सत्यापित करते हैं; HTTPS पर Incus होस्ट सिर्फ़ वही प्रमाणपत्र स्वीकार करते हैं जिसके साथ उन्हें जोड़ा गया था। [SSH होस्ट](/docs/hosts/ssh/#पहला-कनेक्शन) देखें।

### Incus प्रमाणपत्र

[HTTPS पर Incus होस्ट](/docs/hosts/incus/#ट्रस्ट-टोकन-के-साथ-https-पर) जोड़ने से मेमोरी में एक क्लाइंट प्रमाणपत्र और उसकी निजी कुंजी बनती है, एक ECDSA P-384 कुंजी, और उन्हें होस्ट के दूसरे सीक्रेट के साथ एन्क्रिप्ट करके सहेजा जाता है, कभी डिस्क पर सादे रूप में नहीं। Incus का अपना प्रमाणपत्र भी इसी तरह सहेजा और पिन किया जाता है: Homeport सर्वर से ठीक वही प्रमाणपत्र स्वीकार करता है, उसके SHA-256 फ़िंगरप्रिंट से तुलना करके, और कोई अलग प्रमाणपत्र दोनों फ़िंगरप्रिंट दिखाते हुए अस्वीकार करता है। ट्रस्ट टोकन एक बार इस्तेमाल होता है और रखा नहीं जाता। Homeport की पहुँच रद्द करने के लिए सर्वर पर `incus config trust remove` से उसका प्रमाणपत्र हटाएँ।

## Homeport किससे कनेक्ट होता है

- **आपके जोड़े हुए होस्ट।** जब आप कोई इमेज पुल, पुश या बिल्ड करते हैं, तो इंजन रजिस्ट्री से संपर्क करता है, Homeport नहीं। Homeport अनुरोध के साथ, होस्ट के कनेक्शन पर, उस रजिस्ट्री का सहेजा गया लॉगिन इंजन को देता है; इंजन उसे नहीं रखता।
- **हर होस्ट के इंजन के ज़रिए आपकी इमेज की रजिस्ट्री**, यह जानने के लिए कि कोई [नई इमेज](/docs/guides/containers/#नई-इमेज) प्रकाशित हुई है या नहीं: जब कंटेनर, इमेज या स्टैक पेज लोड होता है (हर जवाब 6 घंटे तक रखा जाता है) और जब आप **नई इमेज जाँचें** चुनते हैं। इंजन रजिस्ट्री से वह digest पूछता है जिसकी ओर कोई टैग इंगित करता है, प्राइवेट रजिस्ट्री के लिए सहेजे गए लॉगिन के साथ, और कुछ भी डाउनलोड नहीं करता। लोकल होस्ट के लिए, इंजन आपके कंप्यूटर पर चलता है, इसलिए अनुरोध वहीं से जाता है।
- **Docker Hub, जब आप पुल डायलॉग में टैग ब्राउज़ करते हैं**: Homeport इस कंप्यूटर से, `hub.docker.com` से किसी रिपॉज़िटरी के टैग सूचीबद्ध करता है, अगर Docker Hub लॉगिन सहेजा हो तो उसके साथ। रिपॉज़िटरी खोजना इसके बजाय होस्ट के इंजन से होता है।
- **कोई रजिस्ट्री, जब आप उसका लॉगिन जाँचते हैं** **सेटिंग्स → रजिस्ट्री** में: Homeport इस कंप्यूटर से रजिस्ट्री के `/v2/` endpoint, और उसकी टोकन सर्विस से पूछता है, HTTPS पर यूज़र नाम और पासवर्ड या टोकन भेजते हुए (सादा HTTP सिर्फ़ इस कंप्यूटर पर मौजूद रजिस्ट्री के लिए, जैसे `localhost:5000`)।
- **आपकी रिपॉज़िटरी के सर्वर**, [सिंक्ड स्टैक](/docs/guides/synced-stacks/) के लिए: जब आप पहुँच की जाँच करते हैं, कोई सिंक्ड स्टैक बनाते या सिंक करते हैं, और अगर polling चालू है तो Homeport खुले रहते हुए एक अंतराल पर। Homeport इस कंप्यूटर से उस रिपॉज़िटरी की डिप्लॉय कुंजी या टोकन के साथ `git` चलाता है।
- **आपके जोड़े हुए क्लस्टर**, उस Kubernetes API सर्वर के ज़रिए जिसका नाम उनका kubeconfig देता है (और जब हो तो उसके proxy के ज़रिए), उसके दिए क्रेडेंशियल के साथ, सर्वर के प्रमाणपत्र को kubeconfig के CA से जाँचते हुए। Exec प्लगइन इस कंप्यूटर से अपने क्लाउड (AWS, Google Cloud, Azure) से संपर्क करते हैं, जैसे वे `kubectl` के लिए करते हैं।
- **आपके जोड़े हुए Nomad क्लस्टर**, आपके दिए agent पते के ज़रिए, और कुछ नहीं: किसी job के लॉग और शेल उस agent से होकर जाते हैं, जो उन्हें client node तक फ़ॉरवर्ड करता है, इसलिए Homeport कभी ख़ुद node से कनेक्ट नहीं होता। Agent का प्रमाणपत्र आपके दिए CA से, या इस कंप्यूटर के CA से जाँचा जाता है।
- **Incus इमेज सर्वर**, किसी [Incus होस्ट](/docs/guides/instances/#इंस्टेंस-बनाना) पर इमेज चुनने के लिए: Homeport इस कंप्यूटर से किसी सर्वर की इमेज सूची (`streams/v1/images.json`, `images.linuxcontainers.org` से, जब तक आप कोई दूसरा न चुनें) डाउनलोड करता है, और उसे दस मिनट तक रखता है। इमेज ख़ुद Incus डाउनलोड करता है।
- **helm के ज़रिए चार्ट रिपॉज़िटरी और OCI रजिस्ट्री**, जब आप कोई रिपॉज़िटरी जोड़ते या अपडेट करते हैं, चार्ट खोजते हैं, या कोई चार्ट इंस्टॉल या अपग्रेड करते हैं: `helm` इस कंप्यूटर से इंडेक्स और चार्ट डाउनलोड करता है, जैसे टर्मिनल में करता है।
- **यह वेबसाइट, अपडेट जाँचने के लिए**: लॉन्च पर और हर 6 घंटे में, Homeport `updates/latest.json` डाउनलोड करता है, एक छोटी फ़ाइल जो नवीनतम संस्करण बताती है। अनुरोध में आपके, आपके होस्ट या आपके कंटेनर के बारे में कुछ नहीं होता, लेकिन किसी भी वेब अनुरोध की तरह यह आपके IP पते से GitHub Pages तक पहुँचता है, जो इस साइट को होस्ट करता है। इसे **सेटिंग्स → अपडेट** में बंद करें। अपडेट ख़ुद GitHub Releases से डाउनलोड होते हैं, और Homeport किसी अपडेट को सिर्फ़ तब इंस्टॉल करता है जब वह Homeport की अपडेट कुंजी से साइन किया गया हो। [अपडेट करना](/docs/reference/updating/) देखें।

## Homeport आपके होस्ट पर क्या चलाता है

Homeport किसी होस्ट के इंजन से उसके API के ज़रिए बात करता है, और किसी होस्ट के सर्वर पर कमांड सिर्फ़ उन चीज़ों के लिए चलाता है जो वह API नहीं कर सकता:

| कब                                                                                              | कहाँ                                                 | कमांड                                                                                                               |
| ----------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| किसी SSH होस्ट का सर्वर अपना इंजन सॉकेट खोलने से इनकार करता है                                  | SSH सर्वर                                            | एक POSIX शेल जाँच कि सॉकेट मौजूद और पढ़ने योग्य है या नहीं, और कोई इंजन इंस्टॉल है या नहीं                          |
| किसी [Quadlet यूनिट](/docs/guides/quadlet/) को **शुरू करें**, **रोकें** या **फिर से शुरू करें** | SSH सर्वर, या Linux पर लोकल सॉकेट के लिए यह कंप्यूटर | `systemctl [--user] start\|stop\|restart '<unit>.service'`                                                          |
| किसी [containerd कंटेनर के लॉग](/docs/hosts/containerd/#लॉग)                                   | SSH सर्वर, या Linux पर लोकल सॉकेट के लिए यह कंप्यूटर | `tail -n <lines> [-F] -- '<log file>'`, जब CRI फ़ाइल का नाम न दे तो Kubernetes कंटेनर के लॉग फ़ोल्डर के `ls` के बाद |
| किसी [containerd कंटेनर में टर्मिनल](/docs/hosts/containerd/#कंटेनर-में-टर्मिनल)         | SSH सर्वर, या Linux पर लोकल सॉकेट के लिए यह कंप्यूटर | `mktemp -d`, उस फ़ोल्डर में दो FIFO के लिए `mkfifo -m 600`, उनके ज़रिए `cat`, फिर फ़ोल्डर का `rm -rf`               |

वे SSH यूज़र के अधिकारों के साथ (या इस कंप्यूटर पर, आपके अधिकारों के साथ) चलते हैं और कभी `sudo` के साथ नहीं। मान किसी कमांड में जाने से पहले जाँचे और quote किए जाते हैं। Quadlet यूनिट इंस्टॉल करना, संपादित करना और हटाना Podman के API से होता है, जो फ़ाइलें ख़ुद लिखता है। Incus होस्ट पर कुछ नहीं चलता: उसका कंसोल और टर्मिनल Incus के अपने API से होकर जाते हैं। Homeport किसी होस्ट पर जो एकमात्र फ़ाइलें बनाता है, वे containerd टर्मिनल के दो FIFO हैं, एक निजी अस्थायी फ़ोल्डर में जो टर्मिनल बंद होने पर हटा दिया जाता है।

## Homeport क्या कभी नहीं करता

- **कोई अकाउंट नहीं।** साइन अप करने के लिए कुछ नहीं है।
- **कोई टेलीमेट्री, एनालिटिक्स या क्रैश रिपोर्टिंग नहीं।**
- **आपके क्लस्टर पर कुछ भी इंस्टॉल नहीं।** Homeport सिर्फ़ Kubernetes API का इस्तेमाल करता है, आपके क्रेडेंशियल के अधिकारों के साथ, और आपके कहे बिना कुछ नहीं बदलता: जो भी चीज़ कुछ हटाती या बदलती है, वह क्लस्टर का नाम लेते हुए पहले पूछती है।
- **आपके होस्ट पर कुछ भी इंस्टॉल नहीं।** Homeport किसी होस्ट पर जो कमांड चलाता है, वे [ऊपर सूचीबद्ध](#homeport-आपके-होस्ट-पर-क्या-चलाता-है) हैं। Homeport अपनी ओर से जो एकमात्र कंटेनर कभी शुरू करता है, वह एक अल्पकालिक [सहायक कंटेनर](/docs/guides/volumes-networks/#सहायक-कंटेनर) है, जब आप कोई वॉल्यूम खोलते हैं, उसका बैकअप लेते हैं, उसे रीस्टोर या क्लोन करते हैं; उसका कोई नेटवर्क नहीं होता और काम पूरा होने पर उसे हटा दिया जाता है। उसकी इमेज सिर्फ़ आपकी सहमति के बाद पुल की जाती है।
- **कोई चुपचाप इंस्टॉल नहीं।** कोई अपडेट सिर्फ़ तब इंस्टॉल होता है जब आप **इंस्टॉल करें और रीस्टार्ट करें** चुनते हैं; Linux पैकेज सिर्फ़ आपका पैकेज मैनेजर अपडेट करता है।

[गोपनीयता नीति](/privacy/) बताती है कि क़ानूनी रूप से इसका क्या मतलब है: आपके डेटा के लिए कौन ज़िम्मेदार है, किस आधार पर, और अपने अधिकारों का इस्तेमाल कैसे करें।

## लॉग

Homeport समस्याओं के निदान के लिए एक छोटी लॉग फ़ाइल लिखता है — कुछ दर्जन किलोबाइट, भर जाने पर बदल दी जाती है। इसमें कनेक्शन इवेंट और त्रुटियाँ होती हैं, आपके क्रेडेंशियल या कंटेनर आउटपुट नहीं।

| सिस्टम  | फ़ोल्डर                                 |
| ------- | --------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/logs/` |
| macOS   | `~/Library/Logs/com.homeport.app/`      |
| Windows | `%LOCALAPPDATA%\com.homeport.app\logs\` |

## किसी डाउनलोड पर भरोसा करना

रिलीज़ पब्लिक सोर्स कोड से GitHub Actions द्वारा बनाई जाती हैं। हर फ़ाइल के साथ एक SHA-256 चेकसम और एक साइन किया हुआ बिल्ड प्रोवेनेंस अटेस्टेशन आता है, जो उसे उस सटीक कमिट और वर्कफ़्लो से जोड़ता है जिसने उसे बनाया। [डाउनलोड सत्यापित करना](/docs/reference/verifying/) देखें।

## किसी कमज़ोरी की रिपोर्ट करना

कृपया सुरक्षा समस्याओं की रिपोर्ट किसी पब्लिक issue के बजाय निजी तौर पर [GitHub की private vulnerability reporting](https://github.com/DamienReichhart/Homeport/security/advisories/new) के ज़रिए करें।
