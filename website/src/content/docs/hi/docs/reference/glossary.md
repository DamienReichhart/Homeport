---
title: शब्दावली
description: Homeport जिन शब्दों का इस्तेमाल करता है, और उनका क्या मतलब है।
---

Homeport चीज़ों को सटीक नाम देता है। ये शब्द पूरे ऐप और इस दस्तावेज़ में दिखते हैं। हर एंट्री में प्रोडक्ट का अंग्रेज़ी शब्द है, जिसके बाद वह शब्द है जिसका ऐप हिन्दी में इस्तेमाल करता है।

### Host (hi. _होस्ट_)

एक Docker Engine जिससे Homeport कनेक्ट होता है, जिसे एक नाम और उस तक पहुँचने के तरीक़े से परिभाषित किया जाता है: लोकल सॉकेट, TCP, TLS या SSH। हर कंटेनर, इमेज, वॉल्यूम, नेटवर्क और स्टैक ठीक एक होस्ट का होता है। [होस्ट और कनेक्शन](/docs/hosts/) देखें।

### Engine kind (hi. _इंजन का प्रकार_)

होस्ट किस प्रकार के इंजन की ओर इंगित करता है: Docker-संगत (Docker Engine, या अपने संगत API के ज़रिए Podman), containerd या Incus। इससे तय होता है कि होस्ट कौन-से पेज दिखाता है: containerd और Incus होस्ट को अपने ख़ुद के पेज मिलते हैं। Podman अपना अलग प्रकार नहीं है: Homeport हर बार कनेक्ट होने पर उसे पहचानता है। [इंजन के प्रकार](/docs/hosts/#engine-kinds) देखें।

### Namespace (containerd’s) (hi. _नेमस्पेस_)

containerd होस्ट पर, वह जगह जिसमें हर कंटेनर, इमेज और स्नैपशॉट रहता है: nerdctl `default` का इस्तेमाल करता है, Kubernetes `k8s.io` का, Docker `moby` का। containerd होस्ट के पेज एक बार में एक नेमस्पेस दिखाते हैं। किसी क्लस्टर के Namespace Kubernetes वाले होते हैं। [containerd नेमस्पेस](/docs/hosts/containerd/#namespaces) देखें।

### Snapshot (hi. _स्नैपशॉट_)

containerd होस्ट पर, डिस्क पर फ़ाइलों की एक लेयर: अनपैक की गई इमेज की लेयर, या किसी कंटेनर की लिखने योग्य लेयर। [स्नैपशॉट](/docs/hosts/containerd/#snapshots) देखें। Incus होस्ट पर, किसी इंस्टेंस की सहेजी गई स्थिति जिस पर उसे रीस्टोर किया जा सकता है; [इंस्टेंस स्नैपशॉट](/docs/guides/instances/#snapshots) देखें।

### Instance (hi. _इंस्टेंस_)

Incus होस्ट क्या चलाता है: एक सिस्टम कंटेनर, जो होस्ट के kernel पर एक पूरा Linux डिस्ट्रीब्यूशन बूट करता है, या अपने ख़ुद के kernel वाली वर्चुअल मशीन। कंटेनर नहीं, जो एक ऐप्लिकेशन चलाता है। [इंस्टेंस](/docs/guides/instances/) देखें।

### Project (Incus’s) (hi. _प्रोजेक्ट_)

Incus होस्ट पर, वह जगह जिसमें उसके इंस्टेंस, इमेज, प्रोफ़ाइल, कस्टम वॉल्यूम और नेटवर्क रहते हैं। Incus होस्ट के पेज एक बार में एक प्रोजेक्ट दिखाते हैं, जो होस्ट स्विचर के नीचे चुना जाता है। [प्रोजेक्ट](/docs/hosts/incus/#projects) देखें।

### Profile (hi. _प्रोफ़ाइल_)

Incus होस्ट पर, कॉन्फ़िगरेशन और डिवाइस जिन्हें वे इंस्टेंस साझा करते हैं जो इसे सूचीबद्ध करते हैं। [प्रोफ़ाइल](/docs/guides/instances/#profiles) देखें।

### Trust token (hi. _ट्रस्ट टोकन_)

Incus सर्वर पर `incus config trust add` जो प्रिंट करता है, जिसे उस सर्वर को HTTPS पर जोड़ने के लिए एक बार Homeport में पेस्ट किया जाता है। [ट्रस्ट टोकन](/docs/hosts/incus/#over-https-with-a-trust-token) देखें।

### Pod (hi. _Podman पॉड_)

Podman होस्ट पर, कंटेनर का एक समूह जो एक नेटवर्क साझा करते हैं और साथ में शुरू होते और रुकते हैं, एक infra कंटेनर के इर्द-गिर्द जिसमें वे पोर्ट होते हैं जिन्हें पॉड प्रकाशित करता है। किसी क्लस्टर के Pod, Kubernetes Pod होते हैं। [Podman पॉड](/docs/guides/podman-pods/) देखें।

### Quadlet unit (hi. _Quadlet यूनिट_)

Podman होस्ट पर एक फ़ाइल, जैसे `web.container`, जिसे systemd एक सर्विस, `web.service`, में बदलता है, ताकि Podman के कंटेनर बूट पर शुरू हों और systemd उन्हें चलता रखे। [Quadlet यूनिट](/docs/guides/quadlet/) देखें।

### Cluster (hi. _क्लस्टर_)

एक Kubernetes क्लस्टर या Nomad क्लस्टर जिससे Homeport उसके API के ज़रिए कनेक्ट होता है। Kubernetes क्लस्टर किसी kubeconfig के context से जोड़ा जाता है: एक नाम, API सर्वर का पता, और kubeconfig के दिए क्रेडेंशियल, एन्क्रिप्ट करके सहेजे गए। Nomad क्लस्टर उसके किसी agent के पते से जोड़ा जाता है, ACL टोकन और TLS सामग्री के साथ, एन्क्रिप्ट करके सहेजे गए। Homeport दोनों में से किसी पर कुछ इंस्टॉल नहीं करता और सिर्फ़ उसी तक पहुँचता है जिसकी वे क्रेडेंशियल अनुमति देते हैं। Swarm नहीं, जो अपने होस्ट के ज़रिए मिलता है और कभी जोड़ा नहीं जाता। Kubernetes के अपने ऑब्जेक्ट अपने Kubernetes नाम रखते हैं: Namespace, Pod, Deployment, Service, Node… Nomad के ऑब्जेक्ट Nomad के नाम रखते हैं: job, task group, task, allocation, client node, namespace। [क्लस्टर](/docs/clusters/) और [Nomad क्लस्टर](/docs/clusters/nomad/) देखें।

### Allocation (hi. _allocation_)

Nomad क्लस्टर पर, किसी job के task group का किसी client node पर एक प्लेसमेंट, जो उसके task चलाता है। उसके लॉग और उसमें शेल Nomad के सर्वर से होकर node तक जाते हैं। [लॉग और शेल](/docs/clusters/nomad/#logs-and-shell) देखें।

### Swarm (hi. _Swarm_)

एक Docker Swarm क्लस्टर, जो उन होस्ट के ज़रिए मिलता है जो उसके हिस्से हैं और कभी अपने-आप में जोड़ा नहीं जाता। Homeport किसी भी कनेक्ट किए गए मैनेजर होस्ट के ज़रिए उस तक पहुँचता है, Swarm को उनके swarm ID से अलग पहचानता है, और किसी Swarm के बारे में कुछ नहीं सहेजता। इसका नाम इसके पहले मैनेजर होस्ट पर रखा जाता है, क्योंकि Docker हर Swarm को एक ही नाम देता है। [Swarm](/docs/guides/swarm/) देखें।

### Port forward (hi. _पोर्ट फ़ॉरवर्ड_)

इस कंप्यूटर के loopback पर एक पोर्ट जिसे Homeport, Kubernetes API के ज़रिए, किसी Pod के पोर्ट से, या किसी Service के पोर्ट से उसके किसी तैयार Pod के ज़रिए, जोड़ता है, `kubectl port-forward` की तरह। Homeport बंद होने पर यह ख़त्म हो जाता है। [पोर्ट फ़ॉरवर्डिंग](/docs/clusters/port-forward/) देखें।

### Release (hi. _रिलीज़_)

एक Helm रिलीज़: किसी क्लस्टर पर किसी chart का एक इंस्टॉल, जिसका नाम उसके Namespace में होता है, हर इंस्टॉल, अपग्रेड और रोलबैक के लिए एक क्रमांकित revision के साथ। Helm इसे क्लस्टर पर रखता है; टर्मिनल में बनी रिलीज़ और Homeport में बनी रिलीज़ एक ही हैं। [Helm रिलीज़](/docs/clusters/helm/) देखें।

### Chart repository (hi. _चार्ट रिपॉज़िटरी_)

एक सर्वर जिससे helm चार्ट डाउनलोड करता है, इस कंप्यूटर पर helm की अपनी सूची में — वही जो `helm repo list` दिखाता है। किसी OCI रजिस्ट्री के चार्ट इसके बजाय उनके `oci://` रेफ़रेंस से इंस्टॉल किए जाते हैं। [चार्ट रिपॉज़िटरी](/docs/clusters/helm/#chart-repositories) देखें।

### Node (hi. _नोड_)

किसी Swarm में एक इंजन: मैनेजर या वर्कर। किसी क्लस्टर के Node, Kubernetes Node होते हैं, वे मशीनें जिन पर वह Pod चलाता है। नोड सिर्फ़ तब होस्ट होता है जब Homeport उससे कनेक्ट होता है, और होस्ट का पेज उसके नोड से लिंक करता है।

### Service (hi. _सर्विस_)

Swarm क्या चलाता है: एक इमेज, उसकी सेटिंग्स और रेप्लिका की एक संख्या, या global सर्विस के लिए हर नोड पर एक टास्क।

### Task (hi. _टास्क_)

किसी नोड पर किसी सर्विस का एक स्लॉट, जो वहाँ एक कंटेनर के रूप में चलता है। जब कोई सर्विस converge नहीं होती, तो उसके टास्क बताते हैं कि क्यों। containerd होस्ट पर, टास्क वह है जो किसी कंटेनर के लिए चलता है, जो सिर्फ़ मेटाडेटा है: कंटेनर शुरू करने से उसका टास्क बनता है।

### Stack (hi. _स्टैक_)

किसी होस्ट पर चल रहा एक Compose प्रोजेक्ट, या किसी Swarm पर चल रहा एक swarm स्टैक, जिसकी पहचान उसके प्रोजेक्ट नाम से होती है। हर स्टैक प्रबंधित, लिंक्ड, सिंक्ड या बाहरी होता है। [स्टैक](/docs/guides/stacks/) और [swarm स्टैक](/docs/guides/swarm/#swarm-stacks) देखें।

### Managed Stack (hi. _प्रबंधित स्टैक_)

एक स्टैक जिसकी compose परिभाषा और परिवेश Homeport रखता है, ताकि उसे Homeport से डिप्लॉय, फिर से डिप्लॉय और संपादित किया जा सके।

### Linked Stack (hi. _लिंक्ड स्टैक_)

एक स्टैक जिसकी compose फ़ाइलें इस कंप्यूटर का एक फ़ोल्डर हैं। Homeport रखता है कि फ़ोल्डर और उसकी compose फ़ाइलें कहाँ हैं, फ़ाइलों को उनकी जगह पर पढ़ता और लिखता है, और उस फ़ोल्डर को प्रोजेक्ट डायरेक्टरी मानकर डिप्लॉय करता है, ताकि `build:`, `env_file:` और relative पाथ काम करें। यह चल रहे कंटेनर के compose लेबल से मिलता है, या किसी फ़ोल्डर से बनाया जाता है। जब तक इसकी फ़ाइलें गायब हैं, यह बाहरी बन जाता है। [लिंक्ड स्टैक](/docs/guides/stacks/#linked-stacks) देखें।

### Synced Stack (hi. _सिंक्ड स्टैक_)

एक स्टैक जिसकी compose परिभाषा किसी git रिपॉज़िटरी से आती है। Homeport इस कंप्यूटर पर उसका एक क्लोन रखता है, माँगने पर या Homeport खुले रहते हुए एक अंतराल पर कोई branch या tag फ़ेच करता है, दिखाता है कि क्या बदला, और compose फ़ाइल के फ़ोल्डर से एक कमिट डिप्लॉय करता है, ताकि `build:` और relative पाथ काम करें। इसे Homeport में कभी संपादित नहीं किया जाता: इसकी फ़ाइलें git के ज़रिए बदलती हैं; सिर्फ़ इसका परिवेश और सिंक सेटिंग्स Homeport की होती हैं। [सिंक्ड स्टैक](/docs/guides/synced-stacks/) देखें।

### Repository (hi. _रिपॉज़िटरी_)

एक git रिपॉज़िटरी जिसे Homeport सिंक्ड स्टैक के लिए पढ़ सकता है: उसका URL और Homeport उसके साथ कैसे प्रमाणीकरण करता है — Homeport की बनाई डिप्लॉय कुंजी, एक यूज़र नाम और टोकन, या पब्लिक रिपॉज़िटरी के लिए कुछ नहीं। हर होस्ट के लिए एक बार रखी जाती है, और उससे बने हर सिंक्ड स्टैक द्वारा साझा की जाती है।

### Deploy key (hi. _डिप्लॉय कुंजी_)

वह Ed25519 कुंजी जो Homeport एक रिपॉज़िटरी के लिए बनाता है, जिसे आप अपने git forge पर सिर्फ़ पढ़ने की पहुँच के साथ उसमें जोड़ते हैं। कभी आपकी अपनी SSH कुंजी नहीं।

### External Stack (hi. _बाहरी स्टैक_)

किसी होस्ट पर चलता हुआ मिला एक स्टैक जिसकी compose परिभाषा Homeport के पास नहीं है, न सहेजी हुई, न इस कंप्यूटर के किसी फ़ोल्डर में, न किसी ऐसी रिपॉज़िटरी में जिसका वह पालन करता है। इसे शुरू किया, रोका और हटाया जा सकता है, लेकिन फिर से डिप्लॉय या संपादित नहीं किया जा सकता।

### Adopt (hi. _अपनाना_)

किसी बाहरी स्टैक की compose परिभाषा देकर उसे प्रबंधित स्टैक में बदलना।

### Registry login (hi. _रजिस्ट्री लॉगिन_)

वह यूज़र नाम और पासवर्ड या एक्सेस टोकन जो Homeport किसी एक कंटेनर रजिस्ट्री, जैसे Docker Hub या GHCR, के लिए रखता है, और हर होस्ट पर पुल, पुश और बिल्ड करने के लिए इस्तेमाल करता है। [सेटिंग्स](/docs/guides/settings/#registries) देखें।

### Helper container (hi. _सहायक कंटेनर_)

एक अल्पकालिक `busybox` कंटेनर जिसे Homeport किसी होस्ट पर कोई वॉल्यूम खोलने के लिए बनाता है — उसे ब्राउज़ करने, उसका बैकअप लेने, उसे रीस्टोर या क्लोन करने के लिए — क्योंकि Engine API वॉल्यूम नहीं पढ़ सकता। इसका कोई नेटवर्क नहीं होता, यह वॉल्यूम को सिर्फ़-पढ़ने के लिए माउंट करता है जब तक उसे उसमें लिखना न हो, और कार्रवाई ख़त्म होने पर हटा दिया जाता है। यह कभी कंटेनर सूची में या इवेंट पेज पर नहीं दिखता। [किसी वॉल्यूम की फ़ाइलें ब्राउज़ करना](/docs/guides/volumes-networks/#the-helper-container) देखें।

### Board (hi. _बोर्ड_)

वह पेज जो हर कनेक्ट किए गए होस्ट के कंटेनर को एक टेबल में सूचीबद्ध करता है, हर एक पर उसके होस्ट का लेबल होता है। [बोर्ड](/docs/guides/overview/#board) देखें।

### Command palette (hi. _कमांड पैलेट_)

<kbd>Mod</kbd> <kbd>K</kbd> से खुलने वाला सर्च बॉक्स: किसी पेज पर जाएँ, होस्ट बदलें, कोई कमांड चलाएँ, या किसी भी कनेक्ट किए गए होस्ट पर कोई कंटेनर, इमेज, वॉल्यूम, नेटवर्क या स्टैक ढूँढें। [कीबोर्ड](/docs/guides/keyboard/#command-palette) देखें।

### Engine (hi. _इंजन_)

Docker Engine (`dockerd`), या Podman जैसा कोई संगत इंजन, जो किसी मशीन पर कंटेनर चलाता है। Homeport Docker Engine API के ज़रिए उससे बात करता है।

### Socket (hi. _सॉकेट_)

वह पता जिस पर कोई इंजन सुनता है: एक Unix सॉकेट फ़ाइल जैसे `/var/run/docker.sock`, या Windows पर एक named pipe जैसे `//./pipe/docker_engine`।

### Keychain (hi. _कीचेन_)

पासवर्ड और कुंजियों के लिए आपके ऑपरेटिंग सिस्टम का सुरक्षित स्टोर — macOS Keychain, Windows Credential Manager या Linux Secret Service — जहाँ Homeport वह कुंजी रखता है जो उसके सीक्रेट को एन्क्रिप्ट करती है।

### Trust on first use (hi. _पहले इस्तेमाल पर भरोसा_)

Homeport SSH सर्वर की जाँच कैसे करता है: आप पहले कनेक्शन पर सर्वर की कुंजी के फ़िंगरप्रिंट की पुष्टि करते हैं, और अगर कुंजी बाद में बदलती है तो जब तक आप फिर से पुष्टि न करें, Homeport कनेक्ट होने से इनकार करता है।
