**Homeport** est une application de bureau pour gérer des Docker Engines, containerd et Incus où qu’ils soient — ceux de cette machine, ou des moteurs distants via SSH, TLS ou TCP —, les Swarms qu’ils forment, ainsi que les clusters Kubernetes que votre kubeconfig atteint et les clusters Nomad que vous indiquez, dans l’esprit de Docker Desktop. Il fonctionne sous Windows, macOS et Linux, est gratuit, et est open source sous la [GNU Affero General Public License, version 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE).

Homeport n’exécute pas de conteneurs lui-même. Il se connecte aux moteurs que vous avez déjà, appelés **hôtes**, et vous donne une seule fenêtre pour tout ce qu’ils contiennent : conteneurs, images, volumes, réseaux et **stacks** Compose. Il se connecte aussi aux **clusters** Kubernetes et Nomad, pour voir ce qui s’y exécute et le gérer. Rien n’est installé sur un hôte ni sur un cluster.

## Les mots que nous employons

Homeport nomme les choses avec précision, et la documentation fait de même :

- Un **hôte** est un moteur auquel Homeport se connecte : un Docker Engine ou un moteur compatible comme Podman, containerd ou Incus. Chaque conteneur, image, volume, réseau et stack appartient à exactement un hôte.
- Un **cluster** est un cluster Kubernetes, ajouté à partir d’un contexte de votre kubeconfig, ou un cluster Nomad, ajouté par l’adresse de l’un de ses agents.
- Un **Swarm** est un Docker Swarm, trouvé via les hôtes qui en font partie et jamais ajouté seul.
- Une **stack** est un projet Compose qui s’exécute sur un hôte, ou une stack swarm qui s’exécute sur un Swarm. Une **stack gérée** est une stack dont Homeport conserve le fichier compose ; une **stack liée** garde ses fichiers compose dans un dossier de cet ordinateur ; une **stack synchronisée** suit un dépôt git ; une **stack externe** a été déployée autrement. Vous pouvez **adopter** une stack externe pour la gérer.

Le [glossaire](/docs/reference/glossary/) donne la liste complète.
