**Homeport** est une application de bureau pour gérer des Docker Engines où qu’ils soient — celui de cette machine, ou des moteurs distants via SSH, TLS ou TCP — ainsi que les clusters Kubernetes que votre kubeconfig atteint, dans l’esprit de Docker Desktop. Il fonctionne sous Windows, macOS et Linux, est gratuit, et est open source sous la [GNU Affero General Public License, version 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE).

Homeport n’exécute pas de conteneurs lui-même. Il se connecte aux Docker Engines que vous avez déjà, appelés **hôtes**, et vous donne une seule fenêtre pour tout ce qu’ils contiennent : conteneurs, images, volumes, réseaux et **stacks** Compose. Il se connecte aussi aux **clusters** Kubernetes de votre kubeconfig, pour parcourir ce qui s’y exécute.

## Les mots que nous employons

Homeport nomme les choses avec précision, et la documentation fait de même :

- Un **hôte** est un Docker Engine auquel Homeport se connecte. Chaque conteneur, image, volume, réseau et stack appartient à exactement un hôte.
- Un **cluster** est un cluster Kubernetes auquel Homeport se connecte, ajouté à partir d’un contexte de votre kubeconfig.
- Une **stack** est un projet Compose qui s’exécute sur un hôte. Une **stack gérée** est une stack dont Homeport conserve le fichier compose ; une **stack liée** garde ses fichiers compose dans un dossier de cet ordinateur ; une **stack externe** a été déployée autrement. Vous pouvez **adopter** une stack externe pour la gérer.

Le [glossaire](/docs/reference/glossary/) donne la liste complète.
