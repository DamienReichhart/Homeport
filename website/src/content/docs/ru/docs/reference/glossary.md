---
title: Глоссарий
description: Слова, которые использует Homeport, и что они означают.
---

Homeport называет вещи точно. Эти термины встречаются по всему приложению и в этой документации. Каждая запись содержит английский термин продукта, а за ним — слово, которое использует русская версия приложения.

### Host (рус. _хост_)

Движок Docker, к которому подключается Homeport, заданный именем и способом подключения: локальный сокет, TCP, TLS или SSH. Каждый контейнер, образ, том, сеть и стек принадлежит ровно одному хосту. См. [Хосты и подключения](/docs/hosts/).

### Engine kind (рус. _тип движка_)

Вид движка, на который указывает хост: совместимый с Docker (Docker Engine или Podman через его совместимый API), containerd или Incus. От него зависит, какие страницы показывает хост: у хостов containerd и Incus есть свои. Podman не отдельный тип: Homeport распознаёт его при каждом подключении. См. [Типы движков](/docs/hosts/#типы-движков).

### Namespace (containerd's) (рус. _пространство имён containerd_)

На хосте containerd — пространство, в котором находится каждый контейнер, образ и снимок: nerdctl использует `default`, Kubernetes — `k8s.io`, Docker — `moby`. Страницы хоста containerd показывают одно за раз. Namespace кластера — это пространства имён Kubernetes. См. [пространства имён containerd](/docs/hosts/containerd/#пространства-имён).

### Snapshot (рус. _снимок_)

На хосте containerd — слой файлов на диске: слой распакованного образа или записываемый слой контейнера. См. [снимки](/docs/hosts/containerd/#снимки). На хосте Incus — сохранённое состояние экземпляра, к которому его можно вернуть; см. [снимки экземпляров](/docs/guides/instances/#снимки).

### Instance (рус. _экземпляр_)

То, что запускает хост Incus: системный контейнер, который загружает целый дистрибутив Linux на ядре хоста, или виртуальная машина со своим ядром. Не контейнер, который запускает одно приложение. См. [Экземпляры](/docs/guides/instances/).

### Project (Incus's) (рус. _проект_)

На хосте Incus — пространство, в котором находятся его экземпляры, образы, профили, пользовательские тома и сети. Страницы хоста Incus показывают один проект за раз, выбранный под переключателем хостов. См. [проекты](/docs/hosts/incus/#проекты).

### Profile (рус. _профиль_)

На хосте Incus — конфигурация и устройства, общие для экземпляров, в которых он указан. См. [профили](/docs/guides/instances/#профили).

### Trust token (рус. _токен доверия_)

То, что выводит `incus config trust add` на сервере Incus; один раз вставляется в Homeport, чтобы добавить этот сервер по HTTPS. См. [токены доверия](/docs/hosts/incus/#по-https-с-токеном-доверия).

### Pod (рус. _под Podman_)

На хосте Podman — группа контейнеров, которые используют одну сеть и запускаются и останавливаются вместе, вокруг инфраструктурного контейнера, удерживающего публикуемые подом порты. Pod кластера — это Pod Kubernetes. См. [Поды Podman](/docs/guides/podman-pods/).

### Quadlet unit (рус. _юнит Quadlet_)

Файл на хосте Podman, например `web.container`, который systemd превращает в сервис `web.service`, чтобы контейнеры Podman запускались при загрузке, а systemd поддерживал их работу. См. [Юниты Quadlet](/docs/guides/quadlet/).

### Cluster (рус. _кластер_)

Кластер Kubernetes или кластер Nomad, к которому Homeport подключается через его API. Кластер Kubernetes добавляется из контекста kubeconfig: имя, адрес API-сервера и учётные данные, которые даёт kubeconfig, хранящиеся в зашифрованном виде. Кластер Nomad добавляется по адресу одного из его агентов, с токеном ACL и материалами TLS, хранящимися в зашифрованном виде. Homeport ничего не устанавливает ни на тот, ни на другой и получает доступ только к тому, что разрешают эти учётные данные. Не Swarm, который находится через свои хосты и никогда не добавляется. Собственные объекты Kubernetes сохраняют свои имена из Kubernetes: Namespace, Pod, Deployment, Service, Node… Объекты Nomad — имена из Nomad: job, task group, task, allocation, client node, namespace. См. [Кластеры](/docs/clusters/) и [Кластеры Nomad](/docs/clusters/nomad/).

### Allocation (рус. _allocation_)

В кластере Nomad — одно размещение task group из job на client node, выполняющее её task. Её журналы и оболочка в ней идут через серверы Nomad к узлу. См. [журналы и оболочка](/docs/clusters/nomad/#журналы-и-оболочка).

### Swarm (рус. _Swarm_)

Кластер Docker Swarm, который находится через входящие в него хосты и никогда не добавляется отдельно. Homeport обращается к нему через любой подключённый управляющий хост, различает Swarm по их идентификатору swarm и ничего о них не хранит. Swarm называется по своему первому управляющему хосту, поскольку Docker даёт всем Swarm одно и то же имя. См. [Swarm](/docs/guides/swarm/).

### Port forward (рус. _проброс порта_)

Порт на интерфейсе loopback этого компьютера, который Homeport через API Kubernetes соединяет с портом Pod или Service — через один из его готовых Pod, — как `kubectl port-forward`. Завершается при выходе из Homeport. См. [Проброс портов](/docs/clusters/port-forward/).

### Release (рус. _релиз_)

Релиз Helm: одна установка чарта в кластере, названная в своём Namespace, с пронумерованной ревизией для каждой установки, обновления и отката. Helm хранит его в кластере; релиз, созданный в терминале, и релиз, созданный в Homeport, — одно и то же. См. [Релизы Helm](/docs/clusters/helm/).

### Chart repository (рус. _репозиторий чартов_)

Сервер, с которого helm скачивает чарты, из собственного списка helm на этом компьютере — того, что показывает `helm repo list`. Чарты в реестре OCI вместо этого устанавливаются по их ссылке `oci://`. См. [репозитории чартов](/docs/clusters/helm/#репозитории-чартов).

### Node (рус. _узел_)

Один движок в Swarm: управляющий или рабочий. Node кластера — это Node Kubernetes, машины, на которых он запускает Pod. Узел является хостом, только если Homeport к нему подключается, и страница хоста ссылается на его узел.

### Service (рус. _сервис_)

То, что запускает Swarm: образ, его параметры и число реплик или, для глобального сервиса, по одной задаче на каждом узле.

### Task (рус. _задача_)

Одно место сервиса на одном узле, запускаемое там как контейнер. Если сервис не сходится, его задачи сообщают почему. На хосте containerd задача — это то, что работает для контейнера, который сам является лишь метаданными: запуск контейнера создаёт его задачу.

### Stack (рус. _стек_)

Проект Compose, работающий на хосте, или swarm stack, работающий в Swarm, определяемый именем своего проекта. Каждый стек — управляемый, связанный, синхронизируемый или внешний. См. [Стеки](/docs/guides/stacks/) и [стеки Swarm](/docs/guides/swarm/#стеки-swarm).

### Managed Stack (рус. _управляемый стек_)

Стек, compose-определение и окружение которого хранит Homeport, так что его можно развернуть, развернуть заново и изменить из Homeport.

### Linked Stack (рус. _связанный стек_)

Стек, compose-файлы которого — это папка на этом компьютере. Homeport запоминает, где находятся папка и её compose-файлы, читает и записывает файлы на месте и разворачивает с этой папкой в качестве каталога проекта, так что `build:`, `env_file:` и относительные пути работают. Находится по меткам compose работающих контейнеров или создаётся из папки. Становится внешним, пока его файлы отсутствуют. См. [Связанные стеки](/docs/guides/stacks/#связанные-стеки).

### Synced Stack (рус. _синхронизируемый стек_)

Стек, compose-определение которого берётся из репозитория git. Homeport хранит его клон на этом компьютере, получает ветку или тег по запросу или с заданным интервалом, пока Homeport открыт, показывает, что изменилось, и разворачивает коммит из папки compose-файла, так что `build:` и относительные пути работают. Он никогда не редактируется в Homeport: его файлы меняются через git; Homeport принадлежат только его окружение и параметры синхронизации. См. [Синхронизируемые стеки](/docs/guides/synced-stacks/).

### Repository (рус. _репозиторий_)

Репозиторий git, который Homeport может читать для синхронизируемых стеков: его URL и способ аутентификации Homeport в нём — созданный им ключ развёртывания, имя пользователя и токен или ничего для публичного. Хранится один раз для всех хостов и используется всеми синхронизируемыми стеками, созданными из него.

### Deploy key (рус. _ключ развёртывания_)

Ключ Ed25519, который Homeport создаёт для одного репозитория и который вы добавляете в него на своей git-платформе только с правом чтения. Никогда не ваш собственный ключ SSH.

### External Stack (рус. _внешний стек_)

Стек, найденный работающим на хосте, compose-определения которого у Homeport нет: ни в хранилище, ни в папке на этом компьютере, ни в отслеживаемом им репозитории. Его можно запускать, останавливать и удалять, но нельзя развернуть заново или изменить.

### Adopt (рус. _взять под управление_)

Превратить внешний стек в управляемый, предоставив его compose-определение.

### Registry login (рус. _вход в реестр_)

Имя пользователя и пароль или токен доступа, которые Homeport хранит для одного реестра контейнеров, например Docker Hub или GHCR, и использует на каждом хосте для скачивания, отправки и сборки. См. [Настройки](/docs/guides/settings/#реестры).

### Helper container (рус. _вспомогательный контейнер_)

Кратковременный контейнер `busybox`, который Homeport создаёт на хосте, чтобы открыть том — для просмотра, резервного копирования, восстановления или клонирования, — поскольку Engine API не умеет его читать. У него нет сети, он монтирует том только для чтения, если ему не нужно в него писать, и удаляется по завершении действия. Он никогда не показывается в списке контейнеров или на странице «События». См. [Просмотр файлов тома](/docs/guides/volumes-networks/#вспомогательный-контейнер).

### Board (рус. _Доска_)

Страница, на которой контейнеры всех подключённых хостов показаны в одной таблице, каждый с отметкой своего хоста. См. [Доска](/docs/guides/overview/#доска).

### Command palette (рус. _палитра команд_)

Поле поиска, открываемое сочетанием <kbd>Mod</kbd> <kbd>K</kbd>: перейти на страницу, переключить хост, выполнить команду или найти контейнер, образ, том, сеть или стек на любом подключённом хосте. См. [Клавиатура](/docs/guides/keyboard/#палитра-команд).

### Engine (рус. _движок_)

Docker Engine (`dockerd`) или совместимый с ним движок, например Podman, который запускает контейнеры на машине. Homeport общается с ним через Docker Engine API.

### Socket (рус. _сокет_)

Адрес, который слушает движок: файл сокета Unix, например `/var/run/docker.sock`, или именованный канал, например `//./pipe/docker_engine` в Windows.

### Keychain (рус. _связка ключей ОС_)

Защищённое хранилище паролей и ключей вашей операционной системы — Связка ключей macOS, Диспетчер учётных данных Windows или Secret Service в Linux, — где Homeport хранит ключ, которым шифрует свои секреты.

### Trust on first use (рус. _доверие при первом использовании_)

Способ, которым Homeport проверяет серверы SSH: вы подтверждаете отпечаток ключа сервера при первом подключении, и если ключ потом изменится, Homeport откажется подключаться, пока вы не подтвердите снова.

## На русском

Русская версия приложения, документации и сайта использует эти термины, чтобы экран и страница всегда говорили одно и то же.

| Английский     | Русский                 |
| -------------- | ----------------------- |
| Host           | хост (м.)               |
| Engine         | движок (м.)             |
| Instance       | экземпляр (м.)          |
| Swarm          | Swarm (м.)              |
| Cluster        | кластер (м.)            |
| Stack          | стек (м.)               |
| Managed Stack  | управляемый стек        |
| Linked Stack   | связанный стек          |
| Synced Stack   | синхронизируемый стек   |
| External Stack | внешний стек            |
| Adopt          | взять под управление    |
| Board          | Доска                   |
| Bastion        | бастион (м.)            |
| Deploy key     | ключ развёртывания (м.) |
| Port forward   | проброс порта (м.)      |
| Release (Helm) | релиз (м.)              |
