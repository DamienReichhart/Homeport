### Homeport бесплатен?

Да. Homeport можно бесплатно использовать для личной и коммерческой работы, и он распространяется с открытым исходным кодом по лицензии [GNU Affero General Public License версии 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE) (AGPL).

### Что AGPL означает для меня?

Если вы пользуетесь Homeport, ничего не меняется: устанавливайте его, запускайте дома или на работе, на любом количестве компьютеров. AGPL требует чего-то только от тех, кто **распространяет** Homeport, изменённый или нет, или предоставляет изменённую версию другим по сети: они должны опубликовать её полный исходный код под той же лицензией. Каждая копия Homeport ссылается на исходный код своей точной версии в **Настройки → Лицензии**.

Версии до 0.11 включительно выпускались под лицензией MIT и остаются доступными на её условиях.

### Заменяет ли Homeport Docker Desktop?

Не полностью. Homeport — это средство управления: сам он не запускает Docker Engine. В Linux установите Docker Engine и используйте Homeport как его интерфейс. В macOS и Windows вам всё равно нужно что-то, что запускает движок, — Docker Desktop, Colima, OrbStack, Rancher Desktop или Podman, — и Homeport может работать поверх любого из них, вместе с вашими удалёнными серверами.

### Работает ли он с containerd?

Да, напрямую, без Docker: движком хоста может быть [containerd](/docs/hosts/containerd/), доступный через свой сокет на этом компьютере или по SSH, — containerd из k3s, собственный containerd Docker Engine или служба containerd на сервере. Homeport показывает его пространства имён, его контейнеры и их задачи (запуск, остановка, приостановка, сигнал, удаление), их журналы там, где их записали nerdctl или Kubernetes, терминал в них, его образы (скачивание, удаление) и его снимки. Он не создаёт там контейнеры и не разворачивает стеки; это делает nerdctl.

### Работает ли он с Incus?

Да: движком хоста может быть [Incus](/docs/hosts/incus/) 6.0 или новее, доступный через свой сокет на этом компьютере, по SSH или по HTTPS с токеном доверия из `incus config trust add`. Homeport показывает [экземпляры](/docs/guides/instances/) проекта — системные контейнеры и виртуальные машины, — запускает, останавливает, замораживает, удаляет и создаёт их, открывает их консоль и терминал в них, делает и восстанавливает снимки, управляет образами, профилями, пулами хранения и сетями. Он не разворачивает там стеки и ничего не устанавливает на хост.

### Работает ли он с LXD?

Не как таковой: Homeport работает с Incus, форком LXD от сообщества, и отказывается работать с сервером LXD, API которого разошёлся с Incus. Перенесите его с помощью `lxd-to-incus`, затем добавьте как хост Incus.

### Работает ли он с Podman?

Да, через Docker-совместимый сокет API Podman. Homeport обнаруживает обычные сокеты Podman в Linux, каждую работающую [машину Podman в macOS](/docs/hosts/local/#машины-podman-в-macos) и канал машины Podman по умолчанию в Windows. Всё остальное можно [добавить вручную](/docs/hosts/local/#добавление-сокета-вручную).

Кроме того, Homeport распознаёт Podman при подключении и тогда предлагает то, что есть только у Podman, через собственный API Podman на том же сокете: [поды](/docs/guides/podman-pods/), которые можно просматривать, запускать, останавливать, создавать и удалять, а также запускать в них контейнеры из диалога «Запустить»; и [юниты Quadlet](/docs/guides/quadlet/), которые можно просматривать, читать, устанавливать, редактировать и удалять, а также запускать или останавливать по SSH.

### Работает ли он с Kubernetes, Nomad или Docker Swarm?

Docker Swarm — да. Homeport находит Swarm через его управляющие хосты, как только один из них добавлен как хост, и полностью управляет им: его узлами, сервисами, задачами, секретами, конфигурациями и swarm stack, включая развёрнутые в нём управляемые, связанные и синхронизируемые стеки. Он также может создать Swarm на хосте, присоединиться к нему или выйти из него. Всё идёт через Engine API подключённого управляющего узла; на узлы ничего не устанавливается. См. [Swarm](/docs/guides/swarm/).

Kubernetes — да. Добавьте кластер из своего kubeconfig — этого компьютера или вставленного вами, — а локальные кластеры (Docker Desktop, OrbStack, Rancher Desktop, kind, k3d, minikube) Homeport найдёт сам. EKS, GKE и AKS работают через плагин exec, указанный в их kubeconfig. Можно в реальном времени просматривать Namespace, рабочие нагрузки, Pod, Service, Ingress, ConfigMap, Secret, Node, Event и любые другие ресурсы API, включая пользовательские; следить за журналами, открывать терминал в Pod, пробрасывать порты, масштабировать, перезапускать и удалять, а также применять или редактировать YAML с предварительным просмотром. На кластер ничего не устанавливается: Homeport лишь обращается к API Kubernetes, до которого уже дотягивается ваш kubeconfig, с правами его учётных данных. При наличии CLI `helm` на этом компьютере Homeport также показывает, устанавливает, обновляет, откатывает и удаляет [релизы Helm](/docs/clusters/helm/) и управляет репозиториями чартов helm. См. [Кластеры](/docs/clusters/).

Nomad — да. Добавьте кластер по адресу его агента, с токеном ACL и материалами TLS, если они используются. Можно в реальном времени просматривать job и их allocation; запускать job из HCL или JSON, увидев план Nomad; изменять и перезапускать job, останавливать или полностью удалять его и масштабировать его task group; следить за журналами task и открывать в нём оболочку; освобождать узлы и переключать их пригодность; выбирать namespace. На кластер ничего не устанавливается, и CLI `nomad` не нужен: Homeport обращается к HTTP API Nomad с правами токена. См. [Кластеры Nomad](/docs/clusters/nomad/).

### Нужен ли мне kubectl?

Нет. Homeport читает ваш kubeconfig и сам работает с API Kubernetes. Единственные программы, которые он запускает, — это [плагины exec](/docs/clusters/exec-plugins/), указанные в kubeconfig, например AWS CLI для EKS, `gke-gcloud-auth-plugin` для GKE или `kubelogin` для AKS, — те же, что запустил бы `kubectl`. Но иметь `kubectl` под рукой всё же полезно, чтобы проверить, что разрешают ваши учётные данные (`kubectl auth can-i`).

### Нужно ли что-то устанавливать на серверы?

Нет — только Docker Engine и сервер SSH, которые у вас, скорее всего, уже есть. Homeport не устанавливает агентов.

Swarm тоже не требует ничего, кроме движка. Однако его узлы должны видеть друг друга, а это Homeport настроить за вас не может: откройте между ними 2377/tcp (к управляющим узлам), 7946/tcp и 7946/udp, а также 4789/udp. См. [порты между узлами](/docs/guides/swarm/#порты-между-узлами).

### Нужен ли Docker на моём компьютере, чтобы управлять удалёнными серверами?

Нет. Homeport сам работает с Engine API и SSH. Единственные исключения — развёртывание управляемых, связанных и синхронизируемых стеков, которое использует команду `docker compose` на вашем компьютере, и их развёртывание в Swarm, которое использует команду `docker` (`docker stack deploy`). Ни то, ни другое не требует движка на вашем компьютере.

### Синхронизирует ли Homeport мои стеки, когда он закрыт?

Нет. [Синхронизируемые стеки](/docs/guides/synced-stacks/) проверяются на новые коммиты и, если вы это включили, автоматически разворачиваются только пока Homeport открыт. Homeport ничего не устанавливает на ваши серверы — ни агента, ни приёмника webhook, — поэтому, когда он закрыт, за вашими репозиториями никто не следит. Когда вы снова его откроете, он подождёт один интервал, а затем проверит их все. Для развёртываний, которые должны круглосуточно следовать за каждой отправкой, запускайте их из своего CI.

Чтобы Homeport работал без окна, включите **Сворачивать в системный трей при закрытии**, а также **Запускать при входе в систему** вместе с **Запускать скрытым в трее** в [Настройки → Рабочий стол](/docs/guides/settings/#рабочий-стол).

### Может ли Homeport сообщить мне о падении контейнера?

Да, пока он работает, — даже скрытым в системном трее. Он показывает уведомление ОС, когда контейнер останавливается с ошибкой, исчерпывает память или становится нездоровым, а также когда хост становится недоступен или снова доступен. Каждый вид уведомлений можно отключить в [Настройки → Уведомления](/docs/guides/settings/#уведомления). Homeport узнаёт об этом из потока событий, который он и так получает от каждого хоста, поэтому на серверы ничего не устанавливается; когда Homeport не запущен, никто не получает уведомлений.

### Нужен ли Homeport git?

Только для [синхронизируемых стеков](/docs/guides/synced-stacks/), которые используют `git`, установленный на вашем компьютере, с собственным ключом развёртывания или токеном каждого репозитория. **Настройки → Этот компьютер** показывает, нашёл ли его Homeport. Ваша собственная конфигурация git, помощники учётных данных и ключи SSH никогда не используются.

### Могут ли несколько человек пользоваться общими хостами Homeport?

Каждый запускает свой Homeport со своими хостами и ключами. С ключом, созданным Homeport, для каждого человека и каждого сервера вы можете видеть и отзывать доступ каждого в `authorized_keys`.

### Можно ли перенести Homeport на другой компьютер?

Да, двумя способами:

- **Всё**: **Настройки → Данные → Создать резервную копию…** сохраняет все хосты, кластеры, стеки, входы в реестры, репозитории и настройки вместе с их секретами в один файл, защищённый парольной фразой длиной не менее 12 символов. На новом компьютере **Восстановить…** в том же месте открывает его, показывает его содержимое и заменяет то, что там есть. Всё подключается и разворачивается без повторных запросов ключа или пароля. См. [резервное копирование и восстановление](/docs/guides/settings/#резервное-копирование-и-восстановление).
- **Некоторые хосты**: на странице **Хосты** **экспортируйте** выбранные хосты и **импортируйте** их на другом компьютере, рядом с уже имеющимися там хостами. См. [перенос на другой компьютер](/docs/reference/security/#перенос-на-другой-компьютер).

Копирование `homeport.db` для секретов не работает: они зашифрованы ключом из связки ключей этого компьютера и в другом месте отображаются как **Учётные данные утеряны**.

### Входят ли в резервную копию мои контейнеры и тома?

Нет. Резервная копия содержит то, что хранит Homeport, — как подключаться к вашим хостам, определения и окружения ваших стеков, входы и настройки, — а не то, что работает на ваших хостах. Ваши контейнеры, образы и тома остаются на хостах. Чтобы скопировать данные тома, [сохраните его в файл](/docs/guides/volumes-networks/#резервное-копирование-и-восстановление) со страницы «Тома».

### Умеет ли Homeport собирать образы?

Да, в двух местах. Страница **Образы** собирает образ из папки на этом компьютере. А [связанный стек](/docs/guides/stacks/#связанные-стеки) — стек, compose-файлы которого лежат в папке на этом компьютере, — может использовать `build:`: Homeport запускает `docker compose` в этой папке, так что контекст сборки отправляется оттуда движку хоста, который и выполняет сборку. **Пересобрать и развернуть** пересобирает после изменения кода. Управляемый стек собирать не может, поскольку Homeport хранит только его YAML и собирать не из чего: вместо этого свяжите папку или отправьте образ в реестр.

### Почему на другом компьютере мой стек отображается как внешний?

Стек, запущенный командой `docker compose up` в папке, отображается как [связанный](/docs/guides/stacks/#как-находятся-связанные-стеки) только на компьютере, где эта папка и её compose-файлы существуют по тому же пути и определяют работающие сервисы. На другом компьютере такого пути нет, поэтому у Homeport нет для него compose-файла и он показывает стек как внешний. Чтобы управлять им и оттуда, клонируйте проект на этот компьютер и свяжите его через **Новый стек → Использовать папку на этом компьютере** или возьмите его под управление как управляемый стек.

### Собирает ли Homeport данные обо мне?

Нет. Нет ни учётной записи, ни телеметрии, ни аналитики. Единственный запрос, который Homeport сам делает с вашего компьютера, — проверка обновлений, которая скачивает небольшой файл с этого сайта и ничего не отправляет о вас; её можно отключить в **Настройки → Обновления**. Отдельно проверка новых версий образов спрашивает у реестров ваших образов, через движок каждого хоста, на какую версию указывают их теги; для локального хоста этот запрос тоже уходит с вашего компьютера. См. [безопасность и ваши данные](/docs/reference/security/#к-чему-подключается-homeport).

### Может ли Homeport использовать мои приватные реестры?

Да. Добавьте вход для каждого реестра в **Настройки → Реестры** — Docker Hub, GHCR или ваш собственный. Homeport передаёт его движку для скачивания, отправки и сборки на любом хосте и скачивает с ним образы управляемого, связанного или синхронизируемого стека перед развёртыванием. Пароли и токены шифруются с помощью связки ключей ОС. Homeport не читает входы `docker login` на этом компьютере.

### Как Homeport узнаёт, что вышел более новый образ?

Он спрашивает у реестра образа, через движок хоста, на какой дайджест сейчас указывает тег, и сравнивает его с тем, который скачал хост. Ничего не скачивается, но Docker Hub засчитывает каждый такой вопрос в лимит скачиваний, как `docker pull`, не нашедший ничего нового. Поэтому Homeport хранит каждый ответ 6 часов, опрашивает не более четырёх реестров одновременно и спрашивает раньше, только если вы выберете **Проверить новые версии образов**. Вход в Docker Hub в **Настройки → Реестры** повышает лимит. Если реестр недоступен или ограничивает частоту запросов, Homeport не показывает отметку для его образов и записывает строку в свой журнал.

### Как обновиться?

В Windows, macOS и в AppImage Homeport сообщает о выходе новой версии: выберите **Установить и перезапустить**. В Linux пакеты `.deb` и `.rpm` обновляются вместе с остальной системой из репозитория пакетов Homeport. См. [обновление](/docs/reference/updating/).

### Есть ли Homeport в Homebrew, winget, Flathub или AUR?

Пока нет. Это запланировано; [страница установки](/docs/installation/#в-планах) ссылается на issue по каждому из них.

### Доступен ли Homeport на моём языке?

Homeport говорит на английском, французском, испанском, немецком, итальянском, бразильском португальском, русском, упрощённом китайском, японском, корейском, хинди и арабском и следует языку вашей операционной системы, если вы не выберете другой в [Настройки → Внешний вид](/docs/guides/settings/#внешний-вид). Сайт и эта документация тоже доступны на всех этих языках; только юридические страницы остаются на английском. Как добавить язык, см. [Участие в разработке](/docs/project/contributing/#перевод-homeport).

### Доступен ли Homeport для людей с ограниченными возможностями?

Им можно пользоваться только с клавиатуры, он следует системной настройке уменьшения движения, соответствует требованиям контрастности WCAG 2.2 AA, и каждая страница проверяется автоматическими средствами проверки доступности. Ведётся ручная проверка с экранными дикторами. Что работает, известные ограничения и как сообщить о барьере, см. на странице [Клавиатура и доступность](/docs/reference/accessibility/).

### Есть ли интерфейс командной строки?

Нет — Homeport является настольным приложением. Ваш имеющийся CLI `docker` работает рядом с ним, а Homeport обновляется в реальном времени, когда вы что-то меняете из терминала.

Сообщайте об ошибках и предлагайте функции в [issues на GitHub](https://github.com/DamienReichhart/Homeport/issues) или см. [участие в разработке](/docs/project/contributing/).
