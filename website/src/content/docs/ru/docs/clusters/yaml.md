Два способа изменить кластер с помощью YAML — для всего, что не покрывают отдельные действия: **Применить YAML** для манифестов, как `kubectl apply -f`, и **Изменить** на вкладке **YAML** любого объекта, как `kubectl edit`. Оба показывают, что изменится, до того как что-либо изменится.

## Применить YAML

**Применить YAML** в боковой панели кластера принимает один или несколько манифестов: вставьте их или нажмите **Открыть файл…**, чтобы загрузить файл `.yaml`, `.yml` или `.json` с этого компьютера. Несколько документов, разделённых `---`, применяются вместе, по порядку.

Документ без пространства имён попадает в пространство имён, выбранное справа вверху (или, при **Все пространства имён**, в пространство имён кластера по умолчанию). Объекты вне пространств имён, например Namespace или ClusterRole, его не учитывают.

1. **Просмотреть изменения** спрашивает у кластера, что сделал бы каждый документ, с помощью пробного запуска на стороне сервера: пока ничего не меняется. Каждый документ отображается как **Создан**, **Изменён** или **Без изменений**, со строками, которые он изменил бы.
2. **Применить** просит подтверждения, называя кластер, затем применяет.

Если применить те же манифесты дважды, во второй раз будет **Без изменений**. Если изменить YAML после предпросмотра, сначала потребуется новый предпросмотр.

## Изменение объекта

На вкладке **YAML** у каждого объекта есть **Изменить**: его YAML в том виде, в каком его хранит кластер, без того, чем управляет сервер (`managedFields`, `status`, его `resourceVersion`, uid и время создания). Измените его, нажмите **Просмотреть изменения**, чтобы увидеть только изменённые вами строки, затем **Применить**.

Предпросмотр сравнивает ваш YAML с объектом в том виде, в каком тот находится в момент предпросмотра, так что изменение, сделанное тем временем, видно в сравнении. Если правка меняет поле, которым управляет другой инструмент, предпросмотр показывает это как конфликт, а не перезаписывает поле.

Secret нельзя изменять в Homeport, поскольку он никогда не показывает все их значения сразу; а события Kubernetes записывает сам.

## Server-side apply

Homeport применяет изменения через server-side apply Kubernetes под менеджером полей `homeport`: кластер записывает, какие поля задал Homeport, наряду с полями, заданными `kubectl`, Helm, контроллерами или другими инструментами; вы увидите это в `managedFields` объекта.

Когда документ меняет поле, которым управляет другой инструмент, — `.spec.replicas`, заданное `kubectl apply` или управляемое автомасштабировщиком, — предпросмотр называет эти поля и их менеджеров. Не указывайте эти поля или нажмите **Всё равно применить** после второго подтверждения: Homeport забирает их себе, а другой инструмент может вернуть их обратно.

## Если документ нельзя применить

Предпросмотр показывает проблему каждого документа на месте, а **Применить** остаётся неактивной, пока каждый документ нельзя применить:

- **Некорректный YAML**, со строкой, на которой он ломается.
- **Неизвестный kind**: кластер не обслуживает этот `apiVersion` и `kind`. Пользовательскому ресурсу сначала нужен установленный CRD.
- **Отклонено кластером**: ответ его проверки для каждого поля, например отсутствующее обязательное поле или значение неверного типа.
- **Не разрешено**: для применения нужен `patch` на ресурс (и `create` для новых объектов), с командой `kubectl auth can-i` для проверки.
