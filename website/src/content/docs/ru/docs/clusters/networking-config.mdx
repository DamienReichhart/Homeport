## Service и Ingress

**Сеть** показывает **Service** выбранного пространства имён — их тип, cluster IP, внешние адреса (балансировщиков нагрузки и `externalIPs`) и порты так, как их показывает `kubectl` (`443:30443/TCP` с портом узла), — а на второй вкладке **Ingress** с их классом, хостами и адресами, опубликованными их контроллером.

- Страница Service показывает его порты и целевые порты, привязку сеансов, метки, по которым он выбирает Pod, и вкладку **Pod** с этими Pod. Service без селектора сообщает об этом: его конечные точки управляются вручную.
- Страница Ingress перечисляет пути каждого правила (сначала бэкенд по умолчанию) с тем, куда каждый направляет трафик, со ссылкой на страницу Service, а также его хосты TLS и Secret с сертификатами.

## ConfigMap и Secret

**Конфигурация** показывает **ConfigMap** и **Secret** с их ключами. Страница ConfigMap показывает каждое значение; для двоичных данных показан только размер.

<DocScreenshot
  name="cluster-secret"
  alt="Вкладка «Данные» Secret db-credentials: password раскрыт, с кнопками «Копировать» и «Скрыть», username всё ещё скрыт, с кнопкой «Показать»."
  caption="Один ключ раскрыт; другой остаётся скрытым, пока вы не попросите."
/>

Страница Secret показывает его тип и каждый ключ с размером, в скрытом виде. **Показать** получает из кластера одно это значение и показывает его в декодированном виде (двоичные значения — в base64) с кнопками **Копировать** и **Скрыть**. Значения никогда не входят ни в список, ни в страницу Secret, ни в его YAML; раскрытое значение не кэшируется, не сохраняется и не записывается в журнал и снова скрывается, когда вы покидаете страницу. См. [Безопасность и ваши данные](/docs/reference/security/#clusters).

На вкладке **YAML** у ConfigMap есть **Изменить**, чтобы изменить его через предпросмотр и server-side apply ([Применение и изменение YAML](/docs/clusters/yaml/)). Secret в Homeport не изменяются, поскольку он никогда не показывает все их значения сразу; вместо этого примените манифест Secret.

## Всё остальное

Endpoints и EndpointSlice, NetworkPolicy, PersistentVolume и ресурсы, которые добавляют ваши CRD, находятся в разделе [Ресурсы API](/docs/clusters/api-resources/).

У портов Service есть **Пробросить…**, чтобы [обратиться к нему с этого компьютера](/docs/clusters/port-forward/) через один из его готовых Pod; на каждой странице здесь в заголовке есть **Удалить**.
