---
title: Плагины exec
description: Как Homeport входит в кластеры EKS, GKE и AKS с помощью плагина учётных данных exec, указанного в их kubeconfig, и что где выполняется.
---

В облачных kubeconfig нет ни пароля, ни сертификата: их пользователь указывает **плагин exec** — программу на вашем компьютере, которая по запросу выводит короткоживущий токен. Homeport запускает ту же программу, что и `kubectl`, на этом компьютере, следуя протоколу Kubernetes `ExecCredential` (`client.authentication.k8s.io/v1` и `v1beta1`).

## Распространённые провайдеры

| Провайдер | Пользователь kubeconfig запускает    | Что установить                                                             |
| --------- | ------------------------------------ | -------------------------------------------------------------------------- |
| EKS       | `aws eks get-token --cluster-name …` | AWS CLI версии 2                                                           |
| GKE       | `gke-gcloud-auth-plugin`             | Google Cloud CLI, затем `gcloud components install gke-gcloud-auth-plugin` |
| AKS       | `kubelogin get-token …`              | `az aks install-cli` или kubelogin из его релизов                          |

Создайте kubeconfig как обычно — `aws eks update-kubeconfig`, `gcloud container clusters get-credentials`, `az aks get-credentials`, а затем `kubelogin convert-kubeconfig`, — после чего [добавьте его контексты](/docs/clusters/).

## Что где выполняется

- Плагин выполняется **на этом компьютере**, от вашего имени, с аргументами и переменными окружения, которые ему передаёт kubeconfig (например, `AWS_PROFILE`). Homeport никогда не просит его работать интерактивно и ничего не подаёт ему на вход.
- Ярлык рабочего стола запускает Homeport с коротким `PATH`, поэтому Homeport также ищет в обычных местах установки AWS CLI, Google Cloud CLI, Azure CLI и kubelogin (Homebrew, собственная папка SDK, `~/.local/bin`, `~/.krew/bin`, Program Files…). Плагин, указанный в kubeconfig по полному пути, запускается оттуда.
- Выведенный им токен или сертификат хранится **только в памяти**, до момента незадолго до истечения срока; затем плагин запускается снова. Он запускается один раз за время жизни токена, а не при каждом запросе. Когда API отклоняет токен, Homeport один раз просит у плагина новый, прежде чем показать **Доступ запрещён**.
- Собственные кэши плагина (`~/.kube/cache`, `~/.aws/sso/cache`, конфигурация gcloud) — его дело; Homeport туда ничего не пишет.

## Если войти не получается

- **«… не установлен на этом компьютере»** — программа не найдена. Установите её (в сообщении сказано как, с использованием `installHint` из kubeconfig, если он есть), проверьте, что она работает в терминале, затем нажмите **Переподключиться**.
- **«… требует входа, а внутри Homeport это сделать нельзя»** — плагину нужен браузер или код устройства (AWS SSO, вход Azure по коду устройства, истёкший сеанс `gcloud`). Запустите `kubectl` один раз в терминале с этим контекстом, войдите там, затем выберите **Переподключиться**: тогда плагин найдёт сохранённый вход.
- **«… не удалось получить учётные данные для …»** — плагин запустился, но завершился ошибкой; **Подробности** показывает конец того, что он вывел. Homeport сам пробует снова.

Остальные сообщения см. в разделе [Устранение неполадок](/docs/reference/troubleshooting/#кластеры).
