У Homeport есть собственные страницы для рабочих нагрузок, Pod, Service, Ingress, ConfigMap, Secret, Node и событий. **Ресурсы API** в боковой панели кластера охватывают всё остальное: PersistentVolume и их запросы, NetworkPolicy, ServiceAccount и RBAC, а также ресурсы, которые операторы добавляют своими CRD, — Certificate из cert-manager, Application из Argo CD, ServiceMonitor из Prometheus.

## Поиск типа

В левом столбце перечислены все типы, которые обслуживает кластер, сгруппированные по группе API (сначала `core`), в предпочтительной версии каждой группы, как это делает `kubectl api-resources`. Ищите по виду, форме множественного числа или группе либо введите короткое имя: `pvc`, `netpol`, `sa`, `cert`.

Замком отмечены типы, которые вы не можете перечислить: те, которые вашим учётным данным не разрешено перечислять в выбранном пространстве имён (как кластер сообщает Homeport через `SelfSubjectRulesReview`), и те немногие, чей API вообще не умеет перечислять. Если открыть такой тип, будет сказано почему. Некоторые кластеры, например те, у которых авторизатор — webhook, не могут этого сообщить; тогда ничего не отмечено, а список, в котором отказано, сообщает об этом.

Установка или удаление CRD обновляет список сам по себе; **Обновить** читает его заново.

## Список объектов

Выберите тип, и его объекты появятся с теми же столбцами, что и в `kubectl get`: какие именно, говорит API-сервер, включая `additionalPrinterColumns` из CRD, так что Certificate из cert-manager показывают **Ready**, **Secret** и **Возраст**, как в терминале. Список отслеживает изменения в реальном времени через watch.

У типов с пространством имён есть выбор пространства имён, как и на других страницах Homeport; при выборе **Все пространства имён** добавляется столбец **Пространство имён**.

## Страница объекта

Щёлкните объект, чтобы открыть его страницу:

- **Обзор**: его пространство имён, объекты, которые им владеют, — со ссылками на их страницы, — его возраст, метки и аннотации.
- **Условия**, если они есть в его `status`, как на собственных страницах Homeport.
- **События** о нём и его **YAML**, без `managedFields`.

Если его тип это позволяет, **Изменить** открывает его YAML, чтобы изменить его через предпросмотр и server-side apply (см. [Применение и изменение YAML](/docs/clusters/yaml/)), а **Удалить** удаляет его после подтверждения, в котором названы он и кластер (см. [Удаление](/docs/clusters/actions/#deleting)). В списке отметьте несколько объектов, чтобы удалить их вместе.
