## Node

**Node** перечисляет машины, на которых кластер запускает Pod, и для каждой показывает, находится ли она в состоянии **Ready** (и **размещение отключено**, если она закрыта для новых Pod), её роли, версию kubelet, внутренний IP, платформу, а также доступные для размещения CPU и память.

CPU показаны в ядрах (`3.92` для `3920m`), а память — в ГБ; Kubernetes сообщает, что **доступно для размещения** Pod, — немного меньше, чем есть у машины, поскольку часть оставляют себе kubelet и система.

Страница Node показывает его образ ОС, ядро, среду выполнения контейнеров, адреса, taint, метки и ёмкость рядом с тем, что доступно для размещения Pod; затем **Pod**, работающие на нём, во всех пространствах имён, его **Условия** (нехватка памяти, диска и PID), **События** и **YAML**. Страница Pod ссылается на его Node.

## События

<DocScreenshot
  name="cluster-events"
  alt="Страница «События»: сначала три предупреждения (Pod в состоянии back-off, образ, который не удаётся скачать, Node не готов), затем обычные события, каждое со своим объектом, сообщением, числом повторов и возрастом."
/>

**События** перечисляет то, о чём Kubernetes сообщил в выбранном пространстве имён (или во всех): сначала предупреждения, затем самые новые, каждое со своей причиной, объектом, к которому оно относится, — со ссылкой на страницу этого объекта, — сообщением, числом повторов и временем последнего повтора. Фильтруйте по **Предупреждения** или **Обычные** и ищите по причине, объекту или сообщению. Список обновляется в реальном времени.

Kubernetes хранит события около часа, поэтому пустой список на спокойном кластере — это нормально. У страницы каждого объекта также есть своя вкладка **События**.

## Если ваши учётные данные чего-то не видят

Node не принадлежат пространству имён, поэтому для их перечисления нужно разрешение на уровне всего кластера, которого у многих пользователей нет. Тогда страница сообщает «Ваши учётные данные не разрешают „list“ для nodes.», а все остальные страницы продолжают работать.
