**Incus** запускает системные контейнеры и виртуальные машины — **экземпляры** из [руководства](/docs/guides/instances/). Homeport подключается к нему через его собственный REST API, как решено в [ADR 0021](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0021-incus-over-its-rest-api.md). Хост Incus получает в боковой панели собственные страницы: **Экземпляры**, **Образы**, **Профили**, **Хранилище** и **Сети**. Страницы Docker, стеки и Доска для него не предлагаются.

## Добавление хоста Incus

Выберите **Incus** в поле **Движок** формы, затем способ подключения:

| Подключение         | Когда                                                 | Что нужно                                                            |
| ------------------- | ----------------------------------------------------- | -------------------------------------------------------------------- |
| **Локальный сокет** | Incus работает на этом компьютере (Linux)             | ваш пользователь в группе `incus-admin` или `incus` (см. ниже)       |
| **SSH**             | Incus работает на сервере, на который вы можете войти | пользователь SSH в группе `incus-admin` или `incus`                  |
| **TLS** (HTTPS)     | Incus слушает в сети, или SSH не разрешён             | токен доверия или клиентский сертификат, которому Incus уже доверяет |

Обычный **TCP** неактивен: Incus не предоставляет свой API без TLS. Homeport подключается к **Incus 6.0** (выпуск с долгосрочной поддержкой) и новее.

### Его сокеты

| Сокет                             | Кто может использовать        | К чему даёт доступ                                                                |
| --------------------------------- | ----------------------------- | --------------------------------------------------------------------------------- |
| `/var/lib/incus/unix.socket`      | группа `incus-admin`          | ко всему: всем проектам, пулам хранения и сетям                                   |
| `/var/lib/incus/unix.socket.user` | группа `incus` (`incus-user`) | только к собственному проекту пользователя, создаваемому при первом использовании |

В Linux раздел **Найдено на этом компьютере** показывает оба сокета, если они отвечают, а ограниченный — как **Incus (restricted to your project)**. Сокет, который вам пока нельзя использовать, показывается с командой, которая это исправляет:

```bash
sudo usermod -aG incus-admin "$USER"
```

Изменения групп действуют для новых входов: выйдите и войдите снова (или переподключитесь по SSH), прежде чем добавлять хост. Остановленный Incus сообщает, какие юниты его запускают:

```bash
sudo systemctl enable --now incus.socket incus.service
```

### По HTTPS с токеном доверия

Incus слушает в сети, как только задан `core.https_address`. На сервере Incus:

```bash
incus config set core.https_address :8443
incus config trust add homeport
```

Вторая команда выводит **токен доверия**: одну строку из букв и цифр. В Homeport выберите **Incus** и **TLS**, оставьте **Токен доверия** и вставьте его. Homeport показывает, что он из него прочитал (имя, для которого он выдан, адреса сервера и отпечаток сертификата, а также срок действия), а затем по нажатию **Добавить**:

1. создаёт собственный клиентский сертификат с ключом ECDSA P-384, созданным в памяти;
2. по порядку пробует адреса из токена и оставляет первый, у сертификата которого отпечаток, указанный в токене; любой другой отклоняется с указанием обоих отпечатков;
3. отправляет токен вместе со своим сертификатом и проверяет, что Incus теперь ему доверяет.

После этого хост появляется в `incus config trust list` под именем из токена. Токен срабатывает один раз и имеет срок действия; использованный, отозванный или просроченный токен отклоняется с командой, которая создаёт новый. Чтобы позже отозвать доступ Homeport, удалите там его сертификат:

```bash
incus config trust list
incus config trust remove <fingerprint>
```

**Существующий сертификат** принимает клиентский сертификат и ключ, которым Incus уже доверяет (`incus config trust add-certificate`), вместе с собственным сертификатом Incus, которому нужно доверять (`/var/lib/incus/server.crt` или `cluster.crt` в кластере).

### Сертификат сервера закрепляется

Сертификат Incus самоподписанный, поэтому нет ЦС, по которому его можно проверить. Homeport хранит сертификат, которому доверился, вместе с хостом и в дальнейшем принимает только его, сравнивая по отпечатку SHA-256, по какому бы адресу к нему ни подключались. Если Incus переустановлен или его сертификат обновлён, хост отклоняется с ожидаемым и полученным отпечатками: проверьте новый на сервере командой `incus info`, затем добавьте хост заново с новым токеном. Клиентский ключ и оба сертификата хранятся в зашифрованном виде, как и любой другой секрет; см. [безопасность](/docs/reference/security/#incus-certificates).

## Проекты

Incus хранит экземпляры, образы, профили, пользовательские тома и сети в **проектах**. Страницы показывают один проект за раз, выбранный под переключателем хостов, где у каждого указано, сколько в нём экземпляров и образов. Homeport запоминает выбор для каждого хоста между запусками. Пока вы ничего не выбрали, хост показывает `default` или, на ограниченном сокете, свой единственный проект. Пулы хранения принадлежат всему серверу; их тома показываются для выбранного проекта.

## События

Страницы обновляются по событиям жизненного цикла Incus во всех проектах: запуск или остановка экземпляра, создание снимка, добавление образа, изменение профиля или сети. Они также сохраняются на странице **События**. Incus не хранит их историю, поэтому то, что произошло, пока Homeport был закрыт, не восполняется.

Пока подключение активно, Homeport каждые 15 секунд запрашивает у Incus `GET /1.0`. Остановленный Incus делает хост **Недоступен**, и Homeport сам переподключается, когда тот снова отвечает.

## Что Homeport делает на хосте

На хосте Incus ничего не запускается, кроме самого Incus: консоли и терминалы идут через собственные веб-сокеты Incus, а удалённые образы скачивает Incus. Список образов удалённого сервера образов Homeport читает с этого компьютера, для выбора образа.
