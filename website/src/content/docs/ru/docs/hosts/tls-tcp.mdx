Движки Docker могут слушать не только свой сокет, но и порт TCP. Homeport подключается к ним по взаимному TLS — Docker называет такую настройку `--tlsverify` — или, в сети, которой вы полностью доверяете, по обычному TCP.

## TLS

При взаимном TLS Homeport проверяет сертификат сервера по вашему ЦС, а сервер проверяет клиентский сертификат Homeport. Это безопасный способ открыть движок в сети.

### Что понадобится

Три файла из вашей настройки TLS для Docker в формате PEM:

| Поле                      | Обычно называется | Содержит                                                                                    |
| ------------------------- | ----------------- | ------------------------------------------------------------------------------------------- |
| **Сертификат ЦС**         | `ca.pem`          | Центр сертификации, подписавший сертификат сервера. Может содержать несколько сертификатов. |
| **Клиентский сертификат** | `cert.pem`        | Сертификат Homeport, подписанный ЦС, которому доверяет сервер.                              |
| **Клиентский ключ**       | `key.pem`         | Закрытый ключ клиентского сертификата, без шифрования.                                      |

Как их создать, объясняет руководство Docker [Protect the Docker daemon socket](https://docs.docker.com/engine/security/protect-access/).

### Добавление хоста TLS

1. Выберите **Добавить хост…** в переключателе хостов и выберите **TLS**.
2. Введите **Имя** и **Адрес** в виде `host:port`, например `docker.example.com:2376`.
3. Для каждого сертификата и для ключа вставьте текст PEM или выберите **Загрузить из файла…**.
4. Выберите **Добавить хост**.

Сертификат сервера должен называть введённый вами хост — его DNS-имя или IP-адрес должны быть среди альтернативных имён субъекта (subject alternative names) сертификата, — иначе подключение завершится ошибкой _Не удалось установить защищённое соединение с …_

Сертификаты и ключ хранятся в зашифрованном виде, для чего нужна [связка ключей ОС](/docs/requirements/#необязательно-связка-ключей-ос). При изменении хоста оставьте поле пустым, чтобы сохранить то, что уже хранится.

### Из контекста Docker

Если `docker context ls` уже показывает движок, **Импортировать контексты Docker** на странице **Добавить хост** создаёт хост с адресом контекста и его `ca.pem`, `cert.pem` и `key.pem`, без выбора файлов. Контексты, пропускающие проверку TLS, не импортируются. См. [Контексты Docker](/docs/hosts/#контексты-docker).

## TCP

Хост **TCP** подключается к `tcp://host:port` без шифрования и без аутентификации.

<Aside type="danger" title="Без шифрования и без аутентификации">
  Любой, кто может достучаться до порта, управляет движком — а через него и компьютером. Используйте
  обычный TCP только в сети, которой полностью доверяете, например для локальной виртуальной машины.
  В остальных случаях используйте [SSH](/docs/hosts/ssh/) или TLS.
</Aside>

1. Выберите **Добавить хост…** и выберите **TCP**.
2. Введите **Имя** и **Адрес** в виде `host:port`, например `192.168.1.10:2375`. Адреса IPv6 пишутся в квадратных скобках: `[fd00::10]:2375`.
3. Выберите **Добавить хост**.
