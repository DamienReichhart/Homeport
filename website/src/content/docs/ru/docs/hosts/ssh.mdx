SSH — рекомендуемый способ подключения к движку Docker на сервере. Не нужно открывать ничего, кроме порта SSH, а сокет движка остаётся доступным только на сервере.

## Как это работает

У Homeport свой клиент SSH. Он входит на сервер и пробрасывает канал к сокету Unix движка — то же, что делает `docker -H ssh://…`, но без необходимости иметь на вашем компьютере программу `ssh` или `docker`.

- Ключи расшифровываются только в памяти и никогда не записываются на диск, поэтому всё работает одинаково в Windows, macOS и Linux.
- Homeport не читает `~/.ssh/known_hosts`: ключам серверов доверяют в самом Homeport, для каждого хоста отдельно. Сервер, доступный только через промежуточный сервер, добавляется с [бастионами](#through-a-bastion) — аналогом `ProxyJump` в Homeport.
- Сервер должен разрешать перенаправление на сокеты Unix. OpenSSH разрешает его по умолчанию (`AllowStreamLocalForwarding yes`).

## Добавление хоста SSH

<Steps>

1. Выберите **Добавить хост…** в переключателе хостов и оставьте выбранным **SSH**.

2. Заполните параметры подключения:

   | Поле                         | Что ввести                                                                                                                                                      |
   | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | **Имя**                      | Понятное вам имя, например `production`.                                                                                                                        |
   | **Сервер**                   | Имя хоста или IP-адрес сервера.                                                                                                                                 |
   | **Порт**                     | Порт SSH; по умолчанию `22`.                                                                                                                                    |
   | **Пользователь**             | Учётная запись для входа. Ей нужен доступ к сокету Docker, обычно через группу `docker`.                                                                        |
   | **Путь к удалённому сокету** | Где движок слушает на сервере: по умолчанию `/var/run/docker.sock`, `/run/user/<uid>/docker.sock` для rootless Docker или `/run/podman/podman.sock` для Podman. |

3. Выберите способ входа в разделе **Аутентификация** (см. ниже).

4. Выберите **Добавить хост**. Homeport откроет страницу хоста и подключится.

</Steps>

## Импорт из ~/.ssh/config

Если ваши серверы уже есть в `~/.ssh/config`, выберите **Импортировать из ~/.ssh/config** на странице **Добавить хост** вместо того, чтобы вводить каждый вручную. Homeport перечисляет все серверы, указанные в файле, — следуя `Include` и применяя значения по умолчанию из `Host *`, — а вы выбираете, какие добавить.

| В `~/.ssh/config`  | В Homeport                                                                                                       |
| ------------------ | ---------------------------------------------------------------------------------------------------------------- |
| `Host prod`        | Хост с именем `prod`. Записи с подстановочными знаками (`Host *.example.com`) дают только значения по умолчанию. |
| `HostName`         | **Сервер**; если его нет — сам псевдоним.                                                                        |
| `User`, `Port`     | **Пользователь** (по умолчанию имя вашего локального пользователя) и **Порт** (`22`).                            |
| `IdentityFile`     | **Существующий ключ**: первый файл, который удаётся прочитать, с раскрытием `~` и `%h`, `%r`, `%u`, `%p`.        |
| нет `IdentityFile` | **ssh-agent**.                                                                                                   |
| `ProxyJump a,b`    | Два [бастиона](#through-a-bastion) по порядку, каждый ищется в том же файле. О зацикливании сообщается.          |

**Путь к удалённому сокету** изначально равен `/var/run/docker.sock`; для rootless Docker или Podman измените его в предварительном просмотре. Там же запрашивается парольная фраза зашифрованного ключа.

Предварительный просмотр отмечает то, что требует внимания: ключ, который не удаётся прочитать (тогда хост использует ssh-agent), `ProxyCommand` (не поддерживается; добавьте его промежуточные серверы как бастионы) и псевдоним, который уже является именем хоста. Такой псевдоним не выбирается: переименуйте его, чтобы импортировать, — так повторный импорт никогда не создаёт дубликатов. Ключи читаются один раз и хранятся в зашифрованном виде; сам файл никогда не изменяется, а блоки `Match` и сертификаты (`CertificateFile`) игнорируются.

## Аутентификация

### Новый ключ для этого хоста (рекомендуется)

Homeport создаёт ключ Ed25519 специально для этого хоста, хранит его в зашифрованном виде и показывает команду, которая авторизует его на сервере. Один ключ на хост означает, что можно отозвать доступ Homeport к одному серверу, ничего больше не трогая. Комментарий ключа называет этот компьютер и хост, например `homeport@laptop-production`, так что его легко отличить в `authorized_keys`.

### Существующий ключ

Вставьте закрытый ключ или выберите **Загрузить из файла…** и введите его **Парольную фразу**, если она есть. Homeport читает ключи OpenSSH (`BEGIN OPENSSH PRIVATE KEY`), ключи PKCS#8 и PEM, а также файлы PuTTY `.ppk` с ключами Ed25519, ECDSA или RSA. Ключ и его парольная фраза хранятся в зашифрованном виде, так что повторно их не спрашивают.

### ssh-agent

Homeport запрашивает ключи у вашего запущенного агента SSH и ничего не хранит. В macOS и Linux он использует агент по адресу `$SSH_AUTH_SOCK`.

В Windows он сначала обращается к службе OpenSSH Authentication Agent, затем к **Pageant** из PuTTY — или к заменяющему его инструменту, например KeeAgent или gpg-agent с поддержкой PuTTY. Подходит ключ, хранящийся в любом из них: если агент OpenSSH не запущен или в нём нет ключа, который принимает сервер, Homeport пробует и ключи Pageant.

<Aside>
  ssh-agent — единственный вариант SSH, который работает без [связки ключей
  ОС](/docs/requirements/#optional-an-os-keychain). Если Homeport запущен из меню рабочего стола,
  убедитесь, что агент вашего сеанса ему доступен.
</Aside>

## Первое подключение

При первом подключении страница хоста проводит вас через два шага.

### Доверьтесь ключу сервера

Состояние показывает **Ключ сервера не доверенный**, а страница спрашивает **Это нужный сервер?** и показывает отпечаток ключа сервера, например `SHA256:Kx8f…`.

Сравните его с отпечатком на сервере:

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

Если они совпадают, выберите **Доверять этому ключу**. Homeport запомнит его и подключится. Это та же проверка доверия при первом использовании, что выполняет `ssh`, только ключ хранится в Homeport, а не в `~/.ssh/known_hosts`.

### Авторизуйте ключ Homeport

Для ключа, созданного Homeport или импортированного вами, карточка **Авторизуйте Homeport на сервере** показывает две команды, у каждой есть кнопка **Копировать**. Выполните их на сервере от имени пользователя SSH:

<DocScreenshot
  name="host-ssh"
  alt="Страница хоста SSH с командами, которые авторизуют ключ Homeport на сервере."
/>

<Steps>

1. **Добавьте открытый ключ** в `authorized_keys` пользователя:

   ```sh
   mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'ssh-ed25519 AAAAC3Nza… homeport@laptop-production' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
   ```

2. **Дайте пользователю доступ к Docker**, если его ещё нет:

   ```sh
   sudo usermod -aG docker deploy
   ```

3. Вернитесь в Homeport и выберите **Переподключиться**.

</Steps>

Пока ключ не авторизован, хост показывает **Доступ запрещён**: _Сервер отклонил ключ для deploy@server. Добавьте открытый ключ в его authorized_keys._ Он ждёт вас, а не повторяет попытки.

## Если ключ сервера изменился

Если позже сервер предъявит другой ключ, Homeport остановится и покажет **Ключ сервера изменился** с ожидаемым и предъявленным отпечатками.

<Aside type="caution">
  Смена ключа ожидаема после переустановки сервера или пересоздания его ключей хоста. Но она может
  также означать, что кто-то перехватывает соединение. Доверяйте новому ключу, только если знаете,
  почему он изменился.
</Aside>

Когда будете уверены, выберите **Доверять новому ключу** и подтвердите.

Если изменить хост так, чтобы он указывал на другой сервер или порт, доверенный ключ забывается, и вас попросят довериться новому. Переименование хоста или смена пользователя либо пути к сокету его сохраняют.

## Через бастион

Некоторые серверы принимают SSH только с промежуточного сервера. Добавьте этот сервер в разделе **Бастионы** формы хоста, и Homeport сначала войдёт на него, а затем подключится к хосту через него — так же, как `ssh -J` или `ProxyJump`, но собственным клиентом SSH Homeport. На бастион ничего не устанавливается, и никакой ключ не записывается на диск.

<Steps>

1. В форме хоста SSH выберите **Добавить бастион**.

2. Введите его **Сервер**, **Порт** и **Пользователя**.

3. Выберите, как Homeport будет на него входить:

   | Аутентификация       | Когда использовать                                                                                                                                |
   | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
   | **Как у хоста**      | Бастион принимает ключ, который использует хост: созданный Homeport, ваш существующий ключ или ключ вашего агента.                                |
   | **Собственный ключ** | Бастиону нужен другой ключ. Вставьте его или выберите **Загрузить из файла…**; он хранится в зашифрованном виде вместе с другими секретами хоста. |
   | **ssh-agent**        | В вашем агенте есть ключ бастиона, а хост использует другой, например ключ, созданный Homeport специально для него.                               |

4. Для цепочки промежуточных серверов (`ProxyJump a,b`) добавьте по одному бастиону на сервер, в том порядке, в котором Homeport их проходит. Стрелки перемещают бастион вверх или вниз.

</Steps>

При первом подключении Homeport по очереди просит довериться ключу каждого сервера, начиная с первого бастиона: **Это нужный бастион?** называет его и показывает его отпечаток. Ключ каждого бастиона хранится вместе с хостом, и изменившийся ключ останавливает подключение с сообщением **Ключ бастиона … изменился**, как и для самого хоста.

Если хост использует ключ, созданный Homeport, карточка **Авторизуйте Homeport на сервере** перечисляет все серверы, на которые его нужно добавить: каждый бастион с настройкой **Как у хоста**, затем сам хост.

Бастион должен разрешать перенаправление TCP к хосту (`AllowTcpForwarding yes`, значение OpenSSH по умолчанию). Если это не так или бастион не может достучаться до хоста, хост показывает _Бастион … не смог открыть соединение с …_.

Перемещение бастиона в списке сохраняет его доверенный ключ; смена его сервера или порта забывает только этот ключ.

## Пересоздание ключа

Для ключа, созданного Homeport, кнопка **Создать ключ заново** на странице хоста заменяет его. Старый ключ перестаёт работать, поэтому выполните на сервере новую команду **Добавьте открытый ключ** и удалите старую строку из `~/.ssh/authorized_keys`.

## Удаление хоста SSH

Удаление хоста удаляет его ключ из Homeport, но не с сервера. Удалите его строку из `~/.ssh/authorized_keys` пользователя — её можно узнать по комментарию, начинающемуся с `homeport@`.

## Частые проблемы

| Сообщение                                                                                                 | Что делать                                                                                                                                                                                             |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| _Сервер отклонил ключ для …_                                                                              | Выполните на сервере команду **Добавьте открытый ключ**, затем выберите **Переподключиться**.                                                                                                          |
| _SSH-сервер не смог открыть /var/run/docker.sock … Проверьте путь и то, что … может использовать Docker._ | Проверьте **Путь к удалённому сокету** и добавьте пользователя в группу `docker`.                                                                                                                      |
| _Время ожидания SSH-подключения истекло_                                                                  | Проверьте имя сервера, порт и межсетевые экраны между вами.                                                                                                                                            |
| _ssh-agent не запущен_                                                                                    | Запустите агент, добавьте ключ командой `ssh-add` и убедитесь, что Homeport видит `SSH_AUTH_SOCK`. В Windows откройте Pageant и загрузите свой ключ или запустите службу OpenSSH Authentication Agent. |
| _Бастион … не смог открыть соединение с …_                                                                | Проверьте, что бастион может достучаться до хоста и что его `sshd` разрешает `AllowTcpForwarding`.                                                                                                     |

Подробнее — в разделе [Устранение неполадок](/docs/reference/troubleshooting/).
