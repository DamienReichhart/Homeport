**Quadlet** — это способ, которым Podman запускает долгоживущие сервисы под управлением systemd. Юнит Quadlet — это файл (`web.container`, `shop.pod`, `cache.volume`, `lan.network`, `app.kube`, `base.image`, `api.build`), который генератор systemd превращает в сервис `web.service`, запускающий контейнер при загрузке и перезапускающий его, когда тот останавливается. Podman с правами root хранит свои юниты в `/etc/containers/systemd/`; Podman без root хранит юниты каждого пользователя в `~/.config/containers/systemd/`.

Страница **Quadlet** появляется в боковой панели, пока выбран хост Podman. Она работает через собственный API Podman на том же сокете, который хост уже использует, а для запуска и остановки — через `systemctl`, как решено в [ADR 0019](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0019-quadlet-units-through-podmans-api-and-systemctl.md).

## Что позволяют разные версии Podman и подключения

API Podman получил поддержку Quadlet за два выпуска, и он никогда не запускает и не останавливает сервис юнита. Поэтому то, что может Homeport, зависит от Podman на хосте и от того, как Homeport к нему подключается:

| Действие                               | Podman          | Подключение                     |
| -------------------------------------- | --------------- | ------------------------------- |
| Список юнитов с их состоянием          | 5.7 и новее     | любое                           |
| Список юнитов по их контейнерам        | от 4.0 до 5.6   | любое                           |
| Чтение файла юнита                     | 5.8 и новее     | любое                           |
| Установка, изменение и удаление юнитов | 5.8 и новее     | любое                           |
| Запуск, остановка и перезапуск сервиса | любой с Quadlet | SSH или локальный сокет в Linux |

В Podman до 5.7 юниты находятся по метке `PODMAN_SYSTEMD_UNIT`, которую Podman ставит на созданные ими контейнеры, поэтому юнит появляется, только когда он создал контейнер, и называется по своему сервису. Страница сообщает об этом над списком.

Для запуска и остановки нужен `systemctl`, который Homeport выполняет там же, где работает Podman: в SSH-сеансе хоста SSH или на этом компьютере для локального сокета в Linux. Хост TCP или TLS либо локальный сокет в macOS или Windows (где Podman работает в виртуальной машине) может всё остальное; кнопки неактивны, и указана причина.

## Страница Quadlet

| Столбец        | Что показывает                                                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **Юнит**       | Имя файла юнита и приложение, с которым он был установлен.                                                                                   |
| **Вид**        | `container`, `pod`, `volume`, `network`, `kube`, `image`, `build` или `artifact`.                                                            |
| **Сервис**     | Сервис systemd, который он генерирует, или **ещё не сгенерирован**, пока systemd его не загрузил.                                            |
| **Состояние**  | **Работает**, **Запускается**, **Останавливается**, **Остановлен**, **Сбой**, **Не загружен systemd** или **Шаблон** — как сообщает systemd. |
| **Контейнеры** | Сколько контейнеров он создал.                                                                                                               |

В каждой строке есть **Запустить** для остановленного юнита или **Остановить** для работающего. Выберите юнит, чтобы открыть его страницу. Список обновляется сам, когда его контейнеры запускаются и останавливаются.

Юнит в состоянии **Не загружен systemd** установлен, но генератор systemd его пропустил: обычно из-за ошибки в файле. На хосте `systemctl --user daemon-reload` (или `systemctl daemon-reload` для Podman с правами root) и затем `journalctl` покажут причину.

На странице **Контейнеры** у контейнера, созданного юнитом, рядом с именем показан сервис юнита; выберите его, чтобы открыть юнит.

## Страница юнита

- В заголовке есть **Запустить**, **Остановить** и **Перезапустить**, **Изменить** и **Удалить**.
- **Сервис** показывает юнит systemd, системный это юнит или пользовательский (`systemctl --user`), где на хосте лежит его файл, а также его приложение и под, если они есть.
- **Файл юнита** показывает файл так, как его читает Podman, с подсветкой.
- **Контейнеры** перечисляет созданные им контейнеры; каждый открывает страницу своего контейнера.

Остановка контейнера юнита со страницы «Контейнеры» идёт вразрез с systemd, который запускает его снова согласно `Restart=`. Вместо этого остановите юнит.

## Установка юнита

**Новый юнит** (или `n` на странице Quadlet, или **Новый юнит** в палитре команд) открывает редактор с заготовкой для выбранного вида или с файлом, который вы открываете с этого компьютера через **Открыть файл…**. Назовите его с расширением, например `web.container`; в файле нужна секция его вида — `[Container]` для `.container`.

**Добавить файлы…** кладёт другие файлы рядом с юнитом — `Containerfile` для `.build`, YAML для `.kube`, файл переменных окружения — в папку приложения, названную по юниту, как это делает `podman quadlet install`.

Podman записывает файлы туда, где лежат юниты его пользователя, и перезагружает systemd, так что сервис появляется сразу. Установка его не запускает: когда он появится, выберите **Запустить**. Юнит с уже занятым именем отклоняется; измените вместо этого существующий.

## Изменение и удаление

**Изменить** открывает файл юнита. **Сохранить** записывает его на место и перезагружает systemd; файлы, установленные рядом с ним, остаются. Работающий сервис сохраняет прежние настройки, пока вы его не **Перезапустите**.

**Удалить** удаляет файл юнита и перезагружает systemd. **Сначала остановить его работающий сервис** включено по умолчанию; без этого Podman откажется удалять работающий юнит. Контейнеры, тома и образы, созданные юнитом, сохраняются.

## Что Homeport выполняет на хосте

Для **Запустить**, **Остановить** и **Перезапустить**, и ни для чего другого, Homeport выполняет одну команду на сервере хоста по SSH (или на этом компьютере для локального сокета) с правами пользователя SSH:

```bash
systemctl --user start 'web.service'
```

`--user` указывается для юнитов Podman без root и опускается для юнитов Podman с правами root; для этих действий `start` заменяется на `stop` или `restart`. Homeport проверяет имя сервиса и заключает его в кавычки и никогда не использует `sudo`. Поэтому:

- **Системным юнитам** (Podman с правами root) нужен пользователь SSH, которому разрешено ими управлять, например `root`.
- **Пользовательским юнитам** (Podman без root) нужен экземпляр systemd этого пользователя. Чтобы он работал без сеанса входа и юниты запускались при загрузке, один раз включите lingering от имени этого пользователя на хосте:

```bash
loginctl enable-linger "$USER"
```

На [странице о безопасности](/docs/reference/security/#что-homeport-запускает-на-ваших-хостах) перечислены все команды, которые Homeport выполняет на хосте.
