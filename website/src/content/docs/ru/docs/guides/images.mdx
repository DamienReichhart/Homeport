Остановленные контейнеры тоже считаются использующими образ. Выберите заголовок столбца, чтобы отсортировать, и ищите через **Поиск образов**.

⬆ рядом с именем означает, что один из тегов образа указывает на более новый образ в его реестре; наведите на значок, чтобы увидеть, какой именно. Скачайте тег, чтобы получить его. **Проверить новые версии образов** снова опрашивает реестры вместо того, чтобы использовать ответы, хранящиеся 6 часов. Как работает проверка, описано в разделе [Новые версии образов](/docs/guides/containers/#newer-images).

## Скачивание образа

Выберите **Скачать образ** и введите ссылку: `nginx` (что означает `nginx:latest`), `nginx:1.27`, `ghcr.io/org/app:v2`, `registry.example.com:5000/app` или дайджест, например `app@sha256:…`.

Homeport показывает ход скачивания слой за слоем и пишет **Готово.**, когда оно завершено. **Отмена** прекращает следить за скачиванием.

### Поиск в Docker Hub

При вводе простого имени, например `postg`, поиск в Docker Hub идёт по мере ввода и показывает подходящие репозитории с их описанием, звёздами и пометкой **Официальный**. Выберите один, чтобы увидеть его теги, сначала самые новые, с их размером и временем отправки; **Фильтр тегов** сужает список (`alpine`), а **Ещё теги** загружает следующую страницу. Выбор тега заполняет ссылку, например `postgres:17-alpine`, — всё готово, чтобы нажать **Скачать**.

Поиск выполняется на выбранном хосте, поэтому он обращается к Docker Hub через сеть хоста, как и само скачивание. Теги читает из Docker Hub этот компьютер; сохранённый [вход](/docs/guides/settings/#registries) в Docker Hub повышает его лимиты запросов. Если ввести тег, дайджест или другой реестр (`ghcr.io/…`), поиск пропускается, а если Docker Hub недоступен, диалог сообщает об этом и всё равно скачивает то, что вы ввели. Искать в других реестрах пока нельзя.

### Приватные образы

Когда вход в реестр образа сохранён в [**Настройки → Реестры**](/docs/guides/settings/#registries), Homeport передаёт его движку вместе со скачиванием, поэтому приватные образы скачиваются на любом хосте — локальном, TCP, TLS или SSH — без какой-либо настройки на нём. Под ссылкой диалог сообщает, как будет скачан образ: **Скачано как alice из ghcr.io** или **Скачано анонимно**, если подходящего входа нет.

Образ без реестра в имени (`nginx`, `bitnami/redis`) использует вход в Docker Hub. Вход в Docker Hub также повышает лимит скачиваний Docker Hub.

Если реестр отказывает в скачивании, сообщение говорит, что делать: добавить вход в этот реестр, если он не был сохранён, или проверить сохранённый.

<Aside>
  Данные входа передаются движку вместе с запросом и не сохраняются на хосте. Homeport не читает
  учётные данные `docker login` из `~/.docker/config.json`.
</Aside>

## Сборка образа

Выберите **Собрать** и укажите **Папку** на этом компьютере, в которой лежит Dockerfile, — контекст сборки. Homeport упаковывает папку, исключает всё, что исключает её `.dockerignore` (по правилам Docker: `*`, `**`, исключения `!`, побеждает последняя подходящая строка), и передаёт её потоком на выбранный хост, движок которого её собирает. Та же сборка работает на удалённом хосте по SSH или TLS, без установки чего-либо на нём.

| Поле                                     | Что делает                                                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **Dockerfile**                           | Его путь внутри папки; по умолчанию `Dockerfile`. Он отправляется всегда, даже если указан в `.dockerignore`. |
| **Целевой этап**                         | Этап многоэтапного Dockerfile, на котором нужно остановиться (`--target`).                                    |
| **Имена**                                | Одно или несколько имён для результата, например `app:1.0, ghcr.io/me/app:1.0`.                               |
| **Аргументы сборки**                     | `NAME=value`, по одному на строку, для `ARG` в Dockerfile.                                                    |
| **Не использовать кеш сборки**           | Выполняет все шаги заново (`--no-cache`).                                                                     |
| **Скачать новые версии базовых образов** | Скачивает образы `FROM`, даже если они есть на хосте (`--pull`).                                              |

Вывод сборки передаётся в реальном времени; **Отмена** её останавливает. Когда она завершится, имена появятся на странице «Образы». Если шаг завершился сбоем, сообщение его называет (**Сборка завершилась сбоем на шаге 3/5 (RUN make)**), а в **Подробностях** — конец вывода. Приватные образы `FROM` скачиваются с сохранёнными вами [входами в реестры](/docs/guides/settings/#registries).

<Aside>
  Homeport использует классический сборщик движка — тот, который предлагает его API. Возможности
  BuildKit, такие как `RUN --mount` и секреты сборки, недоступны; собирайте такое из терминала.
</Aside>

### Вместо этого — фиксация контейнера

Образ можно получить и из контейнера: **Зафиксировать в образ…** в меню **⋮** контейнера сохраняет его файлы и настройки в их текущем виде — см. [Фиксация контейнера](/docs/guides/containers/#committing-a-container). Это быстрый способ сохранить то, что кто-то установил или изменил внутри работающего контейнера. Сборка — способ надолго: её Dockerfile описывает, как сделан образ, поэтому его можно пересобрать, проверить и обновить, когда базовый образ уйдёт вперёд. Зафиксированный образ — нельзя.

## Отправка образа

Выберите **Отправить** в меню **⋮** образа. **Имя для отправки** сначала совпадает с первым именем образа; выберите другое из его имён или введите новое, например `ghcr.io/org/app:v2`, — сначала образу присваивается это имя, как при **Добавить тег**. Первая часть имени указывает, в какой реестр он отправляется: `ghcr.io/org/app` — в GHCR, `org/app` — в Docker Hub.

Homeport отправляет образ через движок хоста с [входом в реестр](/docs/guides/settings/#registries), сохранённым для этого реестра, и под именем указывает, с каким именно (**Отправлено как alice в ghcr.io**). Если вход не сохранён, диалог предупреждает до начала, поскольку большинство реестров отклоняют анонимную отправку. Во время работы диалог считает отправленные слои и те, что уже были в реестре, и показывает идущую выгрузку; **Отмена** останавливает отправку.

Если реестр отказывает, сообщение говорит, нужно ли добавить вход или проверить, может ли сохранённый вход отправлять в этот репозиторий.

## Сохранение и загрузка образов

Чтобы перенести образы на хост, у которого нет доступа к реестру, — изолированный сервер, Raspberry Pi в домашней сети, — сохраните их в файл на этом компьютере и загрузите файл на другой хост.

- **Сохранить…** в меню **⋮** образа записывает его со всеми его именами в один выбранный вами файл `.tar`. Чтобы сохранить несколько сразу, отметьте их в списке и выберите **Сохранить N образов…** вверху страницы.
- **Загрузить…** вверху страницы считывает `.tar`, созданный через **Сохранить…** или `docker save`, — в том числе сжатый `.tar.gz` — на выбранный хост. По завершении диалог называет загруженные образы с их тегами.

Файл передаётся между этим компьютером и хостом по собственному подключению хоста, так что это работает и для удалённых хостов. Ход выполнения показывает записанные или отправленные байты; **Отмена** останавливает операцию, а отменённое или неудачное сохранение не оставляет частичного файла. Homeport никогда не держит в памяти весь архив, так что образы размером в несколько гигабайт не проблема.

### Импорт файловой системы

**Импортировать из tar…** вверху страницы превращает tar корневой файловой системы в образ, как `docker import`: созданный через [**Экспортировать файловую систему…**](/docs/guides/containers/#exporting-a-containers-filesystem) контейнера или `docker export`, результат `debootstrap` или Buildroot либо готовый образ от поставщика. Выберите файл (обычный или сжатый gzip, xz или bzip2), дайте образу **имя** — изначально это имя файла — и при желании укажите **Изменения**: инструкции Dockerfile, например `CMD ["/bin/sh"]` или `ENV LANG=C.UTF-8`, поскольку у импортированного образа нет своей команды. Ход выполнения показывает отправленные байты; затем образ появляется в списке.

### Сохранение и загрузка или экспорт и импорт?

|                 | **Сохранить** / **Загрузить**        | **Экспортировать файловую систему** / **Импортировать из tar**            |
| --------------- | ------------------------------------ | ------------------------------------------------------------------------- |
| Исходные данные | Один или несколько образов           | Файлы одного контейнера в их текущем виде                                 |
| Сохраняет       | Все слои, историю, имена и настройки | Только файлы, сведённые в один слой                                       |
| Теряет          | Ничего                               | Историю, имена и настройки, такие как команда и окружение                 |
| Для чего        | Перенести образы на хост без реестра | Сделать резервную копию файлов контейнера, изучить их или начать с rootfs |

## Работа с образом

- **▶ Запустить** открывает [диалог запуска](/docs/guides/containers/#running-a-container) с уже указанным образом.
- **Просмотреть** — или выбор строки — показывает **Слои**, инструкции, которые создали каждый слой, и их размеры, а также **Исходный JSON**.
- **Добавить тег** добавляет ещё одно имя, например `registry.example.com/app:v2`. Это ничего не отправляет; отправляет **Отправить**.
- **Удалить** удаляет образ и слои, которые не использует ни один другой образ. Образ с несколькими тегами теряет их все. Движок отказывается удалять образ, который ещё использует контейнер; сначала удалите контейнер.

## Очистка

**Очистить** предлагает два уровня:

- **Висячие образы** — образы без тегов, оставшиеся после сборок и скачиваний. Их можно безопасно удалить.
- **Все неиспользуемые образы** — все образы, которые не использует ни один контейнер, включая образы с тегами. Их можно скачать снова, но это требует времени и трафика.

Homeport сообщает, сколько образов удалено и сколько места освободилось. [Очистка на странице «Обзор»](/docs/guides/overview/#cleaning-up) также может за один раз удалить остановленные контейнеры, сети, кеш сборки и тома.
