**Синхронизируемый стек** — это [стек](/docs/guides/stacks/), файл compose которого берётся из git-репозитория. Homeport клонирует репозиторий на этот компьютер, получает его ветку или тег по вашему запросу (или периодически, пока Homeport открыт), показывает, что изменилось, и разворачивает новый коммит на хосте. Он никогда не изменяет, не коммитит и не отправляет изменения: изменения идут через git.

<Aside type="note" title="Homeport нужен git">
  Синхронизируемые стеки используют `git`, установленный на этом компьютере. **Настройки → Этот
  компьютер** показывает, нашёл ли его Homeport, и как его установить, если нет. Все остальные виды
  стеков работают без git.
</Aside>

## Репозитории

Homeport читает репозитории, которые вы добавляете в **Настройки → Репозитории** или со страницы **Новый стек**. Репозиторий добавляется один раз, и его могут использовать синхронизируемые стеки на любом хосте. Homeport обращается к нему одним из трёх способов:

| Доступ                 | URL                                                | Что хранит Homeport                                                             |
| ---------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------- |
| **Ключ развёртывания** | SSH: `git@github.com:owner/repo.git` или `ssh://…` | Ключ, который он создаёт только для этого репозитория, **в зашифрованном виде** |
| **Токен**              | HTTPS: `https://gitlab.com/owner/repo.git`         | Ваше имя пользователя и токен доступа **в зашифрованном виде**                  |
| **Публичный**          | HTTPS, для репозитория, который может читать любой | Ничего секретного                                                               |

`http://` и локальные пути не принимаются, так что токен никогда не передаётся открытым текстом.

### С ключом развёртывания

<Steps>

1. Выберите **Добавить репозиторий**, вставьте SSH URL репозитория, оставьте **Ключ развёртывания** и выберите **Добавить и создать ключ развёртывания**.

2. Скопируйте ключ, который показывает Homeport, и добавьте его в репозиторий **только с правом чтения**:
   - GitHub: **Settings → Deploy keys → Add deploy key** репозитория.
   - GitLab: **Settings → Repository → Deploy keys** проекта.
   - Gitea и Forgejo: **Settings → Deploy keys → Add deploy key** репозитория.

3. Выберите **Проверить доступ**. Homeport перечислит ветки и теги репозитория с этого компьютера.

</Steps>

У каждого репозитория свой ключ, поэтому утёкший ключ может читать только этот один репозиторий, а ваши собственные SSH-ключи и `~/.ssh/config` никогда не используются. **Новый ключ** заменяет его: добавьте новый ключ в репозиторий и удалите там старый.

Когда Homeport впервые обращается к SSH-серверу, он доверяет ключу, который предъявляет сервер, и запоминает его, как это делает `ssh`; если ключ потом изменится, каждое получение изменений будет завершаться сбоем, пока вы не проверите новый отпечаток на сайте git-хостинга и не выберете **Сбросить** рядом с доверенным ключом.

### С токеном

Вставьте URL репозитория `https://`, выберите **Токен**, затем введите имя пользователя и токен доступа, которому разрешено читать содержимое репозитория: на GitHub — fine-grained token с **Contents: Read-only**, на GitLab — токен проекта или личный токен с `read_repository`. **Проверить доступ** проверяет его. Когда срок его действия истечёт, введите новый в **Заменить токен**.

<Aside type="tip">
  Без связки ключей ОС Homeport не может хранить ключи развёртывания или токены, поэтому добавить
  можно только публичные репозитории. См. [Системные
  требования](/docs/requirements/#optional-an-os-keychain).
</Aside>

Удаление репозитория удаляет его ключ или токен и его клон на этом компьютере. Это отклоняется, пока его использует синхронизируемый стек.

## Создание синхронизируемого стека

<Steps>

1. Откройте **Стеки** на хосте, на который нужно развернуть, выберите **Новый стек**, затем **Использовать git-репозиторий**.

2. Выберите **Репозиторий** или нажмите **Добавить репозиторий**, чтобы добавить его прямо там.

3. Выберите **Ветку** или **Тег**. Homeport перечисляет их с сервера репозитория, сначала ветку по умолчанию.

4. Введите путь к **Файлу compose** относительно корня репозитория: `compose.yaml` или `deploy/prod/compose.yaml`. Его папка — это папка проекта, поэтому `build:`, `env_file:` и относительные пути в нём работают так же, как в вашем собственном клоне.

5. Проверьте **Имя** (оно берётся из имени репозитория) и добавьте **Окружение** для того, чему не место в git, например паролей: строки `KEY=value`, зашифрованные на этом компьютере и передаваемые Compose как переменные при развёртывании.

6. Выберите **Сохранить и развернуть** — или **Сохранить**, чтобы развернуть позже.

</Steps>

Homeport получает ветку или тег и читает файл compose, прежде чем что-либо сохранить, поэтому о неправильном пути, ветке или теге либо о файле, который Compose не смог бы развернуть, сообщается сразу. Стек отображается как **Синхронизируемый** и **Не развёрнут** до первого развёртывания; его вкладка **Определение** показывает его репозиторий, ветку или тег, файл compose и развёрнутый коммит.

Репозиторий клонируется на этот компьютер один раз, в папку `repositories` рядом с базой данных Homeport, и используется всеми синхронизируемыми стеками, созданными из него. Каждый синхронизируемый стек разворачивается из своей собственной рабочей копии коммита в папке `synced-stacks` там же, которая остаётся на месте между развёртываниями: файлы, которые ваши контейнеры записывают через относительные bind-монтирования, остаются там, где были. Символические ссылки в репозитории извлекаются как обычные файлы, поэтому файл compose не может направить Compose на файл в другом месте этого компьютера. Файлы сохраняют те окончания строк, с которыми они хранятся в репозитории, в том числе в Windows, так что скрипт, скопированный в образ Linux, по-прежнему запускается; изменить их может только собственный `.gitattributes` репозитория.

Синхронизируемый стек можно вместо этого развернуть в [Swarm](/docs/guides/swarm/): выберите его в поле **Куда развернуть** на странице **Новый стек**. Он синхронизируется, разворачивается и разворачивается автоматически так же, с помощью `docker stack deploy`, запущенного из его рабочей копии; что при этом меняется — в первую очередь `build:`, — см. в разделе [Связанные и синхронизируемые стеки в Swarm](/docs/guides/swarm/#linked-and-synced-stacks-on-a-swarm).

**Забыть** прекращает отслеживание репозитория Homeport. Контейнеры стека продолжают работать, и он становится внешним стеком; его рабочая копия удаляется, если только контейнеры не записали в неё файлы, а клон репозитория удаляется, когда его больше не использует ни один синхронизируемый стек. Репозиторий остаётся в **Настройки → Репозитории**.

## Синхронизация

Выберите **Синхронизировать** в строке или на странице синхронизируемого стека. Homeport получает его ветку или тег и затем, прежде чем что-либо делать, показывает, что изменит развёртывание:

- **новые коммиты** после развёрнутого, которые что-то меняют в папке файла compose, с их автором и временем создания;
- каждый **изменённый файл** в этой папке, сначала файл compose, с удалёнными строками, зачёркнутыми над теми, что их заменяют. Нетекстовый файл называется, но не показывается.

Выберите **Развернуть**, чтобы развернуть именно этот коммит: Homeport извлекает его в рабочую копию стека и запускает `docker compose up` из папки файла compose, пересобирая сервисы, у которых есть `build:`, так что изменённый `Dockerfile` применяется. Вывод передаётся по мере выполнения, а развёртывание записывается в **Историю** стека вместе с его коммитом.

- Отправка, которая ничего не меняет в папке файла compose, — например, документация в другом месте репозитория — показывает **Актуально**. **Всё равно развернуть заново** всё же разворачивает её.
- Если тег теперь указывает на другой коммит, чем когда Homeport получал его в последний раз, проверка сначала сообщает об этом.
- Если получение изменений не удаётся (ключ развёртывания удалён, сервер недоступен) или развёртывание завершается сбоем, Homeport показывает причину и что делать, а стек сохраняет развёрнутый коммит.

**Развернуть заново** снова разворачивает текущий развёрнутый коммит, предварительно показав, что изменилось в его окружении или профилях. **Развернуть** для стека, который ни разу не разворачивался, разворачивает коммит, полученный при его создании. Синхронизируемый стек нельзя откатить из Homeport: отмените изменение в его репозитории или укажите для стека более ранний тег, затем синхронизируйте.

## Опрос и автоматическое развёртывание

<Aside type="caution" title="Только пока Homeport открыт">
  Homeport проверяет ваши репозитории, только пока он открыт. **Пока он закрыт, ничего не
  синхронизируется**: на ваших серверах нет агента и нет веб-хука, поскольку Homeport ничего там не
  устанавливает. Когда вы снова его откроете, он выждет один интервал перед первой проверкой.
</Aside>

Пока Homeport открыт, он периодически получает ветку или тег каждого синхронизируемого стека — по умолчанию каждые 5 минут, это задаётся в **Настройки → Синхронизируемые стеки** (не меньше 1 минуты). Каждый репозиторий запрашивается один раз за цикл, сколько бы стеков его ни использовало, а тот, который постоянно даёт сбой, опрашивается всё реже и реже, вплоть до раза в час.

Когда новый коммит меняет папку файла compose, стек показывает **Доступно обновление** в списке и на своей странице. **Синхронизировать** показывает, что изменилось, и разворачивает это. Вкладка **Определение** стека показывает, когда была **последняя проверка**, и почему последняя проверка не удалась, если так было.

Этим управляют два переключателя на вкладке **Определение**, для каждого стека отдельно:

- **Проверять новые коммиты**, по умолчанию включено. Выключите, чтобы синхронизировать только тогда, когда вы выбираете **Синхронизировать**.
- **Автоматически разворачивать новые коммиты**, по умолчанию выключено. Когда включено, Homeport разворачивает каждый новый коммит, как только его видит, **не показывая сначала, что изменилось**, теми же шагами, что и **Синхронизировать**; развёртывание записывается в **Историю** как автоматическое, а уведомление сообщает о его завершении. Пока хост недоступен, оно ждёт. Если оно не удаётся, Homeport показывает причину и не пытается развернуть этот коммит снова: это сделает следующий коммит или **Синхронизировать**, которое вы развернёте сами.

## Почему нельзя изменить синхронизируемый стек?

Потому что его репозиторий — единственное место, где живёт его определение. Если бы Homeport изменил файл compose, следующая синхронизация либо перезаписала бы это изменение, либо конфликтовала бы с ним, и никто, читая репозиторий, не знал бы, что развёрнуто. Поэтому вкладка **Определение** синхронизируемого стека показывает его файл compose на полученном коммите **только для чтения** — выделять и копировать из него по-прежнему можно, — перечисляет другие файлы его папки и даёт для каждого ссылку на его страницу в GitHub, GitLab, Gitea или Forgejo. Измените их там, отправьте изменения, затем выберите **Синхронизировать**.

То, что хранит сам Homeport, на той же вкладке можно изменять:

- его **Окружение**, зашифрованное на этом компьютере, для значений, которым не место в git;
- его **профили**, если файл compose их объявляет;
- **проверяет ли он новые коммиты** и **разворачивает ли их автоматически**.

**Забыть** прекращает отслеживание репозитория Homeport; контейнеры стека продолжают работать, и он становится внешним.
