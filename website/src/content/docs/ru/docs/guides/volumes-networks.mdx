## Тома

Страница **Тома** перечисляет тома выбранного хоста и сколько из них не используется.

<DocScreenshot
  name="volumes"
  alt="Страница «Тома», показывающая для каждого тома его стек, драйвер и использующие его контейнеры."
/>

| Столбец          | Что показывает                                                               |
| ---------------- | ---------------------------------------------------------------------------- |
| **Имя**          | Имя тома; длинный ID для анонимных томов.                                    |
| **Стек**         | Стек, который его создал, если есть.                                         |
| **Драйвер**      | Обычно `local`.                                                              |
| **Размер**       | Сколько места на диске занимают его данные, по данным `docker system df -v`. |
| **Используется** | Контейнеры, которые его монтируют, или **Не используется**.                  |
| **Создан**       | Когда он был создан.                                                         |

Том считается используемым, если его монтирует любой контейнер, работающий или остановленный. Выберите том, чтобы увидеть его размер, какие контейнеры его используют, и все его подробности, включая то, где на хосте лежат его данные (`Mountpoint`).

### Размеры

Чтобы сообщить размеры, движок измеряет каждый том, а на хосте с большим объёмом данных это может занять несколько секунд, поэтому список появляется сразу, а столбец **Размер** заполняется после. Отсортируйте по **Размеру**, чтобы найти том, который заполняет диск. Размеры измеряются снова, когда том создаётся или удаляется и когда вы выбираете **Обновить размеры**, — но не при каждой записи контейнера, так что размер может немного отставать.

Размер есть только у томов драйвера `local`; у других драйверов (NFS, плагины облачных хранилищ) показывается **—**.

### Просмотр файлов тома

Кнопка с папкой в строке тома открывает его файлы: открывайте папки, возвращайтесь наверх по пути над списком и скачивайте файл или папку в виде архива `.tar`. Пути начинаются от корня тома (`/`).

Просмотр выполняется только для чтения. Ничто из того, что вы здесь делаете, не может изменить том, даже пока его использует контейнер.

#### Вспомогательный контейнер

API движка не умеет читать том, поэтому Homeport открывает его с помощью недолговечного **вспомогательного контейнера**: контейнера `busybox:1.37` без сети и с файловой системой только для чтения, который монтирует том только для чтения. Homeport удаляет его, как только вы закрываете просмотр или выходите из программы. Если Homeport не может этого сделать (он аварийно завершился или хост пропал), вспомогательный контейнер останавливается и удаляется движком в течение часа, а Homeport удаляет то, что осталось, при следующем подключении этого компьютера к хосту. Вспомогательные контейнеры никогда не показываются в списке «Контейнеры», в поле тома **Используется** или на странице «События».

Если на хосте нет `busybox:1.37` (около 2 МБ), Homeport сообщает об этом и скачивает образ, только когда вы выберете **Скачать busybox:1.37**, используя ваши [входы в реестры](/docs/guides/settings/#реестры). По завершении он снова удаляет образ, если только его не использует что-то ещё. Хост без доступа в интернет не может его скачать; доставьте его туда сами:

```sh
docker pull busybox:1.37
```

или на машине, где он есть, выполните `docker save busybox:1.37 -o busybox.tar`, скопируйте файл и выполните `docker load -i busybox.tar` на хосте.

<Aside>
  Движки, на которых работают контейнеры Windows, не могут запустить вспомогательный контейнер,
  поэтому их тома открыть нельзя.
</Aside>

### Резервное копирование и восстановление

**Создать резервную копию в файл…** в меню **⋯** строки тома сохраняет его содержимое в файл `.tar` на этом компьютере. Архив содержит файлы тома с их владельцами и правами по путям относительно его корня — так, как их создала бы команда `tar -C <volume> -cf backup.tar .`, — поэтому его можно открыть или восстановить и без Homeport.

**Восстановить из файла** восстанавливает резервную копию:

- Из верхней части страницы — в **Новый том**, названный по имени файла, если вы его не измените, или в выбранный вами **Существующий том**.
- Из меню **⋯** тома — в этот том.

Если в существующем томе уже есть файлы, Homeport спрашивает подтверждение, прежде чем удалить их и положить на их место файлы из резервной копии. Файл, который не является архивом tar, отклоняется прежде, чем что-либо изменится.

Обе операции показывают ход выполнения, и их можно отменить. Отменённое резервное копирование не оставляет файла; отменённое восстановление может оставить том записанным частично, поэтому восстановите его снова, прежде чем использовать.

#### Контейнеры, использующие том

Резервная копия тома, в который пишет работающий контейнер, — например, база данных, — может оказаться несогласованной. Homeport называет работающие контейнеры, которые его используют, и вы выбираете **Всё равно создать копию** или остановить их на время резервного копирования. Восстановление всегда сначала их останавливает. В обоих случаях Homeport затем снова их запускает.

Резервное копирование и восстановление используют тот же [вспомогательный контейнер](#вспомогательный-контейнер), что и просмотр, и при резервном копировании монтируют том только для чтения. Архив передаётся по подключению хоста и никогда не хранится в памяти целиком, так что работают и большие тома, и удалённые хосты. На хосте ничего не записывается, кроме восстанавливаемого тома.

### Клонирование тома

**Клонировать…** в меню **⋯** строки тома копирует его в новый том на том же хосте — например, чтобы опробовать миграцию или новую версию образа на копии реальных данных. Копия называется `<name>-copy`, если вы не измените имя, и после создания выбирается в списке.

Она сохраняет владельцев и права файлов, а также драйвер, параметры драйвера и метки исходного тома — кроме меток Compose, так что копия не принадлежит ни одному стеку. Исходный том монтируется во [вспомогательный контейнер](#вспомогательный-контейнер) только для чтения и никогда не изменяется. Как и при резервном копировании, Homeport называет работающие контейнеры, которые используют исходный том; копируйте всё равно или остановите их на время копирования.

Если копирование не удаётся — например, диск заполнен, — Homeport удаляет незавершённую копию и сообщает об этом, с ошибкой в **Подробностях**. Чтобы скопировать том на другой хост, [создайте его резервную копию](#резервное-копирование-и-восстановление) и восстановите файл там.

### Создание тома

**Создать том** запрашивает **Имя** и необязательный **Драйвер** (`local`, если пусто).

### Удаление томов

<Aside type="danger">Удаление тома безвозвратно удаляет данные в нём.</Aside>

Кнопка удаления в каждой строке запрашивает подтверждение и называет контейнеры, которые всё ещё монтируют том. Движок отказывается удалять том, который использует какой-либо контейнер, даже остановленный, — сначала удалите эти контейнеры.

**Очистить** удаляет несколько томов сразу:

- **Неиспользуемые анонимные тома** — безымянные тома, которые не использует ни один контейнер.
- **Все неиспользуемые тома** — все тома, которые не использует ни один контейнер, включая именованные.

## Сети

Страница **Сети** перечисляет сети выбранного хоста, сначала встроенные `bridge`, `host` и `none`.

<DocScreenshot
  name="networks"
  alt="Страница «Сети» со встроенными сетями и сетями стеков, их подсетями и числом контейнеров."
/>

| Столбец        | Что показывает                                                   |
| -------------- | ---------------------------------------------------------------- |
| **Имя**        | С пометкой **встроенная** или **внутренняя**, где это применимо. |
| **Стек**       | Стек, который её создал, если есть.                              |
| **Драйвер**    | `bridge`, `overlay`, `macvlan`…                                  |
| **Подсеть**    | Её диапазон IP-адресов.                                          |
| **Контейнеры** | Сколько контейнеров подключено, работающих или остановленных.    |

### Подключение контейнеров

Выберите сеть, чтобы увидеть подключённые к ней контейнеры. В созданных вами сетях:

- **Отключить** отсоединяет контейнер.
- **Подключить контейнер…** перечисляет ещё не подключённые контейнеры; выберите один и нажмите **Подключить**.

Встроенные сети здесь изменить нельзя.

### Создание сети

**Создать сеть** принимает **Имя**, **Драйвер** (`bridge`, если пусто) и, при желании, **Подсеть** и **Шлюз** — оставьте их пустыми, чтобы их выбрал движок. Два переключателя:

- **Внутренняя** — контейнеры в сети не могут обращаться к внешним сетям.
- **Подключаемая** — отдельные контейнеры могут присоединяться к сети `overlay`.

### Удаление сетей

Встроенные сети удалить нельзя. Для других сетей подтверждение сообщает, сколько контейнеров ещё подключено; движок отказывается удалять сеть, в которой есть работающие контейнеры. Контейнеры, которые ссылаются на удалённую сеть по имени, не запустятся, пока она не появится снова.

**Очистить** удаляет все пользовательские сети, к которым не подключён ни один контейнер.
