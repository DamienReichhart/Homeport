## Операционные системы

| Система | Версии                                                                 | Архитектуры          |
| ------- | ---------------------------------------------------------------------- | -------------------- |
| Windows | Windows 10 и 11                                                        | x64, ARM64           |
| macOS   | macOS 10.15 Catalina или новее                                         | Apple silicon, Intel |
| Linux   | glibc 2.35 или новее: Ubuntu 22.04, Debian 12, Fedora 36 и более новые | x64, ARM64           |

Для отрисовки окна Homeport использует системный веб-движок: WebView2 в Windows (входит в Windows 10 и 11), WebKit в macOS и WebKitGTK в Linux (устанавливается как зависимость пакетов `.deb` и `.rpm` и встроен в AppImage).

## Движок Docker для управления

Homeport не содержит среды выполнения контейнеров. Он управляет движками Docker, которые уже где-то работают:

- **На этом компьютере** — Docker Engine, Docker Desktop, Colima, OrbStack, Rancher Desktop или Podman. Homeport находит их сам; см. [локальные движки](/docs/hosts/local/).
- **На сервере** — доступные по [SSH](/docs/hosts/ssh/) или по [TLS или TCP](/docs/hosts/tls-tcp/).

Подходит любой движок, поддерживающий Docker Engine API, в том числе Docker-совместимый сокет Podman.

Homeport также напрямую управляет [containerd](/docs/hosts/containerd/) 1.7 и новее — через его сокет на этом компьютере или по SSH: containerd из k3s, собственный containerd Docker Engine или службу containerd на сервере. Для скачивания образов там нужен containerd 2.0 или новее, а для журналов и терминалов — хост, доступный по SSH, или containerd на этом компьютере (Linux).

Он также управляет [Incus](/docs/hosts/incus/) 6.0 и новее — через его сокет на этом компьютере, по SSH или по HTTPS с токеном доверия. Виртуальным машинам нужна аппаратная виртуализация (`/dev/kvm`) на сервере Incus, а терминалу в виртуальной машине — `incus-agent`, который запускает её образ.

На хосте Podman Homeport также использует собственный API Podman: [поды](/docs/guides/podman-pods/) требуют Podman 4.0 или новее, а [юниты Quadlet](/docs/guides/quadlet/) отображаются начиная с Podman 5.7 и устанавливаются, редактируются и удаляются начиная с 5.8. Для запуска и остановки юнита Quadlet нужен хост, доступный по SSH, или Podman на этом компьютере (Linux).

## Необязательно: кластеры Kubernetes

Чтобы просматривать [кластеры](/docs/clusters/), Homeport нужен kubeconfig, через который они доступны (тот, что использует `kubectl`, или вставленный вами), и сетевой доступ к их API-серверам. Homeport сам работает с API Kubernetes, поэтому `kubectl` не нужен.

- **Версии Kubernetes**: кластеры с Kubernetes 1.24 или новее. Homeport использует только стабильные API (`v1`, `apps/v1`, `batch/v1`, `networking.k8s.io/v1`) и собран под API версии 1.33.
- **Плагины exec**: облачный kubeconfig указывает программу, которую нужно запустить на этом компьютере для получения учётных данных, — [AWS CLI](https://aws.amazon.com/cli/) (версии 2) для EKS, `gke-gcloud-auth-plugin` из Google Cloud CLI для GKE, `kubelogin` для AKS. Установите ту, что указана в вашем kubeconfig; см. [плагины exec](/docs/clusters/exec-plugins/).

## Необязательно: кластеры Nomad

Чтобы управлять [кластерами Nomad](/docs/clusters/nomad/), Homeport нужен сетевой доступ к HTTP API агента Nomad (по умолчанию порт 4646) и, если в кластере включены ACL, токен; см. нужную ему [политику ACL](/docs/clusters/nomad/#acl-policies). Homeport сам работает с API Nomad, поэтому CLI `nomad` не нужен, и на кластер ничего не устанавливается.

- **Версии Nomad**: Nomad 1.6 или новее. **Изменить и запустить** начинает с отправленной спецификации job, которую Nomad хранит начиная с 1.6.

## Необязательно: связка ключей ОС

Homeport шифрует ключи SSH, сертификаты TLS, учётные данные kubeconfig кластеров, окружения стеков, входы в реестры, а также ключи развёртывания и токены репозиториев ключом, который хранит в связке ключей вашей операционной системы:

- **macOS** — Связка ключей (Keychain)
- **Windows** — Диспетчер учётных данных
- **Linux** — поставщик Secret Service, например GNOME Keyring или KWallet

Без неё Homeport показывает баннер и продолжает работать с локальными сокетами, обычным TCP и SSH через **ssh-agent**. Хостам TLS, хостам SSH с сохранёнными ключами, кластерам, окружениям стеков, входам в реестры и приватным репозиториям нужна связка ключей; без неё образы скачиваются анонимно, а добавить можно только публичные репозитории. См. [безопасность и ваши данные](/docs/reference/security/).

## Необязательно: Docker Compose

Чтобы разворачивать [управляемые, связанные и синхронизируемые стеки](/docs/guides/stacks/), Homeport запускает команду `docker compose` на **этом** компьютере — не на хосте. Установите Docker CLI с плагином Compose (он входит в Docker Desktop) или отдельный `docker-compose` v2.

Без него стеки всё равно отображаются — включая связанные — и их можно запускать, останавливать и удалять; Compose нужен только для развёртывания. **Настройки → Этот компьютер** показывает, нашёл ли его Homeport.

Чтобы развернуть стек в [Swarm](/docs/guides/swarm/), Homeport вместо этого запускает `docker stack deploy` на этом компьютере, поэтому ему нужна сама команда `docker` (плагин Compose не используется). В Docker Desktop она есть; в Linux установите пакет Docker CLI своего дистрибутива (`docker-ce-cli`, `docker.io` или `docker`). Запускать движок здесь не нужно.

## Необязательно: git

[Синхронизируемые стеки](/docs/guides/synced-stacks/) используют `git`, установленный на **этом** компьютере, чтобы клонировать свои репозитории и получать из них изменения: Git for Windows, инструменты командной строки Apple (`xcode-select --install`) или пакет `git` вашего дистрибутива. В Windows для репозиториев по SSH Homeport направляет его на системный OpenSSH. Все остальные функции работают без git; **Настройки → Этот компьютер** показывает, нашёл ли его Homeport.

## Необязательно: Helm

Чтобы управлять [релизами Helm](/docs/clusters/helm/) в кластере, Homeport запускает команду `helm` версии 3 или новее на **этом** компьютере. Он направляет helm на кластер через приватное подключение, поэтому никакие учётные данные кластера не записываются на диск, а helm использует свои собственные репозитории чартов, как в терминале. Установите его через `brew install helm` (macOS), `winget install Helm.Helm`, Chocolatey или Scoop (Windows) либо через `snap install helm --classic`, пакет вашего дистрибутива или скрипт с [helm.sh](https://helm.sh/docs/intro/install/) (Linux). Все остальные страницы кластера работают без него; **Настройки → Этот компьютер** показывает, нашёл ли его Homeport.

## Необязательно: системный трей

Homeport помещает в системный трей (в строку меню в macOS, в область уведомлений в Windows) значок, в котором перечислены все хосты с их состояниями. В Windows и macOS трей есть всегда. В Linux для него нужна библиотека **appindicator**: AppImage её содержит, а пакеты `.deb` и `.rpm` её рекомендуют, так что `apt`, `dnf` и `zypper` устанавливают её, если вы не отключили рекомендуемые пакеты. Иначе установите `libayatana-appindicator3-1` (Debian, Ubuntu, openSUSE) или `libayatana-appindicator-gtk3` (Fedora). Некоторые рабочие окружения скрывают значки трея — GNOME показывает их только с расширением, например AppIndicator Support. Без трея Homeport работает из своего окна, а закрытие окна завершает его.
