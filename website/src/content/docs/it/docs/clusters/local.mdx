## Cosa viene trovato

| Strumento           | Il suo contesto nel kubeconfig               | Aggiunto come        |
| ------------------- | -------------------------------------------- | -------------------- |
| **Docker Desktop**  | `docker-desktop`                             | `Docker Desktop`     |
| **OrbStack**        | `orbstack`                                   | `OrbStack`           |
| **Rancher Desktop** | `rancher-desktop`                            | `Rancher Desktop`    |
| **kind**            | `kind-<name>`                                | il nome del contesto |
| **k3d**             | `k3d-<name>`                                 | il nome del contesto |
| **minikube**        | `minikube`, o un profilo scritto da minikube | il nome del contesto |

Un contesto conta come locale solo quando il suo server API si trova su questo computer (`127.0.0.1`, `localhost`, `kubernetes.docker.internal`…) o, per minikube e Rancher Desktop, nella loro VM su un indirizzo privato. Un contesto remoto non viene mai proposto, qualunque sia il suo nome. Un cluster locale che non risponde mostra **Non in esecuzione**; avvialo con il suo strumento e apri di nuovo la pagina.

### Cluster kind e k3d assenti dal kubeconfig

Quando un [host locale](/docs/hosts/local/) è connesso, Homeport individua anche i container dei cluster kind e k3d in esecuzione (tramite le loro etichette `io.x-k8s.kind.cluster` e `k3d.cluster`). Uno che il tuo kubeconfig non raggiunge viene mostrato con il comando che lo aggiunge, invece di essere aggiunto a tua insaputa:

```bash
kind export kubeconfig --name <name>
```

```bash
k3d kubeconfig merge <name> --kubeconfig-merge-default
```

## Attivare Kubernetes

- **Docker Desktop**: **Settings → Kubernetes → Enable Kubernetes**, poi **Apply & restart**. Aggiunge il contesto `docker-desktop`.
- **OrbStack**: **Settings → Kubernetes → Enable Kubernetes**, o esegui `orb start k8s`. Aggiunge il contesto `orbstack`.
- **Rancher Desktop**: **Preferences → Kubernetes → Enable Kubernetes**. Aggiunge il contesto `rancher-desktop`.

kind (`kind create cluster`), k3d (`k3d cluster create`) e minikube (`minikube start`) aggiungono i loro contesti quando creano un cluster. Creano nuovi certificati ogni volta che ne ricreano uno: usa poi **Aggiorna dal kubeconfig** nella sua pagina.
