**Homeport** è un’app desktop per gestire Docker Engine, containerd e Incus ovunque si trovino — quelli di questo computer, o Engine remoti tramite SSH, TLS o TCP — gli Swarm che formano, e i cluster Kubernetes raggiunti dal tuo kubeconfig e i cluster Nomad che indichi, nello spirito di Docker Desktop. Funziona su Windows, macOS e Linux, è gratuita ed è open source sotto la [GNU Affero General Public License, versione 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE).

Homeport non esegue container da sé. Si connette agli Engine che hai già, chiamati **host**, e ti offre un’unica finestra per tutto ciò che contengono: container, immagini, volumi, reti e **stack** Compose. Si connette anche ai **cluster** Kubernetes e Nomad, per vedere ciò che vi è in esecuzione e gestirlo. Nulla viene installato su un host o un cluster.

## Le parole che usiamo

Homeport chiama le cose con precisione, e la documentazione fa lo stesso:

- Un **host** è un Engine a cui Homeport si connette: un Docker Engine o uno compatibile come Podman, containerd o Incus. Ogni container, immagine, volume, rete e stack appartiene esattamente a un host.
- Un **cluster** è un cluster Kubernetes, aggiunto da un contesto del tuo kubeconfig, o un cluster Nomad, aggiunto tramite l’indirizzo di uno dei suoi agenti.
- Uno **Swarm** è un Docker Swarm, trovato tramite gli host che ne fanno parte e mai aggiunto da solo.
- Uno **stack** è un progetto Compose in esecuzione su un host, o uno stack swarm in esecuzione su uno Swarm. Uno **stack gestito** è uno stack il cui file compose è conservato da Homeport; uno **stack collegato** conserva i suoi file compose in una cartella di questo computer; uno **stack sincronizzato** segue un repository git; uno **stack esterno** è stato distribuito in un altro modo. Puoi **adottare** uno stack esterno per gestirlo.

Il [glossario](/docs/reference/glossary/) contiene l’elenco completo.
