**Homeport**는 이 컴퓨터의 Docker Engine이든 SSH, TLS, TCP로 연결하는 원격 Docker Engine이든 어디에 있는 Docker Engine이나 관리하고, kubeconfig로 접근할 수 있는 Kubernetes 클러스터도 관리하는 데스크톱 앱으로, Docker Desktop과 같은 방식을 따릅니다. Windows, macOS, Linux에서 실행되고, 무료이며, [GNU Affero General Public License 버전 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE)에 따른 오픈 소스입니다.

Homeport는 컨테이너를 직접 실행하지 않습니다. 이미 가지고 있는 Docker Engine, 즉 **호스트**에 연결하여 그 위의 모든 것, 곧 컨테이너, 이미지, 볼륨, 네트워크, Compose **스택**을 하나의 창에서 다룰 수 있게 합니다. 또한 kubeconfig에 있는 Kubernetes **클러스터**에 연결하여 그 위에서 실행되는 것을 살펴볼 수 있습니다.

## 이 문서의 구성

- **시작하기** — [Homeport를 설치](/docs/installation/)한 다음 [빠른 시작](/docs/quick-start/)을 따라 첫 번째 호스트에 연결합니다.
- **호스트** — 연결 종류별 작동 방식: [로컬 엔진](/docs/hosts/local/), [SSH](/docs/hosts/ssh/), [TLS와 TCP](/docs/hosts/tls-tcp/).
- **클러스터** — kubeconfig에서 [Kubernetes 클러스터를 추가](/docs/clusters/)하고 살펴보는 방법.
- **Homeport 사용하기** — 앱의 각 페이지에 대한 안내.
- **참고 자료** — [보안](/docs/reference/security/), [문제 해결](/docs/reference/troubleshooting/), [자주 묻는 질문](/docs/reference/faq/), [용어집](/docs/reference/glossary/).

## 이 문서에서 쓰는 용어

Homeport는 대상을 정확한 이름으로 부르며, 이 문서도 그대로 따릅니다.

- **호스트**는 Homeport가 연결하는 Docker Engine입니다. 모든 컨테이너, 이미지, 볼륨, 네트워크, 스택은 정확히 하나의 호스트에 속합니다.
- **클러스터**는 Homeport가 연결하는 Kubernetes 클러스터로, kubeconfig의 컨텍스트에서 추가합니다.
- **스택**은 호스트에서 실행되는 Compose 프로젝트입니다. **관리형 스택**은 Homeport가 compose 파일을 보관하는 스택이고, **링크된 스택**은 compose 파일을 이 컴퓨터의 폴더에 두는 스택이며, **외부 스택**은 다른 방법으로 배포된 스택입니다. 외부 스택을 **관리형으로 전환**하면 Homeport에서 관리할 수 있습니다.

전체 목록은 [용어집](/docs/reference/glossary/)에 있습니다.
