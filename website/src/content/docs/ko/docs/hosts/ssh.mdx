서버의 Docker Engine에 연결할 때는 SSH를 권장합니다. SSH 포트 외에는 아무것도 노출할 필요가 없고, 엔진의 소켓은 서버 안에서만 쓰입니다.

## 작동 방식

Homeport에는 자체 SSH 클라이언트가 있습니다. 서버에 로그인한 다음 엔진의 Unix 소켓으로 채널을 포워딩합니다. `docker -H ssh://…`와 같은 일을 하지만, 이 컴퓨터에 `ssh` 프로그램이나 `docker`가 필요하지 않습니다.

- 키는 메모리에서만 복호화되고 디스크에 기록되지 않으므로 Windows, macOS, Linux에서 똑같이 작동합니다.
- Homeport는 `~/.ssh/known_hosts`를 읽지 않습니다. 서버 키는 Homeport 안에서 호스트별로 신뢰합니다. 점프 서버를 거쳐야만 접근할 수 있는 서버는 Homeport의 `ProxyJump`인 [배스천](#through-a-bastion)으로 추가합니다.
- 서버가 Unix 소켓으로의 포워딩을 허용해야 합니다. OpenSSH는 기본적으로 허용합니다(`AllowStreamLocalForwarding yes`).

## SSH 호스트 추가

<Steps>

1. 호스트 전환기에서 **호스트 추가…** 항목을 선택하고 **SSH**를 선택된 상태로 둡니다.

2. 연결 정보를 입력합니다.

   | 필드               | 입력할 내용                                                                                                                                                         |
   | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
   | **이름**           | `production`처럼 알아보기 쉬운 이름.                                                                                                                                |
   | **서버**           | 서버의 호스트 이름 또는 IP 주소.                                                                                                                                    |
   | **포트**           | SSH 포트. 기본값은 `22`.                                                                                                                                            |
   | **사용자**         | 로그인할 계정. 보통 `docker` 그룹을 통해 Docker 소켓에 접근할 수 있어야 합니다.                                                                                     |
   | **원격 소켓 경로** | 서버에서 엔진이 수신 대기하는 위치. 기본값은 `/var/run/docker.sock`이고, rootless Docker는 `/run/user/<uid>/docker.sock`, Podman은 `/run/podman/podman.sock`입니다. |

3. **인증**에서 로그인 방법을 고릅니다(아래 참고).

4. **호스트 추가**를 선택합니다. Homeport가 호스트 페이지를 열고 연결합니다.

</Steps>

## ~/.ssh/config에서 가져오기

서버가 이미 `~/.ssh/config`에 있다면 하나씩 입력하는 대신 **호스트 추가**에서 **~/.ssh/config에서 가져오기**를 선택하세요. Homeport는 `Include`를 따라가고 `Host *` 기본값을 적용하여 파일에 있는 모든 서버를 나열하며, 추가할 서버를 고르면 됩니다.

| `~/.ssh/config`에서 | Homeport에서                                                                                   |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| `Host prod`         | `prod`라는 이름의 호스트. 와일드카드가 있는 항목(`Host *.example.com`)은 기본값만 제공합니다.  |
| `HostName`          | **서버**. 없으면 별칭 자체.                                                                    |
| `User`, `Port`      | **사용자**(기본값은 로컬 사용자 이름)와 **포트**(`22`).                                        |
| `IdentityFile`      | **기존 키**: 읽을 수 있는 첫 번째 파일. `~`와 `%h`, `%r`, `%u`, `%p`를 확장합니다.             |
| `IdentityFile` 없음 | **ssh-agent**.                                                                                 |
| `ProxyJump a,b`     | [배스천](#through-a-bastion) 두 개를 순서대로. 각각 같은 파일에서 찾습니다. 순환은 보고됩니다. |

**원격 소켓 경로**는 `/var/run/docker.sock`으로 시작합니다. rootless Docker나 Podman이라면 미리 보기에서 바꾸세요. 암호화된 키는 미리 보기에서 암호 문구를 묻습니다.

미리 보기는 확인이 필요한 항목을 표시합니다. 읽을 수 없는 키(이 호스트는 대신 ssh-agent를 사용합니다), `ProxyCommand`(지원하지 않으므로 점프 서버를 배스천으로 추가하세요), 이미 호스트 이름으로 쓰이는 별칭이 해당합니다. 마지막 경우는 선택되지 않습니다. 가져오려면 이름을 바꾸세요. 그래서 두 번 가져와도 중복이 생기지 않습니다. 키는 한 번만 읽고 암호화하여 저장합니다. 파일 자체는 절대 변경하지 않으며, `Match` 블록과 인증서(`CertificateFile`)는 무시합니다.

## 인증

### 이 호스트용 새 키(권장)

Homeport가 이 호스트 전용 Ed25519 키를 만들어 암호화하여 저장하고, 서버에서 이 키를 승인하는 명령을 보여 줍니다. 호스트마다 키가 하나씩이므로, 다른 것은 건드리지 않고 서버 하나에 대한 Homeport의 접근만 취소할 수 있습니다. 키의 주석에는 이 컴퓨터와 호스트의 이름이 들어가므로(예: `homeport@laptop-production`) `authorized_keys`에서 구별할 수 있습니다.

### 기존 키

개인 키를 붙여 넣거나 **파일에서 불러오기…** 버튼을 선택하고, 암호 문구가 있으면 **암호 문구**에 입력합니다. Homeport는 OpenSSH 키(`BEGIN OPENSSH PRIVATE KEY`), PKCS#8 및 PEM 키, PuTTY `.ppk` 파일을 읽으며, Ed25519, ECDSA, RSA 키를 지원합니다. 키와 암호 문구는 암호화하여 저장하므로 다시 묻지 않습니다.

### ssh-agent

Homeport는 실행 중인 SSH 에이전트에 키를 요청하며, 아무것도 저장하지 않습니다. macOS와 Linux에서는 `$SSH_AUTH_SOCK`의 에이전트를 사용합니다.

Windows에서는 먼저 OpenSSH Authentication Agent 서비스에 요청하고, 그다음 PuTTY의 **Pageant**나 KeeAgent, PuTTY 지원을 켠 gpg-agent처럼 Pageant를 대신하는 도구에 요청합니다. 어느 쪽에 있는 키든 작동합니다. OpenSSH 에이전트가 실행 중이 아니거나 서버가 받아들이는 키가 없으면 Homeport는 Pageant의 키도 시도합니다.

<Aside>
  ssh-agent는 [OS 키체인](/docs/requirements/#optional-an-os-keychain) 없이 작동하는 유일한 SSH
  방식입니다. Homeport를 데스크톱 메뉴에서 시작했다면 세션의 에이전트를 Homeport가 사용할 수 있는지
  확인하세요.
</Aside>

## 첫 연결

Homeport가 처음 연결할 때 호스트 페이지가 두 단계를 안내합니다.

### 서버 키 신뢰

상태에 **신뢰하지 않는 서버 키**가 표시되고, 페이지가 `SHA256:Kx8f…` 같은 서버 키 지문과 함께 **올바른 서버입니까?** 하고 묻습니다.

서버에서 지문을 확인하여 비교하세요.

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

일치하면 **이 키 신뢰**를 선택합니다. Homeport가 키를 기억하고 연결합니다. `ssh`가 하는 것과 같은 최초 사용 시 신뢰 확인이며, 키는 `~/.ssh/known_hosts`가 아니라 Homeport에 저장됩니다.

### Homeport의 키 승인

Homeport가 만든 키나 가져온 키라면 **서버에서 Homeport 승인** 카드에 명령 두 개가 각각 **복사** 버튼과 함께 표시됩니다. 서버에서 SSH 사용자로 실행하세요.

<DocScreenshot
  name="host-ssh"
  alt="서버에서 Homeport의 키를 승인하는 명령이 표시된 SSH 호스트 페이지."
/>

<Steps>

1. 사용자의 `authorized_keys`에 **공개 키를 추가**합니다.

   ```sh
   mkdir -p ~/.ssh && chmod 700 ~/.ssh && echo 'ssh-ed25519 AAAAC3Nza… homeport@laptop-production' >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys
   ```

2. 사용자가 아직 Docker에 접근할 수 없다면 **Docker 접근을 허용**합니다.

   ```sh
   sudo usermod -aG docker deploy
   ```

3. Homeport로 돌아와 **다시 연결**을 선택합니다.

</Steps>

키가 승인될 때까지 호스트에는 **액세스 거부됨**이 표시됩니다. _서버가 deploy@server의 키를 거부했습니다. 서버의 authorized_keys에 공개 키를 추가하세요._ 이때는 재시도하지 않고 사용자를 기다립니다.

## 서버 키가 바뀌었을 때

나중에 서버가 다른 키를 제시하면 Homeport는 연결을 멈추고, 예상한 지문과 제시된 지문과 함께 **서버 키가 변경됨**을 표시합니다.

<Aside type="caution">
  서버를 다시 설치하거나 호스트 키를 다시 생성한 뒤라면 키가 바뀌는 것이 정상입니다. 하지만 누군가
  연결을 가로채고 있다는 뜻일 수도 있습니다. 키가 바뀐 이유를 아는 경우에만 새 키를 신뢰하세요.
</Aside>

확실하다면 **새 키 신뢰**를 선택하고 확인합니다.

호스트를 편집하여 다른 서버나 포트를 가리키게 하면 신뢰한 키를 잊으므로, 새 키를 신뢰하라는 요청을 받습니다. 호스트 이름을 바꾸거나 사용자 또는 소켓 경로를 바꾸면 키가 유지됩니다.

## 배스천을 통한 연결

일부 서버는 점프 서버에서 오는 SSH만 받아들입니다. 그 서버를 호스트 양식의 **배스천**에 추가하면 Homeport가 먼저 배스천에 로그인한 다음 배스천을 거쳐 호스트에 연결합니다. `ssh -J`나 `ProxyJump`가 하는 일을 Homeport 자체 SSH 클라이언트로 하는 것입니다. 배스천에는 아무것도 설치하지 않으며, 키를 디스크에 기록하지도 않습니다.

<Steps>

1. SSH 호스트 양식에서 **배스천 추가**를 선택합니다.

2. 배스천의 **서버**, **포트**, **사용자**를 입력합니다.

3. Homeport가 배스천에 로그인할 방법을 고릅니다.

   | 인증              | 사용하는 경우                                                                                                                               |
   | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
   | **호스트와 동일** | 배스천이 호스트가 쓰는 키, 즉 Homeport가 만든 키, 기존 키 또는 에이전트의 키를 받아들이는 경우.                                             |
   | **자체 키**       | 배스천에 다른 키가 필요한 경우. 붙여 넣거나 **파일에서 불러오기…** 버튼을 선택하세요. 호스트의 다른 비밀 정보와 함께 암호화하여 저장합니다. |
   | **ssh-agent**     | 에이전트에 배스천의 키가 있고, 호스트는 다른 키(예: Homeport가 이 호스트 전용으로 만든 키)를 쓰는 경우.                                     |

4. 점프 서버가 여러 개 이어진 경우(`ProxyJump a,b`) Homeport가 거쳐 갈 순서대로 서버마다 배스천을 하나씩 추가합니다. 화살표로 배스천을 위아래로 옮길 수 있습니다.

</Steps>

첫 연결에서 Homeport는 첫 번째 배스천부터 차례로 각 서버의 키를 신뢰할지 묻습니다. **올바른 배스천입니까?** 화면이 배스천 이름과 지문을 보여 줍니다. 각 배스천의 키는 호스트와 함께 보관되며, 키가 바뀌면 호스트와 마찬가지로 **배스천 …의 키가 변경됨**과 함께 연결이 멈춥니다.

호스트가 Homeport가 만든 키를 쓰는 경우, **서버에서 Homeport 승인** 카드에 키를 추가해야 하는 모든 서버가 나열됩니다. **호스트와 동일**로 설정된 각 배스천과, 그다음 호스트입니다.

배스천은 호스트로의 TCP 포워딩을 허용해야 합니다(`AllowTcpForwarding yes`, OpenSSH의 기본값). 허용하지 않거나 호스트에 연결할 수 없으면 호스트에 *배스천 …에서 … 주소로 연결을 열지 못했습니다*가 표시됩니다.

목록에서 배스천을 옮겨도 신뢰한 키는 유지됩니다. 배스천의 서버나 포트를 바꾸면 그 배스천의 키만 잊습니다.

## 키 다시 생성

Homeport가 만든 키라면 호스트 페이지의 **키 다시 생성**으로 교체할 수 있습니다. 이전 키는 더 이상 작동하지 않으므로, 새 **공개 키 추가** 명령을 서버에서 실행하고 `~/.ssh/authorized_keys`에서 이전 줄을 삭제하세요.

## SSH 호스트 삭제

호스트를 삭제하면 Homeport에서는 키가 삭제되지만 서버에서는 삭제되지 않습니다. 사용자의 `~/.ssh/authorized_keys`에서 해당 줄을 삭제하세요. `homeport@`로 시작하는 주석으로 알아볼 수 있습니다.

## 흔한 문제

| 메시지                                                                                                    | 해결 방법                                                                                                                                                                                               |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| _서버가 …의 키를 거부했습니다_                                                                            | 서버에서 **공개 키 추가** 명령을 실행한 다음 **다시 연결**하세요.                                                                                                                                       |
| _SSH 서버가 /var/run/docker.sock을 열지 못했습니다 … 경로와 … 사용자가 Docker를 쓸 수 있는지 확인하세요._ | **원격 소켓 경로**를 확인하고, 사용자를 `docker` 그룹에 추가하세요.                                                                                                                                     |
| _SSH 연결 시간이 초과되었습니다_                                                                          | 서버 이름, 포트, 그리고 중간의 방화벽을 확인하세요.                                                                                                                                                     |
| _실행 중인 ssh-agent가 없습니다_                                                                          | 에이전트를 시작하고 `ssh-add`로 키를 추가한 다음, Homeport가 `SSH_AUTH_SOCK`을 볼 수 있는지 확인하세요. Windows에서는 Pageant를 열고 키를 불러오거나, OpenSSH Authentication Agent 서비스를 시작하세요. |
| _배스천 …에서 … 주소로 연결을 열지 못했습니다_                                                            | 배스천이 호스트에 연결할 수 있는지, 그리고 배스천의 `sshd`가 `AllowTcpForwarding`을 허용하는지 확인하세요.                                                                                              |

자세한 내용은 [문제 해결](/docs/reference/troubleshooting/)에 있습니다.
