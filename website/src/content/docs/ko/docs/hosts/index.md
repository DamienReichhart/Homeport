title: 호스트와 연결
description: Homeport가 Docker Engine, containerd, Incus에 연결하는 방법, 각 호스트 상태의 의미, 다시 연결이 작동하는 방식.
---

**호스트**는 Homeport가 연결하는 Docker Engine, containerd 또는 Incus입니다. 호스트에는 이름과 접근 방법이 있습니다. 화면에 보이는 모든 컨테이너, 인스턴스, 이미지, 볼륨, 네트워크, 스택은 정확히 하나의 호스트에 속합니다.

## 연결 종류

| 유형          | 연결할 엔진                                             | 자격 증명                                            | 안내                                                           |
| ------------- | ------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------- |
| **로컬 소켓** | 이 컴퓨터에서 소켓이나 파이프로                         | 없음                                                 | [로컬 엔진](/docs/hosts/local/)                                |
| **SSH**       | 로그인할 수 있는 서버에서                               | Homeport 키, 직접 가진 키 또는 ssh-agent             | [SSH](/docs/hosts/ssh/)                                        |
| **TLS**       | `dockerd --tlsverify`로 노출된 엔진, 또는 Incus의 HTTPS | CA 인증서, 클라이언트 인증서와 키. Incus는 신뢰 토큰 | [TLS와 TCP](/docs/hosts/tls-tcp/), [Incus](/docs/hosts/incus/) |
| **TCP**       | 신뢰할 수 있는 네트워크에서 암호화 없이 노출된 엔진     | 없음                                                 | [TLS와 TCP](/docs/hosts/tls-tcp/)                              |

원격 서버라면 **SSH**를 권장합니다. SSH 포트 외에는 아무것도 노출할 필요가 없고, 안전하게 설정하기도 가장 쉽습니다.

## 엔진 종류

각 호스트는 접근 방법 외에, 가리키는 엔진의 종류도 양식의 **엔진** 필드에 지정합니다. 이 값에 따라 사이드바에 그 호스트의 어떤 페이지가 표시될지 정해집니다.

| 엔진            | 대상                                                                      | 페이지                                                                                          |
| --------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Docker 호환** | Docker Engine, Docker Desktop, Colima, OrbStack, Rancher Desktop, Podman  | 컨테이너, 이미지, 볼륨, 네트워크, 스택, 이벤트. Podman에서는 Podman 전용 페이지도 표시          |
| **containerd**  | containerd 자체 서비스, k3s의 containerd, Docker Engine 자체의 containerd | containerd의 컨테이너, 이미지, 스냅샷, 네임스페이스. [containerd](/docs/hosts/containerd/) 참고 |
| **Incus**       | Incus 6.0 이상: 시스템 컨테이너와 가상 머신                               | 인스턴스, 이미지, 프로필, 스토리지, 네트워크. [Incus](/docs/hosts/incus/) 참고                  |

소켓 경로가 containerd나 Incus의 소켓을 가리키면 양식이 엔진을 자동으로 고릅니다. containerd는 이 컴퓨터나 SSH를 통한 소켓으로만 연결하므로 TCP와 TLS가 비활성화되고, Incus는 소켓이나 HTTPS(TLS)로 연결하므로 TCP만 비활성화됩니다. Homeport 0.18 이전에 추가한 호스트는 다른 설정은 그대로 둔 채 Docker 호환으로 지정됩니다.

**Podman**은 Homeport가 연결할 때마다 인식하는 Docker 호환 엔진입니다. 같은 소켓이라도 제품이 바뀔 수 있기 때문입니다. 이때 호스트 상태에는 엔진 버전 대신 **Podman**과 그 버전이 표시되고, 사이드바에 Podman에만 있는 페이지가 추가됩니다. 선택한 호스트에서 표시할 수 없는 페이지는 사이드바에 나타나지 않으며, 링크로 열면 그 이유를 알려 줍니다.

Docker Swarm에 속한 호스트에는 Swarm 이름과 함께 **…의 매니저** 또는 **…의 워커**가 표시되며, 매니저 하나를 호스트로 추가하기만 하면 사이드바에 Swarm이 나타납니다. 호스트 페이지에는 Swarm을 시작하거나, 가입하거나, 떠날 수 있는 **Swarm** 카드도 있습니다. [Swarm](/docs/guides/swarm/)을 참고하세요.

## 호스트 추가, 편집, 삭제

- 사이드바 위쪽 호스트 전환기의 **호스트 추가…** 항목이나 개요의 **호스트 추가**로 호스트를 **추가**합니다.
- 호스트 전환기의 **호스트 관리**는 모든 호스트를 유형, 주소, 상태와 함께 나열합니다. 하나를 선택하면 해당 호스트 페이지가 열립니다.
- 호스트 페이지에서 연결 정보를 바꾸고 **저장**을 선택하면 Homeport가 새 설정으로 다시 연결합니다. 호스트의 연결 유형은 바꿀 수 없으므로, 삭제한 다음 다시 추가하세요.
- **사용** 스위치는 호스트를 잊지 않고 연결만 끊습니다. 사용하지 않는 호스트는 다시 켤 때까지 재시도하지 않습니다.
- **호스트 삭제**는 호스트, 저장된 자격 증명, 관리형 스택의 compose 정의, 링크된 스택, 스택의 배포 기록을 잊습니다. 호스트에서 실행 중인 것은 건드리지 않습니다. 컨테이너, 이미지, 볼륨은 그대로 남고, 링크된 스택의 폴더도 남습니다. 호스트가 관리하는 Swarm의 스택은 Swarm에 속하므로 유지됩니다.

호스트 이름은 대소문자를 구분하지 않고 고유해야 합니다.

## 호스트 가져오기

**호스트 추가**에서는 이 컴퓨터에 이미 있는 정보로 여러 호스트를 한 번에 추가하는 두 가지 방법을 제공합니다. 각각 미리 보기가 열리며, 가져올 항목을 고르고 이름을 바꾼 다음 **가져오기**를 선택합니다.

- **~/.ssh/config에서 가져오기**는 SSH 설정에 있는 서버를 사용자, 포트, 키, `ProxyJump` 배스천과 함께 추가합니다. [~/.ssh/config에서 가져오기](/docs/hosts/ssh/#sshconfig에서-가져오기)를 참고하세요.
- **Docker 컨텍스트 가져오기**는 Docker CLI 컨텍스트(`docker context ls`)의 엔진을 TLS 인증서와 함께 추가합니다.

키와 인증서는 가져올 때 한 번만 읽고 다른 비밀 정보와 마찬가지로 암호화하여 저장합니다. `~/.ssh`와 `~/.docker`는 절대 변경하지 않습니다.

### Docker 컨텍스트

Homeport는 `~/.docker/contexts`(설정되어 있으면 `$DOCKER_CONFIG`) 아래의 모든 컨텍스트를 읽고 Docker 엔드포인트를 다음과 같이 변환합니다.

| 엔드포인트                                               | 변환 결과                                                |
| -------------------------------------------------------- | -------------------------------------------------------- |
| `unix:///…`, `npipe:////./pipe/…`                        | **로컬 소켓** 호스트                                     |
| TLS 파일이 없는 `tcp://host:port`                        | **TCP** 호스트                                           |
| `ca.pem`, `cert.pem`, `key.pem`이 있는 `tcp://host:port` | 인증서가 포함된 **TLS** 호스트                           |
| `ssh://user@host:port`                                   | ssh-agent와 `/var/run/docker.sock`을 쓰는 **SSH** 호스트 |

기본 제공 `default` 컨텍스트는 표시되지 않습니다. [로컬 감지](/docs/hosts/local/)가 이미 이 컴퓨터의 엔진을 찾기 때문입니다. 다음과 같은 컨텍스트는 표시되지만 선택할 수 없습니다.

- `SkipTLSVerify`를 설정한 컨텍스트. Homeport는 항상 엔진의 인증서를 확인합니다.
- TLS 폴더에 세 파일 중 일부만 있는 컨텍스트.
- Kubernetes 엔드포인트처럼 다른 종류의 엔드포인트를 쓰는 컨텍스트.
- 이미 다른 호스트가 같은 엔진에 연결하는 컨텍스트. 어떤 호스트인지 이름으로 알려 줍니다.

이름이 이미 호스트 이름으로 쓰이는 컨텍스트는 `name (2)`로 제안됩니다.

## 다른 컴퓨터로 옮기기

호스트 페이지의 **내보내기**는 선택한 호스트를 암호 문구로 보호되는 파일에 저장합니다. 다른 컴퓨터의 호스트 페이지에서 **가져오기**로 이 파일을 열고 선택한 호스트를 추가하면 바로 연결할 수 있습니다. 그 컴퓨터에 이미 같은 이름의 호스트가 있으면 `name (2)`로 제안되며, 이름을 바꾸거나 건너뛸 수 있습니다. 파일이 어떻게 보호되는지는 [다른 컴퓨터로 옮기기](/docs/reference/security/#다른-컴퓨터로-옮기기)를 참고하세요.

## 호스트 선택

모든 리소스 페이지(컨테이너, 이미지, 볼륨, 네트워크, 스택, 이벤트)는 **호스트 전환기**에서 선택한 호스트를 보여 줍니다. containerd 호스트의 페이지는 [전환기 아래](/docs/hosts/containerd/#네임스페이스)에서 고른 네임스페이스 하나만, Incus 호스트의 페이지는 [프로젝트](/docs/hosts/incus/#프로젝트) 하나만 보여 줍니다. 전환기에서 호스트를 바꾸거나 [개요](/docs/guides/overview/)에서 호스트 카드를 선택하세요. Homeport는 다음 실행 때도 선택을 기억합니다.

## 상태

각 호스트의 이름 옆에는 상태가 표시됩니다. 선택한 호스트가 연결되어 있지 않으면 리소스 페이지에 상태와 함께 **지금 다시 시도**와 **호스트 설정 열기**가 표시됩니다.

| 상태                        | 의미                                                                                | 다음 동작                                                           |
| --------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| **연결됨**                  | 엔진이 응답했습니다. 엔진 버전, 또는 Podman, containerd, Incus의 버전이 표시됩니다. | Homeport가 연결을 계속 감시합니다.                                  |
| **연결 중**                 | Homeport가 엔진에 연결하는 중입니다.                                                | —                                                                   |
| **사용 안 함**              | 호스트의 **사용** 스위치가 꺼져 있습니다.                                           | 켤 때까지 아무것도 하지 않습니다.                                   |
| **연결할 수 없음**          | 네트워크, 소켓 또는 엔진이 응답하지 않았습니다.                                     | 스스로 재시도하며, 매번 조금 더 기다립니다.                         |
| **액세스 거부됨**           | SSH 서버가 키를 거부했거나, ssh-agent가 실패했거나, TLS 핸드셰이크가 실패했습니다.  | 원인을 해결한 다음 **다시 연결**하세요.                             |
| **신뢰하지 않는 서버 키**   | 첫 SSH 연결입니다. 서버나 배스천의 키를 승인해야 합니다.                            | 호스트 페이지에서 [키를 신뢰](/docs/hosts/ssh/#서버-키-신뢰)하세요. |
| **서버 키가 변경됨**        | SSH 서버가 신뢰한 키와 다른 키를 제시했습니다.                                      | [먼저 조사하세요](/docs/hosts/ssh/#서버-키가-바뀌었을-때).          |
| **자격 증명 손실**          | 저장된 자격 증명을 복호화할 수 없습니다.                                            | [다시 입력하세요](/docs/reference/troubleshooting/#자격-증명-손실). |
| **키체인을 사용할 수 없음** | 호스트에 저장된 비밀 정보가 필요하지만 OS 키체인이 없습니다.                        | [요구 사항](/docs/requirements/#선택-사항-os-키체인)을 참고하세요.  |
| **잘못 구성됨**             | 호스트 설정에 누락되었거나 잘못된 항목이 있습니다.                                  | 메시지가 무엇인지 알려 줍니다. 고친 다음 **저장**하세요.            |

## 다시 연결

Homeport는 시작할 때 사용 중인 모든 호스트에 연결하며, 호스트마다 연결이 따로 있으므로 느린 서버 하나가 다른 서버를 막지 않습니다.

연결되어 있는 동안 Homeport는 엔진의 이벤트 스트림을 수신하고(페이지가 스스로 갱신되는 이유입니다) 15초마다 엔진을 확인합니다. 연결이 끊기면 호스트는 **연결할 수 없음**이 되고, Homeport는 1초 후, 이어서 2초, 4초, 8초처럼 간격을 늘려 가며 최대 1분에 한 번까지 재시도합니다. 연결에 성공하면 대기 시간이 초기화됩니다.

**연결할 수 없음**만 자동으로 재시도합니다. 다른 문제는 모두 사용자의 조치가 필요하며, 그다음 **다시 연결**(호스트 페이지)이나 **지금 다시 시도**를 선택하면 곧바로 다시 시도합니다.

## 이벤트와 실시간 업데이트

Homeport는 폴링하지 않습니다. 컨테이너 시작이나 이미지 풀처럼 엔진이 변경을 보고하면, 영향을 받는 페이지가 1초도 안 되어 새로 고쳐집니다. [이벤트](/docs/guides/overview/#이벤트) 페이지에서 원시 스트림을 볼 수 있습니다.
