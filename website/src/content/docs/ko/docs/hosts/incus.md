**Incus**는 시스템 컨테이너와 가상 머신, 즉 [안내서](/docs/guides/instances/)에서 다루는 **인스턴스**를 실행합니다. Homeport는 [ADR 0021](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0021-incus-over-its-rest-api.md)에서 정한 대로 Incus 자체의 REST API를 통해 연결합니다. Incus 호스트는 사이드바에 전용 페이지인 **인스턴스**, **이미지**, **프로필**, **스토리지**, **네트워크**를 가집니다. Docker 페이지, 스택, 보드는 제공되지 않습니다.

## Incus 호스트 추가

양식의 **엔진** 필드에서 **Incus**를 선택한 다음 연결 방법을 고릅니다.

| 연결           | 사용하는 경우                                              | 필요한 것                                                     |
| -------------- | ---------------------------------------------------------- | ------------------------------------------------------------- |
| **로컬 소켓**  | 이 컴퓨터(Linux)에서 Incus가 실행되는 경우                 | `incus-admin` 그룹 또는 `incus` 그룹에 속한 사용자(아래 참고) |
| **SSH**        | 로그인할 수 있는 서버에서 Incus가 실행되는 경우            | `incus-admin` 그룹 또는 `incus` 그룹에 속한 SSH 사용자        |
| **TLS**(HTTPS) | Incus가 네트워크에서 수신 대기하거나 SSH를 쓸 수 없는 경우 | 신뢰 토큰, 또는 Incus가 이미 신뢰하는 클라이언트 인증서       |

일반 **TCP**는 비활성화됩니다. Incus는 TLS 없이 API를 제공하지 않기 때문입니다. Homeport는 **Incus 6.0**(장기 지원 릴리스) 이상에 연결합니다.

### Incus의 소켓

| 소켓                              | 사용할 수 있는 사용자      | 접근 범위                                          |
| --------------------------------- | -------------------------- | -------------------------------------------------- |
| `/var/lib/incus/unix.socket`      | `incus-admin` 그룹         | 모든 것: 모든 프로젝트, 스토리지 풀, 네트워크      |
| `/var/lib/incus/unix.socket.user` | `incus` 그룹(`incus-user`) | 처음 사용할 때 만들어지는 사용자 자신의 프로젝트만 |

Linux에서는 두 소켓이 응답하면 **이 컴퓨터에서 찾음**에 둘 다 나열되며, 제한된 소켓은 **Incus(프로젝트로 제한됨)** 항목으로 표시됩니다. 아직 사용할 권한이 없는 소켓은 해결하는 명령과 함께 나열됩니다.

```bash
sudo usermod -aG incus-admin "$USER"
```

그룹 변경은 새로 로그인할 때 적용됩니다. 호스트를 추가하기 전에 로그아웃했다가 다시 로그인하세요(SSH라면 다시 연결하세요). 중지된 Incus는 어떤 유닛으로 시작하는지 알려 줍니다.

```bash
sudo systemctl enable --now incus.socket incus.service
```

### 신뢰 토큰을 사용한 HTTPS

`core.https_address`를 설정하면 Incus가 네트워크에서 수신 대기합니다. Incus 서버에서 다음을 실행합니다.

```bash
incus config set core.https_address :8443
incus config trust add homeport
```

두 번째 명령은 문자와 숫자로 된 한 줄짜리 **신뢰 토큰**을 출력합니다. Homeport에서 **Incus**와 **TLS**를 고르고 **신뢰 토큰**을 선택된 상태로 둔 채 토큰을 붙여 넣으세요. Homeport가 읽은 내용(토큰이 발급된 이름, 서버 주소와 인증서 지문, 만료 시각)을 보여 주며, **추가**를 선택하면 다음을 수행합니다.

1. 메모리에서 만든 ECDSA P-384 키로 자체 클라이언트 인증서를 만듭니다.
2. 토큰의 주소를 순서대로 시도하여, 토큰에 지정된 지문과 인증서가 일치하는 첫 번째 주소를 사용합니다. 다른 인증서는 두 지문을 함께 보여 주며 거부합니다.
3. 인증서와 함께 토큰을 보내고, Incus가 이제 인증서를 신뢰하는지 확인합니다.

그러면 호스트가 `incus config trust list`에 토큰의 이름으로 나타납니다. 토큰은 한 번만 쓸 수 있고 만료됩니다. 사용했거나, 취소되었거나, 만료된 토큰은 새 토큰을 만드는 명령과 함께 거부됩니다. 나중에 Homeport의 접근을 취소하려면 그곳에서 인증서를 삭제하세요.

```bash
incus config trust list
incus config trust remove <fingerprint>
```

**기존 인증서**는 Incus가 이미 신뢰하는 클라이언트 인증서와 키(`incus config trust add-certificate`)를, 신뢰할 Incus 자체의 인증서(`/var/lib/incus/server.crt`, 클러스터에서는 `cluster.crt`)와 함께 받습니다.

### 서버 인증서 고정

Incus의 인증서는 자체 서명이므로 확인할 CA가 없습니다. Homeport는 신뢰한 인증서를 호스트와 함께 보관하고, 이후에는 어느 주소로 연결하든 SHA-256 지문으로 비교하여 정확히 그 인증서만 받아들입니다. Incus를 다시 설치하거나 인증서를 갱신하면 예상한 지문과 받은 지문을 보여 주며 호스트 연결이 거부됩니다. 서버에서 `incus info`로 새 지문을 확인한 다음, 새 토큰으로 호스트를 다시 추가하세요. 클라이언트 키와 두 인증서는 다른 모든 비밀 정보처럼 암호화하여 저장합니다. [보안](/docs/reference/security/#incus-인증서)을 참고하세요.

## 프로젝트

Incus는 인스턴스, 이미지, 프로필, 사용자 지정 볼륨, 네트워크를 **프로젝트**에 보관합니다. 페이지는 한 번에 프로젝트 하나만 보여 주며, 호스트 전환기 아래에서 고릅니다. 이 목록에는 프로젝트마다 인스턴스와 이미지가 몇 개 있는지 표시됩니다. Homeport는 호스트별로 선택을 기억하여 다음 실행 때도 유지합니다. 선택하기 전에는 호스트가 `default`를 보여 주며, 제한된 소켓에서는 유일한 프로젝트를 보여 줍니다. 스토리지 풀은 서버 전체에 속하며, 그 볼륨은 선택한 프로젝트 기준으로 표시됩니다.

## 이벤트

페이지는 모든 프로젝트에서 발생하는 Incus의 수명 주기 이벤트로 새로 고쳐집니다. 인스턴스의 시작이나 중지, 스냅샷 생성, 이미지 추가, 프로필이나 네트워크 변경이 해당합니다. 이 이벤트는 **이벤트** 페이지에도 보관됩니다. Incus는 이벤트 기록을 보관하지 않으므로, Homeport가 닫혀 있는 동안 일어난 일은 채워지지 않습니다.

연결되어 있는 동안 Homeport는 15초마다 Incus에 `GET /1.0`을 요청합니다. Incus가 중지되면 호스트가 **연결할 수 없음**이 되고, Incus가 다시 응답하면 Homeport가 스스로 다시 연결합니다.

## Homeport가 호스트에서 하는 일

Incus 호스트에서는 Incus 자체 외에는 아무것도 실행되지 않습니다. 콘솔과 터미널은 Incus 자체의 웹소켓을 통하고, 원격 이미지는 Incus가 다운로드합니다. Homeport는 이미지 선택기를 위해 원격 이미지 서버의 이미지 목록을 이 컴퓨터에서 읽습니다.
