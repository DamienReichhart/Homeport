**containerd**는 k3s, nerdctl, BuildKit, 그리고 Docker가 없는 많은 서버의 밑에서 실행됩니다. Homeport는 [ADR 0020](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0020-containerd-over-grpc.md)에서 정한 대로 containerd 자체의 gRPC API를 통해 직접 연결합니다. containerd 호스트는 사이드바에 전용 페이지인 **컨테이너**, **이미지**, **스냅샷**, **네임스페이스**를 가집니다. Docker 페이지, 스택, 보드는 제공되지 않습니다.

## containerd 호스트 추가

양식의 **엔진** 필드에서 **containerd**를 선택합니다. containerd에는 소켓으로만 연결하므로 연결은 **로컬 소켓**이나 **SSH**입니다. containerd는 네트워크로 API를 제공하지 않으므로 TCP와 TLS는 비활성화됩니다.

| containerd                      | 소켓                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------- |
| containerd 자체 서비스          | `/run/containerd/containerd.sock`                                            |
| k3s                             | `/run/k3s/containerd/containerd.sock`                                        |
| Docker Engine 자체의 containerd | `/run/containerd/containerd.sock`. 컨테이너는 `moby` 네임스페이스에 있습니다 |

Linux에서는 이 컴퓨터의 containerd와 k3s의 containerd가 응답하면 **이 컴퓨터에서 찾음**에 나열됩니다. 아직 사용할 권한이 없는 소켓은 해결 방법과 함께 나열됩니다.

### 사용자가 소켓을 쓸 수 있게 하기

containerd의 소켓은 root 소유입니다. 로컬이나 SSH로 다른 사용자가 쓰려면 `/etc/containerd/config.toml`에서 그룹에 소켓 접근 권한을 주고 그 그룹에 사용자를 추가하세요.

```bash
sudo groupadd -f containerd
sudo usermod -aG containerd "$USER"
getent group containerd | cut -d: -f3
```

출력된 숫자를 `/etc/containerd/config.toml`의 `[grpc]` 아래에 넣고, containerd를 다시 시작한 다음 다시 로그인하세요.

```toml
[grpc]
  gid = 1001
```

```bash
sudo systemctl restart containerd
```

**rootless containerd**(`containerd-rootless.sh`)는 소켓을 RootlessKit의 네임스페이스 안에 두므로, Homeport를 포함해 그 바깥에서는 아무것도 접근할 수 없습니다. Homeport는 이를 발견하면 알려 줍니다. 대신 containerd의 시스템 서비스를 사용하세요.

### 버전과 연결별로 가능한 작업

Homeport는 containerd **1.7** 이상에 연결합니다. 풀은 **2.0**부터 안정된 containerd의 Transfer 서비스를 통해 이루어집니다.

| 작업                                            | containerd | 연결                        |
| ----------------------------------------------- | ---------- | --------------------------- |
| 네임스페이스, 컨테이너와 태스크, 이미지, 스냅샷 | 1.7 이상   | 로컬 소켓 또는 SSH          |
| 이미지 풀                                       | 2.0 이상   | 로컬 소켓 또는 SSH          |
| 로그와 터미널                                   | 1.7 이상   | SSH, 또는 Linux의 로컬 소켓 |

연결하기에 너무 오래된 containerd는 버전을 알려 주며 호스트를 **잘못 구성됨** 상태로 둡니다. 풀하기에 너무 오래된 경우에는 풀할 때 알려 줍니다.

## 네임스페이스

모든 containerd 객체는 **네임스페이스**에 있습니다. nerdctl은 `default`, Kubernetes는 `k8s.io`, Docker는 `moby`, BuildKit은 `buildkit`을 사용합니다. 페이지는 한 번에 네임스페이스 하나만 보여 주며, 호스트 전환기 아래에서 고릅니다. 이 목록에는 네임스페이스마다 컨테이너와 이미지가 몇 개 있는지 표시됩니다. Homeport는 호스트별로 선택을 기억하여 다음 실행 때도 유지합니다. 선택하기 전에는 호스트가 `default`를 보여 주며, `default`가 비어 있으면 무언가 들어 있는 유일한 네임스페이스를 보여 줍니다. 그래서 k3s 호스트는 `k8s.io`로 열립니다.

**네임스페이스** 페이지에서는 빈 네임스페이스를 만들고 빈 네임스페이스를 삭제합니다. containerd는 무언가 남아 있는 네임스페이스를 삭제하지 않으며, Homeport가 무엇이 남아 있는지 알려 줍니다. 먼저 컨테이너, 이미지, 스냅샷을 삭제하세요.

## 컨테이너와 태스크

containerd에서 **컨테이너**는 메타데이터일 뿐입니다. 이미지, 명세, 스냅샷이 전부입니다. 실제로 실행되는 것은 **태스크**입니다. **컨테이너** 페이지는 네임스페이스의 컨테이너를 태스크 상태와 함께 나열합니다. **실행 중**, **일시 중지됨**, 종료 코드가 있는 **중지됨**, 또는 **태스크 없음**입니다. 각 컨테이너에는 만든 도구가 표시되며(**Kubernetes**(Pod 포함), **nerdctl**, **Docker**, **ctr 또는 기타**), Pod의 pause 컨테이너는 요청하지 않으면 숨겨집니다.

| 작업            | Homeport가 하는 일                                                                                                                                                                                                                                      |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **시작**        | 컨테이너의 스냅샷 위에 태스크를 만들고, nerdctl이 로그를 남기는 위치에 로그를 남기도록 하여 시작합니다. `ctr task start`에서 필요한 것처럼 중지된 태스크는 교체합니다.                                                                                  |
| **중지**        | 이미지의 중지 신호(다른 신호를 지정하지 않으면 SIGTERM)를 보내고, 10초 후 SIGKILL을 보냅니다. 그 후에도 살아 있는 태스크는 보고합니다.                                                                                                                  |
| **일시 중지**   | 태스크를 정지시킵니다. **재개**로 다시 실행합니다.                                                                                                                                                                                                      |
| **신호 보내기** | 태스크의 주 프로세스에 이름(`SIGHUP`)이나 번호로 원하는 신호를 보냅니다.                                                                                                                                                                                |
| **삭제**        | 먼저 확인을 받은 다음, 실행 중인 태스크를 강제 종료하고, 태스크와 컨테이너, 그리고 변경된 파일과 함께 스냅샷을 삭제합니다. 단, **…도 삭제**의 선택을 해제하면 남긴 스냅샷에 `containerd.io/gc.root`가 표시되어 containerd의 가비지 컬렉터가 유지합니다. |

컨테이너 페이지에는 런타임, 스냅샷, 레이블, OCI 명세가 표시됩니다. Homeport는 containerd에서 컨테이너를 만들지 않습니다. containerd에는 자체 네트워킹이 없고, 네트워킹은 nerdctl과 CNI가 추가합니다.

Kubernetes의 컨테이너는 **kubelet**이 관리합니다. 중지하면 다시 시작하고, 삭제하면 다시 만듭니다. 이런 컨테이너의 페이지에는 그렇다고 표시되므로, 대신 클러스터에서 Pod를 변경하세요. 여기서 nerdctl 컨테이너를 삭제하면 `ctr`과 마찬가지로 nerdctl 자체의 기록(이름과 네트워크)은 남습니다. 이런 컨테이너는 `nerdctl rm`으로 삭제하는 편이 깔끔합니다.

## 로그

containerd는 로그를 보관하지 않습니다. 태스크를 시작한 도구가 출력의 행방을 정합니다. **로그** 탭은 그 도구가 기록한 곳에서 출력을 읽습니다.

| 만든 도구                | 출력이 가는 곳                                                        | Homeport가 보여 주는 것                              |
| ------------------------ | --------------------------------------------------------------------- | ---------------------------------------------------- |
| nerdctl                  | nerdctl 상태 폴더의 JSON 로그 파일. `nerdctl/` 레이블로 이름이 정해짐 | 그 파일을 실시간으로                                 |
| Kubernetes(`k8s.io`)     | `/var/log/pods/<pod>/<container>/N.log`. CRI의 기록에 이름이 있음     | 그 파일을 실시간으로                                 |
| `ctr` 및 기타 클라이언트 | 클라이언트가 지정한 곳. 보통 아무 데도 없음                           | **이 컨테이너의 출력은 기록되지 않습니다**와 그 이유 |

다른 드라이버(journald, fluentd)로 로그를 보내는 nerdctl 컨테이너는 대신 그 드라이버 이름을 표시합니다. Homeport는 호스트의 컴퓨터에서 `tail`로 파일을 읽습니다([아래](#what-runs-on-the-host) 참고). 로그 파일은 보통 root 소유이므로 SSH 사용자에게 읽기 권한이 있어야 합니다.

## 컨테이너 안의 터미널

**Exec** 탭은 실행 중인 컨테이너에서 셸(이미지에 bash가 있으면 bash, 없으면 sh)이나 지정한 명령을, 숫자 사용자(`uid` 또는 `uid:gid`)로, 원하는 폴더에서 엽니다. **다시 열기**는 입력한 내용으로 새 터미널을 시작합니다.

containerd는 프로세스의 입력과 출력을 자신의 컴퓨터에 있는 경로로 받습니다. 그래서 Homeport는 그 컴퓨터에서 짧은 스크립트를 실행하여 비공개 임시 폴더에 FIFO 두 개를 만들고, 이를 통해 터미널 입출력을 전달합니다. containerd는 컨테이너 자체의 프로세스 명세에 따라 이 FIFO로 프로세스를 시작합니다. 탭을 닫으면 프로세스를 강제 종료하고 폴더를 삭제합니다.

## 이미지

**이미지** 페이지는 네임스페이스의 이미지를 플랫폼, 이미지로 만든 컨테이너, 그리고 `ctr images ls`가 계산하는 방식으로 호스트 플랫폼 기준 크기와 함께 나열합니다.

**이미지 풀**은 containerd 자체를 통해 이미지를 가져온 다음, 호스트 플랫폼용으로 기본 스냅샷터에 압축을 풀어 `nerdctl run`이 곧바로 사용할 수 있게 합니다. 전체 참조(`ghcr.io/home/app:1.2`)나 짧은 참조(`nginx`, `docker.io/library/nginx:latest`가 됨)를 입력하세요. 비공개 레지스트리의 이미지는 **설정 → 레지스트리**의 로그인으로 풀합니다. 로그인은 레지스트리가 요청할 때만 containerd에 보내며, 호스트에는 절대 저장하지 않습니다.

네임스페이스의 컨테이너를 만든 이미지는 삭제할 수 없습니다. 먼저 컨테이너를 삭제하세요. containerd는 아무것도 참조하지 않게 된 이미지의 콘텐츠를 해제합니다.

## 스냅샷

containerd가 디스크를 쓰는 곳이 스냅샷입니다. 압축을 푼 이미지의 레이어와 각 컨테이너의 쓰기 가능한 레이어가 여기에 해당합니다. **스냅샷** 페이지는 스냅샷터 하나(`overlayfs`가 우선이고, 없으면 호스트가 불러온 다른 스냅샷터)의 스냅샷을 부모 기준 트리로, 큰 것부터 보여 주며, `ctr snapshot usage`가 계산하는 사용량과 맨 위에 합계를 표시합니다.

각 스냅샷에는 사용하는 대상이 표시됩니다. 스냅샷을 쓰는 컨테이너나, 레이어를 쓰는 이미지입니다. 아무것도 사용하지 않고 그 위에 아무것도 만들어지지 않은 스냅샷(여기서 컨테이너를 삭제할 때 남긴 스냅샷 등)은 **사용하지 않는 항목만**으로 따로 보고 삭제할 수 있습니다. 나머지는 여기서 삭제할 수 없습니다. `ctr containers rm --keep-snapshot`이 남기는 스냅샷처럼 아무것도 참조하지 않고 루트로 표시되지도 않은 스냅샷은 오래가지 않습니다. containerd의 가비지 컬렉터가 다음 실행 때 삭제합니다.

## 호스트에서 실행되는 것

위의 모든 작업은 containerd API를 통해 이루어지지만, 로그와 터미널은 containerd가 있는 컴퓨터의 파일이 필요합니다. 이를 위해 Homeport는 이미 연결된 SSH 세션을 통해, 또는 Linux의 로컬 소켓이라면 이 컴퓨터에서, SSH 사용자의 권한으로 다음 명령을 실행하며 `sudo`는 절대 사용하지 않습니다.

| 용도   | 명령                                                                                                        |
| ------ | ----------------------------------------------------------------------------------------------------------- |
| 로그   | `tail -n <lines> [-F] -- '<log file>'`. CRI의 기록이 없는 Kubernetes 컨테이너는 먼저 로그 폴더를 `ls`합니다 |
| 터미널 | `mktemp -d`, 그 폴더에 FIFO 두 개를 만드는 `mkfifo -m 600`, 이를 통한 `cat`, 그리고 폴더의 `rm -rf`         |

macOS나 Windows의 로컬 소켓에서는 이 명령을 실행할 수 없으므로 로그와 터미널에 SSH가 필요하다고 표시됩니다. Homeport가 호스트에서 실행하는 모든 명령은 [보안 페이지](/docs/reference/security/#what-homeport-runs-on-your-hosts)에 나와 있습니다.

## 이벤트

페이지는 모든 네임스페이스에서 발생하는 containerd 자체 이벤트로 새로 고쳐집니다. 태스크의 시작이나 종료, 컨테이너나 이미지의 생성이나 삭제, 스냅샷 커밋이 해당합니다. containerd는 이벤트 기록을 보관하지 않으므로, Homeport가 닫혀 있는 동안 일어난 일은 채워지지 않습니다.
