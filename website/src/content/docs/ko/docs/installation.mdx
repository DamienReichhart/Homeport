Homeport는 Windows, macOS, Linux용 설치 프로그램을 x64와 ARM용으로 각각 제공합니다. 시스템에 맞는 파일을 알려 주는 [다운로드 페이지](/download/)나 [최신 GitHub 릴리스](https://github.com/DamienReichhart/Homeport/releases/latest)에서 받으세요. Linux에서는 Homeport 패키지 저장소를 사용해 명령 하나로 설치할 수 있습니다.

어떤 방식으로 설치하든 최신 상태가 유지됩니다. Windows, macOS, AppImage에서는 Homeport가 스스로 업데이트하고, Linux 패키지는 시스템의 다른 패키지와 함께 업데이트됩니다. [업데이트](/docs/reference/updating/)를 참고하세요.

<Aside>
  Homeport는 Docker Engine을 관리하지만 Docker Engine을 포함하지는 않습니다. 이 컴퓨터에서
  컨테이너를 실행하려면 Docker Engine, Docker Desktop, Colima, OrbStack, Rancher Desktop 또는
  Podman도 설치하세요. 아니면 Homeport를 원격 서버에 연결하세요. [시스템 요구
  사항](/docs/requirements/)을 참고하세요.
</Aside>

## Windows

| 파일                                 | 용도                                        |
| ------------------------------------ | ------------------------------------------- |
| `Homeport_<version>_x64-setup.exe`   | 대부분의 PC. 현재 사용자용으로 설치합니다.  |
| `Homeport_<version>_arm64-setup.exe` | ARM용 Windows(Snapdragon 및 기타 ARM64 PC). |
| `Homeport_<version>_x64_en-US.msi`   | x64에서 관리형 설치와 자동 설치.            |

<Steps>

1. PC에 맞는 설치 프로그램을 다운로드하여 엽니다.

2. 설치 프로그램이 아직 유료 인증서로 서명되지 않았기 때문에 Windows SmartScreen이 **Windows의 PC 보호**라고 표시할 수 있습니다. **추가 정보**를 선택한 다음 **실행**을 선택하세요.

3. 설치 프로그램의 안내를 따릅니다. Homeport가 시작 메뉴에 추가됩니다.

</Steps>

MSI 패키지로 자동 설치하려면 다음을 실행합니다.

```powershell
msiexec /i Homeport_<version>_x64_en-US.msi /quiet
```

## macOS

| 파일                             | 용도                                |
| -------------------------------- | ----------------------------------- |
| `Homeport_<version>_aarch64.dmg` | Apple 실리콘(M1 이상)을 탑재한 Mac. |
| `Homeport_<version>_x64.dmg`     | Intel 프로세서를 탑재한 Mac.        |

어느 쪽인지 모르겠다면 Apple 메뉴 → **이 Mac에 관하여**를 여세요. **칩** 항목이 있으면 Apple 실리콘이고, **프로세서** 항목에 Intel이라고 표시되면 Intel입니다.

<Steps>

1. `.dmg`를 열고 **Homeport**를 **응용 프로그램**으로 드래그합니다.

2. 응용 프로그램 폴더나 Launchpad에서 Homeport를 엽니다.

3. Homeport는 아직 Apple의 공증을 받지 않았으므로 macOS가 **열 수 없습니다** 또는 **악성 소프트웨어가 있는지 확인할 수 없습니다**라고 표시할 수 있습니다. **완료**(또는 **확인**)를 선택하고 **시스템 설정 → 개인정보 보호 및 보안**을 연 다음, 보안 항목까지 스크롤하여 Homeport 옆의 **확인 없이 열기**를 선택하세요. 확인하면 macOS가 선택을 기억합니다.

</Steps>

<Aside type="tip" title="터미널에서">
  macOS가 다운로드한 앱에 붙이는 격리 플래그를 직접 지울 수도 있습니다.

```sh
xattr -dr com.apple.quarantine /Applications/Homeport.app
```

</Aside>

## Linux

Linux용 Homeport에는 x64 또는 ARM64에서 glibc 2.35 이상이 필요합니다. Ubuntu 22.04, Debian 12, Fedora 36 또는 그 이후 버전이 해당합니다.

다음 명령은 Homeport 패키지 저장소를 설정하고 Homeport를 설치하므로, `apt`, `dnf` 또는 `zypper`가 시스템의 다른 패키지와 함께 Homeport를 최신 상태로 유지합니다.

<Code code={INSTALL_COMMAND} lang="sh" />

이 스크립트는 Debian, Ubuntu와 그 파생 배포판(`apt`), Fedora, RHEL과 그 계열 배포판(`dnf`), openSUSE(`zypper`)에서 작동합니다. `sudo`를 요청하기 전에 무엇을 할지 알려 준 다음, 다음 작업을 합니다.

1. Homeport 서명 키를 추가합니다.
2. Homeport 저장소를 추가합니다.
3. `homeport` 패키지를 설치하거나, 이미 설치되어 있으면 업데이트합니다.

다시 실행해도 문제가 없습니다. 먼저 [스크립트를 읽어 보거나](https://github.com/DamienReichhart/Homeport/blob/main/packaging/linux/install.sh), 아래의 수동 설정을 따라도 됩니다. 결과는 같습니다.

### 패키지 파일

`.deb`(x64는 `amd64`, ARM은 `arm64`)나 `.rpm`(`x86_64` 또는 `aarch64`)을 다운로드하여 직접 설치할 수도 있습니다.

<Tabs syncKey="linux-format">
<TabItem label="Debian, Ubuntu">

```sh
sudo apt install ./Homeport_<version>_amd64.deb
```

</TabItem>
<TabItem label="Fedora, RHEL">

```sh
sudo dnf install ./Homeport-<version>-1.x86_64.rpm
```

</TabItem>
<TabItem label="openSUSE">

```sh
sudo zypper install ./Homeport-<version>-1.x86_64.rpm
```

</TabItem>
</Tabs>

이 패키지 중 하나를 처음 설치하면 Homeport 저장소도 추가되므로, 빠른 설치와 같은 방식으로 업데이트를 받습니다. 원하지 않으면 저장소 파일(`/etc/apt/sources.list.d/homeport.sources`, `/etc/yum.repos.d/homeport.repo` 또는 `/etc/zypp/repos.d/homeport.repo`)을 삭제하세요. 이후 패키지를 업데이트해도 다시 추가되지 않습니다.

### AppImage

AppImage는 아무것도 설치하지 않고 대부분의 배포판에서 실행되며, Homeport 안에서 스스로 업데이트합니다. 실행 권한을 주고 실행하세요.

```sh
chmod +x Homeport_<version>_amd64.AppImage
./Homeport_<version>_amd64.AppImage
```

실행할 때마다 Homeport를 애플리케이션 메뉴에 추가합니다. 시작되지 않고 FUSE에 대한 메시지가 나오면 `libfuse2`(Ubuntu 24.04 이상에서는 `libfuse2t64`)를 설치하세요.

`.deb`와 `.rpm` 패키지는 Homeport를 애플리케이션 메뉴에 추가하고, 라이선스 고지를 `/usr/share/doc/homeport/` 또는 `/usr/share/licenses/homeport/`에 설치합니다.

<Aside type="caution" title="이 컴퓨터에서 Docker를 사용하는 경우">
  root 권한 없이 로컬 Docker 소켓에 접근하려면 사용자가 `docker` 그룹에 속해야 합니다.

```sh
sudo usermod -aG docker $USER
```

적용하려면 로그아웃했다가 다시 로그인하세요. 그러지 않으면 로컬 호스트가 *Permission denied*와
함께 **연결할 수 없음**으로 표시됩니다.

</Aside>
