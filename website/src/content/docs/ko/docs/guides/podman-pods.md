Podman은 **Pod** 단위로 컨테이너를 묶습니다. Pod 안의 컨테이너는 하나의 네트워크(와 호스트 이름, IPC)를 공유하므로 `localhost`로 서로에게 접근할 수 있고, 함께 시작하고 중지합니다. 각 Pod에는 공유하는 요소와 Pod가 게시하는 포트를 보유하는 **인프라 컨테이너** 하나가 있습니다. Homeport는 엔진이 Podman인 호스트에서 Pod를 표시하며, 호스트가 이미 사용하는 소켓을 통해 Podman 자체 API를 사용합니다. 호스트에는 아무것도 설치하지 않습니다.

**Pod** 페이지는 Podman 호스트를 선택한 동안에만 사이드바에 나타납니다. 다른 Docker 호환 엔진에서는 이 페이지가 없으며, 이 페이지로 가는 링크에 그 이유가 표시됩니다. Homeport가 Podman을 구별하는 방법은 [엔진 종류](/docs/hosts/#엔진-종류)를 참고하세요.

## Pod 페이지

| 열           | 표시 내용                                                                                                         |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| **이름**     | Pod의 이름과, 점으로 표시되는 상태.                                                                               |
| **상태**     | **실행 중**, **일부 실행 중**(일부 컨테이너가 중지됨), **일시 중지됨**, **중지됨**, **생성됨**, **실패** 중 하나. |
| **컨테이너** | Pod 자체 컨테이너 중 실행 중인 수(인프라 컨테이너는 제외).                                                        |
| **네트워크** | Pod가 속한 네트워크.                                                                                              |
| **생성일**   | Pod가 생성된 시각.                                                                                                |

각 행에는 상태에 맞는 작업(중지된 Pod에는 **시작**, 실행 중인 Pod에는 **중지**)과 **삭제** 버튼이 있습니다. Pod를 선택하면 해당 페이지가 열립니다. Homeport에서든 터미널에서든 Pod의 컨테이너가 시작하고 중지하면 목록이 저절로 갱신됩니다.

**컨테이너** 페이지에서 Pod 안에서 실행되는 컨테이너는 자기 이름 옆에 Pod 이름을 표시합니다. 그 이름을 선택하면 Pod가 열립니다.

## Pod의 페이지

헤더에는 **컨테이너 실행** 버튼과, 상태에 따라 Pod의 작업 **시작**, **중지**, **다시 시작**, **일시 중지**, **재개**, **삭제** 버튼이 있습니다. 각 작업은 `podman pod start` 등의 명령처럼 Pod의 모든 컨테이너에 한꺼번에 적용됩니다.

- **컨테이너** 섹션은 Pod의 컨테이너를 나열하며, 인프라 컨테이너는 마지막에 표시됩니다. 컨테이너를 선택하면 로그, 터미널, 파일이 있는 컨테이너 페이지가 열립니다.
- **설정** 섹션은 Pod가 게시하는 포트, 컨테이너가 공유하는 네임스페이스, 네트워크, 호스트 이름, 레이블, 그리고 Podman이 보관한 경우 Pod를 만들 때 사용한 `podman pod create` 명령을 보여 줍니다.

## Pod 삭제

**삭제** 버튼은 먼저 확인을 요청하며, Pod와 함께 삭제되는 컨테이너 수를 알려 줍니다. 실행 중인 Pod는 먼저 중지되며, 이때 버튼에는 **중지 후 삭제** 문구가 표시됩니다. Pod의 볼륨은 유지됩니다.

## Pod 만들기

**새 Pod** 버튼(또는 Pod 페이지에서 `n` 키, 명령 팔레트의 **새 Pod** 항목)을 누르면 다음을 입력합니다.

- **이름** 필드: 문자, 숫자, `_`, `.`, `-`를 사용하며 문자나 숫자로 시작합니다.
- 게시할 **포트** 항목: 컨테이너 실행 대화 상자와 마찬가지로 호스트 포트를 컨테이너 포트에 연결합니다. 호스트 포트를 비워 두면 Podman이 사용 가능한 포트를 선택합니다.
- **레이블** 필드: 한 줄에 `key=value` 하나씩.

포트는 Pod에 속합니다. 포트는 Pod의 인프라 컨테이너에 게시되며, Pod 안에서 그 포트를 수신 대기하는 컨테이너에 전달됩니다. 새 Pod의 페이지가 열리며, 바로 그 안에서 컨테이너를 실행할 수 있습니다. Pod는 컨테이너를 하나 실행하기 전까지 자체 컨테이너가 없으며, Podman은 첫 번째 컨테이너와 함께 Pod를 시작합니다.

## Pod 안에서 컨테이너 실행

Podman 호스트에서는 **컨테이너 실행** 대화 상자에 **Pod** 필드가 있으며, Pod의 **컨테이너 실행** 버튼은 해당 Pod가 선택된 상태로 대화 상자를 엽니다. Pod 안의 컨테이너는 다음과 같습니다.

- Pod의 네트워크를 공유하므로 포트를 게시하거나 다른 네트워크에 참여할 수 없습니다. Pod를 선택하면 대화 상자에서 해당 필드가 숨겨집니다.
- Pod의 호스트 이름과 DNS 설정을 사용하므로 Homeport는 컨테이너 자체의 설정을 거부합니다.
- 그 밖에 실행 대화 상자가 제공하는 모든 것은 그대로 유지합니다. 명령, 환경, 마운트, 재시작 정책, 제한, capability, 장치, 헬스 체크, 로깅입니다.

복제와 편집은 컨테이너를 Pod 안으로 옮기지 않습니다. Podman은 기존 컨테이너를 Pod 안으로 옮길 수 없습니다.

## Homeport에 필요한 것

Pod는 Podman 4.0 이상에서, 로컬 소켓, SSH, TLS, TCP 등 모든 종류의 연결에서 작동합니다. 다른 모든 요청과 같은 소켓을 거치기 때문입니다.
