**설정** 페이지는 사이드바의 마지막 페이지이며, 그 아래에 브라우저에서 열리는 **문서**와 **GitHub** 링크가 있습니다.

## 모양

**테마** 항목의 기본값은 **시스템 설정에 맞춤** 옵션이며, 운영 체제의 라이트 모드나 다크 모드가 바뀌면 그대로 따라갑니다. 고정하려면 **라이트** 또는 **다크** 값을 고르세요.

**언어** 항목의 기본값은 **시스템 설정에 맞춤** 옵션입니다. Homeport는 운영 체제의 언어를 지원하면 그 언어로, 지원하지 않으면 영어로 표시됩니다. 이 선택지에는 **시스템 설정에 맞춤(Français)** 항목처럼 찾아낸 언어의 이름이 표시됩니다. 다른 언어를 쓰려면 그 언어를 고르세요. 다시 시작하지 않아도 창 전체가 즉시 바뀌며, 트레이 메뉴와 알림도 함께 바뀝니다.

Homeport는 영어, 프랑스어(Français), 스페인어(Español), 독일어(Deutsch), 이탈리아어(Italiano), 브라질 포르투갈어(Português), 러시아어(Русский), 중국어 간체(简体中文), 일본어(日本語), 한국어, 힌디어(हिन्दी), 아랍어(العربية)를 지원하며, 아랍어는 오른쪽에서 왼쪽으로 표시합니다. 지역 변형은 해당 언어를 따릅니다. 캐나다 프랑스어는 프랑스어로, 유럽 포르투갈어는 브라질 포르투갈어로 표시됩니다. 중국어 번체는 아직 지원하지 않으며 영어로 표시됩니다.

날짜, 숫자, 크기도 언어를 따르며, 시스템에 해당 언어의 지역 형식이 있으면 그 형식을 사용합니다. 예를 들어 영국 영어에서는 _1.5 GB_ 및 _4 Nov 2026_ 형식, 프랑스어에서는 _1,5 Go_ 및 _4 nov. 2026_ 형식으로 표시됩니다. 이름, ID, 명령, 로그, 엔진과 클러스터가 보내는 메시지는 그대로 유지되며, 오류의 **세부 정보** 항목에는 실패한 시스템이나 라이브러리의 원문이 그대로 남으므로 버그 보고서는 어느 언어에서나 똑같이 읽힙니다.

## 데스크톱

이 컴퓨터에서 Homeport가 실행되는 방식입니다.

- **닫으면 시스템 트레이로 이동** — 기본값은 꺼짐이므로 창을 닫으면 Homeport가 종료됩니다. 켜면 창을 닫을 때 대신 [시스템 트레이](/docs/guides/overview/#시스템-트레이)로 숨기며, Homeport는 호스트 연결을 연 채로 계속 실행됩니다. 트레이 아이콘이나 Homeport를 다시 실행해 창을 다시 표시하고, 트레이의 **종료** 항목으로 종료합니다. 트레이가 없는 데스크톱에서는 이 스위치가 설명과 함께 회색으로 비활성화됩니다.
- **로그인 시 시작** — 기본값은 꺼짐입니다. 켜면 로그인할 때 Homeport가 시작되어 처음부터 호스트를 지켜봅니다. 스위치는 시스템의 실제 상태를 보여 주므로, 직접 로그인 항목에서 Homeport를 삭제하면 꺼짐으로 표시됩니다. Windows에서는 **작업 관리자 → 시작 앱**, macOS에서는 **시스템 설정 → 일반 → 로그인 항목**, Linux에서는 `~/.config/autostart/`에 나열됩니다. AppImage의 항목은 파일을 옮기면 다음에 실행할 때부터 새 위치를 따릅니다.
- **트레이에 숨긴 채로 시작** — 기본값은 꺼짐이며, **로그인 시 시작** 옵션이 켜져 있을 때만 사용할 수 있습니다. 로그인 시 Homeport가 시작되면 창을 열지 않고 [시스템 트레이](/docs/guides/overview/#시스템-트레이)에 머뭅니다. Homeport를 직접 실행하면 언제나 창이 표시되며, 트레이가 없으면 언제나 창이 열립니다.

## 알림

Homeport는 창이 열려 있든, 최소화되어 있든, [트레이로 닫혀 있든](#데스크톱) 호스트에서 일이 생기면 운영 체제의 알림을 표시합니다. 종류마다 스위치가 있고 기본적으로 모두 켜져 있으며, 스위치는 즉시 적용됩니다.

| 스위치                                              | 예                                                                                                                    |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| **컨테이너가 오류로 중지되거나 메모리가 부족할 때** | _prod-server 호스트의 web-1 컨테이너가 중지되었습니다(종료 코드 137)_, _… 호스트의 db 컨테이너에 메모리가 부족합니다_ |
| **컨테이너가 비정상 상태가 될 때**                  | _prod-server 호스트의 api 컨테이너가 비정상 상태입니다_                                                               |
| **연결된 호스트에 연결할 수 없게 될 때**            | _prod-server 호스트에 연결할 수 없습니다: …_                                                                          |
| **연결할 수 없던 호스트가 다시 연결될 때**          | _prod-server 호스트에 다시 연결되었습니다._                                                                           |

Homeport의 **중지** 버튼, `docker stop`, `docker kill`, `docker compose down`으로 컨테이너를 중지하는 것은 비정상 종료가 아니므로 알림이 표시되지 않습니다. 종료 코드 0으로 끝난 컨테이너도 마찬가지입니다. Homeport를 시작할 때 연결에 실패한 호스트도 장애가 아니며, 연결되어 있던 호스트만 해당합니다. 다시 시작을 반복하는 컨테이너나 연결이 계속 끊기는 호스트는 최대 5분에 한 번만 알립니다.

알림은 Homeport가 이미 유지하는 연결에서 오므로 호스트에는 아무것도 설치되지 않으며, Homeport를 종료하면 알림도 멈춥니다. 알림의 모양과 표시 여부는 운영 체제가 결정합니다. 알림이 나타나지 않으면 운영 체제의 알림 설정에서 Homeport 항목을 확인하세요.

## 업데이트

- **자동으로 업데이트 확인** — 기본값은 켜짐입니다. Homeport는 시작할 때와 6시간마다 새 버전을 찾고, 새 버전이 있으면 창 위쪽에 표시줄을 보여 줍니다.
- **지금 확인** — 자동 확인이 꺼져 있어도 즉시 확인하고, 최신 버전인지 알려 줍니다.

업데이트가 있으면 카드에 할 수 있는 작업이 표시되며, 이는 Homeport를 설치한 방법에 따라 다릅니다.

- **Windows, macOS, AppImage** — **설치 후 다시 시작** 버튼은 업데이트를 다운로드하고, 서명을 확인하고, 설치한 다음 Homeport를 다시 엽니다.
- **`.deb` 및 `.rpm` 패키지** — 업데이트는 패키지 관리자가 설치하므로, 카드에 실행할 명령과 **명령 복사** 버튼이 표시됩니다.

**새로운 기능** 링크는 [변경 내역](/changelog/)을 엽니다. 자세한 내용은 [업데이트](/docs/reference/updating/)를 참고하세요.

## 레지스트리

Docker Hub, GitHub Container Registry(GHCR), 또는 직접 운영하는 컨테이너 레지스트리의 로그인으로, Homeport에 한 번만 보관하면 모든 호스트에서 사용됩니다. 이미지를 풀하거나, 아직 없는 이미지로 컨테이너를 실행하거나, 푸시, 빌드하거나, 관리형, 링크된, 동기화 스택을 배포할 때 사용됩니다. 로그인은 레지스트리 주소마다 하나입니다.

- **로그인 추가** 버튼을 누르면 **레지스트리**(`docker.io`, `ghcr.io`, `registry.example.com:5000`), **사용자 이름**, **비밀번호 또는 액세스 토큰** 항목을 입력합니다. GHCR과 2단계 인증을 사용하는 Docker Hub 계정에는 비밀번호 대신 액세스 토큰이 필요합니다.
- **로그인 확인** 버튼은 `docker login` 명령처럼, 아무것도 저장하지 않고 이 컴퓨터에서 레지스트리에 로그인을 받아들이는지 묻습니다. 로그인이 거부되면 힌트와 함께 그 사실을 알려 주고, Homeport가 레지스트리에 접근할 수 없으면 대신 그 사실을 알려 줍니다.
- **편집** 버튼은 주소나 사용자 이름을 변경합니다. 저장된 비밀번호를 유지하려면 비밀번호를 비워 두세요. **삭제** 버튼은 로그인을 잊으며, 그 레지스트리의 이미지는 다시 익명으로 풀됩니다.

Docker Hub는 `docker.io`, `index.docker.io`, `https://index.docker.io/v1/` 중 어느 것으로 입력해도 같은 레지스트리입니다. `nginx`나 `bitnami/redis`처럼 이름에 레지스트리가 없는 이미지는 Docker Hub 로그인을 사용합니다.

비밀번호와 토큰은 OS 키체인의 키로 암호화되며, 다시 표시되거나 로그에 기록되거나 오류 세부 정보에 들어가지 않습니다. 키체인이 없으면 카드에 로그인을 저장할 수 없다는 설명이 표시되고, 이미지는 익명으로 풀됩니다. [보안](/docs/reference/security/)을 참고하세요.

Homeport는 `~/.docker/config.json`이나 그 자격 증명 도우미를 읽지 않습니다.

## 저장소

[동기화 스택](/docs/guides/synced-stacks/)을 배포하는 git 저장소로, 한 번만 보관하면 모든 호스트에서 사용할 수 있습니다.

- **저장소 추가** 버튼을 누르면 저장소의 URL과 Homeport가 저장소에 접근하는 방법을 입력합니다. 해당 저장소용으로 Homeport가 만드는 **배포 키**(SSH URL), 사용자 이름과 함께 쓰는 **토큰**(HTTPS URL), 또는 누구나 읽을 수 있는 저장소라면 **공개** 중에서 고릅니다.
- 톱니바퀴 버튼은 저장소의 배포 키와 함께 GitHub, GitLab, Gitea, Forgejo에서 키를 추가할 위치를 보여 주며, 키를 교체하는 **새 키** 버튼이 있습니다. 토큰이라면 **토큰 교체** 버튼이 있습니다. **액세스 테스트** 버튼은 이 컴퓨터에서 저장소의 브랜치와 태그를 나열합니다. Homeport가 SSH 서버의 키를 신뢰한 뒤에는 그 지문이 이곳에 표시되며, 포지가 실제로 키를 바꾼 경우를 위한 **재설정** 버튼이 있습니다.
- **삭제** 버튼은 저장소를 잊고 이 컴퓨터에 있는 클론을 삭제합니다. 동기화 스택이 저장소를 사용하는 동안에는 거부됩니다.

키와 토큰은 OS 키체인의 키로 암호화되며, 다시 표시되거나 로그에 기록되거나 오류 세부 정보에 들어가지 않습니다. 사용자 자신의 git 구성, 자격 증명 도우미, SSH 키는 절대 사용하지 않습니다. [저장소](/docs/guides/synced-stacks/#저장소)를 참고하세요.

## 동기화 스택

**저장소 확인 주기** 항목은 Homeport가 동기화 스택의 저장소에서 새 커밋을 확인하는 간격을 분 단위로 정합니다. 기본값은 5분이고 최소 1분입니다. Homeport는 열려 있는 동안에만 확인하며, 닫혀 있는 동안에는 아무것도 동기화하지 않습니다. [폴링과 자동 배포](/docs/guides/synced-stacks/#폴링과-자동-배포)를 참고하세요.

## 데이터

Homeport가 이 컴퓨터에 보관하는 항목입니다.

### 백업과 복원

**백업…** 버튼은 모든 호스트, 클러스터, 스택, 레지스트리 로그인, 저장소, 설정을 해당 키, 인증서, 토큰, 비밀번호, 환경과 함께 `.homeport` 파일 하나에 저장합니다. 12자 이상의 암호 문구를 두 번 입력하세요. 파일 전체가 이 암호 문구로 암호화되며, 암호 문구는 복구할 수 없습니다. 엔진 이벤트와 배포 기록은 포함되지 않으며, 호스트나 클러스터에 있는 것도 포함되지 않습니다. 컨테이너, 이미지, 볼륨, Kubernetes 리소스는 있던 곳에 그대로 남습니다.

**복원…** 버튼은 이런 파일을 암호 문구로 열고 포함된 항목을 나열합니다. 호스트와 클러스터는 이름으로, 스택, 레지스트리 로그인, 저장소는 개수로 표시됩니다. 그런 다음 **모두 교체** 버튼을 누르면 이 컴퓨터나 다른 컴퓨터에서 Homeport의 모든 데이터가 백업의 데이터로 교체됩니다.

- 모든 항목이 즉시 연결되고 배포됩니다. SSH와 TLS 호스트, 레지스트리, 저장소는 키나 비밀번호를 다시 요청하지 않으며, 서버의 키를 다시 신뢰하라고 요청하지도 않습니다.
- 폴더가 이 컴퓨터에 없는 [링크된 스택](/docs/guides/stacks/#링크된-스택)은 같은 경로에 폴더가 생길 때까지 외부 스택으로 표시됩니다.
- [동기화 스택](/docs/guides/synced-stacks/)은 다음 동기화 때 저장소를 다시 클론합니다.
- 현재 데이터는 먼저 Homeport 데이터 폴더의 `homeport.db.before-restore-<date>`에 복사됩니다. 잘못된 파일, 더 새로운 Homeport의 파일을 복원하거나 복원이 중간에 실패하면 아무것도 바뀌지 않습니다.

기존 호스트에 일부 호스트만 추가하려면 대신 호스트 페이지의 **내보내기** 기능과 **가져오기** 기능을 사용하세요. Homeport의 파일이 어디에 있는지, 백업에 무엇이 들어가는지, 데이터베이스를 직접 복사하는 방법은 [데이터와 백업](/docs/reference/data-and-backups/)에서 설명합니다.

### 엔진 이벤트 보관

**엔진 이벤트 보관 기간** 항목은 각 호스트의 [엔진 이벤트](/docs/guides/overview/#이벤트)를 보관할 일수를 정합니다. 기본값은 30일이며 1일에서 365일까지 지정할 수 있습니다. 이 값과 관계없이 각 호스트는 최대 10,000개의 이벤트를 보관합니다. 오래된 이벤트는 Homeport를 시작할 때와 매시간 삭제되며, 값을 낮추면 즉시 삭제됩니다.

## 이 컴퓨터

Homeport가 이 컴퓨터에서 사용할 수 있는 항목입니다.

- **OS 키체인** — SSH 키, 인증서, 스택 환경, 레지스트리 로그인을 암호화해 저장할 수 있으면 **사용 가능**, 그렇지 않으면 **사용할 수 없음** 상태로 표시됩니다. [요구 사항](/docs/requirements/#선택-사항-os-키체인)을 참고하세요.
- **Compose CLI** — `docker compose v2.29.1`처럼 찾은 Compose 버전, 또는 스택을 시작하고 중지할 수는 있지만 배포할 수 없으면 **찾을 수 없음** 상태가 표시됩니다. [스택](/docs/guides/stacks/#배포에-필요한-것)을 참고하세요.
- **git** — `/usr/bin/git 2.43.0`처럼 찾은 git, 또는 동기화 스택을 사용할 수 없으면 설치할 항목이 표시됩니다. [요구 사항](/docs/requirements/#선택-사항-git)을 참고하세요.
- **Helm CLI** — `/usr/local/bin/helm v3.16.2`처럼 찾은 helm, 또는 [Helm 릴리스](/docs/clusters/helm/)를 나열하거나 설치할 수 없으면 이 시스템에 설치할 항목이 표시됩니다. Helm 2는 지원하지 않는 버전으로 표시됩니다. [요구 사항](/docs/requirements/#선택-사항-helm)을 참고하세요.

Homeport는 이 페이지가 열릴 때마다 CLI를 확인하므로, 실행한 뒤 설치한 CLI도 표시됩니다. 키체인을 설치한 뒤에는 Homeport를 종료했다가 다시 실행하세요.

## 정보

Homeport의 버전과 빌드 대상 플랫폼을 보여 줍니다. 예: `v1.0.0 · macos/aarch64`.

**로그 폴더 열기** 버튼은 Homeport가 [로그](/docs/reference/security/#로그)를 기록하는 곳을 보여 줍니다.

**진단 정보 내보내기…** 버튼은 [문제를 보고](https://github.com/DamienReichhart/Homeport/issues/new/choose)할 때 첨부할 zip을 저장합니다. 버전과 사용 중인 호스트 및 클러스터 종류의 요약, 그리고 비밀 정보를 제거한 로그가 들어 있습니다. 대화 상자가 먼저 내용을 보여 주며, 어디로도 아무것도 전송되지 않습니다. [진단 정보 내보내기](/docs/reference/troubleshooting/#버그-보고용-진단-정보-내보내기)를 참고하세요.

**라이선스** 항목은 Homeport의 라이선스(GNU AGPL 버전 3), 실행 중인 버전의 소스 코드 링크, 그리고 Homeport를 만드는 데 사용된 모든 오픈 소스 패키지의 고지 사항을 보여 줍니다.
