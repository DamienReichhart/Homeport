**이미지** 페이지는 선택한 호스트에 저장된 이미지를 전체 크기와 함께 나열합니다.

<DocScreenshot name="images" alt="이미지를 크기, 사용 여부와 함께 나열한 이미지 페이지." />

| 열         | 표시 내용                                                          |
| ---------- | ------------------------------------------------------------------ |
| **이름**   | 첫 번째 태그와 나머지 태그 수. 태그 없는 이미지는 `<none>`.        |
| **ID**     | 짧은 이미지 ID.                                                    |
| **생성일** | 이미지를 빌드한 지 얼마나 지났는지.                                |
| **크기**   | 디스크에서 차지하는 크기.                                          |
| **상태**   | 이미지로 만든 컨테이너 수와 함께 **사용 중**, 또는 **사용 안 함**. |

중지된 컨테이너도 이미지를 사용하는 것으로 간주합니다. 열 머리글을 선택하면 정렬되며, **이미지 검색** 필드로 검색할 수 있습니다.

이름 옆의 ⬆ 표시는 이미지의 태그 중 하나가 레지스트리에서 더 새로운 이미지를 가리킨다는 뜻입니다. 포인터를 올리면 어떤 태그인지 볼 수 있습니다. 새 이미지를 가져오려면 해당 태그를 풀하세요. **새 이미지 확인** 버튼은 6시간 동안 보관한 응답을 쓰는 대신 레지스트리에 다시 묻습니다. 확인 방식은 [새 이미지](/docs/guides/containers/#새-이미지)를 참고하세요.

## 이미지 풀

**이미지 풀** 버튼을 누르고 참조를 입력합니다. `nginx`(`nginx:latest`를 뜻함), `nginx:1.27`, `ghcr.io/org/app:v2`, `registry.example.com:5000/app`, 또는 `app@sha256:…` 같은 다이제스트를 입력할 수 있습니다.

Homeport는 풀 진행 상황을 레이어별로 보여 주며, 완료되면 **완료되었습니다.** 문구를 표시합니다. **취소** 버튼을 누르면 풀 진행 상황 추적을 멈춥니다.

### Docker Hub 검색

`postg`처럼 이름만 입력하면 입력하는 동안 Docker Hub를 검색하고, 일치하는 저장소를 설명, 별 수, **공식** 표시와 함께 나열합니다. 저장소를 고르면 태그가 크기, 푸시 시각과 함께 최신순으로 표시됩니다. **태그 필터** 필드로 목록을 좁히고(`alpine`), **태그 더 보기** 버튼으로 다음 페이지를 불러옵니다. 태그를 고르면 `postgres:17-alpine` 같은 참조가 채워져 바로 **풀** 버튼을 누를 수 있습니다.

검색은 선택한 호스트에서 실행되므로, 풀과 마찬가지로 호스트의 네트워크를 통해 Docker Hub에 접근합니다. 태그는 이 컴퓨터가 Docker Hub에서 읽으며, 저장된 Docker Hub [로그인](/docs/guides/settings/#레지스트리)이 있으면 요청 한도가 늘어납니다. 태그, 다이제스트, 다른 레지스트리(`ghcr.io/…`)를 입력하면 검색을 건너뛰며, Docker Hub에 접근할 수 없으면 대화 상자에 그 사실이 표시되지만 입력한 이미지는 그대로 풀합니다. 다른 레지스트리는 아직 검색할 수 없습니다.

### 비공개 이미지

[**설정 → 레지스트리**](/docs/guides/settings/#레지스트리)에 이미지의 레지스트리용 로그인이 저장되어 있으면, Homeport가 풀 요청과 함께 로그인을 엔진에 전달합니다. 따라서 로컬, TCP, TLS, SSH 등 어떤 호스트에서도 그곳에 아무것도 구성하지 않고 비공개 이미지를 풀할 수 있습니다. 대화 상자의 참조 아래에는 이미지를 풀하는 방식이 표시됩니다. 예: **ghcr.io에서 alice 사용자로 풀했습니다**, 일치하는 로그인이 없으면 **익명으로 풀했습니다**.

이름에 레지스트리가 없는 이미지(`nginx`, `bitnami/redis`)는 Docker Hub 로그인을 사용합니다. Docker Hub 로그인은 Docker Hub의 풀 한도도 늘려 줍니다.

레지스트리가 풀을 거부하면, 메시지에 해야 할 일이 표시됩니다. 저장된 로그인이 없으면 해당 레지스트리의 로그인을 추가하고, 있으면 저장된 로그인을 확인하세요.

<Aside>
  로그인은 요청과 함께 엔진으로 전달되며 호스트에 저장되지 않습니다. Homeport는
  `~/.docker/config.json`에서 `docker login` 자격 증명을 읽지 않습니다.
</Aside>

## 이미지 빌드

**빌드** 버튼을 누르고 이 컴퓨터에서 Dockerfile이 있는 **폴더**, 즉 빌드 컨텍스트를 고릅니다. Homeport는 폴더를 묶으면서 `.dockerignore`가 제외하는 항목을 빼고(Docker의 규칙: `*`, `**`, `!` 예외, 마지막으로 일치하는 줄이 우선), 선택한 호스트로 스트리밍하며, 그 호스트의 엔진이 빌드합니다. 같은 빌드가 SSH나 TLS를 통한 원격 호스트에서도, 그곳에 아무것도 설치하지 않고 작동합니다.

| 필드                     | 하는 일                                                                                       |
| ------------------------ | --------------------------------------------------------------------------------------------- |
| **Dockerfile**           | 폴더 안에서의 경로. 기본값은 `Dockerfile`. `.dockerignore`에 나열되어 있어도 항상 전송됩니다. |
| **대상 스테이지**        | 멀티 스테이지 Dockerfile에서 멈출 스테이지(`--target`).                                       |
| **이름**                 | `app:1.0, ghcr.io/me/app:1.0`처럼 결과에 붙일 하나 이상의 이름.                               |
| **빌드 인수**            | Dockerfile의 `ARG`에 쓸 `NAME=value`, 한 줄에 하나씩.                                         |
| **빌드 캐시 사용 안 함** | 모든 단계를 다시 실행합니다(`--no-cache`).                                                    |
| **새 기본 이미지 풀**    | 호스트에 있더라도 `FROM` 이미지를 풀합니다(`--pull`).                                         |

빌드 출력은 실시간으로 스트리밍되며, **취소** 버튼으로 중단할 수 있습니다. 빌드가 끝나면 이미지 페이지에 이름이 나타납니다. 단계가 실패하면 메시지에 그 단계가 표시되고(**빌드가 3/5단계(RUN make)에서 실패했습니다.**), **세부 정보** 항목에 출력의 마지막 부분이 들어 있습니다. 비공개 `FROM` 이미지는 저장한 [레지스트리 로그인](/docs/guides/settings/#레지스트리)으로 풀합니다.

<Aside>
  Homeport는 엔진 API가 제공하는 기존 빌더를 사용합니다. `RUN --mount`나 빌드 시크릿 같은 BuildKit
  기능은 사용할 수 없으므로, 이런 빌드는 터미널에서 하세요.
</Aside>

### 대신 컨테이너 커밋

이미지는 컨테이너에서 만들 수도 있습니다. 컨테이너의 **⋮** 메뉴에 있는 **이미지로 커밋…** 항목은 컨테이너의 파일과 설정을 현재 상태 그대로 저장합니다. [컨테이너 커밋](/docs/guides/containers/#컨테이너-커밋)을 참고하세요. 누군가 실행 중인 컨테이너 안에서 설치하거나 변경한 내용을 보존하는 빠른 방법입니다. 빌드는 오래 유지되는 방법입니다. Dockerfile에 이미지를 만드는 방법이 적혀 있으므로, 기본 이미지가 바뀌면 다시 빌드하고 검토하고 업데이트할 수 있습니다. 커밋한 이미지는 그럴 수 없습니다.

## 이미지 푸시

이미지의 **⋮** 메뉴에서 **푸시** 항목을 고릅니다. **푸시할 이름** 필드는 이미지의 첫 번째 이름으로 시작합니다. 이미지의 다른 이름을 고르거나 `ghcr.io/org/app:v2` 같은 새 이름을 입력하면, **태그** 기능처럼 이미지에 먼저 그 이름이 붙습니다. 이름의 첫 부분이 이미지를 보낼 레지스트리를 결정합니다. `ghcr.io/org/app`은 GHCR로, `org/app`은 Docker Hub로 갑니다.

Homeport는 해당 레지스트리용으로 저장된 [레지스트리 로그인](/docs/guides/settings/#레지스트리)을 사용해 호스트의 엔진을 통해 푸시하며, 이름 아래에 어떤 로그인인지 표시합니다(**ghcr.io에서 alice 사용자로 푸시했습니다**). 저장된 로그인이 없으면, 대부분의 레지스트리가 익명 푸시를 거부하므로 시작하기 전에 대화 상자가 경고합니다. 푸시하는 동안 대화 상자는 푸시한 레이어와 레지스트리에 이미 있던 레이어의 수를 세고, 진행 중인 업로드를 보여 줍니다. **취소** 버튼으로 푸시를 중단할 수 있습니다.

레지스트리가 거부하면, 메시지에 로그인을 추가해야 하는지, 아니면 저장된 로그인이 그 저장소에 푸시할 수 있는지 확인해야 하는지 표시됩니다.

## 이미지 저장과 불러오기

인터넷과 분리된 서버나 홈 네트워크의 Raspberry Pi처럼 레지스트리에 접근할 수 없는 호스트로 이미지를 옮기려면, 이미지를 이 컴퓨터의 파일로 저장한 다음 그 파일을 다른 호스트로 불러오세요.

- 이미지의 **⋮** 메뉴에 있는 **저장…** 항목은 이미지를 모든 이름과 함께, 직접 고른 `.tar` 파일 하나에 씁니다. 여러 이미지를 한꺼번에 저장하려면 목록에서 선택한 다음 페이지 위쪽의 **이미지 N개 저장…** 버튼을 누르세요.
- 페이지 위쪽의 **불러오기…** 버튼은 **저장…** 기능이나 `docker save`로 만든 `.tar` 파일(압축된 `.tar.gz` 포함)을 선택한 호스트로 읽어 들입니다. 완료되면 대화 상자에 불러온 이미지가 태그와 함께 표시됩니다.

파일은 호스트 자체의 연결을 통해 이 컴퓨터와 호스트 사이를 오가므로 원격 호스트에서도 작동합니다. 진행 상황에는 쓰거나 보낸 바이트가 표시됩니다. **취소** 버튼으로 중단할 수 있으며, 취소되거나 실패한 저장은 불완전한 파일을 남기지 않습니다. Homeport는 아카이브 전체를 메모리에 올리지 않으므로 수 기가바이트의 이미지도 문제없습니다.

### 파일 시스템 가져오기

페이지 위쪽의 **tar에서 가져오기…** 버튼은 `docker import`처럼 루트 파일 시스템의 tar를 이미지로 바꿉니다. 컨테이너의 [**파일 시스템 내보내기…**](/docs/guides/containers/#컨테이너의-파일-시스템-내보내기) 기능이나 `docker export`로 만든 tar, `debootstrap`이나 Buildroot의 출력, 공급업체 어플라이언스 등이 해당합니다. 파일(일반 파일 또는 gzip, xz, bzip2로 압축된 파일)을 고르고, 파일 이름에서 시작하는 이미지 **이름** 값을 지정하고, 필요하면 **변경 사항** 항목에 `CMD ["/bin/sh"]`나 `ENV LANG=C.UTF-8` 같은 Dockerfile 명령어를 입력합니다. 가져온 이미지에는 자체 명령이 없기 때문입니다. 진행 상황에는 보낸 바이트가 표시되며, 그런 다음 이미지가 목록에 나타납니다.

### 저장과 불러오기, 아니면 내보내기와 가져오기?

|        | **저장** / **불러오기**                | **파일 시스템 내보내기** / **tar에서 가져오기**                 |
| ------ | -------------------------------------- | --------------------------------------------------------------- |
| 시작점 | 하나 이상의 이미지                     | 컨테이너 하나의 현재 파일                                       |
| 유지   | 모든 레이어, 기록, 이름, 설정          | 레이어 하나로 평탄화된 파일만                                   |
| 손실   | 없음                                   | 기록, 이름, 그리고 명령과 환경 같은 설정                        |
| 용도   | 레지스트리 없는 호스트로 이미지 옮기기 | 컨테이너의 파일을 백업하거나 검사하기, 또는 rootfs에서 시작하기 |

## 이미지 다루기

- **▶ 실행** 버튼은 이미지가 채워진 [컨테이너 실행 대화 상자](/docs/guides/containers/#컨테이너-실행)를 엽니다.
- **검사** 항목(또는 행 선택)은 각 레이어를 만든 명령어와 크기를 보여 주는 **레이어** 탭과 **원본 JSON** 탭을 표시합니다.
- **태그** 항목은 `registry.example.com/app:v2` 같은 이름을 추가합니다. 아무것도 푸시하지 않으며, 푸시는 **푸시** 항목이 합니다.
- **삭제** 항목은 이미지와, 다른 이미지가 사용하지 않는 레이어를 삭제합니다. 태그가 여러 개인 이미지는 모든 태그를 잃습니다. 엔진은 컨테이너가 아직 사용하는 이미지의 삭제를 거부하므로, 먼저 컨테이너를 삭제하세요.

## 정리

**정리** 버튼은 두 가지 수준을 제공합니다.

- **댕글링 이미지** — 빌드와 풀 후에 남은 태그 없는 이미지. 안전하게 삭제할 수 있습니다.
- **사용하지 않는 모든 이미지** — 태그된 이미지를 포함해, 어떤 컨테이너도 사용하지 않는 모든 이미지. 다시 풀할 수 있지만 시간과 대역폭이 듭니다.

Homeport는 삭제한 이미지 수와 확보한 공간을 알려 줍니다. [개요 페이지의 정리](/docs/guides/overview/#정리) 기능은 중지된 컨테이너, 네트워크, 빌드 캐시, 볼륨도 한 번에 삭제할 수 있습니다.
