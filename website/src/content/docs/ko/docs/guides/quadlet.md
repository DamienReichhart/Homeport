Podman은 **Quadlet** 방식으로 systemd 아래에서 오래 실행되는 서비스를 실행합니다. Quadlet 유닛은 `web.container`, `shop.pod`, `cache.volume`, `lan.network`, `app.kube`, `base.image`, `api.build` 같은 파일이며, systemd의 생성기가 이를 `web.service` 같은 서비스로 바꿉니다. 이 서비스는 부팅할 때 컨테이너를 시작하고, 컨테이너가 중지되면 다시 시작합니다. rootful Podman은 유닛을 `/etc/containers/systemd/`에 보관하고, rootless Podman은 각 사용자의 유닛을 `~/.config/containers/systemd/`에 보관합니다.

**Quadlet** 페이지는 Podman 호스트를 선택한 동안 사이드바에 나타납니다. [ADR 0019](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0019-quadlet-units-through-podmans-api-and-systemctl.md)에서 정한 대로, 호스트가 이미 사용하는 소켓을 통해 Podman 자체 API를 사용하고, 시작과 중지에는 `systemctl`을 사용합니다.

## Podman 버전과 연결별로 가능한 작업

Podman의 API는 두 번의 릴리스에 걸쳐 Quadlet 지원을 갖추었으며, 유닛의 서비스를 시작하거나 중지하지는 않습니다. 따라서 Homeport가 할 수 있는 일은 호스트의 Podman 버전과 Homeport가 호스트에 연결하는 방식에 따라 다릅니다.

| 작업                         | Podman                   | 연결                       |
| ---------------------------- | ------------------------ | -------------------------- |
| 상태와 함께 유닛 나열        | 5.7 이상                 | 모두                       |
| 컨테이너로부터 유닛 나열     | 4.0~5.6                  | 모두                       |
| 유닛 파일 읽기               | 5.8 이상                 | 모두                       |
| 유닛 설치, 편집, 삭제        | 5.8 이상                 | 모두                       |
| 서비스 시작, 중지, 다시 시작 | Quadlet이 있는 모든 버전 | SSH 또는 Linux의 로컬 소켓 |

5.7 이전 Podman에서는 유닛이 만든 컨테이너에 Podman이 붙이는 `PODMAN_SYSTEMD_UNIT` 레이블로 유닛을 찾습니다. 따라서 유닛은 컨테이너를 만든 뒤에야 나타나며, 서비스 이름으로 표시됩니다. 페이지의 목록 위에 그 사실이 표시됩니다.

시작과 중지에는 `systemctl`이 필요하며, Homeport는 Podman이 실행되는 곳에서 이를 실행합니다. SSH 호스트라면 SSH 세션에서, Linux의 로컬 소켓이라면 이 컴퓨터에서 실행합니다. TCP나 TLS 호스트, 또는 macOS나 Windows의 로컬 소켓(Podman이 가상 머신에서 실행됨)에서는 그 밖의 모든 작업이 가능하며, 해당 버튼은 이유와 함께 비활성화됩니다.

## Quadlet 페이지

| 열           | 표시 내용                                                                                                                                      |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **유닛**     | 유닛의 파일 이름과, 함께 설치된 애플리케이션.                                                                                                  |
| **종류**     | `container`, `pod`, `volume`, `network`, `kube`, `image`, `build`, `artifact` 중 하나.                                                         |
| **서비스**   | 유닛이 생성하는 systemd 서비스. systemd가 로드하기 전까지는 **아직 생성되지 않음** 문구가 표시됩니다.                                          |
| **상태**     | systemd가 알려 주는 대로 **실행 중**, **시작하는 중**, **중지하는 중**, **중지됨**, **실패**, **systemd에 로드되지 않음**, **템플릿** 중 하나. |
| **컨테이너** | 유닛이 만든 컨테이너 수.                                                                                                                       |

각 행에는 중지된 유닛이면 **시작** 버튼, 실행 중인 유닛이면 **중지** 버튼이 있습니다. 유닛을 선택하면 해당 페이지가 열립니다. 유닛의 컨테이너가 시작하고 중지하면 목록이 저절로 갱신됩니다.

**systemd에 로드되지 않음** 상태인 유닛은 설치되어 있지만 systemd의 생성기가 건너뛴 것으로, 보통 파일에 실수가 있는 경우입니다. 호스트에서 `systemctl --user daemon-reload`(rootful Podman이면 `systemctl daemon-reload`)와 `journalctl`을 실행하면 그 이유를 알 수 있습니다.

**컨테이너** 페이지에서 유닛이 만든 컨테이너는 이름 옆에 유닛의 서비스를 표시합니다. 그 서비스를 선택하면 유닛이 열립니다.

## 유닛의 페이지

- 헤더에는 **시작**, **중지**, **다시 시작**, **편집**, **삭제** 버튼이 있습니다.
- **서비스** 섹션은 systemd 유닛, 그것이 시스템 유닛인지 사용자 유닛(`systemctl --user`)인지, 호스트에서 파일이 있는 위치, 그리고 있는 경우 애플리케이션과 Pod를 보여 줍니다.
- **유닛 파일** 섹션은 Podman이 읽는 그대로의 파일을 강조 표시와 함께 보여 줍니다.
- **컨테이너** 섹션은 유닛이 만든 컨테이너를 나열하며, 각 컨테이너를 선택하면 컨테이너 페이지가 열립니다.

컨테이너 페이지에서 유닛의 컨테이너를 중지하면 systemd와 충돌합니다. systemd가 `Restart=`에 따라 컨테이너를 다시 시작하기 때문입니다. 대신 유닛을 중지하세요.

## 유닛 설치

**새 유닛** 버튼(또는 Quadlet 페이지에서 `n` 키, 명령 팔레트의 **새 유닛** 항목)을 누르면 편집기가 열립니다. 고른 종류에 맞는 시작 내용이 들어 있거나, **파일 열기…** 버튼으로 이 컴퓨터에서 연 파일이 들어 있습니다. `web.container`처럼 확장자를 포함해 이름을 지정하세요. 파일에는 해당 종류의 섹션이 있어야 합니다. `.container` 파일이라면 `[Container]` 섹션입니다.

**파일 추가…** 버튼은 `podman quadlet install` 명령처럼, 유닛 이름을 딴 애플리케이션 폴더에 유닛과 함께 다른 파일(`.build`의 `Containerfile`, `.kube`의 YAML, env 파일)을 넣습니다.

Podman은 사용자의 유닛이 들어가는 위치에 파일을 쓰고 systemd를 다시 로드하므로 서비스가 바로 생깁니다. 설치한다고 서비스가 시작되지는 않습니다. 서비스가 생기면 **시작** 버튼을 누르세요. 이미 사용 중인 이름의 유닛은 거부됩니다. 대신 기존 유닛을 편집하세요.

## 편집과 삭제

**편집** 버튼은 유닛의 파일을 엽니다. **저장** 버튼은 파일을 그 자리에 쓰고 systemd를 다시 로드하며, 함께 설치된 파일은 유지됩니다. 실행 중인 서비스는 **다시 시작** 버튼을 누를 때까지 이전 설정을 유지합니다.

**삭제** 버튼은 유닛의 파일을 삭제하고 systemd를 다시 로드합니다. **먼저 실행 중인 서비스 중지** 옵션은 기본적으로 켜져 있으며, 이 옵션이 없으면 Podman은 실행 중인 유닛의 삭제를 거부합니다. 유닛이 만든 컨테이너, 볼륨, 이미지는 유지됩니다.

## Homeport가 호스트에서 실행하는 명령

**시작**, **중지**, **다시 시작** 작업에 한해서만, Homeport는 SSH 사용자의 권한으로 SSH를 통해 호스트의 서버에서(로컬 소켓이라면 이 컴퓨터에서) 명령 하나를 실행합니다.

```bash
systemctl --user start 'web.service'
```

`--user`는 rootless Podman의 유닛에만 붙고 rootful Podman의 유닛에는 빠집니다. `start`는 해당 작업에 따라 `stop` 또는 `restart`가 됩니다. Homeport는 서비스 이름을 확인하고 따옴표로 감싸며, `sudo`는 절대 사용하지 않습니다. 따라서 다음이 필요합니다.

- **시스템 유닛**(rootful Podman)에는 `root`처럼 시스템 유닛을 관리할 수 있는 SSH 사용자가 필요합니다.
- **사용자 유닛**(rootless Podman)에는 사용자의 systemd 인스턴스가 필요합니다. 로그인 세션 없이 실행되고 부팅할 때 유닛이 시작되게 하려면, 호스트에서 해당 사용자로 lingering을 한 번 활성화하세요.

```bash
loginctl enable-linger "$USER"
```

[보안 페이지](/docs/reference/security/#what-homeport-runs-on-your-hosts)에 Homeport가 호스트에서 실행하는 모든 명령이 나열되어 있습니다.
