## 볼륨

**볼륨** 페이지는 선택한 호스트의 볼륨과, 그중 사용하지 않는 볼륨의 수를 나열합니다.

<DocScreenshot
  name="volumes"
  alt="각 볼륨의 스택, 드라이버, 볼륨을 사용하는 컨테이너를 보여 주는 볼륨 페이지."
/>

| 열                     | 표시 내용                                                         |
| ---------------------- | ----------------------------------------------------------------- |
| **이름**               | 볼륨의 이름. 익명 볼륨은 긴 ID.                                   |
| **스택**               | 볼륨을 만든 스택(있는 경우).                                      |
| **드라이버**           | 보통 `local`.                                                     |
| **크기**               | `docker system df -v`가 알려 주는, 데이터가 차지하는 디스크 공간. |
| **사용 중인 컨테이너** | 볼륨을 마운트한 컨테이너, 또는 **사용 안 함**.                    |
| **생성일**             | 볼륨이 생성된 시각.                                               |

실행 중이든 중지되었든 어떤 컨테이너든 볼륨을 마운트하고 있으면 사용 중인 볼륨으로 간주합니다. 볼륨을 선택하면 크기, 볼륨을 사용하는 컨테이너, 그리고 호스트에서 데이터가 있는 위치(`Mountpoint`)를 포함한 전체 세부 정보를 볼 수 있습니다.

### 크기

엔진은 크기를 알려 주기 위해 모든 볼륨을 측정하는데, 데이터가 많은 호스트에서는 몇 초가 걸릴 수 있습니다. 그래서 목록은 바로 표시되고 **크기** 열은 나중에 채워집니다. 디스크를 가득 채운 볼륨을 찾으려면 **크기** 열로 정렬하세요. 크기는 볼륨을 만들거나 삭제할 때, 그리고 **크기 새로 고침** 버튼을 누를 때 다시 측정됩니다. 컨테이너가 쓸 때마다 측정하는 것은 아니므로 크기가 조금 늦게 반영될 수 있습니다.

`local` 드라이버의 볼륨만 크기가 있으며, 다른 드라이버(NFS, 클라우드 스토리지 플러그인)의 볼륨에는 **—** 기호가 표시됩니다.

### 볼륨의 파일 찾아보기

볼륨 행의 폴더 버튼을 누르면 볼륨의 파일이 열립니다. 폴더를 열고, 목록 위의 경로로 상위 폴더로 돌아가고, 파일을 다운로드하거나 폴더를 `.tar` 아카이브로 다운로드할 수 있습니다. 경로는 볼륨의 루트(`/`)에서 시작합니다.

찾아보기는 읽기 전용입니다. 컨테이너가 볼륨을 사용하는 중에도, 여기에서 하는 어떤 작업도 볼륨을 변경할 수 없습니다.

#### 도우미 컨테이너

엔진 API로는 볼륨을 읽을 수 없으므로, Homeport는 짧게 실행되는 **도우미 컨테이너** 하나로 볼륨을 엽니다. 네트워크가 없고 파일 시스템이 읽기 전용인 `busybox:1.37` 컨테이너로, 볼륨을 읽기 전용으로 마운트합니다. 브라우저를 닫거나 Homeport를 종료하면 Homeport가 즉시 이 컨테이너를 삭제합니다. Homeport가 삭제하지 못하면(Homeport가 비정상 종료되었거나 호스트가 사라진 경우) 도우미 컨테이너는 한 시간 안에 중지되어 엔진에 의해 삭제되며, 남은 것은 이 컴퓨터가 다음에 호스트에 연결할 때 Homeport가 삭제합니다. 도우미 컨테이너는 컨테이너 목록, 볼륨의 **사용 중인 컨테이너** 열, 이벤트 페이지에 절대 표시되지 않습니다.

호스트에 `busybox:1.37`(약 2MB)이 없으면 Homeport가 그 사실을 알리며, **busybox:1.37 풀** 버튼을 누를 때만 [레지스트리 로그인](/docs/guides/settings/#registries)을 사용해 이미지를 풀합니다. 작업이 끝나면 다른 곳에서 사용하지 않는 한 이미지를 다시 삭제합니다. 인터넷에 접근할 수 없는 호스트는 이미지를 풀할 수 없으므로 직접 가져다 놓으세요.

```sh
docker pull busybox:1.37
```

또는 이미지가 있는 머신에서 `docker save busybox:1.37 -o busybox.tar`를 실행하고, 파일을 복사한 다음, 호스트에서 `docker load -i busybox.tar`를 실행합니다.

<Aside>
  Windows 컨테이너를 실행하는 엔진은 도우미 컨테이너를 실행할 수 없으므로, 그 볼륨은 열 수 없습니다.
</Aside>

### 백업과 복원

볼륨 행의 **⋯** 메뉴에 있는 **파일로 백업…** 항목은 볼륨의 내용을 이 컴퓨터의 `.tar` 파일로 저장합니다. 아카이브에는 볼륨의 파일이 소유자와 권한을 유지한 채 루트 기준 상대 경로로 들어 있습니다. `tar -C <volume> -cf backup.tar .`로 만든 것과 같으므로 Homeport 없이도 열거나 복원할 수 있습니다.

**파일에서 복원** 기능은 백업을 복원합니다.

- 페이지 위쪽에서는 **새 볼륨**(이름을 바꾸지 않으면 파일 이름을 따름) 또는 직접 고른 **기존 볼륨** 중 하나로 복원합니다.
- 볼륨의 **⋯** 메뉴에서는 해당 볼륨으로 복원합니다.

기존 볼륨에 이미 파일이 있으면 Homeport는 그 파일을 삭제하고 백업의 파일로 바꾸기 전에 확인을 요청합니다. tar 아카이브가 아닌 파일은 아무것도 바뀌기 전에 거부됩니다.

백업과 복원 모두 진행 상황이 표시되며 취소할 수 있습니다. 취소된 백업은 파일을 남기지 않습니다. 취소된 복원은 볼륨을 일부만 쓴 상태로 남길 수 있으므로, 볼륨을 사용하기 전에 다시 복원하세요.

#### 볼륨을 사용하는 컨테이너

데이터베이스처럼 실행 중인 컨테이너가 쓰고 있는 볼륨의 백업은 일관성이 없을 수 있습니다. Homeport는 볼륨을 사용하는 실행 중인 컨테이너의 이름을 알려 주며, **그래도 백업** 버튼을 누르거나 백업하는 동안 컨테이너를 중지하도록 선택할 수 있습니다. 복원은 항상 컨테이너를 먼저 중지합니다. 어느 경우든 Homeport가 작업 후 컨테이너를 다시 시작합니다.

백업과 복원은 찾아보기와 같은 [도우미 컨테이너](#the-helper-container)를 사용하며, 백업할 때는 볼륨을 읽기 전용으로 마운트합니다. 아카이브는 호스트의 연결을 통해 전송되며 메모리에 통째로 올라가지 않으므로, 큰 볼륨과 원격 호스트에서도 작동합니다. 복원하는 볼륨 외에는 호스트에 아무것도 쓰지 않습니다.

### 볼륨 복제

볼륨 행의 **⋯** 메뉴에 있는 **복제…** 항목은 볼륨을 같은 호스트의 새 볼륨으로 복사합니다. 예를 들어 실제 데이터의 사본으로 마이그레이션이나 새 이미지 버전을 시험해 볼 때 사용합니다. 사본의 이름은 바꾸지 않으면 `<name>-copy`이며, 만들어지면 목록에서 선택됩니다.

파일의 소유자와 권한, 그리고 원본의 드라이버, 드라이버 옵션, 레이블을 유지합니다. 단, Compose의 레이블은 제외되므로 사본은 어떤 스택에도 속하지 않습니다. 원본은 [도우미 컨테이너](#the-helper-container)에 읽기 전용으로 마운트되며 절대 바뀌지 않습니다. 백업과 마찬가지로 Homeport는 원본을 사용하는 실행 중인 컨테이너의 이름을 알려 주며, 그대로 복사하거나 복사하는 동안 컨테이너를 중지할 수 있습니다.

디스크가 가득 차는 등 복사에 실패하면 Homeport가 불완전한 사본을 삭제하고 그 사실을 알리며, 오류는 **세부 정보** 항목에 표시됩니다. 볼륨을 다른 호스트로 복사하려면 [백업](#backing-up-and-restoring)한 다음 그 호스트에서 파일을 복원하세요.

### 볼륨 만들기

**볼륨 만들기** 버튼을 누르면 **이름** 항목과 선택 사항인 **드라이버** 항목(비워 두면 `local`)을 입력합니다.

### 볼륨 삭제

<Aside type="danger">볼륨을 삭제하면 그 안의 데이터가 영구적으로 삭제됩니다.</Aside>

각 행의 삭제 버튼은 확인을 요청하며, 볼륨을 아직 마운트하고 있는 컨테이너의 이름을 알려 줍니다. 엔진은 중지된 컨테이너라도 어떤 컨테이너가 사용하는 볼륨은 삭제를 거부합니다. 먼저 그 컨테이너를 삭제하세요.

**정리** 버튼은 여러 볼륨을 한꺼번에 삭제합니다.

- **사용하지 않는 익명 볼륨** — 어떤 컨테이너도 사용하지 않는 이름 없는 볼륨.
- **사용하지 않는 모든 볼륨** — 이름 있는 볼륨을 포함해, 어떤 컨테이너도 사용하지 않는 모든 볼륨.

## 네트워크

**네트워크** 페이지는 선택한 호스트의 네트워크를 나열하며, 기본 제공 네트워크 `bridge`, `host`, `none`이 먼저 표시됩니다.

<DocScreenshot
  name="networks"
  alt="기본 제공 네트워크와 스택 네트워크, 서브넷, 컨테이너 수가 표시된 네트워크 페이지."
/>

| 열           | 표시 내용                                                   |
| ------------ | ----------------------------------------------------------- |
| **이름**     | 해당하는 경우 **기본 제공** 또는 **내부** 배지가 함께 표시. |
| **스택**     | 네트워크를 만든 스택(있는 경우).                            |
| **드라이버** | `bridge`, `overlay`, `macvlan`…                             |
| **서브넷**   | IP 범위.                                                    |
| **컨테이너** | 연결된 컨테이너 수(실행 중이거나 중지된 컨테이너 모두).     |

### 컨테이너 연결

네트워크를 선택하면 연결된 컨테이너를 볼 수 있습니다. 직접 만든 네트워크에서는 다음을 할 수 있습니다.

- **연결 해제** 버튼은 컨테이너를 분리합니다.
- **컨테이너 연결…** 목록에는 아직 연결되지 않은 컨테이너가 나열됩니다. 하나를 고르고 **연결** 버튼을 누르세요.

기본 제공 네트워크는 여기에서 변경할 수 없습니다.

### 네트워크 만들기

**네트워크 만들기** 버튼을 누르면 **이름**, **드라이버**(비워 두면 `bridge`), 그리고 선택 사항인 **서브넷** 및 **게이트웨이** 항목을 입력합니다. 비워 두면 엔진이 정합니다. 스위치는 두 가지입니다.

- **내부** — 네트워크의 컨테이너가 외부 네트워크에 접근할 수 없습니다.
- **연결 가능** — 독립 실행형 컨테이너가 `overlay` 네트워크에 참여할 수 있습니다.

### 네트워크 삭제

기본 제공 네트워크는 삭제할 수 없습니다. 다른 네트워크는 확인 창에 아직 연결된 컨테이너 수가 표시되며, 엔진은 실행 중인 컨테이너가 있는 네트워크의 삭제를 거부합니다. 삭제된 네트워크를 이름으로 참조하는 컨테이너는 그 네트워크가 다시 생길 때까지 시작되지 않습니다.

**정리** 버튼은 연결된 컨테이너가 없는 모든 사용자 지정 네트워크를 삭제합니다.
