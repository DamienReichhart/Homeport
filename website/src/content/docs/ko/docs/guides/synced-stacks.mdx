import { Aside, Steps } from '@astrojs/starlight/components';

**동기화 스택** 유형은 compose 파일을 git 저장소에서 가져오는 [스택](/docs/guides/stacks/)입니다. Homeport는 이 컴퓨터에 저장소를 클론하고, 요청할 때(또는 Homeport가 열려 있는 동안 일정 간격으로) 브랜치나 태그를 가져와 무엇이 바뀌었는지 보여 준 다음, 새 커밋을 호스트에 배포합니다. 편집, 커밋, 푸시는 절대 하지 않으며, 변경은 git을 통해 이루어집니다.

<Aside type="note" title="Homeport에는 git이 필요합니다">
  동기화 스택은 이 컴퓨터에 설치된 `git`을 실행합니다. **설정 → 이 컴퓨터** 항목에서 Homeport가
  git을 찾았는지, 찾지 못했다면 설치 방법은 무엇인지 확인할 수 있습니다. 다른 종류의 스택은 모두 git
  없이 작동합니다.
</Aside>

## 저장소

Homeport는 **설정 → 저장소** 항목이나 **새 스택** 페이지에서 추가한 저장소를 읽습니다. 저장소는 한 번만 추가하면 모든 호스트의 동기화 스택에서 사용할 수 있습니다. Homeport는 다음 세 가지 방법 중 하나로 저장소에 접근합니다.

| 액세스      | URL                                                 | Homeport가 저장하는 것                   |
| ----------- | --------------------------------------------------- | ---------------------------------------- |
| **배포 키** | SSH: `git@github.com:owner/repo.git` 또는 `ssh://…` | 이 저장소 전용으로 만든 키(**암호화됨**) |
| **토큰**    | HTTPS: `https://gitlab.com/owner/repo.git`          | 사용자 이름과 액세스 토큰(**암호화됨**)  |
| **공개**    | HTTPS, 누구나 읽을 수 있는 저장소                   | 비밀 정보 없음                           |

`http://`와 로컬 경로는 허용되지 않으므로 토큰이 평문으로 전송되는 일은 없습니다.

### 배포 키 사용

<Steps>

1. **저장소 추가** 버튼을 누르고, 저장소의 SSH URL을 붙여 넣고, **배포 키** 옵션을 그대로 둔 채 **추가하고 배포 키 만들기** 버튼을 누릅니다.

2. Homeport가 보여 주는 키를 복사해 저장소에 **읽기 전용 액세스** 권한으로 추가합니다.
   - GitHub: 저장소의 **Settings → Deploy keys → Add deploy key**.
   - GitLab: 프로젝트의 **Settings → Repository → Deploy keys**.
   - Gitea 및 Forgejo: 저장소의 **Settings → Deploy keys → Add deploy key**.

3. **액세스 테스트** 버튼을 누릅니다. Homeport가 이 컴퓨터에서 저장소의 브랜치와 태그를 나열합니다.

</Steps>

저장소마다 자체 키가 있으므로 키가 유출되어도 그 저장소 하나만 읽을 수 있으며, 사용자 자신의 SSH 키와 `~/.ssh/config`는 절대 사용하지 않습니다. **새 키** 버튼은 키를 교체합니다. 새 키를 저장소에 추가하고, 저장소에서 이전 키를 삭제하세요.

Homeport가 SSH 서버에 처음 접근하면, `ssh`처럼 서버가 제시하는 키를 신뢰하고 기억합니다. 나중에 키가 바뀌면, 포지의 웹사이트에서 새 지문을 확인하고 신뢰하는 키 옆의 **재설정** 버튼을 누를 때까지 모든 가져오기가 실패합니다.

### 토큰 사용

저장소의 `https://` URL을 붙여 넣고 **토큰** 옵션을 고른 다음, 사용자 이름과 저장소 내용을 읽을 수 있는 액세스 토큰을 입력합니다. GitHub에서는 **Contents: Read-only** 권한이 있는 세분화된 토큰, GitLab에서는 `read_repository` 권한이 있는 프로젝트 토큰이나 개인 토큰입니다. **액세스 테스트** 버튼으로 확인합니다. 토큰이 만료되면 **토큰 교체** 항목에서 새 토큰을 입력하세요.

<Aside type="tip">
  OS 키체인이 없으면 Homeport는 배포 키나 토큰을 저장할 수 없으므로 공개 저장소만 추가할 수
  있습니다. [요구 사항](/docs/requirements/#선택-사항-os-키체인)을 참고하세요.
</Aside>

저장소를 삭제하면 그 키나 토큰과 이 컴퓨터의 클론이 삭제됩니다. 동기화 스택이 저장소를 사용하는 동안에는 거부됩니다.

## 동기화 스택 만들기

<Steps>

1. 배포할 호스트에서 **스택** 페이지를 열고 **새 스택** 버튼을 누른 다음 **git 저장소 사용** 항목을 고릅니다.

2. **저장소** 항목을 고르거나, **저장소 추가** 버튼을 눌러 그 자리에서 저장소를 추가합니다.

3. **브랜치** 또는 **태그** 값을 고릅니다. Homeport는 저장소 서버에서 브랜치와 태그를 가져와 나열하며, 기본 브랜치를 먼저 표시합니다.

4. 저장소 루트 기준 **Compose 파일** 경로를 입력합니다. `compose.yaml` 또는 `deploy/prod/compose.yaml` 등입니다. 이 파일의 폴더가 프로젝트 폴더가 되므로, 파일 안의 `build:`, `env_file:`, 상대 경로는 직접 클론했을 때처럼 작동합니다.

5. **이름** 항목(저장소 이름에서 가져옴)을 확인하고, 비밀번호처럼 git에 넣으면 안 되는 값은 **환경** 항목에 추가합니다. `KEY=value` 형식의 줄로 입력하며, 이 컴퓨터에 암호화되어 저장되고 배포할 때 Compose에 변수로 전달됩니다.

6. **저장 후 배포** 버튼을 누릅니다. 나중에 배포하려면 **저장** 버튼을 누르세요.

</Steps>

Homeport는 무언가를 저장하기 전에 브랜치나 태그를 가져와 compose 파일을 읽으므로, 잘못된 경로, 브랜치, 태그, 또는 Compose가 배포할 수 없는 파일은 즉시 보고됩니다. 스택은 첫 배포 전까지 **동기화** 및 **배포되지 않음** 상태로 나열됩니다. **정의** 탭에는 저장소, 브랜치 또는 태그, compose 파일, 배포한 커밋이 표시됩니다.

저장소는 이 컴퓨터의 Homeport 데이터베이스 옆 `repositories` 폴더에 한 번만 클론되며, 그 저장소로 만든 모든 동기화 스택이 함께 사용합니다. 각 동기화 스택은 같은 위치의 `synced-stacks` 폴더에 있는 자체 커밋 체크아웃에서 배포하며, 이 체크아웃은 배포 사이에도 그대로 유지됩니다. 컨테이너가 상대 바인드 마운트를 통해 쓴 파일은 원래 자리에 남습니다. 저장소의 심볼릭 링크는 일반 파일로 체크아웃되므로, compose 파일이 Compose에게 이 컴퓨터의 다른 위치에 있는 파일을 가리키게 할 수 없습니다. 파일은 Windows에서도 저장소에 들어 있는 줄 끝 문자를 유지하므로, Linux 이미지에 복사한 스크립트도 그대로 실행됩니다. 줄 끝 문자는 저장소 자체의 `.gitattributes`만 바꿀 수 있습니다.

동기화 스택은 대신 [Swarm](/docs/guides/swarm/)에 배포할 수도 있습니다. **새 스택** 페이지의 **배포 대상** 항목에서 Swarm을 고르세요. 동기화, 배포, 자동 배포는 같은 방식으로 이루어지며, `docker stack deploy`가 체크아웃에서 실행됩니다. 무엇이 달라지는지는(무엇보다 `build:`) [Swarm의 링크된 스택과 동기화 스택](/docs/guides/swarm/#swarm의-링크된-스택과-동기화-스택)을 참고하세요.

**잊기** 버튼을 누르면 Homeport가 저장소 추적을 중단합니다. 컨테이너는 계속 실행되고 스택은 외부 스택이 됩니다. 컨테이너가 체크아웃 안에 파일을 쓰지 않았다면 체크아웃은 삭제되며, 저장소의 클론은 그 저장소를 사용하는 동기화 스택이 없어지면 삭제됩니다. 저장소는 **설정 → 저장소** 항목에 그대로 남습니다.

## 동기화

동기화 스택의 행이나 페이지에서 **동기화** 버튼을 누릅니다. Homeport는 브랜치나 태그를 가져온 다음, 아무것도 하기 전에 배포하면 무엇이 바뀌는지 보여 줍니다.

- 배포된 커밋 이후 compose 파일의 폴더에서 무언가를 바꾼 **새 커밋** 목록과, 각 커밋의 작성자 및 작성 시각
- 그 폴더에서 **변경된 파일** 각각(compose 파일 먼저). 삭제된 줄은 취소선으로, 그 줄을 대체한 줄 위에 표시됩니다. 텍스트가 아닌 파일은 이름만 표시됩니다.

**배포** 버튼을 누르면 바로 그 커밋을 배포합니다. Homeport는 스택의 체크아웃에서 커밋을 체크아웃하고 compose 파일의 폴더에서 `docker compose up`을 실행하며, `build:`가 있는 서비스를 다시 빌드하므로 변경된 `Dockerfile`이 적용됩니다. 출력은 실행되는 동안 스트리밍되며, 배포는 커밋과 함께 스택의 **기록** 탭에 기록됩니다.

- 저장소의 다른 곳에 있는 문서처럼 compose 파일의 폴더에서 아무것도 바꾸지 않은 푸시에는 **최신 상태** 문구가 표시됩니다. **그래도 다시 배포** 버튼을 누르면 그래도 배포합니다.
- Homeport가 마지막으로 가져왔을 때와 다른 커밋을 태그가 가리키고 있으면, 검토 화면에서 먼저 그 사실을 알려 줍니다.
- 가져오기가 실패하거나(배포 키가 삭제되었거나 서버에 접근할 수 없는 경우) 배포가 실패하면, Homeport가 이유와 해결 방법을 보여 주며 스택은 배포된 커밋을 유지합니다.

**다시 배포** 버튼은 환경이나 프로필에서 무엇이 바뀌었는지 보여 준 다음, 현재 배포된 커밋을 다시 배포합니다. 한 번도 배포되지 않은 스택의 **배포** 버튼은 스택을 만들 때 가져온 커밋을 배포합니다. 동기화 스택은 Homeport에서 롤백할 수 없습니다. 저장소에서 변경을 되돌리거나 스택이 이전 태그를 가리키게 한 다음 동기화하세요.

## 폴링과 자동 배포

<Aside type="caution" title="Homeport가 열려 있는 동안에만">
  Homeport는 열려 있는 동안에만 저장소를 확인합니다. **닫혀 있는 동안에는 아무것도 동기화되지
  않습니다**. Homeport는 서버에 아무것도 설치하지 않으므로 서버에 에이전트도 웹훅도 없습니다. 다시
  열면 첫 확인 전에 한 간격만큼 기다립니다.
</Aside>

Homeport가 열려 있는 동안에는 각 동기화 스택의 브랜치나 태그를 일정 간격으로 가져옵니다. 기본값은 5분마다이며, **설정 → 동기화 스택** 항목에서 정합니다(최소 1분). 각 저장소는 사용하는 스택 수와 관계없이 한 회차에 한 번만 가져오며, 계속 실패하는 저장소는 점점 덜 자주, 최대 한 시간에 한 번까지 시도합니다.

새 커밋이 compose 파일의 폴더를 바꾸면, 목록과 스택 페이지에 **업데이트 있음** 표시가 나타납니다. **동기화** 버튼은 무엇이 바뀌었는지 보여 주고 배포합니다. 스택의 **정의** 탭에는 **마지막 확인** 시각과, 마지막 확인이 실패했다면 그 이유가 표시됩니다.

**정의** 탭의 스위치 두 개가 스택별로 이를 제어합니다.

- **새 커밋 확인** — 기본값은 켜짐입니다. 끄면 **동기화** 버튼을 누를 때만 동기화합니다.
- **새 커밋 자동 배포** — 기본값은 꺼짐입니다. 켜면 Homeport는 새 커밋을 발견하는 즉시 **무엇이 바뀌었는지 먼저 보여 주지 않고** **동기화** 기능과 같은 단계로 배포합니다. 배포는 **기록** 탭에 자동 배포로 기록되며, 완료되면 알림이 표시됩니다. 호스트에 접근할 수 없는 동안에는 기다립니다. 실패하면 Homeport가 이유를 보여 주며 그 커밋을 다시 시도하지 않습니다. 다음 커밋이나 직접 배포하는 **동기화** 작업이 다시 시도합니다.

## 동기화 스택을 편집할 수 없는 이유는?

저장소가 동기화 스택의 정의가 있는 유일한 곳이기 때문입니다. Homeport가 compose 파일을 바꾸면 다음 동기화가 그 변경을 덮어쓰거나 충돌하게 되며, 저장소를 읽는 사람은 무엇이 배포되어 있는지 알 수 없게 됩니다. 그래서 동기화 스택의 **정의** 탭은 가져온 커밋의 compose 파일을 **읽기 전용** 모드로 보여 주며(선택하고 복사할 수는 있음), 폴더의 다른 파일을 나열하고, 각 파일을 GitHub, GitLab, Gitea, Forgejo의 해당 페이지로 연결합니다. 그곳에서 변경하고 푸시한 다음 **동기화** 버튼을 누르세요.

Homeport가 보유하는 항목은 같은 탭에서 계속 편집할 수 있습니다.

- git에 넣으면 안 되는 값을 위한 **환경** 항목(이 컴퓨터에 암호화되어 저장)
- compose 파일에 프로필이 선언되어 있다면 **프로필** 항목
- **새 커밋 확인** 여부와 **새 커밋 자동 배포** 여부

**잊기** 버튼을 누르면 Homeport가 저장소 추적을 중단합니다. 스택의 컨테이너는 계속 실행되며, 스택은 외부 스택이 됩니다.
