클러스터 사이드바의 **Helm** 페이지에는 그 클러스터의 [Helm](https://helm.sh) 릴리스가 표시됩니다. Homeport에서 설치했는지와 관계없이, 터미널에서 `helm list`가 보여 주는 것과 같은 릴리스입니다.

## Homeport에 필요한 것

Homeport는 **이** 컴퓨터에서 버전 3 이상의 `helm` 명령을 실행합니다. macOS에서는 `brew install helm`으로, Windows에서는 `winget install Helm.Helm`(또는 Chocolatey나 Scoop)으로, Linux에서는 `snap install helm --classic`, 배포판의 패키지 또는 helm.sh의 스크립트로 설치하세요. **설정 → 이 컴퓨터** 화면에 Homeport가 찾은 helm이 표시됩니다. helm이 없으면 Helm 페이지에 시스템에 맞는 설치 방법이 표시되며, 클러스터의 다른 페이지는 모두 작동합니다.

Homeport는 helm에 kubeconfig를 넘기지 않습니다. helm 명령마다 이 컴퓨터의 루프백 주소에 클러스터로 가는 전용 연결을 열고, 그 연결을 가리키는 임시 kubeconfig를 helm에 줍니다. 이 kubeconfig에는 일회용 토큰만 있고 클러스터 자격 증명은 없습니다. 다른 모든 페이지와 마찬가지로 Homeport가 중간에서 각 요청에 클러스터 자체의 자격 증명(인증서, 토큰, exec 플러그인의 토큰)을 추가하며, 명령이 끝나면 kubeconfig를 삭제합니다. 따라서 helm은 exec 플러그인을 쓰는 클라우드 클러스터를 포함해 Homeport가 연결하는 모든 클러스터에 연결할 수 있고, 어떤 자격 증명도 디스크에 기록되지 않습니다.

Helm은 릴리스를 각 릴리스의 Namespace에 Secret으로 보관합니다. Homeport는 클러스터에 아무것도 설치하지 않습니다.

## 릴리스

목록에는 각 릴리스의 이름, Namespace, 차트와 차트 버전, 앱 버전, 리비전, 상태, 마지막 변경 시각이 표시됩니다. 오른쪽 위에서 Namespace 하나 또는 전체를 고르세요. helm에는 실시간 업데이트가 없으므로 목록이 열려 있는 동안 30초마다 다시 조회하며, **새로 고침** 버튼을 누르면 즉시 조회합니다.

**실패한** 릴리스는 빨간색으로, 설치, 업그레이드, 롤백이 **대기 중인** 릴리스(`pending-install`, `pending-upgrade`, `pending-rollback`)는 주황색으로 표시됩니다. 대기 중인 릴리스는 그 작업이 끝날 때까지 잠깁니다.

자격 증명으로 모든 Namespace의 Secret 목록을 볼 수 없으면, Homeport는 대신 클러스터 기본 Namespace의 릴리스를 나열하고 그 사실을 알려 줍니다. 다른 Namespace를 선택하면 그 Namespace의 릴리스를 볼 수 있습니다.

## 차트 설치

릴리스 탭의 **차트 설치** 버튼(또는 <kbd>n</kbd>)은 선택한 클러스터에 차트를 설치합니다.

1. **차트를 고릅니다.** helm [저장소](#chart-repositories)의 차트를 검색하여 **사용** 버튼을 클릭하거나, **OCI 레지스트리에서** 항목 아래에 `oci://registry-1.docker.io/bitnamicharts/nginx` 같은 참조를 입력합니다. 이 경우 저장소를 추가하지 않고 설치합니다.
2. **버전, 이름, Namespace를 정합니다.** 저장소 차트는 버전이 최신순으로 나열되고, OCI 차트는 버전을 직접 입력하거나 비워 두면 최신 버전이 됩니다. 릴리스 이름은 처음에 차트 이름을 따르며, 소문자, 숫자, 대시, 점으로 최대 53자입니다. Namespace는 페이지에 표시된 Namespace(또는 클러스터의 기본 Namespace)이며, 체크를 해제하지 않으면 없을 때 새로 만듭니다.
3. **값을 편집합니다.** 편집기는 차트의 기본값(`helm show values`)으로 시작합니다. 필요한 부분을 바꾸고, **차트 기본값으로 재설정** 버튼으로 되돌릴 수 있습니다. 값은 helm이 실행되기 전에 YAML로 검사되며, 파일이 아니라 표준 입력으로 helm에 전달됩니다.
4. 필요하면 **미리 보기** 단계를 실행합니다. helm이 클러스터의 도움(`--dry-run=server`)을 받아 값으로 차트를 렌더링하고, Homeport가 적용될 매니페스트(훅 포함)와 차트의 노트를 보여 줍니다. 클러스터에서는 아무것도 바뀌지 않습니다.
5. **설치합니다.** `helm install`이 출력하는 대로 helm의 출력이 스트리밍됩니다. **리소스가 준비될 때까지 대기** 옵션을 켜면 helm이 릴리스의 Deployment, Pod, Service가 준비될 때까지 지정한 시간(기본 5분)만큼 기다리며, 준비되지 않으면 릴리스를 실패로 표시합니다. 그다음 **릴리스 열기** 버튼으로 릴리스 페이지를 엽니다.

로컬 폴더나 `.tgz` 파일의 차트는 Homeport에서 설치하지 않습니다. 로그인이 필요한 OCI 레지스트리의 차트도 터미널에서 `helm registry login`으로 로그인하지 않았다면 설치하지 않습니다.

## 릴리스 페이지

릴리스를 클릭하면 열립니다.

- **기록**: 모든 리비전이 최신순으로, 날짜, 상태, 차트, 앱 버전, 그리고 무슨 일이 있었는지에 대한 helm의 설명(`Install complete`, `Upgrade "web" failed: …`)과 함께 표시됩니다.
- **값**: 설치나 업그레이드 때 지정한 값(**사용자 지정**), 또는 기본값을 포함해 차트 렌더링에 쓰인 모든 값(**차트 기본값을 포함한 계산 결과**).
- **노트**: 설치 후 차트가 출력하는 내용(`NOTES.txt`).
- **매니페스트**: 리비전이 렌더링한 Kubernetes 객체를 YAML로 표시합니다.
- **리소스**: 그 객체를 종류, 이름, Namespace별로 보여 주며, 각 객체는 Homeport 안의 페이지로 연결됩니다. Deployment, Pod, Service 등은 전용 페이지로, 나머지는 [API 리소스](/docs/clusters/api-resources/) 아래의 페이지로 연결됩니다.

값, 노트, 매니페스트, 리소스 탭은 현재 리비전을 보여 줍니다. 그 위에서 이전 리비전을 고르면 그 리비전이 무엇으로 설치되었는지 볼 수 있습니다.

## 릴리스 업그레이드

릴리스 페이지의 **업그레이드** 버튼은 차트 버전, 값 또는 둘 다를 바꿉니다.

- **차트**: 업그레이드에 쓸 차트입니다. helm은 차트의 출처를 기록하지 않으므로, Homeport는 저장소에서 같은 이름의 차트를 찾으며 릴리스의 현재 버전이 있는 저장소를 먼저 고릅니다. **다른 차트…** 버튼으로 `repository/chart` 또는 `oci://` 참조를 지정해 다른 차트를 고를 수 있으며, OCI 레지스트리에서 설치한 릴리스에는 이 방법이 필요합니다.
- **차트 버전**: 그 차트의 버전이 최신순으로 표시되며, OCI 차트는 직접 입력합니다.
- **값**: 편집기는 릴리스의 사용자 지정 값으로 시작합니다. 이 값이 릴리스의 값을 대체하며, 나머지는 차트의 기본값으로 채워집니다. **값 변경 사항** 항목은 현재 값과 나란히 보여 주고, **현재 값으로 재설정** 버튼으로 되돌릴 수 있습니다.
- **리소스가 준비될 때까지 대기**: 지정한 시간만큼 기다립니다.

**미리 보기** 버튼은 아무것도 바꾸지 않고 클러스터의 도움을 받아 업그레이드를 렌더링하며, 새 매니페스트와 현재 매니페스트 대비 바뀌는 내용을 보여 줍니다. **업그레이드** 버튼은 helm의 출력을 실시간으로 보여 주며 `helm upgrade`를 실행합니다. 업그레이드할 때마다 **기록** 탭에 새 리비전이 생깁니다.

## 롤백

**기록** 탭에서 이전 리비전의 **N번 리비전으로 롤백** 버튼을 누르면, 현재와 롤백 후의 차트 및 앱 버전을 밝히며 먼저 확인을 요청한 다음 `helm rollback`을 실행합니다. helm은 그 리비전의 차트와 값을 새 리비전으로 되살리므로, 롤백 자체도 다시 롤백할 수 있습니다. **리소스가 준비될 때까지 대기** 옵션에 체크하면 helm이 리소스를 기다립니다.

설치, 업그레이드, 롤백이 중단되어 **대기 중** 상태로 멈춘 릴리스는 잠겨 있습니다. helm은 그 작업이 끝날 때까지 릴리스 변경을 거부합니다. 마지막으로 배포된 리비전으로 롤백하면 잠금이 풀립니다.

## 제거

릴리스 페이지의 **제거** 버튼은 `helm uninstall`을 실행하기 전에 릴리스, 그 Namespace와 클러스터를 밝히고 함께 삭제될 객체를 나열합니다. 차트가 유지하도록 표시한 객체(`helm.sh/resource-policy: keep`)와 StatefulSet의 PersistentVolumeClaim은 클러스터에 남습니다. **롤백할 수 있도록 기록 유지** 옵션을 켜면 릴리스가 `uninstalled` 상태로 목록에 남아 롤백할 수 있고, 끄면 릴리스가 목록에서 사라집니다. **객체가 삭제될 때까지 대기** 옵션을 켜면 helm이 객체 삭제를 기다립니다.

## 차트 저장소

Helm 페이지의 두 번째 탭인 **차트 저장소** 탭에는 이 컴퓨터의 helm이 아는 저장소가 나열됩니다. 터미널의 `helm repo list`와 같은 목록이며, 모든 클러스터가 공유합니다. Homeport는 자체 목록을 두지 않으므로, 터미널에서 추가한 저장소가 여기에 표시되고 여기서 추가한 저장소가 `helm repo list`에 표시됩니다.

- **저장소 추가** 버튼은 이름(문자, 숫자, 점, 대시, 밑줄)과 `https://charts.bitnami.com/bitnami` 같은 저장소의 `https://` URL을 묻고 인덱스를 다운로드합니다.
- **모두 업데이트** 버튼, 또는 저장소 하나의 **업데이트** 버튼은 `helm repo update`처럼 최신 인덱스를 다운로드하며, helm의 출력을 실시간으로 보여 줍니다. 마지막 업데이트 이후 게시된 차트는 업데이트한 다음에야 표시됩니다.
- **삭제** 버튼은 확인을 거쳐 저장소를 잊습니다. 그 저장소에서 설치한 릴리스는 계속 실행됩니다.

**차트 찾기** 기능은 `helm search repo`처럼 이 저장소들의 차트를 이름이나 설명으로 검색합니다. Bitnami 저장소를 추가한 다음 `postgres`를 입력하면 PostgreSQL 차트가 최신 차트 버전 및 앱 버전과 함께 표시됩니다.

Homeport는 공개 저장소만 추가합니다. 로그인이 필요한 저장소는 터미널에서 `helm repo add --username …`으로 추가하세요. helm은 평소처럼 비밀번호를 보관하며, 그 저장소는 여기에 표시되어 다른 저장소처럼 작동합니다. OCI 레지스트리의 차트(`oci://…`)에는 저장소가 필요 없습니다.

## 작동하지 않을 때

- **helm CLI가 이 컴퓨터에 설치되어 있지 않습니다**: 위와 같이 helm 3을 설치한 다음 페이지를 다시 여세요.
- **Helm 2**: Homeport는 Helm 3 이상만 지원합니다. 최신 helm을 설치하세요.
- **허용되지 않음**: helm은 Secret에서 릴리스를 읽으므로, 목록을 보려면 Namespace의 `secrets`에 대한 `list` 권한이 필요합니다. 거부된 내용은 세부 정보에 나옵니다.
- **이 릴리스의 다른 설치, 업그레이드 또는 롤백이 아직 진행 중입니다**: 대기 중인 작업이 릴리스를 잠갔습니다. 작업이 끝날 때까지 기다리거나, 마지막으로 배포된 리비전으로 롤백하세요.
- **이 Namespace에 같은 이름의 릴리스가 이미 있습니다**: 릴리스 이름은 Namespace 안에서 고유합니다. 다른 이름을 고르거나 기존 릴리스를 업그레이드하세요.
- **helm이 이 차트나 버전을 찾지 못했습니다**: 이름과 버전을 확인하세요. 저장소 차트는 해당 저장소가 추가되고 [업데이트](#chart-repositories)되어 있어야 합니다. 차트가 내 저장소에 없는 릴리스를 업그레이드하려면 먼저 그 저장소를 추가하세요.
- **값이 올바른 YAML이 아닙니다**: 메시지에 줄 번호가 나옵니다. 고친 다음 다시 시도하세요.
- **대기 시간 초과**: **대기** 옵션을 켰을 때 리소스가 제시간에 준비되지 않았습니다. 릴리스의 Pod와 이벤트에서 무엇이 멈춰 있는지 확인하세요.
- **차트 저장소가 아니거나 연결할 수 없음**: URL이 `index.yaml`을 제공하지 않거나, 이 컴퓨터에서 연결할 수 없습니다. 세부 정보에 helm의 응답이 표시됩니다.
- **연결되지 않음**: helm은 Homeport 안의 클러스터 연결을 거칩니다. 클러스터 페이지에서 연결되지 않은 이유를 확인하세요.
