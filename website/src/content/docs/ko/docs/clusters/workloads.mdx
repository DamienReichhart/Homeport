전환기에서 클러스터를 선택하면 사이드바에 그 클러스터의 페이지가 표시됩니다. **워크로드** 페이지와 **Pod** 페이지에는 클러스터에서 실행 중인 것이 나열됩니다. 모든 목록은 Kubernetes watch로 클러스터를 실시간으로 따라가므로, 스케일한 Deployment나 크래시한 Pod의 새 상태가 새로 고침 없이 몇 초 안에 표시됩니다. 각 페이지에서는 표시된 대상에 대해 [로그와 터미널](/docs/clusters/logs-exec/), [스케일, 다시 시작, 삭제](/docs/clusters/actions/), [YAML 편집](/docs/clusters/yaml/) 작업도 할 수 있습니다.

## Namespace

각 클러스터 페이지는 오른쪽 위에서 고른 Namespace 하나, 또는 **모든 Namespace** 항목을 보여 줍니다. 처음에는 클러스터 kubeconfig 컨텍스트의 Namespace(없으면 `default`)로 시작하며, Homeport는 선택한 Namespace를 클러스터별로 기억합니다.

자격 증명으로 일부 Namespace만 볼 수 있다면 그중 하나를 선택하세요. 그 Namespace에서는 페이지가 작동합니다. Namespace 목록조차 볼 수 없으면 선택기가 입력 필드로 바뀌며, 사용이 허용된 Namespace를 직접 입력합니다.

## 워크로드

**워크로드** 페이지에는 종류별 탭인 **Deployment**, **StatefulSet**, **DaemonSet**, **Job**, **CronJob** 탭이 있습니다. 각 행에는 상태, 원하는 Pod 중 준비된 Pod의 수, 최신 템플릿으로 실행 중인 Pod의 수, 이미지, 생성 후 경과 시간이 표시됩니다.

| 상태            | 의미                                                                                    |
| --------------- | --------------------------------------------------------------------------------------- |
| **준비됨**      | 원하는 모든 Pod가 준비되었고 최신입니다. Job은 완료되었고, CronJob은 예약되어 있습니다. |
| **진행 중**     | 롤아웃 중이거나 스케줄링 중이거나 Job이 아직 실행 중입니다.                             |
| **성능 저하**   | Deployment의 롤아웃이 진행 기한을 넘겼습니다.                                           |
| **실패**        | Job이 실패했습니다.                                                                     |
| **일시 중지됨** | 0으로 스케일되었거나, 일시 중단된 Job 또는 CronJob입니다.                               |

### 워크로드 읽기

**준비** 값은 워크로드가 원하는 Pod 중 readiness probe를 통과한 Pod의 수이고, **최신** 값은 최신 템플릿으로 실행 중인 Pod의 수입니다. 롤아웃 중에는 두 번째 값이 첫 번째 값보다 뒤처집니다. `2/3` 준비에 최신이 `1`이면 새 Pod 하나가 들어왔고 이전 Pod가 아직 요청을 처리하고 있다는 뜻입니다. **최신** 값이 계속 뒤처지고 상태가 **성능 저하** 상태로 바뀌면 새 Pod가 시작하지 못하는 것입니다. 그 Pod의 페이지에서 이유를 확인할 수 있습니다.

워크로드 페이지에는 다음 탭이 있습니다.

- **개요**: Namespace, 레플리카, 롤아웃 전략, Pod를 선택하는 레이블, 레이블과 어노테이션, 이미지와 포트가 표시된 컨테이너.
- **Pod**: 워크로드가 선택하는 Pod(CronJob이라면 **Job** 탭: 시작한 Job, 최신순).
- **로그**: Pod의 로그를 모두 섞어서 보거나 하나씩 봅니다(CronJob에는 없으며, 그 Job에 각자의 로그가 있습니다).
- **조건**, **이벤트**(경고가 먼저 표시되며, Kubernetes는 약 1시간 동안 보관), **YAML**(`managedFields` 제외, **편집** 버튼 포함).

헤더에는 워크로드의 작업이 있습니다. 해당하는 경우 **스케일**, **다시 시작**, **일시 중단** 또는 **재개**, **지금 실행**, 그리고 **삭제** 버튼이 있습니다. [스케일, 다시 시작, 삭제](/docs/clusters/actions/)를 참고하세요.

## Pod

**Pod** 페이지는 각 Pod를 `kubectl get pods`와 같은 형식의 상태(`Running`, `Pending`, `CrashLoopBackOff`, `ImagePullBackOff`, `Init:…`, `Terminating`), 준비된 컨테이너, 재시작 횟수, Node, 생성 후 경과 시간과 함께 나열합니다. 긴 목록은 페이지당 100행씩 표시하므로 Pod가 수천 개인 클러스터에서도 반응이 느려지지 않으며, 검색 상자는 모든 Pod를 대상으로 필터링합니다. 클러스터에서 metrics-server가 실행 중이면 **CPU**와 **메모리**에 각 Pod가 제한 대비 얼마나 사용하는지 표시됩니다([CPU와 메모리](/docs/clusters/metrics/)).

Pod 페이지에는 Node, IP, QoS 클래스, 서비스 계정, Pod를 제어하는 대상이 표시되고, 그다음 각 컨테이너(init 컨테이너가 먼저)가 이미지, 상태, 대기 중이거나 종료된 이유, 재시작 횟수, 마지막으로 다시 시작한 이유와 함께 표시됩니다. 각 컨테이너에는 선언한 포트가 나열되며, **포워딩…** 버튼으로 [이 컴퓨터에서 포트에 연결](/docs/clusters/port-forward/)할 수 있습니다. 이어서 **로그** 탭과 **터미널** 탭([로그와 터미널](/docs/clusters/logs-exec/)), 워크로드와 같은 **조건**, **이벤트**, **YAML** 탭이 있고, 헤더에 **삭제** 버튼이 있습니다. metrics-server가 있으면 **메트릭**에 각 컨테이너의 CPU와 메모리가 요청과 제한 대비 그래프로 표시됩니다([CPU와 메모리](/docs/clusters/metrics/)).

### Pod가 준비되지 않은 이유 찾기

1. **Pod** 페이지에서 **상태** 또는 **재시작 횟수** 열로 정렬합니다. `CrashLoopBackOff`, `ImagePullBackOff`, `Error`는 빨간색으로 표시됩니다.
2. Pod를 엽니다. 준비되지 않은 컨테이너에 대기 중이거나 종료된 이유가 표시되고, **재시작 횟수** 항목에서 마지막 종료 이유(`Error`, `OOMKilled`(메모리 제한에 도달), `Completed`)를 확인할 수 있습니다.
3. **로그** 탭에서 **이전 실행** 옵션을 켜면 컨테이너가 크래시하기 전에 출력한 내용이 표시됩니다.
4. **이벤트** 탭에는 kubelet과 스케줄러가 보고한 내용이 있습니다. 풀할 수 없는 이미지, 실패하는 probe, 메모리가 충분한 Node가 없는 경우 등입니다.
5. **YAML** 탭에는 클러스터가 가진 그대로의 Pod가 표시되므로 probe, 제한, 환경 변수를 확인할 수 있습니다.

## 자격 증명으로 볼 수 없는 경우

자격 증명으로 읽을 수 없는 목록에는 "자격 증명으로 shop Namespace의 daemonsets 목록을 볼 수 없습니다." 같은 메시지와 확인용 `kubectl auth can-i` 명령이 표시됩니다. 다른 페이지는 계속 작동합니다.
