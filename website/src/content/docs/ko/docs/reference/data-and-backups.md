Homeport는 알고 있는 것을 이 컴퓨터에 보관합니다. 호스트와 클러스터에 연결하는 방법, 스택의 정의와 환경 변수, 레지스트리 로그인, 저장소, 설정입니다. 이 페이지에서는 그것이 어디에 있는지, 무엇을 복사해야 하는지, 어떻게 되돌리는지 설명합니다. 어떻게 보호되는지는 [보안과 데이터](/docs/reference/security/)를 참고하세요.

호스트와 클러스터에서 실행되는 것은 Homeport의 데이터가 아닙니다. 컨테이너, 이미지, 볼륨, Kubernetes나 Nomad의 객체는 그 자리에 남으며, Homeport의 백업에는 들어 있지 않습니다. 볼륨의 내용을 복사하려면 볼륨 페이지에서 [파일로 백업](/docs/guides/volumes-networks/#백업과-복원)하세요.

## 무엇이 어디에 있는지

### 데이터 폴더

| 시스템  | 폴더                                              |
| ------- | ------------------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/`                |
| macOS   | `~/Library/Application Support/com.homeport.app/` |
| Windows | `%APPDATA%\com.homeport.app\`                     |

Linux에서는 `$XDG_DATA_HOME`이 설정되어 있으면 폴더가 그 아래에 있습니다. Homeport가 데이터베이스를 열 수 없으면 창에 파일의 전체 경로가 **폴더 열기** 버튼과 함께 표시됩니다.

| 폴더 안의 항목                       | 내용                                                                                                                                                               |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `homeport.db`                        | 데이터베이스입니다. 모든 호스트, 클러스터, 스택, 레지스트리 로그인, 저장소, 설정, 배포 기록, 엔진 이벤트가 들어 있습니다. 그 안의 비밀 정보는 암호화되어 있습니다. |
| `homeport.db-wal`, `homeport.db-shm` | SQLite의 미리 쓰기 로그와 그 인덱스로, Homeport가 실행 중일 때 있습니다. 최근 변경 사항은 Homeport가 종료될 때까지 `-wal` 파일에만 있을 수 있습니다.               |
| `homeport.db.before-restore-<date>`  | [복원](#백업-복원) 직전마다 만들어지는 데이터베이스 사본입니다. 더 이상 필요 없는 것은 삭제하세요.                                                                 |
| `repositories/`, `synced-stacks/`    | [동기화 스택](/docs/guides/synced-stacks/) 저장소의 클론과 작업 사본입니다. Homeport가 저장소 자체에서 다시 만듭니다.                                              |

데이터베이스에 무엇이 들어 있고 어느 부분이 암호화되는지는 [Homeport가 저장하는 것](/docs/reference/security/#homeport가-저장하는-것)에 나와 있습니다.

### 키체인 항목

비밀 정보를 암호화하는 키는 이 폴더에 없습니다. 운영 체제 키체인의 항목 하나로, 서비스는 `com.homeport.app`, 계정은 `secrets-key`입니다. macOS에서는 **키체인 접근**, Windows에서는 **자격 증명 관리자 → Windows 자격 증명**, Linux에서는 **암호 및 키**(Seahorse)나 KWallet에 있습니다. 이 항목은 이 컴퓨터의 사용자 계정에 속합니다.

데이터베이스와 이 항목은 함께 갑니다. 키가 없는 데이터베이스도 열리고 모든 이름, 주소, compose 파일이 남아 있지만, 비밀 정보는 하나도 복호화할 수 없습니다. 호스트와 클러스터는 **자격 증명 손실**로 표시됩니다. 그래서 폴더를 복사하는 것만으로는 다른 컴퓨터로 옮길 수 없으며, [앱 안의 백업](#homeport에서-백업하기)을 권장합니다.

### 로그와 창 위치

| 시스템  | 로그                                    | 창 크기와 위치                                                      |
| ------- | --------------------------------------- | ------------------------------------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/logs/` | `~/.config/com.homeport.app/.window-state.json`                     |
| macOS   | `~/Library/Logs/com.homeport.app/`      | `~/Library/Application Support/com.homeport.app/.window-state.json` |
| Windows | `%LOCALAPPDATA%\com.homeport.app\logs\` | `%APPDATA%\com.homeport.app\.window-state.json`                     |

둘 다 백업할 필요는 없습니다. **설정 → 정보 → 로그 폴더 열기**로 로그를 열 수 있습니다.

### 사용자가 직접 관리하는 것

- **링크된 스택의 폴더.** Homeport는 [링크된 스택](/docs/guides/stacks/#링크된-스택)의 폴더와 compose 파일이 어디에 있는지만 보관합니다. 폴더, 그 compose 파일, 그 `.env`는 사용자의 것입니다. 다른 프로젝트처럼, 보통 git으로 백업하세요.
- **kubeconfig, `~/.ssh`, `~/.docker`.** Homeport는 여기서 가져올 때 읽기만 하고 절대 바꾸지 않습니다.
- **helm의 차트 저장소와 로그인.** helm 자체의 것으로, 터미널과 함께 씁니다.

## Homeport에서 백업하기

**설정 → 데이터 → 백업…**은 모든 것을 `.homeport` 파일 하나에 기록합니다. 비밀 정보 자체를 이 컴퓨터의 키체인 대신 암호 문구로 보호해 담기 때문에 어느 컴퓨터에서나 복원할 수 있으며, 가장 권장하는 백업입니다.

1. **설정**을 열고 **데이터** 아래에서 **백업…**을 선택합니다.
2. 12자 이상의 암호 문구를 두 번 입력합니다. Homeport는 암호 문구를 저장하지 않으며, 암호 문구 없이는 아무것도 이 파일을 열 수 없습니다.
3. 파일을 저장할 곳을 선택합니다.

그러면 Homeport가 무엇을 저장했는지 알려 주고, 이 컴퓨터에서 복호화할 수 없어서 비밀 정보 없이 저장한 항목이 있으면 그 이름을 밝힙니다.

| 백업에 들어가는 것                                          | 백업에 들어가지 않는 것                                  |
| ----------------------------------------------------------- | -------------------------------------------------------- |
| 호스트와 그 키, 암호 문구, 인증서, 배스천, 신뢰한 서버 키   | 엔진 이벤트                                              |
| 클러스터와 그 인증서, 토큰, exec 플러그인 설정              | 배포 기록                                                |
| 관리형 스택의 compose 파일과 환경 변수                      | 링크된 스택의 폴더와 파일                                |
| 링크된 스택의 폴더와 파일 경로                              | 동기화 스택의 클론(다음 동기화 때 다시 만들어짐)         |
| 동기화 스택의 저장소, 브랜치나 태그, 동기화 설정, 환경 변수 | 로그, 창 크기와 위치                                     |
| Swarm에 배포한 스택                                         | 호스트와 클러스터에 있는 모든 것: 컨테이너, 이미지, 볼륨 |
| 레지스트리 로그인과 그 비밀번호, 토큰                       | helm의 차트 저장소                                       |
| 저장소와 그 배포 키, 토큰                                   | Homeport가 종료되면 끝나는 포트 포워딩                   |
| 설정                                                        |                                                          |

파일 전체가 암호 문구로 암호화되므로, 암호 문구가 없으면 호스트 이름조차 알 수 없습니다. 이 파일에는 Homeport가 가진 모든 비밀 정보가 들어 있으므로, 파일과 암호 문구를 키 자체만큼 안전하게 보관하세요. 암호화 방식은 [백업](/docs/reference/security/#백업)에서 설명합니다.

사전 릴리스를 써 보기 전, 시스템을 다시 설치하기 전, 그리고 다시 설정하고 싶지 않은 호스트를 추가했을 때마다 백업하세요.

### 백업 복원

1. 이 컴퓨터나 다른 컴퓨터에서 **설정**을 열고 **데이터** 아래에서 **복원…**을 선택합니다.
2. `.homeport` 파일을 고르고 암호 문구를 입력합니다. Homeport는 아무것도 바꾸기 전에 파일에 들어 있는 내용과, 어느 Homeport가 언제 만들었는지를 나열합니다.
3. **모두 교체**를 선택합니다.

복원하면 Homeport의 모든 데이터가 백업의 데이터로 대체되며, 합쳐지지 않습니다. Homeport는 먼저 현재 데이터베이스를 데이터 폴더의 `homeport.db.before-restore-<date>`에 복사한 다음 한 번에 모든 것을 대체하므로, 실패하면 데이터가 그대로 남습니다. 모든 비밀 정보는 이 컴퓨터의 키체인 키로 다시 암호화됩니다.

복원 후에는 다음과 같습니다.

- 호스트와 클러스터는 키, 비밀번호, 신뢰할 서버 키를 묻지 않고 바로 다시 연결됩니다.
- 폴더가 이 컴퓨터의 같은 경로에 없는 링크된 스택은 폴더가 생길 때까지 외부 스택으로 표시됩니다.
- 동기화 스택은 다음 동기화 때 저장소를 다시 클론합니다.
- 이벤트 페이지와 배포 기록은 비어 있는 상태로 시작합니다.

이전 Homeport로 만든 백업은 더 새로운 Homeport에서 복원됩니다. 더 새로운 Homeport로 만든 백업은 거부되므로 먼저 Homeport를 업데이트하세요.

복원 전 상태로 돌아가려면 Homeport를 종료하고, `homeport.db`의 이름을 다른 것으로 바꾸고, 원하는 `homeport.db.before-restore-<date>`의 이름을 `homeport.db`로 바꾸고, 그 옆에 남은 `homeport.db-wal`과 `homeport.db-shm`을 삭제한 다음 Homeport를 다시 여세요.

### 일부 호스트만 옮기기

호스트 페이지의 **내보내기**와 **가져오기**는 고른 호스트를 비밀 정보와 함께 같은 종류의 파일로 옮기고, 다른 컴퓨터에 이미 있는 호스트에 추가합니다. [다른 컴퓨터로 옮기기](/docs/reference/security/#다른-컴퓨터로-옮기기)를 참고하세요.

## 파일 직접 복사하기

데이터베이스 사본은 Time Machine, 파일 히스토리, 직접 만든 스크립트 같은 이 컴퓨터의 시스템 백업에 알맞습니다. 앱 안의 백업에서 빠지는 엔진 이벤트와 배포 기록도 남지만, **키체인 키는 들어 있지 않습니다**. 비밀 정보까지 복원되는 것은 같은 컴퓨터의 같은 사용자이거나, 키체인을 함께 복원한 컴퓨터뿐입니다. 그 밖의 곳에서는 모든 이름, 주소, compose 파일이 돌아오지만 비밀 정보는 [다시 입력](#비밀-정보를-잃었을-때)해야 합니다.

### Homeport가 닫혀 있을 때

Homeport를 종료한 다음(창을 닫으면 [트레이에 남는](/docs/guides/settings/#데스크톱) 경우 트레이의 **종료** 메뉴로), 데이터 폴더 전체를 복사하세요. Homeport가 종료되면 `homeport.db`에 모든 것이 들어 있고, `-wal`과 `-shm` 파일은 사라집니다.

### Homeport가 실행 중일 때

Homeport가 실행 중일 때 `homeport.db`만 복사하지 마세요. 최근 변경 사항이 아직 `homeport.db-wal`에 있을 수 있고, 쓰는 도중에 만든 사본은 일관성이 깨질 수 있습니다. 대신 `sqlite3` 명령줄 도구로 SQLite에 일관된 사본을 요청하세요(macOS에는 포함되어 있으며, Linux와 Windows에서는 배포판의 `sqlite3` 패키지나 [sqlite.org](https://sqlite.org/download.html)에서 설치합니다).

```sh
# Linux
sqlite3 ~/.local/share/com.homeport.app/homeport.db ".backup '$HOME/homeport-backup.db'"

# macOS
sqlite3 "$HOME/Library/Application Support/com.homeport.app/homeport.db" ".backup '$HOME/homeport-backup.db'"
```

```powershell
# Windows
sqlite3 "$env:APPDATA\com.homeport.app\homeport.db" ".backup '$HOME\homeport-backup.db'"
```

결과는 완전한 파일 하나이며, 옆에 `-wal` 파일이 없습니다. 확인하려면 다음을 실행하세요.

```sh
sqlite3 ~/homeport-backup.db "PRAGMA integrity_check;"
```

`ok`가 출력됩니다.

### 사본 복원

1. Homeport를 종료합니다.
2. 데이터 폴더에서 `homeport.db`를 다른 곳으로 옮기고, `homeport.db-wal`과 `homeport.db-shm`이 있으면 삭제합니다. 이 파일들은 대체할 데이터베이스의 것입니다.
3. 사본을 `homeport.db`라는 이름으로 그곳에 둡니다. 폴더 전체를 복사했다면 대신 폴더를 되돌려 둡니다.
4. Homeport를 엽니다.

이전 버전으로 만든 사본은 Homeport가 열 때 업그레이드합니다. 더 새로운 Homeport가 마지막으로 사용한 사본은 손대지 않은 채 거부되며, [설치할 버전을 알려 주는 메시지](/docs/reference/troubleshooting/#이-데이터베이스는-homeport--이상에서-마지막으로-사용되었습니다)가 표시됩니다.

## 비밀 정보를 잃었을 때

키체인 초기화, 새 사용자 계정, 다른 컴퓨터에서 연 데이터베이스 사본 이후에 Homeport는 아직 읽을 수 있는 것은 모두 유지하고 읽을 수 없는 것은 표시해 둡니다. 아무것도 삭제되지 않으며, 비밀 정보가 아닌 것(이름, 주소, compose 파일, 폴더 경로)은 그대로 있습니다. 다음을 다시 입력하세요.

| 대상                              | 방법                                                                                                                                                           |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TLS 호스트**                    | 호스트 페이지에서 CA 인증서, 클라이언트 인증서, 클라이언트 키를 다시 불러오고 **저장**을 선택합니다.                                                           |
| **가져온 키를 쓰는 SSH 호스트**   | 개인 키와 그 암호 문구를 다시 붙여 넣고 **저장**을 선택합니다.                                                                                                 |
| **Homeport 키를 쓰는 SSH 호스트** | **키 다시 생성**을 선택한 다음 서버에서 [새 키를 승인](/docs/hosts/ssh/#homeport의-키-승인)합니다. 서버에 있는 이전 `homeport@` 줄은 삭제하세요.               |
| **HTTPS로 연결한 Incus 호스트**   | 호스트를 삭제하고 [새 신뢰 토큰으로 다시 추가](/docs/hosts/incus/#신뢰-토큰을-사용한-https)합니다.                                                             |
| **Kubernetes 클러스터**           | 클러스터 페이지에서 **kubeconfig에서 새로 고침**을 사용합니다.                                                                                                 |
| **Nomad 클러스터**                | 클러스터의 **설정**에 ACL 토큰과, 사용하는 경우 인증서를 붙여 넣습니다.                                                                                        |
| **스택 환경 변수**                | 관리형 스택이나 동기화 스택의 환경 변수를 그 페이지에서 다시 입력합니다. 링크된 스택은 폴더의 `.env`에 환경 변수를 두며, Homeport는 이를 보관한 적이 없습니다. |
| **레지스트리 로그인**             | **설정 → 레지스트리**에서 각 로그인을 편집하고 비밀번호나 토큰을 입력합니다.                                                                                   |
| **저장소**                        | **설정 → 저장소**에서 **새 키**를 만들어 포지의 저장소에 추가하거나, **토큰 교체**를 선택합니다.                                                               |

로컬 소켓, TCP, ssh-agent 호스트는 비밀 정보가 없으므로 계속 작동합니다. 배포 기록에 기록된 환경 변수는 다시 입력할 수 없지만, 기록의 compose 파일은 계속 읽을 수 있습니다.

대신 Homeport가 비밀 정보를 봉인한 키체인 항목이 없다고 알린다면, 아직 비밀 정보를 포기한 것이 아닙니다. 그 항목이 있는 키체인으로 돌아가거나, 다시 입력하기 전에 **설정 → 이 컴퓨터**에서 **새 키로 다시 시작**을 선택하세요.

문제 해결의 [자격 증명 손실](/docs/reference/troubleshooting/#자격-증명-손실)도 참고하세요.

## 데이터 삭제

삭제할 폴더와 키체인 항목, 서버에서 삭제할 키는 [데이터 삭제](/docs/reference/updating/#데이터-삭제)에 나와 있습니다.
