모든 Homeport 릴리스는 공개 저장소에서 GitHub Actions가 빌드합니다. 다운로드한 파일이 빌드된 파일과 같은지 두 가지 방법으로 확인할 수 있습니다. Linux 패키지와 업데이트는 서명도 되어 있으며, 자동으로 확인됩니다.

## 체크섬

각 릴리스에는 모든 파일의 SHA-256 체크섬이 담긴 `SHA256SUMS.txt`가 포함됩니다. [다운로드 페이지](/download/)에도 각 파일의 체크섬이 표시됩니다. 설치 프로그램과 같은 폴더에 `SHA256SUMS.txt`를 다운로드한 다음 다음을 실행합니다.

<Tabs syncKey="os">
<TabItem label="Linux">

```sh
sha256sum --ignore-missing -c SHA256SUMS.txt
```

</TabItem>
<TabItem label="macOS">

```sh
shasum -a 256 --ignore-missing -c SHA256SUMS.txt
```

</TabItem>
<TabItem label="Windows">

```powershell
(Get-FileHash .\Homeport_0.2.0_x64-setup.exe -Algorithm SHA256).Hash.ToLower()
```

결과를 `SHA256SUMS.txt`에 있는 설치 프로그램의 줄과 비교하세요.

</TabItem>
</Tabs>

파일 이름 옆에 `OK`가 표시되면 일치하는 것입니다.

## 빌드 출처

체크섬은 체크섬이 게시된 뒤 파일이 손상되거나 바꿔치기되지 않았음을 증명합니다. [빌드 출처 증명](https://docs.github.com/actions/security-for-github-actions/using-artifact-attestations)은 한 걸음 더 나아갑니다. GitHub가 서명하며, 파일을 만든 저장소, 커밋, 워크플로를 기록합니다.

[GitHub CLI](https://cli.github.com)를 설치했다면 다음을 실행합니다.

```sh
gh attestation verify Homeport_0.2.0_x64-setup.exe --repo DamienReichhart/Homeport
```

확인에 성공하면 파일을 빌드한 워크플로와 커밋이 출력됩니다.

## 패키지 서명

Homeport 패키지 저장소와 모든 `.rpm`은 Homeport 패키지 키(RSA 4096)로 서명되어 있습니다.

**지문:** <SigningKeyFingerprint />

`apt`, `dnf`, `zypper`는 업데이트할 때마다 이 서명을 확인하며, 일치하지 않는 패키지와 저장소 데이터는 거부합니다. 다운로드한 키나 `.rpm` 파일을 확인하려면 다음을 실행합니다.

<Code code={`curl -fsSL ${KEY_URL} | gpg --show-keys --with-fingerprint`} lang="sh" />

```sh
sudo rpm --import homeport.asc   # once
rpm -K Homeport-<version>-1.x86_64.rpm
```

서명된 패키지라면 `rpm -K`가 `digests signatures OK`를 출력합니다. `.deb` 파일 자체는 서명되어 있지 않습니다. 저장소의 서명된 인덱스가 `.deb`를 보증하며, 다운로드한 `.deb`는 체크섬과 증명으로 보증됩니다.

## 업데이트 서명

앱 내 업데이터가 설치하는 모든 업데이트는 별도의 Homeport 업데이트 키로 서명되어 있으며, 그 공개 키는 Homeport에 내장되어 있습니다. 설치하기 전에 Homeport는 서명과, 그 서명이 공지된 버전을 위해 만들어졌는지를 확인하며, 올바른 주소에서 왔더라도 그 밖의 것은 거부합니다.

## 코드 서명

macOS 앱은 임시(ad-hoc) 서명되어 있고 Windows 설치 프로그램은 아직 상용 인증서로 서명되지 않았으므로, macOS와 Windows는 처음 실행할 때 확인을 요청합니다. 방법은 [설치](/docs/installation/)에 나와 있습니다. Homeport 안에서 설치한 업데이트는 다시 묻지 않습니다.
