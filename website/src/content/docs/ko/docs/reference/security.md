Homeport는 서버를 여는 자격 증명을 보관합니다. 이 페이지에서는 무엇을 보관하고 그것을 어떻게 보호하는지 정확히 설명합니다. 백업하려면 무엇을 복사해야 하는지, 어떻게 복원하는지는 [데이터와 백업](/docs/reference/data-and-backups/)에서 설명합니다.

## Homeport가 저장하는 것

모든 데이터는 사용자의 애플리케이션 데이터 폴더에 있는 SQLite 데이터베이스 `homeport.db` 하나에 있습니다.

| 시스템  | 폴더                                              |
| ------- | ------------------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/`                |
| macOS   | `~/Library/Application Support/com.homeport.app/` |
| Windows | `%APPDATA%\com.homeport.app\`                     |

다음 내용이 들어 있습니다.

| 데이터                                         | 저장 방식   |
| ---------------------------------------------- | ----------- |
| 호스트 이름, 주소, SSH 사용자, 소켓 경로       | 일반 텍스트 |
| SSH 공개 키와 신뢰한 서버 키                   | 일반 텍스트 |
| SSH 개인 키와 암호 문구                        | **암호화**  |
| TLS CA 인증서, 클라이언트 인증서와 키          | **암호화**  |
| Incus 호스트의 클라이언트 키와 고정된 인증서   | **암호화**  |
| 관리형 스택의 compose 파일                     | 일반 텍스트 |
| 관리형 스택의 환경 변수                        | **암호화**  |
| 링크된 스택의 폴더와 compose 파일 경로         | 일반 텍스트 |
| 배포 기록: compose 파일과 프로필               | 일반 텍스트 |
| 배포 기록: 환경 변수                           | **암호화**  |
| 레지스트리 주소와 사용자 이름                  | 일반 텍스트 |
| 레지스트리 비밀번호와 액세스 토큰              | **암호화**  |
| 저장소 URL, 배포 키의 공개 키 부분             | 일반 텍스트 |
| 신뢰한 저장소 서버 키                          | 일반 텍스트 |
| 저장소 배포 키와 액세스 토큰                   | **암호화**  |
| 클러스터 이름, API 서버 URL, Namespace         | 일반 텍스트 |
| 각 클러스터의 로그인 방식, kubeconfig 컨텍스트 | 일반 텍스트 |
| 클러스터 CA, 클라이언트 인증서와 키            | **암호화**  |
| 클러스터 토큰, 비밀번호, OIDC 토큰             | **암호화**  |
| Exec 플러그인의 명령, 인수, 환경 변수          | **암호화**  |
| 테마, 마지막 선택, 클러스터별 Namespace        | 일반 텍스트 |
| 이벤트 페이지용 각 호스트의 엔진 이벤트        | 일반 텍스트 |

Homeport는 엔진에서 그 밖의 어떤 것도 복사하지 않습니다. 컨테이너, 이미지, 볼륨, 로그는 실시간으로 읽고 저장하지 않으며, 사용자가 직접 로그나 파일을 다운로드하거나 볼륨을 백업할 때만 예외입니다. 보관하는 엔진 이벤트(어떤 컨테이너, 이미지, 볼륨, 네트워크에 무슨 일이 있었는지와 그 레이블)는 기본적으로 30일 동안([설정 → 데이터](/docs/guides/settings/#데이터)), 호스트당 최대 10,000개까지 보관하며, 호스트를 삭제하거나 **기록 지우기**를 선택하면 삭제됩니다.

### 링크된 스택의 폴더

[링크된 스택](/docs/guides/stacks/#링크된-스택)의 경우 Homeport는 폴더와 compose 파일의 위치, 그리고 파일이 바뀌었는지 알기 위한 파일 지문만 저장하며, 파일의 사본은 절대 저장하지 않습니다. 스택을 열 때 compose 파일을 읽고, **정의** 탭에서 **저장**을 선택할 때만 파일에 기록합니다. 편집한 파일은 한 번에 교체하며 권한을 유지합니다. 연 이후 바뀐 파일은 사용자가 지시하지 않는 한 덮어쓰지 않습니다. Homeport는 폴더의 `.env`를 절대 읽거나 쓰지 않습니다. `.env`는 Compose가 실행될 때 읽습니다. 링크된 스택을 잊어도 폴더는 건드리지 않습니다.

### 저장소

[동기화 스택](/docs/guides/synced-stacks/)의 경우 Homeport는 각 저장소의 URL과 함께, 그 저장소용으로 생성한 배포 키(개인 키 부분은 암호화) 또는 사용자 이름과 액세스 토큰(암호화)을 보관합니다. 저장소의 내용은 비밀이 아닙니다. 클론은 `homeport.db` 옆의 `repositories` 폴더에 있습니다.

### Swarm

Homeport는 [Swarm](/docs/guides/swarm/)에 대해 아무것도 저장하지 않습니다. 연결할 때마다 매니저 호스트를 통해 찾습니다. Swarm 시크릿 값은 Swarm으로 가며 Homeport가 보관하지 않습니다. 입력하거나 파일에서 불러온 값은 엔진에 한 번 보내고, `homeport.db`나 파일, 로그에 절대 기록하지 않으며, 대화 상자가 닫히면 메모리에서 지웁니다. 엔진은 시크릿 값을 절대 돌려보내지 않으므로 Homeport도 보여 줄 수 없습니다. 가입 토큰은 필요할 때 매니저에서 가져오며, 절대 저장하거나 로그에 남기지 않습니다.

### 클러스터

[클러스터](/docs/clusters/)의 자격 증명은 kubeconfig에서 오며 SSH 키처럼 암호화해서만 저장합니다. kubeconfig가 참조하는 파일은 한 번 읽어 포함시키고, 붙여 넣은 kubeconfig는 파일에 절대 기록하지 않으며, 사용자의 kubeconfig는 절대 변경하지 않습니다. [Exec 플러그인](/docs/clusters/exec-plugins/)은 이 컴퓨터에서 사용자 권한으로 실행되며, 플러그인이 출력한 토큰이나 인증서는 만료될 때까지 메모리에만 보관합니다. Homeport는 클러스터에서 실행되는 것에 대해 그 밖에는 아무것도 저장하지 않습니다. Pod, 워크로드 등은 실시간으로 읽습니다. [포트 포워딩](/docs/clusters/port-forward/)은 이 컴퓨터의 루프백(`127.0.0.1`과 `::1`)에서만 수신 대기하므로 네트워크의 다른 어떤 것도 사용할 수 없으며, Homeport가 종료되면 끝납니다. [YAML 적용 또는 편집](/docs/clusters/yaml/)으로 한 변경은 클러스터에 필드 관리자 `homeport`로 기록됩니다.

[Helm](/docs/clusters/helm/)은 사용자의 kubeconfig 없이, 그리고 클러스터 자격 증명을 디스크에 기록하지 않고 클러스터를 대상으로 사용자의 `helm` CLI를 실행합니다. 명령마다 Homeport는 이 컴퓨터의 루프백(`127.0.0.1`, 임의 포트)에 임의의 토큰을 지닌 요청만 받아들이는 비공개 연결을 열고, 그 토큰만 들어 있으며 사용자만 읽을 수 있는 임시 kubeconfig를 helm에 줍니다. Homeport는 요청이 지나갈 때 클러스터 자체의 자격 증명을 덧붙이고, 명령이 끝나면 kubeconfig를 삭제하고 연결을 닫습니다. 차트 값은 파일이 아니라 표준 입력으로 helm에 전달합니다. helm 자체의 차트 저장소, 레지스트리 로그인, 캐시는 터미널에서처럼 helm의 것으로 남습니다. Homeport는 공개 저장소만 추가하며 저장소 비밀번호는 저장하지 않습니다.

[Nomad 클러스터](/docs/clusters/nomad/)의 ACL 토큰, CA 인증서, 클라이언트 인증서와 키는 SSH 키처럼 암호화해서만 저장하며, 주소, 리전, TLS 서버 이름은 일반 텍스트로 보관합니다. 토큰은 셸의 WebSocket을 포함해 각 요청의 `X-Nomad-Token` 헤더로 전달하며, URL에는 절대 넣지 않습니다. Homeport는 job 명세의 사본을 보관하지 않습니다. Nomad가 job과 함께 저장합니다.

**Kubernetes Secret 값**은 키 하나에 대해 **표시**를 선택할 때만 하나씩 가져옵니다. 목록, Secret 페이지, YAML에는 키와 크기만 있고 값은 절대 없습니다. 표시한 값은 그 페이지의 메모리에만 남으며(캐시에도, `homeport.db`에도, 로그에도 없습니다), 페이지를 떠나면 다시 숨겨집니다.

## 비밀 정보 암호화 방식

- 각 비밀 정보는 인증 암호인 **XChaCha20-Poly1305**로 개별 봉인되므로, 읽기를 막을 뿐 아니라 변조도 감지합니다.
- 256비트 키는 처음 실행할 때 무작위로 만들어지며, **OS 키체인**(macOS 키체인, Windows 자격 증명 관리자, Linux의 Secret Service)에 `com.homeport.app` 서비스로 보관됩니다. 데이터 옆에 저장되는 일은 절대 없습니다.
- 마스터 비밀번호는 없습니다. 키체인이 이미 키를 사용자 계정에 묶어 둡니다.

`homeport.db` 사본만 가진 사람은 호스트와 클러스터의 이름과 주소는 읽을 수 있지만, 키, 인증서, 토큰, 스택 환경 변수, 레지스트리 비밀번호는 읽을 수 없습니다.

### 키체인이 없을 때

Homeport는 배너를 표시하고 비밀 정보를 저장하지 않습니다. 로컬 소켓, TCP, ssh-agent 호스트는 계속 작동합니다. [요구 사항](/docs/requirements/#선택-사항-os-키체인)을 참고하세요.

### 키체인의 키를 잃었을 때

키체인을 초기화하거나, `homeport.db`를 다른 컴퓨터나 사용자로 옮기면 복호화할 수 없는 비밀 정보가 남습니다. Homeport는 아무것도 삭제하지 않습니다. 영향을 받은 호스트와 클러스터는 자격 증명을 다시 입력할 때까지 **자격 증명 손실**로 표시됩니다. 무엇을 어디에서 다시 입력해야 하는지는 [비밀 정보를 잃었을 때](/docs/reference/data-and-backups/#if-the-secrets-are-lost)에 나와 있습니다. 데이터를 옮기려면 대신 [백업](#backups)하거나 [호스트를 내보내세요](#moving-to-another-computer).

### 다른 컴퓨터로 옮기기

호스트 페이지의 **내보내기**는 선택한 호스트를 키, 인증서, 신뢰한 서버 키와 함께, 사용자가 정한 암호 문구로 암호화하여 파일 하나에 기록합니다.

- 파일 전체가 암호화되므로(XChaCha20-Poly1305, 키는 Argon2id로 암호 문구에서 파생) 암호 문구 없이는 호스트 이름이나 주소조차 드러나지 않습니다. 파일이 조금이라도 바뀌면 읽을 수 없게 됩니다.
- 암호 문구는 12자 이상이어야 합니다. Homeport는 암호 문구를 절대 저장하거나 로그에 남기지 않으므로, 잃어버리면 파일을 열 수 없습니다.
- 다른 컴퓨터에서 **가져오기**는 암호 문구를 물은 다음, 다른 비밀 정보와 마찬가지로 각 호스트의 비밀 정보를 그 컴퓨터 자체의 키체인 키로 암호화하여 저장합니다.
- 이 컴퓨터에서 이미 자격 증명을 잃은 호스트는 자격 증명 없이 내보내지며, 내보내기 결과에 어떤 호스트인지 표시됩니다.

파일은 그 안에 든 키처럼 다루세요. 가져온 뒤에는 삭제하세요. 형식은 [ADR 0013](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0013-passphrase-protected-export-bundles.md)에 설명되어 있습니다.

### 백업

**설정 → 데이터 → 백업…** 메뉴는 위의 모든 것, 즉 호스트, 클러스터, 스택, 레지스트리 로그인, 저장소, 설정을 비밀 정보를 연 상태로, 두 번 입력한 암호 문구와 함께 같은 암호화 형식의 파일 하나에 기록합니다. 엔진 이벤트와 배포 기록은 포함되지 않습니다. 이 컴퓨터에서 열 수 없는 비밀 정보는 빠지며, 백업 결과에 어떤 것인지 표시됩니다.

**복원…** 메뉴는 암호 문구를 묻고, 무엇이든 바꾸기 전에 파일에 든 내용을 나열합니다. 그런 다음 복원은 다음을 수행합니다.

1. 현재 데이터베이스를 `homeport.db` 옆의 `homeport.db.before-restore-<date and time>`으로 복사합니다.
2. 모든 호스트, 클러스터, 스택, 로그인, 저장소, 설정을 한 번에 교체하므로, 실패하면 데이터가 원래대로 남습니다.
3. 모든 비밀 정보를 이 컴퓨터의 키체인 키로 다시 암호화합니다.

더 새로운 Homeport로 만든 백업은 거부되고, 더 오래된 Homeport로 만든 백업은 복원됩니다. 백업에는 Homeport가 가진 모든 비밀 정보가 들어 있으므로, 백업과 암호 문구를 키 자체만큼 안전하게 보관하세요. 절차, 백업에 들어가는 것과 빠지는 것, 데이터베이스를 직접 복사하는 방법은 [데이터와 백업](/docs/reference/data-and-backups/)에 있습니다.

## 키는 절대 평문으로 디스크에 닿지 않습니다

Homeport에는 자체 SSH 클라이언트가 있으므로, `ssh`가 읽도록 개인 키를 파일에 기록하는 일이 절대 없고 `~/.ssh`도 절대 변경하지 않습니다. 복호화한 키는 메모리에만 있습니다.

`docker compose`가 SSH 또는 TLS 호스트에 스택을 배포할 때, Homeport는 이 컴퓨터에 수명이 짧은 비공개 소켓(사용자만 읽을 수 있는 소켓, Windows에서는 원격 클라이언트를 거부하는 명명된 파이프)을 열고, 그 명령 하나를 위해 자체 연결로 포워딩합니다.

저장소 키와 토큰도 디스크에 닿지 않습니다. `git` 명령마다 Homeport는 그 저장소의 배포 키만 담은 비공개 SSH 에이전트를 사용자만 열 수 있는 소켓(Windows에서는 원격 클라이언트를 거부하는 명명된 파이프)에서 제공하거나, 명령의 환경 변수를 통해 HTTPS 헤더로 토큰을 전달합니다. 사용자 자신의 git 설정, 자격 증명 도우미, SSH 키는 쓰지 않으므로 키체인이나 `~/.git-credentials`에 아무것도 캐시되지 않습니다.

레지스트리 로그인도 `docker compose`에 전달되지 않습니다. Homeport는 `docker compose up`을 실행하기 전에 엔진 API를 통해 스택의 이미지를 직접 풀하므로, 명령의 환경 변수와 명령에 주는 파일에는 비밀번호나 토큰이 없습니다.

## 서버 신뢰

Homeport는 SSH 서버에 처음 연결할 때 서버 키 지문을 확인하라고 요청하며, 나중에 키가 바뀌면 다시 확인할 때까지 연결을 거부합니다. TLS 호스트는 서버 인증서를 CA와 서버 이름으로 확인하고, HTTPS를 쓰는 Incus 호스트는 추가할 때의 인증서만 받아들입니다. [SSH 호스트](/docs/hosts/ssh/#첫-연결)를 참고하세요.

### Incus 인증서

[HTTPS로 Incus 호스트를 추가](/docs/hosts/incus/#신뢰-토큰을-사용한-https)하면 클라이언트 인증서와 개인 키(ECDSA P-384 키)를 메모리에서 만들고, 호스트의 다른 비밀 정보와 함께 암호화하여 저장하며, 디스크에 평문으로 두지 않습니다. Incus 자체의 인증서도 같은 방식으로 저장하고 고정합니다. Homeport는 SHA-256 지문으로 비교하여 서버에서 정확히 그 인증서만 받아들이며, 다른 인증서는 두 지문을 함께 보여 주며 거부합니다. 신뢰 토큰은 한 번 사용하고 보관하지 않습니다. Homeport의 접근을 취소하려면 서버에서 `incus config trust remove`로 Homeport의 인증서를 삭제하세요.

## Homeport가 연결하는 곳

- **추가한 호스트.** 이미지를 풀, 푸시, 빌드할 때 레지스트리에 연결하는 것은 Homeport가 아니라 엔진입니다. Homeport는 호스트 연결을 통해 요청과 함께 그 레지스트리의 저장된 로그인을 엔진에 넘기며, 엔진은 이를 보관하지 않습니다.
- **각 호스트의 엔진을 통한 이미지 레지스트리**: [새 이미지](/docs/guides/containers/#새-이미지)가 게시되었는지 알기 위해, 컨테이너, 이미지, 스택 페이지를 불러올 때(각 응답은 6시간 동안 보관)와 **새 이미지 확인**을 선택할 때 연결합니다. 엔진이 레지스트리에 태그가 가리키는 다이제스트를 묻고(비공개 레지스트리에는 저장된 로그인 사용), 아무것도 다운로드하지 않습니다. 로컬 호스트라면 엔진이 이 컴퓨터에서 실행되므로 요청도 이 컴퓨터에서 나갑니다.
- **태그를 탐색할 때의 Docker Hub**: 풀 대화 상자에서 Homeport는 이 컴퓨터에서 `hub.docker.com`으로부터 저장소의 태그를 가져오며, Docker Hub 로그인이 저장되어 있으면 함께 사용합니다. 저장소 검색은 대신 호스트의 엔진을 통합니다.
- **로그인을 확인할 때의 레지스트리**: **설정 → 레지스트리**에서 Homeport는 이 컴퓨터에서 레지스트리의 `/v2/` 엔드포인트와 토큰 서비스에 요청하며, 사용자 이름과 비밀번호 또는 토큰을 HTTPS로 보냅니다(`localhost:5000`처럼 이 컴퓨터에 있는 레지스트리만 일반 HTTP).
- **저장소 서버**: [동기화 스택](/docs/guides/synced-stacks/)을 위해, 접근을 테스트하거나 동기화 스택을 만들거나 동기화할 때, 그리고 폴링이 켜져 있으면 Homeport가 열려 있는 동안 주기적으로 연결합니다. Homeport는 이 컴퓨터에서 그 저장소의 배포 키나 토큰으로 `git`을 실행합니다.
- **추가한 클러스터**: kubeconfig에 지정된 Kubernetes API 서버(프록시가 있으면 그 프록시)를 통해, kubeconfig가 주는 자격 증명으로 연결하며, 서버 인증서를 kubeconfig의 CA로 확인합니다. Exec 플러그인은 `kubectl`에서처럼 이 컴퓨터에서 자체 클라우드(AWS, Google Cloud, Azure)에 연결합니다.
- **추가한 Nomad 클러스터**: 지정한 에이전트 주소를 통해서만 연결합니다. job의 로그와 셸은 그 에이전트를 거치며 에이전트가 클라이언트 노드로 전달하므로, Homeport는 노드 자체에 절대 연결하지 않습니다. 에이전트의 인증서는 지정한 CA나 이 컴퓨터의 CA로 확인합니다.
- **Incus 이미지 서버**: [Incus 호스트](/docs/guides/instances/#인스턴스-만들기)의 이미지 선택기를 위해, Homeport는 이 컴퓨터에서 서버의 이미지 목록(`streams/v1/images.json`, 다른 서버를 고르지 않으면 `images.linuxcontainers.org`)을 다운로드하고 10분 동안 보관합니다. 이미지 자체는 Incus가 다운로드합니다.
- **helm을 통한 차트 저장소와 OCI 레지스트리**: 저장소를 추가하거나 업데이트할 때, 차트를 검색할 때, 차트를 설치하거나 업그레이드할 때 `helm`이 터미널에서처럼 이 컴퓨터에서 인덱스와 차트를 다운로드합니다.
- **업데이트 확인을 위한 이 웹사이트**: 실행할 때와 6시간마다 Homeport는 최신 버전이 적힌 작은 파일 `updates/latest.json`을 다운로드합니다. 이 요청에는 사용자, 호스트, 컨테이너에 대한 정보가 없지만, 다른 웹 요청과 마찬가지로 사용자의 IP 주소에서 이 사이트를 호스팅하는 GitHub Pages에 도달합니다. **설정 → 업데이트**에서 끌 수 있습니다. 업데이트 자체는 GitHub Releases에서 다운로드하며, Homeport의 업데이트 키로 서명된 경우에만 설치합니다. [업데이트](/docs/reference/updating/)를 참고하세요.

## Homeport가 호스트에서 실행하는 것

Homeport는 API를 통해 호스트의 엔진과 통신하며, 그 API로 할 수 없는 일에만 호스트의 서버에서 명령을 실행합니다.

| 시점                                                                            | 위치                                             | 명령                                                                                                                   |
| ------------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| SSH 호스트의 서버가 엔진 소켓 열기를 거부할 때                                  | SSH 서버                                         | 소켓이 있고 읽을 수 있는지, 엔진이 설치되어 있는지 확인하는 POSIX 셸 검사                                              |
| [Quadlet 유닛](/docs/guides/quadlet/)의 **시작**, **중지**, **다시 시작**       | SSH 서버, 또는 Linux의 로컬 소켓이라면 이 컴퓨터 | `systemctl [--user] start\|stop\|restart '<unit>.service'`                                                             |
| [containerd 컨테이너의 로그](/docs/hosts/containerd/#로그)                      | SSH 서버, 또는 Linux의 로컬 소켓이라면 이 컴퓨터 | `tail -n <lines> [-F] -- '<log file>'`. CRI가 파일 이름을 알려 주지 않으면 먼저 Kubernetes 컨테이너의 로그 폴더를 `ls` |
| [containerd 컨테이너 안의 터미널](/docs/hosts/containerd/#컨테이너-안의-터미널) | SSH 서버, 또는 Linux의 로컬 소켓이라면 이 컴퓨터 | `mktemp -d`, 그 폴더에 FIFO 두 개를 만드는 `mkfifo -m 600`, 이를 통한 `cat`, 그다음 폴더의 `rm -rf`                    |

이 명령은 SSH 사용자의 권한(이 컴퓨터에서는 사용자의 권한)으로 실행되며 `sudo`는 절대 사용하지 않습니다. 값은 명령에 들어가기 전에 확인하고 따옴표로 묶습니다. Quadlet 유닛의 설치, 편집, 삭제는 파일을 직접 기록하는 Podman API를 통합니다. Incus 호스트에서는 아무것도 실행하지 않습니다. 콘솔과 터미널은 Incus 자체 API를 통합니다. Homeport가 호스트에 만드는 파일은 containerd 터미널의 FIFO 두 개뿐이며, 터미널을 닫으면 삭제되는 비공개 임시 폴더에 있습니다.

## Homeport가 절대 하지 않는 일

- **계정이 없습니다.** 가입할 것이 없습니다.
- **원격 측정, 분석, 충돌 보고가 없습니다.** 버그를 보고할 때의 [진단 정보 번들](/docs/reference/troubleshooting/#exporting-diagnostics-for-a-bug-report)은 사용자가 직접 내보내고, 읽고, 첨부하는 파일입니다.
- **클러스터에 아무것도 설치하지 않습니다.** Homeport는 사용자 자격 증명의 권한으로 Kubernetes API만 사용하며, 요청하지 않으면 아무것도 바꾸지 않습니다. 무언가를 삭제하거나 교체하는 작업은 클러스터 이름을 밝히며 먼저 확인을 받습니다.
- **호스트에 아무것도 설치하지 않습니다.** Homeport가 호스트에서 실행하는 명령은 [위에 나열된](#homeport가-호스트에서-실행하는-것) 것뿐입니다. Homeport가 스스로 시작하는 컨테이너는 볼륨을 열거나, 백업하거나, 복원하거나, 복제할 때 쓰는 수명이 짧은 [도우미 컨테이너](/docs/guides/volumes-networks/#도우미-컨테이너)뿐입니다. 이 컨테이너에는 네트워크가 없고 작업이 끝나면 삭제됩니다. 그 이미지는 사용자가 동의한 경우에만 풀합니다.
- **몰래 설치하지 않습니다.** 업데이트는 **설치 후 다시 시작**을 선택할 때만 설치되며, Linux 패키지는 항상 패키지 관리자만 업데이트합니다.

[개인정보 처리방침](/privacy/)에서 이것이 법적으로 무엇을 뜻하는지, 즉 데이터에 대한 책임자, 처리 근거, 권리를 행사하는 방법을 설명합니다.

## 로그

Homeport는 문제 진단을 위해 작은 로그 파일(수십 킬로바이트이며 가득 차면 교체됨)을 기록합니다. 연결 이벤트와 오류가 들어 있으며, 자격 증명이나 컨테이너 출력은 들어 있지 않습니다.

| 시스템  | 폴더                                    |
| ------- | --------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/logs/` |
| macOS   | `~/Library/Logs/com.homeport.app/`      |
| Windows | `%LOCALAPPDATA%\com.homeport.app\logs\` |

Homeport에는 원격 측정도 충돌 보고도 없습니다. 로그는 사용자가 보내지 않는 한 이 컴퓨터를 떠나지 않습니다. 버그를 보고할 때는 **설정 → 정보 → 진단 정보 내보내기…**로 버전 요약과 이 로그를 담은 zip을 저장할 수 있습니다. 이때 비밀 정보처럼 보이는 것(키, 비밀번호, 토큰, URL 안의 자격 증명)과, 따로 요청하지 않으면 호스트와 클러스터의 이름과 주소가 대체됩니다. [진단 정보 내보내기](/docs/reference/troubleshooting/#exporting-diagnostics-for-a-bug-report)를 참고하세요.

## 다운로드 신뢰

릴리스는 공개 소스 코드로 GitHub Actions가 빌드합니다. 각 파일에는 SHA-256 체크섬과, 파일을 빌드한 정확한 커밋과 워크플로에 연결하는 서명된 빌드 출처 증명이 함께 제공됩니다. [다운로드 확인](/docs/reference/verifying/)을 참고하세요.
