title: スケール、再起動、削除
description: Deployment と StatefulSet のスケール、ロールアウトの再起動、CronJob の一時停止と実行、そしてクラスターのあらゆるオブジェクトの削除を、それぞれ対象を名指しした確認の後に行います。
---

クラスターに対する日常的な変更は、そのページからワンクリックで行えます。どれも `kubectl` と同じように、クラスター自身の認証情報で Kubernetes API に送られます。一覧は watch を通じて変更をリアルタイムに追従します。

何かを削除または置き換える操作はすべて事前に確認を求めます。確認にはクラスター、Namespace、種類、名前が示されるので、誤って別のクラスターや Namespace に変更が加わることはありません。

## ワークロード

ワークロードのページでは、操作はヘッダーにあります。**ワークロード** では、各行の **⋯** メニューにあります。

| 操作           | 対象                               | 動作（相当するもの）                                                       |
| -------------- | ---------------------------------- | -------------------------------------------------------------------------- |
| **スケール**   | Deployment、StatefulSet            | `kubectl scale --replicas=N`                                               |
| **再起動**     | Deployment、StatefulSet、DaemonSet | `kubectl rollout restart`                                                  |
| **一時停止**   | CronJob                            | `kubectl patch cronjob … -p '{"spec":{"suspend":true}}'`                   |
| **再開**       | 一時停止中の CronJob               | 同じものを `false` で                                                      |
| **今すぐ実行** | CronJob                            | `kubectl create job --from=cronjob/…`                                      |
| **削除**       | すべて                             | `kubectl delete`（その Pod と Job もバックグラウンドで一緒に削除されます） |

### スケール

**スケール** は、現在実行している Pod の数を示したうえで、実行する Pod の数を尋ねます。`0` にスケールすると、再びスケールアップするまでワークロードは停止します。HorizontalPodAutoscaler がワークロードを管理している場合は、ダイアログにその旨が表示されます。オートスケーラーは次の確認時に数を元に戻すので、代わりにオートスケーラーの最小値と最大値を変更してください。

### 再起動

**再起動** は、`kubectl rollout restart` とまったく同じく、Pod テンプレートに `kubectl.kubernetes.io/restartedAt` アノテーションを追加します。ワークロードは戦略に従って新しい Pod のセットをロールアウトし（Deployment の場合は新しい ReplicaSet）、新しい Pod が準備完了になると古い Pod はなくなります。

### CronJob

**一時停止** は CronJob が新しい Job を開始しないようにし（すでに実行中のものは続きます）、**再開** で再び開始できるようにします。一時停止中の CronJob は **一時停止** と表示されます。**今すぐ実行** は、テンプレートからすぐに Job を開始します。Job の名前は `<cronjob>-manual-<id>` で、CronJob に所有され、kubectl と同じく `cronjob.kubernetes.io/instantiate: manual` が付きます。この Job は CronJob の **Job** タブに表示されます。

## 削除

オブジェクトのどのページにも（ワークロード、Pod、Service、Ingress、ConfigMap、Secret、Node、**API リソース** にあるあらゆるオブジェクト）、ヘッダーに **削除** があります。一覧では、行にチェックを入れると、**N 個を削除** で、それらを列挙した 1 回の確認の後にすべて削除できます。

オブジェクトは、`kubectl delete` と同じく、伝播ポリシー `Background` で削除されます。オブジェクトはすぐに削除され、ガベージコレクターがそれが所有するもの（Deployment の ReplicaSet と Pod、CronJob の Job）を削除します。

確認には、次に何が起こるかが示されます:

- **コントローラーが所有する Pod**（ReplicaSet、StatefulSet、DaemonSet、Job が所有するもの）は戻ってきます。コントローラーが代わりに新しい Pod を起動します。なくしたい場合は、ワークロードを削除するかスケールしてください。
- **Namespace** は、その中のすべて（ワークロード、Pod、Service、ConfigMap、Secret）を削除します。
- **Node** は、先にドレインされることなく、クラスターの一覧から削除されます。

## うまくいかない場合

- **許可されていない**: 認証情報で行えない変更には、その旨が動詞とリソースとともに表示されます（「この認証情報では、shop の deployments に対する「patch」は許可されていません。」）。確認用の `kubectl auth can-i` コマンドも示されます。
- **その間に変更された**: 確認してから操作するまでの間にほかの誰かがオブジェクトを変更した場合、Homeport はその旨を表示します。もう一度確認してから再試行してください。
- **すでに存在しない**: すでに削除されたものを削除しようとすると、もう存在しないことが表示されます。
