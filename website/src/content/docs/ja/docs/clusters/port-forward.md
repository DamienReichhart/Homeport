---
title: ポートフォワード
description: kubectl port-forward のように、Pod や Service のポートを公開せずに、このコンピューターからアクセスします。
---

ポートフォワードは、Pod または Service のポートを、このコンピューターからアクセスできるようにします。データベース、管理 UI、内部 API に、`LoadBalancer` も Ingress も、`kubectl port-forward` を実行したまま開いておくターミナルも使わずにアクセスできます。

## ポートのフォワード

- **Pod** のページでは、コンテナが宣言しているポートが表示され、各 TCP ポートの横に **フォワード…** があります。
- **Service** のページでは、各 TCP ポートの横に **フォワード…** があります。

ローカルのポートを選びます。そのポートがこのコンピューターで空いていれば同じ番号が、そうでなければ空欄が最初に入っています。空欄のままにすると、Homeport が空いているポートを選びます。トーストに待ち受けているアドレスが表示され、**開く** でブラウザーに読み込めます。

フォワードはループバックアドレス（`127.0.0.1`、および同じポートが空いていれば `[::1]`）でのみ待ち受けるので、ネットワーク上のほかのものからはアクセスできません。

### Pod と Service

**Pod** へのフォワードは、その Pod にアクセスします。Pod がなくなると（ロールアウトで置き換えられた場合など）、フォワードは終了し、Homeport がその旨を表示します。

**Service** へのフォワードは、`kubectl port-forward svc/…` と同じく、準備完了の Pod の 1 つを経由して、Service がそのポートを送る先のポート（番号またはコンテナポートの名前で指定された `targetPort`）に届きます。その Pod がなくなると、次の接続では準備完了の別の Pod が選ばれるので、Service へのフォワードはロールアウトの後も続きます。接続を Pod 間で分散することはありません。

フォワードできるのは TCP だけです。セレクターのない Service（外部のエンドポイントを指すもの）はフォワードできません。

## ポートフォワード

クラスターのサイドバーにある **ポートフォワード** には、すべてのクラスターにわたって実行中のフォワードが一覧表示されます。それぞれ、ローカルのアドレス、アクセス先の Pod または Service とポート（Service の場合は、現在経由している Pod も）、Namespace とクラスター、そこを通じて開いている接続の数が表示されます。**開く** はブラウザーに読み込み、**停止** はフォワードを終了して接続を閉じます。

フォワードは Homeport が動作している間だけ存在します。Homeport を終了するとすべて停止し、次回の起動時に復元されるものはありません。クラスターを削除または無効にした場合も、そのフォワードは停止します。

## うまくいかない場合

- **ポートが使用中**: ほかのプログラムがすでにそのローカルのポートで待ち受けています。別のポートを選ぶか、空欄のままにしてください。
- **1024 未満のポート**: ほとんどのシステムでは、アプリがこれらのポートで待ち受けることは許可されていません。より大きい番号のローカルのポートを選んでください。
- **実行されていない**、**準備完了の Pod がない**: まだフォワード先がありません。理由は Pod のページに表示されます。
- **許可されていない**: フォワードには `pods/portforward` に対する `create` が必要です。Homeport はそれを、確認用の `kubectl auth can-i` コマンドとともに示します。
