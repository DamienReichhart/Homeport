**クラスター** は、Homeport が API を通じて接続する Kubernetes クラスター、または [Nomad クラスター](/docs/clusters/nomad/)です。このセクションでは Kubernetes のクラスターを扱います。Nomad のクラスターには[専用のページ](/docs/clusters/nomad/)があります。Kubernetes のクラスターは、Homeport が API サーバーを通じて到達するクラスターです。クラスターは kubeconfig（`kubectl` がすでに使っているファイル）のコンテキストから追加するので、新しい認証情報を作る必要はありません。また、Homeport はクラスターに何もインストールしません。kubeconfig ですでに到達できる Kubernetes API と、その認証情報が持つ権限の範囲でやり取りするだけです。

クラスターは、サイドバー上部の切り替えメニューでホストの隣に並びます。クラスターを選ぶと、そのクラスターについてのページ（**ワークロード**、**Pod**、**ネットワーク**、**構成**、**Node**、**イベント**、**API リソース**、**YAML を適用**、**Helm**、**ポートフォワード**）と、[概要](/docs/guides/overview/#選択したクラスター)のサマリーが表示されます。ホストを選ぶと、ホストのページに戻ります。

## できること

クラスターで何が動いていて、正常かどうかをリアルタイムで確認でき、日常的な `kubectl` の作業を Homeport から行えます:

1. kubeconfig から[クラスターを追加](#クラスターの追加)するか、[ローカルのクラスター](/docs/clusters/local/)をワンクリックで追加します。クラウドのクラスターは [exec プラグイン](/docs/clusters/exec-plugins/)でサインインします。
2. [ワークロードと Pod](/docs/clusters/workloads/)、[Service、Ingress、ConfigMap、Secret](/docs/clusters/networking-config/)、[Node とイベント](/docs/clusters/nodes-events/)、そしてカスタムリソースを含む[その他すべての API リソース](/docs/clusters/api-resources/)を閲覧します。
3. Pod やワークロードの[ログを読み、コンテナでターミナルを開き](/docs/clusters/logs-exec/)、[ポートをこのコンピューターにフォワード](/docs/clusters/port-forward/)します。
4. [スケール、再起動、削除](/docs/clusters/actions/)を行い、変更内容をプレビューしながら [YAML を適用または編集](/docs/clusters/yaml/)します。
5. このコンピューターの `helm` CLI を使って、[Helm のリリース](/docs/clusters/helm/)の一覧表示、インストール、アップグレード、ロールバック、アンインストールを行い、helm のチャートリポジトリを管理します。

すべての変更は、認証情報の権限で Kubernetes API に送られます。何かを削除または置き換える操作は、クラスター名を示したうえで事前に確認を求めます。

## クラスターの追加

<DocScreenshot
  name="add-cluster"
  alt="「クラスターを追加」ページ。上部にこのマシンで見つかったローカルのクラスター、その下に ~/.kube/config のコンテキストが、API サーバー、サインイン方法、追加済みかどうかとともに並んでいる。"
/>

切り替えメニューで **クラスターを追加…** を選ぶか、「クラスター」ページで **クラスターを追加** を選びます。[ローカルのクラスター](/docs/clusters/local/)（Docker Desktop、OrbStack、Rancher Desktop、kind、k3d、minikube）は上部に表示され、それぞれワンクリックで追加できます。選んだコンテキストはそれぞれ 1 つのクラスターになり、コンテキストの名前が付きます。名前はインポートの前でも後でも変更できます。

- **このマシンの kubeconfig から** は、`KUBECONFIG` に列挙されたファイルを `kubectl` と同じ方法でマージして読み込みます。`KUBECONFIG` が設定されていない場合は `~/.kube/config` を読み込みます。現在のコンテキストがあらかじめ選択されます。
- **kubeconfig を貼り付け** は、貼り付けたテキストをメモリ上でだけ読み込み、ファイルとして保存することはありません。そこから参照されるファイル（`certificate-authority: /…`）はフルパスでなければなりません。いちばん簡単なのは、すべてを埋め込んだものを貼り付けることです:

  ```bash
  kubectl config view --raw --flatten --minify
  ```

各コンテキストには、API サーバー、Namespace、ユーザーのサインイン方法（**クライアント証明書**、**トークン**、**OpenID Connect**、クラウドの場合は **Exec プラグイン（aws）** など）が表示されるので、インポートする前にローカルのクラスターと本番のクラスターを見分けられます。追加したいものにチェックを入れてください。それぞれにコンテキストの名前が入った名前欄が付きます。`arn:aws:eks:…:cluster/prod` のような長い ARN は、`eks-prod` のような短い名前に変えておくとよいでしょう。切り替えメニューと概要に表示されるのはこの名前です。

すでにクラスターになっているコンテキストを二重にインポートすることはできません。代わりに Homeport は **更新する** を提示します。使えないコンテキストには理由が表示されます。たとえば、`auth-provider` が `gcp` や `azure` のユーザーです。これらは Kubernetes から削除されました（`kubectl` が現在求めているとおり、`gke-gcloud-auth-plugin` か `kubelogin` に切り替えてください）。

ユーザーは、クライアント証明書、トークン（または `tokenFile`）、ユーザー名とパスワード、OpenID Connect の `auth-provider`（ID トークンはメモリ上で更新されます）、または exec プラグインでサインインできます。

## 保存される場所

| Homeport のデータベースに平文で保持                                     | 暗号化した状態でのみ保持（SSH キーと同様）                               |
| ----------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 名前、API サーバーの URL、コンテキストの Namespace                      | CA 証明書、クライアント証明書とキー                                      |
| ユーザーのサインイン方法（証明書、トークン…）、インポート元コンテキスト | トークンまたはパスワード、OIDC トークン、exec プラグインの引数と環境変数 |

kubeconfig が参照するファイルはインポート時に一度だけ読み込まれ、ほかのものと一緒に暗号化して保存されます。kubeconfig が変更されることはありません。OS のキーチェーンがない場合、Homeport は認証情報を保存できないため、クラスターを追加しません。[セキュリティとデータ](/docs/reference/security/)を参照してください。

## kubeconfig からの更新

kind、k3d、minikube はクラスターを作り直すたびに新しい証明書を発行し、クラウドの認証情報も更新されます。クラスターのページの **kubeconfig から更新** は、そのコンテキストを読み込み直し（このマシンの kubeconfig から、または貼り付けで追加したクラスターの場合はもう一度貼り付けた kubeconfig から）、名前はそのままで再接続します。

## クラスターの管理

- 切り替えメニューの **クラスターを管理** には、すべてのクラスターがステータス、API サーバー、サインイン方法とともに一覧表示されます。
- クラスターのページでは、**有効** スイッチでクラスターを破棄せずに切断でき、**再接続** ですぐに再試行し、**名前を変更** で Homeport 内での名前だけを変更します。
- **クラスターを削除** は、クラスターと保存された認証情報を破棄します。クラスター上や kubeconfig では何も変わりません。

クラスター名は、大文字と小文字を区別せずに一意でなければなりません。

## ステータス

| ステータス                   | 意味                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| **接続済み**                 | API サーバーが応答しています。横に Kubernetes のバージョンが表示されます。                                          |
| **接続中**                   | Homeport が接続しようとしています。                                                                                 |
| **到達不能**                 | API サーバーが応答しませんでした。Homeport は 1 秒から最大 1 分の間隔を空けて、自動で再試行します。                 |
| **アクセスが拒否されました** | API サーバーが認証情報を拒否しました。そのコンテキストで `kubectl` が動作することを確認してから、更新してください。 |
| **設定に誤りがあります**     | 一致しない証明書など、ユーザーにしか直せない問題があります。Homeport は直されるまで待機します。                     |
| **認証情報が失われました**   | 認証情報を保護している OS のキーチェーンの鍵がなくなりました。kubeconfig からクラスターを更新してください。         |
| **無効**                     | **有効** スイッチでオフにされています。                                                                             |

接続済みのクラスターは 15 秒ごとに確認されます。そのため、ホストと同じく、クラスターがなくなればそれが表示され、戻ってくれば自動で再接続します。
