クラスターは、Kubernetes のクラスターだけでなく **Nomad** のクラスターにもできます。Homeport は、Nomad エージェント（サーバーまたはクライアント）がすでに提供している HTTP API と、コンピューターからやり取りします。クラスターには何もインストールされず、このマシンに `nomad` CLI も必要ありません。Homeport が行うことはすべて、指定した ACL トークンの権限で API を通じて行われます。

Nomad のクラスターは、切り替えメニューでホストや Kubernetes のクラスターの隣に並びます。選ぶと、概要にバージョン、リージョン、アドレスが表示され、サイドバーには専用のページが表示されます: **[ジョブ](#ジョブ)**（[ジョブを実行](#ジョブの実行)したり、アロケーションの[ログとシェル](#ログとシェル)を開いたりする場所）と **[ノード](#ノード)** です。選択している間、Kubernetes のページは非表示になります。

できることを、このページで説明する順に挙げます:

1. アドレスで[クラスターを追加](#nomad-クラスターの追加)します。使っている場合は [TLS](#tls) と [ACL トークン](#acl-トークン)も指定します。
2. [ジョブ](#ジョブ)とそのアロケーションをリアルタイムで確認し、停止、パージ、スケールします。
3. Nomad の計画を確認したうえで HCL または JSON から[ジョブを実行](#ジョブの実行)し、ジョブを編集して再実行します。
4. タスクの[ログを追い、シェルを開きます](#ログとシェル)。
5. [ノードをドレイン](#ノード)し、その対象可否を切り替えます。
6. [名前空間](#名前空間)を 1 つ、またはすべてを選びます。

## Nomad クラスターの追加

切り替えメニューで **クラスターを追加…** を選び、**Nomad** タブを選んで、次の項目を入力します:

- **名前**: 切り替えメニューと概要に表示される名前です（例: `nomad-prod`）。
- **アドレス**: エージェントの HTTP API です。`NOMAD_ADDR` で `nomad` CLI に渡すのと同じものです。`nomad.example.com` は `http://nomad.example.com:4646` になります。ポートを指定しなければ 4646 が追加され、TLS の証明書類を指定すると `https://` が使われます。
- **リージョン**: 空欄にすると、エージェント自身のリージョンを使います。`NOMAD_REGION` と同じく、連携したエージェントを通じて別のリージョンを管理するときに設定します。
- **ACL トークン**: クラスターで ACL が有効な場合の、トークンのシークレット ID です。下記の[トークン](#acl-トークン)を参照してください。

**接続をテスト** は、保存せずに一度接続し、Nomad のバージョンとリージョン、または接続できない理由を表示します。**クラスターを追加** は保存して接続します。その後、クラスターのページにステータス、バージョン、リージョンが表示され、これらの設定をどれでも変更できます。トークンと TLS のキーが再び表示されることはなく、空欄のままにした項目は保存済みの値が維持されます。保存済みの認証情報の横にある **削除** を選ぶと、保存時にそれが削除されます。

## TLS

公開 CA の証明書、またはコンピューターがすでに信頼している CA の証明書で HTTPS を提供しているエージェントには、`https://` のアドレスだけで十分です。それ以外の場合は **TLS 設定** を開き、`nomad` CLI に渡す PEM ファイルの内容を貼り付けます:

| 項目                                           | `nomad` CLI の変数                      | 必要になる場合                                                                                                                                     |
| ---------------------------------------------- | --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **CA 証明書**                                  | `NOMAD_CACERT`                          | エージェントの証明書が、`nomad-agent-ca.pem` のような独自の CA で署名されている場合。                                                              |
| **クライアント証明書** と **クライアントキー** | `NOMAD_CLIENT_CERT`、`NOMAD_CLIENT_KEY` | エージェントがクライアント証明書を求める場合（`verify_https_client`）。両方を指定するか、どちらも指定しないでください。                            |
| **TLS サーバー名**                             | `NOMAD_TLS_SERVER_NAME`                 | 証明書がアドレスの名前用に作られていない場合。Nomad 自身の証明書は `server.global.nomad` 用に作られており、`global` の部分はリージョンになります。 |

CA 証明書を指定すると、`nomad` CLI と同じく、このクラスターではその CA だけが信頼されます。

## ACL トークン

Homeport は、トークンを各リクエストの `X-Nomad-Token` ヘッダーで送り、URL に含めることはありません。接続中は 15 秒ごとにトークンを確認します。Nomad が認識しないトークン（削除された、期限切れ、入力ミス）の場合、新しいトークンを貼り付けるまで、接続は **アクセスが拒否されました** で止まります。

エージェントを読み取れない（`agent:read` がない）トークンでも接続はできます。その場合、クラスターのページにはリージョンが表示されますが、バージョンは表示されません。

## ジョブ

**ジョブ** には、選択したクラスターのジョブが、種類（`service`、`batch`、`system`、`sysbatch`）、ステータス、タスクグループが実行しているアロケーションの数と必要な数とともに一覧表示されます。ページは開いている間、最新の状態に保たれます。Homeport は Nomad に[ブロッキングクエリ](https://developer.hashicorp.com/nomad/api-docs#blocking-queries)で問い合わせるので、何かが変わるとすぐに Nomad が応答し、ポーリングは行いません。ページを離れるとクエリは終了します。

ジョブを開くと、その設定（優先度、データセンター、ノードプール、バージョン）、タスクとドライバーを含む **タスクグループ**、それぞれが実行されているノードとともに新しい順に並んだ **アロケーション** が表示されます。

- **停止** は、ジョブとその名前空間を示して確認を求めます。Nomad はすべてのアロケーションを停止し、ガベージコレクションが実行されるまでジョブの定義を保持します。`nomad job stop -purge` と同じく、ジョブとその履歴をすぐに削除するには **パージする** にチェックを入れます。パージはデフォルトでオフです。
- `service` または `batch` のジョブのタスクグループにある **スケール** は、`nomad job scale` と同じく、実行するアロケーションの数を設定します。グループに `scaling` ブロックがある場合、数はその `min` と `max` の範囲内でなければなりません。Homeport は範囲外の数を Nomad に問い合わせる前に拒否し、Nomad が拒否した場合は、デプロイメントの進行中など、Nomad 自身の理由を表示します。ポリシーに基づいて動作するオートスケーラーが、数を再び変更することもあります。

ジョブの一覧表示には `list-jobs` と `read-job` のケイパビリティが、停止には `submit-job` が、スケールには `scale-job`（または `submit-job`）が、ジョブの名前空間で必要です。

## ジョブの実行

「ジョブ」ページの **ジョブを実行** は、HCL2 または JSON のジョブ仕様を受け付けます。書くか、貼り付けるか、**ファイルを開く…** で `.nomad.hcl`、`.hcl`、`.json` のファイルを読み込みます。Homeport は最初の文字（JSON なら `{`）で 2 つの形式を見分け、Nomad 自身のエンドポイントを使うので、ここに HCL パーサーや `nomad` CLI は必要ありません。

1. **計画** は、`nomad job plan` と同じく、Nomad に HCL を解析させ、実行すると何が変わるかを問い合わせます。タスクグループごとに、配置、停止、インプレース更新、置き換えされるアロケーション、変わるフィールド（イメージ、数、引数…）、そして Nomad が配置できないアロケーションとその理由（制約で除外されたノード、メモリや CPU の不足）が示されます。この時点ではクラスター上で何も変わりません。
2. **実行** は、計画したとおりにジョブを投入します。その間にほかの誰かがジョブを実行または停止していた場合、Nomad は拒否し、Homeport はその変更を上書きせずにその旨を表示します。もう一度計画して確認してください。配置できないアロケーションがある計画では **それでも実行** が提示され、ノードが受け入れられるまでそれらはキューに入ります。

解析できない仕様では、Nomad が問題を見つけた行と列が示され、Nomad のメッセージは **詳細** に表示されます。JSON の仕様は Nomad の API 形式のジョブで、`nomad job inspect` が出力する `{"Job": {…}}` か、ジョブのオブジェクトそのもののどちらでもかまいません。

`namespace` を指定したジョブはその名前空間に入ります。指定していないジョブは、「ジョブ」ページで選択した名前空間、または `default` に入ります。`variable` ブロックは、デフォルト値があれば動作します。Homeport は変数ファイル（`-var-file`）を渡しません。

ジョブのページの **編集して実行** は、同じダイアログを、投入されたときのジョブ仕様で開きます（Nomad が保持している場合。Nomad 1.6 以降は、ソースとともに投入されたジョブのソースを保持します）。保持していない場合は JSON で開きます。Homeport は仕様のコピーを一切保持しません。Nomad がジョブとともに保存します。

計画と実行には、ジョブの名前空間での `submit-job` ケイパビリティが必要です。

## ログとシェル

ジョブのページからアロケーションを開くと、そのタスク、状態と再起動回数、最近のイベント（受信、起動、終了、ドライバーの失敗…）が表示され、ページを開いている間は最新の状態に保たれます。2 つのタブがタスクの 1 つを対象に動作します。タスクグループに複数のタスクがある場合は、どれを対象にするか選びます。

- **ログ** は、`nomad alloc logs -f` と同じく、タスクの stdout と stderr を最後の数行からリアルタイムで追います。どちらかのストリームをオフにしたり、検索したり、表示されている内容を **ダウンロード** したりできます。ログはタスクが停止した後も、アロケーションがガベージコレクションされるまで読めます。
- **シェル** は、`nomad alloc exec -t` と同じく、実行中のタスクで対話型のターミナルを開きます。デフォルトは `/bin/sh` で、入力したコマンド（`/bin/bash`、`/busybox/sh`、任意のプログラム）も使えます。ウィンドウに合わせてサイズが変わり、コマンドの終了コードを報告します。**再接続** で新しいものを開始します。タブを離れると、ノード上のコマンドは終了します。

どちらも Nomad の HTTP API を経由します。サーバーがアロケーションを実行しているクライアントノードに転送するので、Homeport はノードへの SSH アクセスを必要とせず、ノードに何もインストールしません。トークンはヘッダーで送られ、WebSocket の URL に含まれることはありません。

| 目的                 | トークンに必要なもの（ジョブの名前空間で）                               |
| -------------------- | ------------------------------------------------------------------------ |
| アロケーションを見る | `read-job`                                                               |
| ログを読む           | `read-logs`                                                              |
| シェルを開く         | `alloc-exec`、`raw_exec` ドライバーを使うタスクには `alloc-node-exec` も |

実行されていないタスク、サーバーが到達できないノード、ケイパビリティのないトークンには、それぞれ専用のメッセージが表示されます。

## ノード

**ノード** には、クラスターのクライアントノードが、ステータス（準備完了、初期化中、ダウン、切断）、新しいアロケーションを受け入れるかどうか、データセンターとノードプール、それぞれで実行されているアロケーションの数、アドレス、Nomad のバージョンとともに一覧表示されます。ノードを開くと、ドライバーとその正常性、オペレーティングシステムと CPU、実行しているアロケーションが表示されます。

- **ドレイン** は、`nomad node drain -enable` と同じく、確認を求めます。Nomad はノードを対象外にし、`migrate` ブロックが許す範囲でアロケーションをほかのノードに移動します。**期限** はデフォルトで 1 時間です（`30m`、`2h`、`1h30m`…）。期限を過ぎると、まだ残っているアロケーションは停止されます。すべてが移動するまで待つには **期限なし** に、`-ignore-system` と同じくシステムジョブをそのノードに残すには **システムジョブはこのノードで実行したままにする** にチェックを入れます。その後、ノードのページにはドレインの進捗として、そこでまだ実行されているアロケーションの数が、なくなるまで表示されます。
- **ドレインをキャンセル** は、進行中のドレインを止め、ノードを再び対象にします。すでに移動したアロケーションは移動先に残ります。
- **新しいアロケーションの対象にする** は、`nomad node eligibility -enable` と `-disable` と同じく、ノードで実行中のものを移動せずに、ノードをスケジューリングの対象に入れたり外したりします。

ノードの読み取りには `policy = "read"` の `node` ルールが、ドレインと対象可否の変更には `policy = "write"` が必要です。Homeport はノードプールの管理、ノードのパージ、ガベージコレクションの実行は行いません。

## 名前空間

名前空間のあるクラスターでは、「ジョブ」ページに **名前空間** の選択欄が表示されます。最初は `default` で、その後は選んだ名前空間になり、再起動後もクラスターごとに記憶されます。**すべての名前空間** を選ぶと、`nomad job status -namespace '*'` と同じく、トークンが読み取れるすべての名前空間のジョブが、**名前空間** 列とともに一覧表示されます。

**ジョブを実行** は、仕様で指定された名前空間にジョブを送ります。指定していないジョブは、選んだ名前空間、またはすべてを表示している間は `default` に入ります。ジョブ自身のページ、そのアロケーション、そのログとシェルは、常にジョブの名前空間を使います。

名前空間を一覧表示できないトークンや、名前空間のないクラスターでは、デフォルトの名前空間が選択欄もエラーもなしに表示されます。Homeport は名前空間の作成、編集、削除は行いません。

## ACL ポリシー

ACL が有効なクラスターでは、使う機能を許可するポリシーを持つ、Homeport 専用のトークンを渡してください。次のポリシーは Homeport が行うことをすべてカバーします:

```hcl title="homeport.hcl"
namespace "*" {
  policy       = "read"
  capabilities = ["submit-job", "scale-job", "read-logs", "alloc-exec"]
}

node {
  policy = "write"
}

agent {
  policy = "read"
}
```

次のポリシーでは、Homeport は閲覧だけができます。ジョブ、アロケーション、そのログ、ノード、名前空間を見られますが、変更もシェルもできません:

```hcl title="homeport-read.hcl"
namespace "*" {
  policy       = "read"
  capabilities = ["read-logs"]
}

node {
  policy = "read"
}

agent {
  policy = "read"
}
```

どちらかを適用してトークンを作り、そのトークンのシークレット ID をクラスターの設定に貼り付けます:

```bash
nomad acl policy apply -description "Homeport" homeport homeport.hcl
nomad acl token create -name=homeport -policy=homeport
```

Homeport を特定の名前空間に限定するには `"*"` をその名前空間の名前に置き換え、`raw_exec` ドライバーを使うタスクでシェルを開くにはケイパビリティに `alloc-node-exec` を追加します。それぞれに必要なもの:

| Homeport が行うこと                            | 必要なもの                                      |
| ---------------------------------------------- | ----------------------------------------------- |
| クラスターのバージョンを表示する               | `agent` `read`（任意: なくても接続できます）    |
| ジョブ、アロケーション、名前空間を一覧表示する | 名前空間での `read`                             |
| ジョブを計画して実行する、停止する             | 名前空間での `submit-job`                       |
| タスクグループをスケールする                   | 名前空間での `scale-job`（または `submit-job`） |
| タスクのログを読む                             | 名前空間での `read-logs`                        |
| シェルを開く                                   | 名前空間での `alloc-exec`                       |
| ノードを一覧表示する                           | `node` `read`                                   |
| ノードをドレインする、対象可否を変更する       | `node` `write`                                  |

## ステータスと問題

ステータスは [Kubernetes のクラスター](/docs/clusters/#ステータス)と同じルールに従います。エージェントに到達できない間、Homeport は自動で再試行し、ユーザーにしか直せない問題の場合は直されるまで待機します。

- **アドレスが間違っている**: 見つからない名前、拒否された接続、タイムアウトのいずれかが、試したアドレスとともに示されます。
- **証明書の期限切れ、不明な CA、名前の不一致**: それぞれ **TLS 設定** で何を変えればよいかが示されます。
- **エージェントが HTTPS でしか応答しない**、またはまったく TLS を使っていない: アドレスの `http://` または `https://` を変更してください。
- **リーダーがいない**: クラスターのサーバーがリーダーについて合意できず、何も読み取れません。Nomad はサーバーの過半数が動作している必要があります。サーバー上で `nomad server members` を実行して確認してください。

## 保存される場所

| Homeport のデータベースに平文で保持                      | 暗号化した状態でのみ保持（SSH キーと同様） |
| -------------------------------------------------------- | ------------------------------------------ |
| 名前、アドレス、リージョン、TLS サーバー名               | ACL トークン                               |
| トークン、CA、クライアント証明書が保存されているかどうか | CA 証明書、クライアント証明書とそのキー    |

Homeport の[データのバックアップ](/docs/reference/security/)には、Kubernetes のクラスターと同じく、Nomad のクラスターも認証情報とともに含まれます。
