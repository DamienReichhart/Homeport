クラスターのサイドバーにある **Helm** には、そのクラスター上の [Helm](https://helm.sh) リリースが表示されます。ターミナルで `helm list` が表示するのと同じリリースで、Homeport からインストールしたものかどうかは問いません。

## Homeport に必要なもの

Homeport は、**この** コンピューター上で `helm` コマンド（バージョン 3 以降）を実行します。macOS では `brew install helm`、Windows では `winget install Helm.Helm`（または Chocolatey、Scoop）、Linux では `snap install helm --classic`、ディストリビューションのパッケージ、または helm.sh のスクリプトでインストールしてください。**設定 → このマシン** に、Homeport が見つけた helm が表示されます。見つからない場合、Helm のページにはシステムに合わせてインストールするものが表示され、クラスターのほかのページはすべて動作します。

Homeport は kubeconfig を helm に渡しません。helm のコマンドごとに、このコンピューターのループバックアドレス上にクラスターへのプライベートな接続を開き、それを指す一時的な kubeconfig を helm に渡します。この kubeconfig には使い捨てのトークンだけが含まれ、クラスターの認証情報は含まれません。Homeport は、ほかのすべてのページと同じく、各リクエストの途中でクラスター自身の認証情報（証明書、トークン、exec プラグインのトークン）を追加し、コマンドが終わると kubeconfig を削除します。そのため helm は、exec プラグインを使うクラウドのクラスターを含め、Homeport が到達できるすべてのクラスターに到達でき、認証情報がディスクに書き込まれることはありません。

Helm はリリースを各リリースの Namespace に Secret として保持します。Homeport はクラスターに何もインストールしません。

## リリース

一覧には、各リリースの名前、Namespace、チャートとチャートのバージョン、アプリのバージョン、リビジョン、ステータス、最後に変更された時刻が表示されます。右上で Namespace を選ぶか、すべての Namespace を選びます。helm にはリアルタイムの更新がないため、一覧は開いている間 30 秒ごとに問い合わせ直し、**更新** ですぐに問い合わせます。

**failed** のリリースは赤で、インストール、アップグレード、ロールバックが **pending** のリリース（`pending-install`、`pending-upgrade`、`pending-rollback`）は琥珀色で示されます。pending のリリースは、その操作が終わるまでロックされます。

認証情報ですべての Namespace の Secret を一覧表示できない場合、Homeport は代わりにクラスターのデフォルトの Namespace のリリースを一覧表示し、その旨を表示します。ほかの Namespace のリリースを見るには、その Namespace を選んでください。

## チャートのインストール

「リリース」タブの **チャートをインストール**（または <kbd>n</kbd>）は、選択したクラスターにチャートをインストールします:

1. **チャートを選びます。** helm の[リポジトリ](#chart-repositories)のチャートを検索して **使用** をクリックするか、**OCI レジストリから** で `oci://registry-1.docker.io/bitnamicharts/nginx` のような参照を指定します。後者はリポジトリを追加せずにインストールします。
2. **バージョン、名前、Namespace を選びます。** リポジトリのチャートはバージョンが新しい順に一覧表示されます。OCI のチャートはバージョンを入力するか、空欄にすると最新になります。リリースの名前は最初はチャートの名前で、英小文字、数字、ハイフン、ドットで 53 文字以内です。Namespace はページに表示されているもの（またはクラスターのデフォルト）で、存在しなければ作成されます（チェックを外せば作成されません）。
3. **値を編集します。** エディターはチャートのデフォルト値（`helm show values`）で始まります。必要なものを変更してください。**チャートのデフォルトに戻す** で元に戻せます。値は helm を実行する前に YAML として検証され、helm には標準入力で渡されます。ファイルに書かれることはありません。
4. 必要に応じて **プレビュー** します。helm が入力した値とクラスターの助けを借りてチャートをレンダリングし（`--dry-run=server`）、Homeport はフックを含めて適用されるマニフェストと、チャートのノートを表示します。クラスター上では何も変わりません。
5. **インストールします。** helm の出力が、`helm install` が出力するとおりにストリーミングされます。**リソースの準備が完了するまで待機** を選ぶと、helm はリリースの Deployment、Pod、Service の準備が完了するのを、指定した分数（デフォルトは 5 分）まで待ち、完了しなければリリースを失敗とします。その後、**リリースを開く** でリリースのページを開きます。

ローカルのフォルダーや `.tgz` ファイルからのチャートは、Homeport からはインストールしません。ログインが必要な OCI レジストリのチャートも、ターミナルで `helm registry login` でサインインしていない限りインストールしません。

## リリースのページ

リリースをクリックすると開きます:

- **履歴**: すべてのリビジョンが新しい順に、日付、ステータス、チャート、アプリのバージョン、何が起きたかについての helm の説明（`Install complete`、`Upgrade "web" failed: …`）とともに表示されます。
- **値**: インストールやアップグレードで指定された値（**ユーザー指定**）、またはデフォルトを含め、チャートのレンダリングに使われたすべての値（**計算済み**）。
- **ノート**: インストール後にチャートが出力する内容（`NOTES.txt`）。
- **マニフェスト**: そのリビジョンがレンダリングした Kubernetes オブジェクトの YAML。
- **リソース**: それらのオブジェクトを種類、名前、Namespace で示し、それぞれ Homeport のページを開きます。Deployment、Pod、Service などはそれぞれ専用のページ、それ以外は [API リソース](/docs/clusters/api-resources/)のページです。

値、ノート、マニフェスト、リソースには現在のリビジョンが表示されます。その上で以前のリビジョンを選ぶと、そのリビジョンが何でインストールされたかを確認できます。

## リリースのアップグレード

リリースのページの **アップグレード** は、チャートのバージョン、値、またはその両方を変更します:

- **チャート**: アップグレード元のチャートです。helm はチャートの取得元を記録しないため、Homeport はリポジトリからその名前のチャートを探し、リリースの現在のバージョンを持つリポジトリを優先します。**別のチャート…** で、`repository/chart` または `oci://` の参照としてほかのチャートを選べます。OCI レジストリからインストールしたリリースには、これが必要です。
- **チャートのバージョン**: そのチャートのバージョンが新しい順に並びます。OCI のチャートの場合は入力します。
- **値**: エディターはリリースのユーザー指定の値で始まります。これがリリースの値を置き換え、残りはチャートのデフォルトで補われます。**値の変更** では現在の値と並べて表示し、**現在の値に戻す** で元に戻せます。
- **リソースの準備が完了するまで待機**: 指定した分数まで待ちます。

**プレビュー** は、何も変更せずにクラスターの助けを借りてアップグレードをレンダリングし、新しいマニフェストと、現在のものとの違いを表示します。**アップグレード** は `helm upgrade` を実行し、helm の出力をリアルタイムで表示します。アップグレードのたびに **履歴** に新しいリビジョンが追加されます。

## ロールバック

**履歴** で、以前の任意のリビジョンにある **リビジョン N にロールバック** は、現在と変更後のチャートとアプリのバージョンを示して確認を求めてから、`helm rollback` を実行します。helm はそのリビジョンのチャートと値を新しいリビジョンとして戻すので、ロールバック自体もロールバックできます。helm にリソースを待たせるには、**リソースの準備が完了するまで待機** にチェックを入れます。

インストール、アップグレード、ロールバックが中断されて **pending** のままになったリリースはロックされています。helm は、その操作が終わるまで変更を拒否します。最後にデプロイされたリビジョンにロールバックすると、ロックが解除されます。

## アンインストール

リリースのページの **アンインストール** は、`helm uninstall` を実行する前に、リリース、その Namespace とクラスターの名前を示し、一緒に削除されるオブジェクトを一覧表示します。チャートが保持するよう指定したオブジェクト（`helm.sh/resource-policy: keep`）と StatefulSet の PersistentVolumeClaim は、クラスターに残ります。**ロールバックできるように履歴を保持** を選ぶと、リリースは `uninstalled` として一覧に残り、ロールバックできます。選ばなければ、リリースは一覧から消えます。**オブジェクトが削除されるまで待機** を選ぶと、helm はオブジェクトの削除を待ちます。

## チャートリポジトリ

Helm のページの 2 つ目のタブである **チャートリポジトリ** には、このコンピューターの helm が知っているリポジトリが一覧表示されます。ターミナルで `helm repo list` が表示するのと同じ一覧で、すべてのクラスターで共有されます。Homeport は独自の一覧を持たないので、ターミナルで追加したリポジトリはここに表示され、ここで追加したリポジトリは `helm repo list` に表示されます。

- **リポジトリを追加** は、名前（英字、数字、ドット、ハイフン、アンダースコア）と、`https://charts.bitnami.com/bitnami` のようなリポジトリの `https://` URL を尋ね、そのインデックスをダウンロードします。
- **すべて更新**、または各リポジトリの **更新** は、`helm repo update` と同じく最新のインデックスをダウンロードし、helm の出力をリアルタイムで表示します。前回の更新以降に公開されたチャートは、更新した後に表示されます。
- **削除** は、確認の後にリポジトリを破棄します。そこからインストールしたリリースは動作し続けます。

**チャートを探す** は、`helm search repo` と同じく、これらのリポジトリのチャートを名前や説明で検索します。Bitnami のリポジトリを追加した後に `postgres` と入力すると、その PostgreSQL のチャートが、最新のチャートとアプリのバージョンとともに表示されます。

Homeport が追加するのは公開リポジトリだけです。ログインが必要なリポジトリは、ターミナルで `helm repo add --username …` を使って追加してください。helm はいつもどおりそのパスワードを保持します。追加したリポジトリはここに表示され、ほかのリポジトリと同じように使えます。OCI レジストリ（`oci://…`）のチャートにはリポジトリは不要です。

## うまくいかない場合

- **helm CLI がインストールされていない**: 上記のとおり helm 3 をインストールしてから、ページを開き直してください。
- **Helm 2**: Homeport が扱えるのは Helm 3 以降だけです。最新の helm をインストールしてください。
- **許可されていない**: helm はリリースを Secret から読み取ります。一覧表示には、その Namespace の `secrets` に対する `list` が必要です。何が拒否されたかは「詳細」に示されます。
- **別のインストール、アップグレード、ロールバックが進行中**: リリースが保留中の操作によってロックされています。それが終わるのを待つか、最後にデプロイされたリビジョンにロールバックしてください。
- **この名前のリリースがすでに存在する**: リリース名は Namespace 内で一意です。別の名前を選ぶか、既存のリリースをアップグレードしてください。
- **チャートまたはバージョンが見つからない**: 名前とバージョンを確認してください。リポジトリのチャートには、そのリポジトリを追加して[更新](#chart-repositories)しておく必要があります。自分のどのリポジトリにもないチャートのリリースをアップグレードするには、先にそのリポジトリを追加してください。
- **値が有効な YAML ではない**: メッセージに行が示されます。修正して再試行してください。
- **待機をあきらめた**: **待機** を選んでいた場合に、リソースが時間内に準備完了になりませんでした。何が止まっているかは、リリースの Pod とイベントで確認してください。
- **チャートリポジトリではない、または到達できない**: その URL が `index.yaml` を提供していないか、このコンピューターから到達できません。helm が出力した内容は「詳細」に表示されます。
- **接続されていない**: helm は Homeport のクラスターへの接続を経由します。接続されていない理由はクラスターのページに表示されます。
