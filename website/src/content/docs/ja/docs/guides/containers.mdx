**コンテナ** ページには、選択したホスト上のすべてのコンテナが、実行中かどうかにかかわらず一覧表示されます。

## 一覧

[スタック](/docs/guides/stacks/)に属するコンテナはその下にまとめられ、その後にスタンドアロンのコンテナが続きます。スタックの行には、実行中のコンテナの数と、それらの CPU とメモリの合計が表示されます。行を選ぶとグループが折りたたまれ、**スタックを開く** でスタックに移動します。

| 列             | 表示内容                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| **名前**       | 状態を示すドット、名前（スタック内ではサービス名）、短い ID。                                                |
| **イメージ**   | 作成元のイメージ。[新しいイメージ](#新しいイメージ)が公開されている場合は ⬆ の印が付きます。                   |
| **ステータス** | エンジンが報告するとおりの状態（例: _Up 3 hours (healthy)_）。ヘルスチェックがある場合はヘルスのバッジ付き。 |
| **ポート**     | 最大 3 つのポート。公開ポートが先です。公開ポートはリンクになっており、ブラウザーで開けます。                |
| **CPU**        | リアルタイム。1 CPU に対する割合で、`200%` は 2 CPU をフルに使っていることを意味します。                     |
| **メモリ**     | リアルタイム。カーネルが解放できるページキャッシュは含みません。                                             |
| **作成日時**   | どれくらい前に作成されたか。                                                                                 |

CPU とメモリは 2 秒ごとに更新されます。**コンテナを検索** は、名前、イメージ、スタック、サービス、ID の先頭部分に一致します。**実行中のみ** を選ぶと、それ以外は非表示になります。

コンテナを選ぶと、そのコンテナが開きます。

### 新しいイメージ

イメージの横の ⬆ は、コンテナの作成元のタグで、レジストリに別のイメージがあることを示します。プルした後に `nginx:1.27` が更新された場合や、新しいイメージをプルしたもののコンテナを作り直していない場合です。ポインターを合わせると、どれかがわかります。更新するには、イメージをプルしてコンテナを作り直します。スタックの場合は、**イメージをプル** してから **再デプロイ** します。

Homeport は、ホストのエンジンを通じてレジストリに問い合わせます。エンジンは何もプルせずにダイジェストを比較し、プライベートイメージには保存した[レジストリのログイン情報](/docs/guides/settings/#レジストリ)を使います。結果は 6 時間保持されるため、一覧をもう一度開いても問い合わせは発生しません。ページの上部にある **新しいイメージを確認** を選ぶと、すべてのレジストリに今すぐもう一度問い合わせます。ローカルでビルドしたイメージ、ダイジェストでプルしたイメージ（`app@sha256:…`）、レジストリに到達できないイメージでは、誤った警告を出す代わりに何も表示されません。コンテナのページでも、イメージの横に同じ印が表示されます。

### 操作

各行の末尾のボタンで、コンテナを起動または停止します。それ以外は **⋮** メニューにあります: **ログ**、**ターミナルを開く**、**再起動**、**一時停止** または **再開**、**強制終了**、**名前を変更**、[**編集**](#コンテナを編集する)、[**複製**](#コンテナを複製する)、[**イメージにコミット…**](#コンテナをコミットする)、[**ファイルシステムをエクスポート…**](#コンテナのファイルシステムをエクスポートする)、**削除**。

コンテナにチェックを入れると、**起動**、**停止**、**再起動**、**削除** で複数のコンテナをまとめて操作できます。スタックの行のチェックボックスでは、そのすべてのコンテナが選択されます。

<Aside type="caution" title="削除で消えるもの">
  コンテナを削除すると、コンテナ、その書き込み可能なレイヤー、匿名ボリュームが削除されます。名前付きボリュームは
  残ります。実行中のコンテナは、正常にシャットダウンするのを待たずに、すぐに停止されます。
</Aside>

**強制終了** はすぐに `SIGKILL` を送るため、プロセスには後処理をする機会がありません。**停止** は、まずコンテナの停止タイムアウトの時間を与えます。

## コンテナのページ

ヘッダーには、イメージと状態、そして **起動** または **停止**、**再起動**、**一時停止** または **再開**、**削除** が表示されます。その **⋮** メニューには、**名前を変更**、**編集**、**複製**、**イメージにコミット…**、**ファイルシステムをエクスポート…** があります。それ以外はすべて下のタブにあります。

<Aside>
  タブを離れると、そこで行っていたことは終了します。**Exec** を離れるとターミナルは閉じ、**統計**
  に戻るとグラフは 最初からになり、**ログ** は再読み込みされます。
</Aside>

### ログ

<DocScreenshot
  name="container-logs"
  alt="履歴、タイムスタンプ、ストリームのフィルター、検索が表示されたコンテナのログタブ。"
/>

ログは、コンテナが書き込むとリアルタイムで表示されます。ツールバーで表示内容を制御します:

- **履歴** — 読み込む過去の行数。最後の 100 行、1,000 行（既定）、10,000 行、またはすべて。
- **期間** — 全期間、または過去 5 分、1 時間、24 時間。
- **タイムスタンプ** — 各行の前にエンジンのタイムスタンプを表示します。
- **stdout** と **stderr** — それぞれのストリームを表示または非表示にします。
- **追従** — 最新の行まで自動でスクロールし続けます。オフでも新しい行は届き続けます。
- **ログ内を検索** — 一致する箇所をハイライトします。<kbd>Enter</kbd> で次の一致、<kbd>Shift</kbd>+<kbd>Enter</kbd> で前の一致に移動します。
- **クリア** は表示を空にします。**ログをダウンロード** は、読み込んだ内容を最大で最後の 100,000 行までテキストファイルとして保存します。

コンテナが停止すると、ログは _— ログの終わり —_ で終わります。

### 検査

**詳細** は、コンテナの情報をカードにまとめて表示します。状態と終了コード、コマンド、再起動ポリシー、ヘルスチェック、環境変数、マウント、ポート、ネットワーク、ラベルです。**生の JSON** には、エンジンの inspect の完全なドキュメントが表示されます。

<Aside type="caution">
  環境変数は、エンジンが保存しているとおり平文で表示されます。画面を共有する前に、このことに注意してください。
</Aside>

### ヘルス

ヘルスチェック（コンテナ独自のもの、またはイメージのもの）があるコンテナで表示されます。**ヘルスチェック** には、状態（_starting_、_healthy_、_unhealthy_）、コマンド、タイミング（設定されていない項目はエンジンの既定値: 30 秒ごと、タイムアウト 30 秒、リトライ 3 回）、連続して失敗したチェックの数が表示されます。**最近の結果** には、エンジンが保持しているチェックが新しい順に、終了コード、実行日時、所要時間、出力とともに一覧表示されます。長い出力は **さらに N 行を表示** の下に折りたたまれます。

そのため、一覧に _unhealthy_ と表示されたときは、生の JSON を読まなくても、ここで理由がわかります。タブは、チェックの間隔ごとと、状態が変わるたびに自動で更新されます。ヘルスチェックが無効になっているコンテナには、ヘルスタブはありません。ヘルスチェックを追加・変更するには、[コンテナを編集](#コンテナを編集する)します。

### Exec

<DocScreenshot name="container-terminal" alt="コンテナの Exec タブ内の対話型ターミナル。" />

実行中のコンテナ内の対話型ターミナルです。最初のターミナル **シェル** は自動で開き、`bash`、またはイメージに bash がない場合は `sh` を実行します。

**新しいターミナル** は、指定した **コマンド**、**ユーザー**、**ディレクトリ** で別のターミナルを開きます。たとえば、ユーザー `postgres` として `psql -U postgres` を実行できます。複数を同時に開くことができ、**×** で閉じます。ターミナルはウィンドウに合わせてサイズが変わります。

シェルのないイメージ（`scratch` や distroless のイメージ）では、既定のターミナルを開けません。

### ファイル

コンテナのファイルシステムを `/` から参照します。フォルダーを選ぶと開き、上部のパスを使って上の階層に戻ります。

- 行の末尾のボタンで、ファイル、またはフォルダー全体を `.tar` アーカイブとして **ダウンロード** します。
- **ここにアップロード** は、コンピューターのファイルを現在のフォルダーにコピーし、同じ名前のファイルを置き換えます。

ファイルの一覧表示はコンテナ内で `find` と `stat` を実行するため、それらのない最小構成のイメージは参照できません。転送はメモリ上で行われるため、非常に大きなファイルは `docker cp` でコピーするほうが適しています。

### 統計

直近 5 分間のリアルタイムのグラフで、1 秒ごとに更新されます: **CPU**、**メモリ**（コンテナの上限に対して）、**ネットワーク** の受信と送信、**ディスク I/O** の読み取りと書き込み、そしてプロセス数。

  name="container-stats"

### プロセス

コンテナ内で実行中のプロセスが、`ps aux` と同じ形式で表示され、5 秒ごとに更新されます。

## コンテナを実行する

コンテナページの **コンテナを実行**、またはイメージの横の ▶ ボタンを選ぶと、**コンテナを実行** が開きます:

| 項目                       | 説明                                                                                                                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **イメージ**               | 必須。ホストのイメージが候補として表示されます。ホストにない場合は、保存した[レジストリのログイン情報](/docs/guides/settings/#レジストリ)で先にプルされます。                      |
| **名前**                   | 任意。空の場合はエンジンが生成します。                                                                                                                                             |
| **コマンド**               | イメージの既定のコマンド（エントリーポイントではありません）を置き換えます。引数はシェルと同じようにクォートします。                                                               |
| **ポート**                 | **ホストポート** → **コンテナポート**、`tcp` または `udp`。ホストポートを空にすると、エンジンが空いているポートを選びます。ポートはすべてのインターフェースで公開されます。        |
| **ボリューム**             | ボリューム名または絶対パスの `/host/path` を、コンテナ内の絶対パスにマウントします。任意で **読み取り専用** にできます。まだ存在しない名前を指定すると、ボリュームが作成されます。 |
| **環境変数**               | 1 行に 1 つずつ `KEY=value`。空行と `#` で始まる行は無視されます。                                                                                                                 |
| **ネットワーク**           | **デフォルト（bridge）**、またはホスト上の任意のネットワーク。                                                                                                                     |
| **再起動**                 | **しない**、**失敗時**、**停止されていない限り**、**常に**。                                                                                                                       |
| **終了時にコンテナを削除** | `docker run --rm` と同じです。終了時に削除されるコンテナは、再起動もさせることはできません。                                                                                       |

**実行** を選ぶと、Homeport はコンテナを作成して起動し、そのログを開きます。

コンテナが起動できない場合（ポートがすでに使われているなど）、Homeport はそのコンテナを再び削除し、ダイアログは理由を表示したまま開いています。項目を修正して、同じ名前で実行できます。

### 詳細オプション

再起動ポリシーの下にある **詳細オプション** を開くと、あまり使わない設定がタブごとに表示されます。Homeport が読み取れない値には、その項目の下に説明が表示され、修正されるまで **実行** は待機します。ここで設定したものはすべて、コンテナの **検査** タブに表示されます。

**リソース**

| 項目                       | 説明                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------- |
| **CPU の上限**             | 使用できる CPU の数。`0.5` や `2` など（`--cpus`）。空の場合はすべての CPU を使います。                 |
| **CPU シェア**             | CPU が混雑しているときの、ほかのコンテナに対する重み。既定は `1024`（`--cpu-shares`）。                 |
| **メモリの上限**           | `512m` や `2g` など（`--memory`）。Docker と同じく、サイズは 1024 の累乗で数えます。最小 `6m`。         |
| **メモリの予約**           | ホストのメモリが不足したときにだけエンジンが適用するソフトリミット。上限以下にします。                  |
| **メモリとスワップの上限** | メモリとスワップの合計なので、メモリの上限以上にします。`-1` でスワップ無制限。メモリの上限が必要です。 |

**ラベル** — 1 行に 1 つずつ `key=value`。Traefik や Caddy などのリバースプロキシやバックアップツールが読み取ります。`com.docker.compose.` で始まるキーは拒否されます。これらは Docker Compose のもので、Homeport がコンテナをスタックの一部として表示してしまうためです。

**セキュリティ** — 追加するケーパビリティと削除するケーパビリティ（候補を見ながら 1 つずつ入力します。`NET_ADMIN` と `CAP_NET_ADMIN` は同じで、`ALL` はすべてを意味します）、そして **特権**。

<Aside type="danger" title="特権モード">
  特権コンテナはホストのすべてのデバイスとケーパビリティを使え、その中で動作するものはホストを乗っ取ることができます。
  できる限り、代わりに必要なケーパビリティとデバイスだけを追加してください。
</Aside>

**デバイス** — コンテナに渡すホストのデバイス（ハードウェアトランスコード用の `/dev/dri` や、Zigbee スティック用の `/dev/ttyUSB0` など）。コンテナ内のパス（空の場合は同じパス）と権限（`r`ead、`w`rite、デバイスファイルの `m`ake のいずれか）を指定します。**GPU** では、`docker run --gpus` と同じように、すべての GPU、指定した数の GPU、またはインデックスか UUID で選んだ GPU を要求します。

<Aside type="note" title="GPU にはベンダーのツールキットが必要です">
  ホストには GPU ベンダーのコンテナツールキット（NVIDIA の場合は [NVIDIA Container
  Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)）
  がインストールされ、その後 Docker Engine が再起動されている必要があります。Homeport
  はこれをインストールしません。ない場合、実行は _このホストはコンテナに GPU を割り当てられません。_
  で失敗します。
</Aside>

**ヘルスチェック** — **イメージ独自のもの** を使うか、`/bin/sh -c` で実行する **コマンド** を定義する（終了コード 0 は正常を意味します）か、**なし** でイメージのものを無効にします。**間隔**、**タイムアウト**、**開始猶予期間** には `30s` や `1m30s` のような期間を指定します。**リトライ** は、何回連続で失敗すると異常とみなすかです。その後、状態は一覧に _healthy_ または _unhealthy_ として表示されます。

**ネットワーク ID** — コンテナの **ホスト名** と **ドメイン名**、**DNS サーバー**（アドレス）と **DNS 検索ドメイン**、そして **追加のホスト**: ネットワークの DNS が知らない名前のために、コンテナの `/etc/hosts` に追加する `name:address` の行です。`host-gateway` はホスト自身のアドレスを表すため、`host.docker.internal:host-gateway` でホスト上のサービスに到達できます。

**ログ** — **ログドライバー**: `json-file`、`local`、`journald`、`syslog`、`none`、またはエンジンにあるほかのドライバー。空の場合はエンジンの既定を使います。**ドライバーのオプション** は `key=value` の行です。`json-file` では、`max-size=10m` と `max-file=3` で、ログが小さなホストのディスクを埋めるのを防げます。`journald`、`syslog`、`none` では、**ログ** タブが空のままになることがあります。

## コンテナを複製する

**複製** は、コンテナの設定（イメージ、コマンド、環境変数、ポート、ボリューム、ネットワーク、再起動ポリシー、すべての詳細オプション）を入力した状態で、`<name>-copy` という名前で実行ダイアログを開きます。必要なものを変更して **実行** を選びます。

ダイアログに表示されない設定（ulimit、sysctl、セキュリティオプション、tmpfs マウント、コンテナが接続しているほかのネットワークとそのエイリアスなど）は、そのままコピーされます。フォームから外されるのは、イメージから得ただけの設定だけです。そのため、新しいタグのイメージには、そのイメージ独自の既定値が適用されます。

コピーは、元のコンテナを識別するものは引き継ぎません。独自のホスト名（自分で設定しない限り）、MAC アドレス、新しい匿名ボリュームを持ち、[スタック](/docs/guides/stacks/)のコンテナの場合はスタックのラベルとサービスのエイリアスがなくなるため、コピーはスタックに加わらず、サービス名にも応答しません。元のコンテナが固定のホストポートを公開している場合は、ダイアログにその旨が表示されます。2 つのコンテナが同時に実行中にそのポートを使うことはできないため、変更するか、空にしてエンジンに選ばせてください。

## コンテナを編集する

Docker Engine は既存のコンテナのほとんどの設定を変更できないため、**編集** はコンテナを作り直します。コンテナの設定を入力した状態で実行ダイアログを開き、**適用** を選ぶと、変更内容から作成したコンテナに置き換えます。名前はそのままです（変更するには **名前を変更** を使います）。

何かを行う前に、Homeport は新しいコンテナが持たないものを一覧表示します:

- **匿名ボリューム** — 新しいコンテナは空の匿名ボリュームで始まります。古いものは削除されず、未使用のボリュームとして残るため、開いたり[未使用のものとして削除](/docs/guides/volumes-networks/)したりできます。
- 作成以降に **コンテナ内で変更されたファイル**（インストールしたパッケージや編集した設定など）。これを残すには、先に[コンテナをイメージにコミット](#コンテナをコミットする)し（確認画面にそのためのボタンがあります）、そのイメージを使うようにコンテナを編集します。
- **ダウンタイム** — 実行中のコンテナは、2 つを入れ替える間、通常は数秒間停止します。
- **スタックの次のデプロイ** — スタック内のコンテナの場合、スタックの次のデプロイで、編集内容を含まない compose ファイルからコンテナが作り直されます。変更を残すには compose ファイルを変更してください。

残るもの: 名前、ネットワークとそのエイリアス、名前付きボリュームとバインドマウント、そしてダイアログに表示されないすべての設定。実行中だったコンテナは、その後も実行されます。

<Aside type="note" title="問題が起きた場合">
  Homeport
  は元のコンテナに触れる前に新しいコンテナを作成し、新しいコンテナが実行されてから初めて元のコンテナを削除します。
  いずれかの手順が失敗した場合（新しいポートが使用中など）、新しいコンテナは削除され、元のコンテナは元の状態に戻され
  （実行中だった場合は実行中に）、ダイアログに理由が表示されます。まれに元に戻すことにも失敗した場合は、メッセージに
  `web-old-1a2b3c4d` のような元のコンテナの場所が示されるため、名前を元に戻して起動できます。
</Aside>

## コンテナをコミットする

**イメージにコミット…** は、`docker commit` と同じように、コンテナのファイルを現在の状態のまま（作成以降に内部で変更されたものもすべて含めて）、その設定とともに、ホスト上の新しいイメージとして保存します。

| 項目                               | 説明                                                                                                                                                                                      |
| ---------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **イメージ名**                     | `repo:tag`。最初はコンテナの名前と今日の日付（`web:2026-11-04` など）が入っています。その名前のイメージがすでにある場合は、ダイアログにその旨が表示され、名前は新しいイメージに移ります。 |
| **メッセージ**                     | イメージの履歴（**検査** → **レイヤー**）に表示されます。                                                                                                                                 |
| **作成者**                         | 任意。                                                                                                                                                                                    |
| **変更**                           | 新しいイメージに適用する Dockerfile の命令。1 行に 1 つずつ: `CMD`、`ENTRYPOINT`、`ENV`、`EXPOSE`、`LABEL`、`ONBUILD`、`USER`、`VOLUME`、`WORKDIR`（`ENV MODE=prod` など）。              |
| **コミット中はコンテナを一時停止** | 既定でオンです。コミットにかかる数秒間プロセスが凍結されるため、書き込み中のファイルの整合性が保たれます。コンテナはその後も動作を続けます。                                              |

新しいイメージは、すぐに[イメージページ](/docs/guides/images/)に表示されます。ボリュームは、名前付きでも匿名でも含まれないため、別にバックアップしてください。再ビルドできるイメージを作るには、[Dockerfile からビルドする](/docs/guides/images/#イメージをビルドする)ほうが適しています。

## コンテナのファイルシステムをエクスポートする

**ファイルシステムをエクスポート…** は、`docker export` と同じように、コンテナのすべてのファイル（イメージのファイルと、それ以降に変更されたものすべて）を、このコンピューター上の 1 つの `.tar` に保存します。保存先を選びます。ファイル名はコンテナの名前になります。進行状況には書き込んだバイト数が表示され、**キャンセル** で停止でき、キャンセルまたは失敗したエクスポートは不完全なファイルを残しません。アーカイブはディスクに直接書き込まれるため、数ギガバイトのコンテナでも問題ありません。

アーカイブは、レイヤー、履歴、設定、ボリュームを含まない、平坦なただのファイルシステムです。任意の tar ツールで開くか、イメージページの [**tar からインポート…**](/docs/guides/images/#ファイルシステムをインポートする) や `docker import` でイメージに戻せます。コンテナの設定も残すには、代わりに[コミット](#コンテナをコミットする)してください。
