**イメージ** ページには、選択したホストに保存されているイメージが、合計サイズとともに一覧表示されます。

| 列             | 表示内容                                                                       |
| -------------- | ------------------------------------------------------------------------------ |
| **名前**       | 最初のタグと、ほかにいくつタグがあるか。タグのないイメージでは `<none>`。      |
| **ID**         | イメージの短い ID。                                                            |
| **作成日時**   | イメージがどれくらい前にビルドされたか。                                       |
| **サイズ**     | ディスク上のサイズ。                                                           |
| **ステータス** | そのイメージから作成されたコンテナの数とともに **使用中**、または **未使用**。 |

停止中のコンテナも、イメージを使っているものとみなされます。列の見出しを選ぶと並べ替えられ、**イメージを検索** で検索できます。

名前の横の ⬆ は、イメージのタグのいずれかが、レジストリ内のより新しいイメージを指していることを示します。ポインターを合わせると、どのタグかがわかります。それを取得するには、そのタグをプルします。**新しいイメージを確認** は、6 時間保持している結果を使わずに、レジストリにもう一度問い合わせます。確認の仕組みについては、[新しいイメージ](/docs/guides/containers/#新しいイメージ)を参照してください。

## イメージをプルする

**イメージをプル** を選び、参照を入力します。`nginx`（`nginx:latest` の意味）、`nginx:1.27`、`ghcr.io/org/app:v2`、`registry.example.com:5000/app`、または `app@sha256:…` のようなダイジェストです。

Homeport はプルの進行状況をレイヤーごとに表示し、完了すると **完了しました。** と表示します。**キャンセル** を選ぶと、プルの追跡を止めます。

### Docker Hub を検索する

`postg` のように名前だけを入力すると、入力に合わせて Docker Hub が検索され、一致するリポジトリが説明、スター数、**公式** の印とともに一覧表示されます。1 つ選ぶと、そのタグが新しい順に、サイズとプッシュされた日時とともに表示されます。**タグを絞り込み** で一覧を絞り込み（`alpine`）、**その他のタグ** で次のページを読み込みます。タグを選ぶと、`postgres:17-alpine` のような参照が入力され、**プル** できる状態になります。

検索は選択したホスト上で実行されるため、プルと同じように、ホストのネットワークを通じて Docker Hub に接続します。タグはこのコンピューターが Docker Hub から読み取ります。Docker Hub の[ログイン情報](/docs/guides/settings/#レジストリ)を保存しておくと、レート制限が緩和されます。タグ、ダイジェスト、またはほかのレジストリ（`ghcr.io/…`）を入力すると検索は行われません。Docker Hub に接続できない場合は、ダイアログにその旨が表示され、それでも入力したものをプルします。ほかのレジストリはまだ検索できません。

### プライベートイメージ

イメージのレジストリのログイン情報が [**設定 → レジストリ**](/docs/guides/settings/#レジストリ) に保存されていれば、Homeport はプルとともにそれをエンジンに渡します。そのため、ローカル、TCP、TLS、SSH のどのホストでも、ホスト側で何も設定せずにプライベートイメージをプルできます。参照の下には、イメージがどのようにプルされるかがダイアログに表示されます。**ghcr.io で alice としてプルしました**、または一致するログイン情報がない場合は **匿名でプルしました** です。

名前にレジストリを含まないイメージ（`nginx`、`bitnami/redis`）には、Docker Hub のログイン情報が使われます。Docker Hub のログイン情報は、Docker Hub のプル制限も緩和します。

レジストリがプルを拒否した場合は、メッセージに対処方法が示されます。ログイン情報が保存されていなければそのレジストリのログイン情報を追加し、保存されていればその内容を確認してください。

<Aside>
  ログイン情報はリクエストとともにエンジンに送られ、ホストには保存されません。Homeport は
  `~/.docker/config.json` から `docker login` の認証情報を読みません。
</Aside>

## イメージをビルドする

**ビルド** を選び、このコンピューター上の Dockerfile を含む **フォルダー**（ビルドコンテキスト）を選びます。Homeport はフォルダーをまとめ、`.dockerignore` で除外されるものをすべて除き（Docker のルールに従います: `*`、`**`、`!` による例外、最後に一致した行が優先）、選択したホストに送ります。ビルドはそのホストのエンジンが行います。同じビルドは、SSH や TLS 経由のリモートのホストでも、何もインストールせずに動作します。

| 項目                           | 動作                                                                                          |
| ------------------------------ | --------------------------------------------------------------------------------------------- |
| **Dockerfile**                 | フォルダー内のパス。既定は `Dockerfile`。`.dockerignore` に記載されていても、常に送られます。 |
| **ターゲットステージ**         | マルチステージの Dockerfile で、どのステージまでビルドするか（`--target`）。                  |
| **名前**                       | 結果に付ける 1 つ以上の名前（`app:1.0, ghcr.io/me/app:1.0` など）。                           |
| **ビルド引数**                 | Dockerfile の `ARG` に渡す `NAME=value`。1 行に 1 つ。                                        |
| **ビルドキャッシュを使わない** | すべてのステップを実行し直します（`--no-cache`）。                                            |
| **新しいベースイメージをプル** | ホストにあっても `FROM` のイメージをプルします（`--pull`）。                                  |

ビルドの出力はリアルタイムで表示され、**キャンセル** で停止できます。完了すると、名前がイメージページに表示されます。ステップが失敗した場合、メッセージにそのステップが示され（**ビルドがステップ 3/5（RUN make）で失敗しました。**）、**詳細** に出力の末尾が含まれます。プライベートな `FROM` のイメージは、保存した[レジストリのログイン情報](/docs/guides/settings/#レジストリ)でプルされます。

<Aside>
  Homeport は、エンジンの API が提供するクラシックビルダーを使います。`RUN --mount`
  やビルドシークレットのような BuildKit
  の機能は使えません。それらはターミナルからビルドしてください。
</Aside>

### 代わりにコンテナをコミットする

イメージはコンテナから作ることもできます。コンテナの **⋮** メニューにある **イメージにコミット…** は、そのファイルと設定を現在の状態のまま保存します。[コンテナをコミットする](/docs/guides/containers/#コンテナをコミットする)を参照してください。実行中のコンテナ内で誰かがインストールしたり変更したりしたものを残す手早い方法です。ビルドは長く使える方法です。Dockerfile にイメージの作り方が記述されるため、ベースイメージが更新されたときに、再ビルド、レビュー、更新ができます。コミットしたイメージではそれができません。

## イメージをプッシュする

イメージの **⋮** メニューで **プッシュ** を選びます。**プッシュする名前** には、最初はイメージの最初の名前が入っています。イメージのほかの名前を選ぶか、`ghcr.io/org/app:v2` のような新しい名前を入力します。その場合、**タグ付け** と同じように、まずイメージにその名前が付けられます。名前の最初の部分で、送り先のレジストリが決まります。`ghcr.io/org/app` は GHCR に、`org/app` は Docker Hub に送られます。

Homeport は、そのレジストリ用に保存された[レジストリのログイン情報](/docs/guides/settings/#レジストリ)を使って、ホストのエンジンを通じてプッシュし、名前の下にどのログイン情報を使うかを表示します（**ghcr.io で alice としてプッシュしました**）。ログイン情報が保存されていない場合、ほとんどのレジストリは匿名でのプッシュを拒否するため、開始前にダイアログが警告します。実行中は、プッシュしたレイヤーとレジストリにすでにあったレイヤーの数が表示され、アップロードの進行状況が示されます。**キャンセル** でプッシュを停止します。

レジストリが拒否した場合は、ログイン情報を追加するのか、保存されたログイン情報がそのリポジトリにプッシュできるかを確認するのかが、メッセージに示されます。

## イメージの保存と読み込み

レジストリに到達できないホスト（エアギャップのサーバー、ホームネットワーク上の Raspberry Pi など）にイメージを移すには、イメージをこのコンピューター上のファイルに保存し、そのファイルを別のホストに読み込みます。

- イメージの **⋮** メニューにある **保存…** は、イメージをそのすべての名前とともに、選んだ 1 つの `.tar` ファイルに書き込みます。複数をまとめて保存するには、一覧でそれらにチェックを入れ、ページの上部で **N 個のイメージを保存…** を選びます。
- ページの上部にある **読み込み…** は、**保存…** または `docker save` で作成した `.tar`（圧縮された `.tar.gz` も可）を、選択したホストに読み込みます。完了すると、読み込んだイメージがタグとともにダイアログに表示されます。

ファイルは、ホスト自身の接続を通じて、このコンピューターとホストの間で転送されるため、リモートのホストでも使えます。進行状況には、書き込んだバイト数または送信したバイト数が表示されます。**キャンセル** で停止でき、キャンセルまたは失敗した保存は不完全なファイルを残しません。Homeport はアーカイブ全体をメモリに保持することがないため、数ギガバイトのイメージでも問題ありません。

### ファイルシステムをインポートする

ページの上部にある **tar からインポート…** は、`docker import` と同じように、ルートファイルシステムの tar をイメージに変換します。コンテナの [**ファイルシステムをエクスポート…**](/docs/guides/containers/#コンテナのファイルシステムをエクスポートする) や `docker export` で作成したもの、`debootstrap` や Buildroot の出力、ベンダーのアプライアンスなどです。ファイル（非圧縮、または gzip、xz、bzip2 で圧縮されたもの）を選び、イメージに **名前** を付け（最初はファイル名が入っています）、任意で **変更** を指定します。インポートしたイメージには独自のコマンドがないため、`CMD ["/bin/sh"]` や `ENV LANG=C.UTF-8` のような Dockerfile の命令を指定します。進行状況には送信したバイト数が表示され、その後イメージが一覧に表示されます。

### 保存と読み込みか、エクスポートとインポートか

|              | **保存** / **読み込み**                | **ファイルシステムをエクスポート** / **tar からインポート**          |
| ------------ | -------------------------------------- | -------------------------------------------------------------------- |
| 元になるもの | 1 つ以上のイメージ                     | 1 つのコンテナの、現在の状態のファイル                               |
| 保持するもの | すべてのレイヤー、履歴、名前、設定     | ファイルのみ。1 つのレイヤーにまとめられます                         |
| 失うもの     | なし                                   | 履歴、名前、そしてコマンドや環境変数などの設定                       |
| 用途         | レジストリのないホストにイメージを移す | コンテナのファイルをバックアップ・調査する、または rootfs から始める |

## イメージを操作する

- **▶ 実行** は、イメージが入力された状態で[実行ダイアログ](/docs/guides/containers/#コンテナを実行する)を開きます。
- **検査**（または行を選ぶ）では、**レイヤー**（各レイヤーをビルドした命令とそのサイズ）と **生の JSON** が表示されます。
- **タグ付け** は、`registry.example.com/app:v2` のような別の名前を追加します。何もプッシュしません。プッシュするのは **プッシュ** です。
- **削除** は、イメージと、ほかのイメージが使っていないレイヤーを削除します。複数のタグがあるイメージでは、すべてのタグが失われます。エンジンは、コンテナがまだ使っているイメージの削除を拒否します。先にコンテナを削除してください。

## 未使用のものを削除する

**未使用を削除** には 2 つのレベルがあります:

- **dangling イメージ** — ビルドやプルで残された、タグのないイメージ。削除しても安全です。
- **未使用のすべてのイメージ** — タグ付きのものを含め、どのコンテナも使っていないすべてのイメージ。再びプルできますが、時間と帯域幅がかかります。

Homeport は、削除した数と解放された容量を表示します。[概要の未使用データの削除](/docs/guides/overview/#未使用のものを削除する)では、停止中のコンテナ、ネットワーク、ビルドキャッシュ、ボリュームもまとめて削除できます。
