**同期スタック** は、compose ファイルを git リポジトリから取得する[スタック](/docs/guides/stacks/)です。Homeport はリポジトリをこのコンピューターにクローンし、指示したとき（または Homeport を開いている間は一定の間隔で）ブランチやタグをフェッチし、変更内容を表示して、新しいコミットをホストにデプロイします。編集、コミット、プッシュは決して行いません。変更は git を通じて行います。

<Aside type="note" title="Homeport には git が必要です">
  同期スタックは、このコンピューターにインストールされた `git` を実行します。**設定 → このマシン**
  に、Homeport が git
  を見つけたかどうかと、見つからない場合のインストール方法が表示されます。それ以外の種類のスタックは、git
  なしで動作します。
</Aside>

## リポジトリ

Homeport は、**設定 → リポジトリ** または **新しいスタック** ページで追加したリポジトリを読み取ります。リポジトリは一度追加すれば、すべてのホストの同期スタックで使えます。Homeport は、次の 3 つの方法のいずれかでリポジトリにアクセスします:

| アクセス         | URL                                                   | Homeport が保存するもの                              |
| ---------------- | ----------------------------------------------------- | ---------------------------------------------------- |
| **デプロイキー** | SSH: `git@github.com:owner/repo.git` または `ssh://…` | このリポジトリ専用に作成したキー。**暗号化して保存** |
| **トークン**     | HTTPS: `https://gitlab.com/owner/repo.git`            | ユーザー名と、**暗号化した** アクセストークン        |
| **公開**         | HTTPS。誰でも読めるリポジトリ用                       | 秘密情報はなし                                       |

`http://` とローカルパスは受け付けないため、トークンが平文で送られることはありません。

### デプロイキーを使う

<Steps>

1. **リポジトリを追加** を選び、リポジトリの SSH の URL を貼り付け、**デプロイキー** のまま **追加してデプロイキーを作成** を選びます。

2. Homeport が表示するキーをコピーし、**読み取りアクセスのみで** リポジトリに追加します:
   - GitHub: リポジトリの **Settings → Deploy keys → Add deploy key**。
   - GitLab: プロジェクトの **Settings → Repository → Deploy keys**。
   - Gitea と Forgejo: リポジトリの **Settings → Deploy keys → Add deploy key**。

3. **アクセスをテスト** を選びます。Homeport は、このコンピューターからリポジトリのブランチとタグを一覧表示します。

</Steps>

リポジトリごとに独自のキーが作られるため、キーが漏洩しても読めるのはそのリポジトリだけです。また、ご自身の SSH キーや `~/.ssh/config` が使われることはありません。**新しいキー** でキーを置き換えます。新しいキーをリポジトリに追加し、古いキーをそこから削除してください。

Homeport が初めて SSH サーバーに接続すると、`ssh` と同じように、サーバーが提示したキーを信頼して記憶します。後でキーが変わると、フォージの Web サイトで新しいフィンガープリントを確認し、信頼済みキーの横の **リセット** を選ぶまで、すべてのフェッチが失敗します。

### トークンを使う

リポジトリの `https://` の URL を貼り付け、**トークン** を選び、ユーザー名と、リポジトリの内容を読み取れるアクセストークンを入力します。GitHub では **Contents: Read-only** を持つ fine-grained トークン、GitLab では `read_repository` を持つプロジェクトトークンまたは個人トークンです。**アクセスをテスト** で確認します。トークンの有効期限が切れたら、**トークンを置き換え** で新しいトークンを入力します。

<Aside type="tip">
  OS のキーチェーンがない場合、Homeport
  はデプロイキーもトークンも保存できないため、追加できるのは公開リポジトリだけです。
  [システム要件](/docs/requirements/#任意-os-のキーチェーン)を参照してください。
</Aside>

リポジトリを削除すると、そのキーまたはトークンと、このコンピューター上のクローンが削除されます。同期スタックが使っている間は拒否されます。

## 同期スタックを作成する

<Steps>

1. デプロイ先のホストで **スタック** を開き、**新しいスタック** を選び、続いて **Git リポジトリを使う** を選びます。

2. **リポジトリ** を選ぶか、**リポジトリを追加** でその場で追加します。

3. **ブランチ** または **タグ** を選びます。Homeport はリポジトリのサーバーからそれらを一覧表示し、既定のブランチを先頭に表示します。

4. リポジトリのルートからの相対パスで **compose ファイル** のパスを入力します。`compose.yaml` や `deploy/prod/compose.yaml` などです。そのフォルダーがプロジェクトフォルダーになるため、ファイル内の `build:`、`env_file:`、相対パスは、ご自身のクローンと同じように動作します。

5. **名前**（リポジトリ名から付けられます）を確認し、パスワードなど git に入れるべきでないものを **環境変数** に追加します。`KEY=value` の行で指定し、このコンピューター上で暗号化され、デプロイ時に変数として Compose に渡されます。

6. **保存してデプロイ** を選びます。後でデプロイする場合は **保存** を選びます。

</Steps>

Homeport は何かを保存する前にブランチやタグをフェッチして compose ファイルを読むため、パス、ブランチ、タグの誤りや、Compose がデプロイできないファイルは、すぐに報告されます。スタックは最初のデプロイまで **同期** かつ **未デプロイ** として一覧表示されます。**定義** タブには、リポジトリ、ブランチまたはタグ、compose ファイル、デプロイしたコミットが表示されます。

リポジトリは、このコンピューター上の Homeport のデータベースの隣にある `repositories` フォルダーに一度だけクローンされ、そこから作成されたすべての同期スタックで共有されます。各同期スタックは、そこにある `synced-stacks` フォルダー内の、コミットの独自のチェックアウトからデプロイします。チェックアウトはデプロイの間もそのまま残るため、コンテナが相対パスのバインドマウントを通じて書き込んだファイルは元の場所に残ります。リポジトリ内のシンボリックリンクは通常のファイルとしてチェックアウトされるため、compose ファイルが Compose をこのコンピューター上の別の場所のファイルに向けることはできません。ファイルは、Windows でも、リポジトリが保持している改行コードのままになるため、Linux のイメージにコピーしたスクリプトもそのまま動作します。改行コードを変えられるのは、リポジトリ自身の `.gitattributes` だけです。

同期スタックは、代わりに [Swarm](/docs/guides/swarm/) にデプロイすることもできます。**新しいスタック** の **デプロイ先** でそれを選びます。同期、デプロイ、自動デプロイは同じように動作し、`docker stack deploy` がチェックアウトから実行されます。何が変わるか（何よりもまず `build:`）については、[Swarm 上のリンクスタックと同期スタック](/docs/guides/swarm/#swarm-上のリンクスタックと同期スタック)を参照してください。

**破棄** を選ぶと、Homeport はリポジトリへの追従をやめます。コンテナは動作し続け、スタックは外部スタックになります。チェックアウトは、コンテナがそこにファイルを書き込んでいなければ削除され、リポジトリのクローンは、どの同期スタックも使わなくなった時点で削除されます。リポジトリは **設定 → リポジトリ** に残ります。

## 同期

同期スタックの行またはページで **同期** を選びます。Homeport はブランチやタグをフェッチし、何かを行う前に、デプロイすると何が変わるかを表示します:

- デプロイ済みのコミット以降で compose ファイルのフォルダー内の何かを変更した **新しいコミット**。作成者と作成日時も表示されます。
- そのフォルダー内の **変更された各ファイル**。compose ファイルが先頭で、削除された行は取り消し線付きで、置き換える行の上に表示されます。テキストでないファイルは、名前だけが表示されます。

**デプロイ** を選ぶと、まさにそのコミットをデプロイします。Homeport はスタックのチェックアウトでそのコミットをチェックアウトし、compose ファイルのフォルダーから `docker compose up` を実行して、`build:` のあるサービスを再ビルドするため、変更された `Dockerfile` も反映されます。出力は実行中にリアルタイムで表示され、デプロイはそのコミットとともにスタックの **履歴** に記録されます。

- compose ファイルのフォルダー内で何も変更しないプッシュ（リポジトリの別の場所のドキュメントなど）では、**最新です** と表示されます。**それでも再デプロイ** を選ぶと、それでもデプロイします。
- 前回 Homeport がフェッチしたときとは別のコミットをタグが指している場合は、確認画面の最初にその旨が表示されます。
- フェッチが失敗した場合（デプロイキーが削除された、サーバーに到達できないなど）やデプロイが失敗した場合、Homeport はその理由と対処方法を表示し、スタックはデプロイ済みのコミットのままです。

**再デプロイ** は、環境変数やプロファイルで何が変わったかを表示した後、現在デプロイされているコミットを再びデプロイします。一度もデプロイされていないスタックで **デプロイ** を選ぶと、作成時にフェッチしたコミットをデプロイします。同期スタックは Homeport からロールバックできません。リポジトリで変更を元に戻すか、スタックを以前のタグに向けてから、同期してください。

## ポーリングと自動デプロイ

<Aside type="caution" title="Homeport を開いている間だけ">
  Homeport がリポジトリを確認するのは、開いている間だけです。**閉じている間は何も同期されません**。
  Homeport はサーバーに何もインストールしないため、サーバー上のエージェントも Webhook
  もありません。もう一度開くと、 最初の確認までに 1 間隔分待ちます。
</Aside>

Homeport を開いている間は、各同期スタックのブランチやタグを一定の間隔でフェッチします。既定は 5 分ごとで、**設定 → 同期スタック** で設定します（最小 1 分）。各リポジトリは、使っているスタックの数にかかわらず 1 回の巡回につき 1 回だけフェッチされ、失敗し続けるリポジトリは試行の頻度が徐々に下がり、最終的に 1 時間に 1 回になります。

新しいコミットが compose ファイルのフォルダーを変更すると、スタックの一覧とページに **アップデートがあります** と表示されます。**同期** を選ぶと、変更内容が表示され、それをデプロイします。スタックの **定義** タブには、**前回の確認** の日時と、前回の確認が失敗した場合はその理由が表示されます。

**定義** タブにある 2 つのスイッチで、スタックごとにこれを制御します:

- **新しいコミットを確認**。既定でオンです。オフにすると、**同期** を選んだときだけ同期します。
- **新しいコミットを自動でデプロイ**。既定でオフです。オンにすると、Homeport は新しいコミットを見つけるとすぐに、**先に変更内容を表示せずに**、**同期** と同じ手順でデプロイします。デプロイは **履歴** に自動として記録され、完了すると通知が届きます。ホストに到達できない間は待機します。失敗した場合、Homeport はその理由を表示し、同じコミットを再試行しません。次のコミット、またはご自身でデプロイする **同期** で再試行されます。

## 同期スタックを編集できないのはなぜですか

リポジトリが、その定義が存在する唯一の場所だからです。Homeport が compose ファイルを変更すると、次の同期でその変更が上書きされるか、変更と競合することになり、リポジトリを読む人には何がデプロイされているのかわからなくなります。そのため、同期スタックの **定義** タブには、フェッチしたコミット時点の compose ファイルが **読み取り専用** で表示され（選択とコピーはできます）、そのフォルダーにあるほかのファイルが一覧表示され、それぞれが GitHub、GitLab、Gitea、Forgejo 上のページにリンクしています。そこで変更してプッシュし、**同期** してください。

Homeport が保持しているものは、同じタブで編集できます:

- git に入れるべきでない値のための **環境変数**。このコンピューター上で暗号化されます。
- compose ファイルでプロファイルが宣言されている場合は、その **プロファイル**。
- **新しいコミットを確認** するかどうかと、**自動でデプロイ** するかどうか。

**破棄** を選ぶと、Homeport はリポジトリへの追従をやめます。スタックのコンテナは動作し続け、スタックは外部スタックになります。
