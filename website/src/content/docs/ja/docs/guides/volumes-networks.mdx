## ボリューム

**ボリューム** ページには、選択したホストのボリュームと、未使用のボリュームの数が表示されます。

<DocScreenshot
  name="volumes"
  alt="各ボリュームのスタック、ドライバー、それを使っているコンテナが表示されたボリュームページ。"
/>

| 列             | 表示内容                                                   |
| -------------- | ---------------------------------------------------------- |
| **名前**       | ボリュームの名前。匿名ボリュームの場合は長い ID。          |
| **スタック**   | ボリュームを作成したスタック（ある場合）。                 |
| **ドライバー** | 通常は `local`。                                           |
| **サイズ**     | `docker system df -v` が示す、データが占めるディスク容量。 |
| **使用元**     | ボリュームをマウントしているコンテナ、または **未使用**。  |
| **作成日時**   | 作成された日時。                                           |

実行中か停止中かにかかわらず、いずれかのコンテナがマウントしていれば、そのボリュームは使用中とみなされます。ボリュームを選ぶと、そのサイズ、使っているコンテナ、そしてホスト上のデータの場所（`Mountpoint`）を含むすべての詳細が表示されます。

### サイズ

エンジンはサイズを求めるためにすべてのボリュームを計測します。データの多いホストでは数秒かかることがあるため、一覧はすぐに表示され、**サイズ** 列は後から埋まります。ディスクを埋めているボリュームを探すには、**サイズ** で並べ替えます。サイズは、ボリュームが作成・削除されたときと、**サイズを更新** を選んだときに計測し直されます。コンテナが書き込むたびに計測されるわけではないため、サイズが少し古いことがあります。

サイズがあるのは `local` ドライバーのボリュームだけです。ほかのドライバー（NFS、クラウドストレージのプラグイン）では **—** と表示されます。

### ボリュームのファイルを参照する

ボリュームの行にあるフォルダーのボタンを選ぶと、そのファイルが開きます。フォルダーを開き、一覧の上のパスを使って上の階層に戻り、ファイルをダウンロードしたり、フォルダーを `.tar` アーカイブとしてダウンロードしたりできます。パスはボリュームのルート（`/`）から始まります。

参照は読み取り専用です。コンテナがボリュームを使っている間でも、ここでの操作でボリュームが変更されることはありません。

#### ヘルパーコンテナ

エンジンの API はボリュームを読めないため、Homeport は短時間だけ存在する **ヘルパーコンテナ** でボリュームを開きます。これはネットワークがなくファイルシステムが読み取り専用の `busybox:1.37` コンテナで、ボリュームを読み取り専用でマウントします。Homeport は、ブラウザーを閉じるか終了すると、すぐにこれを削除します。Homeport が削除できない場合（クラッシュした、ホストがなくなったなど）は、ヘルパーは停止し、1 時間以内にエンジンによって削除されます。残ったものは、次にこのコンピューターがホストに接続したときに Homeport が削除します。ヘルパーは、コンテナの一覧、ボリュームの **使用元**、イベントページには決して表示されません。

ホストに `busybox:1.37`（約 2 MB）がない場合、Homeport はその旨を表示し、**busybox:1.37 をプル** を選んだときに初めて、[レジストリのログイン情報](/docs/guides/settings/#レジストリ)を使ってプルします。完了すると、ほかに使っているものがなければ、イメージを再び削除します。インターネットにアクセスできないホストではプルできないため、ご自身でホストに用意してください:

```sh
docker pull busybox:1.37
```

または、イメージがあるマシンで `docker save busybox:1.37 -o busybox.tar` を実行し、ファイルをコピーして、ホストで `docker load -i busybox.tar` を実行します。

<Aside>
  Windows コンテナを実行しているエンジンではヘルパーを実行できないため、そのボリュームは開けません。
</Aside>

### バックアップと復元

ボリュームの行の **⋯** メニューにある **ファイルにバックアップ…** は、その内容をこのコンピューター上の `.tar` ファイルに保存します。アーカイブには、ボリュームのファイルが所有者と権限とともに、ルートからの相対パスで、`tar -C <volume> -cf backup.tar .` と同じように格納されるため、Homeport を使わずに開いたり復元したりすることもできます。

**ファイルから復元** は、バックアップを復元します:

- ページの上部からは、**新しいボリューム**（変更しなければファイル名にちなんだ名前）、または選んだ **既存のボリューム** に復元します。
- ボリュームの **⋯** メニューからは、そのボリュームに復元します。

既存のボリュームにすでにファイルがある場合、Homeport はそれらを削除してバックアップのファイルに置き換える前に確認します。tar アーカイブでないファイルは、何かが変更される前に拒否されます。

どちらも進行状況が表示され、キャンセルできます。キャンセルしたバックアップはファイルを残しません。キャンセルした復元はボリュームが部分的に書き込まれたままになることがあるため、使う前にもう一度復元してください。

#### ボリュームを使っているコンテナ

実行中のコンテナが書き込んでいるボリューム（データベースなど）のバックアップは、整合性が取れていないことがあります。Homeport は、そのボリュームを使っている実行中のコンテナを示します。**それでもバックアップ** するか、バックアップ中はそれらを停止するかを選びます。復元では、常に先にそれらを停止します。どちらの場合も、Homeport は後でそれらを再び起動します。

バックアップと復元には、参照と同じ[ヘルパーコンテナ](#ヘルパーコンテナ)を使い、バックアップではボリュームを読み取り専用でマウントします。アーカイブはホストの接続を通じて転送され、メモリに丸ごと保持されることはないため、大きなボリュームやリモートのホストでも使えます。ホストに書き込まれるのは、復元するボリュームだけです。

### ボリュームをクローンする

ボリュームの行の **⋯** メニューにある **クローン…** は、ボリュームを同じホスト上の新しいボリュームにコピーします。たとえば、実データのコピーでマイグレーションや新しいバージョンのイメージを試すときに使います。コピーの名前は、変更しなければ `<name>-copy` になり、作成されると一覧で選択されます。

ファイルの所有者と権限、そしてコピー元のドライバー、ドライバーオプション、ラベルが保持されます。ただし Compose のラベルは除かれるため、コピーはどのスタックにも属しません。コピー元は[ヘルパーコンテナ](#ヘルパーコンテナ)に読み取り専用でマウントされ、変更されることはありません。バックアップと同様に、Homeport はコピー元を使っている実行中のコンテナを示します。それでもコピーするか、コピー中はそれらを停止するかを選びます。

コピーが失敗した場合（ディスクがいっぱいになったなど）、Homeport は不完全なコピーを削除してその旨を表示し、エラーを **詳細** に示します。ボリュームを別のホストにコピーするには、[バックアップ](#バックアップと復元)して、そのファイルを別のホストで復元します。

### ボリュームを作成する

**ボリュームを作成** では、**名前** と、任意で **ドライバー**（空の場合は `local`）を入力します。

### ボリュームを削除する

<Aside type="danger">ボリュームを削除すると、その中のデータは完全に削除されます。</Aside>

各行の削除ボタンは確認を求め、まだボリュームをマウントしているコンテナを示します。エンジンは、停止中のものも含め、いずれかのコンテナが使っているボリュームの削除を拒否します。先にそれらのコンテナを削除してください。

**未使用を削除** は、複数のボリュームをまとめて削除します:

- **未使用の匿名ボリューム** — どのコンテナも使っていない、名前のないボリューム。
- **未使用のすべてのボリューム** — 名前付きのものを含め、どのコンテナも使っていないすべてのボリューム。

## ネットワーク

**ネットワーク** ページには、選択したホストのネットワークが、組み込みの `bridge`、`host`、`none` を先頭に一覧表示されます。

<DocScreenshot
  name="networks"
  alt="組み込みのネットワークとスタックのネットワークが、サブネットとコンテナ数とともに表示されたネットワークページ。"
/>

| 列             | 表示内容                                                   |
| -------------- | ---------------------------------------------------------- |
| **名前**       | 該当する場合は **組み込み** または **内部** のバッジ付き。 |
| **スタック**   | ネットワークを作成したスタック（ある場合）。               |
| **ドライバー** | `bridge`、`overlay`、`macvlan`…                            |
| **サブネット** | IP の範囲。                                                |
| **コンテナ**   | 実行中か停止中かにかかわらず、接続しているコンテナの数。   |

### コンテナを接続する

ネットワークを選ぶと、接続しているコンテナが表示されます。自分で作成したネットワークでは:

- **切断** はコンテナを切り離します。
- **コンテナを接続…** には、まだ接続していないコンテナが一覧表示されます。1 つ選んで **接続** を選びます。

組み込みのネットワークは、ここでは変更できません。

### ネットワークを作成する

**ネットワークを作成** では、**名前**、**ドライバー**（空の場合は `bridge`）、そして任意で **サブネット** と **ゲートウェイ** を指定します。空のままにすると、エンジンが選びます。スイッチは 2 つあります:

- **内部** — ネットワーク上のコンテナは、外部のネットワークにアクセスできません。
- **アタッチ可能** — スタンドアロンのコンテナが `overlay` ネットワークに参加できます。

### ネットワークを削除する

組み込みのネットワークは削除できません。それ以外のネットワークでは、確認画面にまだ接続しているコンテナの数が表示されます。エンジンは、実行中のコンテナがあるネットワークの削除を拒否します。削除したネットワークを名前で参照しているコンテナは、そのネットワークが再び作成されるまで起動しません。

**未使用を削除** は、どのコンテナも接続していないすべてのカスタムネットワークを削除します。
