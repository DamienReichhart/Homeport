**Pod** は、Podman がコンテナをまとめる仕組みです。Pod 内のコンテナは 1 つのネットワーク（とホスト名、IPC）を共有するため、`localhost` で互いに通信でき、まとめて起動・停止します。各 Pod には **インフラコンテナ** があり、共有するものと、Pod が公開するポートを保持します。Homeport は、エンジンが Podman のホストで、ホストがすでに使っているソケット上の Podman 独自の API を通じて Pod を表示します。ホストには何もインストールしません。

**Pod** ページは、Podman のホストを選択している間だけサイドバーに表示されます。ほかの Docker 互換エンジンでは表示されず、そのページへのリンクには理由が示されます。Homeport が Podman をどう見分けるかは、[エンジンの種類](/docs/hosts/#エンジンの種類)を参照してください。

## Pod ページ

| 列               | 表示内容                                                                                                        |
| ---------------- | --------------------------------------------------------------------------------------------------------------- |
| **名前**         | Pod の名前と、その状態を示すドット。                                                                            |
| **ステータス**   | **実行中**、**一部実行中**（一部のコンテナが停止）、**一時停止**、**停止**、**作成済み**、**失敗** のいずれか。 |
| **コンテナ**     | Pod 自身のコンテナのうち実行中の数。インフラコンテナは数えません。                                              |
| **ネットワーク** | Pod が接続しているネットワーク。                                                                                |
| **作成日時**     | 作成された日時。                                                                                                |

各行には、状態に応じた操作（停止中の Pod には **起動**、実行中の Pod には **停止**）と **削除** があります。Pod を選ぶと、そのページが開きます。Pod のコンテナが起動・停止すると、Homeport からでもターミナルからでも、一覧は自動的に更新されます。

**コンテナ** ページでは、Pod 内で動作しているコンテナの名前の横に Pod の名前が表示されます。その名前を選ぶと Pod が開きます。

## Pod のページ

ヘッダーには **コンテナを実行** と、Pod の操作（状態に応じて **起動**、**停止**、**再起動**、**一時停止**、**再開**、**削除**）があります。それぞれ、`podman pod start` などと同じように、Pod のすべてのコンテナに対して一度に動作します。

- **コンテナ** には Pod のコンテナが一覧表示され、インフラコンテナは最後に表示されます。いずれかを選ぶと、ログ、ターミナル、ファイルを含むそのコンテナのページが開きます。
- **設定** には、Pod が公開するポート、コンテナが共有する名前空間、ネットワーク、ホスト名、ラベル、そして Podman が保持している場合は Pod の作成に使われた `podman pod create` コマンドが表示されます。

## Pod を削除する

**削除** を選ぶと確認があり、Pod とともに削除されるコンテナの数が表示されます。実行中の Pod は先に停止されます。その場合、ボタンの表示は **停止して削除** になります。Pod のボリュームは残ります。

## Pod を作成する

**新しい Pod**（Pod ページで `n`、またはコマンドパレットの **新しい Pod**）では、次の項目を入力します:

- **名前**: 英字、数字、`_`、`.`、`-`。英字または数字で始めます。
- 公開する **ポート**: 実行ダイアログと同じく、ホストのポートからコンテナのポートへの対応です。ホストのポートを空にすると、Podman が空いているポートを選びます。
- **ラベル**: 1 行に 1 つずつ `key=value` の形式で指定します。

ポートは Pod に属します。ポートは Pod のインフラコンテナで公開され、Pod 内でそのポートを待ち受けているコンテナに届きます。新しい Pod のページが開き、その中でコンテナを実行できる状態になります。コンテナを実行するまで、Pod 自身のコンテナはありません。Podman は最初のコンテナとともに Pod を起動します。

## Pod 内でコンテナを実行する

Podman のホストでは、**実行** ダイアログに **Pod** 欄があり、Pod の **コンテナを実行** ボタンを選ぶと、その Pod が選択された状態でダイアログが開きます。Pod 内のコンテナは:

- Pod のネットワークを共有するため、ポートを公開したり、別のネットワークに参加したりできません。Pod を選ぶと、ダイアログのそれらの欄は非表示になります。
- Pod のホスト名と DNS 設定を使うため、Homeport はコンテナ独自の設定を受け付けません。
- 実行ダイアログが提供するそのほかの設定はすべて使えます: コマンド、環境変数、マウント、再起動ポリシー、リソース制限、ケーパビリティ、デバイス、ヘルスチェック、ログ。

複製と編集でコンテナが Pod に移ることはありません。Podman は既存のコンテナを Pod に移動できないためです。

## Homeport に必要なもの

Pod は、Podman 4.0 以降で、あらゆる種類の接続（ローカルソケット、SSH、TLS、TCP）で使えます。ほかのすべてと同じソケットを通じて動作するためです。
