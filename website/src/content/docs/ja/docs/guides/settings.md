**設定** はサイドバーの最後の項目です。

## 外観

**テーマ** は既定で **システムに合わせる** になっており、オペレーティングシステムのライトモードとダークモードの切り替えに追従します。固定するには **ライト** または **ダーク** を選びます。

**言語** は既定で **システムに合わせる** になっています。Homeport は、オペレーティングシステムの言語に対応していればその言語で表示し、対応していなければ英語で表示します。選択肢には、見つかった言語が **システムに合わせる（Français）** のように示されます。代わりに特定の言語を使うには、その言語を選びます。再起動なしでウィンドウ全体がすぐに切り替わり、トレイのメニューと通知も切り替わります。

Homeport は、英語、フランス語（Français）、スペイン語（Español）、ドイツ語（Deutsch）、イタリア語（Italiano）、ブラジルポルトガル語（Português）、ロシア語（Русский）、簡体字中国語（简体中文）、日本語、韓国語（한국어）、ヒンディー語（हिन्दी）、アラビア語（العربية）に対応しています。アラビア語は右から左に表示されます。地域による変種は、その言語に従います。カナダのフランス語ではフランス語が、ヨーロッパのポルトガル語ではブラジルポルトガル語が表示されます。繁体字中国語にはまだ対応しておらず、英語が表示されます。

日付、数値、サイズも言語に従い、システムにその言語の地域形式があればその形式で表示されます。イギリス英語では _1.5 GB_ と _4 Nov 2026_、フランス語では _1,5 Go_ と _4 nov. 2026_ のようになります。名前、ID、コマンド、ログ、そしてエンジンやクラスターが返す内容はそのままで、エラーの **詳細** には、失敗したシステムやライブラリの元のテキストが残ります。そのため、バグ報告はどの言語でも同じ内容になります。

## デスクトップ

このコンピューターでの Homeport の動作です。

- **閉じるとシステムトレイに常駐** — 既定ではオフで、ウィンドウを閉じると Homeport は終了します。オンにすると、ウィンドウは代わりに[システムトレイ](/docs/guides/overview/#システムトレイ)に隠れ、Homeport はホストへの接続を開いたまま動作し続けます。トレイアイコンから、または Homeport をもう一度開くと再表示されます。終了するには、トレイの **終了** を選びます。トレイのないデスクトップでは、このスイッチは説明付きでグレーアウトされます。
- **ログイン時に起動** — 既定ではオフです。オンにすると、ログイン時に Homeport が起動し、最初からホストを見守ります。スイッチはシステムの設定を反映します。自分でログイン項目から Homeport を削除した場合は、オフと表示されます。Windows では **タスク マネージャー → スタートアップ アプリ**、macOS では **システム設定 → 一般 → ログイン項目**、Linux では `~/.config/autostart/` に表示されます。AppImage の項目は、ファイルを移動すると、次に開いたときからファイルの新しい場所に従います。
- **トレイに隠した状態で起動** — 既定ではオフで、**ログイン時に起動** がオンの間だけ使えます。ログイン時に Homeport が起動すると、ウィンドウを開かずに[システムトレイ](/docs/guides/overview/#システムトレイ)に常駐します。自分で Homeport を開いたときは常にウィンドウが表示され、トレイがない場合は常にウィンドウが開きます。

## 通知

ウィンドウが開いていても、最小化されていても、[トレイに常駐](#デスクトップ)していても、ホストで何かが起きると、Homeport はオペレーティングシステムの通知を表示します。種類ごとにスイッチがあり、既定ではすべてオンで、切り替えはすぐに反映されます:

| スイッチ                                                         | 例                                                                                          |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| **コンテナがエラーで停止したとき、またはメモリ不足になったとき** | _prod-server の web-1 が停止しました（終了コード 137）_、_… の db がメモリ不足になりました_ |
| **コンテナが異常な状態になったとき**                             | _prod-server の api が異常な状態です_                                                       |
| **接続中のホストに到達できなくなったとき**                       | _prod-server に到達できません: …_                                                           |
| **到達できなかったホストが復帰したとき**                         | _prod-server に再び接続しました。_                                                          |

コンテナの停止（Homeport の **停止**、`docker stop`、`docker kill`、`docker compose down`）はクラッシュではないため、何も表示されません。終了コード 0 で終了したコンテナも同様です。Homeport の起動時に接続できなかったホストも障害とはみなされず、通知されるのは接続していたホストだけです。再起動を繰り返すコンテナや、接続が切れ続けるホストの通知は、最大で 5 分に 1 回です。

通知は Homeport がすでに保持している接続から届くため、ホストには何もインストールされず、Homeport を終了すると通知も止まります。通知の見た目と表示するかどうかはオペレーティングシステムが決めます。通知が表示されない場合は、オペレーティングシステムの通知設定で Homeport を確認してください。

## アップデート

- **アップデートを自動で確認** — 既定ではオンです。Homeport は起動時と 6 時間ごとに新しいバージョンを探し、見つかるとウィンドウの上部にバーを表示します。
- **今すぐ確認** — 自動確認がオフでもすぐに確認し、最新バージョンかどうかを表示します。

アップデートがあると、カードにできることが表示されます。これは Homeport のインストール方法によって異なります:

- **Windows、macOS、AppImage** — **インストールして再起動** を選ぶと、アップデートをダウンロードし、署名を確認してインストールし、Homeport を再び開きます。
- **`.deb` と `.rpm` パッケージ** — アップデートはパッケージマネージャーがインストールするため、カードには実行するコマンドが **コマンドをコピー** ボタンとともに表示されます。

**新機能** を選ぶと[変更履歴](/changelog/)が開きます。詳しくは[アップデート](/docs/reference/updating/)を参照してください。

## レジストリ

コンテナレジストリ（Docker Hub、GitHub Container Registry（GHCR）、独自のレジストリ）のログイン情報は、Homeport に一度保存すれば、すべてのホストで使われます。イメージのプル、まだないイメージからのコンテナの実行、プッシュ、ビルド、管理スタック・リンクスタック・同期スタックのデプロイのときです。ログイン情報はレジストリのアドレスごとに 1 つです。

- **ログイン情報を追加** では、**レジストリ**（`docker.io`、`ghcr.io`、`registry.example.com:5000`）、**ユーザー名**、**パスワードまたはアクセストークン** を入力します。GHCR と、2 要素認証を使っている Docker Hub のアカウントでは、パスワードではなくアクセストークンが必要です。
- **ログインを確認** は、`docker login` と同じように、このコンピューターからレジストリにログイン情報を受け入れるかどうかを問い合わせます。何も保存しません。拒否された場合はその旨がヒントとともに表示され、Homeport がレジストリに到達できない場合はその旨が表示されます。
- **編集** では、アドレスやユーザー名を変更します。保存済みのパスワードを使い続けるには、パスワードを空欄のままにします。**削除** はログイン情報を消去します。そのレジストリのイメージは再び匿名でプルされます。

Docker Hub は、`docker.io`、`index.docker.io`、`https://index.docker.io/v1/` のいずれでも入力できます。これらは同じ 1 つのレジストリです。`nginx` や `bitnami/redis` のように名前にレジストリを含まないイメージには、Docker Hub のログイン情報が使われます。

パスワードとトークンは OS のキーチェーンのキーで暗号化され、再表示されることも、ログに書かれることも、エラーの詳細に含まれることもありません。キーチェーンがない場合は、ログイン情報を保存できないことがカードに説明され、イメージは匿名でプルされます。[セキュリティ](/docs/reference/security/)を参照してください。

Homeport は `~/.docker/config.json` やその認証情報ヘルパーを読みません。

## リポジトリ

[同期スタック](/docs/guides/synced-stacks/)のデプロイ元となる git リポジトリです。一度保存すれば、すべてのホストで使えます。

- **リポジトリを追加** では、リポジトリの URL と、Homeport がそこにアクセスする方法を指定します。そのリポジトリ用に Homeport が作成する **デプロイキー**（SSH の URL）、ユーザー名付きの **トークン**（HTTPS の URL）、または誰でも読めるリポジトリ用の **公開** です。
- 歯車のボタンを選ぶと、リポジトリのデプロイキーと、GitHub、GitLab、Gitea、Forgejo でそれを追加する場所が表示され、**新しいキー** で置き換えられます。トークンの場合は **トークンを置き換え** です。**アクセスをテスト** は、このコンピューターからリポジトリのブランチとタグを一覧表示します。Homeport が SSH サーバーのキーを信頼すると、そのフィンガープリントがそこに表示され、フォージが実際にキーを変更した場合のために **リセット** があります。
- **削除** はリポジトリを消去し、このコンピューター上のクローンを削除します。同期スタックが使っている間は拒否されます。

キーとトークンは OS のキーチェーンのキーで暗号化され、再表示されることも、ログに書かれることも、エラーの詳細に含まれることもありません。ご自身の git の設定、認証情報ヘルパー、SSH キーが使われることはありません。[リポジトリ](/docs/guides/synced-stacks/#リポジトリ)を参照してください。

## 同期スタック

**リポジトリの確認間隔** では、同期スタックのリポジトリに新しいコミットがないかを Homeport が確認する間隔を分単位で設定します。既定は 5 分で、最小は 1 分です。Homeport が確認するのは開いている間だけで、閉じている間は何も同期されません。[ポーリングと自動デプロイ](/docs/guides/synced-stacks/#ポーリングと自動デプロイ)を参照してください。

## データ

Homeport がこのコンピューターに保持しているものです。

### バックアップと復元

**バックアップ…** は、すべてのホスト、クラスター、スタック、レジストリのログイン情報、リポジトリ、設定を、そのキー、証明書、トークン、パスワード、環境変数とともに、1 つの `.homeport` ファイルに保存します。12 文字以上のパスフレーズを 2 回入力します。ファイル全体がこのパスフレーズで暗号化され、パスフレーズは復元できません。エンジンのイベントとデプロイ履歴は含まれず、ホストやクラスター上のものも含まれません。コンテナ、イメージ、ボリューム、Kubernetes のリソースはそのまま残ります。

**復元…** は、そのようなファイルをパスフレーズで開き、内容を一覧表示します。ホストとクラスターは名前で、スタック、レジストリのログイン情報、リポジトリは数で表示されます。続いて **すべて置き換え** を選ぶと、このコンピューターでも別のコンピューターでも、Homeport のすべてのデータがバックアップの内容に置き換わります:

- すべてがすぐに接続・デプロイできます。SSH と TLS のホスト、レジストリ、リポジトリで、キーやパスワードを再び求められることも、サーバーのキーの信頼を求められることもありません。
- フォルダーがこのコンピューターにない[リンクスタック](/docs/guides/stacks/#リンクスタック)は、同じパスにフォルダーができるまで外部スタックとして表示されます。
- [同期スタック](/docs/guides/synced-stacks/)は、次の同期でリポジトリを再びクローンします。
- 現在のデータは、先に Homeport のデータフォルダー内の `homeport.db.before-restore-<date>` にコピーされます。間違ったファイル、より新しい Homeport のファイル、途中で失敗した復元では、何も変更されません。

代わりに既存のホストにいくつかのホストを追加するには、ホストページの **エクスポート** と **インポート** を使います。

### エンジンのイベントの保持

**エンジンのイベントの保持期間** では、各ホストの[エンジンのイベント](/docs/guides/overview/#イベント)を保持する日数を設定します。既定は 30 日で、1 から 365 まで指定できます。この設定にかかわらず、各ホストが保持するイベントは最大 10,000 件です。それより古いイベントは、Homeport の起動時と 1 時間ごと、そして日数を減らしたときにすぐ削除されます。

## このマシン

このコンピューターで Homeport が使えるもの:

- **OS のキーチェーン** — SSH キー、証明書、スタックの環境変数、レジストリのログイン情報を暗号化して保存できる場合は **利用可能**、できない場合は **利用不可**。[システム要件](/docs/requirements/#任意-os-のキーチェーン)を参照してください。
- **Compose CLI** — 見つかった Compose のバージョン（`docker compose v2.29.1` など）、またはスタックの起動と停止はできてもデプロイできない場合は **見つかりません**。[スタック](/docs/guides/stacks/#デプロイに必要なもの)を参照してください。
- **git** — 見つかった git（`/usr/bin/git 2.43.0` など）、または同期スタックを使えない場合はインストールするもの。[システム要件](/docs/requirements/#任意-git)を参照してください。
- **Helm CLI** — 見つかった helm（`/usr/local/bin/helm v3.16.2` など）、または [Helm のリリース](/docs/clusters/helm/)を一覧表示・インストールできない場合は、このシステムにインストールするもの。Helm 2 は未対応と表示されます。[システム要件](/docs/requirements/#任意-helm)を参照してください。

Homeport はこのページを開くたびに CLI を確認するため、起動後にインストールしたものも表示されます。キーチェーンをインストールした後は、Homeport を終了して開き直してください。

## Homeport について

Homeport のバージョンと、ビルド対象のプラットフォームを表示します（例: `v0.2.0 · macos/aarch64`）。[問題を報告する](https://github.com/DamienReichhart/Homeport/issues)ときは、これを含めてください。

**ライセンス** には、Homeport のライセンス（GNU AGPL バージョン 3）、実行中のバージョンのソースコードへのリンク、そして Homeport が使っているすべてのオープンソースパッケージの通知が表示されます。
