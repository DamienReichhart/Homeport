**インスタンス** は、[Incus のホスト](/docs/hosts/incus/)が実行するものです。ホストのカーネルを共有して Linux ディストリビューション全体を起動する **システムコンテナ** か、独自のカーネルを持つ **仮想マシン** のどちらかです。ここで説明するページはどれも、ホストの切り替えメニューの下で選んだプロジェクトを表示します。

## インスタンスページ

**インスタンス** には、プロジェクトのインスタンスが、タイプ、状態、イメージ、グローバルアドレス（IPv4 が先）、メモリ、経過時間とともに一覧表示されます。名前で絞り込んだり、コンテナだけ、または仮想マシンだけを表示したりできます。

| 操作         | Incus が行うこと                                                                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **起動**     | インスタンスを起動します。                                                                                                                                        |
| **停止**     | システムにシャットダウンを求め、30 秒待ちます。シャットダウンしない場合はその旨が報告され、**強制停止** で対処できます。                                          |
| **強制停止** | 電源プラグを抜くように、すぐに停止します。                                                                                                                        |
| **再起動**   | 正常にシャットダウンしてから、再び起動します。                                                                                                                    |
| **フリーズ** | 中のすべてのプロセスを一時停止します。**フリーズ解除** で再開します。                                                                                             |
| **削除**     | 削除前に確認があり、一緒に削除されるスナップショットが示されます。実行中のインスタンスは、**先に停止する（実行中です）** にチェックを入れたときだけ削除されます。 |

誰が変更したかにかかわらず、一覧は Incus のイベントからすぐに更新されます。

インスタンスのページには、**概要**（アドレス、CPU 時間、メモリ、プロセス、スナップショット、プロファイル。プロファイルはそれぞれのページにリンクしています）、プロファイルによる設定に **プロファイルから** と印が付いた **構成** と **デバイス**、そして **Raw** の下に Incus 自身によるインスタンスの記述があります。

## インスタンスを作成する

**新しいインスタンス**（または <kbd>n</kbd>）で、イメージからインスタンスを作成します:

- **イメージサーバーから**: 既定では公開の `https://images.linuxcontainers.org`、またはほかの simplestreams サーバー。Homeport は、サーバーがホストのアーキテクチャ向けに公開しているものを、コンテナ用または仮想マシン用として一覧表示し、システム、リリース、エイリアスで検索できます。`debian/12` や `ubuntu/24.04/cloud` のようなエイリアスを入力することもできます。Incus は、`incus launch images:debian/12` と同じようにイメージをダウンロードします。
- **このホストのイメージから**: ホストがすでに保持しているイメージ。

**プロファイル** を選び（順番どおりに適用され、後のものが前のものを上書きします）、必要に応じて **CPU**、**メモリ**（`2GiB`）、**ルートディスク** のサイズ（`20GiB`。プロファイルのルートディスクがあるプールに作成）を指定します。**作成後に起動する** は既定でオンです。ダイアログは、ダウンロードと展開の進行状況を Incus 自身の言葉で表示し、その後新しいインスタンスを開きます。

すでに使われている名前、サーバーにないイメージ、空きのないストレージプール、ハードウェア仮想化のない（`/dev/kvm` がない）ホストでの仮想マシンは、それぞれその旨と対処方法が表示されます。

## コンソールとターミナル

**コンソール** は、インスタンスがこれまでにテキストコンソールに出力した内容を表示してから、コンソールに接続します。`incus console` と同じように、ログインプロンプトや、進行中の起動処理が表示されます。仮想マシンでも、インスタンスのネットワークや SSH が壊れているときでも使えます。タブを離れたり **再接続** を選んだりしても、接続が切り離されるだけです。

**Exec** は、実行中のインスタンスでシェル（bash があれば bash、なければ sh）を開くか、指定したコマンドを、数値で指定したユーザーとして、選んだフォルダーで実行します。**開く** を選ぶと、入力した内容で新しく開始します。タブを閉じるとコマンドは切断されるため、そこから開始したものが動作し続けることはありません。仮想マシンでは、Exec には `incus-agent` が必要です。これは Incus 自身のイメージに含まれ、起動時に開始されます。これが動作するまでは Homeport がその旨を表示するので、コンソールタブから入ってください。

## スナップショット

**スナップショット** には、インスタンスのスナップショットが、作成日時、有効期限、実行状態を保持しているかどうかとともに一覧表示されます。

- **スナップショットを作成** では、名前を付け（または Incus に `snap0`、`snap1`… と名前を付けさせ）、削除するまで、または 1 日、1 週間、30 日間保持します。インスタンスの実行中で、`migration.stateful` の設定が許可していれば、スナップショットにメモリを含めることができ、復元すると元の場所から再開します。
- **復元** は、インスタンスをスナップショットを作成した時点の状態に戻します。それ以降の変更はすべて失われ、実行中のインスタンスは再起動するため、Homeport は先に確認します。
- **削除** は、確認の後にスナップショットを削除します。インスタンスはそのままです。

## イメージ

**イメージ** には、プロジェクトが保持しているイメージが、エイリアス、説明、タイプ、アーキテクチャ、サイズ、経過時間とともに一覧表示されます。インスタンスの作成のために Incus がダウンロードしたイメージには **キャッシュ** の印が付きます。Incus は、しばらく使われなかったものを削除します。

- **イメージを取得** では、新しいインスタンスと同じ方法で選んだイメージを、イメージサーバーから前もってダウンロードします。**サーバーから最新の状態に保つ** を選ぶと、Incus がサーバーからイメージを更新します。**ここでも同じエイリアスを付ける** を選ぶと、新しいインスタンスがその名前でイメージを使えるようになります。
- **更新** は、イメージの取得元から新しいビルドを取得します。
- タグのボタンでエイリアスを追加し、エイリアスの × で削除します。
- **削除** はイメージを削除します。そこから作成したインスタンスは動作し続けます。それぞれが独自のコピーを持っているためです。

## プロファイル

**プロファイル** には、プロジェクトのプロファイルが、それぞれが設定するキーとデバイスの数、それを使っているインスタンスとともに一覧表示されます。プロファイルのページでは、`incus profile edit` と同じように、説明、構成、デバイスを YAML で編集でき、それを使っているインスタンスへのリンクがあります。**保存** を選ぶと、Incus と同じように、変更がそれらのインスタンスに適用されます。ページがプロファイルを読み込んだ後に誰かが変更していた場合、相手の変更を上書きせずに保存は拒否されます。**再読み込み** してから、もう一度変更してください。

**新しいプロファイル** は空のプロファイルを作成して開きます。`default` と、インスタンスが使っているプロファイルは削除できません。

## ストレージ

**ストレージ** には、各ストレージプールがドライバーと使用率とともに表示され、選択したプールにあるプロジェクトのボリューム（インスタンスやイメージ自身のボリュームとカスタムボリューム）が、内容、サイズ、使用しているものとともに表示されます。

**新しいボリューム** は、インスタンスより長く残るデータのためにインスタンスに接続する（`incus storage volume attach`）カスタムボリュームを、ファイルシステムまたはブロックデバイスとして、指定したサイズかプールの既定のサイズで作成します。カスタムボリュームは、何にも使われていなければ削除できます。プール自体は `incus storage create` で作成します。

## ネットワーク

**ネットワーク** には、プロジェクトから見えるネットワークが、管理ネットワーク（Incus が作成したもの）を先頭に、IPv4 と IPv6 の設定、NAT、利用者とともに一覧表示されます。ネットワークのページには、ホスト上のアドレス、MTU、MAC アドレス、それを使っているインスタンスとプロファイル、そして管理ネットワークの場合は、`incus network list-leases` と同じように DHCP のリースが表示されます。

**新しいブリッジ** は管理ブリッジを作成します。IPv4 と IPv6 には、`auto`（空いているサブネット）、`none`、または `10.0.5.1/24` のようにプレフィックス付きのブリッジ自身のアドレスを指定します。**NAT** は、送信する IPv4 トラフィックをマスカレードします。使用中のネットワークや、マシン自身のインターフェースは、ここからは削除されません。
