## 概要

**概要** は、すべてのホストと[クラスター](/docs/clusters/)をまとめて表示する唯一のページです。Homeport の起動時に開きます。上部の **ホストを追加** と **クラスターを追加** から、それぞれを追加するページに進みます。

### ホストのカード

各ホストには、名前、アドレス、タイプ、状態を示すカードがあります。接続しているホストでは、次の情報も表示されます:

- 実行中のコンテナ数と全コンテナ数、イメージの数。
- コンテナによる CPU 使用率のリアルタイム表示。1 CPU に対する割合で、8 CPU のホストで `250%` なら 2.5 CPU 分が使われていることを意味します。
- コンテナが使用しているメモリと、ホストのメモリ総量。

カードを選ぶと、そのホストに切り替わります。接続していれば、Homeport はその **コンテナ** を開きます。**ボードでこのホストのコンテナを表示** を選ぶと、そのホストだけを表示した状態で[ボード](#ボード)が開きます。

### クラスターのカード

ホストのカードの後に、各クラスターのカードが続きます。名前、API サーバー、状態、Kubernetes のバージョンが表示され、接続後は、準備ができている Node の数と、実行中の Pod の数（そのページが表示している Namespace 内）も表示されます。これらは Homeport 側で数え、概要を開いている間は 30 秒ごとに問い合わせ直します。認証情報で読み取りが許可されていない数は、代わりに **許可されていません** と表示されます。カードを選ぶと、そのクラスターに切り替わります。

### 選択したクラスター

クラスターを選択すると、カードの下のセクションには、ホストの代わりにそのクラスターが表示されます:

<DocScreenshot
  name="cluster-overview"
  alt="3 つのホストのカード、2 つのクラスターのカード、選択した EKS クラスターのダッシュボードが表示された概要。バージョン、5 台中 4 台の Node が準備完了、フェーズごとの Pod、準備ができていないワークロード、最近の警告。"
  caption="eks-prod を選択した概要。Node が 1 台準備できておらず、api と search は Pod が不足しています。"
/>

- **クラスター** — バージョン、プラットフォーム、API サーバー、そのページが表示している Namespace。
- **Node** — 準備ができている数と、準備ができていない各 Node。それぞれのページにリンクしています。
- **Pod** — 実行中、待機中、失敗（クラッシュしている、またはイメージをプルできない）、完了の数。
- **準備ができていないワークロード** — 準備ができている Pod が必要な数に満たない Deployment、StatefulSet、DaemonSet。それぞれのページにリンクしています。
- **最近の警告** — 直近の Warning イベント。それぞれ対象のオブジェクトにリンクしています。**すべてのイベント** を選ぶと、クラスターのイベントが開きます。

認証情報で読み取れない部分はその旨が表示され、ほかの部分は引き続き表示されます。

### 選択したホスト

カードの下には、選択したホストのセクションが表示されます:

- **エンジン** — 名前、バージョン、オペレーティングシステム、カーネル、アーキテクチャ、CPU とメモリ、ストレージドライバー、ルートディレクトリ。
- **ディスク使用量** — イメージ、コンテナ、ボリューム、ビルドキャッシュが占める容量、そのうち使用中の量、解放できる量。バージョン 29 より古い Docker Engine は報告する情報が少なく、その場合イメージのサイズは推定値になり、ボリュームとビルドキャッシュのサイズは **—** と表示され、カードにその旨が示されます。
- **最近のイベント** — エンジンが直近に報告したいくつかの出来事。**すべてのイベント** を選ぶと、イベントページが開きます。

### 未使用のものを削除する

ディスク使用量のカードにある **未使用を削除…** は、何にも使われていないものを、選択したホストでのみ削除します。削除するものを選んでください:

| オプション                   | 既定 | 削除されるもの                                                           |
| ---------------------------- | :--: | ------------------------------------------------------------------------ |
| **停止中のコンテナ**         | オン | 実行中でないすべてのコンテナ。                                           |
| **dangling イメージ**        | オン | ビルドやプルで残された、タグのないレイヤー。                             |
| **未使用のすべてのイメージ** | オフ | どのコンテナも使っていないタグ付きイメージと、dangling イメージ。        |
| **未使用のネットワーク**     | オン | どのコンテナも接続していないカスタムネットワーク。                       |
| **ビルドキャッシュ**         | オン | キャッシュされたビルドレイヤー。                                         |
| **未使用のボリューム**       | オフ | どのコンテナも使っていないすべてのボリューム。**そのデータも含みます**。 |

コンテナが最初に削除されるため、コンテナが保持していたイメージ、ネットワーク、ボリュームも未使用として扱われます。その後、Homeport は解放された容量を表示します。

<Aside type="danger">
  **未使用のボリューム**
  は、名前付きボリュームを含めてデータを削除し、元に戻せません。これにチェックを入れると、最後の注意として、ボタンの表示が
  **ボリュームのデータも含めて削除** に変わります。
</Aside>

## ボード

サイドバーの 2 番目にある **ボード** は、接続しているすべてのホストのコンテナを 1 つの表に一覧表示します。ホストを切り替えずに、どこで何が動いていて、何が止まっているかがわかります。

<DocScreenshot
  name="board"
  alt="3 つのホストのコンテナを、ホスト列、フィルター、リアルタイムの CPU とメモリとともに一覧表示したボード。"
/>

- **列** — ホスト、名前、イメージ、状態（ヘルス状態を含む）、スタック、ポート、CPU、メモリ、作成日時。列名を選ぶとその列で並べ替え、もう一度選ぶと逆順になります。CPU とメモリはリアルタイムで更新されます。
- **フィルター** — 表示するホスト（既定ではすべて）、状態（**実行中**、**停止**、**異常**）、1 つのスタック、そして名前、短い ID、イメージ、スタック、ホスト名に一致する検索。<kbd>/</kbd> で検索欄に移動します。**フィルターをクリア** を選ぶと、すべてが再び表示されます。コンテナを開いて戻ってきても、フィルターはそのまま残ります。
- **操作** — 各行には、コンテナページと同じ起動/停止ボタンとメニューがあり、その行のホストに対して動作します。1 つまたは複数のホストにまたがって複数の行にチェックを入れると、まとめて起動、停止、再起動、削除できます。削除する前には確認があり、対象のコンテナがホストごとに一覧表示されます。
- **コンテナを開く** — 行を選ぶと、Homeport はそのホストに切り替えてコンテナを開きます。**戻る** でボードに戻ります。

ボードを開かずに、すべてのホストのコンテナから 1 つを探すには、[コマンドパレットから検索](/docs/guides/keyboard/#すべてのホストを検索する)します。

接続していないホスト（到達不能、無効、操作待ちなど）は、表の上に 1 行で示されます。例: _nas（到達不能）は表示されていません。_ そのページへのリンクも付きます。ほかのホストは通常どおり一覧表示されます。コンテナが数百を超えると、表示範囲内の行だけが描画されるため、ボードの動作は軽いままです。

## システムトレイ

Homeport はシステムトレイ（macOS ではメニューバー、Windows では通知領域）にアイコンを追加します。そのメニューには、すべてのホストが **prod-server — 接続済み** のように状態とともに一覧表示され、状態が変わるとすぐに更新されます:

- ホストを選ぶと、ウィンドウが前面に表示され、そのホストの概要が開きます。
- **到達不能** のホストには、**開く** と **再接続** のサブメニューがあります。**再接続** はすぐに接続を再試行します。
- **Homeport を開く** でウィンドウが再び表示され、**ホストを追加…** でホストを追加するページが開き、**終了** は常に Homeport を終了します。

アイコンのツールチップには、**Homeport — 4 台中 3 台のホストに接続中** のように要約が表示されます。Windows では、アイコンをダブルクリックするとウィンドウが開きます。

[設定](/docs/guides/settings/#デスクトップ)で **閉じるとシステムトレイに常駐** をオンにすると、ウィンドウを閉じても Homeport は終了せずに非表示になり、ホストへの接続は開いたままになります。トレイから、または Homeport をもう一度開くと再表示されます。一部の Linux デスクトップではトレイアイコンが表示されません。[システム要件](/docs/requirements/#任意-システムトレイ)を参照してください。

### 通知

Homeport の実行中は（トレイに隠れているときも）、コンテナがエラーで停止したとき、メモリ不足になったとき、異常になったとき、そしてホストに到達できなくなったときや再び接続できたときに、オペレーティングシステムの通知でお知らせします。それぞれの種類は[設定](/docs/guides/settings/#通知)でオン/オフを切り替えられます。

## イベント

**イベント** ページには、選択したホストのエンジンが報告した出来事が新しい順に一覧表示されます。コンテナの起動と停止、イメージのプル、ボリュームの作成、ネットワークの接続などです。Homeport はこれらを保持するため、再起動後も残っています。「夜の間に何が再起動したか」にも答えられます。

| 列           | 表示内容                                   |
| ------------ | ------------------------------------------ |
| **時刻**     | 発生した日時（ローカル時刻）。             |
| **種類**     | `container`、`image`、`volume`、`network`… |
| **操作**     | `start`、`die`、`pull`、`create`…          |
| **対象**     | 対象となったものの名前。                   |
| **スタック** | 属しているスタック（ある場合）。           |

操作やオブジェクト名で検索したり、種類で絞り込んだりできます。一覧はリアルタイムで更新されます。

### 保持される内容

- **再起動をまたいで。** イベントは届いた時点でこのコンピューターに保存されます。ページには最新の 1,000 件が表示されます。一番下までスクロールするか、**古いイベントを読み込む** を選ぶと、さらに 1,000 件ずつ表示されます。
- **Homeport を閉じていた間も。** Homeport がホストに再接続すると、最後に保持したイベント以降のイベントをエンジンに問い合わせるため、その間に起きたことも補完されます。さかのぼれるのはエンジンが覚えている範囲（直近の数百件）までです。同じイベントが二重に表示されることはありません。
- **30 日間**、または [設定 → データ](/docs/guides/settings/#データ)の **エンジンのイベントの保持期間** で指定した期間、ホストごとに最大 10,000 件まで保持します。それより古いイベントは 1 時間ごとに削除されます。

**履歴を消去** を選ぶと、選択したホストについて保持しているすべてのイベントが消去されます。新しいイベントは引き続き表示されます。ホストを削除すると、そのイベントも削除されます。エンジン自体のイベントが変更されることはありません。

ボリュームを開くための Homeport 自身の[ヘルパーコンテナ](/docs/guides/volumes-networks/#ヘルパーコンテナ)が、ここに表示されることはありません。
