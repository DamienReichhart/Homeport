Homeport は、すべての[言語](/docs/guides/settings/#外観)で、キーボードだけでも、スクリーンリーダーでも、視差効果を減らす設定でも使えることを目指しています。このページでは、何が使えて何がまだ使えないか、そして使う上での障壁があったときにどう知らせればよいかを説明します。

## 移動

Homeport のすべての要素には <kbd>Tab</kbd> と <kbd>Shift</kbd> <kbd>Tab</kbd> で移動でき、<kbd>Enter</kbd> か <kbd>Space</kbd> で操作できます。フォーカスの位置はリングで表示されます。

- **サイドバー** にはすべてのページが並び、それぞれがリンクです。<kbd>Mod</kbd> <kbd>1</kbd> ～ <kbd>9</kbd> で順に開けます。[コマンドパレット](/docs/guides/keyboard/#コマンドパレット)（<kbd>Mod</kbd> <kbd>K</kbd>）を使えば、入力してすべてのページ、ホスト、操作に到達できます。
- **一覧**（コンテナ、イメージ、ボリューム、ネットワーク、スタック、ホスト、Pod…）: 各行の名前はボタンかリンクです。<kbd>Tab</kbd> で移動して <kbd>Enter</kbd> を押すと、行をクリックしたときと同じように項目が開きます。チェックボックスはその前、行のメニューはその後にあります。
- **並べ替え**: 並べ替えできる列の見出しはボタンです。<kbd>Enter</kbd> か <kbd>Space</kbd> を押すとその列で並べ替え、もう一度押すと逆順になります。スクリーンリーダーは並び順を読み上げます。
- **コンテナ一覧のスタック** は、名前の前にあるボタンで開閉します。ボタンは展開されているかどうかを伝えます。
- **ダイアログ** は開くとフォーカスを受け取り、開いている間はフォーカスを内側に保ち、閉じるとそれを開いた要素にフォーカスを戻します。<kbd>Esc</kbd> を押すと、何もせずにダイアログを閉じます。
- **メニュー、選択欄、タブ** は矢印キー、<kbd>Home</kbd>、<kbd>End</kbd> で移動し、<kbd>Enter</kbd> で選択、<kbd>Esc</kbd> で閉じます。
- **ショートカット**: どのページでも <kbd>?</kbd> を押すと、そのページで使えるショートカットが一覧表示されます。[キーボード](/docs/guides/keyboard/)を参照してください。

## ターミナル、ログ、エディター

コンテナの **ターミナル** とログビューアーは、フォーカスがある間はすべてのキーを受け取るため、中のプログラムは <kbd>Tab</kbd>、<kbd>Esc</kbd>、<kbd>Ctrl</kbd> キーも受け取ります。マウスか、スクリーンリーダー自身のコマンドでフォーカスを移動して抜けてください。

compose、YAML、ジョブ、ユニットのエディターは、スクリーンリーダー向けの名前が付いた CodeMirror エディターです。エディター内では <kbd>Tab</kbd> でインデントします。エディターからフォーカスを移すには、<kbd>Esc</kbd> を押してから <kbd>Tab</kbd> を押します。

## 視差効果を減らす

オペレーティングシステムが視差効果を減らすよう求めている場合（macOS の **視差効果を減らす**、Windows の **アニメーション効果** のオフ、GNOME と KDE の **アニメーションを減らす**）、Homeport はフェードだけを使います。ダイアログ、メニュー、選択欄、ツールチップはズームもスライドもせず、何も点滅せず、ボタンは押しても動かず、ターミナルのカーソルは点滅しなくなります。スピナーは処理が進行中であることを示すため、回転を続けますが、速度は遅くなります。設定の変更は再起動なしで反映されます。

## スクリーンリーダー

すべてのページと主なダイアログは、変更のたびに [axe](https://github.com/dequelabs/axe-core) で確認されています。ボタン、フィールド、領域には名前があり、見出しとランドマークは正しい順序で、ARIA の誤用はありません。Homeport はページの言語を設定しているため、スクリーンリーダーは各言語をその言語の音声で読み上げ、アラビア語は右から左に表示されます。

Homeport のウィンドウは Web ビューです。Linux では WebKitGTK、macOS では WKWebView、Windows では WebView2 です。それぞれでの Orca、VoiceOver、NVDA を使った実地の監査を進めています（[#184](https://github.com/DamienReichhart/Homeport/issues/184)）。完了するまでは、スクリーンリーダーでの使い勝手はツールによるテストのみと考えてください。

### 現在わかっている制限

- **ターミナルとログ**: コンテナのターミナルとログビューアー内のテキストは、まだスクリーンリーダーで読み上げられません。出力をコピーするか、`docker logs` を使ってターミナルでログを開いてください。
- **リアルタイムの一覧**: 一覧はエンジンが変更を報告するたびにその場で更新されますが、変更ごとの読み上げはありません。行った操作はトーストで読み上げられます。
- **グラフ** は値を描画します。それぞれの最新の値は、グラフのタイトルにもテキストとして含まれています。

## コントラスト

テキストは、ライトテーマとダークテーマの両方で WCAG 2.2 AA（4.5:1）を満たしており、フィールドの境界線、フォーカスリング、ステータスの形状（3:1）も同様です。ステータスは色だけに頼らず、それぞれ独自の形状を持っています。比率はプロジェクトのブランドガイドに記載されています。

## バリアの報告

キーボード、スクリーンリーダー、拡大鏡などの支援技術で Homeport を使う上で妨げになるものがあれば、`accessibility` ラベルを付けて [issue を作成](https://github.com/DamienReichhart/Homeport/issues/new?labels=accessibility)してください。次のことを書いてください:

- 何をしようとしていたか、そしてどこで（ページ、ダイアログ、ホストの種類）
- オペレーティングシステムとそのバージョン、支援技術とそのバージョン
- 何が聞こえたか、または見えたか、そして何を期待していたか

バリアは機能要望ではなく、バグとして扱います。
