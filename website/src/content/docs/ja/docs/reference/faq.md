### Homeport は無料ですか？

はい。Homeport は個人でも商用でも無料で使え、[GNU Affero General Public License バージョン 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE)（AGPL）のもとで公開されたオープンソースです。

### AGPL は自分にどう関係しますか？

Homeport を使うだけなら何も変わりません。インストールして、自宅でも職場でも、何台のコンピューターでも実行できます。AGPL が求めるのは、改変の有無にかかわらず Homeport を **配布** する人、または改変したバージョンをネットワーク越しにほかの人に提供する人に対してだけです。その場合、完全なソースコードを同じライセンスで公開する必要があります。Homeport のどのコピーにも、**設定** の下部にある **ライセンス** に、そのバージョンのソースへのリンクがあります。

バージョン 0.11 までは MIT ライセンスで公開されており、引き続きそのライセンスで利用できます。

### Homeport は Docker Desktop の代わりになりますか？

完全にではありません。Homeport は管理ツールであり、Docker Engine そのものは実行しません。Linux では Docker Engine をインストールし、Homeport をそのインターフェースとして使ってください。macOS と Windows では、エンジンを実行するもの（Docker Desktop、Colima、OrbStack、Rancher Desktop、Podman）が引き続き必要です。Homeport はそのどれの上でも、リモートのサーバーとあわせて使えます。

### containerd で使えますか？

はい。Docker なしで直接使えます。ホストのエンジンには [containerd](/docs/hosts/containerd/) を指定でき、このマシン上のソケット経由か SSH 経由で到達します。k3s のもの、Docker Engine 自身のもの、サーバー上の containerd のサービスが対象です。Homeport は名前空間、コンテナとそのタスク（起動、停止、一時停止、シグナル、削除）、nerdctl や Kubernetes が書き込んだ場所にあるログ、コンテナ内のターミナル、イメージ（プル、削除）、スナップショットを扱えます。containerd 上でのコンテナの作成やスタックのデプロイは行いません。それは nerdctl の役割です。

### Incus で使えますか？

はい。ホストのエンジンには [Incus](/docs/hosts/incus/) 6.0 以降を指定でき、このマシン上のソケット経由か SSH 経由、または `incus config trust add` で得た信頼トークンを使って HTTPS 経由で到達します。Homeport はプロジェクトの[インスタンス](/docs/guides/instances/)（システムコンテナと仮想マシン）を一覧表示し、起動、停止、凍結、削除、作成ができ、コンソールやインスタンス内のターミナルを開き、スナップショットを作成・復元し、イメージ、プロファイル、ストレージプール、ネットワークを管理できます。Incus 上でスタックはデプロイせず、ホストには何もインストールしません。

### LXD で使えますか？

そのままでは使えません。Homeport が話すのは LXD のコミュニティフォークである Incus で、API が変わってしまった LXD のサーバーは拒否します。`lxd-to-incus` で移行してから、Incus のホストとして追加してください。

### Podman で使えますか？

はい。Podman の Docker 互換 API ソケットを通じて使えます。Homeport は Linux の通常の Podman ソケット、動作中のすべての [macOS の Podman マシン](/docs/hosts/local/#podman-machines-on-macos)、Windows の既定の Podman マシンのパイプを検出します。それ以外は[手動で追加](/docs/hosts/local/#adding-a-socket-by-hand)できます。

Homeport は接続時に Podman を識別し、同じソケット上の Podman 独自の API を通じて、Podman にしかない機能も提供します。[Pod](/docs/guides/podman-pods/) は一覧表示、起動、停止、作成、削除ができ、「実行」ダイアログからその中でコンテナを実行できます。[Quadlet ユニット](/docs/guides/quadlet/)は一覧表示、閲覧、インストール、編集、削除ができ、SSH 経由で起動や停止ができます。

### Kubernetes、Nomad、Docker Swarm で使えますか？

Docker Swarm は使えます。Homeport は、マネージャーのホストのいずれかがホストとして追加されていれば、それを通じて Swarm を見つけ、完全に管理します。ノード、サービス、タスク、シークレット、コンフィグ、Swarm のスタック（Swarm にデプロイした管理スタック、リンクスタック、同期スタックを含む）を扱えます。ホスト上で Swarm を開始したり、Swarm に参加したり離脱したりすることもできます。すべて接続済みのマネージャーのエンジン API を通じて行われ、ノードには何もインストールされません。[Swarm](/docs/guides/swarm/) を参照してください。

Kubernetes も使えます。kubeconfig（このコンピューターのもの、または貼り付けたもの）からクラスターを追加でき、ローカルのもの（Docker Desktop、OrbStack、Rancher Desktop、kind、k3d、minikube）は Homeport が見つけます。EKS、GKE、AKS は、kubeconfig が指定する exec プラグインを通じて動作します。Namespace、ワークロード、Pod、Service、Ingress、ConfigMap、Secret、Node、Events、そしてカスタムリソースを含むほかのあらゆる API リソースをリアルタイムで閲覧できます。ログの追跡、Pod 内でのターミナル、ポートフォワード、スケール、再起動、削除、プレビュー付きの YAML の適用や編集もできます。クラスターには何もインストールされません。Homeport は kubeconfig がすでに到達できる Kubernetes API と、その認証情報の権限の範囲でだけ通信します。このコンピューターに `helm` CLI があれば、[Helm リリース](/docs/clusters/helm/)の一覧表示、インストール、アップグレード、ロールバック、アンインストールや、helm のチャートリポジトリの管理もできます。[クラスター](/docs/clusters/)を参照してください。

Nomad も使えます。エージェントのアドレスでクラスターを追加し、必要に応じて ACL トークンと TLS の情報を指定します。ジョブとそのアロケーションのリアルタイムの一覧表示、Nomad の計画を確認した上での HCL や JSON からのジョブの実行、ジョブの編集と再実行、停止や完全削除、タスクグループのスケール、タスクのログの追跡やシェルの起動、ノードのドレインと適格性の切り替え、名前空間の選択ができます。クラスターには何もインストールされず、`nomad` CLI も必要ありません。Homeport はトークンの権限の範囲で Nomad の HTTP API と通信します。[Nomad クラスター](/docs/clusters/nomad/)を参照してください。

### kubectl は必要ですか？

いいえ。Homeport は kubeconfig を読み込み、Kubernetes API と直接通信します。Homeport が実行するプログラムは、kubeconfig が指定する [exec プラグイン](/docs/clusters/exec-plugins/)（EKS 用の AWS CLI、GKE 用の `gke-gcloud-auth-plugin`、AKS 用の `kubelogin` など）だけで、これは `kubectl` が実行するものと同じです。それでも、認証情報で何ができるかを確認する（`kubectl auth can-i`）には `kubectl` があると便利です。

### サーバーに何かをインストールする必要はありますか？

いいえ。必要なのは Docker Engine と SSH サーバーだけで、どちらもおそらくすでにあるでしょう。Homeport はエージェントをインストールしません。

Swarm にもエンジン以外は必要ありません。ただし、ノード同士が互いに到達できる必要があり、これは Homeport では設定できません。ノード間で 2377/tcp（マネージャー宛て）、7946/tcp と 7946/udp、4789/udp を開放してください。[ノード間のポート](/docs/guides/swarm/#ports-between-nodes)を参照してください。

### リモートのサーバーを管理するのに、手元のコンピューターに Docker が必要ですか？

いいえ。Homeport はエンジン API と SSH を自分で話します。例外は、手元のコンピューターで `docker compose` コマンドを使う管理スタック、リンクスタック、同期スタックのデプロイと、`docker` コマンド（`docker stack deploy`）を使う Swarm へのデプロイだけです。どちらも手元のコンピューターにエンジンは必要ありません。

### Homeport を閉じている間もスタックは同期されますか？

いいえ。[同期スタック](/docs/guides/synced-stacks/)の新しいコミットの確認と、有効にしている場合の自動デプロイは、Homeport が開いている間だけ行われます。Homeport はサーバーに何もインストールしない（エージェントも Webhook の受信先もない）ため、閉じている間はリポジトリを監視するものは何もありません。もう一度開くと、1 回分の間隔を待ってからすべてを確認します。プッシュのたびに 24 時間いつでもデプロイする必要がある場合は、CI から実行してください。

ウィンドウなしで Homeport を動かし続けるには、[設定 → デスクトップ](/docs/guides/settings/#desktop)で **閉じるとシステムトレイに常駐** をオンにし、**ログイン時に起動** と **トレイに隠した状態で起動** をオンにします。

### コンテナがクラッシュしたときに Homeport から通知を受けられますか？

はい、Homeport が動作している間は受けられます（システムトレイに隠れている場合も含む）。コンテナがエラーで停止したとき、メモリ不足になったとき、unhealthy になったとき、そしてホストが到達不能になったときや復帰したときに、OS の通知を表示します。種類ごとに[設定 → 通知](/docs/guides/settings/#notifications)でオフにできます。Homeport は各ホストとの間ですでに保持しているイベントストリームからこれを知るため、サーバーには何もインストールされません。Homeport が動いていないときは、誰にも通知されません。

### Homeport に git は必要ですか？

[同期スタック](/docs/guides/synced-stacks/)にだけ必要です。同期スタックは、コンピューターにインストールされた `git` を、各リポジトリ専用のデプロイキーかトークンとともに使います。Homeport が git を見つけたかどうかは **設定 → このマシン** に表示されます。ご自身の git の設定、認証情報ヘルパー、SSH キーが使われることはありません。

### Homeport のホストを複数人で共有できますか？

各自がそれぞれ自分のホストとキーで自分の Homeport を実行します。人ごと、サーバーごとに Homeport が作成したキーを使えば、`authorized_keys` で各自のアクセスを確認し、取り消せます。

### Homeport を別のコンピューターに移せますか？

はい。方法は 2 つあります:

- **すべて**: **設定 → データ → バックアップ…** で、すべてのホスト、クラスター、スタック、レジストリのログイン情報、リポジトリ、設定を、シークレットとともに、12 文字以上のパスフレーズで保護された 1 つのファイルに保存します。新しいコンピューターでは、同じ場所の **復元…** でファイルを開くと、含まれる内容が一覧表示され、既存の内容が置き換えられます。キーやパスワードを再び求められることなく、すべてが接続し、デプロイできます。[バックアップと復元](/docs/guides/settings/#backing-up-and-restoring)を参照してください。
- **一部のホスト**: **ホスト** ページで、選んだホストを **エクスポート** し、もう一方のコンピューターで **インポート** すると、既存のホストに加えて追加されます。[別のコンピューターへの移行](/docs/reference/security/#moving-to-another-computer)を参照してください。

`homeport.db` をコピーしてもシークレットは移行できません。シークレットはこのコンピューターのキーチェーンにある鍵で暗号化されているため、ほかの場所では **認証情報が失われました** と表示されます。

### バックアップにはコンテナやボリュームも含まれますか？

いいえ。バックアップに含まれるのは Homeport が保持しているもの（ホストへの到達方法、スタックの定義と環境変数、ログイン情報、設定）で、ホスト上で動いているものは含まれません。コンテナ、イメージ、ボリュームはホスト上に残ります。ボリュームのデータをコピーするには、「ボリューム」ページから[ファイルにバックアップ](/docs/guides/volumes-networks/#backing-up-and-restoring)してください。

### Homeport でイメージをビルドできますか？

はい、2 つの場所でできます。**イメージ** ページでは、このコンピューター上のフォルダーからイメージをビルドできます。また、[リンクスタック](/docs/guides/stacks/#linked-stacks)（compose ファイルがこのコンピューター上のフォルダーにあるスタック）では `build:` を使えます。Homeport はそのフォルダーで `docker compose` を実行するため、ビルドコンテキストはそこからホストのエンジンに送られ、エンジンがビルドします。コードを変更した後は **再ビルドしてデプロイ** で再ビルドできます。管理スタックはビルドできません。Homeport が保持しているのは YAML だけで、ビルド元のフォルダーがないためです。代わりにフォルダーをリンクするか、イメージをレジストリにプッシュしてください。

### 別のコンピューターでスタックが外部スタックとして表示されるのはなぜですか？

フォルダーで `docker compose up` を使って起動したスタックが[リンクスタック](/docs/guides/stacks/#how-linked-stacks-are-found)として表示されるのは、そのフォルダーと compose ファイルが同じパスに存在し、実際に動いているサービスを定義しているコンピューターだけです。別のコンピューターではそのパスが存在しないため、Homeport はそのスタックの compose ファイルを持たず、外部スタックとして表示します。そちらからも管理するには、プロジェクトをそのコンピューターにクローンして **新しいスタック → このコンピューター上のフォルダーを使う** でリンクするか、管理スタックとして引き継いでください。

### Homeport は私についてのデータを収集しますか？

いいえ。アカウントも、テレメトリも、分析もありません。Homeport が自らコンピューターから行うリクエストはアップデートの確認だけで、このサイトから小さなファイルをダウンロードし、ユーザーについての情報は何も送りません。これは **設定 → アップデート** でオフにできます。これとは別に、新しいイメージの確認では、各ホストのエンジンを通じてイメージのレジストリに、タグがどのバージョンを指しているかを問い合わせます。ローカルのホストの場合、このリクエストもコンピューターから送られます。[セキュリティとデータ](/docs/reference/security/#what-homeport-connects-to)を参照してください。

### Homeport でプライベートレジストリを使えますか？

はい。**設定 → レジストリ** で、レジストリごとにログイン情報（Docker Hub、GHCR、独自のもの）を追加してください。Homeport はそれをエンジンに渡し、どのホストでもプル、プッシュ、ビルドに使います。また、管理スタック、リンクスタック、同期スタックのイメージをデプロイ前にそれを使ってプルします。パスワードとトークンは OS のキーチェーンで暗号化されます。Homeport は、このコンピューターの `docker login` のログイン情報は読み込みません。

### Homeport はどうやって新しいイメージがあることを知るのですか？

ホストのエンジンを通じてイメージのレジストリに、タグが現在どのダイジェストを指しているかを問い合わせ、ホストがプルしたものと比較します。何もダウンロードされませんが、Docker Hub は、新しいものが見つからなかった `docker pull` と同様に、問い合わせのたびにプルのレート制限にカウントします。そのため Homeport は各回答を 6 時間保持し、同時に問い合わせるレジストリは最大 4 つまでとし、それより早く問い合わせ直すのは **新しいイメージを確認** を選んだときだけです。**設定 → レジストリ** に Docker Hub のログイン情報があれば、制限が緩和されます。レジストリに到達できない場合やレート制限中の場合、Homeport はそのイメージに印を表示せず、ログに 1 行書き込みます。

### アップデートするにはどうすればよいですか？

Windows、macOS、AppImage では、新しいバージョンが出ると Homeport が知らせます。**インストールして再起動** を選んでください。Linux では、`.deb` と `.rpm` のパッケージが、Homeport のパッケージリポジトリからシステムのほかの部分と一緒にアップデートされます。[アップデート](/docs/reference/updating/)を参照してください。

### Homeport は Homebrew、winget、Flathub、AUR にありますか？

まだありません。予定はあり、[インストールのページ](/docs/installation/#coming-later)にそれぞれの issue へのリンクがあります。

### Homeport は私の言語に対応していますか？

Homeport は英語、フランス語、スペイン語、ドイツ語、イタリア語、ブラジルポルトガル語、ロシア語、簡体字中国語、日本語、韓国語、ヒンディー語、アラビア語に対応しており、[設定 → 外観](/docs/guides/settings/#appearance)で言語を選ばない限り、オペレーティングシステムの言語に従います。Web サイトもすべての言語に対応しています。ドキュメントはフランス語に完全に翻訳されており、ほかの言語では、翻訳がまだないページは英語のページが表示されます。言語を追加するには、[コントリビューション](/docs/project/contributing/#translating-homeport)を参照してください。

### Homeport はアクセシブルですか？

キーボードだけで使え、システムの視差効果を減らす設定に従い、WCAG 2.2 AA のコントラストを満たしており、すべてのページが自動のアクセシビリティツールで確認されています。スクリーンリーダーによる実地の監査を進めています。何が使えるか、現在わかっている制限、バリアの報告方法については、[キーボードとアクセシビリティ](/docs/reference/accessibility/)を参照してください。

### コマンドラインインターフェースはありますか？

いいえ。Homeport はデスクトップアプリです。既存の `docker` CLI と併用でき、ターミナルから変更すると Homeport にもリアルタイムで反映されます。
