Homeport は、知っていることをすべてこのコンピューターに保存します。ホストとクラスターへの到達方法、スタックの定義と環境変数、レジストリのログイン情報、リポジトリ、設定です。このページでは、それがどこにあるか、何をコピーすればよいか、どう元に戻すかを説明します。それがどのように保護されているかは、[セキュリティとデータ](/docs/reference/security/)を参照してください。

ホストとクラスターで動いているものは Homeport のデータではありません。コンテナ、イメージ、ボリューム、Kubernetes や Nomad のオブジェクトはその場所に残り、Homeport のバックアップには含まれません。ボリュームの中身をコピーするには、「ボリューム」ページから[ファイルにバックアップ](/docs/guides/volumes-networks/#backing-up-and-restoring)してください。

## 何がどこにあるか

### データフォルダー

| システム | フォルダー                                        |
| -------- | ------------------------------------------------- |
| Linux    | `~/.local/share/com.homeport.app/`                |
| macOS    | `~/Library/Application Support/com.homeport.app/` |
| Windows  | `%APPDATA%\com.homeport.app\`                     |

Linux では、`$XDG_DATA_HOME` が設定されている場合、フォルダーはその下になります。Homeport がデータベースを開けない場合、ウィンドウにはファイルのフルパスが **フォルダーを開く** とともに表示されます。

| フォルダー内のもの                   | 内容                                                                                                                                                                                           |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `homeport.db`                        | データベースです。すべてのホスト、クラスター、スタック、レジストリのログイン情報、リポジトリ、設定、デプロイ履歴、エンジンのイベントが入っています。その中のシークレットは暗号化されています。 |
| `homeport.db-wal`、`homeport.db-shm` | SQLite の先行書き込みログとそのインデックスで、Homeport の実行中に存在します。最新の変更は、Homeport を終了するまで `-wal` ファイルにしかないことがあります。                                  |
| `homeport.db.before-restore-<date>`  | [復元](#restoring-a-backup)の直前に毎回作られるデータベースのコピーです。不要になったものは削除してください。                                                                                  |
| `repositories/` と `synced-stacks/`  | [同期スタック](/docs/guides/synced-stacks/)のリポジトリのクローンと作業コピーです。Homeport はリポジトリそのものから、これらを再び作成します。                                                 |

データベースに何が含まれ、どの部分が暗号化されているかは、[Homeport が保存するもの](/docs/reference/security/#what-homeport-stores)に一覧があります。

### キーチェーンの項目

シークレットを暗号化する鍵は、このフォルダーにはありません。オペレーティングシステムのキーチェーンにある 1 つの項目で、サービスは `com.homeport.app`、アカウントは `secrets-key` です。macOS では **キーチェーンアクセス**、Windows では **資格情報マネージャー → Windows 資格情報**、Linux では **パスワードと鍵**（Seahorse）か KWallet にあります。この項目は、このコンピューター上のユーザーアカウントに属します。

データベースとこの項目は一組です。鍵のないデータベースも開くことはでき、名前、アドレス、compose ファイルはすべて残りますが、シークレットはどれも復号できません。ホストとクラスターには **認証情報が失われました** と表示されます。フォルダーをコピーするだけでは別のコンピューターに移せないのも、[アプリ内のバックアップ](#backing-up-in-homeport)をおすすめするのも、このためです。

### ログとウィンドウの位置

| システム | ログ                                    | ウィンドウのサイズと位置                                            |
| -------- | --------------------------------------- | ------------------------------------------------------------------- |
| Linux    | `~/.local/share/com.homeport.app/logs/` | `~/.config/com.homeport.app/.window-state.json`                     |
| macOS    | `~/Library/Logs/com.homeport.app/`      | `~/Library/Application Support/com.homeport.app/.window-state.json` |
| Windows  | `%LOCALAPPDATA%\com.homeport.app\logs\` | `%APPDATA%\com.homeport.app\.window-state.json`                     |

どちらもバックアップする必要はありません。**設定 → Homeport について → ログフォルダーを開く** でログを開けます。

### ユーザー自身が管理するもの

- **リンクスタックのフォルダー。** Homeport が保持しているのは、[リンクスタック](/docs/guides/stacks/#linked-stacks)のフォルダーと compose ファイルの場所だけです。フォルダー、その compose ファイル、その `.env` はユーザーのものです。ほかのプロジェクトと同じように、通常は git でバックアップしてください。
- **kubeconfig、`~/.ssh`、`~/.docker`。** Homeport はそこからインポートするときにこれらを読みますが、変更することはありません。
- **helm のチャートリポジトリとログイン情報。** これらは helm 自身のもので、ターミナルと共有されています。

## Homeport でバックアップする

**設定 → データ → バックアップ…** は、すべてを 1 つの `.homeport` ファイルに書き出します。シークレットそのものを、このコンピューターのキーチェーンではなくパスフレーズで保護して持ち運ぶため、おすすめのバックアップ方法です。どのコンピューターでも復元できます。

1. **設定** を開き、**データ** の下で **バックアップ…** を選びます。
2. 12 文字以上のパスフレーズを 2 回入力します。Homeport はこれを保存せず、パスフレーズなしではファイルを開けません。
3. ファイルを保存する場所を選びます。

その後、Homeport は保存した内容を示し、このコンピューターで復号できなかったためにシークレットなしで保存したものがあれば、その名前を挙げます。

| バックアップに含まれるもの                                               | バックアップに含まれないもの                                       |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| ホストと、そのキー、パスフレーズ、証明書、踏み台、信頼したサーバーのキー | エンジンのイベント                                                 |
| クラスターと、その証明書、トークン、exec プラグインの設定                | デプロイ履歴                                                       |
| 管理スタックの compose ファイルと環境変数                                | リンクスタックのフォルダーとファイル                               |
| リンクスタックのフォルダーとファイルのパス                               | 同期スタックのクローン（次の同期で再び作成されます）               |
| 同期スタックのリポジトリ、ブランチまたはタグ、同期の設定、環境変数       | ログ、ウィンドウのサイズと位置                                     |
| Swarm にデプロイしたスタック                                             | ホストとクラスター上のすべてのもの: コンテナ、イメージ、ボリューム |
| レジストリのログイン情報と、そのパスワードとトークン                     | helm のチャートリポジトリ                                          |
| リポジトリと、そのデプロイキーとトークン                                 | Homeport の終了とともに終わるポートフォワード                      |
| 設定                                                                     |                                                                    |

ファイル全体がパスフレーズで暗号化されているため、パスフレーズがなければ、ホストの名前さえ何もわかりません。このファイルには Homeport が持つすべてのシークレットが含まれます。ファイルとそのパスフレーズは、キーそのものと同じくらい安全に保管してください。暗号化については[バックアップ](/docs/reference/security/#backups)で説明しています。

プレリリースを試す前、システムを再インストールする前、そして設定し直したくないホストを追加したときには、バックアップしてください。

### バックアップを復元する

1. このコンピューターか別のコンピューターで **設定** を開き、**データ** の下で **復元…** を選びます。
2. `.homeport` ファイルを選び、そのパスフレーズを入力します。Homeport は何かを変更する前に、ファイルの内容と、どの Homeport がいつ作成したかを一覧表示します。
3. **すべて置き換え** を選びます。

復元では、Homeport のすべてのデータがバックアップの内容に置き換わります。統合はされません。Homeport はまず現在のデータベースをデータフォルダー内の `homeport.db.before-restore-<date>` にコピーし、それからすべてを 1 回の操作で置き換えるため、失敗した場合もデータは元のまま残ります。すべてのシークレットは、このコンピューターのキーチェーンの鍵で暗号化し直されます。

復元の後は:

- ホストとクラスターは、キー、パスワード、信頼するサーバーのキーを求めることなく、すぐに再接続します。
- フォルダーがこのコンピューターの同じパスにないリンクスタックは、フォルダーができるまで外部スタックとして表示されます。
- 同期スタックは、次の同期でリポジトリを再びクローンします。
- 「イベント」ページとデプロイ履歴は空の状態から始まります。

古い Homeport で作成したバックアップは、新しい Homeport で復元できます。新しい Homeport で作成したものは拒否されます。先に Homeport をアップデートしてください。

復元前の状態に戻すには、Homeport を終了し、`homeport.db` の名前を別のものに変え、戻したい `homeport.db.before-restore-<date>` の名前を `homeport.db` に変えて、その隣に残っている `homeport.db-wal` と `homeport.db-shm` を削除してから、Homeport を再び開きます。

### 一部のホストだけを移す

「ホスト」ページの **エクスポート** と **インポート** は、選んだホストをシークレットとともに同じ種類のファイルで移し、もう一方のコンピューターにすでにあるホストに追加します。[別のコンピューターへの移行](/docs/reference/security/#moving-to-another-computer)を参照してください。

## ファイルを自分でコピーする

データベースのコピーは、Time Machine、ファイル履歴、独自のスクリプトなど、このコンピューターのシステムバックアップに向いています。アプリ内のバックアップに含まれないエンジンのイベントとデプロイ履歴も残りますが、**キーチェーンの鍵は含まれません**。シークレットごと復元できるのは、同じコンピューターの同じユーザーか、キーチェーンも一緒に復元したコンピューターだけです。それ以外の場所では、名前、アドレス、compose ファイルはすべて戻りますが、シークレットは[入力し直す](#if-the-secrets-are-lost)必要があります。

### Homeport を閉じているとき

Homeport を終了し（[トレイに閉じる](/docs/guides/settings/#desktop)設定の場合はトレイの **終了** から）、データフォルダー全体をコピーします。Homeport が終了すると、`homeport.db` にすべてが入り、`-wal` と `-shm` のファイルはなくなります。

### Homeport の実行中

Homeport の実行中に `homeport.db` だけをコピーしないでください。最新の変更がまだ `homeport.db-wal` にあるかもしれず、書き込みの途中で取ったコピーは整合性が取れていないことがあります。代わりに、`sqlite3` コマンドラインツールで SQLite に整合性のあるコピーを作らせてください（macOS には付属しています。Linux と Windows では、ディストリビューションの `sqlite3` パッケージか [sqlite.org](https://sqlite.org/download.html) からインストールします）:

```sh
# Linux
sqlite3 ~/.local/share/com.homeport.app/homeport.db ".backup '$HOME/homeport-backup.db'"

# macOS
sqlite3 "$HOME/Library/Application Support/com.homeport.app/homeport.db" ".backup '$HOME/homeport-backup.db'"
```

```powershell
# Windows
sqlite3 "$env:APPDATA\com.homeport.app\homeport.db" ".backup '$HOME\homeport-backup.db'"
```

結果は 1 つの完全なファイルで、隣に `-wal` はありません。確認するには:

```sh
sqlite3 ~/homeport-backup.db "PRAGMA integrity_check;"
```

`ok` と表示されます。

### コピーを復元する

1. Homeport を終了します。
2. データフォルダーで `homeport.db` を別の場所に移し、`homeport.db-wal` と `homeport.db-shm` があれば削除します。これらは置き換えるデータベースのものです。
3. コピーを `homeport.db` という名前でそこに置きます。フォルダー全体をコピーした場合は、代わりにフォルダーを元に戻します。
4. Homeport を開きます。

古いバージョンで作成したコピーは、開くときに Homeport がアップグレードします。新しい Homeport で最後に使用されたコピーは、そのまま手を付けずに拒否され、[インストールすべきバージョンを示すメッセージ](/docs/reference/troubleshooting/#this-database-was-last-used-by-homeport--or-later)が表示されます。

## シークレットが失われた場合

キーチェーンのリセット、新しいユーザーアカウント、別のコンピューターで開いたデータベースのコピーの後、Homeport はまだ読めるものをすべて保持し、読めないものに印を付けます。何も削除されず、シークレットでないもの（名前、アドレス、compose ファイル、フォルダーのパス）はそのまま残ります。次のものを入力し直してください:

| 対象                                      | 方法                                                                                                                                                            |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **TLS のホスト**                          | ホストのページで、CA 証明書、クライアント証明書、クライアントキーを再び読み込み、**保存** を選びます。                                                          |
| **インポートしたキーを使う SSH のホスト** | 秘密鍵とそのパスフレーズを再び貼り付け、**保存** を選びます。                                                                                                   |
| **Homeport のキーを使う SSH のホスト**    | **キーを再生成** を選び、サーバーで[新しいキーを許可](/docs/hosts/ssh/#authorise-homeports-key)します。サーバーにある古い `homeport@` の行は削除します。        |
| **HTTPS で接続する Incus のホスト**       | ホストを削除し、[新しい信頼トークンで追加し直します](/docs/hosts/incus/#over-https-with-a-trust-token)。                                                        |
| **Kubernetes のクラスター**               | クラスターのページで **kubeconfig から更新** を使います。                                                                                                       |
| **Nomad のクラスター**                    | クラスターの **設定** に、ACL トークンと、使っている場合は証明書を貼り付けます。                                                                                |
| **スタックの環境変数**                    | 管理スタックや同期スタックの環境変数を、そのページで入力し直します。リンクスタックの環境変数はフォルダーの `.env` にあり、Homeport が保持したことはありません。 |
| **レジストリのログイン情報**              | **設定 → レジストリ** で各ログイン情報を編集し、パスワードかトークンを入力します。                                                                              |
| **リポジトリ**                            | **設定 → リポジトリ** で **新しいキー** を作成してフォージのリポジトリに追加するか、**トークンを置き換え** を選びます。                                         |

ローカルソケット、TCP、ssh-agent のホストはシークレットを持たないため、そのまま動作し続けます。デプロイ履歴に記録された環境変数は入力し直せませんが、履歴の compose ファイルは読めるままです。

トラブルシューティングの[認証情報が失われました](/docs/reference/troubleshooting/#credentials-lost)も参照してください。

## データの削除

削除するフォルダーとキーチェーンの項目、サーバーから削除するキーは、[データの削除](/docs/reference/updating/#removing-your-data)に一覧があります。
