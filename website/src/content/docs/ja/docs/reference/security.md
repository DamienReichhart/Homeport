Homeport は、サーバーにアクセスするための認証情報を保持します。このページでは、Homeport が何をどのように保持するかを正確に説明します。

## Homeport が保存するもの

すべては、ユーザーのアプリケーションデータフォルダーにある 1 つの SQLite データベース `homeport.db` に保存されます:

| システム | フォルダー                                        |
| -------- | ------------------------------------------------- |
| Linux    | `~/.local/share/com.homeport.app/`                |
| macOS    | `~/Library/Application Support/com.homeport.app/` |
| Windows  | `%APPDATA%\com.homeport.app\`                     |

内容は次のとおりです:

| データ                                                  | 保存方法   |
| ------------------------------------------------------- | ---------- |
| ホスト名、アドレス、SSH のユーザー、ソケットのパス      | 平文       |
| SSH の公開鍵と、信頼したサーバーのキー                  | 平文       |
| SSH の秘密鍵とそのパスフレーズ                          | **暗号化** |
| TLS の CA 証明書、クライアント証明書とキー              | **暗号化** |
| Incus のホストのクライアントキーと固定された証明書      | **暗号化** |
| 管理スタックの compose ファイル                         | 平文       |
| 管理スタックの環境変数                                  | **暗号化** |
| リンクスタックのフォルダーと compose ファイルのパス     | 平文       |
| デプロイ履歴: compose ファイルとプロファイル            | 平文       |
| デプロイ履歴: 環境変数                                  | **暗号化** |
| レジストリのアドレスとユーザー名                        | 平文       |
| レジストリのパスワードとアクセストークン                | **暗号化** |
| リポジトリの URL、デプロイキーの公開鍵部分              | 平文       |
| 信頼したリポジトリのサーバーのキー                      | 平文       |
| リポジトリのデプロイキーとアクセストークン              | **暗号化** |
| クラスター名、API サーバーの URL、Namespace             | 平文       |
| 各クラスターのサインイン方法、kubeconfig のコンテキスト | 平文       |
| クラスターの CA、クライアント証明書とキー               | **暗号化** |
| クラスターのトークン、パスワード、OIDC トークン         | **暗号化** |
| Exec プラグインのコマンド、引数、環境変数               | **暗号化** |
| テーマ、最後の選択、クラスターごとの Namespace          | 平文       |
| 「イベント」ページ用の、各ホストのエンジンのイベント    | 平文       |

Homeport はエンジンからそれ以外のものをコピーしません。コンテナ、イメージ、ボリューム、ログはその場で読み込まれ、保存されることはありません。例外は、ユーザー自身がログやファイルをダウンロードしたり、ボリュームをバックアップしたりする場合だけです。保持するエンジンのイベント（どのコンテナ、イメージ、ボリューム、ネットワークに何が起きたか、とそのラベル）は、既定で 30 日間（[設定 → データ](/docs/guides/settings/#データ)）、ホストごとに最大 10,000 件まで保持され、ホストの削除時か **履歴を消去** で削除されます。

### リンクスタックのフォルダー

[リンクスタック](/docs/guides/stacks/#リンクスタック)について、Homeport が保存するのはフォルダーと compose ファイルの場所と、ファイルの変更を検知するためのフィンガープリントだけで、ファイルのコピーは決して保存しません。compose ファイルを読み込むのはスタックを開いたときで、書き込むのは **定義** タブで **保存** を選んだときだけです。編集した各ファイルは 1 回の操作で置き換えられ、権限は維持されます。開いた後に変更されたファイルは、指示しない限り上書きしません。Homeport はフォルダーの `.env` を読み書きすることはありません。これは Compose が実行時に読み込みます。リンクスタックを破棄しても、フォルダーには一切手を触れません。

### リポジトリ

[同期スタック](/docs/guides/synced-stacks/)のために、Homeport は各リポジトリの URL と、そのリポジトリのために生成したデプロイキー（秘密鍵部分は暗号化）か、ユーザー名とアクセストークン（暗号化）のどちらかを保持します。リポジトリの内容はシークレットではありません。そのクローンは `homeport.db` の隣の `repositories` フォルダーに置かれます。

### Swarm

Homeport は [Swarm](/docs/guides/swarm/) について何も保存しません。接続するたびに、マネージャーのホストを通じて Swarm を見つけます。Swarm のシークレットの値は Swarm に送られ、Homeport には保持されません。入力した値やファイルから読み込んだ値はエンジンに一度だけ送られ、`homeport.db`、ファイル、ログに書き込まれることはなく、ダイアログを閉じるとメモリから破棄されます。エンジンはシークレットの値を返さないため、Homeport が表示することもできません。参加トークンは必要なときにマネージャーから取得され、保存もログへの記録もされません。

### クラスター

[クラスター](/docs/clusters/)の認証情報は kubeconfig から取得され、SSH キーと同様に暗号化した状態でのみ保存されます。kubeconfig が参照するファイルは一度だけ読み込まれて埋め込まれ、貼り付けた kubeconfig がファイルに書き込まれることはなく、ご自身の kubeconfig が変更されることもありません。[exec プラグイン](/docs/clusters/exec-plugins/)はこのコンピューター上でユーザーとして実行され、それが出力するトークンや証明書は、有効期限が切れるまでメモリ上にだけ保持されます。Homeport はクラスター上で動いているものについて、それ以外に何も保存しません。Pod、ワークロードなどはその場で読み込まれます。[ポートフォワード](/docs/clusters/port-forward/)はこのコンピューターのループバック（`127.0.0.1` と `::1`）でのみ待ち受けるため、ネットワーク上のほかのものからは使えず、Homeport を終了すると終わります。[YAML の適用や編集](/docs/clusters/yaml/)による変更は、クラスター上でフィールドマネージャー `homeport` のもとに記録されます。

[Helm](/docs/clusters/helm/) は、kubeconfig を使わず、クラスターの認証情報をディスクに書き込むこともなく、`helm` CLI をクラスターに対して実行します。コマンドごとに、Homeport はこのコンピューターのループバック（`127.0.0.1`、ランダムなポート）上に、ランダムなトークンを持つリクエストだけを受け付けるプライベートな接続を開き、そのトークンだけを含み、ユーザーだけが読める一時的な kubeconfig を helm に渡します。Homeport は各リクエストの途中でクラスター自身の認証情報を追加し、コマンドが終わると kubeconfig を削除して接続を閉じます。チャートの値はファイルではなく標準入力で helm に渡されます。helm 自身のチャートリポジトリ、レジストリのログイン情報、キャッシュは、ターミナルで使うときと同じく helm のものです。Homeport が追加するのは公開リポジトリだけで、リポジトリのパスワードは保存しません。

[Nomad クラスター](/docs/clusters/nomad/)の ACL トークン、CA 証明書、クライアント証明書とキーは、SSH キーと同様に暗号化した状態でのみ保存されます。アドレス、リージョン、TLS のサーバー名は平文で保持されます。トークンは、シェルの WebSocket を含め、各リクエストの `X-Nomad-Token` ヘッダーで送られ、URL に含まれることはありません。Homeport はジョブの仕様のコピーを保持しません。Nomad がジョブとともに保存します。

**Kubernetes の Secret の値** は、1 つのキーについて **表示** を選んだときにだけ、1 つずつ取得されます。一覧、Secret のページ、その YAML に含まれるのはキーとサイズだけで、値は含まれません。表示した値はそのページのメモリ上にだけ残り（キャッシュにも、`homeport.db` にも、ログにも残りません）、ページを離れると再び隠されます。

## シークレットの暗号化の方法

- 各シークレットは、認証付き暗号である **XChaCha20-Poly1305** で個別に封印されるため、読み取りを防ぐだけでなく、改ざんも検出されます。
- 256 ビットの鍵はランダムで、初回起動時に作成され、**OS のキーチェーン**（macOS のキーチェーン、Windows の資格情報マネージャー、Linux の Secret Service）に、サービス名 `com.homeport.app` で保管されます。データと同じ場所に保存されることはありません。
- マスターパスワードはありません。キーチェーンがすでに鍵をユーザーアカウントに結び付けているためです。

`homeport.db` のコピーだけを持っている人は、ホストとクラスターの名前やアドレスは読めますが、キー、証明書、トークン、スタックの環境変数、レジストリのパスワードは読めません。

### キーチェーンがない場合

Homeport はバナーを表示し、シークレットを保存しません。ローカルソケット、TCP、ssh-agent のホストは引き続き動作します。[要件](/docs/requirements/#任意-os-のキーチェーン)を参照してください。

### キーチェーンの鍵が失われた場合

キーチェーンをリセットしたり、`homeport.db` を別のコンピューターや別のユーザーに移したりすると、復号できないシークレットが残ります。Homeport は何も削除しません。影響を受けたホストには、認証情報を入力し直すまで **認証情報が失われました** と表示されます。[トラブルシューティング](/docs/reference/troubleshooting/#認証情報が失われました)を参照してください。データを移すには、代わりにバックアップするか、ホストをエクスポートしてください。

### 別のコンピューターへの移行

「ホスト」ページの **エクスポート** は、選んだホストを、そのキー、証明書、信頼したサーバーのキーとともに、選んだパスフレーズで暗号化した 1 つのファイルに書き出します:

- ファイル全体が暗号化される（XChaCha20-Poly1305。鍵は Argon2id でパスフレーズから導出）ため、パスフレーズがなければホスト名やアドレスすら明かしません。ファイルを少しでも変更すると読めなくなります。
- パスフレーズは 12 文字以上必要です。Homeport はパスフレーズを保存もログへの記録もしません。忘れるとファイルは開けません。
- もう一方のコンピューターで **インポート** を使うとパスフレーズを求められ、その後、各ホストのシークレットは、ほかのものと同様にそのコンピューター自身のキーチェーンの鍵で暗号化して保存されます。
- このコンピューターですでに認証情報が失われているホストは、認証情報なしでエクスポートされ、エクスポートにはどのホストかが示されます。

このファイルは、含まれているキーと同じように扱ってください。インポートしたら削除しましょう。形式は [ADR 0013](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0013-passphrase-protected-export-bundles.md) で説明しています。

### バックアップ

**設定 → データ → バックアップ…** は、上記のすべて（ホスト、クラスター、スタック、レジストリのログイン情報、リポジトリ、設定）を、復号したシークレットとともに、同じ暗号化形式の 1 つのファイルに書き出します。パスフレーズは 2 回入力します。エンジンのイベントとデプロイ履歴は含まれません。このコンピューターで復号できないシークレットは除外され、バックアップにはどれが除外されたかが示されます。

**復元…** はパスフレーズを求め、何かを変更する前にファイルの内容を一覧表示します。その後、復元では次のことを行います:

1. 現在のデータベースを、`homeport.db` の隣に `homeport.db.before-restore-<date and time>` としてコピーします。
2. すべてのホスト、クラスター、スタック、ログイン情報、リポジトリ、設定を 1 回の操作で置き換えます。失敗した場合、データは元のまま残ります。
3. すべてのシークレットを、このコンピューターのキーチェーンの鍵で暗号化し直します。

新しいバージョンの Homeport で作成したバックアップは拒否されます。古いバージョンで作成したものは復元できます。バックアップには Homeport が持つすべてのシークレットが含まれます。バックアップとそのパスフレーズは、キーそのものと同じくらい安全に保管してください。

## キーが平文でディスクに触れることはない

Homeport は独自の SSH クライアントを備えているため、`ssh` に読ませるために秘密鍵をファイルに書き込むことはなく、`~/.ssh` を変更することもありません。復号したキーはメモリ上にとどまります。

`docker compose` が SSH や TLS のホストにスタックをデプロイするとき、Homeport はこのコンピューター上に短命のプライベートなソケット（ユーザーだけが読めるもの。Windows ではリモートのクライアントを拒否する名前付きパイプ）を開き、その 1 つのコマンドのために、自身の接続を通じてそれをフォワードします。

リポジトリのキーとトークンもディスクに触れることはありません。`git` のコマンドごとに、Homeport はそのリポジトリのデプロイキーだけを持つプライベートな SSH エージェントを（ユーザーだけが開けるソケット、または Windows ではリモートのクライアントを拒否する名前付きパイプで）提供するか、コマンドの環境変数を通じて HTTPS ヘッダーでトークンを渡します。ご自身の git の設定、認証情報ヘルパー、SSH キーは使われないため、キーチェーンや `~/.git-credentials` に何かがキャッシュされることはありません。

レジストリのログイン情報も `docker compose` には渡りません。Homeport は `docker compose up` を実行する前に、エンジン API を通じてスタックのイメージを自分でプルするため、コマンドの環境変数や渡されるファイルにパスワードやトークンは含まれません。

## サーバーの信頼

Homeport が初めて SSH サーバーに接続するとき、サーバーのキーのフィンガープリントの確認を求め、その後キーが変わった場合は、再び確認するまで接続を拒否します。TLS のホストは、サーバーの証明書を CA とサーバー名に照らして検証します。HTTPS 経由の Incus のホストは、追加したときの証明書だけを受け入れます。[SSH のホスト](/docs/hosts/ssh/#初回接続)を参照してください。

### Incus の証明書

[HTTPS 経由で Incus のホスト](/docs/hosts/incus/#信頼トークンを使った-https-経由)を追加すると、クライアント証明書とその秘密鍵（ECDSA P-384 キー）がメモリ上で作成され、ホストのほかのシークレットとともに暗号化して保存されます。ディスク上に平文で置かれることはありません。Incus 自身の証明書も同じように保存されて固定されます。Homeport はサーバーからその証明書だけを、SHA-256 フィンガープリントで比較して受け入れ、異なる証明書は両方のフィンガープリントを示して拒否します。信頼トークンは一度だけ使われ、保持されません。アクセスを取り消すには、サーバーで `incus config trust remove` を使って Homeport の証明書を削除します。

## Homeport の接続先

- **追加したホスト。** イメージをプル、プッシュ、ビルドするとき、レジストリに接続するのはエンジンであり、Homeport ではありません。Homeport は、そのレジストリの保存済みのログイン情報を、ホストの接続を通じてリクエストとともにエンジンに渡します。エンジンはそれを保持しません。
- **各ホストのエンジンを通じた、イメージのレジストリ。** [新しいイメージ](/docs/guides/containers/#新しいイメージ)が公開されているかを判断するためです。コンテナ、イメージ、スタックの各ページを読み込んだとき（各回答は 6 時間保持されます）と、**新しいイメージを確認** を選んだときに行われます。エンジンはタグが指すダイジェストをレジストリに問い合わせ（プライベートレジストリには保存済みのログイン情報を使います）、何もダウンロードしません。ローカルのホストの場合、エンジンはこのコンピューター上で動いているため、リクエストはこのコンピューターから送られます。
- **タグを閲覧するときの Docker Hub。** プルのダイアログで、Homeport はこのコンピューターから `hub.docker.com` に接続してリポジトリのタグを一覧表示します。Docker Hub のログイン情報が保存されていればそれを使います。リポジトリの検索は、代わりにホストのエンジンを通じて行われます。
- **ログイン情報を確認するときのレジストリ。** **設定 → レジストリ** で、Homeport はこのコンピューターからレジストリの `/v2/` エンドポイントとそのトークンサービスに問い合わせ、ユーザー名とパスワードまたはトークンを HTTPS で送ります（暗号化なしの HTTP を使うのは、`localhost:5000` のようなこのコンピューター上のレジストリの場合だけです）。
- **リポジトリのサーバー。** [同期スタック](/docs/guides/synced-stacks/)のために、アクセスのテスト、同期スタックの作成や同期のとき、そしてポーリングが有効なら Homeport が開いている間は一定の間隔で接続します。Homeport はこのコンピューターから、そのリポジトリのデプロイキーかトークンを使って `git` を実行します。
- **追加したクラスター。** kubeconfig が指定する Kubernetes API サーバー（プロキシがあればそれも）を通じて、kubeconfig が与える認証情報で接続し、サーバーの証明書を kubeconfig の CA と照合します。Exec プラグインは、`kubectl` の場合と同じく、このコンピューターからそれぞれのクラウド（AWS、Google Cloud、Azure）に接続します。
- **追加した Nomad クラスター。** 指定したエージェントのアドレスを通じてだけ接続します。ジョブのログとシェルはそのエージェントを経由し、エージェントがクライアントノードに転送するため、Homeport がノード自体に接続することはありません。エージェントの証明書は、指定した CA か、このコンピューターの CA と照合されます。
- **Incus のイメージサーバー。** [Incus のホスト](/docs/guides/instances/#インスタンスを作成する)のイメージの選択欄のために、Homeport はこのコンピューターからサーバーのイメージ一覧（`streams/v1/images.json`。ほかを選ばない限り `images.linuxcontainers.org` から）をダウンロードし、10 分間保持します。イメージ自体は Incus がダウンロードします。
- **helm を通じたチャートリポジトリと OCI レジストリ。** リポジトリの追加や更新、チャートの検索、チャートのインストールやアップグレードのときに、`helm` がターミナルの場合と同じくこのコンピューターからインデックスとチャートをダウンロードします。
- **アップデートを確認するためのこの Web サイト。** 起動時と 6 時間ごとに、Homeport は最新バージョンを記載した小さなファイル `updates/latest.json` をダウンロードします。このリクエストには、ユーザー、ホスト、コンテナについての情報は何も含まれませんが、ほかの Web リクエストと同様に、このサイトをホストしている GitHub Pages に IP アドレスから届きます。**設定 → アップデート** でオフにできます。アップデート自体は GitHub Releases からダウンロードされ、Homeport はそれが Homeport のアップデートキーで署名されている場合にだけインストールします。[アップデート](/docs/reference/updating/)を参照してください。

## Homeport がホスト上で実行するもの

Homeport はホストのエンジンと API を通じて通信し、その API でできないことのためにだけ、ホストのサーバー上でコマンドを実行します:

| タイミング                                                                            | 場所                                                                | コマンド                                                                                                                        |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| SSH のホストのサーバーがエンジンのソケットを開くのを拒否したとき                      | SSH サーバー                                                        | ソケットが存在して読み取れるか、エンジンがインストールされているかを調べる POSIX シェルのチェック                               |
| [Quadlet ユニット](/docs/guides/quadlet/)の **起動**、**停止**、**再起動**            | SSH サーバー、または Linux のローカルソケットではこのコンピューター | `systemctl [--user] start\|stop\|restart '<unit>.service'`                                                                      |
| [containerd のコンテナのログ](/docs/hosts/containerd/#ログ)                           | SSH サーバー、または Linux のローカルソケットではこのコンピューター | `tail -n <lines> [-F] -- '<log file>'`。CRI がファイル名を示さない場合は、その前に Kubernetes のコンテナのログフォルダーを `ls` |
| [containerd のコンテナ内のターミナル](/docs/hosts/containerd/#コンテナ内のターミナル) | SSH サーバー、または Linux のローカルソケットではこのコンピューター | `mktemp -d`、そのフォルダーに 2 つの FIFO を作る `mkfifo -m 600`、それらを通じた `cat`、その後フォルダーの `rm -rf`             |

これらは SSH のユーザーの権限（このコンピューターではユーザー自身の権限）で実行され、`sudo` は決して使いません。値はコマンドに入れる前に検証され、クォートされます。Quadlet ユニットのインストール、編集、削除は Podman の API を通じて行われ、ファイルは Podman 自身が書き込みます。Incus のホストでは何も実行されません。コンソールとターミナルは Incus 独自の API を通じて動作します。Homeport がホスト上に作るファイルは、containerd のターミナルの 2 つの FIFO だけで、これはターミナルを閉じると削除されるプライベートな一時フォルダーに置かれます。

## Homeport が決して行わないこと

- **アカウントは不要。** 登録するものは何もありません。
- **テレメトリ、分析、クラッシュレポートはなし。**
- **クラスターには何もインストールしない。** Homeport は Kubernetes API だけを、ユーザーの認証情報の権限の範囲で使い、指示がない限り何も変更しません。何かを削除したり置き換えたりする操作は、クラスター名を示して事前に確認します。
- **ホストには何もインストールしない。** Homeport がホスト上で実行するコマンドは[上記の一覧](#homeport-がホスト上で実行するもの)のものだけです。Homeport が自ら起動するコンテナは、ボリュームを開く、バックアップする、復元する、複製するときの短命の[ヘルパーコンテナ](/docs/guides/volumes-networks/#ヘルパーコンテナ)だけです。ネットワークを持たず、終わると削除されます。そのイメージは、同意した後にだけプルされます。
- **勝手にインストールしない。** アップデートは **インストールして再起動** を選んだときにだけインストールされます。Linux のパッケージは、パッケージマネージャーによってのみアップデートされます。

これが法的に何を意味するか（データの責任者は誰か、どのような根拠に基づくか、権利をどう行使するか）は、[プライバシーポリシー](/privacy/)で説明しています。

## ログ

Homeport は、問題の診断のために小さなログファイル（数十キロバイト程度で、いっぱいになると置き換えられます）を書き込みます。含まれるのは接続のイベントとエラーで、認証情報やコンテナの出力は含まれません。

| システム | フォルダー                              |
| -------- | --------------------------------------- |
| Linux    | `~/.local/share/com.homeport.app/logs/` |
| macOS    | `~/Library/Logs/com.homeport.app/`      |
| Windows  | `%LOCALAPPDATA%\com.homeport.app\logs\` |

## ダウンロードの信頼

リリースは、公開されているソースコードから GitHub Actions によってビルドされます。各ファイルには、SHA-256 チェックサムと、それをビルドした正確なコミットとワークフローに結び付ける署名付きのビルド来歴証明が付いています。[ダウンロードの検証](/docs/reference/verifying/)を参照してください。
