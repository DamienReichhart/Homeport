## アップデート

Homeport のアップデート方法は、インストールした方法によって異なります。

### Windows、macOS、AppImage

Homeport は起動時と 6 時間ごとに新しいバージョンを確認します。新しいバージョンが出ると、ウィンドウ上部のバーで知らせます。**新機能** を選ぶと[変更履歴](/changelog/)を読めます。**インストールして再起動** を選ぶと、Homeport はアップデートをダウンロードし、署名を確認してインストールし、再び開きます。選ぶまでは何もインストールされず、[データは保持されます](#your-data-across-versions)。

**設定 → アップデート → 今すぐ確認** から、すぐに確認することもできます。

### Linux のパッケージ

`.deb` と `.rpm` のパッケージは、[クイックインストール](/docs/installation/#クイックインストール)、[手動セットアップ](/docs/installation/#手動セットアップ)、ダウンロードしたファイルのどれでインストールした場合も、Homeport のパッケージリポジトリから、システムのほかの部分と一緒にアップデートされます。普段のソフトウェアのアップデートに Homeport も含まれます。Homeport だけをアップデートするには:

Homeport は新しいバージョンが出たことを知らせ、お使いのシステム向けのコマンドを表示しますが、インストールはパッケージマネージャーに任せます。

Homeport のリポジトリを削除した場合、パッケージマネージャーは新しいバージョンを認識できません。[クイックインストール](/docs/installation/#クイックインストール)でもう一度設定するか、新しいパッケージをダウンロードして、古いものに上書きしてインストールしてください。

### アップデートの確認をオフにする

**設定 → アップデート → アップデートを自動で確認** をオフにします。**今すぐ確認** は引き続き使えます。確認では、この Web サイトから小さなファイルを 1 つダウンロードするだけで、ユーザーやホストについての情報は何も送りません。[セキュリティとデータ](/docs/reference/security/#homeport-の接続先)を参照してください。

### 0.2.0 以前からのアップデート

0.3.0 より前のバージョンは自身をアップデートせず、その Linux のパッケージはリポジトリを追加しません。Homeport をインストールしたときと同じ方法で、0.3.0 以降を一度インストールしてください。[ダウンロードページ](/download/)から、または Linux では[クイックインストール](/docs/installation/#クイックインストール)で行います。その後は、アップデートが自動で届きます。

それでも新しいバージョンについて知りたい場合は、GitHub でリポジトリをウォッチする（**Watch → Custom → Releases**）か、[リリースのフィード](https://github.com/DamienReichhart/Homeport/releases.atom)をフォローしてください。

## バージョンをまたぐデータ

Homeport のどのバージョンも、0.1.0 までさかのぼるすべての以前のバージョンのデータを開き、何も失わずにアップグレードします。ホスト、スタック、クラスター、設定、シークレットのすべてです。アップデートで何かを設定し直す必要はありません。新しいバージョンは初めて起動したときにその場でデータベースをアップグレードし、すべてがこれまでどおり接続します。各リリースは、それ以前のすべてのリリースのサンプルデータベースに対してテストされています。

**ダウングレードはサポートされていません。** 新しいバージョンがデータを開いた後は、古いバージョンはそれを読めず、読もうともしません。何も変更せずに、[インストールすべきバージョンを示すメッセージ](/docs/reference/troubleshooting/#this-database-was-last-used-by-homeport--or-later)を表示して停止します。データは新しいバージョンが残した状態のままです。そのバージョンかそれより新しいバージョンをインストールすれば、Homeport は再びデータを開きます。

**プレリリースを試す前にバックアップしてください。** プレリリースもほかのバージョンと同じようにデータベースをアップグレードするため、元の安定版ではもう開けなくなります。先に **設定 → データ → バックアップ…** を選んでください。[データとバックアップ](/docs/reference/data-and-backups/#backing-up-in-homeport)を参照してください。安定版に戻すには、Homeport を終了し、`homeport.db` を[データフォルダー](/docs/reference/data-and-backups/#the-data-folder)の外に移し、安定版を再びインストールしてから、そのバックアップを **復元…** します。

## アンインストール

<Tabs syncKey="os">
<TabItem label="Windows">
**設定 → アプリ → インストールされているアプリ** を開き、**Homeport** を見つけて **アンインストール** を選びます。
</TabItem>
<TabItem label="macOS">Homeport を終了し、アプリケーションフォルダーからゴミ箱にドラッグします。</TabItem>
<TabItem label="Linux">

```sh
sudo apt purge homeport       # Debian, Ubuntu
sudo dnf remove homeport      # Fedora, RHEL
sudo zypper remove homeport   # openSUSE
```

これにより、Homeport のリポジトリも削除されます。Debian と Ubuntu では、`apt remove` はパッケージのほかの設定とともにリポジトリを残し、`apt purge` は鍵とともにリポジトリを削除します。Fedora と openSUSE では鍵が rpm のキーリングに残ります。`rpm -q gpg-pubkey --qf '%{NAME}-%{VERSION}-%{RELEASE} %{SUMMARY}\n'` で鍵を一覧表示でき、`sudo rpm -e gpg-pubkey-<version>-<release>` で Homeport の鍵を削除できます。

AppImage の場合は、ファイルを削除します。メニューの項目も一緒に消えます。

</TabItem>
</Tabs>

アンインストールしてもデータはそのまま残るため、再インストールするとすべてが元に戻ります。データの場所は[データとバックアップ](/docs/reference/data-and-backups/)で説明しています。

### ログイン項目

**ログイン時に起動** がオンになっている場合は、アンインストールする前に **設定 → デスクトップ** でオフにしてください。アンインストールしてもログイン項目は残り、存在しない Homeport を指したままになります。後から削除するには:

| システム | ログイン項目                                                                                                                                                                       |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows  | **タスク マネージャー → スタートアップ アプリ**: **Homeport** を無効にするか、`HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` の下の `Homeport` の値を削除します |
| macOS    | `~/Library/LaunchAgents/Homeport.plist` を削除します                                                                                                                               |
| Linux    | `~/.config/autostart/Homeport.desktop` を削除します                                                                                                                                |

## データの削除

<Aside type="caution">
  この操作は、ホストとクラスター、その保存されたキー、証明書、トークン、管理スタック、リンクスタック、同期スタックとその環境変数とデプロイ履歴、レジストリのログイン情報、リポジトリ、設定を削除します。リンクスタックのフォルダーはそのまま残ります。ホストとクラスター上のものには一切手を触れません。先にコピーを残すには、[バックアップ](/docs/reference/data-and-backups/)してください。
</Aside>

1. Homeport のデータフォルダーとログフォルダーを削除します:

   | システム | フォルダー                                                                            |
   | -------- | ------------------------------------------------------------------------------------- |
   | Linux    | `~/.local/share/com.homeport.app/`、`~/.config/com.homeport.app/`                     |
   | macOS    | `~/Library/Application Support/com.homeport.app/`、`~/Library/Logs/com.homeport.app/` |
   | Windows  | `%APPDATA%\com.homeport.app\`、`%LOCALAPPDATA%\com.homeport.app\`                     |

2. キーチェーンから暗号化の鍵（`com.homeport.app`、アカウント `secrets-key` の項目）を削除します:
   - **macOS** — **キーチェーンアクセス** で `com.homeport.app` を検索して削除します。
   - **Windows** — **資格情報マネージャー → Windows 資格情報** で、`com.homeport.app` を含む項目を削除します。
   - **Linux** — **パスワードと鍵**（Seahorse）か KWallet で、`com.homeport.app` の項目を削除します。

3. サーバー上で、`~/.ssh/authorized_keys` から Homeport の公開鍵を削除します。コメントが `homeport@` で始まるものです。git のフォージでは、Homeport がリポジトリ用に作成したデプロイキーを削除し、HTTPS で追加した Incus サーバーでは Homeport の証明書を削除します（`incus config trust list` の後に `incus config trust remove`）。
