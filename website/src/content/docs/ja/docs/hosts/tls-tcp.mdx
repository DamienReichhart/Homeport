Docker Engine は、ソケットに加えて TCP ポートで待ち受けることもできます。Homeport はそうしたエンジンに相互 TLS（Docker が `--tlsverify` と呼ぶ構成）で接続します。完全に信頼できるネットワークであれば、暗号化なしの TCP でも接続できます。

## TLS

相互 TLS では、Homeport がサーバーの証明書を CA と照合し、サーバーが Homeport のクライアント証明書を確認します。ネットワーク上にエンジンを公開する場合の安全な方法です。

### 必要なもの

Docker の TLS 設定で使う 3 つのファイル（PEM 形式）:

| フィールド             | 通常のファイル名 | 内容                                                                 |
| ---------------------- | ---------------- | -------------------------------------------------------------------- |
| **CA 証明書**          | `ca.pem`         | サーバーの証明書に署名した認証局。複数の証明書を含むこともあります。 |
| **クライアント証明書** | `cert.pem`       | Homeport の証明書。サーバーが信頼する CA によって署名されたもの。    |
| **クライアントキー**   | `key.pem`        | クライアント証明書の秘密鍵（暗号化されていないもの）。               |

作成方法は Docker のガイド [Protect the Docker daemon socket](https://docs.docker.com/engine/security/protect-access/) で説明されています。

### TLS のホストを追加する

1. ホストの切り替えメニューで **ホストを追加…** を選び、**TLS** を選択します。
2. **名前** と、`host:port` 形式の **アドレス**（例: `docker.example.com:2376`）を入力します。
3. それぞれの証明書とキーについて、PEM のテキストを貼り付けるか **ファイルから読み込む…** を選びます。
4. **ホストを追加** を選びます。

サーバーの証明書には、入力したホストの名前が含まれている必要があります。つまり、その DNS 名か IP アドレスが証明書のサブジェクト代替名に含まれていなければなりません。そうでない場合、接続は「_… へのセキュアな接続が失敗しました_」というエラーで失敗します。

証明書とキーは暗号化して保存されるため、[OS のキーチェーン](/docs/requirements/#任意-os-のキーチェーン)が必要です。ホストを編集するとき、フィールドを空のままにすると保存済みの内容が維持されます。

### Docker コンテキストから

`docker context ls` にすでにそのエンジンが表示されている場合、**ホストを追加** の **Docker コンテキストをインポート** を使えば、ファイルを選ばなくても、コンテキストのアドレスと `ca.pem`、`cert.pem`、`key.pem` でホストが作成されます。TLS の検証をスキップするコンテキストはインポートされません。[Docker コンテキスト](/docs/hosts/#docker-コンテキスト)を参照してください。

## TCP

**TCP** のホストは、暗号化も認証もなしで `tcp://host:port` に接続します。

<Aside type="danger" title="暗号化なし、認証なし">
  そのポートに到達できる人は誰でもエンジンを、そしてエンジンを通じてマシンを制御できます。暗号化なしの
  TCP は、ローカルの VM など、完全に信頼できるネットワークでだけ使ってください。それ以外では
  [SSH](/docs/hosts/ssh/) か TLS を使ってください。
</Aside>

1. **ホストを追加…** を選び、**TCP** を選択します。
2. **名前** と、`host:port` 形式の **アドレス**（例: `192.168.1.10:2375`）を入力します。IPv6 アドレスは角かっこで囲みます: `[fd00::10]:2375`。
3. **ホストを追加** を選びます。
