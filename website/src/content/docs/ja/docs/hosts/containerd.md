**containerd** は、k3s、nerdctl、BuildKit、そして Docker のない多くのサーバーの下で動いています。Homeport は、[ADR 0020](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0020-containerd-over-grpc.md) で決めたとおり、containerd 独自の gRPC API を通じて直接接続します。containerd のホストには、サイドバーに専用のページ（**コンテナ**、**イメージ**、**スナップショット**、**名前空間**）があります。Docker 用のページ、スタック、ボードは表示されません。

## containerd のホストを追加する

フォームの **エンジン** フィールドで **containerd** を選びます。containerd にはソケット経由でしか到達できないため、接続は **ローカルソケット** か **SSH** です。containerd はネットワーク越しに API を提供しないため、TCP と TLS はグレーアウトされます。

| containerd                      | ソケット                                                                |
| ------------------------------- | ----------------------------------------------------------------------- |
| containerd 自体のサービス       | `/run/containerd/containerd.sock`                                       |
| k3s                             | `/run/k3s/containerd/containerd.sock`                                   |
| Docker Engine 自身の containerd | `/run/containerd/containerd.sock`。コンテナは `moby` 名前空間にあります |

Linux では、このコンピューターの containerd と k3s の containerd が応答すると、**このマシンで見つかったもの** に一覧表示されます。まだ使えないソケットは、その解決方法とともに表示されます。

### ユーザーがソケットを使えるようにする

containerd のソケットは root が所有しています。ローカルでも SSH 経由でも、別のユーザーとして使うには、`/etc/containerd/config.toml` でグループにアクセス権を与え、そのグループにユーザーを追加します:

```bash
sudo groupadd -f containerd
sudo usermod -aG containerd "$USER"
getent group containerd | cut -d: -f3
```

表示された番号を `/etc/containerd/config.toml` の `[grpc]` の下に書き、containerd を再起動して、ログインし直します:

```toml
[grpc]
  gid = 1001
```

```bash
sudo systemctl restart containerd
```

**rootless の containerd**（`containerd-rootless.sh`）はソケットを RootlessKit の名前空間の中に置くため、その外からは Homeport を含め何も到達できません。Homeport はそれを見つけるとそのことを表示します。代わりに containerd のシステムサービスを使ってください。

### バージョンと接続ごとにできること

Homeport は containerd **1.7** 以降に接続します。プルは containerd の Transfer サービスを使い、これは **2.0** から安定版です。

| 操作                                                   | containerd | 接続                                 |
| ------------------------------------------------------ | ---------- | ------------------------------------ |
| 名前空間、コンテナとタスク、イメージ、スナップショット | 1.7 以降   | ローカルソケットまたは SSH           |
| イメージのプル                                         | 2.0 以降   | ローカルソケットまたは SSH           |
| ログとターミナル                                       | 1.7 以降   | SSH、または Linux のローカルソケット |

接続できないほど古い containerd では、ホストはそのバージョンを示して **設定に誤りがあります** になります。プルできないほど古い場合は、プルするときにそう表示されます。

## 名前空間

containerd のすべてのオブジェクトは **名前空間** の中にあります。nerdctl は `default`、Kubernetes は `k8s.io`、Docker は `moby`、BuildKit は `buildkit` を使います。ページは名前空間を 1 つずつ表示し、ホストの切り替えメニューの下で選びます。そこには各名前空間が、含まれるコンテナとイメージの数とともに一覧表示されます。Homeport はホストごとの選択を次回の起動時にも記憶しています。選ぶまでは、ホストは `default` を表示します。`default` が空の場合は、何かを含む唯一の名前空間を表示するため、k3s のホストは `k8s.io` で開きます。

**名前空間** ページでは、空の名前空間を作成したり、空の名前空間を削除したりできます。containerd は何かが残っている名前空間の削除を拒否し、Homeport は何が残っているかを表示します。先にそのコンテナ、イメージ、スナップショットを削除してください。

## コンテナとタスク

containerd では、**コンテナ** はメタデータ（イメージ、spec、スナップショット）にすぎません。実際に動くのは、その **タスク** です。**コンテナ** ページには名前空間のコンテナがタスクとともに一覧表示されます。タスクの状態は **実行中**、**一時停止**、終了コード付きの **停止**、**タスクなし** のいずれかです。各コンテナにはそれを作ったツール（**Kubernetes**（その Pod とともに）、**nerdctl**、**Docker**、**ctr またはその他**）が表示され、Pod の pause コンテナは、表示を指定しない限り隠されます。

| 操作               | Homeport が行うこと                                                                                                                                                                                                                                                                                               |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **起動**           | コンテナのスナップショット上にタスクを作成し、nerdctl と同じ場所にログを出力するようにして起動します。停止したタスクは、`ctr task start` の場合と同様に置き換えられます。                                                                                                                                         |
| **停止**           | イメージの停止シグナル（別のものが指定されていなければ SIGTERM）を送り、10 秒後に SIGKILL を送ります。その後もタスクが生きていれば報告します。                                                                                                                                                                    |
| **一時停止**       | タスクを凍結します。**再開** で解凍します。                                                                                                                                                                                                                                                                       |
| **シグナルを送信** | 任意のシグナルを、名前（`SIGHUP`）か番号で、タスクのメインプロセスに送ります。                                                                                                                                                                                                                                    |
| **削除**           | 事前に確認します。動作中のタスクを強制終了し、タスクとコンテナ、そしてスナップショットを変更されたファイルごと削除します。ただし、**スナップショットも削除する** のチェックを外した場合は除きます。残したスナップショットには `containerd.io/gc.root` が付けられ、containerd のガベージコレクターに保持されます。 |

コンテナのページには、ランタイム、スナップショット、ラベル、OCI spec が表示されます。Homeport は containerd 上でコンテナを作成しません。containerd 自体にはネットワーク機能がなく、それは nerdctl と CNI が追加するものだからです。

Kubernetes のコンテナは **kubelet** が管理しています。停止しても再び起動し、削除しても再び作成します。それらのページにはそのことが表示されます。代わりに、クラスター上で Pod を変更してください。ここから nerdctl のコンテナを削除すると、`ctr` の場合と同様に、nerdctl 自身の記録（名前とネットワーク）は残ります。そうしたコンテナには `nerdctl rm` を使うほうがきれいに削除できます。

## ログ

containerd はログを保持しません。タスクの出力先は、タスクを起動したツールが決めます。**ログ** タブは、そのツールが書き込んだ場所から出力を読み込みます:

| 作成したもの             | 出力先                                                                                  | Homeport が表示するもの                                 |
| ------------------------ | --------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| nerdctl                  | nerdctl の状態フォルダーにある JSON のログファイル。`nerdctl/` ラベルで名前が決まります | そのファイルを追跡表示                                  |
| Kubernetes（`k8s.io`）   | `/var/log/pods/<pod>/<container>/N.log`。CRI の記録に名前があります                     | そのファイルを追跡表示                                  |
| `ctr` などのクライアント | 指定された場所。通常はどこにも出力されません                                            | **このコンテナの出力は記録されていません。** とその理由 |

別のドライバー（journald、fluentd）にログを出力する nerdctl のコンテナは、代わりにそのドライバー名が表示されます。Homeport はホストのマシン上で `tail` を使ってファイルを読み込みます（[下記](#what-runs-on-the-host)を参照）。ログファイルは通常 root が所有しているため、SSH のユーザーに読み取りを許可しておく必要があります。

## コンテナ内のターミナル

**Exec** タブは、動作中のコンテナでシェル（イメージにあれば bash、なければ sh）か、指定したコマンドを開きます。数値のユーザー（`uid` または `uid:gid`）と、任意のフォルダーを指定できます。**再び開く** は、入力した内容で新しいターミナルを開始します。

containerd は、プロセスの入出力を自身のマシン上のパスとして受け取ります。そこで Homeport はそのマシンで短いスクリプトを実行して、プライベートな一時フォルダーに 2 つの FIFO を作り、それらを通じてターミナルの入出力をコピーします。containerd は、コンテナ自身のプロセス spec をもとに、それらの FIFO 上でプロセスを起動します。タブを閉じると、プロセスは強制終了され、フォルダーは削除されます。

## イメージ

**イメージ** ページには、名前空間のイメージが、プラットフォーム、そこから作られたコンテナ、ホストのプラットフォームでのサイズ（`ctr images ls` と同じ数え方）とともに一覧表示されます。

**イメージをプル** は containerd 自身を通じてイメージを取得し、ホストのプラットフォーム向けに既定のスナップショッターへ展開するため、`nerdctl run` ですぐに使えます。完全な参照（`ghcr.io/home/app:1.2`）か短い参照（`nginx`。`docker.io/library/nginx:latest` になります）を指定します。プライベートレジストリのイメージは **設定 → レジストリ** のログイン情報を使ってプルされます。ログイン情報はレジストリが要求したときにだけ containerd に送られ、ホストに保存されることはありません。

名前空間のコンテナの作成元になっているイメージは削除できません。先にそのコンテナを削除してください。containerd は、何も参照しなくなったイメージのコンテンツを解放します。

## スナップショット

containerd のディスク容量を使っているのはスナップショットです。展開されたイメージのレイヤーと、各コンテナの書き込み可能なレイヤーです。**スナップショット** ページは、1 つのスナップショッター（まず `overlayfs`、なければホストが読み込んだほかのもの）のスナップショットを親ごとのツリーで大きい順に表示し、`ctr snapshot usage` と同じ数え方の使用量と、上部に合計を表示します。

各スナップショットには、それを使っているもの（スナップショットを通じてコンテナ、レイヤーを通じてイメージ）が表示されます。何にも使われておらず、その上に何も構築されていないスナップショット（ここでコンテナを削除したときに残したものなど）は、**未使用のみ** で絞り込んで表示し、削除できます。それ以外はここから削除できません。何からも参照されず、ルートとしてもマークされていないスナップショット（`ctr containers rm --keep-snapshot` が残すものなど）は長く残りません。containerd のガベージコレクターが次回の実行時に削除します。

## ホスト上で実行されるもの

上記はすべて containerd の API を通じて行われますが、ログとターミナルだけは containerd のマシン上のファイルが必要です。そのため Homeport は、すでに保持している SSH セッション上で（Linux のローカルソケットの場合はこのコンピューター上で）次のコマンドを、SSH のユーザーの権限で実行します。`sudo` は決して使いません:

| 用途       | コマンド                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------- |
| ログ       | `tail -n <lines> [-F] -- '<log file>'`。CRI の記録がない Kubernetes のコンテナでは、先にログフォルダーを `ls` |
| ターミナル | `mktemp -d`、そのフォルダーに 2 つの FIFO を作る `mkfifo -m 600`、それらを通じた `cat`、フォルダーの `rm -rf` |

macOS や Windows のローカルソケットではこれらを実行できないため、ログとターミナルには SSH が必要だと表示されます。Homeport がホスト上で実行するすべてのコマンドは、[セキュリティのページ](/docs/reference/security/#what-homeport-runs-on-your-hosts)に一覧があります。

## イベント

ページは、すべての名前空間における containerd 自身のイベント（タスクの起動や終了、コンテナやイメージの作成や削除、スナップショットのコミット）をもとに更新されます。containerd はイベントの履歴を保持しないため、Homeport を閉じている間に起きたことは補完されません。
