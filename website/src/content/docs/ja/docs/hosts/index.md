---
title: ホストと接続
description: Homeport が Docker Engine、containerd、Incus に接続する仕組み、ホストの各ステータスの意味、再接続の仕組み。
---

**ホスト**は、Homeport が接続する Docker Engine、containerd、Incus です。ホストには名前と到達方法があります。表示されるすべてのコンテナ、インスタンス、イメージ、ボリューム、ネットワーク、スタックは、ちょうど 1 つのホストに属します。

## 接続の種類

| タイプ               | エンジンへの到達先…                                           | 認証情報                                                    | ガイド                                                          |
| -------------------- | ------------------------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------- |
| **ローカルソケット** | このマシン上。ソケットまたはパイプ経由                        | なし                                                        | [ローカルのエンジン](/docs/hosts/local/)                        |
| **SSH**              | ログインできるサーバー上                                      | Homeport のキー、自分のキー、または ssh-agent               | [SSH](/docs/hosts/ssh/)                                         |
| **TLS**              | `dockerd --tlsverify` で公開されたもの、または Incus の HTTPS | CA 証明書、クライアント証明書とキー。Incus では信頼トークン | [TLS と TCP](/docs/hosts/tls-tcp/)、[Incus](/docs/hosts/incus/) |
| **TCP**              | 信頼できるネットワーク上で、暗号化なしで公開されたもの        | なし                                                        | [TLS と TCP](/docs/hosts/tls-tcp/)                              |

リモートのサーバーには **SSH** をおすすめします。SSH ポート以外に何も公開する必要がなく、安全に設定するのが最も簡単です。

## エンジンの種類

各ホストは、到達方法に加えて、どの種類のエンジンを指しているかをフォームの **エンジン** フィールドで示します。これによって、そのホストでサイドバーに表示されるページが決まります。

| エンジン        | 対象                                                                     | ページ                                                                                                    |
| --------------- | ------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------- |
| **Docker 互換** | Docker Engine、Docker Desktop、Colima、OrbStack、Rancher Desktop、Podman | コンテナ、イメージ、ボリューム、ネットワーク、スタック、イベント。Podman では Podman 独自のページも       |
| **containerd**  | containerd 自体のサービス、k3s のもの、Docker Engine 自身の containerd   | containerd のコンテナ、イメージ、スナップショット、名前空間。[containerd](/docs/hosts/containerd/) を参照 |
| **Incus**       | Incus 6.0 以降: システムコンテナと仮想マシン                             | インスタンス、イメージ、プロファイル、ストレージ、ネットワーク。[Incus](/docs/hosts/incus/) を参照        |

ソケットのパスが containerd や Incus のソケットを指している場合、フォームはそこからエンジンを選びます。containerd にはソケット経由（このコンピューター上か SSH 経由）でしか到達できないため、TCP と TLS はグレーアウトされます。Incus にはソケット経由か HTTPS（TLS）経由で到達するため、グレーアウトされるのは TCP だけです。Homeport 0.18 より前に追加されたホストは Docker 互換になり、それ以外は何も変わりません。

**Podman** は、Homeport が接続するたびに識別する Docker 互換のエンジンです。同じソケットでも製品が切り替わることがあるためです。識別されると、ホストのステータスにはエンジンのバージョンの代わりに **Podman** とそのバージョンが表示され、サイドバーには Podman にしかないページが追加されます。選択中のホストで表示できないページはサイドバーに表示されず、リンクから開くとその理由が表示されます。

Docker Swarm に属するホストには、その Swarm の **マネージャー** または **ワーカー** と表示されます。マネージャーを 1 つホストとして追加すれば、その Swarm がサイドバーに表示されます。ホストのページには **Swarm** カードもあり、Swarm の開始、参加、離脱ができます。[Swarm](/docs/guides/swarm/) を参照してください。

## ホストの追加、編集、削除

- ホストを **追加** するには、サイドバー上部のホストの切り替えメニューにある **ホストを追加…** か、「概要」の **ホストを追加** を使います。
- ホストの切り替えメニューの **ホストを管理** には、すべてのホストがタイプ、アドレス、ステータスとともに一覧表示されます。1 つ選ぶとそのページが開きます。
- ホストのページでは接続の詳細を変更して **保存** を選べます。Homeport は新しい設定で再接続します。ホストの接続タイプは変更できません。代わりにホストを削除して追加し直してください。
- **有効** スイッチは、ホストを忘れずに切断します。無効にしたホストは、再び有効にするまで再試行しません。
- **ホストを削除** は、ホスト、保存された認証情報、管理スタックの compose 定義、リンクスタック、スタックのデプロイ履歴を忘れます。ホスト上で動いているものには一切手を触れません。コンテナ、イメージ、ボリュームはそのまま残り、リンクスタックのフォルダーも残ります。ホストが管理している Swarm のスタックは Swarm に属するため、保持されます。

ホスト名は、大文字と小文字を区別せずに一意である必要があります。

## ホストのインポート

**ホストを追加** には、このコンピューターにすでに記述されている情報から、多数のホストを一度に追加する方法が 2 つあります。どちらもプレビューを開くので、インポートする項目を選び、名前を変更して、**インポート** を選びます。

- **~/.ssh/config からインポート** は、SSH の設定に書かれたサーバーを、ユーザー、ポート、キー、`ProxyJump` の踏み台とともに追加します。[~/.ssh/config からのインポート](/docs/hosts/ssh/#import-from-sshconfig)を参照してください。
- **Docker コンテキストをインポート** は、Docker CLI のコンテキスト（`docker context ls`）のエンジンを、TLS 証明書とともに追加します。

キーと証明書はインポート時に一度だけ読み込まれ、ほかのものと同様に暗号化して保存されます。`~/.ssh` も `~/.docker` も変更されることはありません。

### Docker コンテキスト

Homeport は `~/.docker/contexts`（`$DOCKER_CONFIG` が設定されている場合はその下）にあるすべてのコンテキストを読み込み、その Docker エンドポイントを次のように対応付けます:

| エンドポイント                                           | 変換先                                                      |
| -------------------------------------------------------- | ----------------------------------------------------------- |
| `unix:///…`、`npipe:////./pipe/…`                        | **ローカルソケット** のホスト                               |
| TLS ファイルなしの `tcp://host:port`                     | **TCP** のホスト                                            |
| `ca.pem`、`cert.pem`、`key.pem` 付きの `tcp://host:port` | 証明書付きの **TLS** のホスト                               |
| `ssh://user@host:port`                                   | ssh-agent と `/var/run/docker.sock` を使う **SSH** のホスト |

組み込みの `default` コンテキストは表示されません。このマシンのエンジンは[ローカルの検出](/docs/hosts/local/)ですでに見つかるためです。次の場合、コンテキストは表示されますが選択できません:

- `SkipTLSVerify` を設定している場合。Homeport は常にエンジンの証明書を確認するためです。
- TLS フォルダーに 3 つのファイルの一部しかない場合。
- エンドポイントが Kubernetes のものなど、ほかの種類の場合。
- 同じエンジンにすでに到達しているホストがある場合。どのホストかは名前に表示されます。

名前がすでにホスト名として使われているコンテキストは、`name (2)` として表示されます。

## 別のコンピューターへの移行

「ホスト」ページの **エクスポート** は、選んだホストをパスフレーズで保護されたファイルに保存します。もう一方のコンピューターの「ホスト」ページで **インポート** を使うとそのファイルが開き、選んだホストがすぐに接続できる状態で追加されます。移行先ですでに使われている名前のホストは `name (2)` として提案され、名前を変更するか、スキップできます。ファイルの保護方法については[別のコンピューターへの移行](/docs/reference/security/#moving-to-another-computer)を参照してください。

## ホストの選択

リソースの各ページ（コンテナ、イメージ、ボリューム、ネットワーク、スタック、イベント）には、**ホストの切り替えメニュー** で選んだホストの内容が表示されます。containerd のホストのページは、[切り替えメニューの下](/docs/hosts/containerd/#namespaces)で選んだ名前空間を 1 つずつ表示し、Incus のホストのページは 1 つの[プロジェクト](/docs/hosts/incus/#projects)を表示します。ホストはそこで切り替えるか、[概要](/docs/guides/overview/)でホストのカードを選んで切り替えます。Homeport は、選択した内容を次回の起動時にも記憶しています。

## ステータス

各ホストの名前の横にはステータスが表示されます。選択中のホストが接続されていない場合、リソースのページにはそのステータスとともに **今すぐ再試行** と **ホストの設定を開く** が表示されます。

| ステータス                           | 意味                                                                                                  | 次に起こること                                                               |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| **接続済み**                         | エンジンが応答しました。そのバージョン、または Podman、containerd、Incus のバージョンが表示されます。 | Homeport は接続を監視し続けます。                                            |
| **接続中**                           | Homeport がエンジンに接続しようとしています。                                                         | —                                                                            |
| **無効**                             | ホストの **有効** スイッチがオフです。                                                                | オンにするまで何も起こりません。                                             |
| **到達不能**                         | ネットワーク、ソケット、またはエンジンが応答しませんでした。                                          | 自動で再試行し、そのたびに待ち時間を延ばします。                             |
| **アクセスが拒否されました**         | SSH サーバーがキーを拒否したか、ssh-agent が失敗したか、TLS ハンドシェイクが失敗しました。            | 原因を解決してから **再接続** します。                                       |
| **サーバーキーが信頼されていません** | SSH の初回接続です。サーバーまたは踏み台のキーに承認が必要です。                                      | ホストのページで[キーを信頼](/docs/hosts/ssh/#trust-the-servers-key)します。 |
| **サーバーキーが変更されました**     | SSH サーバーが、信頼したものとは異なるキーを提示しました。                                            | [まず調査してください](/docs/hosts/ssh/#when-the-servers-key-changes)。      |
| **認証情報が失われました**           | 保存された認証情報を復号できません。                                                                  | [入力し直してください](/docs/reference/troubleshooting/#credentials-lost)。  |
| **キーチェーンを利用できません**     | ホストには保存されたシークレットが必要ですが、OS のキーチェーンがありません。                         | [要件](/docs/requirements/#optional-an-os-keychain)を参照してください。      |
| **設定に誤りがあります**             | ホストの設定に、不足しているものか無効なものがあります。                                              | メッセージに内容が表示されます。修正して **保存** します。                   |

## 再接続

Homeport は起動時に有効なすべてのホストに接続します。各ホストは個別に接続するため、1 台のサーバーが遅くてもほかのサーバーが待たされることはありません。

接続中、Homeport はエンジンのイベントストリームを受信し（ページが自動で更新されるのはこのためです）、15 秒ごとにエンジンを確認します。接続が切れると、ホストは **到達不能** になり、Homeport は 1 秒後、続いて 2 秒、4 秒、8 秒…と間隔を延ばしながら、最長で 1 分に 1 回まで再試行します。接続に成功すると待ち時間はリセットされます。

自動で再試行するのは **到達不能** だけです。それ以外の問題はすべてユーザーの対応が必要で、その後に（ホストのページの）**再接続** か **今すぐ再試行** を選ぶと、すぐに再試行します。

## イベントとリアルタイム更新

Homeport はポーリングを行いません。コンテナの起動やイメージのプルなど、エンジンが変更を報告すると、影響を受けるページが一瞬で更新されます。[イベント](/docs/guides/overview/#events)ページには、そのままのストリームが表示されます。
