**Incus** は、システムコンテナと仮想マシン、つまり[ガイド](/docs/guides/instances/)で扱う **インスタンス** を実行します。Homeport は、[ADR 0021](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0021-incus-over-its-rest-api.md) で決めたとおり、Incus 独自の REST API を通じて接続します。Incus のホストには、サイドバーに専用のページ（**インスタンス**、**イメージ**、**プロファイル**、**ストレージ**、**ネットワーク**）があります。Docker 用のページ、スタック、ボードは表示されません。

## Incus のホストを追加する

フォームの **エンジン** フィールドで **Incus** を選び、到達方法を選びます:

| 接続                 | 使う場面                                                    | 必要なもの                                                                       |
| -------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------- |
| **ローカルソケット** | Incus がこのコンピューター（Linux）で動作している           | ユーザーが `incus-admin` グループか `incus` グループに属していること（下記参照） |
| **SSH**              | Incus がログインできるサーバーで動作している                | SSH のユーザーが `incus-admin` グループか `incus` グループに属していること       |
| **TLS**（HTTPS）     | Incus がネットワークで待ち受けている、または SSH が使えない | 信頼トークン、または Incus がすでに信頼しているクライアント証明書                |

暗号化なしの **TCP** はグレーアウトされます。Incus は TLS なしでは API を提供しないためです。Homeport は **Incus 6.0**（長期サポートリリース）以降に接続します。

### ソケット

| ソケット                          | 使えるユーザー                   | 到達できる範囲                                               |
| --------------------------------- | -------------------------------- | ------------------------------------------------------------ |
| `/var/lib/incus/unix.socket`      | `incus-admin` グループ           | すべて: すべてのプロジェクト、ストレージプール、ネットワーク |
| `/var/lib/incus/unix.socket.user` | `incus` グループ（`incus-user`） | ユーザー自身のプロジェクトのみ（初回使用時に作成されます）   |

Linux では、応答があれば両方が **このマシンで見つかったもの** に一覧表示され、制限付きのものは **Incus (restricted to your project)** と表示されます。まだ使えないソケットは、それを解決するコマンドとともに表示されます:

```bash
sudo usermod -aG incus-admin "$USER"
```

グループの変更は新しいログインから反映されます。ホストを追加する前に、ログアウトしてログインし直してください（SSH の場合は再接続してください）。Incus が停止している場合は、それを起動するユニットが表示されます:

```bash
sudo systemctl enable --now incus.socket incus.service
```

### 信頼トークンを使った HTTPS 経由

`core.https_address` を設定すると、Incus はネットワークで待ち受けます。Incus サーバーで次を実行します:

```bash
incus config set core.https_address :8443
incus config trust add homeport
```

2 つ目のコマンドは **信頼トークン**（英数字からなる 1 行）を出力します。Homeport で **Incus** と **TLS** を選び、**信頼トークン** を選択したまま、それを貼り付けます。Homeport は読み取った内容（対象の名前、サーバーのアドレスと証明書のフィンガープリント、有効期限）を表示し、**追加** を選ぶと次のことを行います:

1. 独自のクライアント証明書を作成します。鍵はメモリ上で作成される ECDSA P-384 キーです。
2. トークンのアドレスを順に試し、トークンが示すフィンガープリントを持つ証明書のアドレスのうち最初のものを使います。それ以外は、両方のフィンガープリントを示して拒否されます。
3. 証明書とともにトークンを送信し、Incus がその証明書を信頼したことを確認します。

その後、ホストは `incus config trust list` にトークンの名前で表示されます。トークンは一度だけ使え、有効期限があります。使用済み、取り消し済み、期限切れのトークンは、新しいトークンを作るコマンドとともに拒否されます。後で Homeport のアクセスを取り消すには、そこで証明書を削除します:

```bash
incus config trust list
incus config trust remove <fingerprint>
```

**既存の証明書** は、Incus がすでに信頼しているクライアント証明書とキー（`incus config trust add-certificate`）と、信頼する Incus 自身の証明書（`/var/lib/incus/server.crt`、クラスターでは `cluster.crt`）を受け取ります。

### サーバーの証明書は固定される

Incus の証明書は自己署名のため、照合する CA がありません。Homeport は信頼した証明書をホストとともに保存し、以降はどのアドレスで到達した場合でも、SHA-256 フィンガープリントで比較して、その証明書だけを受け入れます。Incus を再インストールしたり証明書を更新したりすると、ホストは期待したフィンガープリントと受け取ったフィンガープリントを示して拒否されます。サーバーで `incus info` を使って新しいフィンガープリントを確認し、新しいトークンでホストを追加し直してください。クライアントキーと 2 つの証明書は、ほかのシークレットと同様に暗号化して保存されます。[セキュリティ](/docs/reference/security/#incus-certificates)を参照してください。

## プロジェクト

Incus は、インスタンス、イメージ、プロファイル、カスタムボリューム、ネットワークを **プロジェクト** の中に保持します。ページはプロジェクトを 1 つずつ表示し、ホストの切り替えメニューの下で選びます。そこには各プロジェクトが、含まれるインスタンスとイメージの数とともに一覧表示されます。Homeport はホストごとの選択を次回の起動時にも記憶しています。選ぶまでは、ホストは `default` を表示します。制限付きソケットの場合は、唯一のプロジェクトを表示します。ストレージプールはサーバー全体に属し、そのボリュームは選択したプロジェクトのものが表示されます。

## イベント

ページは、すべてのプロジェクトにおける Incus のライフサイクルイベント（インスタンスの起動や停止、スナップショットの作成、イメージの追加、プロファイルやネットワークの変更）をもとに更新されます。これらは **イベント** ページにも保存されます。Incus はイベントの履歴を保持しないため、Homeport を閉じている間に起きたことは補完されません。

接続中、Homeport は 15 秒ごとに Incus に `GET /1.0` を問い合わせます。Incus が停止するとホストは **到達不能** になり、再び応答するようになると Homeport は自動で再接続します。

## Homeport がホスト上で行うこと

Incus のホストでは、Incus 自体以外に何も実行されません。コンソールとターミナルは Incus 独自の WebSocket を通じて動作し、リモートのイメージは Incus がダウンロードします。Homeport は、イメージの選択欄のために、リモートのイメージサーバーのイメージ一覧をこのコンピューターから読み込みます。
