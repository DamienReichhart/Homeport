**Homeport** ist eine Desktop-App zur Verwaltung von Docker Engines, wo auch immer sie laufen – der Engine dieses Rechners oder entfernter Engines über SSH, TLS oder TCP – und der Kubernetes-Cluster, die Ihre kubeconfig erreicht, ganz im Sinne von Docker Desktop. Sie läuft unter Windows, macOS und Linux, ist kostenlos und quelloffen unter der [GNU Affero General Public License, Version 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE).

Homeport führt selbst keine Container aus. Es verbindet sich mit den Docker Engines, die Sie bereits haben, den sogenannten **Hosts**, und bietet Ihnen ein einziges Fenster für alles, was darauf läuft: Container, Images, Volumes, Netzwerke und Compose-**Stacks**. Außerdem verbindet es sich mit Kubernetes-**Clustern** aus Ihrer kubeconfig, um zu durchsuchen, was auf ihnen läuft.

## Begriffe, die wir verwenden

Homeport benennt Dinge genau, und die Dokumentation folgt dem:

- Ein **Host** ist eine Docker Engine, mit der sich Homeport verbindet. Jeder Container, jedes Image, jedes Volume, jedes Netzwerk und jeder Stack gehört zu genau einem Host.
- Ein **Cluster** ist ein Kubernetes-Cluster, mit dem sich Homeport verbindet, hinzugefügt aus einem Kontext Ihrer kubeconfig.
- Ein **Stack** ist ein Compose-Projekt, das auf einem Host läuft. Ein **verwalteter Stack** ist einer, dessen Compose-Datei Homeport aufbewahrt; ein **verknüpfter Stack** bewahrt seine Compose-Dateien in einem Ordner auf diesem Computer auf; ein **externer Stack** wurde auf andere Weise bereitgestellt. Sie können einen externen Stack **übernehmen**, um ihn zu verwalten.

Das [Glossar](/docs/reference/glossary/) enthält die vollständige Liste.
