## Aktualisieren

Wie sich Homeport aktualisiert, hängt davon ab, wie Sie es installiert haben.

### Windows, macOS und das AppImage

Homeport sucht beim Start und alle 6 Stunden nach einer neuen Version. Ist eine erschienen, weist eine Leiste oben im Fenster darauf hin: Wählen Sie **Neuerungen**, um die [Änderungen](/changelog/) zu lesen, oder **Installieren und neu starten**. Homeport lädt das Update herunter, prüft seine Signatur, installiert es und öffnet sich wieder. Nichts wird installiert, bevor Sie es wählen, und [Ihre Daten bleiben erhalten](#ihre-daten-über-versionen-hinweg).

Sie können auch sofort über **Einstellungen → Updates → Jetzt prüfen** suchen.

### Linux-Pakete

Die Pakete `.deb` und `.rpm`, ob mit der [Schnellinstallation](/docs/installation/#schnellinstallation), der [manuellen Einrichtung](/docs/installation/#manuelle-einrichtung) oder aus einer heruntergeladenen Datei installiert, werden aus dem Paket-Repository von Homeport zusammen mit dem Rest Ihres Systems aktualisiert: Ihre üblichen Software-Updates schließen Homeport ein. Um nur Homeport zu aktualisieren:

<Tabs syncKey="linux-format">
  {MANUAL_SETUP.map((setup) => (
    <TabItem label={setup.label}>
      <Code code={UPDATE_COMMANDS[setup.id]} lang="sh" />
    </TabItem>
  ))}
</Tabs>

Homeport sagt Ihnen, wenn eine neue Version erschienen ist, und zeigt den Befehl für Ihr System, überlässt die Installation aber Ihrem Paketmanager.

Wenn Sie das Homeport-Repository entfernt haben, kann Ihr Paketmanager keine neuen Versionen sehen. Richten Sie es mit der [Schnellinstallation](/docs/installation/#schnellinstallation) erneut ein oder laden Sie das neue Paket herunter und installieren Sie es über das alte.

### Update-Prüfungen ausschalten

Schalten Sie **Einstellungen → Updates → Automatisch nach Updates suchen** aus. **Jetzt prüfen** funktioniert weiterhin. Eine Prüfung lädt eine kleine Datei von dieser Website herunter und sendet nichts über Sie oder Ihre Hosts. Siehe [Sicherheit und Ihre Daten](/docs/reference/security/#womit-sich-homeport-verbindet).

### Aktualisieren von 0.2.0 oder älter

Versionen vor 0.3.0 aktualisieren sich nicht selbst, und ihre Linux-Pakete fügen das Repository nicht hinzu. Installieren Sie einmal 0.3.0 oder neuer, auf dieselbe Weise, wie Sie Homeport installiert haben: von der [Download-Seite](/download/) oder unter Linux mit der [Schnellinstallation](/docs/installation/#schnellinstallation). Danach kommen Updates von selbst.

Um trotzdem von neuen Versionen zu erfahren, beobachten Sie das Repository auf GitHub (**Watch → Custom → Releases**) oder folgen Sie dem [Release-Feed](https://github.com/DamienReichhart/Homeport/releases.atom).

## Ihre Daten über Versionen hinweg

Jede Version von Homeport öffnet die Daten jeder früheren Version, zurück bis 0.1.0, und aktualisiert sie, ohne etwas zu verlieren: Hosts, Stacks, Cluster, Einstellungen und Geheimnisse. Ein Update verlangt nie, dass Sie etwas neu einrichten: Wenn eine neue Version zum ersten Mal startet, aktualisiert sie ihre Datenbank an Ort und Stelle, und alles verbindet sich wie zuvor. Jedes Release wird gegen eine Beispieldatenbank jedes früheren Releases getestet.

**Ein Downgrade wird nicht unterstützt.** Sobald eine neuere Version Ihre Daten geöffnet hat, kann eine ältere sie nicht lesen, und sie versucht es auch nicht: Sie hält mit [einer Meldung, die die zu installierende Version nennt](/docs/reference/troubleshooting/#diese-datenbank-wurde-zuletzt-von-homeport--oder-neuer-verwendet), an, statt etwas zu ändern. Ihre Daten bleiben, wie die neuere Version sie hinterlassen hat; installieren Sie diese Version oder eine neuere, und Homeport öffnet sie wieder.

**Sichern Sie, bevor Sie eine Vorabversion ausprobieren.** Eine Vorabversion aktualisiert die Datenbank wie jede andere Version, sodass das stabile Release, von dem Sie kommen, sie nicht mehr öffnen kann. Wählen Sie zuerst **Einstellungen → Daten → Sichern…**; siehe [Ihre Daten und Sicherungen](/docs/reference/data-and-backups/#in-homeport-sichern). Um zum stabilen Release zurückzukehren, beenden Sie Homeport, verschieben Sie `homeport.db` aus dem [Datenordner](/docs/reference/data-and-backups/#der-datenordner), installieren Sie das stabile Release erneut und stellen Sie diese Sicherung mit **Wiederherstellen…** wieder her.

## Deinstallieren

<Tabs syncKey="os">
<TabItem label="Windows">
Öffnen Sie **Einstellungen → Apps → Installierte Apps**, suchen Sie **Homeport** und wählen Sie **Deinstallieren**.
</TabItem>
<TabItem label="macOS">Beenden Sie Homeport und ziehen Sie es aus „Programme“ in den Papierkorb.</TabItem>
<TabItem label="Linux">

```sh
sudo apt purge homeport       # Debian, Ubuntu
sudo dnf remove homeport      # Fedora, RHEL
sudo zypper remove homeport   # openSUSE
```

Dies entfernt auch das Homeport-Repository. Unter Debian und Ubuntu behält `apt remove` es, zusammen mit der restlichen Konfiguration des Pakets, und `apt purge` entfernt es mit seinem Schlüssel. Unter Fedora und openSUSE bleibt der Schlüssel im Schlüsselbund von rpm; `rpm -q gpg-pubkey --qf '%{NAME}-%{VERSION}-%{RELEASE} %{SUMMARY}\n'` listet die Schlüssel auf, und `sudo rpm -e gpg-pubkey-<version>-<release>` entfernt den von Homeport.

Beim AppImage löschen Sie die Datei. Sein Menüeintrag verschwindet mit ihr.

</TabItem>
</Tabs>

Die Deinstallation lässt Ihre Daten an Ort und Stelle, sodass eine Neuinstallation alles zurückbringt. [Ihre Daten und Sicherungen](/docs/reference/data-and-backups/) sagt, wo sie liegen.

### Der Anmeldeeintrag

Wenn **Bei der Anmeldung starten** aktiviert ist, schalten Sie es vor der Deinstallation unter **Einstellungen → Desktop** aus: Die Deinstallation lässt den Anmeldeeintrag zurück, der dann auf ein nicht mehr vorhandenes Homeport verweist. Um ihn danach zu entfernen:

| System  | Anmeldeeintrag                                                                                                                                                                |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows | **Task-Manager → Autostart-Apps**: Deaktivieren Sie **Homeport** oder löschen Sie den Wert `Homeport` unter `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run` |
| macOS   | Löschen Sie `~/Library/LaunchAgents/Homeport.plist`                                                                                                                           |
| Linux   | Löschen Sie `~/.config/autostart/Homeport.desktop`                                                                                                                            |

## Ihre Daten entfernen

<Aside type="caution">
  Dies löscht Ihre Hosts und Cluster mit ihren gespeicherten Schlüsseln, Zertifikaten und Tokens,
  Ihre verwalteten, verknüpften und synchronisierten Stacks mit ihren Umgebungen und ihrem
  Bereitstellungsverlauf, Ihre Registry-Anmeldungen, Repositorys und Einstellungen. Die Ordner
  verknüpfter Stacks bleiben, wo sie sind. Nichts auf Ihren Hosts und Clustern wird angetastet. Um
  vorher eine Kopie zu behalten, [sichern Sie sie](/docs/reference/data-and-backups/).
</Aside>

1. Löschen Sie die Daten- und Logordner von Homeport:

   | System  | Ordner                                                                                |
   | ------- | ------------------------------------------------------------------------------------- |
   | Linux   | `~/.local/share/com.homeport.app/`, `~/.config/com.homeport.app/`                     |
   | macOS   | `~/Library/Application Support/com.homeport.app/`, `~/Library/Logs/com.homeport.app/` |
   | Windows | `%APPDATA%\com.homeport.app\`, `%LOCALAPPDATA%\com.homeport.app\`                     |

2. Löschen Sie den Verschlüsselungsschlüssel aus Ihrem Schlüsselbund – den Eintrag für `com.homeport.app`, Konto `secrets-key`:
   - **macOS** – suchen Sie in der **Schlüsselbundverwaltung** nach `com.homeport.app` und löschen Sie den Eintrag.
   - **Windows** – entfernen Sie in **Anmeldeinformationsverwaltung → Windows-Anmeldeinformationen** den Eintrag, der `com.homeport.app` enthält.
   - **Linux** – löschen Sie in **Passwörter und Verschlüsselung** (Seahorse) oder KWallet den Eintrag für `com.homeport.app`.

3. Entfernen Sie auf Ihren Servern die öffentlichen Schlüssel von Homeport aus `~/.ssh/authorized_keys` – ihre Kommentare beginnen mit `homeport@`. Entfernen Sie auf Ihren Git-Forges die Deploy-Keys, die Homeport für Ihre Repositorys erstellt hat, und auf Incus-Servern, die über HTTPS hinzugefügt wurden, das Zertifikat von Homeport (`incus config trust list`, dann `incus config trust remove`).
