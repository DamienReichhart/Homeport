### هل Homeport مجاني؟

نعم. استخدام Homeport مجاني، للأعمال الشخصية والتجارية، وهو مفتوح المصدر بموجب [GNU Affero General Public License, version 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE) (AGPL).

### ماذا تعني AGPL بالنسبة لي؟

لا يتغير شيء إذا كنت تستخدم Homeport: ثبّته، وشغّله في المنزل أو في العمل، على ما شئت من أجهزة الكمبيوتر. لا تطلب AGPL شيئًا إلا ممن **يوزّعون** Homeport، معدّلًا أو لا، أو يقدّمون نسخة معدّلة منه للآخرين عبر شبكة: إذ يجب عليهم نشر شيفرته المصدرية كاملة بموجب الترخيص نفسه. ترتبط كل نسخة من Homeport بالشيفرة المصدرية لإصدارها بالضبط في **الإعدادات ← التراخيص**.

الإصدارات حتى 0.11 صدرت بموجب ترخيص MIT وتبقى متاحة بموجبه.

### هل يحل Homeport محل Docker Desktop؟

ليس تمامًا. Homeport أداة إدارة: لا يشغّل محرك Docker بنفسه. على Linux، ثبّت Docker Engine واستخدم Homeport كواجهة له. وعلى macOS وWindows، ما زلت تحتاج إلى شيء يشغّل المحرك — Docker Desktop أو Colima أو OrbStack أو Rancher Desktop أو Podman — ويمكن لـ Homeport أن يعمل فوق أي منها، إلى جانب خوادمك البعيدة.

### هل يعمل مع containerd؟

نعم، مباشرةً، دون Docker: يمكن أن يكون محرك المضيف [containerd](/docs/hosts/containerd/)، يُوصَل إليه عبر مقبسه على هذا الجهاز أو عبر SSH — containerd الخاص بـ k3s، أو الخاص بـ Docker Engine، أو خدمة containerd على خادم. يسرد Homeport مساحات أسمائه، وحاوياته ومهامها (تشغيل، وإيقاف، وإيقاف مؤقت، وإرسال إشارة، وإزالة)، وسجلاتها حيث كتبها nerdctl أو Kubernetes، وطرفية داخلها، وصوره (سحب، وإزالة) ولقطاته. لا ينشئ حاويات ولا ينشر مكدسات هناك؛ فهذا ما يفعله nerdctl.

### هل يعمل مع Incus؟

نعم: يمكن أن يكون محرك المضيف [Incus](/docs/hosts/incus/) 6.0 أو أحدث، يُوصَل إليه عبر مقبسه على هذا الجهاز أو عبر SSH، أو عبر HTTPS برمز الثقة من `incus config trust add`. يسرد Homeport [المثيلات](/docs/guides/instances/) في مشروع، من حاويات نظام وآلات افتراضية، ويشغّلها ويوقفها ويجمّدها ويحذفها وينشئها، ويفتح وحدة التحكم الخاصة بها وطرفية داخلها، ويلتقط اللقطات ويستعيدها، ويدير الصور وملفات التعريف ومجمّعات التخزين والشبكات. لا ينشر مكدسات هناك، ولا يثبّت أي شيء على المضيف.

### هل يعمل مع LXD؟

ليس بهذه الصفة: يتحدث Homeport مع Incus، وهو تفرّع المجتمع من LXD، ويرفض خادم LXD، الذي ابتعدت واجهة API الخاصة به. رحّله باستخدام `lxd-to-incus`، ثم أضفه كمضيف Incus.

### هل يعمل مع Podman؟

نعم، عبر مقبس API المتوافق مع Docker في Podman. يكتشف Homeport مقابس Podman المعتادة على Linux، وكل [آلة Podman عاملة على macOS](/docs/hosts/local/#آلات-podman-على-macos)، وأنبوب آلة Podman الافتراضية على Windows. ويمكن [إضافة أي شيء آخر يدويًا](/docs/hosts/local/#إضافة-مقبس-يدويًا).

ويتعرّف Homeport أيضًا على Podman عند الاتصال به، ثم يتيح ما لا يملكه سوى Podman، عبر واجهة API الخاصة بـ Podman على المقبس نفسه: [الـ Pods](/docs/guides/podman-pods/)، التي يمكنك سردها وتشغيلها وإيقافها وإنشاؤها وإزالتها، وتشغيل حاويات فيها من نافذة «تشغيل»؛ و[وحدات Quadlet](/docs/guides/quadlet/)، التي يمكنك سردها وقراءتها وتثبيتها وتحريرها وإزالتها، وتشغيلها أو إيقافها عبر SSH.

### هل يعمل مع Kubernetes أو Nomad أو Docker Swarm؟

Docker Swarm، نعم. يعثر Homeport على Swarm عبر مضيفاته المديرة، بمجرد أن يكون أحدها مضيفًا، ويديره بالكامل: عقده، وخدماته، ومهامه، وأسراره، وتكويناته، ومكدسات الـ swarm، بما فيها المكدسات المُدارة والمرتبطة والمتزامنة المنشورة عليه. ويمكنه أيضًا بدء Swarm على مضيف، والانضمام إلى واحد أو مغادرته. يمر كل شيء عبر Engine API لمدير متصل؛ ولا يُثبَّت أي شيء على العقد. راجع [Swarm](/docs/guides/swarm/).

Kubernetes، نعم. أضف عنقودًا من ملف kubeconfig — الخاص بهذا الكمبيوتر أو ملف تلصقه — ويعثر Homeport على العناقيد المحلية (Docker Desktop وOrbStack وRancher Desktop وkind وk3d وminikube) نيابةً عنك. تعمل EKS وGKE وAKS عبر مكوّن exec الإضافي الذي يسمّيه ملف kubeconfig الخاص بها. يمكنك تصفح الـ Namespaces وأحمال العمل والـ Pods والـ Services والـ Ingresses والـ ConfigMaps والـ Secrets والـ Nodes والأحداث وأي مورد API آخر، بما فيها الموارد المخصصة، مباشرةً؛ ومتابعة السجلات، وفتح طرفية في Pod، وإعادة توجيه المنافذ، وتغيير عدد النسخ، وإعادة التشغيل والحذف، وتطبيق YAML أو تحريره مع معاينة. لا يُثبَّت أي شيء على العنقود: لا يتحدث Homeport إلا مع Kubernetes API الذي يصل إليه ملف kubeconfig الخاص بك مسبقًا، بصلاحيات بيانات اعتماده. ومع وجود أداة `helm` CLI على هذا الكمبيوتر، يسرد Homeport أيضًا [إصدارات Helm](/docs/clusters/helm/) ويثبّتها ويرقّيها ويتراجع عنها ويلغي تثبيتها، ويدير مستودعات المخططات الخاصة بـ helm. راجع [العناقيد](/docs/clusters/).

Nomad، نعم. أضف عنقودًا بعنوان وكيله، مع رمز ACL ومواد TLS عندما يستخدمها. يمكنك سرد الـ jobs والـ allocations الخاصة بها، مباشرةً؛ وتشغيل job من HCL أو JSON بعد رؤية خطة Nomad؛ وتحرير job وإعادة تشغيله، أو إيقافه أو محوه، وتغيير عدد نسخ الـ task groups الخاصة به؛ ومتابعة سجلات مهمة وفتح صدفة فيها؛ وتفريغ العقد وتبديل أهليتها؛ واختيار namespace. لا يُثبَّت أي شيء على العنقود ولا حاجة إلى أداة `nomad` CLI: يتحدث Homeport مع HTTP API الخاص بـ Nomad بصلاحيات الرمز. راجع [عناقيد Nomad](/docs/clusters/nomad/).

### هل أحتاج إلى kubectl؟

لا. يقرأ Homeport ملف kubeconfig الخاص بك ويتحدث مع Kubernetes API بنفسه. البرامج الوحيدة التي يشغّلها هي [مكونات exec الإضافية](/docs/clusters/exec-plugins/) التي يسمّيها ملف kubeconfig، مثل AWS CLI لـ EKS، أو `gke-gcloud-auth-plugin` لـ GKE، أو `kubelogin` لـ AKS — وهي نفسها التي كان `kubectl` سيشغّلها. ومع ذلك يظل وجود `kubectl` مفيدًا للتحقق مما تستطيع بيانات اعتمادك فعله (`kubectl auth can-i`).

### هل أحتاج إلى تثبيت أي شيء على خوادمي؟

لا — فقط محرك Docker وخادم SSH، وهما على الأرجح موجودان لديك مسبقًا. لا يثبّت Homeport وكلاء.

ولا يحتاج Swarm إلى أكثر من المحرك أيضًا. لكن يجب أن تصل عقده إلى بعضها، وهذا ما لا يستطيع Homeport إعداده نيابةً عنك: افتح 2377/tcp (إلى المديرين)، و7946/tcp و7946/udp، و4789/udp بينها. راجع [المنافذ بين العقد](/docs/guides/swarm/#المنافذ-بين-العقد).

### هل أحتاج إلى تثبيت Docker على كمبيوتري لإدارة الخوادم البعيدة؟

لا. يتحدث Homeport Engine API وSSH بنفسه. الاستثناءان الوحيدان هما نشر المكدسات المُدارة والمرتبطة والمتزامنة، الذي يستخدم الأمر `docker compose` على كمبيوترك، ونشرها على Swarm، الذي يستخدم الأمر `docker` (`docker stack deploy`). ولا يحتاج أي منهما إلى محرك على كمبيوترك.

### هل يبقي Homeport مكدساتي متزامنة عندما يكون مغلقًا؟

لا. لا يُتحقق من وجود إيداعات جديدة في [المكدسات المتزامنة](/docs/guides/synced-stacks/)، ولا تُنشر تلقائيًا إذا فعّلت ذلك، إلا أثناء فتح Homeport. لا يثبّت Homeport أي شيء على خوادمك — لا وكيل، ولا مستقبِل webhook — لذا عندما يكون مغلقًا، لا شيء يراقب مستودعاتك. وعندما تفتحه مجددًا، ينتظر فاصلًا زمنيًا واحدًا، ثم يتحقق منها جميعًا. لعمليات النشر التي يجب أن تتبع كل دفع على مدار الساعة، شغّلها من CI الخاص بك.

لإبقاء Homeport يعمل دون نافذته، فعّل **الإغلاق إلى علبة النظام**، و**البدء عند تسجيل الدخول** مع **البدء مخفيًا في علبة النظام**، في [الإعدادات ← سطح المكتب](/docs/guides/settings/#سطح-المكتب).

### هل يستطيع Homeport إخباري عندما تتعطل حاوية؟

نعم، أثناء عمله — حتى وهو مخفي في علبة النظام. يعرض إشعارًا من نظام التشغيل عندما تتوقف حاوية بخطأ، أو تنفد ذاكرتها، أو تصبح غير سليمة، وعندما يتعذّر الوصول إلى مضيف أو يعود. ويمكن إيقاف كل نوع في [الإعدادات ← الإشعارات](/docs/guides/settings/#الإشعارات). يعرف ذلك من تدفق الأحداث الذي يحتفظ به مسبقًا مع كل مضيف، لذا لا يُثبَّت أي شيء على خوادمك؛ وعندما لا يكون Homeport قيد التشغيل، لا يُبلَّغ أحد.

### هل يحتاج Homeport إلى git؟

فقط لـ [المكدسات المتزامنة](/docs/guides/synced-stacks/)، التي تشغّل `git` المثبّت على كمبيوترك، بمفتاح النشر أو الرمز المميز الخاص بكل مستودع. يوضح **الإعدادات ← هذا الجهاز** ما إذا كان Homeport قد عثر عليه. لا يُستخدم أبدًا تكوين git الخاص بك ولا أدوات مساعدة بيانات الاعتماد ولا مفاتيح SSH الخاصة بك.

### هل يمكن لعدة أشخاص مشاركة مضيفات Homeport؟

يشغّل كل شخص Homeport الخاص به بمضيفاته ومفاتيحه الخاصة. ومع مفتاح ينشئه Homeport لكل شخص ولكل خادم، يمكنك رؤية وصول كل منهم وإلغاؤه في `authorized_keys`.

### هل يمكنني نقل Homeport إلى كمبيوتر آخر؟

نعم، بطريقتين:

- **كل شيء**: يحفظ **الإعدادات ← البيانات ← نسخ احتياطي…** كل مضيف وعنقود ومكدس وتسجيل دخول سجل ومستودع وإعداد، مع أسرارها، في ملف واحد محمي بعبارة مرور لا تقل عن 12 حرفًا. على الكمبيوتر الجديد، يفتحه **استعادة…** في المكان نفسه، ويسرد ما يحتويه، ويستبدل ما هو موجود. يتصل كل شيء وينشر دون أن يطلب منك مفتاحًا أو كلمة مرور مجددًا. راجع [النسخ الاحتياطي والاستعادة](/docs/guides/settings/#النسخ-الاحتياطي-والاستعادة).
- **بعض المضيفات**: في صفحة **المضيفات**، استخدم **تصدير** للمضيفات التي تختارها، و**استيراد** على الكمبيوتر الآخر، إلى جانب المضيفات الموجودة عليه. راجع [الانتقال إلى كمبيوتر آخر](/docs/reference/security/#الانتقال-إلى-كمبيوتر-آخر).

نسخ `homeport.db` لا ينفع مع الأسرار: فهي مشفّرة بمفتاح محفوظ في سلسلة مفاتيح هذا الكمبيوتر، وتظهر بحالة **فُقدت بيانات الاعتماد** في أي مكان آخر.

### هل تتضمن النسخة الاحتياطية حاوياتي ووحدات التخزين الخاصة بي؟

لا. تحتوي النسخة الاحتياطية على ما يحتفظ به Homeport — كيفية الوصول إلى مضيفاتك، وتعريفات مكدساتك وبيئاتها، وعمليات تسجيل الدخول والإعدادات — لا ما يعمل على مضيفاتك. تبقى حاوياتك وصورك ووحدات التخزين الخاصة بك على المضيفات. لنسخ بيانات وحدة تخزين، [انسخها احتياطيًا إلى ملف](/docs/guides/volumes-networks/#النسخ-الاحتياطي-والاستعادة) من صفحة «وحدات التخزين».

### هل يستطيع Homeport بناء الصور؟

نعم، في مكانين. تبني صفحة **الصور** صورة من مجلد على هذا الكمبيوتر. ويمكن لـ [المكدس المرتبط](/docs/guides/stacks/#المكدسات-المرتبطة) — وهو مكدس توجد ملفات compose الخاصة به في مجلد على هذا الكمبيوتر — استخدام `build:`: يشغّل Homeport الأمر `docker compose` في ذلك المجلد، فيُرسل سياق البناء من هناك إلى محرك المضيف، الذي يبنيه. يعيد **إعادة البناء والنشر** البناء بعد تغيير في الشيفرة. لا يستطيع المكدس المُدار البناء، لأن Homeport لا يحتفظ إلا بـ YAML الخاص به ولا يوجد مجلد للبناء منه: اربط المجلد بدلًا من ذلك، أو ادفع الصورة إلى سجل.

### لماذا يظهر مكدسي كخارجي على كمبيوتري الآخر؟

المكدس الذي بدأ باستخدام `docker compose up` في مجلد لا يظهر كـ [مرتبط](/docs/guides/stacks/#كيف-يُعثر-على-المكدسات-المرتبطة) إلا على كمبيوتر يوجد فيه ذلك المجلد وملفات compose الخاصة به، في المسار نفسه، وتعرّف الخدمات التي تعمل. على كمبيوتر آخر لا يوجد المسار، لذا لا يملك Homeport ملف compose له ويعرضه كخارجي. لإدارته من هناك أيضًا، استنسخ المشروع إلى ذلك الكمبيوتر واربطه عبر **مكدس جديد ← استخدام مجلد على هذا الكمبيوتر**، أو تبنَّه كمكدس مُدار.

### هل يجمع Homeport بيانات عني؟

لا. لا يوجد حساب ولا قياس عن بُعد ولا تحليلات. الطلب الوحيد الذي يجريه Homeport من تلقاء نفسه من كمبيوترك هو التحقق من التحديثات، الذي ينزّل ملفًا صغيرًا من هذا الموقع ولا يرسل أي شيء عنك؛ ويمكنك إيقافه في **الإعدادات ← التحديثات**. وبشكل منفصل، يسأل التحقق من الصور الأحدث سجلات صورك، عبر محرك كل مضيف، عن الإصدار الذي تشير إليه وسومها؛ وبالنسبة للمضيف المحلي، يخرج ذلك الطلب من كمبيوترك أيضًا. راجع [الأمان وبياناتك](/docs/reference/security/#ما-يتصل-به-homeport).

### هل يستطيع Homeport استخدام سجلاتي الخاصة؟

نعم. أضف تسجيل دخول لكل سجل في **الإعدادات ← سجلات الحاويات** — Docker Hub أو GHCR أو سجلك الخاص. يسلّمه Homeport إلى المحرك للسحب والدفع والبناء على أي مضيف، ويسحب به صور المكدس المُدار أو المرتبط أو المتزامن قبل النشر. تُشفَّر كلمات المرور والرموز المميزة باستخدام سلسلة مفاتيح نظام التشغيل. لا يقرأ Homeport عمليات تسجيل الدخول الخاصة بـ `docker login` على هذا الكمبيوتر.

### كيف يعرف Homeport أن هناك صورة أحدث؟

يسأل سجل الصورة، عبر محرك المضيف، عن الملخص الذي يشير إليه الوسم الآن، ويقارنه بالملخص الذي سحبه المضيف. لا يُنزَّل أي شيء، لكن Docker Hub يحتسب كل سؤال ضمن حد معدل السحب الخاص به، مثل `docker pull` لا يجد جديدًا. لذا يحتفظ Homeport بكل إجابة لمدة 6 ساعات، ولا يسأل أكثر من أربعة سجلات في آن واحد، ولا يسأل مجددًا قبل ذلك إلا عندما تختار **التحقق من وجود صور أحدث**. يرفع تسجيل الدخول إلى Docker Hub في **الإعدادات ← سجلات الحاويات** هذا الحد. إذا تعذّر الوصول إلى سجل أو كان يفرض حدًا للمعدل، لا يعرض Homeport أي علامة لصوره ويكتب سطرًا في سجله.

### كيف أحدّث؟

على Windows وmacOS ومع AppImage، يخبرك Homeport عند صدور إصدار جديد: اختر **تثبيت وإعادة التشغيل**. وعلى Linux، تتحدث حزمتا `.deb` و`.rpm` مع بقية نظامك من مستودع حزم Homeport. راجع [التحديث](/docs/reference/updating/).

### هل Homeport متاح على Homebrew أو winget أو Flathub أو AUR؟

ليس بعد. هي مخطط لها؛ وتربط [صفحة التثبيت](/docs/installation/#قادم-لاحقًا) بالمشكلة الخاصة بكل منها.

### هل Homeport متاح بلغتي؟

يتحدث Homeport الإنجليزية والفرنسية والإسبانية والألمانية والإيطالية والبرتغالية البرازيلية والروسية والصينية المبسطة واليابانية والكورية والهندية والعربية، ويتبع لغة نظام التشغيل ما لم تختر لغة ضمن [الإعدادات ← المظهر](/docs/guides/settings/#المظهر). والموقع متاح بها جميعًا أيضًا؛ أما الوثائق فمترجمة بالكامل إلى الفرنسية، وتعرض اللغات الأخرى الصفحة الإنجليزية حيث لا توجد ترجمة بعد. لإضافة لغة، راجع [المساهمة](/docs/project/contributing/#ترجمة-homeport).

### هل Homeport سهل الوصول؟

يمكن استخدامه بلوحة المفاتيح وحدها، ويتبع إعداد تقليل الحركة في نظامك، ويحقق تباين WCAG 2.2 AA، وتُفحص كل صفحة بأدوات آلية لإمكانية الوصول. ويجري حاليًا تدقيق عملي باستخدام قارئات الشاشة. راجع [لوحة المفاتيح وإمكانية الوصول](/docs/reference/accessibility/) لمعرفة ما يعمل، والقيود المعروفة، وكيفية الإبلاغ عن عائق.

### هل توجد واجهة سطر أوامر؟

لا — Homeport تطبيق سطح مكتب. تعمل أداة `docker` CLI الموجودة لديك إلى جانبه، ويتحدث Homeport مباشرةً عندما تغيّر أشياء من الطرفية.

### كيف يمكنني المساعدة؟

أبلغ عن الأخطاء واقترح الميزات في [مشكلات GitHub](https://github.com/DamienReichhart/Homeport/issues)، أو راجع [المساهمة](/docs/project/contributing/).
