يحتفظ Homeport ببيانات اعتماد تفتح خوادمك. توضح هذه الصفحة بالضبط ما يحتفظ به، وكيف يُحمى. وتذكر صفحة [بياناتك ونسخها الاحتياطية](/docs/reference/data-and-backups/) ما يجب نسخه لعمل نسخة احتياطية منه، وكيفية استعادته.

## ما يخزّنه Homeport

يعيش كل شيء في قاعدة بيانات SQLite واحدة، `homeport.db`، في مجلد بيانات التطبيقات الخاص بمستخدمك:

| النظام  | المجلد                                            |
| ------- | ------------------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/`                |
| macOS   | `~/Library/Application Support/com.homeport.app/` |
| Windows | `%APPDATA%\com.homeport.app\`                     |

وتحتوي على:

| البيانات                                              | طريقة التخزين |
| ----------------------------------------------------- | ------------- |
| أسماء المضيفات وعناوينها ومستخدمو SSH ومسارات المقابس | نص عادي       |
| مفاتيح SSH العامة ومفاتيح الخوادم التي وثقت بها       | نص عادي       |
| مفاتيح SSH الخاصة وعبارات مرورها                      | **مشفّرة**    |
| شهادات CA الخاصة بـ TLS وشهادات العملاء ومفاتيحهم     | **مشفّرة**    |
| مفاتيح العملاء لمضيفات Incus وشهاداتها المثبّتة       | **مشفّرة**    |
| ملفات compose للمكدسات المُدارة                       | نص عادي       |
| بيئات المكدسات المُدارة                               | **مشفّرة**    |
| مجلدات المكدسات المرتبطة ومسارات ملفات compose        | نص عادي       |
| سجل النشر: ملفات compose وملفات التعريف               | نص عادي       |
| سجل النشر: البيئات                                    | **مشفّرة**    |
| عناوين السجلات وأسماء المستخدمين                      | نص عادي       |
| كلمات مرور السجلات ورموز الوصول                       | **مشفّرة**    |
| عناوين URL للمستودعات، والأنصاف العامة لمفاتيح النشر  | نص عادي       |
| مفاتيح خوادم المستودعات التي وثقت بها                 | نص عادي       |
| مفاتيح النشر ورموز الوصول للمستودعات                  | **مشفّرة**    |
| أسماء العناقيد وعناوين URL لخوادم API والـ Namespaces | نص عادي       |
| طريقة تسجيل دخول كل عنقود، وسياق kubeconfig الخاص به  | نص عادي       |
| شهادات CA للعناقيد وشهادات العملاء ومفاتيحهم          | **مشفّرة**    |
| رموز العناقيد وكلمات مرورها ورموز OIDC                | **مشفّرة**    |
| أوامر مكونات exec الإضافية ووسائطها وبيئتها           | **مشفّرة**    |
| السمة، وآخر تحديد، والـ Namespace لكل عنقود           | نص عادي       |
| أحداث محرك كل مضيف، لصفحة «الأحداث»                   | نص عادي       |

لا ينسخ Homeport أي شيء آخر من محركاتك: تُقرأ الحاويات والصور ووحدات التخزين والسجلات مباشرةً ولا تُحفظ أبدًا، إلا عندما تنزّل السجلات أو الملفات، أو تنسخ وحدة تخزين احتياطيًا، بنفسك. أما أحداث المحرك التي يحتفظ بها — ما حدث لأي حاوية أو صورة أو وحدة تخزين أو شبكة، مع تسمياتها — فتُحفظ لمدة 30 يومًا افتراضيًا ([الإعدادات ← البيانات](/docs/guides/settings/#البيانات))، وبحد أقصى 10,000 حدث لكل مضيف، وتُزال مع مضيفها أو باستخدام **مسح السجل**.

### مجلدات المكدسات المرتبطة

بالنسبة إلى [المكدس المرتبط](/docs/guides/stacks/#المكدسات-المرتبطة)، لا يخزّن Homeport سوى موقع مجلده وملفات compose الخاصة به، وبصمة للملفات لمعرفة متى تتغير — ولا يخزّن نسخة منها أبدًا. يقرأ ملفات compose عندما تفتح المكدس، ولا يكتب فيها إلا عندما تختار **حفظ** في علامة التبويب **التعريف** الخاصة به، مستبدلًا كل ملف محرَّر في خطوة واحدة ومحافظًا على أذوناته؛ ولن يستبدل ملفًا تغيّر منذ أن فتحته إلا إذا طلبت ذلك. لا يقرأ Homeport ملف `.env` الخاص بالمجلد ولا يكتب فيه أبدًا: يقرؤه Compose عند تشغيله. ونسيان مكدس مرتبط لا يمسّ المجلد أبدًا.

### المستودعات

بالنسبة إلى [المكدسات المتزامنة](/docs/guides/synced-stacks/)، يحتفظ Homeport بعنوان URL لكل مستودع، وإما بمفتاح نشر أنشأه لذلك المستودع (نصفه الخاص مشفّر) أو باسم المستخدم ورمز وصول (مشفّر). محتوى المستودع ليس سرًا: توجد نسخته المستنسخة في مجلد `repositories` بجانب `homeport.db`.

### Swarm

لا يخزّن Homeport أي شيء عن [Swarm](/docs/guides/swarm/): يعثر عليه عبر مضيفاته المديرة في كل مرة يتصل فيها. تذهب قيم أسرار Swarm إلى الـ Swarm ولا يحتفظ بها Homeport: القيمة التي تكتبها أو تحمّلها من ملف تُرسل إلى المحرك مرة واحدة، ولا تُكتب أبدًا في `homeport.db` أو في ملف أو في السجل، وتُحذف من الذاكرة عند إغلاق مربع الحوار. لا يعيد المحرك قيمة السر أبدًا، لذا لا يستطيع Homeport عرضها أيضًا. تُجلب رموز الانضمام من مدير عندما تحتاج إليها، ولا تُخزَّن ولا تُسجَّل أبدًا.

### العناقيد

تأتي بيانات اعتماد [العنقود](/docs/clusters/) من ملف kubeconfig الخاص بك ولا تُخزَّن إلا مشفّرة، مثل مفاتيح SSH؛ تُقرأ الملفات التي يشير إليها ملف kubeconfig مرة واحدة وتُضمَّن، ولا يُكتب ملف kubeconfig الملصوق في ملف أبدًا، ولا يُغيَّر ملف kubeconfig الخاص بك أبدًا. يعمل [مكوّن exec الإضافي](/docs/clusters/exec-plugins/) على هذا الكمبيوتر، بصفتك أنت، ويُحفظ الرمز أو الشهادة التي يطبعها في الذاكرة فقط، إلى أن تنتهي صلاحيتها. لا يخزّن Homeport أي شيء آخر عما يعمل على العنقود: تُقرأ الـ Pods وأحمال العمل وبقية الموارد مباشرةً. تستمع [عمليات إعادة توجيه المنافذ](/docs/clusters/port-forward/) على واجهة الاسترجاع لهذا الكمبيوتر فقط (`127.0.0.1` و`::1`)، فلا يستطيع أي شيء آخر على شبكتك استخدامها، وتنتهي عند إنهاء Homeport. تُسجَّل التغييرات التي تُجرى باستخدام [تطبيق YAML أو تحرير](/docs/clusters/yaml/) على العنقود تحت مدير الحقول `homeport`.

يشغّل [Helm](/docs/clusters/helm/) أداة `helm` CLI الخاصة بك على عنقود دون ملف kubeconfig الخاص بك ودون كتابة أي بيانات اعتماد للعنقود على القرص: لكل أمر، يفتح Homeport اتصالًا خاصًا على واجهة الاسترجاع لهذا الكمبيوتر (`127.0.0.1`، منفذ عشوائي) لا يقبل إلا الطلبات التي تحمل رمزًا عشوائيًا، ويعطي helm ملف kubeconfig مؤقتًا، لا يقرؤه أحد سواك، لا يحتوي إلا على ذلك الرمز. يضيف Homeport بيانات اعتماد العنقود نفسه إلى كل طلب في طريقه، ويحذف ملف kubeconfig ويغلق الاتصال عند انتهاء الأمر. تذهب قيم المخطط إلى helm عبر مدخله القياسي، وليس في ملف أبدًا. تبقى مستودعات المخططات وعمليات تسجيل الدخول إلى السجلات وذاكرات التخزين المؤقت الخاصة بـ helm ملكًا لـ helm، كما في الطرفية؛ ولا يضيف Homeport إلا مستودعات عامة ولا يخزّن أي كلمة مرور لمستودع.

لا يُخزَّن رمز ACL وشهادة CA وشهادة العميل ومفتاحه الخاصة بـ [عنقود Nomad](/docs/clusters/nomad/) إلا مشفّرة، مثل مفاتيح SSH؛ أما عنوانه ومنطقته واسم خادم TLS الخاص به فتُحفظ بشكل صريح. ينتقل الرمز في الترويسة `X-Nomad-Token` لكل طلب، وليس في عنوان URL أبدًا، بما في ذلك WebSocket الخاص بالصدفة. لا يحتفظ Homeport بنسخة من مواصفات الـ job: إذ يخزّنها Nomad مع الـ job.

**قيم Secret في Kubernetes** لا تُجلب إلا عندما تختار **إظهار** لمفتاح واحد، واحدًا تلو الآخر: تحمل القوائم وصفحة الـ Secret وYAML الخاص به مفاتيحه وأحجامها، ولا تحمل قيمه أبدًا. تبقى القيمة المُظهرة في ذاكرة تلك الصفحة — لا في أي ذاكرة تخزين مؤقت، ولا في `homeport.db`، ولا في السجل — وتُخفى مجددًا عندما تغادر الصفحة.

## كيف تُشفَّر الأسرار

- يُختم كل سر على حدة باستخدام **XChaCha20-Poly1305**، وهو تشفير مصادَق، فيُكتشف العبث كما تُمنع القراءة.
- المفتاح ذو 256 بت عشوائي، يُنشأ عند التشغيل الأول، ويُحفظ في **سلسلة مفاتيح نظام التشغيل** — macOS Keychain، أو Windows Credential Manager، أو Secret Service على Linux — تحت الخدمة `com.homeport.app`. ولا يُخزَّن أبدًا بجانب البيانات.
- لا توجد كلمة مرور رئيسية: إذ تربط سلسلة المفاتيح المفتاح بحساب المستخدم الخاص بك مسبقًا.

من يملك نسخة من `homeport.db` وحدها يستطيع قراءة أسماء المضيفات والعناقيد وعناوينها، لكن ليس مفاتيحك أو شهاداتك أو رموزك أو بيئات مكدساتك أو كلمات مرور السجلات.

### بدون سلسلة مفاتيح

يعرض Homeport شريط تنبيه ولن يخزّن الأسرار. تظل مضيفات المقبس المحلي وTCP وssh-agent تعمل. راجع [المتطلبات](/docs/requirements/#اختياري-سلسلة-مفاتيح-نظام-التشغيل).

### إذا فُقد مفتاح سلسلة المفاتيح

إعادة ضبط سلسلة المفاتيح، أو نقل `homeport.db` إلى كمبيوتر أو مستخدم آخر، يترك أسرارًا لا يمكن فك تشفيرها. لا يحذف Homeport أي شيء: تعرض المضيفات والعناقيد المتأثرة **فُقدت بيانات الاعتماد** إلى أن تعيد إدخال بيانات اعتمادها؛ وتسرد [إذا فُقدت الأسرار](/docs/reference/data-and-backups/#إذا-فُقدت-الأسرار) ما يجب إدخاله مجددًا، وأين. لنقل بياناتك، [انسخها احتياطيًا](#النسخ-الاحتياطية) أو [صدّر مضيفاتك](#الانتقال-إلى-كمبيوتر-آخر) بدلًا من ذلك.

لا يُنشئ Homeport أبدًا مفتاحًا جديدًا فوق أسرار يحتفظ بها بالفعل. عندما تستجيب سلسلة المفاتيح لكن دون إدخال `com.homeport.app` بينما تحتوي قاعدة البيانات على أسرار مشفّرة — تستجيب هذه المرة سلسلة مفاتيح أخرى، مثل Secret Service الخاص بـ KeePassXC بدلًا من GNOME Keyring — لا يخزّن Homeport أي سر ويخبرك بأن **إدخال سلسلة المفاتيح الذي خُتمت به أسرار Homeport مفقود**. ارجع إلى سلسلة المفاتيح التي تحتوي الإدخال وأعد تشغيل Homeport. وإذا ضاع الإدخال نهائيًا، فاختر **البدء من جديد بمفتاح جديد** في **الإعدادات ← هذا الجهاز**: تظهر عندها الأسرار المختومة بالمفتاح القديم على أنها **فُقدت بيانات الاعتماد**، لتُدخلها من جديد أو تستعيدها من نسخة احتياطية.

### الانتقال إلى كمبيوتر آخر

يكتب **تصدير** في صفحة «المضيفات» المضيفات التي تختارها في ملف واحد، مع مفاتيحها وشهاداتها ومفاتيح الخوادم الموثوقة، مشفّرة بعبارة مرور تختارها:

- الملف بأكمله مشفّر (XChaCha20-Poly1305، مع اشتقاق المفتاح من عبارة المرور باستخدام Argon2id)، لذا لا يكشف شيئًا دون عبارة المرور — ولا حتى أسماء المضيفات أو عناوينها. وأي تغيير في الملف يجعله غير قابل للقراءة.
- تحتاج عبارة المرور إلى 12 حرفًا على الأقل. لا يخزّنها Homeport ولا يسجّلها أبدًا؛ وإذا فقدتها، فلا يمكن فتح الملف.
- يطلب **استيراد** على الكمبيوتر الآخر عبارة المرور، ثم يخزّن أسرار كل مضيف مشفّرة بمفتاح سلسلة المفاتيح الخاص بذلك الكمبيوتر، مثل أي أسرار أخرى.
- المضيف الذي فُقدت بيانات اعتماده مسبقًا على هذا الكمبيوتر يُصدَّر بدونها، ويوضح التصدير أيها.

تعامل مع الملف كما تتعامل مع المفاتيح التي يحتويها: احذفه بعد الاستيراد. التنسيق موصوف في [ADR 0013](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0013-passphrase-protected-export-bundles.md).

### النسخ الاحتياطية

يكتب **الإعدادات ← البيانات ← نسخ احتياطي…** كل ما سبق — المضيفات والعناقيد والمكدسات وعمليات تسجيل الدخول إلى السجلات والمستودعات والإعدادات، مع أسرارها مفكوكة — في ملف واحد بالتنسيق المشفّر نفسه، بعبارة مرور تكتبها مرتين. لا تُضمَّن أحداث المحرك وسجل النشر. ويُستبعد السر الذي لا يمكن فتحه على هذا الكمبيوتر، وتوضح النسخة الاحتياطية أيها.

يطلب **استعادة…** عبارة المرور ويسرد ما يحتويه الملف قبل تغيير أي شيء. ثم تقوم الاستعادة بما يلي:

1. تنسخ قاعدة البيانات الحالية إلى `homeport.db.before-restore-<date and time>`، بجانب `homeport.db`؛
2. تستبدل كل مضيف وعنقود ومكدس وتسجيل دخول ومستودع وإعداد في خطوة واحدة، فيترك أي فشل بياناتك كما كانت؛
3. تشفّر كل سر مجددًا بمفتاح سلسلة المفاتيح الخاص بهذا الكمبيوتر.

تُرفض النسخة الاحتياطية التي أنشأها إصدار أحدث من Homeport؛ وتُستعاد التي أنشأها إصدار أقدم. تحتوي النسخة الاحتياطية على كل سر يملكه Homeport: احفظها، وعبارة مرورها، بأمان المفاتيح نفسها. وتتضمن صفحة [بياناتك ونسخها الاحتياطية](/docs/reference/data-and-backups/) الخطوات، وما تتضمنه النسخة الاحتياطية وما تستبعده، وكيف تنسخ قاعدة البيانات بنفسك.

## لا تلمس المفاتيح القرص بشكل صريح أبدًا

لدى Homeport عميل SSH خاص به، لذا لا يكتب أبدًا مفتاحًا خاصًا في ملف ليقرأه `ssh`، ولا يغيّر `~/.ssh` أبدًا. تبقى المفاتيح المفكوكة في الذاكرة.

عندما ينشر `docker compose` مكدسًا على مضيف SSH أو TLS، يفتح Homeport مقبسًا خاصًا قصير العمر على هذا الكمبيوتر — لا يقرؤه سوى مستخدمك، أو أنبوبًا مسمّى يرفض العملاء البعيدين على Windows — ويعيد توجيهه عبر اتصاله الخاص، لذلك الأمر وحده.

ولا تصل مفاتيح المستودعات ورموزها إلى القرص أيضًا. لكل أمر `git`، يقدّم Homeport وكيل SSH خاصًا لا يحتفظ إلا بمفتاح النشر لذلك المستودع — على مقبس لا يفتحه سوى مستخدمك، أو أنبوب مسمّى يرفض العملاء البعيدين على Windows — أو يمرّر الرمز في ترويسة HTTPS عبر بيئة الأمر. يُستبعد تكوين git الخاص بك وأدوات مساعدة بيانات الاعتماد ومفاتيح SSH الخاصة بك، فلا يُخزَّن أي شيء مؤقتًا في سلسلة المفاتيح أو في `~/.git-credentials`.

ولا تصل عمليات تسجيل الدخول إلى السجلات إلى `docker compose` أيضًا: يسحب Homeport صور المكدس بنفسه، عبر Engine API، قبل تشغيل `docker compose up`، فلا تحتوي بيئة الأمر ولا الملفات المعطاة له على أي كلمة مرور أو رمز.

## الوثوق بالخوادم

في أول مرة يتصل فيها Homeport بخادم SSH، يطلب منك تأكيد بصمة مفتاح الخادم، ويرفض الاتصال إذا تغيّر ذلك المفتاح لاحقًا إلى أن تؤكد مجددًا. تتحقق مضيفات TLS من شهادة الخادم مقابل جهة CA الخاصة بك واسم الخادم؛ ولا تقبل مضيفات Incus عبر HTTPS سوى الشهادة التي أُضيفت بها. راجع [مضيفات SSH](/docs/hosts/ssh/#الاتصال-الأول).

### شهادات Incus

تؤدي إضافة [مضيف Incus عبر HTTPS](/docs/hosts/incus/#عبر-https-برمز-الثقة) إلى إنشاء شهادة عميل ومفتاحها الخاص في الذاكرة، بمفتاح ECDSA P-384، وتخزينهما مشفّرين مع أسرار المضيف الأخرى، ولا يُخزَّنان بشكل صريح على القرص أبدًا. وتُخزَّن شهادة Incus نفسه بالطريقة نفسها وتُثبَّت: لا يقبل Homeport من الخادم سوى تلك الشهادة بالضبط، مقارنةً ببصمة SHA-256 الخاصة بها، ويرفض أي شهادة مختلفة، عارضًا البصمتين. يُستخدم رمز الثقة مرة واحدة ولا يُحفظ. أزل شهادة Homeport على الخادم باستخدام `incus config trust remove` لإلغائها.

## ما يتصل به Homeport

- **المضيفات التي تضيفها.** عندما تسحب صورة أو تدفعها أو تبنيها، يتصل المحرك بالسجل، لا Homeport. يسلّمه Homeport تسجيل الدخول المخزن لذلك السجل مع الطلب، عبر اتصال المضيف؛ ولا يحتفظ به المحرك.
- **سجلات صورك، عبر محرك كل مضيف**، لمعرفة ما إذا نُشرت [صورة أحدث](/docs/guides/containers/#الصور-الأحدث): عند تحميل صفحة «الحاويات» أو «الصور» أو «المكدسات» (تُحفظ كل إجابة لمدة 6 ساعات) وعندما تختار **التحقق من وجود صور أحدث**. يسأل المحرك السجل عن الملخص الذي يشير إليه الوسم، مع تسجيل الدخول المخزن للسجلات الخاصة، ولا ينزّل أي شيء. بالنسبة للمضيف المحلي، يعمل المحرك على كمبيوترك، لذا يخرج الطلب منه.
- **Docker Hub، عندما تتصفح الوسوم** في مربع حوار السحب: يسرد Homeport وسوم مستودع من `hub.docker.com`، من هذا الكمبيوتر، مع تسجيل دخولك إلى Docker Hub عند تخزينه. أما البحث في المستودعات فيمر عبر محرك المضيف بدلًا من ذلك.
- **سجل، عندما تتحقق من تسجيل الدخول إليه** في **الإعدادات ← سجلات الحاويات**: يسأل Homeport نقطة النهاية `/v2/` الخاصة بالسجل، وخدمة الرموز الخاصة به، من هذا الكمبيوتر، مرسلًا اسم المستخدم وكلمة المرور أو الرمز عبر HTTPS (HTTP العادي فقط لسجل على هذا الكمبيوتر، مثل `localhost:5000`).
- **خوادم مستودعاتك**، لـ [المكدسات المتزامنة](/docs/guides/synced-stacks/): عندما تختبر الوصول، أو تنشئ مكدسًا متزامنًا أو تزامنه، وعلى فترات أثناء فتح Homeport إذا كان الاستطلاع مفعّلًا. يشغّل Homeport `git` من هذا الكمبيوتر بمفتاح النشر أو الرمز الخاص بذلك المستودع.
- **العناقيد التي تضيفها**، عبر خادم Kubernetes API الذي يسمّيه ملف kubeconfig الخاص بها (والوكيل الخاص به، عند وجوده)، ببيانات الاعتماد التي يوفرها، مع التحقق من شهادة الخادم مقابل جهة CA في ملف kubeconfig. تتصل مكونات exec الإضافية بسحابتها الخاصة (AWS أو Google Cloud أو Azure) من هذا الكمبيوتر، كما تفعل مع `kubectl`.
- **عناقيد Nomad التي تضيفها**، عبر عنوان الوكيل الذي تحدده، ولا شيء غيره: تمر سجلات الـ job والصدفات عبر ذلك الوكيل، الذي يعيد توجيهها إلى عقدة العميل، لذا لا يتصل Homeport بالعقد نفسها أبدًا. يُتحقق من شهادة الوكيل مقابل جهة CA التي تحددها، أو جهات CA الخاصة بهذا الكمبيوتر.
- **خوادم صور Incus**، لمنتقيات الصور على [مضيف Incus](/docs/guides/instances/#إنشاء-مثيل): ينزّل Homeport قائمة الصور في الخادم (`streams/v1/images.json`، من `images.linuxcontainers.org` ما لم تختر خادمًا آخر) من هذا الكمبيوتر، ويحتفظ بها عشر دقائق. أما الصور نفسها فينزّلها Incus.
- **مستودعات المخططات وسجلات OCI، عبر helm**، عندما تضيف مستودعًا أو تحدّثه، أو تبحث في المخططات، أو تثبّت مخططًا أو ترقّيه: ينزّل `helm` الفهارس والمخططات من هذا الكمبيوتر، كما يفعل في الطرفية.
- **هذا الموقع، للتحقق من التحديثات**: عند التشغيل وكل 6 ساعات، ينزّل Homeport الملف `updates/latest.json`، وهو ملف صغير يذكر أحدث إصدار. لا يحمل الطلب أي شيء عنك أو عن مضيفاتك أو حاوياتك، لكنه كأي طلب ويب يصل إلى GitHub Pages، التي تستضيف هذا الموقع، من عنوان IP الخاص بك. أوقفه في **الإعدادات ← التحديثات**. أما التحديثات نفسها فتُنزَّل من GitHub Releases، ولا يثبّت Homeport تحديثًا إلا إذا كان موقّعًا بمفتاح التحديث الخاص بـ Homeport. راجع [التحديث](/docs/reference/updating/).

## ما يشغّله Homeport على مضيفاتك

يتحدث Homeport مع محرك المضيف عبر واجهة API الخاصة به، ولا يشغّل أوامر على خادم المضيف إلا لما لا تستطيع تلك الواجهة فعله:

| متى                                                                                  | أين                                             | الأمر                                                                                                |
| ------------------------------------------------------------------------------------ | ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| يرفض خادم مضيف SSH فتح مقبس محركه                                                    | خادم SSH                                        | فحص بصدفة POSIX لمعرفة ما إذا كان المقبس موجودًا وقابلًا للقراءة، وما إذا كان هناك محرك مثبّت        |
| **تشغيل** أو **إيقاف** أو **إعادة التشغيل** لـ [وحدة Quadlet](/docs/guides/quadlet/) | خادم SSH، أو هذا الكمبيوتر لمقبس محلي على Linux | `systemctl [--user] start\|stop\|restart '<unit>.service'`                                           |
| [سجلات حاوية containerd](/docs/hosts/containerd/#السجلات)                            | خادم SSH، أو هذا الكمبيوتر لمقبس محلي على Linux | `tail -n <lines> [-F] -- '<log file>'`، بعد `ls` لمجلد سجل حاوية Kubernetes عندما لا يسمّي CRI الملف |
| [طرفية داخل حاوية containerd](/docs/hosts/containerd/#طرفية-داخل-حاوية)              | خادم SSH، أو هذا الكمبيوتر لمقبس محلي على Linux | `mktemp -d`، و`mkfifo -m 600` لقناتي FIFO في ذلك المجلد، و`cat` عبرهما، ثم `rm -rf` للمجلد           |

تعمل بصلاحيات مستخدم SSH (أو صلاحياتك، على هذا الكمبيوتر) ولا تعمل باستخدام `sudo` أبدًا. يُتحقق من القيم وتوضع بين علامات اقتباس قبل إدخالها في أمر. يمر تثبيت وحدات Quadlet وتحريرها وإزالتها عبر واجهة API الخاصة بـ Podman، التي تكتب الملفات بنفسها. لا يعمل أي شيء على مضيف Incus: تمر وحدة التحكم والطرفيات عبر واجهة API الخاصة بـ Incus. الملفات الوحيدة التي ينشئها Homeport على مضيف هي قناتا FIFO لطرفية containerd، في مجلد مؤقت خاص يُزال عند إغلاق الطرفية.

## ما لا يفعله Homeport أبدًا

- **لا حساب.** لا يوجد ما تشترك فيه.
- **لا قياس عن بُعد ولا تحليلات ولا تقارير أعطال.** عندما تبلّغ عن خطأ، تكون [حزمة التشخيص](/docs/reference/troubleshooting/#تصدير-التشخيص-لتقرير-خطأ) ملفًا تصدّره وتقرؤه وترفقه بنفسك.
- **لا يُثبَّت أي شيء على عناقيدك.** لا يستخدم Homeport سوى Kubernetes API، بصلاحيات بيانات اعتمادك، ولا يغيّر شيئًا دون أن تطلب: كل ما يزيل شيئًا أو يستبدله يسأل أولًا، مع ذكر العنقود.
- **لا يُثبَّت أي شيء على مضيفاتك.** الأوامر الوحيدة التي يشغّلها Homeport على مضيف [مذكورة أعلاه](#ما-يشغّله-homeport-على-مضيفاتك). والحاوية الوحيدة التي يشغّلها Homeport من تلقاء نفسه هي [حاوية مساعدة](/docs/guides/volumes-networks/#الحاوية-المساعدة) قصيرة العمر عندما تفتح وحدة تخزين أو تنسخها احتياطيًا أو تستعيدها أو تستنسخها؛ ليس لها شبكة وتُزال عند انتهائها. ولا تُسحب صورتها إلا بعد موافقتك.
- **لا عمليات تثبيت صامتة.** لا يُثبَّت التحديث إلا عندما تختار **تثبيت وإعادة التشغيل**؛ ولا تُحدَّث حزم Linux إلا بواسطة مدير الحزم لديك.

توضح [سياسة الخصوصية](/privacy/) ما يعنيه ذلك قانونيًا: من المسؤول عن بياناتك، وعلى أي أساس، وكيف تمارس حقوقك.

## السجلات

يكتب Homeport ملف سجل صغيرًا — بضع عشرات من الكيلوبايتات، يُستبدل عند امتلائه — لتشخيص المشكلات. يحتوي على أحداث الاتصال والأخطاء، لا على بيانات اعتمادك أو إخراج الحاويات.

| النظام  | المجلد                                  |
| ------- | --------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/logs/` |
| macOS   | `~/Library/Logs/com.homeport.app/`      |
| Windows | `%LOCALAPPDATA%\com.homeport.app\logs\` |

ليس لدى Homeport قياس عن بُعد ولا تقارير أعطال: لا يغادر السجل كمبيوترك أبدًا ما لم ترسله أنت. للإبلاغ عن خطأ، يحفظ **الإعدادات ← حول ← تصدير التشخيص…** ملف zip فيه ملخّص للإصدارات وهذه السجلات، بعد استبدال كل ما يشبه سرًا (المفاتيح، وكلمات المرور، والرموز، وبيانات الاعتماد في عناوين URL)، وكذلك أسماء مضيفاتك وعناقيدك وعناوينها ما لم تطلب غير ذلك. راجع [تصدير التشخيص](/docs/reference/troubleshooting/#تصدير-التشخيص-لتقرير-خطأ).

## الوثوق بتنزيل

تُبنى الإصدارات بواسطة GitHub Actions من الشيفرة المصدرية العامة. يأتي كل ملف مع مجموع تحقق SHA-256 وشهادة مصدر بناء موقّعة تربطه بالإيداع وسير العمل اللذين بنياه بالضبط. راجع [التحقق من التنزيلات](/docs/reference/verifying/).
