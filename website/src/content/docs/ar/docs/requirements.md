## أنظمة التشغيل

| النظام  | الإصدارات                                                        | البنيات              |
| ------- | ---------------------------------------------------------------- | -------------------- |
| Windows | Windows 10 و11                                                   | x64، ARM64           |
| macOS   | macOS 10.15 Catalina أو أحدث                                     | Apple silicon، Intel |
| Linux   | glibc 2.35 أو أحدث: Ubuntu 22.04 وDebian 12 وFedora 36 وما بعدها | x64، ARM64           |

يستخدم Homeport عارض الويب الخاص بالنظام لرسم نافذته: WebView2 على Windows (مضمَّن في Windows 10 و11)، وWebKit على macOS، وWebKitGTK على Linux (يُثبَّت كتبعية لحزمتي `.deb` و`.rpm`، ومضمَّن في AppImage).

## محرك Docker لإدارته

لا يتضمن Homeport بيئة تشغيل للحاويات. بل يدير محركات Docker تعمل مسبقًا في مكان ما:

- **على هذا الجهاز** — Docker Engine أو Docker Desktop أو Colima أو OrbStack أو Rancher Desktop أو Podman. يعثر عليها Homeport نيابةً عنك؛ راجع [المحركات المحلية](/docs/hosts/local/).
- **على خادم** — يمكن الوصول إليه عبر [SSH](/docs/hosts/ssh/)، أو عبر [TLS أو TCP](/docs/hosts/tls-tcp/).

يعمل أي محرك يتحدث Docker Engine API، بما في ذلك مقبس Podman المتوافق مع Docker.

ويدير أيضًا [containerd](/docs/hosts/containerd/) 1.7 وما بعده مباشرةً، عبر مقبسه على هذا الجهاز أو عبر SSH: مقبس k3s، أو مقبس Docker Engine نفسه، أو خدمة containerd على خادم. يحتاج سحب الصور هناك إلى containerd 2.0 أو أحدث، وتحتاج السجلات والطرفيات إلى أن يكون الوصول إلى المضيف عبر SSH، أو إلى containerd على هذا الكمبيوتر (Linux).

ويدير أيضًا [Incus](/docs/hosts/incus/) 6.0 وما بعده، عبر مقبسه على هذا الجهاز أو عبر SSH، أو عبر HTTPS باستخدام رمز الثقة. تحتاج الآلات الافتراضية إلى المحاكاة الافتراضية للعتاد (`/dev/kvm`) على خادم Incus، وتحتاج الطرفية داخل إحداها إلى `incus-agent` الذي تشغّله صورتها.

على مضيف Podman، يستخدم Homeport أيضًا واجهة API الخاصة بـ Podman: تحتاج [الـ Pods](/docs/guides/podman-pods/) إلى Podman 4.0 أو أحدث، وتُعرض [وحدات Quadlet](/docs/guides/quadlet/) بدءًا من Podman 5.7 وتُثبَّت وتُحرَّر وتُزال بدءًا من 5.8. يحتاج تشغيل وحدة Quadlet وإيقافها إلى أن يكون الوصول إلى المضيف عبر SSH، أو إلى Podman على هذا الكمبيوتر (Linux).

## اختياري: عناقيد Kubernetes

لتصفح [العناقيد](/docs/clusters/)، يحتاج Homeport إلى ملف kubeconfig يصل إليها (الملف الذي يستخدمه `kubectl`، أو ملف تلصقه) وإلى إمكانية الوصول عبر الشبكة إلى خوادم API الخاصة بها. يتحدث Homeport واجهة Kubernetes API بنفسه، لذا لا حاجة إلى `kubectl`.

- **إصدارات Kubernetes**: العناقيد التي تشغّل Kubernetes 1.24 أو أحدث. لا يستخدم Homeport إلا واجهات API المستقرة (`v1` و`apps/v1` و`batch/v1` و`networking.k8s.io/v1`)، وهو مبني على API الإصدار 1.33.
- **مكونات exec الإضافية**: يسمّي ملف kubeconfig السحابي برنامجًا يُشغَّل على هذا الكمبيوتر للحصول على بيانات الاعتماد — [AWS CLI](https://aws.amazon.com/cli/) (الإصدار 2) لـ EKS، و`gke-gcloud-auth-plugin` من Google Cloud CLI لـ GKE، و`kubelogin` لـ AKS. ثبّت البرنامج الذي يسمّيه ملف kubeconfig الخاص بك؛ راجع [مكونات exec الإضافية](/docs/clusters/exec-plugins/).

## اختياري: عناقيد Nomad

لإدارة [عناقيد Nomad](/docs/clusters/nomad/)، يحتاج Homeport إلى إمكانية الوصول عبر الشبكة إلى واجهة HTTP API لوكيل Nomad (المنفذ 4646 افتراضيًا)، وإلى رمز مميز عندما تكون قوائم ACL مفعّلة في العنقود؛ راجع [سياسة ACL](/docs/clusters/nomad/#سياسات-acl) التي يحتاجها. يتحدث Homeport واجهة Nomad API بنفسه، لذا لا حاجة إلى أداة `nomad` CLI، ولا يُثبَّت أي شيء على العنقود.

- **إصدارات Nomad**: Nomad 1.6 أو أحدث. يبدأ **تحرير وتشغيل** من المواصفات المُرسَلة للـ job، والتي يحتفظ بها Nomad بدءًا من 1.6.

## اختياري: سلسلة مفاتيح نظام التشغيل

يشفّر Homeport مفاتيح SSH وشهادات TLS وبيانات اعتماد kubeconfig للعناقيد وبيئات المكدسات وعمليات تسجيل دخول السجلات ومفاتيح النشر والرموز المميزة للمستودعات، بمفتاح يحتفظ به في سلسلة مفاتيح نظام التشغيل:

- **macOS** — Keychain
- **Windows** — Credential Manager
- **Linux** — موفّر Secret Service، مثل GNOME Keyring أو KWallet

بدونها، يعرض Homeport شريط تنبيه ويظل يعمل مع المقابس المحلية وTCP العادي وSSH عبر **ssh-agent**. تحتاج مضيفات TLS، ومضيفات SSH ذات المفاتيح المخزنة، والعناقيد، وبيئات المكدسات، وعمليات تسجيل دخول السجلات، والمستودعات الخاصة، إلى سلسلة المفاتيح؛ وبدونها، تُسحب الصور دون مصادقة ولا يمكن إضافة سوى المستودعات العامة. راجع [الأمان وبياناتك](/docs/reference/security/).

## اختياري: Docker Compose

لنشر [المكدسات المُدارة والمرتبطة والمتزامنة](/docs/guides/stacks/)، يشغّل Homeport الأمر `docker compose` على **هذا** الجهاز — لا على المضيف. ثبّت Docker CLI مع مكوّن Compose الإضافي (يتضمنه Docker Desktop)، أو `docker-compose` v2 المستقل.

بدونه، تظل المكدسات تظهر — بما فيها المكدسات المرتبطة — ويمكن تشغيلها وإيقافها وإزالتها؛ النشر وحده يحتاج إلى Compose. يُظهر **الإعدادات ← هذا الجهاز** ما إذا كان Homeport قد عثر عليه.

لنشر مكدس على [Swarm](/docs/guides/swarm/)، يشغّل Homeport الأمر `docker stack deploy` على هذا الجهاز بدلًا من ذلك، لذا يحتاج إلى الأمر `docker` نفسه (لا يُستخدم مكوّن Compose الإضافي). يتضمنه Docker Desktop؛ وعلى Linux، ثبّت حزمة Docker CLI الخاصة بتوزيعتك (`docker-ce-cli` أو `docker.io` أو `docker`). لا حاجة إلى تشغيل أي محرك هنا.

## اختياري: git

تشغّل [المكدسات المتزامنة](/docs/guides/synced-stacks/) أداة `git` المثبّتة على **هذا** الجهاز لاستنساخ مستودعاتها وجلبها: Git for Windows، أو أدوات سطر الأوامر من Apple (`xcode-select --install`)، أو حزمة `git` الخاصة بتوزيعتك. على Windows، يوجّهها Homeport إلى OpenSSH الخاص بالنظام لمستودعات SSH. تعمل كل الميزات الأخرى دون git؛ ويُظهر **الإعدادات ← هذا الجهاز** ما إذا كان Homeport قد عثر عليها.

## اختياري: Helm

لإدارة [إصدارات Helm](/docs/clusters/helm/) على عنقود، يشغّل Homeport الأمر `helm`، الإصدار 3 أو أحدث، على **هذا** الجهاز. يوجّه helm إلى العنقود عبر اتصال خاص، فلا تُكتب أي بيانات اعتماد للعنقود على القرص، ويستخدم helm مستودعات المخططات الخاصة به، كما في الطرفية. ثبّته باستخدام `brew install helm` (macOS)، أو `winget install Helm.Helm` أو Chocolatey أو Scoop (Windows)، أو `snap install helm --classic` أو حزمة توزيعتك أو السكربت من [helm.sh](https://helm.sh/docs/intro/install/) (Linux). تعمل كل صفحات العنقود الأخرى بدونه؛ ويُظهر **الإعدادات ← هذا الجهاز** ما إذا كان Homeport قد عثر عليه.

## اختياري: علبة النظام

يضع Homeport أيقونة في علبة النظام (شريط القوائم على macOS، ومنطقة الإشعارات على Windows) تسرد كل مضيف مع حالته. تتوفر العلبة دائمًا على Windows وmacOS. أما على Linux فتحتاج إلى مكتبة **appindicator**: يتضمنها AppImage، وتوصي بها حزمتا `.deb` و`.rpm`، لذا يثبّتها `apt` و`dnf` و`zypper` ما لم تكن قد عطّلت الحزم الموصى بها. وإلا فثبّت `libayatana-appindicator3-1` (Debian وUbuntu وopenSUSE) أو `libayatana-appindicator-gtk3` (Fedora). تخفي بعض بيئات سطح المكتب أيقونات العلبة — لا يعرضها GNOME إلا مع إضافة مثل AppIndicator Support. بدون علبة، يعمل Homeport من نافذته، وإغلاق النافذة يُنهيه.
