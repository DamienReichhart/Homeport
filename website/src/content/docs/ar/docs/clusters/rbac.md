تُظهر **RBAC**، في الشريط الجانبي لعنقود Kubernetes، من يستطيع فعل ماذا على العنقود. الصفحة للقراءة فقط: لا ينشئ Homeport كائنات RBAC ولا يغيّرها ولا يحذفها (ما زال بإمكانك تحريرها بصيغة YAML من [موارد API](/docs/clusters/api-resources/)).

وكبقية الصفحات، تتبع منتقي Namespace: عند اختيار Namespace تعرض Roles وRoleBindings الخاصة به، إضافةً إلى ClusterRoles وClusterRoleBindings التي تنطبق في كل مكان.

## Roles

تسرد **Roles** الـ Roles (كلٌّ في Namespace الخاص به) والـ ClusterRoles مع عدد قواعد كل منها. افتح أحدها لترى صفحته:

- **قواعده** كما يكتبها Kubernetes: الموارد، ومجموعات API (`core` للمجموعة الأساسية)، وأسماء الموارد والأفعال، أو عناوين URL غير الموارد مثل `/healthz`؛
- **عمليات الربط التي تستخدمه**، كلٌّ منها مع روابط إلى جهاته.

يحمل ClusterRole الموسوم بـ **مجمّع** قاعدة `aggregationRule`: تعرض صفحته محدّدات التسميات الخاصة به، والـ ClusterRoles التي تطابقها، وتتضمن قواعده قواعدها. هكذا بُنيت `admin` و`edit` و`view` الخاصة بـ Kubernetes، لذا يظهر في `edit` الـ ClusterRole الخاص بـ CRD يحمل التسمية `rbac.authorization.k8s.io/aggregate-to-edit: "true"`.

## Bindings

تسرد **Bindings** الـ RoleBindings والـ ClusterRoleBindings، كلٌّ منها مع الدور الذي يمنحه (مع رابط) والجهات التي يسمّيها: Users وGroups وServiceAccounts. تُوسم عملية الربط التي لا يوجد دورها بـ **غير موجود**؛ وهي لا تمنح شيئًا.

## الجهات

تسرد **الجهات** كل من تسمّيه عملية ربط. افتح User أو Group أو ServiceAccount لترى ما يمكنه فعله، في مصفوفة من الموارد والأفعال مجمّعة حسب مكان انطباقها: **العنقود كله** أولًا، ثم كل Namespace. وتحتها عمليات الربط التي تمنحه ذلك، وكيف: بتسميته مباشرة، أو عبر مجموعة.

يدمج Homeport قواعد كل عملية ربط تنطبق:

- يمنح ClusterRoleBinding الـ ClusterRole الخاص به في كل مكان: في كل Namespace، وعلى الموارد على مستوى العنقود مثل Nodes، وعلى عناوين URL غير الموارد.
- يمنح RoleBinding دوره في Namespace الخاص به فقط، حتى عندما يربط ClusterRole. فـ ServiceAccount المربوط بـ `edit` عبر RoleBinding في `prod` يستطيع التعديل في `prod`، ولا مكان غيره.
- تُحتسب أيضًا عمليات الربط إلى المجموعات التي يضع Kubernetes فيها كل جهة تلقائيًا: يكون ServiceAccount في `system:serviceaccounts` و`system:serviceaccounts:<الـ Namespace الخاص به>` و`system:authenticated`، وهو أيضًا المستخدم `system:serviceaccount:<Namespace>:<الاسم>`؛ ويكون User في `system:authenticated`.
- يعني `*` كل فعل أو مجموعة API أو مورد، و`*/scale` هذا المورد الفرعي لكل مورد، والقاعدة ذات أسماء الموارد لا تنطبق إلا على تلك الكائنات (تعرضها المصفوفة تحت **فقط**). يُحذف السطر الذي يغطيه سطر أوسع.

**هذا عرض تقريبي.** تُحسب صلاحيات الجهة من عمليات الربط التي تستطيع بيانات اعتمادك قراءتها، ولا تُطلب من خادم API، لذا لا تحتاج إلى صلاحية انتحال هوية أحد. وقد يفوتها ما تسمح به مُخوِّلات أخرى، مثل webhook (شائع في العناقيد المُدارة) أو ABAC، والمجموعات التي يمنحها المُصادِق لمستخدم (من مطالبات OIDC أو من منظمة شهادة العميل)، ولا يعرفها إلا خادم API. لتتأكد من بيانات اعتمادك أنت، استخدم **ماذا يمكنني أن أفعل هنا؟**.

عند اختيار Namespace، لا تُقرأ إلا RoleBindings الخاصة به؛ اختر **كل Namespaces** لترى صلاحيات الجهة في كل مكان.

## ماذا يمكنني أن أفعل هنا؟

**ماذا يمكنني أن أفعل هنا؟** هي إجابة خادم API نفسه عن بيانات الاعتماد التي يستخدمها Homeport، في الـ Namespace المختار (الـ Namespace الافتراضي للعنقود مع **كل Namespaces**)، كما يعرضها `kubectl auth can-i --list`. تذكر الصفحة الهوية التي تسجّل بها الدخول والمجموعات التي تنتمي إليها، في العناقيد التي تخبر بذلك (Kubernetes 1.28 وما بعده)، مع رابط إلى صفحة تلك الجهة.

عندما يقول خادم API إن قائمته قد تكون ناقصة — فقد يسمح مُخوِّل مثل webhook بأكثر مما يستطيع سرده — تذكر الصفحة ذلك.

يطرح **هل يمكنني…؟** سؤالًا واحدًا كما يفعل `kubectl auth can-i`: فعلًا وموردًا وNamespace (فارغًا لكل Namespaces)، واختياريًا مجموعة API ومورد فرعي واسم كائن. يمكن أن يكون المورد بصيغة الجمع (`secrets`) أو اسمًا مختصرًا (`deploy`) أو صيغة الجمع مع مجموعته (`deployments.apps`)؛ ويحلّه Homeport كما يفعل kubectl. تأتي الإجابة مع السؤال نفسه كأمر للنسخ، مثل `kubectl auth can-i delete secrets --namespace prod`، الذي يعطي الإجابة نفسها.

عندما لا تستطيع بيانات اعتمادك سرد أي كائنات RBAC، لا تعرض الصفحة إلا **ماذا يمكنني أن أفعل هنا؟**، تحت رسالة تذكر ما رُفض. وعندما يمكن سرد بعضها فقط، مثل RoleBindings دون ClusterRoles، تذكر الصفحة أيها، ولا يشملها ما تعرضه.
