## Nodes

تسرد **Nodes** الأجهزة التي يشغّل العنقود الـ Pods عليها، مع ما إذا كان كل منها **جاهز** (و**الجدولة معطّلة** عندما يكون معزولًا)، وأدواره، وإصدار kubelet، وعنوان IP الداخلي، والنظام الأساسي، ووحدات المعالجة والذاكرة القابلة للتخصيص.

/>

تُعرض وحدات المعالجة بالأنوية (`3.92` لـ `3920m`) والذاكرة بالغيغابايت؛ ويُبلغ Kubernetes عما هو **قابل للتخصيص** للـ Pods، وهو أقل قليلًا مما يملكه الجهاز، لأن kubelet والنظام يحتفظان بجزء منه. عندما يشغّل العنقود metrics-server، يعرض **المعالج المستخدم** و**الذاكرة المستخدمة** ما يستخدمه كل Node منهما ([المعالج والذاكرة](/docs/clusters/metrics/)).

تعرض صفحة الـ Node صورة نظام التشغيل، والنواة، ووقت تشغيل الحاويات، والعناوين، وTaints، والتسميات، وسعته بجانب ما هو قابل للتخصيص للـ Pods؛ ثم **Pods** التي تعمل عليه، في كل Namespaces، و**الشروط** الخاصة به (ضغط الذاكرة والقرص وPID)، و**الأحداث** و**YAML**. وترتبط صفحة الـ Pod بالـ Node الخاص به. مع metrics-server، يرسم تبويب **المقاييس** المعالج والذاكرة للـ Node مقارنةً بالقابل للتخصيص ([المعالج والذاكرة](/docs/clusters/metrics/)).

## الأحداث

<DocScreenshot
  name="cluster-events"
  alt="صفحة «الأحداث»: ثلاثة تحذيرات أولًا (Pod يتراجع، وصورة لا يمكن سحبها، وNode غير جاهز)، ثم الأحداث العادية، كل منها مع كائنه ورسالته وعدده وعمره."
/>

تسرد **الأحداث** ما أبلغ عنه Kubernetes في الـ Namespace المحددة (أو فيها كلها): التحذيرات أولًا، ثم الأحدث، كل منها مع سببه، والكائن الذي يخصه — مرتبطًا بصفحة ذلك الكائن — ورسالته، وعدد مرات حدوثه، ووقت آخر حدوث له. صفِّ حسب **التحذيرات** أو **عادي**، وابحث حسب السبب أو الكائن أو الرسالة. تتحدث القائمة مباشرةً.

يحتفظ Kubernetes بالأحداث لمدة ساعة تقريبًا، لذا فإن القائمة الفارغة أمر طبيعي في عنقود هادئ. وتحتوي صفحة كل كائن أيضًا على علامة التبويب **الأحداث** الخاصة به.

## عندما لا تستطيع بيانات اعتمادك رؤية شيء ما

لا تنتمي Nodes إلى أي Namespace، لذا يتطلب سردها إذنًا على مستوى العنقود كله لا يملكه كثير من المستخدمين. تقول الصفحة حينها «لا تسمح بيانات اعتمادك بسرد nodes.» وتستمر كل الصفحات الأخرى في العمل.
