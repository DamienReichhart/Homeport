يعمل **containerd** تحت k3s وnerdctl وBuildKit وكثير من الخوادم التي لا تحتوي على Docker. يتصل به Homeport مباشرةً، عبر واجهة gRPC API الخاصة به، كما يقرر [ADR 0020](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0020-containerd-over-grpc.md). يحصل مضيف containerd على صفحات خاصة به في الشريط الجانبي: **الحاويات** و**الصور** و**اللقطات** و**مساحات الأسماء**. ولا تُتاح عليه صفحات Docker ولا المكدسات ولا اللوحة.

## إضافة مضيف containerd

اختر **containerd** في الحقل **المحرك** من النموذج. يصل إلى containerd عبر مقبسه فقط، لذا يكون الاتصال **مقبس محلي** أو **SSH**؛ ويظهر TCP وTLS باهتين، لأن containerd لا يقدّم واجهة API الخاصة به عبر الشبكة.

| containerd                        | المقبس                                                              |
| --------------------------------- | ------------------------------------------------------------------- |
| خدمة containerd نفسها             | `/run/containerd/containerd.sock`                                   |
| k3s                               | `/run/k3s/containerd/containerd.sock`                               |
| containerd الخاص بـ Docker Engine | `/run/containerd/containerd.sock`، وحاوياته في مساحة الأسماء `moby` |

على Linux، يسرد **تم العثور عليها على هذا الجهاز** مقبس containerd ومقبس k3s على هذا الكمبيوتر عندما يجيبان. والمقبس الذي لا يحق لك استخدامه بعد يُسرد مع طريقة إصلاح ذلك بدلًا من إضافته.

### السماح لمستخدمك باستخدام المقبس

مقبس containerd ملك للمستخدم root. لاستخدامه كمستخدم آخر، محليًا أو عبر SSH، امنح مجموعةً حق الوصول إليه في `/etc/containerd/config.toml` وأضف المستخدم إلى تلك المجموعة:

```bash
sudo groupadd -f containerd
sudo usermod -aG containerd "$USER"
getent group containerd | cut -d: -f3
```

ضع الرقم الذي يُطبع ضمن `[grpc]` في `/etc/containerd/config.toml`، وأعد تشغيل containerd، وسجّل الدخول مجددًا:

```toml
[grpc]
  gid = 1001
```

```bash
sudo systemctl restart containerd
```

يحتفظ **containerd بدون صلاحيات root** (`containerd-rootless.sh`) بمقبسه داخل مساحة أسماء RootlessKit، حيث لا يستطيع أي شيء خارجها الوصول إليه، ولا حتى Homeport. يوضح Homeport ذلك عندما يعثر عليه؛ استخدم خدمة النظام الخاصة بـ containerd بدلًا منه.

### ما يتيحه كل إصدار وكل اتصال

يتصل Homeport بـ containerd **1.7** وما بعده. يمر السحب عبر خدمة Transfer في containerd، المستقرة بدءًا من **2.0**.

| الإجراء                                             | containerd   | الاتصال                     |
| --------------------------------------------------- | ------------ | --------------------------- |
| مساحات الأسماء، والحاويات والمهام، والصور، واللقطات | 1.7 وما بعده | مقبس محلي أو SSH            |
| سحب صورة                                            | 2.0 وما بعده | مقبس محلي أو SSH            |
| السجلات والطرفية                                    | 1.7 وما بعده | SSH، أو مقبس محلي على Linux |

إذا كان containerd أقدم من أن يتصل به، يبقى المضيف بحالة **إعداد غير صحيح** مع ذكر إصداره؛ وإذا كان أقدم من أن يسحب، يوضح ذلك عند السحب.

## مساحات الأسماء

يعيش كل كائن في containerd داخل **مساحة أسماء**: يستخدم nerdctl `default`، وKubernetes `k8s.io`، وDocker `moby`، وBuildKit `buildkit`. تعرض الصفحات مساحة أسماء واحدة في كل مرة، تُختار تحت مبدّل المضيفات، الذي يسرد كلًا منها مع عدد الحاويات والصور التي تحتويها. يتذكر Homeport الاختيار لكل مضيف بين مرات التشغيل. وإلى أن تختار واحدة، يعرض المضيف `default`، أو مساحة الأسماء الوحيدة التي تحتوي على شيء عندما تكون `default` فارغة، لذا يُفتح مضيف k3s على `k8s.io`.

تُنشئ صفحة **مساحات الأسماء** مساحات أسماء فارغة وتزيل الفارغة منها. يرفض containerd إزالة مساحة أسماء لا تزال تحتوي على أي شيء، ويوضح Homeport ما لا تزال تحتويه: أزل حاوياتها وصورها ولقطاتها أولًا.

## الحاويات والمهام

في containerd، **الحاوية** مجرد بيانات وصفية: صورتها، ومواصفاتها، ولقطتها. أما ما يعمل فهو **مهمتها**. تسرد صفحة **الحاويات** حاويات مساحة الأسماء مع مهامها: **قيد التشغيل**، أو **متوقفة مؤقتًا**، أو **متوقفة** مع رمز الخروج، أو **لا مهمة**. وتذكر كل منها الأداة التي أنشأتها — **Kubernetes** (مع الـ Pod الخاص بها)، أو **nerdctl**، أو **Docker**، أو **ctr أو غيره** — وتُخفى حاويات pause الخاصة بالـ Pods ما لم تطلب عرضها.

| الإجراء         | ما يفعله Homeport                                                                                                                                                                                                                       |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **تشغيل**       | ينشئ المهمة على لقطة الحاوية، مع تسجيل الإخراج حيث يسجّله nerdctl، ويشغّلها. تُستبدل المهمة المتوقفة، كما يتطلب `ctr task start`.                                                                                                       |
| **إيقاف**       | يرسل إشارة الإيقاف الخاصة بالصورة (SIGTERM ما لم تسمِّ الصورة إشارة أخرى)، ثم SIGKILL بعد 10 ثوانٍ. ويُبلَّغ عن أي مهمة لا تزال حية بعد ذلك.                                                                                            |
| **إيقاف مؤقت**  | يجمّد المهمة؛ ويذيبها **استئناف**.                                                                                                                                                                                                      |
| **إرسال إشارة** | يرسل أي إشارة، بالاسم (`SIGHUP`) أو بالرقم، إلى العملية الرئيسية للمهمة.                                                                                                                                                                |
| **إزالة**       | يسأل أولًا؛ ثم ينهي المهمة العاملة، ويزيل المهمة والحاوية، ولقطتها مع الملفات التي غيّرتها، ما لم تُلغِ تحديد **إزالة لقطتها أيضًا**: تُوسم اللقطة المُبقاة بـ `containerd.io/gc.root`، فيحتفظ بها جامع البيانات المهملة في containerd. |

تعرض صفحة الحاوية بيئة تشغيلها ولقطتها وتسمياتها ومواصفات OCI الخاصة بها. لا ينشئ Homeport حاويات على containerd: إذ لا يملك containerd شبكات خاصة به، وهي ما يضيفه nerdctl وCNI.

يدير **kubelet** حاويات Kubernetes: يشغّلها مجددًا بعد إيقافها ويعيد إنشاءها بعد إزالتها. توضح صفحاتها ذلك؛ غيّر الـ Pod على العنقود الخاص به بدلًا من ذلك. إزالة حاوية nerdctl من هنا تترك سجلات nerdctl الخاصة بها (اسمها وشبكتها)، كما يفعل `ctr`؛ والأمر `nerdctl rm` هو الطريقة الأنظف لتلك الحاويات.

## السجلات

لا يحتفظ containerd بأي سجلات: الأداة التي تشغّل المهمة هي التي تقرر أين يذهب إخراجها. تقرأه علامة التبويب **السجلات** من حيث كتبته تلك الأداة:

| أنشأها                 | أين يذهب إخراجها                                                        | ما يعرضه Homeport                        |
| ---------------------- | ----------------------------------------------------------------------- | ---------------------------------------- |
| nerdctl                | ملف سجل JSON في مجلد حالة nerdctl، يُسمّى بتسميات `nerdctl/` الخاصة بها | ذلك الملف، مع المتابعة                   |
| Kubernetes (`k8s.io`)  | `/var/log/pods/<pod>/<container>/N.log`، المذكور في سجل CRI الخاص بها   | ذلك الملف، مع المتابعة                   |
| `ctr` والعملاء الآخرون | حيثما وجّهوه، وعادةً إلى لا مكان                                        | **لا يُسجَّل إخراج هذه الحاوية**، والسبب |

حاويات nerdctl التي تسجّل إلى برنامج تشغيل آخر (journald أو fluentd) تذكر اسمه بدلًا من ذلك. يقرأ Homeport الملف باستخدام `tail` على جهاز المضيف (راجع [أدناه](#what-runs-on-the-host))؛ وعادةً ما تكون ملفات السجل ملكًا للمستخدم root، لذا يجب أن يُسمح لمستخدم SSH بقراءتها.

## طرفية داخل حاوية

تفتح علامة التبويب **تنفيذ** صدفة في حاوية عاملة — bash إذا كانت الصورة تحتويه، وإلا sh — أو الأمر الذي تحدده، بصفة مستخدم رقمي (`uid` أو `uid:gid`) وفي مجلد من اختيارك. يبدأ **الفتح مجددًا** طرفية جديدة بما كتبته.

يأخذ containerd مدخلات العملية ومخرجاتها كمسارات على جهازه. لذا يشغّل Homeport هناك سكربتًا قصيرًا ينشئ قناتي FIFO في مجلد مؤقت خاص، وينسخ الطرفية عبرهما؛ ويبدأ containerd العملية على قناتي FIFO هاتين، انطلاقًا من مواصفات العملية الخاصة بالحاوية. يؤدي إغلاق علامة التبويب إلى إنهاء العملية وإزالة المجلد.

## الصور

تسرد صفحة **الصور** صور مساحة الأسماء مع منصاتها، والحاويات المنشأة منها، وحجمها لمنصة المضيف، كما يحسبه `ctr images ls`.

يجلب **سحب صورة** صورة عبر containerd نفسه، ثم يفك حزمها لمنصة المضيف في أداة اللقطات الافتراضية، بحيث يستطيع `nerdctl run` استخدامها فورًا. أدخل مرجعًا كاملًا (`ghcr.io/home/app:1.2`) أو مختصرًا (`nginx`، الذي يصبح `docker.io/library/nginx:latest`). تُسحب صورة السجل الخاص باستخدام تسجيل الدخول الخاص به من **الإعدادات ← سجلات الحاويات**، ولا يُرسل إلى containerd إلا عندما يطلبه السجل، ولا يُخزَّن على المضيف أبدًا.

لا يمكن إزالة صورة أُنشئت منها حاوية في مساحة الأسماء؛ أزل الحاويات أولًا. يحرر containerd محتوى الصورة بمجرد ألا يحتفظ بها أي شيء.

## اللقطات

اللقطات هي حيث تذهب مساحة القرص في containerd: طبقات الصور المفكوكة، والطبقة القابلة للكتابة لكل حاوية. تعرض صفحة **اللقطات** لقطات أداة لقطات واحدة (`overlayfs` أولًا، أو أي أداة أخرى حمّلها المضيف) كشجرة حسب الأصل، الأكبر أولًا، مع استخدامها كما يحسبه `ctr snapshot usage` والإجمالي في الأعلى.

تذكر كل لقطة ما يستخدمها: حاوية، عبر لقطتها، أو صورة، عبر طبقاتها. اللقطات التي لا يستخدمها شيء ولا يُبنى عليها شيء — مثل لقطة أُبقيت عند إزالة حاويتها من هنا — يمكن عرضها وحدها باستخدام **غير المستخدمة فقط**، وإزالتها. أما الأخرى فلا يمكن إزالتها من هنا. اللقطة التي لا يشير إليها شيء ولا يسمها شيء كجذر، مثل لقطة يتركها `ctr containers rm --keep-snapshot`، لا تدوم: يزيلها جامع البيانات المهملة في containerd في تشغيله التالي.

## ما يعمل على المضيف

كل ما سبق يمر عبر واجهة API الخاصة بـ containerd، باستثناء السجلات والطرفيات، التي تحتاج إلى ملفات جهاز containerd. لهذه، يشغّل Homeport الأوامر التالية، عبر جلسة SSH التي يحتفظ بها مسبقًا، أو على هذا الكمبيوتر لمقبس محلي على Linux، بصلاحيات مستخدم SSH ودون `sudo` أبدًا:

| من أجل  | الأمر                                                                                                   |
| ------- | ------------------------------------------------------------------------------------------------------- |
| السجلات | `tail -n <lines> [-F] -- '<log file>'`؛ ولحاوية Kubernetes بدون سجل CRI، يُنفَّذ `ls` لمجلد سجلها أولًا |
| طرفية   | `mktemp -d`، و`mkfifo -m 600` لقناتي FIFO في ذلك المجلد، و`cat` عبرهما، و`rm -rf` للمجلد                |

لا يستطيع المقبس المحلي على macOS أو Windows تشغيلها، وعندها توضح السجلات والطرفيات أنها تحتاج إلى SSH. تسرد [صفحة الأمان](/docs/reference/security/#what-homeport-runs-on-your-hosts) كل أمر يشغّله Homeport على مضيف.

## الأحداث

تتحدث الصفحات من أحداث containerd نفسه، في كل مساحات الأسماء: بدء مهمة أو خروجها، وإنشاء حاوية أو صورة أو إزالتها، وتثبيت لقطة. لا يحتفظ containerd بأي سجل لها، لذا لا يُستكمل ما حدث أثناء إغلاق Homeport.
