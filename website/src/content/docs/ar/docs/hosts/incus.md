يشغّل **Incus** حاويات النظام والآلات الافتراضية، أي **المثيلات** الواردة في [الدليل](/docs/guides/instances/). يتصل به Homeport عبر واجهة REST API الخاصة به، كما يقرر [ADR 0021](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0021-incus-over-its-rest-api.md). يحصل مضيف Incus على صفحات خاصة به في الشريط الجانبي: **المثيلات** و**الصور** و**ملفات التعريف** و**التخزين** و**الشبكات**. ولا تُتاح عليه صفحات Docker ولا المكدسات ولا اللوحة.

## إضافة مضيف Incus

اختر **Incus** في الحقل **المحرك** من النموذج، ثم طريقة الوصول إليه:

| الاتصال         | متى                                         | ما يحتاجه                                                        |
| --------------- | ------------------------------------------- | ---------------------------------------------------------------- |
| **مقبس محلي**   | يعمل Incus على هذا الكمبيوتر (Linux)        | أن يكون مستخدمك في مجموعة `incus-admin`، أو `incus` (انظر أدناه) |
| **SSH**         | يعمل Incus على خادم يمكنك تسجيل الدخول إليه | أن يكون مستخدم SSH في مجموعة `incus-admin`، أو `incus`           |
| **TLS** (HTTPS) | يستمع Incus على الشبكة، أو SSH غير مسموح به | رمز الثقة، أو شهادة عميل يثق بها Incus مسبقًا                    |

يظهر **TCP** العادي باهتًا: لا يقدّم Incus واجهة API الخاصة به دون TLS. يتصل Homeport بـ **Incus 6.0** (إصدار الدعم طويل الأمد) وما بعده.

### مقابسه

| المقبس                            | من يحق له استخدامه            | ما يصل إليه                                          |
| --------------------------------- | ----------------------------- | ---------------------------------------------------- |
| `/var/lib/incus/unix.socket`      | مجموعة `incus-admin`          | كل شيء: كل مشروع، وكل مجمّع تخزين، وكل شبكة          |
| `/var/lib/incus/unix.socket.user` | مجموعة `incus` (`incus-user`) | مشروع المستخدم الخاص فقط، الذي يُنشأ عند أول استخدام |

على Linux، يسرد **تم العثور عليها على هذا الجهاز** كليهما عندما يجيبان، والمقيّد منهما باسم **Incus (مقيّد بمشروعك)**. والمقبس الذي لا يحق لك استخدامه بعد يُسرد مع الأمر الذي يصلح ذلك:

```bash
sudo usermod -aG incus-admin "$USER"
```

تُطبَّق تغييرات المجموعات على عمليات تسجيل الدخول الجديدة: سجّل الخروج ثم الدخول مجددًا (أو أعد الاتصال عبر SSH) قبل إضافة المضيف. ويذكر Incus المتوقف الوحدات التي تشغّله:

```bash
sudo systemctl enable --now incus.socket incus.service
```

### عبر HTTPS برمز الثقة

يستمع Incus على الشبكة بمجرد تعيين `core.https_address`. على خادم Incus:

```bash
incus config set core.https_address :8443
incus config trust add homeport
```

يطبع الأمر الثاني **رمز الثقة**: سطرًا واحدًا من الحروف والأرقام. في Homeport، اختر **Incus** و**TLS**، وأبقِ **رمز الثقة**، والصقه. يعرض Homeport ما يقرؤه (الاسم المخصص له، وعناوين الخادم وبصمة شهادته، وموعد انتهاء صلاحيته)، ثم عند **إضافة**:

1. ينشئ شهادة العميل الخاصة به، بمفتاح ECDSA P-384 يُنشأ في الذاكرة؛
2. يجرّب عناوين الرمز بالترتيب، ويحتفظ بأول عنوان تحمل شهادته البصمة التي يذكرها الرمز؛ ويُرفض أي عنوان آخر، مع ذكر البصمتين؛
3. يرسل الرمز مع شهادته، ويتحقق من أن Incus يثق بها الآن.

يظهر المضيف بعد ذلك في `incus config trust list` تحت اسم الرمز. يعمل الرمز مرة واحدة وتنتهي صلاحيته؛ ويُرفض الرمز المستخدم أو الملغى أو المنتهي الصلاحية مع الأمر الذي ينشئ رمزًا جديدًا. لإلغاء وصول Homeport لاحقًا، أزل شهادته من هناك:

```bash
incus config trust list
incus config trust remove <fingerprint>
```

يأخذ **شهادة موجودة** شهادة عميل ومفتاحًا يثق بهما Incus مسبقًا (`incus config trust add-certificate`)، مع شهادة Incus نفسه للوثوق بها (`/var/lib/incus/server.crt`، أو `cluster.crt` في عنقود).

### شهادة الخادم مثبّتة

شهادة Incus موقّعة ذاتيًا، لذا لا توجد جهة CA للتحقق منها مقابلها. يحتفظ Homeport بالشهادة التي وثق بها مع المضيف ولا يقبل بعد ذلك سواها بالضبط، مقارنةً ببصمة SHA-256 الخاصة بها، أيًّا كان العنوان الذي يُوصَل إليه عبره. إذا أُعيد تثبيت Incus أو جُدّدت شهادته، يُرفض المضيف مع البصمة التي كان يتوقعها والبصمة التي تلقاها: تحقق من البصمة الجديدة على الخادم باستخدام `incus info`، ثم أضف المضيف مجددًا برمز جديد. يُخزَّن مفتاح العميل والشهادتان مشفّرة مثل كل سر آخر؛ راجع [الأمان](/docs/reference/security/#شهادات-incus).

## المشاريع

يحتفظ Incus بالمثيلات والصور وملفات التعريف ووحدات التخزين المخصصة والشبكات في **مشاريع**. تعرض الصفحات مشروعًا واحدًا في كل مرة، يُختار تحت مبدّل المضيفات، الذي يسرد كلًا منها مع عدد المثيلات والصور التي يحتويها. يتذكر Homeport الاختيار لكل مضيف بين مرات التشغيل. وإلى أن تختار واحدًا، يعرض المضيف `default`، أو مشروعه الوحيد على المقبس المقيّد. تنتمي مجمّعات التخزين إلى الخادم كله؛ وتُعرض وحدات التخزين فيها للمشروع المحدد.

## الأحداث

تتحدث الصفحات من أحداث دورة الحياة في Incus، في كل المشاريع: بدء مثيل أو إيقافه، والتقاط لقطة، وإضافة صورة، وتغيير ملف تعريف أو شبكة. وتُحفظ أيضًا في صفحة **الأحداث**. لا يحتفظ Incus بأي سجل لها، لذا لا يُستكمل ما حدث أثناء إغلاق Homeport.

أثناء الاتصال، يرسل Homeport إلى Incus الطلب `GET /1.0` كل 15 ثانية. يجعل Incus المتوقف المضيف **يتعذّر الوصول إليه**، ويعيد Homeport الاتصال من تلقاء نفسه عندما يجيب مجددًا.

## ما يفعله Homeport على المضيف

لا يعمل أي شيء على مضيف Incus سوى Incus نفسه: تمر وحدات التحكم والطرفيات عبر مقابس websocket الخاصة بـ Incus، ويُنزّل Incus الصور البعيدة بنفسه. يقرأ Homeport قائمة الصور في خادم صور بعيد من هذا الكمبيوتر، لمنتقيات الصور.
