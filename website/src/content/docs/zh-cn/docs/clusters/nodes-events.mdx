## Node

**Node** 列出集群用来运行 Pod 的机器，显示每台是否**就绪**（被 cordon 时显示**已禁止调度**）、其角色、kubelet 版本、内部 IP、平台以及可分配的 CPU 和内存。

<DocScreenshot
  name="cluster-nodes"
  alt="Node 页面：五个 EKS Node，其中一个未就绪且已禁止调度，显示其 kubelet 版本、内部 IP、平台、CPU 和内存。"
/>

CPU 以核数显示（`3920m` 显示为 `3.92`），内存以 GB 显示；Kubernetes 报告的是**可分配**给 Pod 的量，比机器实际拥有的略少，因为 kubelet 和系统会保留一部分。

Node 的页面显示其操作系统镜像、内核、容器运行时、地址、污点、标签，以及其容量与可分配给 Pod 的量的对比；然后是在其上运行的 **Pod**（涵盖所有 Namespace）、其**条件**（内存、磁盘和 PID 压力）、**事件**和 **YAML**。Pod 的页面会链接到其 Node。

## 事件

<DocScreenshot
  name="cluster-events"
  alt="事件页面：最前面是三条警告（一个 Pod 正在退避重试、一个无法拉取的镜像、一个未就绪的 Node），然后是正常事件，每条都显示其对象、消息、次数和存在时间。"
/>

**事件**列出 Kubernetes 在所选 Namespace（或所有 Namespace）中报告的内容：警告在最前，然后按从新到旧排列，每条都显示其原因、所涉及的对象（链接到该对象的页面）、其消息、发生的次数以及最后一次发生的时间。可以按**警告**或**正常**筛选，并按原因、对象或消息搜索。列表会实时更新。

Kubernetes 只保留事件约一小时，因此在一个安静的集群上列表为空是正常的。每个对象的页面也都有自己的**事件**标签页。

## 当你的凭据看不到某些内容时

Node 不属于任何 Namespace，因此列出它们需要集群范围的权限，而许多用户没有该权限。此时该页面会显示“你的凭据不允许对 nodes 执行‘list’。”，其他所有页面仍能正常使用。
