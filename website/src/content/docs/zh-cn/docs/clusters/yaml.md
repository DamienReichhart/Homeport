title: 应用和编辑 YAML
description: 将清单应用到集群或编辑对象的 YAML，在任何内容发生更改之前查看会改变什么，并使用服务器端应用。
---

对于专门操作未涵盖的一切，有两种方式可以用 YAML 更改集群：用于清单的**应用 YAML**，相当于 `kubectl apply -f`；以及任何对象的 **YAML** 标签页上的**编辑**，相当于 `kubectl edit`。两者都会在任何内容发生更改之前显示将会改变什么。

## 应用 YAML

集群侧边栏中的**应用 YAML** 接受一个或多个清单：粘贴它们，或用**打开文件…**从本机加载一个 `.yaml`、`.yml` 或 `.json` 文件。以 `---` 分隔的多个文档会按顺序一起应用。

没有 namespace 的文档会进入右上角选择的 namespace（选择**所有 Namespace**时，则进入该集群的默认 namespace）。不属于任何 namespace 的对象（例如 Namespace 或 ClusterRole）会忽略它。

1. **预览更改**会通过服务器端试运行询问集群每个文档会做什么：此时还不会发生任何更改。每个文档都会显示为**已创建**、**已更改**或**没有更改**，并附有它将更改的行。
2. **应用**会请你确认（注明集群名称），然后进行应用。

第二次应用同样的清单会报告**没有更改**。在预览之后编辑 YAML，需要先重新预览。

## 编辑对象

每个对象的 **YAML** 标签页都有**编辑**：显示集群中保存的 YAML，不含服务器管理的内容（`managedFields`、`status`、其 `resourceVersion`、uid 和创建时间）。修改后，用**预览更改**查看你更改的那些行，然后选择**应用**。

预览会将你的 YAML 与预览时该对象的状态进行比较，因此在此期间发生的更改会显示在差异中。如果此次编辑更改了另一个工具管理的字段，预览会将其列为冲突，而不是覆盖它。

Secret 不能在 Homeport 中编辑，因为 Homeport 绝不会一次性显示其所有值；事件则由 Kubernetes 自己写入。

## 服务器端应用

Homeport 使用 Kubernetes 的服务器端应用，字段管理器为 `homeport`：集群会记录哪些字段由 Homeport 设置，以及哪些由 `kubectl`、Helm、控制器或其他工具设置，你可以在对象的 `managedFields` 中看到这些信息。

当文档更改了另一个工具管理的字段时——由 `kubectl apply` 设置或由自动扩缩器管理的 `.spec.replicas`——预览会说明是哪些字段以及哪些管理器。请将这些字段排除在外，或者在第二次确认之后选择**仍然应用**：Homeport 会接管这些字段，而另一个工具可能会把它们改回去。

## 文档无法应用时

预览会在原处显示每个文档的问题，在每个文档都能应用之前，**应用**一直处于禁用状态：

- **无效的 YAML**，附有出错的行。
- **未知的 kind**：集群不提供该 `apiVersion` 和 `kind`。自定义资源需要先安装其 CRD。
- **被集群拒绝**：集群校验对每个字段给出的答复，例如缺少必填字段或值的类型错误。
- **无权限**：应用需要对该资源拥有 `patch` 权限（新对象还需要 `create` 权限），并给出用于检查的 `kubectl auth can-i` 命令。
