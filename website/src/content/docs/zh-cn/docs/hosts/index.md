---
title: 主机与连接
description: Homeport 如何连接 Docker Engine、containerd 和 Incus，每种主机状态的含义，以及重新连接的工作方式。
---

**主机**是 Homeport 连接的 Docker Engine、containerd 或 Incus。它有一个名称和一种访问方式。你看到的每个容器、实例、镜像、卷、网络和堆栈都只属于一台主机。

## 连接类型

| 类型           | 访问引擎…                                          | 凭据                                                | 指南                                                            |
| -------------- | -------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------- |
| **本地套接字** | 在本机上，通过套接字或管道                         | 无                                                  | [本地引擎](/docs/hosts/local/)                                  |
| **SSH**        | 在你可以登录的服务器上                             | Homeport 密钥、你自己的密钥或 ssh-agent             | [SSH](/docs/hosts/ssh/)                                         |
| **TLS**        | 通过 `dockerd --tlsverify` 暴露，或 Incus 的 HTTPS | CA 证书、客户端证书和密钥；对于 Incus，则为信任令牌 | [TLS 和 TCP](/docs/hosts/tls-tcp/)、[Incus](/docs/hosts/incus/) |
| **TCP**        | 在受信任的网络上未加密暴露                         | 无                                                  | [TLS 和 TCP](/docs/hosts/tls-tcp/)                              |

对于远程服务器，优先选择 **SSH**：除了 SSH 端口之外无需暴露任何东西，也是最容易安全设置的方式。

## 引擎类型

除了访问方式，每台主机还在表单的**引擎**字段中说明它指向哪种引擎。这决定了侧边栏为该主机显示哪些页面。

| 引擎            | 涵盖范围                                                                 | 页面                                                                                |
| --------------- | ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| **Docker 兼容** | Docker Engine、Docker Desktop、Colima、OrbStack、Rancher Desktop、Podman | 容器、镜像、卷、网络、堆栈、事件；在 Podman 上还有其专属页面                        |
| **containerd**  | containerd 自身的服务、k3s 的、Docker Engine 自带的 containerd           | containerd 的容器、镜像、快照和命名空间；参见 [containerd](/docs/hosts/containerd/) |
| **Incus**       | Incus 6.0 及更高版本：系统容器和虚拟机                                   | 实例、镜像、配置文件、存储和网络；参见 [Incus](/docs/hosts/incus/)                  |

当套接字路径指向 containerd 或 Incus 的套接字时，表单会据此选择引擎。containerd 只能通过其套接字访问（在本机上或通过 SSH），因此 TCP 和 TLS 对它显示为灰色；Incus 可通过其套接字或通过 HTTPS（TLS）访问，因此只有 TCP 显示为灰色。在 Homeport 0.18 之前添加的主机都是 Docker 兼容的，其他设置不变。

**Podman** 是一种 Docker 兼容的引擎，Homeport 每次连接时都会识别它，因为同一个套接字可能会换成另一个产品：此时主机的状态会显示 **Podman** 及其版本，而不是引擎的版本，侧边栏也会添加只有 Podman 才有的页面。所选主机无法显示的页面不会出现在侧边栏中，从链接打开时会说明原因。

属于 Docker Swarm 的主机会显示 **… 的管理节点**或 **… 的工作节点**（… 为其 Swarm），只需将一个管理节点添加为主机，Swarm 就会出现在侧边栏中。主机页面上还有一张 **Swarm** 卡片，用于创建、加入或离开 Swarm。参见 [Swarm](/docs/guides/swarm/)。

## 添加、编辑和删除主机

- 使用侧边栏顶部主机切换器中的**添加主机…**，或“概览”页面上的**添加主机**来**添加**主机。
- 主机切换器中的**管理主机**会列出每台主机及其类型、地址和状态。选择一台即可打开其页面。
- 在主机页面上，你可以修改连接详情并选择**保存**；Homeport 会使用新设置重新连接。主机的连接类型无法更改，请删除后重新添加。
- **已启用**开关可以断开主机连接而不忘记它。已停用的主机在你重新打开开关之前不会重试。
- **删除主机**会忘记该主机、其保存的凭据、其托管堆栈的 compose 定义、其关联堆栈以及其堆栈的部署历史。主机上运行的任何内容都不受影响：容器、镜像和卷保持原样，关联堆栈的文件夹也一样。该主机所管理的 Swarm 中的堆栈属于该 Swarm，会被保留。

主机名称必须唯一，不区分大小写。

## 导入主机

**添加主机**提供两种方式，根据本机上已有的描述一次添加多台主机。每种方式都会打开预览：选择要导入的条目，重命名它们，然后选择**导入**。

- **从 ~/.ssh/config 导入**会添加你的 SSH 配置中列出的服务器，包括其用户、端口、密钥和 `ProxyJump` 堡垒机。参见[从 ~/.ssh/config 导入](/docs/hosts/ssh/#从-sshconfig-导入)。
- **导入 Docker 上下文**会添加 Docker CLI 上下文（`docker context ls`）中的引擎，包括其 TLS 证书。

密钥和证书只在导入时读取一次，并像其他密钥和证书一样加密保存；`~/.ssh` 和 `~/.docker` 都不会被修改。

### Docker 上下文

Homeport 会读取 `~/.docker/contexts`（如果设置了 `$DOCKER_CONFIG`，则读取其下）中的每个上下文，并映射其 Docker 端点：

| 端点                                                        | 变成                                                            |
| ----------------------------------------------------------- | --------------------------------------------------------------- |
| `unix:///…`、`npipe:////./pipe/…`                           | **本地套接字**主机                                              |
| 没有 TLS 文件的 `tcp://host:port`                           | **TCP** 主机                                                    |
| 带有 `ca.pem`、`cert.pem` 和 `key.pem` 的 `tcp://host:port` | **TLS** 主机，包含其证书                                        |
| `ssh://user@host:port`                                      | 使用 ssh-agent 的 **SSH** 主机，套接字为 `/var/run/docker.sock` |

内置的 `default` 上下文不会提供：[本地检测](/docs/hosts/local/)已经会找到本机的引擎。在以下情况下，上下文会显示但无法选择：

- 它设置了 `SkipTLSVerify`，因为 Homeport 总是会检查引擎的证书；
- 其 TLS 文件夹只包含三个文件中的一部分；
- 其端点是其他类型，例如 Kubernetes 端点；
- 已有主机访问同一个引擎。其名称会说明是哪一台。

名称已被某台主机使用的上下文会以 `name (2)` 的形式提供。

## 迁移到另一台计算机

“主机”页面上的**导出**会将你选择的主机保存到一个受口令保护的文件中；在另一台计算机的“主机”页面上使用**导入**打开该文件，即可添加你选择的主机，随时可以连接。如果某台主机的名称在那边已被使用，会建议改为 `name (2)`，你可以重命名或跳过它。关于该文件如何受保护，参见[迁移到另一台计算机](/docs/reference/security/#迁移到另一台计算机)。

## 选择主机

每个资源页面（容器、镜像、卷、网络、堆栈和事件）都显示在**主机切换器**中选中的主机。containerd 主机的页面一次只显示一个命名空间（[在切换器下方](/docs/hosts/containerd/#命名空间)选择），Incus 主机的页面一次只显示一个[项目](/docs/hosts/incus/#项目)。可以在那里切换主机，或在[概览](/docs/guides/overview/)中选择主机的卡片。Homeport 会在每次启动之间记住你的选择。

## 状态

每台主机的名称旁都会显示一个状态。当所选主机未连接时，资源页面会显示其状态，并提供**立即重试**和**打开主机设置**。

| 状态                   | 含义                                                            | 接下来会怎样                                                       |
| ---------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------ |
| **已连接**             | 引擎已响应。会显示其版本，或 Podman、containerd、Incus 的版本。 | Homeport 会持续监视该连接。                                        |
| **正在连接**           | Homeport 正在访问引擎。                                         | —                                                                  |
| **已停用**             | 主机的**已启用**开关已关闭。                                    | 在你打开开关之前不会有任何动作。                                   |
| **无法访问**           | 网络、套接字或引擎没有响应。                                    | 自动重试，每次等待的时间更长。                                     |
| **访问被拒绝**         | SSH 服务器拒绝了密钥、ssh-agent 失败，或 TLS 握手失败。         | 修复原因，然后选择**重新连接**。                                   |
| **服务器密钥未受信任** | 首次 SSH 连接：服务器或堡垒机的密钥需要你批准。                 | 在主机页面上[信任该密钥](/docs/hosts/ssh/#信任服务器的密钥)。 |
| **服务器密钥已更改**   | SSH 服务器提供的密钥与你信任的不同。                            | [先进行调查](/docs/hosts/ssh/#服务器密钥更改时)。      |
| **凭据丢失**           | 保存的凭据无法解密。                                            | [重新输入](/docs/reference/troubleshooting/#凭据丢失)。    |
| **钥匙串不可用**       | 主机需要保存的机密，但没有系统钥匙串。                          | 参见[系统要求](/docs/requirements/#可选系统钥匙串)。      |
| **配置错误**           | 主机设置中有缺失或无效的内容。                                  | 消息会说明是什么；修复后选择**保存**。                             |

## 重新连接

Homeport 启动时会连接每台已启用的主机，每台主机都有自己的连接，因此一台慢速服务器绝不会拖慢另一台。

连接期间，Homeport 会监听引擎的事件流（页面正是这样自动更新的），并每 15 秒检查一次引擎。如果连接中断，主机会变为**无法访问**，Homeport 会在 1 秒后重试，然后是 2、4、8 秒，依此类推，最长每分钟一次。连接成功后等待时间会重置。

只有**无法访问**会自动重试。其他所有问题都需要你处理，然后选择**重新连接**（在主机页面上）或**立即重试**即可立刻再次尝试。

## 事件与实时更新

Homeport 不进行轮询。当引擎报告变化（容器启动、镜像被拉取）时，受影响的页面会在不到一秒内刷新。[事件](/docs/guides/overview/#事件)页面会显示原始事件流。
