Homeport 保存着能打开你的服务器的凭据。本页准确说明它保存了什么，以及如何保存。

## Homeport 保存的内容

所有内容都保存在你用户的应用数据文件夹中的一个 SQLite 数据库 `homeport.db` 里：

| 系统    | 文件夹                                            |
| ------- | ------------------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/`                |
| macOS   | `~/Library/Application Support/com.homeport.app/` |
| Windows | `%APPDATA%\com.homeport.app\`                     |

其中包含：

| 数据                                         | 保存方式 |
| -------------------------------------------- | -------- |
| 主机名称、地址、SSH 用户和套接字路径         | 明文     |
| SSH 公钥和你信任的服务器密钥                 | 明文     |
| SSH 私钥及其口令                             | **加密** |
| TLS CA 证书、客户端证书和密钥                | **加密** |
| Incus 主机的客户端密钥和固定的证书           | **加密** |
| 托管堆栈的 compose 文件                      | 明文     |
| 托管堆栈的环境变量                           | **加密** |
| 关联堆栈的文件夹和 compose 文件路径          | 明文     |
| 部署历史：compose 文件和 profile             | 明文     |
| 部署历史：环境变量                           | **加密** |
| 镜像仓库地址和用户名                         | 明文     |
| 镜像仓库密码和访问令牌                       | **加密** |
| 仓库 URL、部署密钥的公钥部分                 | 明文     |
| 你信任的仓库服务器密钥                       | 明文     |
| 仓库部署密钥和访问令牌                       | **加密** |
| 集群名称、API 服务器 URL 和 Namespace        | 明文     |
| 每个集群的登录方式及其 kubeconfig 上下文     | 明文     |
| 集群 CA、客户端证书和密钥                    | **加密** |
| 集群令牌、密码和 OIDC 令牌                   | **加密** |
| exec 插件的命令、参数和环境变量              | **加密** |
| 你的主题、上次的选择以及每个集群的 Namespace | 明文     |
| 每台主机的引擎事件，用于事件页面             | 明文     |

Homeport 不会从你的引擎复制任何其他内容：容器、镜像、卷和日志都是实时读取的，从不保存，除非你自己下载日志或文件，或备份卷。它保留的引擎事件（哪个容器、镜像、卷或网络发生了什么，以及它们的标签）默认保留 30 天（[设置 → 数据](/docs/guides/settings/#数据)），每台主机最多 10,000 条，并会随其主机一起删除，或通过**清除历史**删除。

### 关联堆栈的文件夹

对于[关联堆栈](/docs/guides/stacks/#关联堆栈)，Homeport 只保存其文件夹和 compose 文件的位置，以及用于判断文件是否变化的文件指纹，从不保存文件副本。它在你打开堆栈时读取 compose 文件，只有在你在其**定义**标签页中选择**保存**时才写入，每个编辑过的文件一步替换，并保留其权限；除非你明确同意，否则它不会覆盖自你打开以来已发生变化的文件。Homeport 从不读写该文件夹的 `.env`：Compose 运行时会自己读取它。忘记关联堆栈从不会影响该文件夹。

### 仓库

对于[同步堆栈](/docs/guides/synced-stacks/)，Homeport 会保存每个仓库的 URL，以及它为该仓库生成的部署密钥（私钥部分加密），或者你的用户名和访问令牌（加密）。仓库的内容不属于机密：其克隆位于 `homeport.db` 旁边的 `repositories` 文件夹中。

### Swarm

Homeport 不保存关于 [Swarm](/docs/guides/swarm/) 的任何信息：每次连接时，它都通过管理节点主机找到 Swarm。Swarm 机密的值会发送给 Swarm，不会由 Homeport 保留：你输入或从文件加载的值只会发送给引擎一次，从不写入 `homeport.db`、文件或日志，并在对话框关闭时从内存中丢弃。引擎从不会返回机密的值，因此 Homeport 也无法显示它。加入令牌在你需要时从管理节点获取，从不保存或记录到日志。

### 集群

[集群](/docs/clusters/)的凭据来自你的 kubeconfig，并且只以加密形式保存，与 SSH 密钥一样；kubeconfig 引用的文件只读取一次并内联保存，粘贴的 kubeconfig 从不会写入文件，你的 kubeconfig 也从不会被修改。[exec 插件](/docs/clusters/exec-plugins/)以你的身份在本机上运行，它输出的令牌或证书只保存在内存中，直到过期。Homeport 不保存关于集群上运行内容的任何其他信息：Pod、工作负载和其余内容都是实时读取的。[端口转发](/docs/clusters/port-forward/)只在本机的回环地址（`127.0.0.1` 和 `::1`）上监听，因此你网络上的其他任何东西都无法使用它们，并且它们会在 Homeport 退出时结束。通过[应用 YAML 或编辑](/docs/clusters/yaml/)所做的更改，会以字段管理器 `homeport` 记录在集群上。

[Helm](/docs/clusters/helm/) 会在不使用你的 kubeconfig、也不将任何集群凭据写入磁盘的情况下，对集群运行你的 `helm` CLI：对于每条命令，Homeport 会在本机的回环地址（`127.0.0.1`，随机端口）上打开一个私有连接，只接受携带随机令牌的请求，并给 helm 一个只有你可以读取的临时 kubeconfig，其中只包含该令牌。Homeport 会在每个请求转发途中加上集群自己的凭据，并在命令结束时删除该 kubeconfig 并关闭连接。Chart 的 values 通过标准输入传给 helm，从不写入文件。helm 自己的 Chart 仓库、镜像仓库登录信息和缓存仍归 helm 所有，与在终端中一样；Homeport 只添加公开仓库，不保存任何仓库密码。

[Nomad 集群](/docs/clusters/nomad/)的 ACL 令牌、CA 证书、客户端证书和密钥只以加密形式保存，与 SSH 密钥一样；其地址、区域和 TLS 服务器名称以明文保存。令牌通过每个请求的 `X-Nomad-Token` 请求头传输，从不出现在 URL 中，shell 的 WebSocket 也是如此。Homeport 不保存 job 规范的副本：Nomad 会将其与 job 一起保存。

**Kubernetes Secret 的值**只有在你为某个键选择**显示**时才会获取，每次一个：列表、Secret 的页面及其 YAML 只包含其键和大小，从不包含其值。显示出来的值只保留在该页面的内存中（不在任何缓存、`homeport.db` 或日志中），并会在你离开该页面时再次隐藏。

## 机密如何加密

- 每个机密都使用 **XChaCha20-Poly1305**（一种认证加密算法）单独加密，因此既能防止读取，也能检测篡改。
- 256 位密钥是随机的，在首次启动时创建，并以服务名 `com.homeport.app` 保存在你的**系统钥匙串**中（macOS 钥匙串、Windows 凭据管理器或 Linux 上的 Secret Service）。它从不与数据保存在一起。
- 没有主密码：钥匙串已经将该密钥与你的用户账户绑定。

仅拥有 `homeport.db` 副本的人可以读取主机和集群的名称及地址，但无法读取你的密钥、证书、令牌、堆栈环境变量或镜像仓库密码。

### 没有钥匙串时

Homeport 会显示一条横幅，并且不会保存机密。本地套接字、TCP 和 ssh-agent 主机仍可使用。参见[系统要求](/docs/requirements/#可选系统钥匙串)。

### 如果钥匙串中的密钥丢失

重置钥匙串，或将 `homeport.db` 移到另一台计算机或另一个用户下，会导致机密无法解密。Homeport 不会删除任何东西：受影响的主机会显示**凭据丢失**，直到你重新输入其凭据。参见[故障排除](/docs/reference/troubleshooting/#凭据丢失)。要迁移你的数据，请改为备份数据或导出主机。

### 迁移到另一台计算机

“主机”页面上的**导出**会将你选择的主机连同其密钥、证书和已信任的服务器密钥写入一个文件，并使用你选择的口令加密：

- 整个文件都经过加密（XChaCha20-Poly1305，密钥由 Argon2id 从口令派生），因此没有口令就什么也看不到，连主机名称或地址也看不到。对文件的任何改动都会使其无法读取。
- 口令至少需要 12 个字符。Homeport 从不保存它，也不会记录到日志；如果你丢失了口令，该文件就无法打开。
- 在另一台计算机上，**导入**会要求输入口令，然后像其他机密一样，使用那台计算机自己的钥匙串密钥加密保存每台主机的机密。
- 在本机上凭据已经丢失的主机会在不含凭据的情况下导出，导出时会说明是哪些主机。

请像对待其中的密钥一样对待该文件：导入后删除它。文件格式在 [ADR 0013](https://github.com/DamienReichhart/Homeport/blob/main/docs/adr/0013-passphrase-protected-export-bundles.md) 中有说明。

### 备份

**设置 → 数据 → 备份…**会将上述所有内容（主机、集群、堆栈、镜像仓库登录信息、仓库和设置，连同已解密的机密）以相同的加密格式写入一个文件，口令需要输入两次。引擎事件和部署历史不包含在内。无法在本机上解密的机密会被排除，备份时会说明是哪些。

**恢复…**会要求输入口令，并在更改任何内容之前列出文件中的内容。然后，恢复会：

1. 将当前数据库复制到 `homeport.db` 旁边的 `homeport.db.before-restore-<date and time>`；
2. 一步替换每台主机、每个集群、堆栈、登录信息、仓库和设置，因此一旦失败，你的数据会保持原样；
3. 使用本机的钥匙串密钥重新加密每个机密。

由更新版本的 Homeport 制作的备份会被拒绝；由旧版本制作的备份可以恢复。备份包含 Homeport 拥有的每个机密：请像保管密钥本身一样妥善保管它及其口令。

## 密钥从不以明文落盘

Homeport 有自己的 SSH 客户端，因此它从不会将私钥写入文件供 `ssh` 读取，也从不修改 `~/.ssh`。解密后的密钥只保留在内存中。

当 `docker compose` 将堆栈部署到 SSH 或 TLS 主机时，Homeport 会在本机上打开一个短期的私有套接字（只有你的用户可以读取；在 Windows 上则是拒绝远程客户端的命名管道），并通过它自己的连接为那一条命令转发它。

仓库密钥和令牌同样从不落盘。对于每条 `git` 命令，Homeport 会提供一个只持有该仓库部署密钥的私有 SSH agent（位于只有你的用户可以打开的套接字上；在 Windows 上则是拒绝远程客户端的命名管道），或者通过命令的环境变量在 HTTPS 请求头中传递令牌。你自己的 git 配置、凭据助手和 SSH 密钥都不会被使用，因此不会有任何内容缓存到你的钥匙串或 `~/.git-credentials` 中。

镜像仓库登录信息也从不会传给 `docker compose`：Homeport 在运行 `docker compose up` 之前，会通过 Engine API 自己拉取堆栈的镜像，因此该命令的环境变量和传给它的文件中都不包含任何密码或令牌。

## 信任服务器

Homeport 首次连接 SSH 服务器时，会要求你确认服务器的密钥指纹；之后如果该密钥发生变化，它会拒绝连接，直到你再次确认。TLS 主机会根据你的 CA 和服务器名称验证服务器证书；通过 HTTPS 连接的 Incus 主机只接受添加时使用的证书。参见 [SSH 主机](/docs/hosts/ssh/#首次连接)。

### Incus 证书

[通过 HTTPS 添加 Incus 主机](/docs/hosts/incus/#通过-https-使用信任令牌)时，会在内存中生成客户端证书及其私钥（ECDSA P-384 密钥），并与主机的其他机密一起加密保存，从不以明文写入磁盘。Incus 自己的证书也以同样方式保存并被固定：Homeport 只接受来自服务器的这一个证书（按其 SHA-256 指纹比较），并拒绝不同的证书，同时显示两个指纹。信任令牌只使用一次，不会保留。要撤销访问权限，请在服务器上使用 `incus config trust remove` 删除 Homeport 的证书。

## Homeport 连接的对象

- **你添加的主机。** 当你拉取、推送或构建镜像时，联系镜像仓库的是引擎，而不是 Homeport。Homeport 会通过主机的连接，随请求将该镜像仓库保存的登录信息交给引擎；引擎不会保留它。
- **你的镜像所在的镜像仓库，通过每台主机的引擎**，用于判断是否发布了[更新的镜像](/docs/guides/containers/#新版镜像)：在加载容器、镜像或堆栈页面时（每个答案保留 6 小时），以及你选择**检查新版镜像**时。引擎会向镜像仓库询问某个标签指向的摘要，对于私有镜像仓库会使用保存的登录信息，并且不会下载任何东西。对于本地主机，引擎在你的计算机上运行，因此请求从你的计算机发出。
- **Docker Hub，当你在拉取对话框中浏览标签时**：Homeport 从本机访问 `hub.docker.com` 列出仓库的标签，如果保存了 Docker Hub 登录信息，则会使用它。搜索仓库则通过主机的引擎进行。
- **镜像仓库，当你在设置 → 镜像仓库中检查其登录信息时**：Homeport 从本机访问该镜像仓库的 `/v2/` 端点及其令牌服务，通过 HTTPS 发送用户名和密码或令牌（只有本机上的镜像仓库，例如 `localhost:5000`，才使用普通 HTTP）。
- **你的仓库所在的服务器**，用于[同步堆栈](/docs/guides/synced-stacks/)：当你测试访问、创建或同步同步堆栈时，以及开启轮询时在 Homeport 打开期间按间隔访问。Homeport 从本机使用该仓库的部署密钥或令牌运行 `git`。
- **你添加的集群**，通过其 kubeconfig 指定的 Kubernetes API 服务器（以及其代理，如果有的话），使用 kubeconfig 提供的凭据，并根据 kubeconfig 的 CA 检查服务器证书。exec 插件会从本机联系它们自己的云服务（AWS、Google Cloud、Azure），与在 `kubectl` 中一样。
- **你添加的 Nomad 集群**，只通过你提供的 agent 地址，不连接其他任何地方：job 的日志和 shell 都经过该 agent，由它转发到 client node，因此 Homeport 从不直接连接节点。agent 的证书会根据你提供的 CA 或本机的 CA 进行检查。
- **Incus 镜像服务器**，用于 [Incus 主机](/docs/guides/instances/#创建实例)上的镜像选择器：Homeport 从本机下载服务器的镜像列表（`streams/v1/images.json`，除非你选择其他服务器，否则来自 `images.linuxcontainers.org`），并保留十分钟。镜像本身由 Incus 下载。
- **Chart 仓库和 OCI 镜像仓库，通过 helm**：当你添加或更新仓库、搜索 chart，或安装或升级 chart 时，`helm` 会从本机下载索引和 chart，与在终端中一样。
- **本网站，用于检查更新**：在启动时以及每 6 小时，Homeport 会下载 `updates/latest.json`，这是一个列出最新版本的小文件。该请求不携带任何关于你、你的主机或你的容器的信息，但与任何网络请求一样，它会从你的 IP 地址到达托管本网站的 GitHub Pages。可以在**设置 → 更新**中关闭它。更新本身从 GitHub Releases 下载，Homeport 只会安装使用 Homeport 更新密钥签名的更新。参见[更新](/docs/reference/updating/)。

## Homeport 在你的主机上运行的内容

Homeport 通过 API 与主机的引擎通信，只有在 API 无法完成某件事时，才会在主机的服务器上运行命令：

| 时机                                                                | 位置                                            | 命令                                                                                                     |
| ------------------------------------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| SSH 主机的服务器拒绝打开其引擎套接字                                | SSH 服务器                                      | 一个 POSIX shell 检查：套接字是否存在且可读，以及是否安装了引擎                                          |
| [Quadlet 单元](/docs/guides/quadlet/)的**启动**、**停止**或**重启** | SSH 服务器，或者对于 Linux 上的本地套接字为本机 | `systemctl [--user] start\|stop\|restart '<unit>.service'`                                               |
| [containerd 容器的日志](/docs/hosts/containerd/#日志)               | SSH 服务器，或者对于 Linux 上的本地套接字为本机 | `tail -n <lines> [-F] -- '<log file>'`；当 CRI 没有指明文件时，先对 Kubernetes 容器的日志文件夹执行 `ls` |
| [containerd 容器中的终端](/docs/hosts/containerd/#容器中的终端)     | SSH 服务器，或者对于 Linux 上的本地套接字为本机 | `mktemp -d`，在该文件夹中用 `mkfifo -m 600` 创建两个 FIFO，通过它们 `cat`，然后 `rm -rf` 该文件夹        |

它们以 SSH 用户的权限（在本机上则是你的权限）运行，从不使用 `sudo`。值在放入命令之前都会经过检查和加引号处理。Quadlet 单元的安装、编辑和删除通过 Podman 的 API 进行，由 Podman 自己写入文件。Incus 主机上不运行任何东西：其控制台和终端通过 Incus 自己的 API 进行。Homeport 在主机上创建的唯一文件是 containerd 终端的两个 FIFO，位于私有临时文件夹中，终端关闭时会被删除。

## Homeport 从不做的事情

- **没有账户。** 无需注册任何东西。
- **没有遥测、分析或崩溃报告。**
- **不在你的集群上安装任何东西。** Homeport 只使用 Kubernetes API，只拥有你的凭据的权限，并且在你没有要求的情况下不做任何更改：任何删除或替换操作都会先询问，并写明集群名称。
- **不在你的主机上安装任何东西。** Homeport 在主机上运行的命令只有[上面列出的那些](#homeport-在你的主机上运行的内容)。Homeport 唯一会自行启动的容器，是在你打开、备份、恢复或克隆卷时使用的短期[辅助容器](/docs/guides/volumes-networks/#辅助容器)；它没有网络，完成后即被删除。其镜像只有在你同意后才会拉取。
- **没有静默安装。** 只有在你选择**安装并重启**时才会安装更新；Linux 软件包只会由你的包管理器更新。

[隐私政策](/privacy/)从法律角度阐明了这意味着什么：谁对你的数据负责、依据什么，以及如何行使你的权利。

## 日志

Homeport 会写入一个小日志文件（几十 KB，写满时会被替换），用于诊断问题。其中包含连接事件和错误，不包含你的凭据或容器输出。

| 系统    | 文件夹                                  |
| ------- | --------------------------------------- |
| Linux   | `~/.local/share/com.homeport.app/logs/` |
| macOS   | `~/Library/Logs/com.homeport.app/`      |
| Windows | `%LOCALAPPDATA%\com.homeport.app\logs\` |

## 信任下载

发布由 GitHub Actions 从公开源代码构建。每个文件都附有 SHA-256 校验和以及经过签名的构建来源证明，将其与构建它的确切提交和工作流绑定。参见[验证下载](/docs/reference/verifying/)。
