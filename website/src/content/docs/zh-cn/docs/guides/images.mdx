**镜像**页面列出所选主机上存储的镜像及其总大小。

<DocScreenshot name="images" alt="镜像页面，列出镜像及其大小和是否正在使用。" />

| 列           | 显示内容                                                        |
| ------------ | --------------------------------------------------------------- |
| **名称**     | 第一个标签，以及还有多少个其他标签；无标签的镜像显示 `<none>`。 |
| **ID**       | 镜像的短 ID。                                                   |
| **创建时间** | 镜像是多久之前构建的。                                          |
| **大小**     | 它在磁盘上的大小。                                              |
| **状态**     | **使用中**及从它创建的容器数量，或**未使用**。                  |

已停止的容器也算作在使用镜像。选择列标题可排序，并可通过**搜索镜像**进行搜索。

名称旁的 ⬆ 表示镜像的某个标签在其镜像仓库中指向一个更新的镜像；将鼠标悬停在上面可查看是哪一个。拉取该标签即可获取它。**检查新版镜像**会重新询问镜像仓库，而不是使用缓存 6 小时的结果。检查的工作方式请参阅[新版镜像](/docs/guides/containers/#newer-images)。

## 拉取镜像

选择**拉取镜像**并输入引用：`nginx`（即 `nginx:latest`）、`nginx:1.27`、`ghcr.io/org/app:v2`、`registry.example.com:5000/app`，或者摘要，例如 `app@sha256:…`。

Homeport 会逐层显示拉取进度，完成时显示**完成。** **取消**会停止跟踪拉取。

### 搜索 Docker Hub

输入不带其他部分的名称（例如 `postg`）时，会边输入边搜索 Docker Hub，并列出匹配的仓库及其描述、星数和**官方**标记。选择一个即可查看其标签，最新的排在前面，并显示大小和推送时间；**筛选标签**可缩小列表（`alpine`），**更多标签**会加载下一页。选择一个标签会填入引用（例如 `postgres:17-alpine`），随后即可**拉取**。

搜索在所选主机上运行，因此它与拉取一样通过主机的网络访问 Docker Hub。标签由本机从 Docker Hub 读取；保存 Docker Hub 的[登录](/docs/guides/settings/#registries)可以提高其速率限制。输入标签、摘要或其他镜像仓库（`ghcr.io/…`）时会跳过搜索；如果无法访问 Docker Hub，对话框会说明这一点，但仍会拉取你输入的内容。暂时还不能搜索其他镜像仓库。

### 私有镜像

如果在[**设置 → 镜像仓库**](/docs/guides/settings/#registries)中保存了该镜像所在镜像仓库的登录信息，Homeport 会在拉取时将其交给引擎，因此私有镜像可以在任何主机上拉取（本地、TCP、TLS 或 SSH），无需在主机上进行任何配置。对话框会在引用下方说明镜像将如何拉取：**已在 ghcr.io 上以 alice 身份拉取**，或在没有匹配的登录时显示**已匿名拉取**。

名称中不含镜像仓库的镜像（`nginx`、`bitnami/redis`）使用 Docker Hub 的登录。Docker Hub 登录还会提高 Docker Hub 的拉取限制。

如果镜像仓库拒绝拉取，消息会说明该怎么做：如果没有保存登录信息，就为该镜像仓库添加一个；否则检查已保存的登录。

<Aside>
  登录信息随请求一起发送给引擎，不会保存在主机上。Homeport 不会从 `~/.docker/config.json` 读取
  `docker login` 的凭据。
</Aside>

## 构建镜像

选择**构建**，并选择本机上包含 Dockerfile 的**文件夹**，即构建上下文。Homeport 会打包该文件夹，排除其 `.dockerignore` 排除的所有内容（遵循 Docker 的规则：`*`、`**`、`!` 例外，最后一条匹配的行生效），并将其流式传输到所选主机，由该主机的引擎进行构建。同样的构建也可以通过 SSH 或 TLS 在远程主机上进行，无需在那里安装任何东西。

| 字段                   | 作用                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------- |
| **Dockerfile**         | 它在文件夹中的路径；默认为 `Dockerfile`。即使 `.dockerignore` 列出了它，它也总会被发送。 |
| **目标阶段**           | 多阶段 Dockerfile 中要停止的阶段（`--target`）。                                         |
| **名称**               | 结果的一个或多个名称，例如 `app:1.0, ghcr.io/me/app:1.0`。                               |
| **构建参数**           | `NAME=value`，每行一个，用于 Dockerfile 中的 `ARG`。                                     |
| **不使用构建缓存**     | 重新运行每个步骤（`--no-cache`）。                                                       |
| **拉取更新的基础镜像** | 即使主机已有 `FROM` 镜像也重新拉取（`--pull`）。                                         |

构建的输出会实时显示；**取消**会停止构建。完成后，这些名称会出现在“镜像”页面上。如果某个步骤失败，消息会指出它（**构建在第 3/5 步（RUN make）失败。**），**详细信息**中包含输出的末尾部分。私有的 `FROM` 镜像会使用你保存的[镜像仓库登录](/docs/guides/settings/#registries)拉取。

<Aside>
  Homeport 使用引擎的经典构建器，即其 API 提供的那个。`RUN --mount` 和构建机密等 BuildKit
  功能不可用；请在终端中构建这类镜像。
</Aside>

### 改为提交容器

镜像也可以来自容器：容器 **⋮** 菜单中的**提交为镜像…**会将其文件和设置按当前状态保存下来，请参阅[提交容器](/docs/guides/containers/#committing-a-container)。这是保留某人在正在运行的容器中安装或更改的内容的快捷方式。构建则是长久之计：它的 Dockerfile 说明了镜像的制作方式，因此可以在基础镜像更新时重新构建、审查和更新。提交得到的镜像做不到这一点。

## 推送镜像

在镜像的 **⋮** 菜单中选择**推送**。**要推送的名称**初始为镜像的第一个名称；可以选择它的其他名称，或输入一个新名称，例如 `ghcr.io/org/app:v2`，镜像会先被加上该名称，与**标记**相同。名称的第一部分决定推送到哪个镜像仓库：`ghcr.io/org/app` 推送到 GHCR，`org/app` 推送到 Docker Hub。

Homeport 通过主机的引擎推送，并使用为该镜像仓库保存的[镜像仓库登录](/docs/guides/settings/#registries)，在名称下方说明使用的是哪一个（**已在 ghcr.io 上以 alice 身份推送**）。没有保存登录时，对话框会在开始前发出警告，因为大多数镜像仓库会拒绝匿名推送。推送过程中，对话框会统计已推送的层和镜像仓库中已存在的层，并显示上传进度；**取消**会停止推送。

如果镜像仓库拒绝推送，消息会说明是需要添加登录，还是需要检查已保存的登录是否有权推送到该仓库。

## 保存和加载镜像

要将镜像转移到无法访问镜像仓库的主机（物理隔离的服务器、家庭网络中的 Raspberry Pi），请将它们保存到本机上的文件，再将该文件加载到另一个主机中。

- 镜像 **⋮** 菜单中的**保存…**会将镜像连同其所有名称写入你选择的一个 `.tar` 文件。要一次保存多个镜像，请在列表中勾选它们，然后选择页面顶部的**保存 N 个镜像…**。
- 页面顶部的**加载…**会将由**保存…**或 `docker save` 生成的 `.tar`（也包括压缩的 `.tar.gz`）读入所选主机。完成后，对话框会列出加载的镜像及其标签。

文件通过主机自己的连接在本机和主机之间传输，因此这同样适用于远程主机。进度显示已写入或已发送的字节数；**取消**会停止操作，被取消或失败的保存不会留下不完整的文件。Homeport 从不将整个归档保存在内存中，因此几 GB 大小的镜像也没有问题。

### 导入文件系统

页面顶部的**从 tar 导入…**会将根文件系统的 tar 转换为镜像，与 `docker import` 相同：可以是容器的[**导出文件系统…**](/docs/guides/containers/#exporting-a-containers-filesystem)或 `docker export` 生成的 tar、`debootstrap` 或 Buildroot 的输出，或者厂商提供的设备镜像。选择文件（未压缩，或使用 gzip、xz 或 bzip2 压缩），为镜像指定**名称**（初始为文件名），并可选择填写**更改**：Dockerfile 指令，例如 `CMD ["/bin/sh"]` 或 `ENV LANG=C.UTF-8`，因为导入的镜像没有自己的命令。进度显示已发送的字节数；之后镜像会出现在列表中。

### 保存和加载，还是导出和导入？

|      | **保存** / **加载**            | **导出文件系统** / **从 tar 导入**         |
| ---- | ------------------------------ | ------------------------------------------ |
| 起点 | 一个或多个镜像                 | 一个容器当前的文件                         |
| 保留 | 每一层、历史、名称和设置       | 仅文件，扁平化为一层                       |
| 丢失 | 无                             | 历史、名称，以及命令和环境变量等设置       |
| 用途 | 将镜像转移到没有镜像仓库的主机 | 备份或检查容器的文件，或从 rootfs 开始构建 |

## 使用镜像

- **▶ 运行**会打开已填入该镜像的[运行对话框](/docs/guides/containers/#running-a-container)。
- **检查**（或选择该行）会显示**层**（构建每一层的指令及其大小）和**原始 JSON**。
- **标记**会添加另一个名称，例如 `registry.example.com/app:v2`。它不会推送任何东西；**推送**才会。
- **删除**会删除镜像以及没有其他镜像使用的层。有多个标签的镜像会失去所有标签。引擎会拒绝删除仍被容器使用的镜像；请先删除该容器。

## 清理

**清理**提供两个级别：

- **悬空镜像**：构建和拉取遗留下来的无标签镜像。可以安全删除。
- **所有未使用的镜像**：没有任何容器使用的所有镜像，包括有标签的镜像。它们可以重新拉取，但需要花费时间和带宽。

Homeport 会告诉你删除了多少个镜像以及回收了多少空间。[概览的清理](/docs/guides/overview/#cleaning-up)还可以一次性删除已停止的容器、网络、构建缓存和卷。
