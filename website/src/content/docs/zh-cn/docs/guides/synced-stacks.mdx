**同步堆栈**是 compose 文件来自 git 仓库的[堆栈](/docs/guides/stacks/)。Homeport 会在本机上克隆该仓库，在你要求时（或在 Homeport 打开期间按间隔）获取其分支或标签，显示更改内容，并将新提交部署到主机。它从不编辑、提交或推送：更改通过 git 进行。

<Aside type="note" title="Homeport 需要 git">
  同步堆栈使用本机上安装的 `git`。**设置 → 本机**会显示 Homeport
  是否找到了它，如果没有，还会说明如何安装。其他所有类型的堆栈都无需 git 即可使用。
</Aside>

## 仓库

Homeport 读取你在**设置 → 仓库**中或从**新建堆栈**页面添加的仓库。仓库只需添加一次，即可供每个主机上的同步堆栈使用。Homeport 通过以下三种方式之一访问它：

| 访问方式     | URL                                               | Homeport 保存的内容                    |
| ------------ | ------------------------------------------------- | -------------------------------------- |
| **部署密钥** | SSH：`git@github.com:owner/repo.git` 或 `ssh://…` | 仅为此仓库生成的密钥，**加密保存**     |
| **令牌**     | HTTPS：`https://gitlab.com/owner/repo.git`        | 你的用户名，以及**加密保存**的访问令牌 |
| **公开**     | HTTPS，用于任何人都能读取的仓库                   | 不保存任何机密                         |

不接受 `http://` 和本地路径，因此令牌从不会以明文发送。

### 使用部署密钥

<Steps>

1. 选择**添加仓库**，粘贴仓库的 SSH URL，保留**部署密钥**，然后选择**添加并生成部署密钥**。

2. 复制 Homeport 显示的密钥，并将其添加到仓库，**仅授予读取权限**：
   - GitHub：仓库的 **Settings → Deploy keys → Add deploy key**。
   - GitLab：项目的 **Settings → Repository → Deploy keys**。
   - Gitea 和 Forgejo：仓库的 **Settings → Deploy keys → Add deploy key**。

3. 选择**测试访问**。Homeport 会从本机列出仓库的分支和标签。

</Steps>

每个仓库都有自己的密钥，因此泄露的密钥只能读取那一个仓库，并且从不会使用你自己的 SSH 密钥和 `~/.ssh/config`。**新密钥**会替换它：将新密钥添加到仓库，并在那里删除旧密钥。

Homeport 第一次访问某个 SSH 服务器时，会信任该服务器出示的密钥并记住它，与 `ssh` 的做法相同；如果之后密钥发生变化，每次获取都会失败，直到你在代码托管平台的网站上核对新指纹，并选择受信任密钥旁边的**重置**。

### 使用令牌

粘贴仓库的 `https://` URL，选择**令牌**，然后输入用户名以及可以读取仓库内容的访问令牌：在 GitHub 上使用带 **Contents: Read-only** 权限的细粒度令牌，在 GitLab 上使用带 `read_repository` 的项目令牌或个人令牌。**测试访问**会检查它。令牌过期后，在**替换令牌**中输入新的令牌。

<Aside type="tip">
  没有系统钥匙串时，Homeport
  无法保存部署密钥或令牌，因此只能添加公开仓库。请参阅[要求](/docs/requirements/#optional-an-os-keychain)。
</Aside>

删除仓库会删除其密钥或令牌以及它在本机上的克隆。只要有同步堆栈在使用它，删除就会被拒绝。

## 创建同步堆栈

<Steps>

1. 在要部署到的主机上打开**堆栈**，选择**新建堆栈**，然后选择**使用 Git 仓库**。

2. 选择**仓库**，或选择**添加仓库**在此处添加一个。

3. 选择**分支**或**标签**。Homeport 会从仓库的服务器列出它们，默认分支排在最前。

4. 输入**Compose 文件**的路径，相对于仓库的根目录：`compose.yaml` 或 `deploy/prod/compose.yaml`。它所在的文件夹就是项目文件夹，因此其中的 `build:`、`env_file:` 和相对路径会像在你自己的克隆中一样工作。

5. 检查**名称**（它来自仓库的名称），并为不应放入 git 的内容（例如密码）添加**环境变量**：`KEY=value` 行，在本机上加密保存，并在部署时作为变量传给 Compose。

6. 选择**保存并部署**，或选择**保存**以稍后部署。

</Steps>

Homeport 会在保存任何内容之前获取分支或标签并读取 compose 文件，因此错误的路径、分支或标签，或者 Compose 无法部署的文件，都会立即报告。在首次部署之前，该堆栈会列为**同步**和**未部署**；它的**定义**标签页会显示其仓库、分支或标签、compose 文件以及它部署的提交。

仓库只会在本机上克隆一次，位于 Homeport 数据库旁边的 `repositories` 文件夹中，并由从它创建的所有同步堆栈共享。每个同步堆栈从自己对该提交的检出副本进行部署，检出副本位于那里的 `synced-stacks` 文件夹中，在两次部署之间保持不动：容器通过相对绑定挂载写入的文件会留在原处。仓库中的符号链接会被检出为普通文件，因此 compose 文件无法让 Compose 指向本机上其他位置的文件。文件保留仓库中的换行符，在 Windows 上也是如此，因此复制到 Linux 镜像中的脚本仍然可以运行；只有仓库自己的 `.gitattributes` 能够更改它们。

同步堆栈也可以部署到 [Swarm](/docs/guides/swarm/)：在**新建堆栈**的**部署到**下选择它。它会以相同的方式同步、部署和自动部署，并从其检出副本运行 `docker stack deploy`；有哪些不同（首先是 `build:`），请参阅 [Swarm 上的关联堆栈和同步堆栈](/docs/guides/swarm/#linked-and-synced-stacks-on-a-swarm)。

**忘记**会让 Homeport 停止跟踪该仓库。其容器会继续运行，它将成为外部堆栈；除非容器向其检出副本中写入了文件，否则检出副本会被删除，而仓库的克隆会在没有同步堆栈使用它时删除。该仓库仍保留在**设置 → 仓库**中。

## 同步

在同步堆栈所在的行或其页面上选择**同步**。Homeport 会获取其分支或标签，然后在执行任何操作之前显示部署它将会更改的内容：

- 自已部署提交以来、更改了 compose 文件所在文件夹中内容的**新提交**，以及它们的作者和创建时间；
- 该文件夹中每个**已更改的文件**，compose 文件排在最前，被删除的行以删除线显示在替换它们的行上方。不是文本的文件只显示名称，不显示内容。

选择**部署**即可部署该确切提交：Homeport 会在堆栈的检出副本中检出它，并从 compose 文件所在的文件夹运行 `docker compose up`，重新构建带有 `build:` 的服务，因此更改后的 `Dockerfile` 会生效。输出会在运行时实时显示，该次部署会连同其提交一起记录在堆栈的**历史**中。

- 没有更改 compose 文件所在文件夹中任何内容的推送（例如仓库中其他位置的文档）会显示**已是最新**。**仍然重新部署**仍会部署它。
- 如果某个标签现在指向的提交与 Homeport 上次获取时不同，审阅界面会首先说明这一点。
- 如果获取失败（部署密钥被删除、无法访问服务器）或部署失败，Homeport 会显示原因和该怎么做，堆栈会保留其已部署的提交。

**重新部署**会再次部署当前已部署的提交，并会先显示其环境变量或 profile 中的更改。对从未部署过的堆栈选择**部署**，会部署创建时获取的提交。同步堆栈无法从 Homeport 回滚：请在其仓库中撤销更改，或将堆栈指向较早的标签，然后同步。

## 轮询和自动部署

<Aside type="caution" title="仅在 Homeport 打开期间">
  Homeport 只在打开期间检查你的仓库。**关闭期间不会同步任何内容**：你的服务器上没有代理，也没有
  webhook，因为 Homeport 不会在那里安装任何东西。重新打开后，它会等待一个间隔再进行第一次检查。
</Aside>

在 Homeport 打开期间，它会按间隔获取每个同步堆栈的分支或标签：默认每 5 分钟一次，可在**设置 → 同步堆栈**中设置（至少 1 分钟）。无论有多少个堆栈使用某个仓库，每一轮都只获取该仓库一次；持续失败的仓库会被越来越少地重试，最少每小时一次。

当新提交更改了 compose 文件所在的文件夹时，该堆栈会在列表和其页面上显示**有可用更新**。**同步**会显示更改的内容并进行部署。堆栈的**定义**标签页会显示**上次检查**的时间，如果上次检查失败，还会显示原因。

**定义**标签页上有两个开关控制这一行为，按堆栈设置：

- **检查新提交**，默认开启。关闭后，只有在你选择**同步**时才会同步。
- **自动部署新提交**，默认关闭。开启后，Homeport 会在看到每个新提交时立即部署它，**不会先向你显示更改的内容**，步骤与**同步**相同；该次部署会在**历史**中记录为自动部署，完成后会有通知告知。主机无法访问时，它会等待。如果部署失败，Homeport 会显示原因，并且不会再次尝试该提交：下一个提交，或你自己部署的一次**同步**，才会再次部署。

## 为什么不能编辑同步堆栈？

因为它的仓库是其定义所在的唯一位置。如果 Homeport 更改了 compose 文件，下次同步要么会覆盖该更改，要么会与之冲突，而阅读仓库的人也无法知道部署的是什么。因此，同步堆栈的**定义**标签页以**只读**方式显示已获取提交中的 compose 文件（你仍然可以从中选择和复制内容），列出其文件夹中的其他文件，并将每个文件链接到其在 GitHub、GitLab、Gitea 或 Forgejo 上的页面。请在那里更改它们，推送，然后**同步**。

Homeport 确实持有的内容在同一标签页上仍可编辑：

- 它的**环境变量**，在本机上加密保存，用于不应放入 git 的值；
- 它的 **profile**（如果 compose 文件声明了 profile）；
- 是否**检查新提交**以及是否**自动部署新提交**。

**忘记**会让 Homeport 停止跟踪该仓库；堆栈的容器会继续运行，它将成为外部堆栈。
