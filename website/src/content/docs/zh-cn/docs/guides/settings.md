**设置**是侧边栏中的最后一个页面，位于**文档**和 **GitHub** 链接上方，这两个链接会在浏览器中打开。

## 外观

**主题**默认为**跟随系统**，会随操作系统的浅色或深色模式变化。选择**浅色**或**深色**可将其固定。

**语言**默认为**跟随系统**：如果 Homeport 支持操作系统的语言，就以该语言显示，否则显示英语。该选项会写出它找到的语言，例如**跟随系统（简体中文）**。选择一种语言即可改用该语言；整个窗口会立即切换，无需重启，托盘菜单和通知也会一起切换。

Homeport 支持英语、法语（Français）、西班牙语（Español）、德语（Deutsch）、意大利语（Italiano）、巴西葡萄牙语（Português）、俄语（Русский）、简体中文、日语（日本語）、韩语（한국어）、印地语（हिन्दी）和阿拉伯语（العربية），阿拉伯语从右向左显示。地区变体跟随其语言：加拿大法语显示为法语，欧洲葡萄牙语显示为巴西葡萄牙语。繁体中文暂不可用，会显示英语。

日期、数字和大小也跟随语言，如果系统有该语言的地区格式，则使用该格式：英式英语中为 _1.5 GB_ 和 _4 Nov 2026_，法语中为 _1,5 Go_ 和 _4 nov. 2026_。名称、ID、命令、日志以及引擎和集群返回的内容保持原样，错误的**详细信息**会保留出错的系统或库的原始文本，因此错误报告在每种语言中读起来都一样。

## 桌面

Homeport 在本机上的运行方式。

- **关闭时最小化到系统托盘**：默认关闭，因此关闭窗口会退出 Homeport。开启后，关闭窗口会将其隐藏到[系统托盘](/docs/guides/overview/#系统托盘)：Homeport 会继续运行，并保持主机连接。从托盘图标或再次打开 Homeport 即可恢复窗口；从托盘的**退出**退出。在没有托盘的桌面环境中，该开关会变灰并附有说明。
- **登录时启动**：默认关闭。开启后，Homeport 会在你登录时启动，从一开始就监视你的主机。该开关显示系统中的实际状态：如果你自己从登录项中删除了 Homeport，它会显示为关闭。在 Windows 上，它列在**任务管理器 → 启动应用**中；在 macOS 上，列在**系统设置 → 通用 → 登录项**中；在 Linux 上，位于 `~/.config/autostart/` 中。移动 AppImage 文件后，其启动项会在下次打开时跟随该文件。
- **启动时隐藏到托盘**：默认关闭，仅在**登录时启动**开启时可用。Homeport 在登录时启动后，会停留在[系统托盘](/docs/guides/overview/#系统托盘)中而不打开窗口。自己打开 Homeport 时总会显示窗口，没有托盘时也总会打开窗口。

## 通知

当主机上发生某些情况时，无论 Homeport 的窗口是打开、最小化还是[关闭到托盘](#桌面)，它都会显示操作系统的通知。每种通知都有自己的开关，默认全部开启，切换后立即生效：

| 开关                         | 示例                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| **容器因错误停止或内存耗尽** | _web-1 在 prod-server 上已停止（退出代码 137）_、_db 在 … 上内存耗尽_ |
| **容器变为不健康**           | _api 在 prod-server 上不健康_                                         |
| **已连接的主机变为无法访问** | _prod-server 无法访问：…_                                             |
| **无法访问的主机已恢复**     | _prod-server 已重新连接。_                                            |

停止容器（使用 Homeport 中的**停止**、`docker stop`、`docker kill` 或 `docker compose down`）不算崩溃，因此不会显示通知；以代码 0 退出的容器也不会。Homeport 启动时连接失败的主机也不算中断：只有原本已连接的主机才算。卡在重启循环中的容器，或反复断开的主机，最多每 5 分钟通知一次。

通知来自 Homeport 已持有的连接，因此主机上不会安装任何东西，Homeport 退出后通知也会停止。通知的外观以及是否显示由操作系统决定：如果没有出现通知，请检查操作系统中 Homeport 的通知设置。

## 更新

- **自动检查更新**：默认开启。Homeport 会在启动时以及每 6 小时检查一次新版本，有新版本时会在窗口顶部显示一个提示栏。
- **立即检查**：立即检查，即使自动检查已关闭，并告诉你是否已是最新版本。

有可用更新时，卡片会显示你可以执行的操作，这取决于你安装 Homeport 的方式：

- **Windows、macOS 和 AppImage**：**安装并重启**会下载更新、检查其签名、安装并重新打开 Homeport。
- **`.deb` 和 `.rpm` 软件包**：由包管理器安装更新，因此卡片会显示要运行的命令，并附有**复制命令**按钮。

**新功能**会打开[更新日志](/changelog/)。更多信息请参阅[更新](/docs/reference/updating/)。

## 镜像仓库

容器镜像仓库（Docker Hub、GitHub Container Registry（GHCR）或你自己的镜像仓库）的登录信息，在 Homeport 中保存一次即可在每个主机上使用：拉取镜像、从尚不存在的镜像运行容器、推送、构建，或部署托管、关联或同步堆栈时都会用到。每个镜像仓库地址对应一个登录。

- **添加登录**会要求填写**镜像仓库**（`docker.io`、`ghcr.io`、`registry.example.com:5000`）、**用户名**以及**密码或访问令牌**。GHCR 以及启用了双重身份验证的 Docker Hub 帐户需要使用访问令牌而不是密码。
- **检查登录**会从本机询问镜像仓库是否接受该登录，与 `docker login` 相同，但不保存任何内容。被拒绝的登录会说明原因并给出提示；无法访问的镜像仓库则会说明这一点。
- **编辑**可更改地址或用户名；密码留空则保留已保存的密码。**删除**会忘记该登录：之后会再次以匿名方式从该镜像仓库拉取镜像。

Docker Hub 可以输入为 `docker.io`、`index.docker.io` 或 `https://index.docker.io/v1/`；它们是同一个镜像仓库。名称中不含镜像仓库的镜像（例如 `nginx` 或 `bitnami/redis`）使用 Docker Hub 的登录。

密码和令牌使用系统钥匙串的密钥加密，之后不会再显示、记录到日志或写入错误详细信息。没有钥匙串时，卡片会说明无法保存登录信息，镜像将以匿名方式拉取。请参阅[安全](/docs/reference/security/)。

Homeport 不读取 `~/.docker/config.json` 或其凭据助手。

## 仓库

用于部署[同步堆栈](/docs/guides/synced-stacks/)的 git 仓库，保存一次即可在每个主机上使用。

- **添加仓库**会要求填写仓库的 URL 以及 Homeport 访问它的方式：Homeport 为该仓库生成的**部署密钥**（SSH URL）、带用户名的**令牌**（HTTPS URL），或者任何人都能读取的**公开**仓库。
- 齿轮按钮会显示仓库的部署密钥，以及在 GitHub、GitLab、Gitea 和 Forgejo 上添加它的位置，并提供**新密钥**来替换它；或者提供**替换令牌**。**测试访问**会从本机列出它的分支和标签。Homeport 信任某个 SSH 服务器的密钥后，其指纹会显示在那里，并附有**重置**，用于代码托管平台确实更换了密钥的情况。
- **删除**会忘记该仓库并删除它在本机上的克隆；只要有同步堆栈在使用它，删除就会被拒绝。

密钥和令牌使用系统钥匙串的密钥加密，之后不会再显示、记录到日志或写入错误详细信息。Homeport 从不使用你自己的 git 配置、凭据助手和 SSH 密钥。请参阅[仓库](/docs/guides/synced-stacks/#仓库)。

## 同步堆栈

**检查仓库的间隔**设置 Homeport 两次检查同步堆栈的仓库是否有新提交之间等待的分钟数：默认为 5，最少为 1。Homeport 只在打开时检查；关闭时不会同步任何内容。请参阅[轮询和自动部署](/docs/guides/synced-stacks/#轮询和自动部署)。

## 数据

Homeport 在本机上保存的内容。

### 备份和恢复

**备份…**会将每个主机、集群、堆栈、镜像仓库登录、仓库和设置，连同它们的密钥、证书、令牌、密码和环境变量，保存到一个 `.homeport` 文件中。输入两次至少 12 个字符的口令：整个文件都会用它加密，并且口令无法找回。引擎事件和部署历史不包括在内，主机或集群上的任何内容也不包括在内：容器、镜像、卷和 Kubernetes 资源都留在原处。

**恢复…**会用口令打开这样的文件，并列出其中的内容：按名称列出主机和集群，以及堆栈、镜像仓库登录和仓库的数量。然后，**全部替换**会在本机或另一台计算机上用备份中的数据替换 Homeport 的全部数据：

- 所有内容都会立即连接和部署：SSH 和 TLS 主机、镜像仓库和仓库都不会再次要求输入密钥或密码，也不会要求信任服务器的密钥。
- 如果[关联堆栈](/docs/guides/stacks/#关联堆栈)的文件夹不在本机上，它会显示为外部堆栈，直到该文件夹出现在相同路径下。
- [同步堆栈](/docs/guides/synced-stacks/)会在下次同步时重新克隆其仓库。
- 当前数据会先复制到 Homeport 数据文件夹中的 `homeport.db.before-restore-<date>`。恢复错误的文件、较新版本 Homeport 的文件，或中途失败的恢复，都不会更改任何内容。

如果只想把一些主机添加到现有主机中，请使用“主机”页面上的**导出**和**导入**。[数据与备份](/docs/reference/data-and-backups/)说明了 Homeport 的文件在哪里、备份包含什么，以及如何自己复制数据库。

### 保留引擎事件

**引擎事件保留**设置每个主机的[引擎事件](/docs/guides/overview/#事件)保留多少天：默认为 30，范围为 1 到 365。无论此处如何设置，每个主机最多保留 10,000 条事件。较早的事件会在 Homeport 启动时以及每小时清除一次，降低该数值时也会立即清除。

## 本机

Homeport 在本机上可以使用的内容：

- **系统钥匙串**：可以加密保存 SSH 密钥、证书、堆栈环境变量和镜像仓库登录信息时为**可用**；否则为**不可用**。请参阅[要求](/docs/requirements/#可选系统钥匙串)。
- **Compose CLI**：找到的 Compose 版本，例如 `docker compose v2.29.1`；如果堆栈只能启动和停止而无法部署，则为**未找到**。请参阅[堆栈](/docs/guides/stacks/#部署需要什么)。
- **git**：找到的 git，例如 `/usr/bin/git 2.43.0`；如果无法使用同步堆栈，则显示需要安装什么。请参阅[要求](/docs/requirements/#可选git)。
- **Helm CLI**：找到的 helm，例如 `/usr/local/bin/helm v3.16.2`；如果无法列出或安装 [Helm Release](/docs/clusters/helm/)，则显示本系统需要安装什么。Helm 2 会被报告为不受支持。请参阅[要求](/docs/requirements/#可选helm)。

每次打开此页面时，Homeport 都会检查这些 CLI，因此启动后安装的 CLI 也会显示出来；安装钥匙串后，请退出并重新打开 Homeport。

## 关于

显示 Homeport 的版本及其构建所针对的平台，例如 `v1.0.0 · macos/aarch64`。

**打开日志文件夹**会显示 Homeport 写入其[日志](/docs/reference/security/#logs)的位置。

**导出诊断信息…**会保存一个 zip，供你在[报告问题](https://github.com/DamienReichhart/Homeport/issues/new/choose)时附上：其中包含版本以及你所用主机和集群类型的摘要，以及已移除机密的日志。对话框会先显示其中的内容，且不会向任何地方发送任何东西。参见[导出诊断信息](/docs/reference/troubleshooting/#exporting-diagnostics-for-a-bug-report)。

**许可证**显示 Homeport 的许可证（GNU AGPL 第 3 版）、你所运行版本的源代码链接，以及构建它所用的每个开源软件包的声明。
