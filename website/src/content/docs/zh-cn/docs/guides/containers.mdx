**容器**页面列出所选主机上的每个容器，无论是否正在运行。

<DocScreenshot name="containers" alt="容器页面，容器按所属堆栈分组，并显示实时 CPU 和内存。" />

## 列表

属于某个[堆栈](/docs/guides/stacks/)的容器会归入该堆栈下；独立容器排在后面。堆栈所在的行会显示其容器中有多少个正在运行，以及它们合计的 CPU 和内存。选择它可以折叠该组，选择**打开堆栈**可以进入该堆栈。

| 列           | 显示内容                                                                              |
| ------------ | ------------------------------------------------------------------------------------- |
| **名称**     | 状态圆点、名称（在堆栈中为服务名称）和短 ID。                                         |
| **镜像**     | 创建它所用的镜像；如果发布了[新版镜像](#新版镜像)，会带有 ⬆ 标记。                    |
| **状态**     | 与引擎报告的一致，例如 _Up 3 hours (healthy)_；如果有健康检查，还会带有健康状态标记。 |
| **端口**     | 最多三个端口，已发布的端口排在前面。已发布的端口是一个链接，可在浏览器中打开它。      |
| **CPU**      | 实时数据，以单个 CPU 的百分比表示：`200%` 表示两个 CPU 被完全占用。                   |
| **内存**     | 实时数据，不计内核可以回收的页缓存。                                                  |
| **创建时间** | 多久之前创建的。                                                                      |

CPU 和内存每两秒更新一次。**搜索容器**可匹配名称、镜像、堆栈、服务和 ID 前缀；**仅运行中**会隐藏其余容器。

选择一个容器即可打开它。

### 新版镜像

镜像旁的 ⬆ 表示其镜像仓库中，创建该容器时所用的标签下现在有一个不同的镜像：`nginx:1.27` 自拉取以来已经更新，或者已经拉取了更新的镜像但容器没有重新创建。将鼠标悬停在上面可查看是哪一个。要更新，请拉取镜像并重新创建容器；对于堆栈，请先选择**拉取镜像**，再选择**重新部署**。

Homeport 通过主机的引擎询问镜像仓库，引擎会比较摘要而不拉取任何内容，对于私有镜像会使用你保存的[镜像仓库登录](/docs/guides/settings/#镜像仓库)。结果会保留 6 小时，因此再次打开列表时不会重新询问；页面顶部的**检查新版镜像**会立即重新询问所有镜像仓库。本地构建的镜像、按摘要拉取的镜像（`app@sha256:…`）或镜像仓库无法访问的镜像不会显示任何标记，而不是给出错误的提醒。容器的页面会在其镜像旁显示同样的标记。

### 操作

每一行末尾的按钮用于启动或停止容器。**⋮** 菜单中包含其余操作：**日志**、**打开终端**、**重启**、**暂停**或**恢复**、**强制终止**、**重命名**、[**编辑**](#编辑容器)、[**复制**](#复制容器)、[**提交为镜像…**](#提交容器)、[**导出文件系统…**](#导出容器的文件系统)以及**删除**。

勾选多个容器，即可用**启动**、**停止**、**重启**或**删除**一次对它们执行操作。堆栈所在行上的复选框会选择该堆栈的所有容器。

<Aside type="caution" title="“删除”会删除什么">
  删除容器会删除容器本身、其可写层及其匿名卷。命名卷会保留。正在运行的容器会被立即停止，不会等待它正常关闭。
</Aside>

**强制终止**会立即发送 `SIGKILL`，因此进程没有机会进行清理。**停止**会先给它容器的停止超时时间。

## 容器的页面

页头显示镜像和状态，并提供**启动**或**停止**、**重启**、**暂停**或**恢复**以及**删除**；其 **⋮** 菜单中有**重命名**、**编辑**、**复制**、**提交为镜像…**和**导出文件系统…**。下方的标签页包含其他所有内容。

<Aside>
  离开标签页会结束它正在进行的操作：离开 **Exec**
  时终端会关闭，返回**统计**时图表会重新开始，**日志**会重新加载。
</Aside>

### 日志

<DocScreenshot name="container-logs" alt="容器的日志标签页，包含历史、时间戳、输出流筛选和搜索。" />

日志会在容器写入时实时显示。工具栏控制你看到的内容：

- **历史**：要加载多少行过去的日志：最后 100 行、1 000 行（默认）或 10 000 行，或者全部。
- **起始时间**：任意时间，或最近 5 分钟、1 小时或 24 小时。
- **时间戳**：在每行前显示引擎的时间戳。
- **stdout** 和 **stderr**：显示或隐藏任一输出流。
- **跟随**：持续滚动到最新的一行。关闭时新行也会继续到达。
- **在日志中查找**：高亮显示匹配项。按 <kbd>Enter</kbd> 跳到下一个匹配项，按 <kbd>Shift</kbd>+<kbd>Enter</kbd> 跳到上一个。
- **清除**会清空视图；**下载日志**会将已加载的内容保存为文本文件，最多为最后 100 000 行。

容器停止后，日志会以 _— 日志结束 —_ 结尾。

### 检查

**详细信息**以卡片形式汇总容器：状态和退出码、命令、重启策略、健康检查、环境变量、挂载、端口、网络和标签。**原始 JSON** 显示引擎完整的 inspect 文档。

<Aside type="caution">环境变量以明文显示，与引擎保存它们的方式相同。共享屏幕前请注意这一点。</Aside>

### 健康

为带有健康检查的容器显示，无论健康检查是容器自己的还是其镜像的。**健康检查**给出状态（_starting_、_healthy_ 或 _unhealthy_）、命令、时间设置（未设置的部分由引擎默认值补充：每 30 秒一次、超时 30 秒、重试 3 次）以及已连续失败了多少次检查。**最近结果**列出引擎保留的检查，最新的排在前面，包括退出码、运行时间、耗时以及输出内容；较长的输出会折叠起来，可通过**再显示…行**展开。

因此，当列表显示 _unhealthy_ 时，原因就在这里，无需阅读原始 JSON。该标签页会在每个检查间隔以及状态变化时自动刷新。关闭了健康检查的容器没有“健康”标签页；要添加或更改健康检查，请[编辑容器](#编辑容器)。

### Exec

<DocScreenshot name="container-terminal" alt="容器 Exec 标签页中的交互式终端。" />

正在运行的容器中的交互式终端。第一个终端 **Shell** 会自动打开并运行 `bash`，镜像中没有 bash 时运行 `sh`。

**新建终端**会用你自己的**命令**、**用户**和**目录**打开另一个终端，例如以用户 `postgres` 运行 `psql -U postgres`。可以同时打开多个终端；用其 **×** 关闭。终端会随窗口调整大小。

没有 shell 的镜像（`scratch` 或 distroless 镜像）无法打开默认终端。

### 文件

从 `/` 开始浏览容器的文件系统。选择一个文件夹即可打开它，或使用顶部的路径返回上级。

- 使用行末的按钮**下载**文件，或将整个文件夹下载为 `.tar` 归档。
- **上传到此处**会将本机上的文件复制到当前所在的文件夹，替换同名文件。

列出文件需要在容器内运行 `find` 和 `stat`，因此没有这些命令的精简镜像无法浏览。传输内容保存在内存中，因此超大文件最好用 `docker cp` 复制。

### 统计

最近五分钟的实时图表，每秒更新一次：**CPU**、**内存**（相对于容器的限制）、接收和发送的**网络**流量，以及读取和写入的**磁盘 I/O**，并显示进程数。

### 进程

容器中正在运行的进程，与 `ps aux` 显示的一样，每五秒刷新一次。

## 运行容器

“容器”页面上的**运行容器**（或镜像旁的 ▶ 按钮）会打开**运行容器**对话框：

| 字段                   | 说明                                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **镜像**               | 必填。会提示主机上的镜像。如果主机上没有该镜像，会先使用已保存的[镜像仓库登录](/docs/guides/settings/#镜像仓库)拉取它。 |
| **名称**               | 可选；留空时由引擎生成。                                                                                                |
| **命令**               | 替换镜像的默认命令（不是其入口点）。参数的引号写法与 shell 中相同。                                                     |
| **端口**               | **主机端口** → **容器端口**，`tcp` 或 `udp`。主机端口留空则由引擎选择一个空闲端口。端口会发布在所有网络接口上。         |
| **卷**                 | 卷名称或绝对路径 `/host/path`，挂载到容器内的绝对路径，可选择**只读**。尚不存在的名称会创建一个卷。                     |
| **环境变量**           | 每行一个 `KEY=value`。空行和以 `#` 开头的行会被忽略。                                                                   |
| **网络**               | **默认 (bridge)**，或主机上的任意网络。                                                                                 |
| **重启**               | **从不**、**失败时**、**除非手动停止**或**始终**。                                                                      |
| **容器退出时将其删除** | 与 `docker run --rm` 相同。退出时被删除的容器不能同时设置重启。                                                         |

选择**运行**：Homeport 会创建并启动容器，然后打开其日志。

如果容器无法启动（例如端口已被占用），Homeport 会再次删除它，对话框保持打开并显示原因，你可以修正该字段，然后以相同名称运行它。

### 高级选项

重启策略下方的**高级选项**会打开不常用的设置，每类一个标签页。Homeport 无法读取的值会在其字段下方说明，并且在修正之前**运行**会一直等待。这里设置的所有内容都会显示在容器的**检查**标签页中。

**资源**

| 字段                   | 说明                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------- |
| **CPU 限制**           | 它可以使用多少个 CPU，例如 `0.5` 或 `2`（`--cpus`）。留空则使用所有 CPU。              |
| **CPU 份额**           | CPU 繁忙时它相对于其他容器的权重；默认为 `1024`（`--cpu-shares`）。                    |
| **内存限制**           | 例如 `512m` 或 `2g`（`--memory`）。大小按 1024 的幂计算，与 Docker 相同。至少为 `6m`。 |
| **内存预留**           | 一个软限制，引擎只在主机内存不足时执行；不超过内存限制。                               |
| **内存和交换空间限制** | 内存加交换空间，因此至少等于内存限制；`-1` 表示不限制交换空间。需要设置内存限制。      |

**标签**：每行一个 `key=value`，供 Traefik、Caddy 等反向代理以及备份工具读取。以 `com.docker.compose.` 开头的键会被拒绝：它们属于 Docker Compose，Homeport 会因此把容器显示为某个堆栈的一部分。

**安全**：要添加和移除的能力，每次输入一个并附有建议（`NET_ADMIN` 和 `CAP_NET_ADMIN` 是同一个；`ALL` 表示全部），以及**特权模式**。

<Aside type="danger" title="特权模式">
  特权容器可以使用主机的所有设备和能力，其中运行的任何东西都可以接管主机。如果可以，请改为只添加它需要的能力和设备。
</Aside>

**设备**：要传入的主机设备，例如用于硬件转码的 `/dev/dri` 或用于 Zigbee 适配器的 `/dev/ttyUSB0`，以及容器内的路径（留空时相同）和权限：`r`（读取）、`w`（写入）和 `m`（创建设备文件）中的若干项。**GPU** 可以请求全部 GPU、指定数量的 GPU，或按索引或 UUID 选择的 GPU，与 `docker run --gpus` 相同。

<Aside type="note" title="GPU 需要厂商的工具包">
  主机必须安装其 GPU 厂商的容器工具包（对于 NVIDIA，为 [NVIDIA Container
  Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html)），并在安装后重启
  Docker Engine。Homeport 不会安装它。没有它时，运行会失败并显示 _此主机无法为容器提供 GPU。_
</Aside>

**健康检查**：保留**镜像自身的**健康检查，定义一个以 `/bin/sh -c` 运行的**命令**（退出码 0 表示健康），或用**无**关闭镜像的健康检查。**间隔**、**超时**和**启动期**接受 `30s` 或 `1m30s` 这样的时长；**重试次数**是连续失败多少次后变为不健康。之后，状态会在列表中显示为 _healthy_ 或 _unhealthy_。

**网络标识**：容器的**主机名**和**域名**、它的 **DNS 服务器**（地址）和**搜索域**，以及**额外的 hosts 条目**：添加到其 `/etc/hosts` 中的 `name:address` 行，用于你网络中的 DNS 不认识的名称。`host-gateway` 代表主机自身的地址，因此 `host.docker.internal:host-gateway` 可以访问主机上的服务。

**日志记录**：**日志驱动**：`json-file`、`local`、`journald`、`syslog`、`none`，或引擎拥有的任何其他驱动；留空则使用引擎的默认值。**驱动选项**是 `key=value` 行；对于 `json-file`，`max-size=10m` 和 `max-file=3` 可防止日志占满小型主机的磁盘。使用 `journald`、`syslog` 或 `none` 时，**日志**标签页可能保持为空。

## 复制容器

**复制**会打开根据该容器填好的运行对话框（镜像、命令、环境变量、端口、卷、网络、重启策略以及所有高级选项），名称为 `<name>-copy`。修改你需要的内容，然后选择**运行**。

对话框中不显示的设置，例如 ulimits、sysctls、安全选项、tmpfs 挂载以及容器所在的其他网络（及其别名），会原样复制。只有那些原本就仅来自镜像的设置不会填入表单，因此镜像的新标签会带来它自己的默认值。

副本不会带走标识原容器的内容：它有自己的主机名（除非你设置了一个）、MAC 地址和新的匿名卷，来自[堆栈](/docs/guides/stacks/)的容器会失去其堆栈标签和服务别名，因此副本不会加入该堆栈，也不会响应其服务名称。如果原容器发布了固定的主机端口，对话框会说明这一点：两个容器无法在同时运行时都使用该端口，因此请更改它，或留空让引擎选择一个。

## 编辑容器

Docker Engine 无法更改现有容器的大多数设置，因此**编辑**会重新创建容器：它会打开根据该容器填好的运行对话框，**应用**会用根据你的更改创建的新容器替换它。名称保持不变（使用**重命名**来更改名称）。

在进行任何操作之前，Homeport 会列出新容器将不会拥有的内容：

- **匿名卷**：新容器从空的匿名卷开始。旧的匿名卷不会被删除：它们会作为未使用的卷保留，你仍然可以打开或[清理](/docs/guides/volumes-networks/)它们。
- **容器内更改的文件**：自容器创建以来的更改，例如已安装的软件包或已编辑的配置。要保留它们，请先[将容器提交为镜像](#提交容器)（确认对话框中有一个按钮可以执行此操作），然后编辑容器以使用该镜像。
- **停机时间**：在两者交换期间，正在运行的容器会停止，通常持续几秒钟。
- **堆栈的下次部署**：对于堆栈中的容器，堆栈的下次部署会根据其 compose 文件重新创建它，而不包含你的编辑。要让更改持久，请修改 compose 文件。

会保留的内容：名称、网络及其别名、命名卷和绑定挂载，以及对话框中不显示的所有设置。如果容器原本在运行，之后它也会运行。

<Aside type="note" title="如果出现问题">
  Homeport
  会在改动原容器之前创建新容器，并且只在新容器运行后才删除原容器。如果任何步骤失败（例如新端口已被占用），新容器会被删除，原容器会恢复原样（如果原本在运行，则继续运行），对话框会显示原因。在极少数情况下，如果恢复也失败了，消息会指出原容器的位置，例如
  `web-old-1a2b3c4d`，以便你将其重命名回来并启动它。
</Aside>

## 提交容器

**提交为镜像…**会将容器当前的文件（包括自创建以来在容器内更改的所有内容）及其设置保存为主机上的一个新镜像，与 `docker commit` 相同。

| 字段               | 说明                                                                                                                                                      |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **镜像名称**       | `repo:tag`，初始为容器名称和当天日期，例如 `web:2026-11-04`。如果已有镜像使用该名称，对话框会说明这一点：该名称会转移到新镜像上。                         |
| **消息**           | 显示在镜像的历史中（**检查** → **层**）。                                                                                                                 |
| **作者**           | 可选。                                                                                                                                                    |
| **更改**           | 应用到新镜像的 Dockerfile 指令，每行一条：`CMD`、`ENTRYPOINT`、`ENV`、`EXPOSE`、`LABEL`、`ONBUILD`、`USER`、`VOLUME` 或 `WORKDIR`，例如 `ENV MODE=prod`。 |
| **提交时暂停容器** | 默认开启：在提交所需的几秒钟内冻结其进程，以便正在写入的文件保持一致。之后容器会继续运行。                                                                |

新镜像会立即出现在[镜像页面](/docs/guides/images/)上。卷（无论是命名卷还是匿名卷）不包含在其中：请单独备份它们。要制作可以重新构建的镜像，最好[从 Dockerfile 构建](/docs/guides/images/#构建镜像)。

## 导出容器的文件系统

**导出文件系统…**会将容器的每个文件（其镜像中的文件以及此后更改的所有内容）保存到本机上的一个 `.tar` 文件中，与 `docker export` 相同。选择保存位置；文件以容器命名。进度显示已写入的字节数，**取消**会停止导出，被取消或失败的导出不会留下不完整的文件。归档直接流式写入磁盘，因此几 GB 大小的容器也没有问题。

该归档是一个普通的扁平文件系统：没有层、历史或设置，也没有卷。可以用任何 tar 工具打开它，或者用“镜像”页面上的[**从 tar 导入…**](/docs/guides/images/#导入文件系统)或 `docker import` 将其转换回镜像。要同时保留容器的设置，请改为[提交它](#提交容器)。
