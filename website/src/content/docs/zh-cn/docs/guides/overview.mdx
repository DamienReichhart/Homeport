## 概览

**概览**是唯一同时显示所有主机和[集群](/docs/clusters/)的页面。Homeport 启动时会打开它。顶部的**添加主机**和**添加集群**会进入添加它们的页面。

<DocScreenshot name="overview" alt="概览页面，包含主机卡片、引擎卡片、磁盘使用情况和最近的事件。" />

### 主机卡片

每个主机都有一张卡片，显示其名称、地址、类型和状态。对于已连接的主机，它还会显示：

- 正在运行的容器数和容器总数，以及镜像数量；
- 其容器的实时 CPU 使用率，以单个 CPU 的百分比表示：在 8 个 CPU 的主机上，`250%` 表示有两个半 CPU 处于繁忙状态；
- 其容器使用的内存，以及主机的总内存。

选择一张卡片即可切换到该主机。如果它已连接，Homeport 会打开它的**容器**页面。**在看板上查看其容器**会打开只显示该主机的[看板](#看板)。

### 集群卡片

在主机卡片之后，每个集群都有一张卡片，显示其名称、API 服务器、状态和 Kubernetes 版本，连接后还会显示有多少个 Node 就绪、有多少个 Pod 正在运行（在其页面显示的 Namespace 中）。Homeport 自己进行统计，并在概览打开期间每 30 秒重新查询一次。你的凭据无权读取的计数会显示为**无权限**。选择一张卡片即可切换到该集群。

### 所选集群

选择集群后，卡片下方的区域会显示该集群，而不是主机：

<DocScreenshot
  name="cluster-overview"
  alt="概览页面，包含三张主机卡片、两张集群卡片以及所选 EKS 集群的仪表信息：版本、5 个 Node 中有 4 个就绪、按阶段统计的 Pod、未就绪的工作负载和最近的警告。"
  caption="选择了 eks-prod 的概览：一个 Node 未就绪，api 和 search 的 Pod 不足。"
/>

- **集群**：其版本、平台、API 服务器以及其页面显示的 Namespace。
- **Node**：有多少个就绪，以及每个未就绪的 Node，并链接到其页面。
- **Pod**：有多少个正在运行、等待中、失败（崩溃或无法拉取镜像）或已完成。
- **未就绪的工作负载**：就绪 Pod 少于期望数量的 Deployment、StatefulSet 和 DaemonSet，并链接到其页面。
- **最近的警告**：最近的 Warning 事件，每个都链接到其对象。**所有事件**会打开集群的事件页面。

你的凭据可能无权读取的部分会说明这一点，其他部分仍会显示。

### 所选主机

在卡片下方，所选主机的区域会显示：

- **引擎**：名称、版本、操作系统、内核、架构、CPU 和内存、存储驱动以及根目录。
- **磁盘使用情况**：镜像、容器、卷和构建缓存占用了多少空间，其中有多少正在使用，以及可以回收多少。版本 29 之前的 Docker Engine 报告的信息较少：此时镜像大小为估算值，卷和构建缓存的大小显示为 **—**，卡片会说明这一点。
- **最近的事件**：引擎最近报告的几件事。**所有事件**会打开“事件”页面。

### 清理

“磁盘使用情况”卡片中的**清理…**会删除未被使用的内容，仅限所选主机。选择要删除的内容：

| 选项                 | 默认 | 删除的内容                                 |
| -------------------- | :--: | ------------------------------------------ |
| **已停止的容器**     | 开启 | 所有未在运行的容器。                       |
| **悬空镜像**         | 开启 | 构建和拉取遗留下的无标签层。               |
| **所有未使用的镜像** | 关闭 | 未被容器使用的有标签镜像，以及悬空镜像。   |
| **未使用的网络**     | 开启 | 未连接任何容器的自定义网络。               |
| **构建缓存**         | 开启 | 缓存的构建层。                             |
| **未使用的卷**       | 关闭 | 未被容器使用的所有卷，**包括其中的数据**。 |

容器最先删除，因此它们占用的镜像、网络和卷也会算作未使用。随后 Homeport 会告诉你回收了多少空间。

<Aside type="danger">
  **未使用的卷**会删除数据（包括已命名的卷），并且无法撤销。勾选它后，按钮会显示为**删除，包括卷数据**，作为最后的提醒。
</Aside>

## 看板

**看板**是侧边栏中的第二项，它在一张表中列出所有已连接主机的容器：无需切换主机，就能看到什么在哪里运行、什么已经停止。

<DocScreenshot
  name="board"
  alt="看板，列出三个主机的容器，带有主机列、筛选器以及实时 CPU 和内存。"
/>

- **列**：主机、名称、镜像、状态（含健康状态）、堆栈、端口、CPU、内存和创建时间。选择列名可按该列排序，再次选择可反向排序。CPU 和内存会实时更新。
- **筛选器**：要显示的主机（默认为全部）、状态（**运行中**、**已停止**或**不健康**）、某个堆栈，以及可匹配名称、短 ID、镜像、堆栈和主机名称的搜索。按 <kbd>/</kbd> 可跳转到搜索框。**清除筛选**会重新显示全部内容。打开容器再返回时，筛选器会保持原样。
- **操作**：每一行都有与“容器”页面相同的启动/停止按钮和菜单，作用于该行所在的主机。勾选多行（可以在同一主机或多个主机上）即可一起启动、停止、重启或删除它们；删除前会先询问，并按主机列出容器。
- **打开容器**：选择一行，Homeport 会切换到其主机并打开该容器。**返回**会回到看板。

要在所有主机的容器中查找某一个容器而不打开看板，请[从命令面板搜索](/docs/guides/keyboard/#搜索所有主机)。

未连接的主机（无法访问、已停用或正在等待你处理）会在表格上方显示一行，例如 _nas（无法访问）未显示_，并附有指向其页面的链接；其他主机照常列出。超过几百个容器后，只会绘制可见的行，因此看板仍然很快。

## 系统托盘

Homeport 会在系统托盘中添加一个图标：在 macOS 上是菜单栏，在 Windows 上是通知区域。它的菜单列出每个主机及其状态，例如 **prod-server — 已连接**，并在状态变化时立即更新：

- 选择一个主机，即可将窗口带到前台并显示该主机的概览。
- **无法访问**的主机有一个子菜单，包含**打开**和**重新连接**，后者会立即重试。
- **打开 Homeport** 会恢复窗口，**添加主机…**会打开添加主机的页面，**退出**总是会退出。

图标的工具提示会进行汇总：**Homeport — 4 个主机中已连接 3 个**。在 Windows 上，双击图标即可打开窗口。

在[设置](/docs/guides/settings/#桌面)中开启**关闭时最小化到系统托盘**后，关闭窗口会隐藏 Homeport 而不是退出，因此其主机连接保持打开；可以从托盘或再次打开 Homeport 来重新打开窗口。某些 Linux 桌面会隐藏托盘图标；请参阅[要求](/docs/requirements/#可选系统托盘)。

### 通知

Homeport 运行时（即使隐藏在托盘中），会在容器因错误停止、内存耗尽或变为不健康，以及主机变为无法访问或恢复时，通过操作系统的通知告诉你。可以在[设置](/docs/guides/settings/#通知)中开启或关闭每种通知。

## 事件

**事件**页面列出所选主机的引擎报告的内容，最新的排在前面：容器启动和停止、镜像拉取、卷创建、网络连接等。Homeport 会保存它们，因此重启后它们仍然存在，“昨晚什么重启了？”也能找到答案。

| 列       | 显示内容                                   |
| -------- | ------------------------------------------ |
| **时间** | 发生的时间，以你的本地时间显示。           |
| **类型** | `container`、`image`、`volume`、`network`… |
| **操作** | `start`、`die`、`pull`、`create`…          |
| **对象** | 事件所涉及对象的名称。                     |
| **堆栈** | 它所属的堆栈（如果有）。                   |

可以按操作或对象名称搜索，或按类型筛选。列表会实时更新。

<DocScreenshot name="events" alt="事件页面，列出引擎最近的事件及其类型、操作、对象和堆栈。" />

### 保留的内容

- **重启后仍然保留。** 事件到达时会保存在本机上。页面显示最近的 1,000 条；滚动到底部或选择**加载更早的事件**，每次可再加载 1,000 条。
- **Homeport 关闭期间的事件。** Homeport 重新连接到主机时，会向引擎请求自它保存的最后一条事件以来的事件，从而补上这段时间发生的事情，最远可追溯到引擎记得的范围，即引擎最近的几百条事件。不会有任何事件被列出两次。
- **保留 30 天**，或按照[设置 → 数据](/docs/guides/settings/#数据)中**引擎事件保留**所设置的天数，并且每个主机最多保留 10,000 条。较早的事件每小时清除一次。

**清除历史**会忘记为所选主机保存的所有事件；新事件会继续出现。删除主机会删除其事件。引擎自己的事件从不会被更改。

Homeport 自己用于打开卷的[辅助容器](/docs/guides/volumes-networks/#辅助容器)从不会出现在这里。
