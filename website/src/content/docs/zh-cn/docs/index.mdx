**Homeport** 是一款桌面应用，用于管理任何地方的 Docker Engine、containerd 和 Incus（本机的，或通过 SSH、TLS 或 TCP 连接的远程引擎）、它们组成的 Swarm，以及你的 kubeconfig 能访问到的 Kubernetes 集群和你指定的 Nomad 集群，理念与 Docker Desktop 相近。它可在 Windows、macOS 和 Linux 上运行，免费，并以 [GNU Affero 通用公共许可证第 3 版](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE)开源。

Homeport 本身不运行容器。它连接到你已有的引擎（称为**主机**），并在一个窗口中呈现其上的一切：容器、镜像、卷、网络和 Compose **堆栈**。它还能连接 Kubernetes 和 Nomad **集群**，查看并管理其上运行的内容。主机和集群上都不会安装任何东西。

## 能做什么

<CardGrid>
  <Card title="连接任何引擎" icon="laptop">
    本地引擎会被自动检测。远程引擎通过 SSH、双向 TLS 或 TCP 加入，并会自动重新连接。
  </Card>
  <Card title="管理容器" icon="seti:docker">
    实时 CPU 和内存、日志、交互式终端、文件浏览器、统计图表、进程，以及“运行”对话框。
  </Card>
  <Card title="部署 Compose 堆栈" icon="rocket">
    在 Homeport 中保存 compose 文件及其加密的环境变量，从项目文件夹部署，或跟随一个 git
    仓库，并部署到任意主机或 Swarm。
  </Card>
  <Card title="管理 Swarm" icon="seti:docker">
    通过管理节点主机找到 Docker Swarm，并管理其节点、服务、任务、机密、配置和 Swarm 堆栈。
  </Card>
  <Card title="使用 Podman 自身的功能" icon="seti:config">
    在 Podman 主机上管理 Pod 并在其中运行容器，以及在 systemd 下安装、编辑和启动 Quadlet 单元。
  </Card>
  <Card title="管理 containerd" icon="seti:config">
    在 containerd
    主机上选择命名空间，运行其容器的任务，阅读日志，打开终端，拉取镜像并清除未使用的快照。
  </Card>
  <Card title="运行 Incus 实例" icon="laptop">
    在 Incus 主机上从镜像创建系统容器和虚拟机，打开其控制台或
    shell，创建和恢复快照，并管理镜像、配置文件、存储和网络。
  </Card>
  <Card title="浏览 Kubernetes" icon="server">
    从 kubeconfig 添加集群（包括 EKS、GKE 和 AKS），实时查看其工作负载、Pod、Service、配置、Node
    和事件。阅读日志、打开终端、转发端口、扩缩容、应用 YAML 以及管理 Helm Release。
  </Card>
  <Card title="运行 Nomad job" icon="server">
    通过其 agent 的地址添加 Nomad 集群，规划并运行 job，跟踪其 allocation 和日志，在 task 中打开
    shell，以及腾空节点。
  </Card>
  <Card title="保持整洁" icon="seti:folder">
    镜像、卷和网络的使用情况一目了然，清理对话框会先说明将删除哪些内容。
  </Card>
</CardGrid>

## 我们使用的术语

Homeport 对事物的命名很精确，本文档也遵循同样的命名：

- **主机**是 Homeport 连接的引擎：Docker Engine，或与之兼容的引擎，例如 Podman、containerd 或 Incus。每个容器、镜像、卷、网络和堆栈都只属于一台主机。
- **集群**是从你的 kubeconfig 中的某个上下文添加的 Kubernetes 集群，或通过其某个 agent 的地址添加的 Nomad 集群。
- **Swarm** 是 Docker Swarm，通过属于它的主机找到，从不单独添加。
- **堆栈**是在主机上运行的 Compose 项目，或在 Swarm 上运行的 Swarm 堆栈。**托管堆栈**的 compose 文件由 Homeport 保存；**关联堆栈**的 compose 文件保存在本机的一个文件夹中；**同步堆栈**跟随一个 git 仓库；**外部堆栈**是通过其他方式部署的。你可以**接管**外部堆栈来管理它。

完整列表见[术语表](/docs/reference/glossary/)。
