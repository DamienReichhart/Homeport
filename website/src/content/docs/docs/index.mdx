**Homeport** is a desktop app for managing Docker Engines, containerd and Incus anywhere — this machine's, or remote ones over SSH, TLS or TCP — the Swarms they form, and the Kubernetes clusters your kubeconfig reaches and the Nomad clusters you name, in the spirit of Docker Desktop. It runs on Windows, macOS and Linux, is free, and is open source under the [GNU Affero General Public License, version 3](https://github.com/DamienReichhart/Homeport/blob/main/LICENSE).

Homeport doesn't run containers itself. It connects to the Engines you already have, called **Hosts**, and gives you one window for everything on them: containers, images, volumes, networks and Compose **Stacks**. It also connects to Kubernetes and Nomad **Clusters**, to see what runs on them and manage it. Nothing is installed on a Host or a Cluster.

## What you can do

  <Card title="Work with containers" icon="seti:docker">

  <Card title="Deploy Compose Stacks" icon="rocket">
    Keep a compose file and its encrypted environment in Homeport, deploy from a project folder or

  </Card>
  <Card title="Manage Swarms" icon="seti:docker">
    Find a Docker Swarm through its manager Hosts, and manage its nodes, services, tasks, secrets,
    configs and swarm stacks.
  </Card>
  <Card title="Use Podman's own features" icon="seti:config">
    On a Podman Host, manage pods and run containers in them, and install, edit and start Quadlet
    units under systemd.
  </Card>
  <Card title="Manage containerd" icon="seti:config">
    On a containerd Host, pick a namespace, run its containers' tasks, read their logs, open a
    terminal, pull images and clear unused snapshots.
  </Card>
  <Card title="Run Incus instances" icon="laptop">
    On an Incus Host, create system containers and virtual machines from an image, open their
    console or a shell, take and restore snapshots, and manage images, profiles, storage and
    networks.
  </Card>
  <Card title="Browse Kubernetes" icon="server">
    Add clusters from your kubeconfig, EKS, GKE and AKS included, and see their workloads, Pods,

  </Card>
  <Card title="Run Nomad jobs" icon="server">

    logs, open a shell in a task, and drain nodes.
  </Card>
  <Card title="Keep things tidy" icon="seti:folder">
    Images, volumes and networks with usage at a glance, and a clean-up dialog that says what it

## Words we use

Homeport names things precisely, and the docs follow it:

- A **Host** is an Engine Homeport connects to: a Docker Engine or a compatible one such as Podman, containerd or Incus. Every container, image, volume, network and Stack belongs to exactly one Host.
- A **Cluster** is a Kubernetes cluster, added from a context of your kubeconfig, or a Nomad cluster, added by the address of one of its agents.
- A **Swarm** is a Docker Swarm, found through the Hosts that belong to it and never added on its own.
- A **Stack** is a Compose project running on a Host, or a swarm stack running on a Swarm. A **Managed Stack** is one whose compose file Homeport keeps; a **Linked Stack** keeps its compose files in a folder on this computer; a **Synced Stack** follows a git repository; an **External Stack** was deployed some other way. You can **adopt** an External Stack to manage it.

The [glossary](/docs/reference/glossary/) has the full list.
