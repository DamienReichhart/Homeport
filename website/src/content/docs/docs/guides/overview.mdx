## Overview

The **Overview** is the only page that shows every Host and [Cluster](/docs/clusters/) together. It opens when Homeport starts. **Add host** and **Add cluster** at the top lead to the pages that add them.

<DocScreenshot
  name="overview"
  alt="The Overview page with host cards, the Engine card, disk usage and recent events."
/>

### Host cards

Each Host has a card with its name, address, type and status. For a connected Host it also shows:

- running and total containers, and the number of images;
- live CPU use of its containers, as a percentage of one CPU — `250%` on an 8-CPU Host means two and a half CPUs are busy;
- memory used by its containers, out of the Host's total.

Select a card to switch to that Host. If it's connected, Homeport opens its **Containers**. **Its containers on the board** opens the [Board](#board) showing that Host only.

### Cluster cards

After the Host cards, each Cluster has a card with its name, API server, status and Kubernetes version, and, once connected, how many of its Nodes are ready and how many of its Pods run (in the namespace its pages show). Homeport counts them on its side and asks again every 30 seconds while the Overview is open. A count your credentials aren't allowed to read says **not allowed** instead. Select a card to switch to that Cluster.

### The selected Cluster

When a Cluster is selected, the section below the cards shows it instead of a Host:

<DocScreenshot
  name="cluster-overview"
  alt="The Overview with three Host cards, two Cluster cards, and the selected EKS Cluster's dashboard: version, Nodes 4 of 5 ready, Pods by phase, workloads not ready and recent warnings."
  caption="The Overview with eks-prod selected: one Node isn't ready, and api and search are short of Pods."
/>

- **Cluster** — its version, platform, API server and the namespace its pages show.
- **Nodes** — how many are ready, each one that isn't, linked to its page.
- **Pods** — how many run, wait, fail (crashing, or unable to pull their image) or are done.
- **Workloads not ready** — Deployments, StatefulSets and DaemonSets with fewer Pods ready than they want, linked to their pages.
- **Recent warnings** — the last Warning events, each linked to its object. **All events** opens the Cluster's Events.

A part your credentials may not read says so, and the others still show.

### The selected Host

Below the cards, a section for the selected Host shows:

- **Engine** — name, version, operating system, kernel, architecture, CPUs and memory, storage driver and root directory.
- **Disk usage** — how much space images, containers, volumes and the build cache take, how much is in use, and how much could be reclaimed. Docker Engines older than version 29 report less: image sizes are then estimated, volume and build cache sizes show as **—**, and the card says so.
- **Recent events** — the last few things the Engine reported. **All events** opens the Events page.

### Cleaning up

**Clean up…** in the Disk usage card removes what nothing uses, on the selected Host only. Pick what to remove:

| Option                 | Default | Removes                                                    |
| ---------------------- | :-----: | ---------------------------------------------------------- |
| **Stopped containers** |   On    | Every container that isn't running.                        |
| **Dangling images**    |   On    | Untagged layers left behind by builds and pulls.           |
| **All unused images**  |   Off   | Tagged images no container uses, as well as dangling ones. |
| **Unused networks**    |   On    | Custom networks no container is attached to.               |
| **Build cache**        |   On    | Cached build layers.                                       |
| **Unused volumes**     |   Off   | Every volume no container uses, **including its data**.    |

Containers go first, so the images, networks and volumes they held count as unused. Homeport then tells you how much space was reclaimed.

<Aside type="danger">
  **Unused volumes** deletes data, named volumes included, and can't be undone. When it's ticked,
  the button reads **Delete, including volume data** as a last reminder.
</Aside>

## Board

The **Board**, second in the sidebar, lists the containers of every connected Host in one table: what runs where, and what's down, without switching Host.

<DocScreenshot
  name="board"
  alt="The Board, listing the containers of three Hosts with a Host column, filters, and live CPU and memory."
/>

- **Columns** — Host, Name, Image, Status (with its health), Stack, Ports, CPU, Memory and Created. Select a column's name to sort by it, again to reverse. CPU and memory update live.
- **Filters** — the Hosts to show (all by default), the state (**Running**, **Stopped** or **Unhealthy**), one Stack, and a search that matches names, short IDs, images, Stacks and Host names. <kbd>/</kbd> jumps to the search. **Clear filters** shows everything again. The filters stay as they were when you open a container and come back.
- **Actions** — each row has the same start/stop button and menu as on the Containers page, acting on that row's Host. Tick several rows, on one Host or several, to start, stop, restart or remove them together; removing asks first and lists the containers Host by Host.
- **Opening a container** — select a row: Homeport switches to its Host and opens the container. **Back** returns to the Board.

To find one container among every Host's without opening the Board, [search from the command palette](/docs/guides/keyboard/#searching-every-host).

A Host that isn't connected — unreachable, disabled, waiting for you — gets one line above the table, such as _nas (Unreachable) isn't shown._, with a link to its page; the other Hosts are listed as usual. Past a few hundred containers, only the rows in view are drawn, so the Board stays quick.

## System tray

Homeport adds an icon to the system tray — the menu bar on macOS, the notification area on Windows. Its menu lists every Host with its status, such as **prod-server — Connected**, and updates as soon as a status changes:

- Pick a Host to bring the window to the front on that Host's Overview.
- An **Unreachable** Host has a submenu with **Open** and **Reconnect**, which tries again straight away.
- **Open Homeport** brings the window back, **Add host…** opens the page to add one, and **Quit** always quits.

The icon's tooltip sums it up: **Homeport — 3 of 4 Hosts connected**. On Windows, double-click the icon to open the window.

With **Close to the system tray** on in [Settings](/docs/guides/settings/#desktop), closing the window hides Homeport instead of quitting it, so its Host connections stay open; reopen it from the tray, or by opening Homeport again. Some Linux desktops hide tray icons; see [requirements](/docs/requirements/#optional-a-system-tray).

### Notifications

While Homeport runs, even hidden in the tray, it tells you through your operating system's notifications when a container stops with an error, runs out of memory or turns unhealthy, and when a Host becomes unreachable or comes back. Turn each kind on or off in [Settings](/docs/guides/settings/#notifications).

## Events

The **Events** page lists what the selected Host's Engine reported, newest first: containers starting and stopping, images pulled, volumes created, networks connected, and so on. Homeport keeps them, so they're still there after it restarts — "what restarted overnight?" has an answer.

| Column     | Shows                                      |
| ---------- | ------------------------------------------ |
| **Time**   | When it happened, in your local time.      |
| **Type**   | `container`, `image`, `volume`, `network`… |
| **Action** | `start`, `die`, `pull`, `create`…          |
| **Object** | The name of what it happened to.           |
| **Stack**  | The Stack it belongs to, if any.           |

Search by action or object name, or filter by type. The list updates live.

### What's kept

- **Across restarts.** Events are saved on this computer as they arrive. The page shows the latest 1,000; scroll to the bottom, or choose **Load older events**, for 1,000 more at a time.
- **While Homeport was closed.** When Homeport connects to a Host again, it asks the Engine for the events since the last one it kept, so what happened meanwhile is filled in — as far back as the Engine remembers, which is its latest few hundred events. Nothing is listed twice.
- **For 30 days**, or as long as **Keep Engine events for** in [Settings → Data](/docs/guides/settings/#data) says, and at most 10,000 per Host. Older events are removed every hour.

**Clear history** forgets every event kept for the selected Host; new ones keep appearing. Removing a Host removes its events. The Engine's own events are never changed.

Homeport's own [helper containers](/docs/guides/volumes-networks/#the-helper-container), which open volumes, never show up here.
