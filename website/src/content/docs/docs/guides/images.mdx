| Column      | Shows                                                                    |
| ----------- | ------------------------------------------------------------------------ |
| **Name**    | The first tag, and how many more it has; `<none>` for untagged images.   |
| **ID**      | The short image ID.                                                      |
| **Created** | How long ago the image was built.                                        |
| **Size**    | Its size on disk.                                                        |
| **Status**  | **In use** with the number of containers created from it, or **Unused**. |

Stopped containers count as using an image. Select a column header to sort, and search with **Search images**.

## Pulling an image

Choose **Pull image** and enter a reference: `nginx` (which means `nginx:latest`), `nginx:1.27`, `ghcr.io/org/app:v2`, `registry.example.com:5000/app`, or a digest such as `app@sha256:…`.

Homeport shows the pull's progress layer by layer, and says **Done.** when it's complete. **Cancel** stops following the pull.

### Private images

When a login for the image's registry is stored in [**Settings → Registries**](/docs/guides/settings/#registries), Homeport hands it to the Engine with the pull, so private images pull on any Host — local, TCP, TLS or SSH — with nothing configured there. Under the reference, the dialog says how the image will be pulled: **Pulled as alice on ghcr.io**, or **Pulled anonymously** when no login matches.

An image without a registry in its name (`nginx`, `bitnami/redis`) uses the Docker Hub login. A Docker Hub login also raises Docker Hub's pull limit.

If the registry refuses the pull, the message says what to do: add a login for that registry when none was stored, or check the stored one.

<Aside>
  The login travels to the Engine with the request and isn't stored on the Host. Homeport doesn't
  read `docker login` credentials from `~/.docker/config.json`.
</Aside>

## Building an image

Choose **Build** and pick a **Folder** on this computer that holds a Dockerfile — the build context. Homeport packs the folder, leaves out everything its `.dockerignore` excludes (with Docker's rules: `*`, `**`, `!` exceptions, the last matching line wins), and streams it to the selected Host, whose Engine builds it. The same build works on a remote Host over SSH or TLS, with nothing installed there.

| Field                         | What it does                                                                                             |
| ----------------------------- | -------------------------------------------------------------------------------------------------------- |
| **Dockerfile**                | Its path inside the folder; `Dockerfile` by default. It's always sent, even if `.dockerignore` lists it. |
| **Target stage**              | The stage of a multi-stage Dockerfile to stop at (`--target`).                                           |
| **Names**                     | One or more names for the result, such as `app:1.0, ghcr.io/me/app:1.0`.                                 |
| **Build arguments**           | `NAME=value`, one per line, for the Dockerfile's `ARG`s.                                                 |
| **Don't use the build cache** | Runs every step again (`--no-cache`).                                                                    |
| **Pull newer base images**    | Pulls the `FROM` images even if the Host has them (`--pull`).                                            |

The build's output streams live; **Cancel** stops it. When it finishes, the names appear on the Images page. If a step fails, the message names it (**The build failed at step 3/5 (RUN make)**) and **Details** holds the end of the output. Private `FROM` images pull with the [registry logins](/docs/guides/settings/#registries) you stored.

<Aside>
  Homeport uses the Engine's classic builder, the one its API offers. BuildKit features such as `RUN
  --mount` and build secrets aren't available; build those from a terminal.
</Aside>

## Pushing an image

Choose **Push** in an image's **⋮** menu. **Name to push** starts as the image's first name; pick another of its names, or type a new one such as `ghcr.io/org/app:v2` — the image is given that name first, as **Tag** does. The name's first part says which registry it goes to: `ghcr.io/org/app` goes to GHCR, `org/app` to Docker Hub.

Homeport pushes through the Host's Engine with the [registry login](/docs/guides/settings/#registries) stored for that registry, and says which one under the name (**Pushed as alice on ghcr.io**). With no login stored, the dialog warns before you start, since most registries refuse anonymous pushes. While it runs, the dialog counts the layers pushed and those the registry already had, and shows the upload in progress; **Cancel** stops the push.

If the registry refuses, the message says whether to add a login or to check that the stored one may push to that repository.

## Working with an image

- **▶ Run** opens the [Run dialog](/docs/guides/containers/#running-a-container) with the image filled in.
- **Inspect** — or selecting the row — shows **Layers**, the instructions that built each layer and their sizes, and **Raw JSON**.
- **Tag** adds another name, such as `registry.example.com/app:v2`. It doesn't push anything; **Push** does.
- **Remove** deletes the image and the layers no other image uses. An image with several tags loses all of them. The Engine refuses to remove an image a container still uses; remove the container first.

## Cleaning up

**Clean up** offers two levels:

- **Dangling images** — untagged images left behind by builds and pulls. Safe to remove.
- **All unused images** — every image no container uses, tagged ones included. They can be pulled again, but that takes time and bandwidth.

Homeport tells you how many were removed and how much space came back. The [Overview's clean-up](/docs/guides/overview/#cleaning-up) can also remove stopped containers, networks, build cache and volumes in one go.
