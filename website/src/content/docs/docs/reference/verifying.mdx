Every Homeport release is built by GitHub Actions from the public repository. You can check that the file you downloaded is the one that was built, in two ways. Linux packages and updates are also signed, and checked for you.

## Checksums

Each release includes `SHA256SUMS.txt`, with a SHA-256 checksum for every file. The [download page](/download/) also shows each file's checksum. Download `SHA256SUMS.txt` into the same folder as the installer, then:

<Tabs syncKey="os">
<TabItem label="Linux">

```sh
sha256sum --ignore-missing -c SHA256SUMS.txt
```

</TabItem>
<TabItem label="macOS">

```sh
shasum -a 256 --ignore-missing -c SHA256SUMS.txt
```

</TabItem>
<TabItem label="Windows">

```powershell
(Get-FileHash .\Homeport-1.0.0-windows-x64-setup.exe -Algorithm SHA256).Hash.ToLower()
```

Compare the result with the installer's line in `SHA256SUMS.txt`.

</TabItem>
</Tabs>

`OK` next to the file name means it matches.

## Build provenance

A checksum proves the file wasn't damaged or swapped after the checksum was published. A [build provenance attestation](https://docs.github.com/actions/security-for-github-actions/using-artifact-attestations) goes further: it's signed by GitHub and records the repository, commit and workflow that produced the file.

With the [GitHub CLI](https://cli.github.com) installed:

```sh
gh attestation verify Homeport-1.0.0-windows-x64-setup.exe --repo DamienReichhart/Homeport
```

A successful check prints the workflow and commit the file was built from.

## Package signatures

The Homeport package repository and every `.rpm` are signed with the Homeport package key (RSA 4096):

**Fingerprint:** <SigningKeyFingerprint />

`apt`, `dnf` and `zypper` check these signatures on every update, and refuse packages and repository data that don't match. To check the key you downloaded, or a `.rpm` file:

<Code code={`curl -fsSL ${KEY_URL} | gpg --show-keys --with-fingerprint`} lang="sh" />

```sh
sudo rpm --import homeport.asc   # once
rpm -K Homeport-<version>-linux-x64.rpm
```

`rpm -K` prints `digests signatures OK` for a signed package. A `.deb` file isn't signed itself: the repository's signed index covers it, and a downloaded one is covered by its checksum and attestation.

## Update signatures

Every update the in-app updater installs is signed with a separate Homeport update key, whose public half is built into Homeport. Before installing, Homeport checks the signature and that it was made for the version announced, and refuses anything else, even when it comes from the right address.

## Code signing

The macOS app is ad-hoc signed and Windows installers aren't signed with a commercial certificate yet, so macOS and Windows ask you to confirm the first launch. [Installation](/docs/installation/) shows how. Updates installed from inside Homeport don't ask again.
