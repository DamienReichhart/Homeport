Homeport has installers for Windows, macOS and Linux, each for x64 and ARM. Get them from the [download page](/download/), which points you at the right file for your system, or from the [latest GitHub release](https://github.com/DamienReichhart/Homeport/releases/latest). On Linux, the Homeport package repository installs it with one command.

Every install stays up to date: Homeport updates itself on Windows, macOS and with the AppImage, and the Linux packages update with the rest of your system. See [updating](/docs/reference/updating/).

<Aside>
  Homeport manages Docker Engines but doesn't include one. If you want containers on this machine,
  install Docker Engine, Docker Desktop, Colima, OrbStack, Rancher Desktop or Podman too — or
  connect Homeport to a remote server instead. See the [system requirements](/docs/requirements/).
</Aside>

## Windows

| File                                         | Use it for                                       |
| -------------------------------------------- | ------------------------------------------------ |
| `Homeport-<version>-windows-x64-setup.exe`   | Most PCs. Installs for the current user.         |
| `Homeport-<version>-windows-arm64-setup.exe` | Windows on ARM (Snapdragon and other ARM64 PCs). |
| `Homeport-<version>-windows-x64.msi`         | Managed and silent installs on x64.              |

<Steps>

1. Download the installer for your PC and open it.

2. Windows SmartScreen may say **Windows protected your PC**, because the installer isn't signed with a paid certificate yet. Choose **More info**, then **Run anyway**.

3. Follow the installer. Homeport is added to the Start menu.

</Steps>

For a silent install with the MSI package:

```powershell
msiexec /i Homeport-<version>-windows-x64.msi /quiet
```

## macOS

| File                                 | Use it for                              |
| ------------------------------------ | --------------------------------------- |
| `Homeport-<version>-macos-arm64.dmg` | Macs with Apple silicon (M1 and later). |
| `Homeport-<version>-macos-x64.dmg`   | Macs with an Intel processor.           |

Not sure which you have? Open the Apple menu → **About This Mac**: a **Chip** line means Apple silicon, a **Processor** line naming Intel means Intel.

<Steps>

1. Open the `.dmg` and drag **Homeport** into **Applications**.

2. Open Homeport from Applications or Launchpad.

3. Homeport isn't notarised by Apple yet, so macOS may say it **can't be opened** or **can't check it for malicious software**. Choose **Done** (or **OK**), open **System Settings → Privacy & Security**, scroll to Security and choose **Open Anyway** next to Homeport. Confirm, and macOS remembers your choice.

</Steps>

<Aside type="tip" title="From the terminal">
  You can also clear the quarantine flag macOS puts on downloaded apps:

```sh
xattr -dr com.apple.quarantine /Applications/Homeport.app
```

</Aside>

## Linux

Homeport for Linux needs glibc 2.35 or later — Ubuntu 22.04, Debian 12, Fedora 36 or anything newer — on x64 or ARM64.

The script works on Debian, Ubuntu and their derivatives (`apt`), Fedora, RHEL and their relatives (`dnf`) and openSUSE (`zypper`). It says what it will do before asking for `sudo`, then:

2. adds the Homeport repository,

### Package files

You can also download the `.deb` or `.rpm` for your processor (`x64` for Intel and AMD, `arm64` for ARM) and install it directly:

<Tabs syncKey="linux-format">
<TabItem label="Debian, Ubuntu">

```sh
sudo apt install ./Homeport-<version>-linux-x64.deb
```

</TabItem>
<TabItem label="Fedora, RHEL">

```sh
sudo dnf install ./Homeport-<version>-linux-x64.rpm
```

</TabItem>
<TabItem label="openSUSE">

```sh
sudo zypper install ./Homeport-<version>-linux-x64.rpm
```

</TabItem>
</Tabs>

The first time you install one of these packages, it adds the Homeport repository too, so you get updates the same way as with the quick install. If you'd rather not, delete the repository file (`/etc/apt/sources.list.d/homeport.sources`, `/etc/yum.repos.d/homeport.repo` or `/etc/zypp/repos.d/homeport.repo`): later updates of the package won't add it back.

### AppImage

The AppImage runs on most distributions without installing anything, and updates itself from inside Homeport. Make it executable and run it:

```sh
chmod +x Homeport-<version>-linux-x64.AppImage
./Homeport-<version>-linux-x64.AppImage
```

Each time it runs, it adds Homeport to your application menu. If it doesn't start and mentions FUSE, install `libfuse2` (`libfuse2t64` on Ubuntu 24.04 and later).

The `.deb` and `.rpm` packages add Homeport to your application menu and install its licence notices in `/usr/share/doc/homeport/` or `/usr/share/licenses/homeport/`.

<Aside type="caution" title="Using Docker on this machine?">
  To reach the local Docker socket without root, your user must be in the `docker` group:

```sh
sudo usermod -aG docker $USER
```

Log out and back in for it to take effect. Without it, a local Host shows as **Unreachable** with
_Permission denied_.

</Aside>

## Check your download

Every release lists a SHA-256 checksum for each file and a signed build provenance attestation, and the Linux packages and repositories are signed. [Verifying downloads](/docs/reference/verifying/) shows how to check them.
